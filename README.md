# infraege

Веб-приложение для подготовки к ЕГЭ по информатике: теория, доступные графические объяснения,
практика с проверкой ответа и локальный прогресс без регистрации.

Технический контракт проекта находится в [`docs/SPEC.md`](docs/SPEC.md), команды и версии стека —
в [`docs/STACK.md`](docs/STACK.md). Ниже приведён практический путь для локального запуска и
ручной проверки текущей темы change 05.

## Быстрый старт — одна команда

Для запуска приложения нужны только запущенный Docker с Compose v2 и GNU Make. Из корня
репозитория выполните:

```bash
make dev
```

Команда сама:

- подставляет одноразовые локальные значения без создания `.env`;
- собирает frontend и backend со всеми зависимостями внутри Docker;
- запускает PostgreSQL, API, Vite dev server и Nginx;
- ждёт, пока healthchecks всех сервисов станут зелёными;
- печатает готовые URL.

После запуска откройте <http://localhost:8080/>. Изменения в `apps/web/src`, `apps/api/app` и
`content` подхватываются контейнерами без ручной переустановки зависимостей.

Основные команды:

```bash
make dev      # собрать/запустить и дождаться готовности
make ps       # показать состояние и health сервисов
make logs     # смотреть общие логи, выход — Ctrl+C
make restart  # перезапустить весь dev-стек
make stop     # корректно остановить стек, сохранив данные PostgreSQL
make down     # совместимый алиас для make stop
make help     # показать доступные команды
```

## Требования

- Docker с Compose v2 и GNU Make — для `make dev`;
- Node.js 22+, pnpm 10+, Python 3.12+ и
  [uv](https://docs.astral.sh/uv/) — только если вы запускаете автоматические тесты на host;
- Chromium — только для локального Playwright E2E.

Проверить установленные версии:

```bash
node --version
pnpm --version
python3 --version
uv --version
docker --version
docker compose version
make --version
```

Все команды ниже выполняются из корня репозитория, если не указано иное.

## Установка зависимостей на host — только для тестов

Для обычного запуска через `make dev` этот раздел не нужен. Если требуется запускать lint,
typecheck или тесты непосредственно в WSL/на host:

```bash
pnpm install
cd apps/api
uv sync
cd ../..
```

Для первого запуска Playwright отдельно установите Chromium:

```bash
pnpm --filter web test:e2e:install
```

## Альтернативный запуск без Docker

Этот вариант не обязателен и оставлен для отладки отдельных процессов. PostgreSQL для текущей
функциональности не требуется: учебный контент хранится в JSON, а прогресс пользователя — в
`localStorage` браузера.

Откройте два терминала.

Терминал 1 — backend:

```bash
cd apps/api
uv run uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Проверка backend:

```bash
curl -f http://127.0.0.1:8000/health
```

Ожидаемый ответ:

```json
{"status":"ok"}
```

Терминал 2 — frontend:

```bash
pnpm dev
```

Откройте главную страницу: <http://127.0.0.1:3000/>.

Опубликованная тема change 05 доступна с главной страницы и включена в sitemap. Прямой URL:

<http://127.0.0.1:3000/theory/zadanie-1-graphs-and-tables>

Остановить каждый локальный процесс можно сочетанием `Ctrl+C` в его терминале.

## Запуск через Docker Compose

Рекомендуемый интерфейс — Makefile:

```bash
make dev
```

Он использует отдельный `infra/docker-compose.dev.yml`. Никакие `.env`, пароли, токены или
локально установленные Node/Python-пакеты не требуются. Встроенные значения существуют только в
процессе команды и предназначены исключительно для локального disposable PostgreSQL.

Проверить состояние:

```bash
make ps
```

В контейнерном режиме открывайте приложение через Nginx:

- UI: <http://localhost:8080/>;
- health check: <http://localhost:8080/health>;
- опубликованная тема: <http://localhost:8080/theory/zadanie-1-graphs-and-tables>.

Остановить стек, сохранив volume PostgreSQL:

```bash
make stop
```

Команда посылает сервисам их штатные stop-сигналы, ждёт до 30 секунд на сервис, затем удаляет
остановленные контейнеры и dev-network. Named volume PostgreSQL не удаляется. `make down` оставлен
как алиас, а timeout при необходимости можно увеличить, например: `make stop STOP_TIMEOUT=60`.

Не запускайте unit- или E2E-тесты внутри контейнеров: по правилам проекта они выполняются только
локально в окружении разработчика.

## Автоматические проверки

Frontend:

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

Backend:

```bash
cd apps/api
uv run ruff check app tests
npx pyright app tests
uv run pytest
cd ../..
```

Связи content-as-code:

```bash
pnpm validate:content
```

Проверить, что Playwright видит E2E-сценарии:

```bash
pnpm --filter web exec playwright test --list
```

Полный локальный E2E запускается командой:

```bash
pnpm --filter web test:e2e
```

Playwright сам поднимает свежие frontend/backend на изолированных адресах
`127.0.0.2:3100` и `127.0.0.2:8100`; заранее запускать серверы для него не нужно. Сценарий проходит
по опубликованной теме с главной страницы, проверяет порог освоения, sitemap, no-JS и оба viewport.

## Ручная проверка темы change 05

### Подготовка

1. Запустите frontend и backend локально либо весь Docker-стек.
2. Откройте опубликованную тему с главной страницы или по прямому URL выше.
3. Откройте DevTools → Console и убедитесь, что при загрузке нет новых ошибок или предупреждений.
4. Для чистого прогона удалите сохранённый прогресс в DevTools → Application → Local Storage.
   Ключ называется `infraege:progress`.

### Контент и доступность

Проверьте на широком экране и на ширине около 390 px:

- заголовок и badge `№1` видны;
- текст читается, страница не имеет горизонтального скролла;
- SVG-граф не обрезан и описан для accessibility tree;
- таблица длин дорог остаётся семантической таблицей и помещается по ширине;
- выделены вершина 2, дорога 2–4 и симметричные клетки Б–Г/Г–Б со значением 7;
- disclosure «Показать разбор», поля и кнопки доступны с клавиатуры, focus indicator заметен;
- при отключённом JavaScript весь урок и условия задач остаются читаемыми; не работает только
  интерактивная отправка ответов, что ожидаемо.

### Правильность задач

| Задача | Правильный ответ | Допустимые формы |
|-------:|------------------|-----------------|
| 1 | `Б` | `Б`, регистр не важен |
| 2 | `8` | `8`, `8 км`, `8км` |
| 3 | `Д` | `Д`, регистр не важен |
| 4 | `24` | `24`, `24 км`, `24км` |
| 5 | `11` | `11`, `11 км`, `11км` |

Для каждой задачи проверьте, что:

1. заведомо неверный ответ показывает «Неверно» и содержательный разбор;
2. после исправления ответа повторная отправка работает и показывает «Верно»;
3. разбор объясняет ход решения и типичную ошибку, а не только называет ответ.

### Прогресс и сохранение

1. На чистом хранилище отображается `0%` и `0 из 5`.
2. Неверный ответ не меняет прогресс.
3. Первый правильный ответ даёт `20%`.
4. Повтор того же правильного ответа не увеличивает прогресс повторно.
5. Четыре разные решённые задачи дают ровно `80%` и статус «Тема освоена».
6. После перезагрузки страницы результат сохраняется.
7. Пятая задача повышает прогресс до `100%`.

### Пройденный Content Quality Gate

Перед публикацией архитектор вручную подтвердил:

- математическую и логическую корректность примера, упражнения и всех пяти задач;
- осмысленность графа, таблицы и подсветки;
- педагогическую последовательность `worked example → объяснение → completion exercise → практика`;
- оригинальность текста и формулировок задач;
- итоговое решение о переводе темы из `review` в `published`.

Чек-лист фиксируется в
[`content/topics/graphs-and-tables.quality.md`](content/topics/graphs-and-tables.quality.md).
В чек-листе зафиксирован итоговый статус `PASS`; автоматические проверки не заменяли явное
одобрение архитектора.
