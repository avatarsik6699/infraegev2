# Product

## Platform

web

## Users

Русскоязычные школьники самостоятельно готовятся к ЕГЭ по информатике с телефона или обычного
домашнего компьютера. Продукт должен помогать понимать закономерности и переносить их в решение
задач, а не подменять обучение банком ответов.

## Product Purpose

infraege.ru должен объединить объяснение, подходящие учебные представления и проверяемую практику
в последовательную систему подготовки. Линейная учебная траектория определена ниже; конкретные
публичные страницы, маршруты, информационная архитектура и визуальная композиция после frontend
reset ещё не выбраны.

## Operating Context

Продукт полностью русскоязычный и работает без обязательного аккаунта. Обязательный материал
должен быть доступен в SSR/no-JS HTML; интерактивность является progressive enhancement.

## Current Foundation

- Публичный frontend временно содержит только нейтральный Table of Contents stand и общий 404.
- Единственный утверждённый визуальный компонент — Learning Path Table of Contents.
- Backend task/content schemas, typed API transport, error telemetry, build/deploy, testing and
  operations infrastructure сохранены без опубликованного content consumer.
- Глобальная дизайн-система, brand direction и product routes намеренно не определены.

## Learning Flow Contract

Одна тема или урок ведёт ученика через четыре явных раздела. Их порядок стабилен, а внутреннее
наполнение зависит от материала:

1. **Теория** — идея, содержательное объяснение, полезные приёмы, схемы и учебные визуалы. Раздел
   отвечает на вопросы «что происходит?» и «почему это работает?» без искусственного
   переключателя «кратко/подробно».
2. **Практика** — алгоритм, разобранный пример, частичные упражнения и постепенно усложняющиеся
   самостоятельные задачи. Визуал может быть связан непосредственно с примером или заданием.
3. **Что важно для ЕГЭ** — типичные ошибки, требования экзаменационного формата, лайфхаки и общие
   подсказки. При необходимости здесь используется отдельный визуал. Подсказки к конкретной задаче
   при этом доступны прямо в практике, а не только после неё.
4. **Результат** — вариативное завершение материала: краткие итоги, освоенные умения, результат
   практики, зоны для повторения, похожие задачи и следующий связанный материал.

Это четыре навигационных раздела, а не четыре жёстких шаблона контента. Внутренний блок появляется
только когда помогает понять материал или сделать следующий шаг.

Подсказки и решение доступны сразу. Правильная работа с подсказкой учитывается в прогрессе; при
слабом результате раздел «Результат» предлагает повторение, а не штраф. Отдельного финального
испытания «без подсказок», таймеров, задержек, оценки уверенности по каждому шагу и штрафного
scoring за помощь нет. Такие механики могут появиться только после отдельного продуктового решения.

## Reset Boundary

Сохранены продуктовая область подготовки к ЕГЭ, нейтральная модель тем/уроков/задач, учебная
траектория и инфраструктурные контракты. Удалены экземпляры прежнего контента, их slug, ассеты,
маршруты, page compositions и визуальные решения. Новый UI должен реализовывать этот flow, но не
наследовать форму удалённых страниц.

## Product Principles

- Визуал объясняет, а не заполняет пространство.
- Сначала понимание, затем самостоятельное применение.
- Фактическая точность и доступная альтернатива обязательны для учебных материалов.
- Новый дизайн не выводится из одной темы, одного типа задачи или удалённой страницы.

## Accessibility & Inclusion

Клавиатурный доступ, корректный heading/source order, читаемость на узком экране, отсутствие
serious/critical axe-нарушений и доступное описание сложных материалов обязательны.
