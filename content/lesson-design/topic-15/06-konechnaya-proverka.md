**Программа проверяет уже доказанную модель: она перебирает конечный набор значений, который рассуждение сделало достаточным, и возвращает контрпример, если кандидат A не подходит.** Это проверка для всех 86 основных задач, а не новый тип: сам перебор без обоснования границ ничего не доказывает.

Главный пример — маски 22 и 10 из подтемы 3: программа должна найти тот же ответ 20 и вернуть для A = 19 контрпример x = 4. Затем тот же контракт проверки — для отрезков, плоскости и делимости.

---

**Поиск контрпримера по x для фиксированного A — короткий цикл, который останавливается на первом нарушении.** Пройди его по шагам на формуле (x ≤ 7) → (x ≤ A) из подтемы 1:

```python run search.py
A = 6
for x in range(12):
    if not ((not x <= 7) or x <= A):
        print('контрпример:', x)
        break
```

```output
контрпример: 7
```

Проверять дальше x = 7 незачем: одного нарушения достаточно, чтобы отбросить A = 6. А вот подтверждение для всех x требует знать, почему выбранного диапазона хватает.

---

**Логическая запись переводится в Python почти дословно, но импликацию и побитовое И нужно записывать явно.**

| Математическая запись | Python |
|---|---|
| ¬p | `not p` |
| p ∧ q | `p and q` |
| p ∨ q | `p or q` |
| p → q | `(not p) or q` |
| p ≡ q | `p == q`, если оба значения логические |
| x & M | `x & M` |
| x² | `x ** 2` |
| ДЕЛ(x, m) | `x % m == 0`, m ≠ 0 |
| x ∈ [l; r] | `l <= x <= r` |

{{bitand|Побитовое `&`}} действует на двоичные разряды числа, его нельзя заменять словом `and`. Знак `^` не возводит в степень: степень записывают через `**`. Для понятности импликацию удобно вынести в функцию:

```python
def implies(p, q):
    return (not p) or q
```

Тогда вложенная стрелка записывается `implies(p, implies(q, r))`, а другой порядок — `implies(implies(p, q), r)`.

---

**Проверять нужно каждое значение x из доказанного диапазона; внешний цикл ищет A, внутренний пытается его опровергнуть.**

Ниже программа для побитового примера с масками 22 и 10. Все числовые пределы уже обоснованы ручным решением: маски и кандидаты до 20 помещаются в пяти битах, поэтому хватает x от 0 до 31.

```python
def formula(x, a):
    p = (x & 22) != 0
    q = (x & 10) == 0
    r = (x & a) != 0
    return implies(p, implies(q, r))

for a in range(21):
    ok = True
    for x in range(32):
        if not formula(x, a):
            ok = False
            break
    if ok:
        print(a)
        break
```

```output
20
```

`range(21)` не включает 21: перебираются значения от 0 до 20. Переменная `ok` означает «пока не встретили нарушения» и перед каждым новым `a` снова равна `True`. Найден контрпример — проверку этого кандидата прекращают ({{break|`break`}}). Нельзя прекращать её после первого истинного результата. Минимум ищут по возрастанию, максимум в доказанно конечной области — по убыванию.

Та же проверка короче с {{anyall|`all`}}:

```python
for a in range(21):
    if all(formula(x, a) for x in range(32)):
        print(a)
        break
```

```output
20
```

`all` проверяет, что все значения истинны. Если набор проверки пуст, `all` вернёт `True`: случайно пустой диапазон не является проверкой задачи.

---

**Сначала контрпример, потом уверенность: функция возвращает первое нарушение или «нарушений нет».**

```python
def counterexample(a, xs):
    for x in xs:
        if not formula(x, a):
            return x
    return None

print(counterexample(19, range(32)))
print(counterexample(20, range(32)))
```

```output
4
None
```

Число 19 содержит бит 16, но не содержит бит 4. Именно поэтому x = 4 выявляет ошибку. {{none|`None`}} означает, что в переданном диапазоне нарушения нет. Только доказанная достаточность диапазона превращает это наблюдение в полную проверку.

---

**Для отрезков точная проверка — не шаг 0,1, а концы, середины между соседними концами и по точке снаружи.**

Принадлежность фиксированным отрезкам не меняется внутри областей между их концами. Для уже выбранного A = [l; r] добавь l, r к списку всех концов, отсортируй различные значения и проверь каждый конец, по одной точке между каждой парой соседних концов и по одной точке левее самого левого и правее самого правого конца. Если формула использует только принадлежность этим промежуткам, такая проверка точна.

Например, P = [0; 1,01], Q = [1,02; 2], A = [0; 2], формула a → (p ∨ q). Проверка только целых x увидит 0, 1, 2 и не обнаружит нарушения. При x = 1,015 формула ложна. Даже шаг 0,1 пропускает этот разрыв. Проверка середины между 1,01 и 1,02 обнаруживает его сразу.

{{fraction|`Fraction`}} хранит точные дроби; десятичные концы передают строками, `Fraction("1.01")`, чтобы не вносить погрешность двоичного `float`:

```python
from fractions import Fraction

def representatives(endpoints):
    cuts = sorted(set(Fraction(v) for v in endpoints))
    points = list(cuts)
    points += [(u + v) / 2 for u, v in zip(cuts, cuts[1:])]
    points += [cuts[0] - 1, cuts[-1] + 1]
    return points

def gap_formula(x):
    p = Fraction("0") <= x <= Fraction("1.01")
    q = Fraction("1.02") <= x <= 2
    a = 0 <= x <= 2
    return implies(a, p or q)

xs = representatives(["0", "1.01", "1.02", "2"])
print([x for x in sorted(xs) if not gap_formula(x)])
```

```output
[Fraction(203, 200)]
```

203/200 = 1,015 — середина узкого разрыва. Программа проверяет уже выбранный кандидат A; поиск оптимальных концов — отдельная задача, её решает рассуждение подтемы 2.

---

**На плоскости перебирают только пары из доказанной опасной области, а не «тысячу на тысячу».**

Для примера (2x + 3y ≥ 30) ∨ (x + 2y < A) опасная область даёт x ≤ 13, y ≤ 9. Можно точно проверить только эти пары:

```python
def plane_formula(x, y, a):
    return (2*x + 3*y >= 30) or (x + 2*y < a)

for a in range(1, 21):
    ok = all(
        plane_formula(x, y, a)
        for x in range(1, 14)
        for y in range(1, 10)
    )
    if ok:
        print(a)
        break
```

```output
20
```

Пары за пределами прямоугольника не нужны: там обязательно 2x + 3y ≥ 30. Для x ≥ 14 и y ≥ 1 сумма не меньше 31; для y ≥ 10 и x ≥ 1 не меньше 32.

---

**Для делимости достаточный диапазон — период НОК всех делителей вместе с A, включая сам НОК.**

Если при фиксированном A формула использует только ДЕЛ(x, mᵢ), её значение повторяется с периодом НОК всех mᵢ и A (подтема 5). Проверим ответ задачи ¬ДЕЛ(x, A) → (ДЕЛ(x, 8) → ¬ДЕЛ(x, 12)) при A = 24 и при соседнем A = 48:

```python
def div_formula(x, a):
    return implies(x % a != 0,
                   implies(x % 8 == 0, x % 12 != 0))

print(all(div_formula(x, 24) for x in range(1, 25)))
bad = next(x for x in range(1, 49) if not div_formula(x, 48))
print(bad)
```

```output
True
24
```

Для A = 24 период — НОК(8, 12, 24) = 24, и диапазон 1 … 24 полон. Для A = 48 контрпример x = 24: делится на 8 и 12, но не на 48.

---

**Итого.**

- Программа проверяет модель, а не заменяет её: сначала доказанный конечный набор, потом перебор.
- Внешний цикл — кандидаты A, внутренний — поиск контрпримера; останавливаться только на нарушении.
- Биты: все маски и A меньше 2ᵏ — x от 0 до 2ᵏ − 1.
- Отрезки: концы, середины, по точке снаружи; точные дроби вместо шага.
- Плоскость: границы опасной области из неравенств.
- Делимость: период НОК всех делителей и A, правый конец включён.
- `all` на пустом наборе — `True`: пустая проверка ничего не доказывает.
