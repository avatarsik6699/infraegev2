**Исключение — сигнал, что операция не завершилась обычным образом; ожидаемые сигналы перехватывают точечно, а неожиданные должны остановить программу и указать на ошибку**. Опора — сообщения об ошибках из первого урока и запуск примеров по шагам: теперь ошибки можно перехватывать, а состояние программы — печатать при отладке.

Всё покажем на функции среднего значения: научим её сообщать о пустом наборе, проверим `assert` и подберём примеры, которые ловят ошибки.

---

**`try` выполняет рискованное действие, `except` обрабатывает только ожидаемую проблему.** Типы ошибок вроде `ValueError` и `ZeroDivisionError` мы уже встречали. Теперь научимся их обрабатывать.

```python
text = "abc"
try:
    number = int(text)
except ValueError:
    print("Нужно ввести целое число")
else:
    print(number * 2)
```

```output
Нужно ввести целое число
```

`try` выполняет потенциально неуспешное действие. `except ValueError` обрабатывает только ожидаемую проблему преобразования. `else` выполняется, если блок `try` завершился без исключения: при `text = "21"` программа напечатала бы 42.

Можно добавить `finally`: его код выполняется при выходе из конструкции, включая выход из-за обычного исключения или `return`. Это используют для освобождения ресурсов. `with` для файла уже решает соответствующую задачу закрытия. Аварийное завершение процесса операционной системой — отдельная ситуация, где Python не гарантирует выполнение завершающего кода.

```python run parse_numbers.py
for text in ["7", "x"]:
    try:
        number = int(text)
    except ValueError:
        print(text, "— не число")
    else:
        print(number * 2)
    finally:
        print("проверено", text)
```

```output
14
проверено 7
x — не число
проверено x
```

Не окружай всю программу `except: pass`: это скроет и ошибки автора. Перехватывай конкретные ожидаемые исключения и решай, что делать с причиной. В задаче с гарантированно корректным входом ошибка чтения часто должна остановить программу и обратить внимание на неверный формат.

Запусти цикл по шагам. Для `"7"` после `try` выполняется `else`, для `"x"` строка с `int` прерывается ошибкой, выполнение переходит к `except`, а `else` пропускается; `finally` выполняется в обоих случаях.

---

**`raise` сообщает о нарушении договорённости функции.** `raise` создаёт исключение, когда нарушена договорённость функции:

```python
def average(numbers):
    if not numbers:
        raise ValueError(
            "Нельзя вычислить среднее пустого набора"
        )
    return sum(numbers) / len(numbers)

print(average([2, 4, 9]))
print(average([]))
```

```output
5.0
```

```error
ValueError: Нельзя вычислить среднее пустого набора
```

`not numbers` истинно для пустого списка: пустые коллекции ложны. Это лучше, чем вернуть 0 и сделать вид, будто пустой набор имеет среднее 0. Но в другой программе договорённость может явно предусматривать `None` для отсутствующего среднего. Важно выбрать и документировать поведение.

---

**Ошибку ищут по состоянию: печатают промежуточные значения или идут отладчиком.** **Отладка** — исследование программы для нахождения причин неверной работы. Один способ — временно печатать промежуточные значения:

```python
numbers = [3, -1, 4]
total = 0
for i, value in enumerate(numbers):
    total += value
    print("шаг", i, "элемент", value, "сумма", total)
```

```output
шаг 0 элемент 3 сумма 3
шаг 1 элемент -1 сумма 2
шаг 2 элемент 4 сумма 6
```

Такая печать показывает то же, что запуск по шагам: значения переменных после каждой итерации. Видно, на каком шаге значение впервые отличается от ожидаемого.

Другой способ — **отладчик**, инструмент остановки и пошагового выполнения. Точка останова указывает, где приостановить программу; затем можно смотреть значения и выполнять следующую строку. Из Python встроенный `breakpoint()` обычно открывает отладчик, а многие IDE предлагают графическое управление.

Перед сдачей решения на автоматическую проверку отладочную печать убирают: она станет лишним текстом в ответе.

---

**`assert` проверяет предположение разработчика.**

```python
def double(number):
    return number * 2

assert double(4) == 8
assert double(-3) == -6
assert double(5) == 11
```

```error
AssertionError
```

`assert condition` при ложном условии вызывает `AssertionError`. Первые две проверки прошли молча, третья — ложна. Он удобен для простых проверок разработчика. При запуске с оптимизацией `python -O` проверки `assert` могут отключаться, поэтому они не должны быть единственной защитой для обязательной проверки пользовательского ввода.

---

**Проверочные примеры выбирают так, чтобы каждый ловил свою ошибку.** Проверь обычный случай, минимальные размеры, крайние границы, отсутствие подходящего ответа, повторяющиеся значения и отрицательные числа, если они разрешены. Не надо проверять недопустимые входы, если функция по договорённости их не поддерживает, но эту границу нужно явно понимать.

Для пары соседей — списки длины 0, 1 и 2. Для цикла от `a` до `b` — случай `a == b`.

Для функций над списком чисел — среднего, максимума — набор может быть таким:

- `[2, 4, 9]` — обычный случай, ловит неверную формулу;
- `[5]` — один элемент, ловит ошибку границы цикла;
- `[]` — пустой вход, ловит деление на ноль или неописанное поведение;
- `[-4, -2]` — отрицательные числа, ловят начальное значение 0 у максимума или минимума;
- `[1, 2]` — дробный ответ, ловит целое деление вместо обычного.

---

**Итого.**

- `try`/`except Тип` перехватывает только ожидаемую ошибку; `else` — при успехе, `finally` — всегда.
- `except: pass` прячет ошибки автора; так не делают.
- `raise ValueError("…")` сообщает о нарушенной договорённости функции.
- Отладка — печать состояния по шагам или отладчик; отладочный вывод удаляют.
- `assert` — проверка разработчика; примеры подбирают на границы, пустой вход и отрицательные числа.
