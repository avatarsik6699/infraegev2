**Дополнительный урок — для продвинутых.** Он для тех, кто хочет писать программы больше экзаменационных: в темах ЕГЭ классы не встречаются. Задачи основных уроков решаются без него.

Главная идея урока: **класс описывает новый тип объектов — какие данные хранит каждый экземпляр и какие действия с ними разрешены**. Это следующий шаг после словаря-записи: правила изменения данных живут рядом с самими данными. Опора — словари и функции: класс соединяет данные записи и функции, которые её меняют.

Сквозной пример урока — прогресс чтения книги: название, число страниц и текущая страница.

---

**Класс — описание нового типа, экземпляр — конкретный объект этого типа.** Словарь способен хранить название книги, число страниц и текущую позицию чтения. Но если таких записей много, хочется одинаково создавать их и одинаково изменять. **Класс** описывает новый тип объектов с данными и связанными действиями. **Экземпляр** — конкретный объект этого класса.

Это основа **объектно-ориентированного программирования**, сокращённо ООП. Оно особенно полезно, когда программа моделирует несколько сущностей со своим состоянием. Для суммы чисел отдельный класс обычно не нужен.

```python
class ReadingProgress:
    def __init__(self, title, total_pages):
        if total_pages <= 0:
            raise ValueError(
                "Число страниц должно быть положительным"
            )
        self.title = title
        self.total_pages = total_pages
        self.current_page = 0

    def advance(self, pages):
        if pages < 0:
            raise ValueError(
                "Нельзя продвинуться "
                "на отрицательное число страниц"
            )
        self.current_page = min(
            self.total_pages, self.current_page + pages
        )

    def fraction(self):
        return self.current_page / self.total_pages

book = ReadingProgress("Python", 200)
book.advance(30)
print(book.title, book.current_page)
print(book.fraction())
```

```output
Python 30
0.15
```

Предполагаются целые числа страниц. `class` определяет класс. `__init__` — специальный метод начальной настройки уже созданного экземпляра. Вызов класса создаёт экземпляр и организует его инициализацию. `__init__` не должен возвращать вместо него произвольный результат.

---

**`self` — экземпляр, для которого выполняется метод.** `self` — обычное имя первого параметра метода, принятое по соглашению. Оно обозначает экземпляр, для которого выполняется действие. При `book.advance(30)` Python автоматически передаёт `book` первым аргументом. Смысл близок к `ReadingProgress.advance(book, 30)`.

**Атрибут** — именованное значение, связанное с объектом. `self.title` и `self.current_page` сохраняются внутри экземпляра. Обычная локальная переменная `pages` существует только во время вызова и сама по себе не запоминается в объекте.

Создай второй экземпляр — у него будет независимая текущая страница:

```python
another_book = ReadingProgress("Алгоритмы", 300)
print(another_book.current_page, book.current_page)
```

```output
0 30
```

---

**Атрибут класса общий для всех экземпляров, атрибут экземпляра — у каждого свой.** Переменная в теле класса вне методов относится к классу и может использоваться всеми экземплярами. Это подходит для общей константы. Изменяемый список, который по ошибке объявили там вместо `self.items = []` в `__init__`, станет общим для объектов.

```python
class Notebook:
    def __init__(self):
        self.notes = []

first = Notebook()
second = Notebook()
first.notes.append("Циклы")
print(second.notes)
```

```output
[]
```

Каждый вызов `__init__` создаёт отдельный список. Это та же идея независимых вложенных списков, а не отдельное исключение ООП.

---

**Класс держит правила изменения данных рядом с самими данными.** **Инкапсуляция** означает организацию данных и правил обращения с ними так, чтобы остальная программа работала с понятными действиями. Например, `advance` контролирует допустимое изменение позиции вместо разрозненных присваиваний в разных местах.

Имя с одним начальным подчёркиванием, например `_current_page`, обозначает внутреннюю деталь по соглашению. Это не запрет доступа. Два начальных подчёркивания вызывают преобразование имени для уменьшения случайных конфликтов в наследовании; это тоже не механизм защиты секретных данных.

`@property` позволяет читать вычисляемое свойство как атрибут:

```python
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    @property
    def area(self):
        return self.width * self.height

rectangle = Rectangle(3, 5)
print(rectangle.area)
```

```output
15
```

`area` читается без скобок. Декоратор преобразует метод в свойство. В приведённой форме присвоить `rectangle.area = ...` нельзя: способ записи свойства не определён. Ширина и высота здесь не проверяются; при необходимости проверку добавляют в договорённость класса и его реализацию.

---

**Наследование уточняет поведение, композиция собирает объект из других объектов.** **Наследование** создаёт класс на основе другого и позволяет уточнить его поведение. Оно уместно, если новый объект действительно можно использовать вместо объекта базового вида.

```python
class NamedItem:
    def __init__(self, name):
        self.name = name

    def label(self):
        return self.name

class Task(NamedItem):
    def __init__(self, name, done=False):
        super().__init__(name)
        self.done = done

    def label(self):
        mark = "✓" if self.done else "○"
        return f"{mark} {self.name}"

for item in [NamedItem("Книга"), Task("Прочитать", True)]:
    print(item.label())
```

```output
Книга
✓ Прочитать
```

`Task(NamedItem)` обозначает наследование. `super()` в этом простом случае позволяет вызвать реализацию базового класса. Более общий смысл — продолжить поиск по порядку наследования; при сложном множественном наследовании это не просто «всегда прямой родитель».

`label` переопределён: одинаковый вызов на разных объектах может выполнять разную реализацию. Это пример **полиморфизма** — работы через общую форму действия. В Python для него не обязательно общее наследование: достаточно, чтобы объект поддерживал нужную операцию.

**Композиция** означает, что объект содержит другие объекты. Например, учебный курс содержит список уроков. Для отношения «содержит» обычно естественна композиция, а не наследование «курс является уроком».

---

**Специальные методы связывают класс с обычными средствами языка, а `dataclass` пишет типовой код за нас.** Специальные методы связывают класс с обычными средствами языка. `__repr__` задаёт представление для разработчика, `__str__` — текстовое представление, `__len__` — поведение `len`, `__eq__` — сравнение через `==`. Не нужно придумывать произвольные имена с двойными подчёркиваниями: у известных имён есть определённые протоколы.

Если класс в основном хранит запись, модуль `dataclasses` сокращает однотипный код:

```python
from dataclasses import dataclass

@dataclass
class Point:
    x: float
    y: float

p = Point(1.0, 2.0)
q = Point(1.0, 2.0)
print(p)
print(p == q)
```

```output
Point(x=1.0, y=2.0)
True
```

Декоратор создаёт инициализацию и некоторые стандартные методы на основе полей. Записи `x: float` и `y: float` — аннотации ожидаемых типов, которые объясним в уроке о читаемости кода. Они не преобразуют аргументы автоматически.

Для независимого изменяемого поля применяют фабрику:

```python
from dataclasses import dataclass, field

@dataclass
class Course:
    name: str
    lessons: list[str] = field(default_factory=list)
```

`default_factory=list` создаёт новый список для каждого экземпляра. Мы снова видим общую закономерность: изменяемые данные требуют явного решения о совместном или независимом владении.

---

**Итого.**

- `class` описывает тип; вызов класса создаёт экземпляр, `__init__` его настраивает.
- `self` — экземпляр, для которого вызван метод; `self.x` — атрибут экземпляра.
- Изменяемый атрибут класса общий для всех экземпляров; свои данные создают в `__init__`.
- `@property` — вычисляемое свойство без скобок; наследование уточняет поведение, композиция — «содержит».
- `@dataclass` создаёт `__init__`, `__repr__` и `__eq__` по полям.
