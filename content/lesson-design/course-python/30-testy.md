**Дополнительный урок — для продвинутых.** Он для тех, кто пишет программы, которые нужно поддерживать и проверять: в темах ЕГЭ аннотации и тесты не нужны, но приём «быстрое решение против медленного эталона» полезен и на экзамене. Задачи основных уроков решаются без него.

Главная идея урока: **код пишут так, чтобы его можно было прочитать и проверить: понятные имена, аннотации договорённости и автоматические проверки на выбранных и случайных примерах**. Опора — `assert` и подбор проверочных примеров из урока об исключениях, разделение программы на части из урока о модулях.

Сквозной пример урока — функция поиска максимального отрицательного числа: аннотируем её, напишем модульные тесты и сравним быстрое решение с медленным эталоном.

---

**Код должен объяснять задачу именами, константами и комментариями о причинах.** Ясные имена, короткие функции и явные условия обычно полезнее сокращения числа строк. Имя `count` говорит о количестве, `total` — о сумме, `best` — о выбранном лучшем результате. Если рядом существуют максимум значения и максимум суммы пары, назови их по-разному.

Избегай **магических чисел** — необъяснённых констант. Если 86400 обозначает число секунд в сутках, имя `SECONDS_PER_DAY` делает смысл видимым. Заглавные буквы — соглашение о постоянном значении; Python не запрещает его изменить.

Комментарий должен объяснять решение, ограничение или причину. Комментарий «увеличиваем i» рядом с `i += 1` обычно менее полезен, чем «левая граница больше не может дать допустимое окно».

---

**Аннотация типа описывает ожидаемые данные, но Python её не проверяет.** **Аннотация типа** сообщает читателю и инструментам, какие данные ожидаются:

```python
def count_positive(numbers: list[int]) -> int:
    return sum(number > 0 for number in numbers)

print(count_positive([3, -1, 0, 5]))
```

```output
2
```

После параметра стоит ожидаемый тип, после `->` — тип результата. `list[int]` означает список целых. Логические значения в арифметике ведут себя как 0 и 1, поэтому сумма истинных сравнений считает их количество.

Python не проверяет эти аннотации при вызове. Для анализа без запуска используют отдельные инструменты проверки типов. Они помогают находить несоответствия, но не доказывают математическую правильность алгоритма.

```python
def maximum_negative(numbers: list[int]) -> int | None:
    best = None
    for number in numbers:
        if number < 0 and (best is None or number > best):
            best = number
    return best

print(maximum_negative([5, -9, -2, 0]), maximum_negative([]))
```

```output
-2 None
```

`int | None` в Python 3.10+ означает один из двух вариантов результата. Это помогает помнить про отсутствие ответа. Если функция принимает любой перебираемый источник, точнее будет `Iterable[int]` из `collections.abc`, а не обязательно `list[int]`.

Аннотация — часть описания договорённости. Проверку диапазона, запрет пустого входа и изменение аргументов часто надо описать отдельно в документации.

---

**Модульный тест — программа, которая сравнивает поведение функции с ожидаемым.** **Тест** — программа, сравнивающая фактическое поведение с ожидаемым. **Модульный тест** проверяет небольшую самостоятельную часть, например функцию. Разделённые вычисление и ввод позволяют делать это без ручного набора данных.

```python
import unittest

def maximum_negative(numbers):
    best = None
    for number in numbers:
        if number < 0 and (best is None or number > best):
            best = number
    return best

class MaximumNegativeTests(unittest.TestCase):
    def test_mixed_values(self):
        self.assertEqual(maximum_negative([5, -9, -2, 0]), -2)

    def test_no_negative_values(self):
        self.assertIsNone(maximum_negative([0, 4]))

    def test_empty_input(self):
        self.assertIsNone(maximum_negative([]))

if __name__ == "__main__":
    unittest.main()
```

`unittest.TestCase` предоставляет методы проверок. Имя метода начинается с `test_`, чтобы система обнаружила тест. `assertEqual` требует равенство, `assertIsNone` — значение `None`. В отличие от инструкции `assert`, это обычные методы тестовой библиотеки, они не исчезают из-за `-O`. Запуск печатает точки для пройденных тестов и строку `OK`; время прогона в отчёте каждый раз своё.

---

**Быстрое решение проверяют медленным, но очевидным эталоном.** Оптимизированный алгоритм может быть трудно проверить глазами. Для маленьких данных напиши очевидный полный перебор, затем сравнивай результаты. Медленный вариант здесь служит независимым образцом, поэтому желательно, чтобы он не повторял ту же самую хитрую логику.

Например, сумму цифр можно считать арифметикой, а эталон — прямо через запись числа:

```python
import random

def digit_sum(number):
    number = abs(number)
    total = 0
    while number > 0:
        total += number % 10
        number //= 10
    return total

def digit_sum_slow(number):
    return sum(int(c) for c in str(abs(number)))

rng = random.Random(42)
for _ in range(1000):
    n = rng.randint(-10**6, 10**6)
    assert digit_sum(n) == digit_sum_slow(n), n
print("совпадает на 1000 случайных числах")
```

```output
совпадает на 1000 случайных числах
```

Договорённость — целые числа любого знака. При случайной генерации используй фиксированное начальное состояние генератора, например `random.Random(42)`, чтобы ошибку можно было воспроизвести. Случайные тесты дополняют, а не заменяют специально выбранные границы: число 0 случайно может и не выпасть.

---

**Иногда проверяют не ответ, а свойство, которое ему обязано принадлежать.** Иногда полезно проверять общие свойства. После сортировки должны сохраниться количество и набор элементов с учётом повторов. Для перевода основания `int(запись, base)` от записи числа должно давать исходное число. Каждый найденный делитель обязан делить число без остатка, а список делителей должен содержать 1 и само положительное число.

```python
from collections import Counter

data = [5, 3, 5, -1, 0]
result = sorted(data)
ordered = all(a <= b for a, b in zip(result, result[1:]))
print(ordered, Counter(result) == Counter(data))
```

```output
True True
```

Однако отдельное свойство может пропустить ошибку: список `[1, n]` содержит только настоящие делители, но не все. Поэтому проверяй и допустимость найденного, и полноту решения.

---

**Итого.**

- Имена, константы и комментарии объясняют смысл и причины, а не пересказывают код.
- Аннотации `list[int]`, `int | None` описывают договорённость; Python их не проверяет.
- `unittest`: методы `test_…` с `assertEqual`, `assertIsNone` и другими.
- Быстрое решение сравнивают с медленным эталоном на случайных данных с фиксированным генератором.
- Свойства результата проверяют вместе с полнотой: одно свойство может пропустить ошибку.
