Главная идея урока: **готовые средства лежат в модулях, и `import` делает их имена доступными в программе; свой код тоже удобно делить на части по задачам**. Опора — функции двух прошлых уроков: модуль — это файл с такими же определениями, и дальше в курсе готовые модули будут подключаться постоянно.

Сквозной пример урока — модуль `math` и наибольший общий делитель 18 и 24.

---

**Модуль — файл с готовыми определениями; `import` подключает его по имени.** **Модуль** обычно соответствует Python-файлу с определениями и инструкциями. **Библиотека** — набор готовых средств для решения задач. **Стандартная библиотека** поставляется вместе с Python; сторонние библиотеки устанавливаются отдельно. **Пакет** организует связанные модули под общим именем; в обычном варианте это папка с файлом `__init__.py`.

```python
import math

print(math.isqrt(50))
print(math.gcd(18, 24))
```

```output
7
6
```

`import math` делает доступным имя модуля. Точка выбирает средство внутри него. `isqrt` возвращает точную целую часть квадратного корня неотрицательного целого: 7² = 49 ≤ 50 < 64. `gcd` находит наибольший общий делитель.

Другая форма импорта:

```python
from math import isqrt
print(isqrt(50))
```

```output
7
```

Теперь в текущую область добавлено непосредственно имя `isqrt`. Запись `import math as m` задаёт короткое имя `m`. Обычно избегай `from module import *`: становится труднее понимать происхождение имён и конфликты.

В `math` есть и округления, и точное сложение дробных чисел. `floor` округляет вниз, `ceil` — вверх; `fsum` складывает дробные числа, не накапливая погрешность:

```python
from math import ceil, floor, fsum

print(floor(-2.5), ceil(-2.5))
total = 0
for _ in range(10):
    total += 0.1
print(total, fsum([0.1] * 10))
```

```output
-3 -2
0.9999999999999999 1.0
```

Цикл-накопитель десять раз прибавлял приближённое 0.1, и погрешности сложились. `fsum` учитывает их и даёт 1.0. Встроенный `sum` в Python 3.12+ тоже складывает дробные числа точнее простого цикла.

Не называй свой файл `math.py`, `random.py` или `json.py`, если собираешься импортировать одноимённый стандартный модуль: локальный файл может его заслонить.

---

**Свой модуль — это обычный файл; условие `__name__ == "__main__"` отделяет запуск от импорта.** Файл `calculations.py` может содержать:

```python
def square(number):
    return number * number
```

В соседнем `main.py`:

```python
from calculations import square

def main():
    print(square(7))

if __name__ == "__main__":
    main()
```

При обычном прямом запуске файла его специальное имя `__name__` равно `"__main__"`. При импорте оно обычно равно имени модуля. Поэтому условие позволяет отделить использование определений от запуска пользовательского сценария: запуск `main.py` напечатает 49, а импорт `main` из другого файла ничего не напечатает.

При первом импорте в обычном процессе выполняется код верхнего уровня модуля. Повторный импорт обычно использует уже загруженный модуль. Определения функций выполняются, но их тела ждут вызова. Поэтому нежелательные `input()` на верхнем уровне могут неожиданно остановить даже импорт.

---

**Сторонние пакеты ставят в виртуальную среду проекта.** **Зависимость** — библиотека, которую использует проект. **Виртуальная среда** хранит отдельный набор установленных пакетов для проекта, чтобы разные проекты не мешали друг другу версиями. Она не является защитной песочницей для недоверенного кода.

Для примеров этого курса дополнительные пакеты не нужны, поэтому команды — в свёрнутом блоке.

<details class="proof" markdown="1">
<summary>Тонкости: виртуальная среда и pip</summary>

Команды терминала:

```shell
python -m venv .venv
```

`-m` запускает модуль как программу. Здесь стандартный `venv` создаёт папку окружения. Можно использовать интерпретатор из неё напрямую, без активации:

```shell
# Windows
.venv\Scripts\python -m pip --version

# Linux и macOS
.venv/bin/python -m pip --version
```

`pip` управляет установкой пакетов. Общая форма установки — `python -m pip install имя_пакета`, выполненная нужным интерпретатором. Важна связь: пакет установлен в конкретное окружение, а не «во все Python на компьютере».

Зависимости проекта можно перечислить с версиями в `requirements.txt`, а устанавливать командой `python -m pip install -r requirements.txt`. Для распространяемых современных проектов метаданные часто задаются в `pyproject.toml`; подробная упаковка — отдельный следующий этап.

**Даже небольшую программу полезно делить на чтение, вычисление и вывод.** Удобно отделять чтение данных, вычисление ответа и вывод. Тогда вычисляющую функцию можно проверять на обычных списках без подготовки файлов. Не нужно создавать десятки модулей ради десяти строк: разделяй по реальным самостоятельным задачам.

```python
def count_multiples(a, b, d):
    count = 0
    for n in range(a, b + 1):
        if n % d == 0:
            count += 1
    return count

def main():
    print(count_multiples(1, 100, 7))

if __name__ == "__main__":
    main()
```

```output
14
```

`count_multiples` — тот же счётчик кратных, что в уроке о `for`, только оформленный функцией. Она ничего не знает о вводе и выводе: её можно вызвать с другими границами или проверить отдельно.

---

**Итого.**

- `import math` — доступ через `math.имя`; `from math import isqrt` — имя напрямую.
- `math.isqrt`, `gcd`, `floor`, `ceil`, `fsum` — точные готовые действия с числами.
- Свой файл не называют как стандартный модуль.
- `if __name__ == "__main__":` выполняет запуск только при прямом запуске файла.
- Программу делят на чтение, вычисление и вывод; вычисление проверяют отдельно.
