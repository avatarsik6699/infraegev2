Главная идея урока: **`for` получает элементы от итератора, который помнит позицию и выдаёт значения по одному; одноразовый итератор после исчерпания пуст**. На этом устроены `map`, генераторные выражения и `yield`. Опора — все источники, по которым уже ходил `for`, и курсор файла из урока о файлах: здесь видно, что у них общий механизм.

Сквозной пример урока — строка `"10 -2 7"`: превратим её в числа через `map` и посмотрим, почему второй проход по тому же `map` пуст.

---

**`for` уже ходил по многим источникам — у всех один механизм.** Вспомним, что выдаёт `for` для каждого знакомого источника:

| Источник | Что получает переменная цикла | Урок |
| --- | --- | --- |
| `range(a, b, step)` | Числа арифметической последовательности | о `for` |
| Строка | Символы по порядку | о строках |
| Список, кортеж | Элементы по порядку | о списках и кортежах |
| Словарь | Ключи; `.items()` — пары | о словарях |
| Множество | Элементы без гарантии порядка | о множествах |
| `enumerate`, `zip` | Пары «номер — элемент», элементы по позициям | о кортежах |
| Открытый файл | Строки файла по одной | о файлах |

Этот урок объясняет, что у них общего: каждый источник выдаёт `for` **итератор**, а итератор помнит позицию.

---

**Итератор помнит текущую позицию и выдаёт следующий элемент.** Теперь уточним механизм. **Итератор** — объект, который помнит текущую позицию и умеет выдавать следующий элемент. **Перебираемый объект** умеет предоставить итератор. Список можно обходить заново; отдельный итератор обычно движется только вперёд.

```python
numbers = [10, 20, 30]
iterator = iter(numbers)
print(next(iterator))
print(next(iterator))
print(list(iterator))
print(list(iterator))
```

```output
10
20
[30]
[]
```

`iter` получает итератор, `next` запрашивает следующий элемент. После исчерпания `next` без запасного значения вызывает `StopIteration`. Цикл `for` обрабатывает этот сигнал как нормальное окончание. Можно использовать `next(iterator, None)`, чтобы при исчерпании получить указанное значение, но нужно отличать его от настоящего элемента `None`, если такой допустим.

Это объясняет, почему прочитанный файл и использованный `map` не стоит бездумно обходить второй раз: это источники с текущим состоянием. `range`, напротив, — повторно перебираемый объект, а не одноразовый итератор.

Итератор устроен так же, как открытый файл в уроке о файлах: у него есть позиция, и она движется только вперёд. Те же шаги для списка `[10, 20, 30]`:

---

**`map` применяет функцию к каждому элементу, `filter` оставляет подходящие — оба постепенно.** `map(function, source)` постепенно применяет функцию к каждому элементу. `filter(function, source)` постепенно пропускает только элементы с истинным результатом проверки.

```python
parts = "10 -2 7".split()
converted = map(int, parts)
numbers = list(converted)
print(numbers)
print(list(converted))
print(list(filter(lambda x: x > 0, numbers)))
```

```output
[10, -2, 7]
[]
[10, 7]
```

`map` ещё не список. `list` потребляет его и собирает результаты, поэтому второй `list(converted)` пуст. Запись `a, b = map(int, input().split())` означает: прочитать строку, разбить, последовательно преобразовать две части, распаковать в два имени. Если частей не две, распаковка завершится ошибкой.

```python
a, b = map(int, input().split())
print(a + b)
```

```console
⟪3 4⟫
7
```

Списковое включение `[int(x) for x in parts]` часто читается не хуже. Выбор между ними — вопрос ясности, а не обязательный приём профессионального кода.

**Генераторное выражение выдаёт результаты по одному, не создавая список.**

```python
numbers = [2, 4, 6]
total = sum(x * x for x in numbers)
print(total)
print(sum(1 for x in range(1, 101) if x % 7 == 0))
```

```output
56
14
```

Выражение `x * x for x in numbers` выдаёт результаты по одному. Оно называется **генераторным выражением**. В отличие от спискового включения, оно не создаёт сразу весь список квадратов. Если оно единственный аргумент вызова, отдельные внешние скобки можно не писать. Вторая строка считает подходящие числа: каждое кратное 7 даёт единицу, а `sum` их складывает.

Это экономит память, когда элементы нужны только один раз. Но генератор также исчерпывается. И он не делает автоматически быстрым алгоритм, который всё равно рассматривает миллиард комбинаций.

---

**Функция с `yield` выдаёт значения и приостанавливается между ними.**

```python run squares_up_to.py
def squares_up_to(limit):
    n = 1
    while n * n <= limit:
        yield n * n
        n += 1

print(list(squares_up_to(20)))
```

```output
[1, 4, 9, 16]
```

`yield` выдаёт значение и приостанавливает функцию, сохранив её локальное состояние. При следующем запросе выполнение продолжается после `yield`. Обычный `return` завершает вызов окончательно.

Функция, в теле которой есть `yield`, при вызове создаёт генератор. Её тело начинает выполняться при запросе элементов. Это важно, если внутри находятся проверка аргументов, чтение файла или другие действия: они произойдут не обязательно в момент создания генератора.

Запусти программу выше по шагам. Каждый `yield` отдаёт значение и ставит функцию на паузу: её переменные остаются на месте с пометкой «на паузе», а при следующем запросе выполнение продолжается со строки после `yield` с прежним значением `n`.

---

**Итого.**

- `for` берёт элементы у итератора; `iter` и `next` делают это вручную.
- Итератор одноразовый: после исчерпания он пуст; `range` и список можно обходить снова.
- `map` и `filter` работают постепенно; `list(...)` собирает их результаты.
- Генераторное выражение в `sum(...)`, `any(...)` не создаёт промежуточный список.
- `yield` выдаёт значение и приостанавливает функцию до следующего запроса.
