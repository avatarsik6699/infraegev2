**Дополнительный урок — для продвинутых.** Он для тех, кто хочет понимать устройство библиотек: в темах ЕГЭ из этих механизмов встречается только готовый декоратор `@cache`. Задачи основных уроков решаются без него.

Главная идея урока: **функции в Python — такие же значения, как числа: их создают внутри других функций, возвращают и оборачивают; на этом держатся замыкания, декораторы и контекстные менеджеры**. Урок стоит читать после уверенного освоения функций. Механизмы ниже полезны для понимания библиотек, но не обязательны в каждом решении. Опора — модель вызова из модуля «Функции» и декоратор `@cache` из урока о рекурсии.

Сквозной пример урока — функция `make_multiplier`, которая создаёт другие функции, и декоратор, который сообщает о вызове.

---

**Внутренняя функция помнит имена внешней — это замыкание.** Функция может быть создана внутри другой функции и использовать её локальные имена. Если такая внутренняя функция продолжает использовать окружающие связи после завершения внешней, возникает **замыкание**.

```python
def make_multiplier(factor):
    def multiply(number):
        return number * factor
    return multiply

triple = make_multiplier(3)
double = make_multiplier(2)
print(triple(7), double(7))
```

```output
21 14
```

Возвращается сама функция `multiply`, не её вызов. Она сохраняет доступ к `factor` этого конкретного вызова `make_multiplier`: у `triple` это 3, у `double` — 2.

Замыкание обычно сохраняет доступ к переменной, а не обязательно снимок её значения в момент создания. Поэтому функции, созданные внутри цикла и обращающиеся к одной переменной цикла, при последующем вызове могут все увидеть её последнее значение:

```python
late = [lambda: i for i in range(3)]
snapshot = [lambda i=i: i for i in range(3)]
print([f() for f in late], [f() for f in snapshot])
```

```output
[2, 2, 2] [0, 1, 2]
```

Если нужен снимок, часто используют параметр по умолчанию, как во втором списке, или отдельный вызов создающей функции.

---

**Декоратор получает функцию и возвращает обёртку с дополнительным поведением.** Декоратор получает функцию и возвращает объект, который будет использоваться под её именем. В простом варианте возвращается функция-обёртка:

```python
from functools import wraps

def announce(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        print("Вызов", function.__name__)
        result = function(*args, **kwargs)
        return result
    return wrapper

@announce
def add(a, b):
    return a + b

print(add(2, 5))
```

```output
Вызов add
7
```

Сначала сообщение о вызове, затем 7. `*args` собирает позиционные аргументы, `**kwargs` — именованные; при вызове `function(*args, **kwargs)` они распаковываются обратно. `wraps` сохраняет полезные метаданные исходной функции, например имя и документацию. `__name__` — имя функции как атрибут.

Если забыть `return result`, обёртка будет всегда возвращать `None`, даже если исходная функция вычисляла число. Сохранение поведения — часть договорённости декоратора. Готовый `@cache` из урока о рекурсии устроен так же: обёртка сначала ищет ответ в словаре и вызывает исходную функцию, только если его там нет.

**Контекстный менеджер задаёт, что делать при входе в блок `with` и при выходе из него.** Объект, поддерживающий вход и выход из блока `with`, называют **контекстным менеджером**. У обычных классов это методы `__enter__` и `__exit__`. Удобно также создавать их через `contextlib.contextmanager`:

```python
from contextlib import contextmanager
from time import perf_counter

@contextmanager
def measured(label):
    start = perf_counter()
    try:
        yield
    finally:
        elapsed = perf_counter() - start
        print(label, elapsed)

with measured("Вычисление"):
    result = sum(range(100_000))
```

Код до `yield` выполняется при входе, блок пользователя — в момент паузы, завершающая часть — при выходе. Здесь генератор должен передать управление ровно один раз. `finally` обеспечивает измерение и при возникновении обычного исключения внутри блока. Вывод — подпись и время — каждый раз разный, поэтому здесь не показан. Файл в `with open(...)` закрывается тем же механизмом.

**`match` проверяет форму значения и раздаёт его части по именам.** В Python 3.10+ конструкция `match` проверяет форму значения. Она полезна для разбора небольших команд и вложенных данных:

```python
for line in ["move 3 5", "quit", "jump"]:
    command = line.split()
    match command:
        case ["move", x, y]:
            print(int(x), int(y))
        case ["quit"]:
            print("Завершение")
        case _:
            print("Неизвестная команда")
```

```output
3 5
Завершение
Неизвестная команда
```

Шаблон `['move', x, y]` требует последовательность из трёх элементов с первым элементом `"move"`, а остальные связывает с именами. Это не просто другая запись цепочки сравнений. Обычное имя в шаблоне чаще захватывает значение, а не сравнивает его с прежней переменной; для сравнения констант необходимо понимать правила шаблонов. Новичку нередко проще обычный `if`.

---

**Текст и байты — разные данные, между ними стоит кодировка.** Строка `str` — символы. `bytes` — последовательность целых значений от 0 до 255, представляющих сырые байты. Для перевода между ними нужна кодировка:

```python
text = "Привет"
data = text.encode("utf-8")
restored = data.decode("utf-8")
print(restored == text)
print(len(text), len(data))
```

```output
True
6 12
```

Количество байтов и количество символов не обязаны совпадать: в UTF-8 каждая русская буква занимает два байта. Чтение файла в режиме `rb` даёт байты. Преобразование `str(data)` не заменяет декодирование: оно создаёт текстовое представление байтового объекта.

**Асинхронность позволяет ждать несколько внешних операций сразу, но не ускоряет вычисления.** Когда программа ждёт сеть или другой внешний источник, она могла бы в это время обслужить другую задачу. **Асинхронное выполнение** позволяет описать такие ожидания и передавать управление между задачами. Это не обязательно одновременные вычисления на разных ядрах.

```python
import asyncio

async def report(name, delay):
    await asyncio.sleep(delay)
    return name

async def main():
    results = await asyncio.gather(
        report("A", 0.02),
        report("B", 0.01),
    )
    print(results)

if __name__ == "__main__":
    asyncio.run(main())
```

```output
['A', 'B']
```

`async def` создаёт асинхронную функцию; её вызов создаёт объект корутины, выполнение которого надо организовать. `await` ожидает результат, позволяя циклу событий выполнять другую готовую работу. `gather` организует совместное выполнение переданных операций и возвращает результаты в порядке аргументов, а не порядке завершения: B закончилась раньше, но стоит второй. `asyncio.run` запускает внешний цикл событий в обычном скрипте. В среде с уже работающим циклом, например некоторых ноутбуках, используют её собственный способ запуска, часто `await main()`.

Обычное тяжёлое вычисление без точек ожидания блокирует такой цикл. Замена `def` на `async def` сама по себе не ускоряет перебор делителей. Потоки и отдельные процессы — другие механизмы конкурентного выполнения с собственными правилами общего состояния. Их стоит изучать под конкретную задачу после этой основы.

---

**Итого.**

- Замыкание — внутренняя функция с доступом к именам внешней; оно видит переменную, а не снимок.
- Декоратор — функция, которая получает функцию и возвращает обёртку; обёртка должна вернуть результат.
- Контекстный менеджер описывает вход и выход блока `with`; `finally` выполняется и при ошибке.
- `match` проверяет форму значения; `str.encode` и `bytes.decode` переводят текст и байты.
- `async`/`await` помогают ждать внешние операции, но не ускоряют вычисления.
