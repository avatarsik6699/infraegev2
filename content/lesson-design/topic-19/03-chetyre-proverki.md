**Рассуждения подтемы 2 переводятся в Python почти дословно: четыре функции повторяют определения четырёх групп позиций.** Без рекурсии и без новых идей — только правила игры, `any` и `all`. Программа нужна почти во всех задачах экзамена — там, где ручная таблица слишком длинна: при пороге в сотни и тысячи камней или при ходах с условиями.

Переводим в код ту же игру: +1 или ×2, победа при s ≥ 21. Программа должна получить то же, что ручной разбор: неудачный ход Пети возможен с S = 6, `L1` — 10, `W2` — 5 и 9, `L2` — 8.

---

**Правила игры записываются двумя функциями: какие позиции получаются одним ходом и закончилась ли игра.** Обозначения:

- `p` — рассматриваемая позиция;
- `q` — позиция после одного разрешённого хода;
- `moves(p)` — список всех позиций, которые можно получить одним ходом;
- `finished(p)` — проверка, закончилась ли игра.

Правила нашей игры — две {{def|функции}}:

```python
def moves(s):
    return [s + 1, s * 2]


def finished(s):
    return s >= 21
```

Проверим их на нескольких позициях:

```python
print(moves(10))
print(finished(20), finished(21), finished(40))
```

```output
[11, 20]
False True True
```

---

**Запись `any(finished(q) for q in moves(p))` спрашивает: есть ли ход, после которого игра окончена?** Для каждой позиции `q`, полученной одним ходом из `p`, проверить окончание игры. Затем выяснить, есть ли хотя бы один результат `True`. Её можно записать длиннее — {{list|списком}} и {{for|циклом}}. Пройди программу по шагам для p = 11:

```python run checks.py
def moves(s):
    return [s + 1, s * 2]


def finished(s):
    return s >= 21


p = 11
checks = []
for q in moves(p):
    checks.append(finished(q))

print(checks, any(checks))
```

```output
[False, True] True
```

Ход 11 → 12 игру не закончил, ход 11 → 22 закончил, поэтому `any` даёт `True`. Короткая запись `any(finished(q) for q in moves(p))` делает то же без промежуточного списка: внутри — {{genexp|генераторное выражение}}, а {{anyall|`any`}} получает результаты по одному.

---

**Четыре проверки — это определения групп, записанные кодом.** {{andor|`not`, `and`, `or`}} — отрицание, «оба условия», «хотя бы одно»:

```python
def win1(p):
    return (
        not finished(p)
        and any(finished(q) for q in moves(p))
    )


def lose1(p):
    return (
        not finished(p)
        and all(win1(q) for q in moves(p))
    )


def win2(p):
    return (
        not finished(p)
        and not win1(p)
        and any(lose1(q) for q in moves(p))
    )


def lose2(p):
    return (
        not finished(p)
        and not lose1(p)
        and all(win1(q) or win2(q) for q in moves(p))
    )
```

Поясним функции по очереди:

- `win1(p)` — игра ещё не закончилась, и существует ход, который её завершает;
- `lose1(p)` — игра ещё не закончилась, и после любого нашего хода соперник получает возможность немедленно выиграть;
- `win2(p)` — игра ещё не закончилась, немедленно выиграть нельзя, но можно передать сопернику позицию `L1`;
- `lose2(p)` — игра ещё не закончилась, позиция не является `L1`, а после любого нашего хода соперник получает `W1` или `W2`.

Отдельно проверим возможность неудачного хода:

```python
def after_mistake(p):
    return (
        not finished(p)
        and any(win1(q) for q in moves(p))
    )
```

Здесь стоит `any`, потому что нам достаточно **одного** хода Пети, после которого соперник сможет выиграть сразу.

---

**`not finished(p)` стоит первым, чтобы не анализировать уже завершившуюся игру как активную.** Например, `win1(22)` должно вернуть `False`: из 22 уже не требуется выигрывать новым ходом — партия закончилась раньше. Это важно и внутри других функций. Если Петя своим ходом получил 22, нельзя продолжать рассуждение так, будто Ваня теперь получил удобную позицию для следующего хода.

В выражении `not finished(p) and …` Python сначала проверяет левую часть. **Если игра закончилась, левая часть равна `False`, и дальнейшие ходы вычислять уже не нужно.**

```python
print(win1(22), win1(11), lose1(22), lose1(10))
```

```output
False True False True
```

---

**Поиск стратегии и поиск ответа — два отдельных действия: сначала собираем все подходящие значения S.** Не нужно смешивать проверку одного значения S с поиском минимума. {{for|`range(1, 21)`}} перебирает числа от 1 до 20 включительно: правая граница в `range` не включается.

```python
answer19_mistake = []
answer19_guaranteed = []
answer20 = []
answer21 = []

for s in range(1, 21):
    p = s

    if after_mistake(p):
        answer19_mistake.append(s)

    if lose1(p):
        answer19_guaranteed.append(s)

    if win2(p):
        answer20.append(s)

    if lose2(p):
        answer21.append(s)

print("19, после неудачного хода:", min(answer19_mistake))
print("19, при любом ходе:", answer19_guaranteed)
print("20:", answer20)
print("21:", answer21)
```

```output
19, после неудачного хода: 6
19, при любом ходе: [10]
20: [5, 9]
21: [8]
```

Это те же числа, что и в ручной таблице подтемы 2. {{agg|`min(...)`}} находит наименьшее число из найденных.

---

**Форма ответа определяется условием, а не программой.** Список найденных значений один, а взять из него нужно ровно то, о чём спрашивают:

:::pick Что спрашивают и что взять из списка
- *Все значения | весь список по возрастанию | `answer20`
- Наименьшее | первое при переборе по возрастанию | `min(answer21)`
- Наибольшее | последнее | `max(answer21)`
- Два наименьших | первые два | `answer20[:2]`
- Два наибольших | последние два | `answer20[-2:]`
- Наименьшее и наибольшее | первое и последнее | `answer20[0], answer20[-1]`
- Количество значений | длина списка | `len(answer20)`
- Сумма значений | сумма списка | `sum(answer20)`
:::

Если программа нашла три подходящих значения, а условие просит **два наименьших**, это не ошибка программы. Просто требуется выбрать часть найденных значений. Срез `[:2]` — {{slice|первые два элемента}}.

---

**Если верхняя граница S не указана, перебор до случайного числа сам по себе не доказывает, что дальше ничего нет.** Для поиска первого или первых нескольких значений можно двигаться по возрастанию до их нахождения. **Для поиска максимума или всех значений нужна обоснованная граница.** В играх с увеличением кучи граница задана самим условием: S меньше порога. Где её приходится выводить, разберём в подтеме 5.

---

**Итого.**

- `moves` и `finished` — правила игры, всё остальное от правил не зависит.
- `win1`, `lose1`, `win2`, `lose2` и `after_mistake` дословно повторяют определения: «есть ход» — `any`, «все ходы» — `all`.
- `not finished(p)` стоит первым: завершённая партия не продолжается.
- Сначала собираем все подходящие S, потом берём из списка то, что спрашивают.
