**Игры с уменьшением кучи и игры с ходами по условию решаются теми же логическими проверками: меняются только разрешённые действия и условие окончания.** В последних вариантах кучу часто уменьшают — вычитанием и делением с округлением, а ходы бывают разрешены только при условии: «если число чётное», «если делится на 3».

Учебная игра: разрешено убрать один камень либо разделить количество камней на 2 с округлением вниз, выигрывает получивший не более 10 камней, первоначально S ≥ 11.

---

**Уменьшение кучи записывается теми же двумя функциями.** Правила:

```python
def moves(s):
    return [s - 1, s // 2]


def finished(s):
    return s <= 10
```

Операция {{intdiv|`//`}} для неотрицательных целых чисел означает целочисленное деление с округлением вниз:

```python
print(20 // 2, 21 // 2, 22 // 2)
```

```output
10 10 11
```

Поэтому из 21 можно выиграть сразу: 21 → 10. А из 22 делением получится 11 — игра ещё продолжается.

---

**Ближайшие группы позиций находят так же, от конца игры.** `W1` — 11, 12, …, 21. `L1` — 22, потому что 22 → 21 или 22 → 11, и оба результата — `W1`. Для `W2` нужно одним ходом попасть в 22. Убавлением единицы: S − 1 = 22, S = 23. Делением на 2 с округлением вниз: 44 // 2 = 22 и 45 // 2 = 22. Поэтому **W2 = 23, 44, 45**.

Для этой игры `L2` — позиции 24 и 46. Проверим: 24 → 23 или 24 → 12, здесь 23 — `W2`, а 12 — `W1`. И 46 → 45 или 46 → 23, здесь оба результата — `W2`.

</figure>

Функции подтемы 3 с новыми `moves` и `finished` дают то же самое. Перебор идёт **вверх от порога**: S ≥ 11.

```python
print([s for s in range(11, 60) if lose1(s)])
print([s for s in range(11, 60) if win2(s)])
print([s for s in range(11, 60) if lose2(s)])
```

```output
[22]
[23, 44, 45]
[24, 46]
```

Таким образом, даже при уменьшении кучи работают те же правила: есть победный ход; все ходы дают сопернику немедленную победу; есть переход в такую ловушку; все ходы дают сопернику победу за один или два его хода.

---

**Округление нужно переносить из условия буквально.** Для положительных целых чисел каждый вид деления записывается по-своему:

:::pick Что требует условие и как записать
- *Деление с округлением вниз | `s // d` | 21 // 2 = 10
- Деление с округлением вверх | `(s + d - 1) // d` | (21 + 1) // 2 = 11
- Деление только при делимости без остатка | сначала проверить `s % d == 0` | 21 на 2 не делится — хода нет
:::

`%` возвращает остаток от деления. Обычное `/` может дать дробное число, а {{round|`round()`}} округляет по другому правилу. **Подставлять их вместо нужного округления нельзя:**

```python
print(10 % 3, 12 % 3)
print(21 / 2, round(10.5), (21 + 1) // 2)
```

```output
1 0
10.5 10 11
```

Деление вверх через {{ceil|`(s + d - 1) // d`}} работает без дробей.

---

**Граница для деления вниз — последнее число, которое ещё делится «в порог».** Например, s // 4 ≤ 10 выполняется вплоть до s = 43, потому что 43 // 4 = 10, но 44 // 4 = 11. **Поэтому граница здесь 43, а не 40.**

---

**Наименьшее S ищут перебором вверх от порога, а для наибольшего нужна граница, выведенная из правил.** В убывающей игре верхнего предела S в условии нет: «S ≥ 11». Если спрашивают наименьшее значение или два наименьших, перебор просто идёт вверх, пока они не найдутся. Если спрашивают наибольшее или все значения, перебор до случайного числа ничего не доказывает (подтема 3).

Найдём наибольшее S, при котором Ваня может выиграть первым ходом после неудачного хода Пети. Быстрее всего куча уменьшается двумя делениями подряд: из S получается S // 2 // 2 = S // 4. Чтобы Ваня закончил игру, нужно S // 4 ≤ 10, а это выполняется только до S = 43 — граница из предыдущего шага. **Из любого S ≥ 44 даже самый быстрый спуск за два хода не доходит до 10**, значит, дальше подходящих S нет. Партия 43 → 21 → 10 возможна: ход Пети в 21 игру не заканчивает.

```python
found = [s for s in range(11, 44) if after_mistake(s)]
print(max(found))
```

```output
43
```

Для гарантии (`L1`) рассуждают наоборот: **после каждого хода Пети, даже самого слабого, у Вани должен быть победный ход**, поэтому границу даёт самый медленный ход Пети. Здесь самый медленный — −1: из S − 1 Ваня должен выиграть, то есть S − 1 ≤ 21, S ≤ 22.

---

**Если некоторые команды разрешены только при определённых условиях, в `moves` включаются только разрешённые действия.** Например, деление на 2 — только без остатка. Ход появляется в списке после проверки {{if|`if`}}:

```python
def moves(s):
    result = [s - 1]

    if s % 2 == 0:
        result.append(s // 2)

    return result


print(moves(13), moves(14))
print([s for s in range(11, 30) if lose1(s)])
```

```output
[12] [13, 7]
[13, 15, 17, 19, 21]
```

**Условие меняет всю картину групп.** Без него 13 была `W1` (13 // 2 = 6), а теперь из 13 есть только ход в 12, и это `L1`. Так же записывают любые ходы с условием: «если чётное — уменьшить вдвое, если кратно трём — на треть», «добавить делитель числа», а в двух кучах — «добавлять только в меньшую кучу»: проверка `if a <= b:` выбирает, какую кучу можно менять.

---

**Запрещённый результат удаляют из списка ходов.** Это делают {{comp|списковым включением}}. Если нужно попасть **ровно** в заданное число и превышение запрещено, необходимо не только изменить проверку окончания, но и убрать запрещённые ходы:

```python
def moves(s):
    candidates = [s + 1, s * 2]
    return [q for q in candidates if q <= 21]


def finished(s):
    return s == 21


print(moves(11), moves(15), finished(21))
```

```output
[12] [16] True
```

Конструкция `[q for q in candidates if q <= 21]` создаёт список из тех кандидатов `q`, для которых выполнено условие `q <= 21`. Так же запрещают, например, ход, после которого количество камней делится на 3: `q % 3 != 0`.

Если же превышение порога разрешено, но приводит к поражению сделавшего ход, это уже другой исход завершения. **Нельзя считать любой конец победой предыдущего игрока**: функция должна различать победное завершение и проигрышное.

---

**Позицию без ходов обрабатывают отдельно: `all` от пустого списка даёт `True`.** Функции подтемы 3 рассчитаны на игры, где у каждой незавершённой позиции есть хотя бы один разрешённый ход. Если ходы зависят от делителей, это не так. Пусть к куче можно добавить её делитель d, где 1 < d < s, а побеждает получивший не менее 30 камней. У простого числа таких делителей нет:

```python
def moves(s):
    return [s + d for d in range(2, s) if s % d == 0]


def finished(s):
    return s >= 30


print(moves(12), moves(7))
print(lose1(7))
```

```output
[14, 15, 16, 18] []
True
```

`lose1(7)` проверяет «все ходы ведут в `W1`», а ходов нет — и {{anyall|`all([])`}} даёт `True`: нет ни одного нарушения. Но из 7 Петя вообще не может сходить, и что это значит, решает условие. В задачах с делителями так бывает и с S = 1, и без такой проверки ответ получается на одно значение больше. Исправление — потребовать, чтобы ходы были: `moves(p) and all(...)`, или исключить такие S из перебора по условию.

---

**Итого.**

- Уменьшение кучи — те же функции с другими `moves` и `finished`; перебор S идёт вверх от порога.
- Округление переносят буквально: `//` — вниз, `(s + d - 1) // d` — вверх, `s % d == 0` — ход только при делимости.
- Для наибольшего S без верхней границы выводят границу: самый быстрый спуск для неудачного хода, самый медленный ход Пети — для гарантии.
- Ход по условию — `if` в `moves`, запрещённый результат — фильтр списка; позицию без ходов обрабатывают отдельно.
