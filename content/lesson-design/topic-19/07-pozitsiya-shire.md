**В позиции нужно хранить всю информацию, которая влияет на допустимые следующие ходы и на исход игры.** Иногда одного числа камней или пары куч для этого мало: правила запрещают повторять ход, вопрос задан без ограничения числа ходов или спрашивают не об одном S, а обо всех позициях сразу. Функции `moves`, `finished` и `f` из подтем 3–6 считаем определёнными выше в программе.

Основная игра урока — та же: +1 или ×2, победа при s ≥ 21; для запрета повтора к ней добавим ход +2.

**Если выбор следующего действия зависит от предыдущего, количества камней уже недостаточно для полного описания ситуации.** Например, правило: нельзя повторять ход, который только что сделал соперник. Тогда состояние должно хранить пару (количество камней, предыдущая команда). Почему? Потому что **при одинаковом количестве камней разрешённые действия могут различаться из-за разных предыдущих команд**: если в куче 5 и соперник только что добавил два камня, можно получить 6 или 10, но не 7.

Игра: можно добавить один или два камня либо удвоить кучу, нельзя повторять ход, который только что сделал соперник, победа при s ≥ 21. Позиция — кортеж `(s, last)`, где `last` — последняя команда; у начальной позиции её нет, поэтому там пустая строка `""`:

```python
def moves(p):
    s, last = p
    result = []
    if last != "+1":
        result.append((s + 1, "+1"))
    if last != "+2":
        result.append((s + 2, "+2"))
    if last != "×2":
        result.append((s * 2, "×2"))
    return result


def finished(p):
    return p[0] >= 21


print(moves((5, "+2")))
starts = [(s, "") for s in range(1, 21)]
print([p[0] for p in starts if not f(p, 1) and f(p, 2)])
print([p[0] for p in starts if not f(p, 1) and f(p, 3)])
print([p[0] for p in starts if not f(p, 2) and f(p, 4)])
```

```output
[(6, '+1'), (10, '×2')]
[10]
[5, 6, 7, 8, 9]
[4]
```

Функция `f` не изменилась: она работает с позицией только через `moves` и `finished`. **История меняет группы**: позиции 6, 7, 8 без запрета не были `W2`, а теперь Петя выигрывает из них вторым ходом — запрет мешает Ване уйти от ловушки.

Если запрет касается предыдущего хода **каждого конкретного игрока** («нельзя повторять свой прошлый ход»), потребуется помнить историю отдельно для игроков: позиция `(s, мой_прошлый, чужой_прошлый)`, а после хода два последних элемента меняются местами — следующий игрок видит свой прошлый ход на втором месте.

**Вопрос без ограничения числа ходов решается рекурсией «играть до конца».** Иногда спрашивают: «у Вани есть выигрышная стратегия, позволяющая ему выиграть при любой игре Пети» — без слов «первым» или «вторым». Тогда m не нужен. Позиция выигрышная для того, кто ходит, если **существует** ход, который сразу заканчивает игру или передаёт сопернику проигрышную позицию:

```python
from functools import cache


@cache
def win(s):
    return any(finished(q) or not win(q) for q in moves(s))


def moves(s):
    return [s + 1, s * 2]


def finished(s):
    return s >= 21


print([s for s in range(1, 21) if not win(s)])
```

```output
[2, 6, 8, 10]
```

Если все ходы ведут в выигрышные позиции противника, текущая позиция проигрышна: `any` даёт `False`, и Ваня выигрывает при любой игре Пети при S = 2, 6, 8, 10. Знакомые 10 (`L1`) и 8 (`L2`) здесь есть, а 2 и 6 — позиции, где Ваня выигрывает позже. `@cache` здесь нужен: без запоминания одни и те же позиции пересчитываются в разных партиях много раз.

**Различай два вида рекурсии.** Рекурсия с ограничением `m` останавливается, потому что число оставшихся ходов уменьшается. Рекурсия «играть до конца» требует уверенности, что бесконечные последовательности невозможны. В играх, где положительное количество камней строго увеличивается до верхнего порога или строго уменьшается до нижнего, завершение обосновать легко. Если разрешены и увеличение, и уменьшение, возможны возвращения к прежним позициям. Тогда простая неограниченная рекурсия требует дополнительного анализа.

**Иногда спрашивают не о начальном S, а обо всех позициях сразу — тогда перебирают пары куч.** Встречается такой вопрос: «Известно, что Петя смог выиграть первым ходом. Какое наименьшее число камней могло быть суммарно в двух кучах?» Начального S здесь нет: подходит любая позиция (a, b), из которой есть победный ход. Перебираем все пары {{nested|вложенными циклами}} и берём наименьшую сумму. Для двух куч с ходами +1 или ×2 и победой при сумме не менее 20:

```python
def moves(p):
    a, b = p
    return [(a + 1, b), (a * 2, b), (a, b + 1), (a, b * 2)]


def finished(p):
    return p[0] + p[1] >= 20


best = None
for a in range(1, 20):
    for b in range(1, 20):
        p = (a, b)
        wins = any(finished(q) for q in moves(p))
        if not finished(p) and wins:
            if best is None or a + b < best:
                best = a + b
print(best)
```

```output
11
```

Например, (1, 10): удвоение второй кучи даёт сумму 21. При сумме 10 не хватает даже лучшего хода: из (1, 9) получается 19. Рассуждением то же видно сразу: после удвоения большей кучи сумма равна a + b + max(a, b), и выгоднее всего, чтобы почти все камни были в одной куче.

---

**Итого.**

- Позиция хранит всё, что влияет на ходы и исход: при запрете повтора — последний ход, при запрете своего повтора — оба последних.
- Без ограничения числа ходов: `win(p) = any(конец или not win(q))` с `@cache`; нужно обосновать, что игра конечна.
- Если начального S нет, перебирают все позиции и берут нужную по условию.
