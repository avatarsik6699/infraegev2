**Рекурсия позволяет описать проверку стратегии одной функцией.** Так задания 19–21 решают на экзамене: одна функция заменяет четыре проверки подтемы 3 и работает для одной кучи, двух куч и убывающих игр. Она же удобнее всего для вопросов о третьем ходе.

Вернёмся к первой игре: +1 или ×2, победа при s ≥ 21. Главный пример — проверка f(5, 3): выигрывает ли Петя из 5 не позднее своего второго хода.

---

**На каждом шаге проверки возникает тот же вопрос — для другой позиции и с меньшим числом оставшихся ходов.** Ранее мы последовательно проверяли: можем ли выиграть сразу? А что получит соперник после нашего хода? А что получим мы после его ответа? Это и есть {{rec|рекурсия}}, знакомая по теме 16: функция вызывает саму себя, чтобы решить более маленькую часть той же задачи. **В нашем случае «меньше» означает: осталось рассмотреть на один ход меньше.** База рекурсии — две ситуации: игра уже окончена или ходов для проверки не осталось.

---

**Сначала разберём рекурсию в форме, где явно указаны игрок и проверяемая цель.** Пусть функция называется `can_win(p, turn, target, left)`:

| Параметр | Что хранит |
|---|---|
| `p` | Текущую позицию |
| `turn` | Чья очередь ходить: `0` — Петя, `1` — Ваня |
| `target` | Чью гарантированную победу проверяем |
| `left` | Сколько общих ходов ещё разрешено рассмотреть |

Правила игры — те же `moves` и `finished`, что в подтеме 3:

```python
def moves(s):
    return [s + 1, s * 2]


def finished(s):
    return s >= 21
```

Например, `can_win(5, 0, 0, 3)` означает: из позиции 5, когда ходит Петя, может ли Петя гарантировать победу не позднее чем за три общих хода? Три общих хода — это первый ход Пети, первый ход Вани и второй ход Пети.

```python
def can_win(p, turn, target, left):
    if finished(p):
        return turn != target

    if left == 0:
        return False

    results = [
        can_win(q, 1 - turn, target, left - 1)
        for q in moves(p)
    ]

    if turn == target:
        return any(results)

    return all(results)
```

Разберём каждую часть.

1. **Проверка окончания.** Если игра уже закончилась, последний ход сделал **предыдущий** игрок, а `turn` хранит того, кто ходил бы следующим. Если следующим должен был ходить проверяемый игрок, последним сходил его соперник — это поражение; если соперник — победа. Поэтому `turn != target` ({{eq|`!=`}} — «не равно»): проверяем Петю (`target = 0`), Петя достиг порога, следующий — Ваня (`turn = 1`), и `1 != 0` даёт `True`.
2. **Проверка оставшихся ходов.** Если игра ещё не закончилась, а разрешённые для проверки ходы исчерпаны, требование не выполнено. Это не обязательно означает, что проверяемый игрок вообще проигрывает: возможно, он победит позже. Но в отведённое число ходов гарантии нет.
3. **Переход к следующему ходу.** Позиция `p` заменяется на результат хода `q`, игрок меняется через `1 - turn` (из 0 получается 1, из 1 — 0), цель остаётся прежней, оставшихся ходов становится на один меньше.
4. **Выбор между `any` и `all`.** На ходе проверяемого игрока достаточно выбрать одно успешное продолжение, на ходе соперника успешными должны быть все.

**Вопросы заданий 19–21 становятся вызовами `can_win` из начальной позиции, где первым ходит Петя.**

| Что проверяем | Вызов |
|---|---|
| Петя выигрывает первым ходом | `can_win(p, 0, 0, 1)` |
| Ваня гарантирует победу первым ходом | `can_win(p, 0, 1, 2)` |
| Петя гарантирует победу первым или вторым ходом | `can_win(p, 0, 0, 3)` |
| Ваня гарантирует победу первым или вторым ходом | `can_win(p, 0, 1, 4)` |

Поэтому типичное условие задания 20 — `not can_win(p, 0, 0, 1) and can_win(p, 0, 0, 3)`, а задания 21 — `not can_win(p, 0, 1, 2) and can_win(p, 0, 1, 4)`.

Этот вариант длиннее коротких шаблонов, зато **смысл каждого параметра виден непосредственно**.

**Короткий шаблон `f(p, m)` получается из той же логики, но часть информации в нём спрятана в чётности числа ходов.** Именно поэтому его опасно заучивать без расшифровки.

```python
def f(p, m):
    if finished(p):
        return m % 2 == 0

    if m == 0:
        return False

    results = [f(q, m - 1) for q in moves(p)]

    if m % 2 == 1:
        return any(results)

    return all(results)
```

Здесь `m` — количество общих ходов, которое ещё можно рассмотреть. Но нужно добавить ключевое соглашение:

> Проверяется гарантированная победа того игрока, которому принадлежал бы последний из этих `m` ходов. Его более ранняя победа тоже засчитывается.

Если сейчас ходит Петя и m = 3, возможный порядок: Петя, Ваня, Петя. Последний разрешённый ход принадлежит Пете — проверяем победу Пети не позднее этого момента. Если m = 4: Петя, Ваня, Петя, Ваня — проверяем победу Вани. Из начальной позиции:

| Вызов | Смысл |
|---|---|
| `f(p, 1)` | Петя может выиграть первым ходом |
| `f(p, 2)` | Ваня гарантирует победу первым ходом |
| `f(p, 3)` | Петя гарантирует победу первым или вторым ходом |
| `f(p, 4)` | Ваня гарантирует победу первым или вторым ходом |
| `f(p, 5)` | Петя гарантирует победу не позднее третьего своего хода |

---

**При нечётном `m` сейчас ходит тот, чью победу проверяем, — поэтому `any`.** Если осталось нечётное число ходов, первый и последний из них принадлежат одному игроку: Петя, Ваня, Петя. Значит, сейчас ходит тот игрок, чью победу проверяем, и он выбирает подходящий ход — `any(results)`. Если осталось чётное число ходов, последний принадлежит сопернику текущего игрока: Петя, Ваня. Сейчас ходит противник того, чью победу проверяем. Нужно выдержать все его действия — `all(results)`.

**При завершённой игре `m % 2 == 0` проверяет победителя, а не количество камней.** После окончания игры последним сходил предыдущий игрок. Если оставшееся `m` чётно, проверяемый победитель — как раз противоположный текущему, то есть предыдущий игрок. Петины победы в `f(p, 3)` приходятся на чётный остаток ходов.

<details class="proof" markdown="1">
<summary>Разбор на f(p, 3): когда закончилась игра и что вернуть</summary>

Возьмём `f(p, 3)` — победу Пети первым или вторым ходом:

| Когда закончилась игра | Кто сделал последний ход | Сколько ходов осталось `m` | Результат |
|---|---|---:|---|
| После общего хода 1 | Петя | 2 | `True` |
| После общего хода 2 | Ваня | 1 | `False` |
| После общего хода 3 | Петя | 0 | `True` |

Петины победы соответствуют чётному остатку: 2 или 0.

</details>

**Окончание проверяется раньше, чем `m == 0`.** Предположим, победа произошла последним разрешённым ходом. После него порог уже достигнут, а оставшихся ходов ровно 0. Победу нужно засчитать. Если сначала написать `if m == 0: return False`, программа ошибочно отвергнет все победы на последнем разрешённом ходе.

**Проследим работу короткой рекурсии на f(5, 3).** Петя должен гарантировать победу не позднее второго собственного хода. Из 5 получаются 6 и 10, поэтому f(5, 3) проверяет `any` по f(6, 2) и f(10, 2): Пете достаточно одного удачного первого хода. В ветке f(10, 2) ходит Ваня, из 10 он получает 11 или 20, и Пете нужна победа после обоих вариантов — `all` по f(11, 1) и f(20, 1). Дальше — вызовы с m = 0, где решает только то, закончена ли игра.

%%game_calls_stepper(5, 3)%%

Пете достаточно выбрать ход из 5 в 10. Ветка f(6, 2) даёт `False`: после 5 → 6 Ваня отвечает 6 → 7, и из 7 Петя за один ход получает только 8 или 14. **Это и есть ручное рассуждение, записанное в виде функции.**

Короткую ветку можно пройти по шагам. Это та же `f`, только ходы и окончание записаны прямо в ней, чтобы шагов было немного, — назовём её `check`:

```python run check.py
def check(s, m):
    if s >= 21:
        return m % 2 == 0
    if m == 0:
        return False
    results = [check(q, m - 1) for q in [s + 1, s * 2]]
    if m % 2 == 1:
        return any(results)
    return all(results)


print(check(20, 1))
```

```output
True
```

Оба хода из 20 заканчивают игру — 21 и 40, — и в обоих вызовах с m = 0 срабатывает первая проверка: победил тот, кто сделал последний ход.

**Вопросы заданий записываются вызовами `f`, а неудачный ход — отдельной проверкой.** Основные условия:

- Ваня гарантированно выигрывает первым ходом — `f(p, 2)`;
- Петя не может выиграть первым, но гарантирует победу не позднее второго своего хода — `not f(p, 1) and f(p, 3)`;
- Ваня гарантирует победу первым или вторым своим ходом, но не гарантирует победу первым — `not f(p, 2) and f(p, 4)`;
- неудачный ход Пети — `any(not finished(q) and f(q, 1) for q in moves(p))`: есть такой первый ход Пети, который не завершает игру его победой и после которого Ваня может выиграть одним ходом.

**`f(p, 2)` для неудачного хода использовать нельзя:** эта функция проверяет гарантию против любого первого хода Пети.

```python
print([s for s in range(1, 21) if f(s, 2)])
print([s for s in range(1, 21) if not f(s, 1) and f(s, 3)])
print([s for s in range(1, 21) if not f(s, 2) and f(s, 4)])
print(min(s for s in range(1, 21)
          if any(not finished(q) and f(q, 1)
                 for q in moves(s))))
```

```output
[10]
[5, 9]
[8]
6
```

**Для двух куч функция `f` остаётся прежней: меняются только `moves`, `finished` и начальная позиция.** Позицию передают кортежем. Здесь пригодится {{cache|`@cache`}} из темы 16: одинаковые позиции встречаются в разных ветках, и запоминание избавляет от повторов.

<details class="proof" markdown="1">
<summary>Программа для двух куч целиком</summary>

```python
from functools import cache


def moves(p):
    a, b = p
    return [(a + 1, b), (a * 2, b), (a, b + 1), (a, b * 2)]


def finished(p):
    a, b = p
    return a + b >= 20


@cache
def f(p, m):
    if finished(p):
        return m % 2 == 0
    if m == 0:
        return False
    results = [f(q, m - 1) for q in moves(p)]
    if m % 2 == 1:
        return any(results)
    return all(results)


print([s for s in range(1, 17)
       if not f((3, s), 1) and f((3, s), 3)])
```

```output
[4, 6, 7]
```

</details>

Для начальных позиций (3, S) задание 20 даёт те же 4, 6 и 7, что в подтеме 4. **Позицию для `@cache` хранят кортежем**: обычный список `[a, b]` для запоминания аргументов не подходит — Python сообщит `TypeError: unhashable type: 'list'`. Если после добавления запоминания изменил правила `moves` или `finished`, старые сохранённые ответы использовать нельзя: нужно перезапустить программу либо очистить сохранённое — `f.cache_clear()`.

---

**«Не позднее второго хода» и «ровно вторым ходом» — разные требования.** Функция `f(p, 3)` засчитывает Петину победу и первым, и вторым ходом. Поэтому для формулировки «Петя не может выиграть первым ходом, но может гарантированно выиграть вторым» нужно `not f(p, 1) and f(p, 3)`. **Одна только проверка `f(p, 3)` недостаточна.** Так же в задании 21 нужно `not f(p, 2)`.

<details class="proof" markdown="1">
<summary>Тонкости: победа ровно заданным ходом</summary>

Утверждение «игрок способен организовать победу ровно вторым ходом» само по себе ещё не означает, что он не мог победить первым. Покажем на маленькой отдельной игре: в куче 3 камня; можно убрать 1 или 3, если камней хватает; выигрывает забравший последний камень.

Первый игрок может сразу убрать 3 и победить. Но может выбрать и такую стратегию:

1. Убрать 1: останется 2.
2. Соперник вынужден убрать 1: останется 1.
3. Убрать последний камень и победить вторым собственным ходом.

Получается, возможность победить ровно вторым ходом есть, но условие «не может выиграть первым» не выполнено.

Если в нестандартной задаче требуется **именно заданный момент завершения**, это нужно проверять отдельно. Например, в подробной функции `can_win` можно заменить проверку завершения на `return turn != target and left == 0`. Теперь победа нужного игрока засчитывается только последним разрешённым ходом. Более ранние завершения не подходят. Это уже другая проверка. Для стандартной формулировки «первым или вторым» такая замена неверна.

</details>

**Вопрос о третьем ходе — та же функция с m = 5 и m = 6.** «Петя не может выиграть за один и за два хода, но может выиграть своим третьим ходом» — `not f(p, 3) and f(p, 5)`. «Ваня может выиграть вторым или третьим ходом, но не может гарантированно выиграть вторым» — `not f(p, 4) and f(p, 6)`. Во второй формулировке ранняя победа первым ходом уже исключена: `f(p, 4)` засчитывает и её. В нашей игре:

```python
print([s for s in range(1, 21) if not f(s, 3) and f(s, 5)])
print([s for s in range(1, 21) if not f(s, 4) and f(s, 6)])
```

```output
[4, 7]
[6]
```

Например, из 4 Петя удваивает кучу и передаёт Ване 8 — позицию `L2`: что бы Ваня ни делал, Петя выиграет не позднее своего третьего хода. Ход 4 → 5 плох: 5 — `W2` уже для Вани.

---

**Для стандартных задач достаточно просмотреть небольшую глубину дерева, поэтому короткая рекурсия обычно не требует сложной оптимизации.** Если из каждой позиции есть четыре хода, то на глубине четырёх общих ходов будет не более 4⁴ = 256 конечных ветвей, а с учётом промежуточных позиций — 1 + 4 + 16 + 64 + 256 = 341 вызов на одно начальное значение в полном дереве. Некоторые ветви закончатся раньше из-за достижения порога. **Для неглубоких проверок на один–четыре общих хода запоминание не является обязательной частью решения**: сначала важнее добиться правильной логики. Оно нужно, когда начальных S десятки тысяч, как в убывающих играх с порогом 20 007.

Различай два вида рекурсии: рекурсия с ограничением `m` останавливается, потому что число оставшихся ходов уменьшается, а рекурсия «играть до конца» требует уверенности, что бесконечные последовательности невозможны. Её разбирает дополнительная подтема 7.

---

**Итого.**

- `can_win(p, turn, target, left)` показывает игрока и цель явно; `f(p, m)` прячет их в чётности `m`: нечётное `m` — `any`, конец игры — `m % 2 == 0`.
- Конец игры проверяется раньше `m == 0`, иначе потеряются победы последним ходом.
- 19 — `f(p, 2)`, 20 — `not f(p, 1) and f(p, 3)`, 21 — `not f(p, 2) and f(p, 4)`, третий ход — m = 5 и 6; неудачный ход — отдельная проверка с `any`.
- Для двух куч меняются только `moves`, `finished` и позиция-кортеж; `@cache` требует кортежа.
