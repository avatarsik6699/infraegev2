**Второй основной приём — хранить две границы фрагмента и постепенно их передвигать.** Так решаются задачи вида «не более K букв», «ровно K букв», «каждая из нескольких букв не более K раз», «не более K пар букв» и «без запрещённого слова».

Все шаги разберём на строке `BABAACB` и ограничении на буквы `A`. Индексы и включённые границы `left`, `right` — из подтемы 1, текущая длина — из подтемы 2.

---

**Фрагмент между двумя границами называют окном.**

Пусть `left = 2` и `right = 6`. Тогда окно — это `s[2:7]`. Правая граница обычно двигается по строке по одному символу. Левая — сдвигается, когда это нужно для выполнения условия.

Такой способ называют **скользящим окном** или **методом двух указателей**. Указателями здесь служат обычные индексы `left` и `right`.

---

**Если в окне стало слишком много нужных букв, левая граница сдвигается, пока ограничение снова не выполнится.**

Начнём с задачи:

> Найти самый длинный фрагмент, содержащий не более двух букв `A`.

Будем хранить `left = 0`, `count_a = 0` и `best = 0`. При добавлении символа справа увеличиваем счётчик, если это `A`. Если букв `A` стало больше двух, удаляем символы слева, пока ограничение снова не выполнится. Пройди строку `BABAACB` по шагам:

%%string_window_stepper("BABAACB", "A", 2)%%

```python
s = 'BABAACB'
K = 2

left = 0
count_a = 0
best = 0

for right in range(len(s)):
    if s[right] == 'A':
        count_a += 1

    while count_a > K:
        if s[left] == 'A':
            count_a -= 1

        left += 1

    best = max(best, right - left + 1)

print(best)
```

```output
5
```

Разберём самый важный момент — добавление `A` на позиции `4`. Получилось `BABAA`: три буквы `A`, условие нарушено. Удаляем первый `B` — получается `ABAA`, букв `A` всё ещё три. Удаляем первую `A` — получается `BAA`, теперь их две.

**Поэтому нужен {{while|`while`}}, а не одноразовый `if`.** Для исправления окна иногда требуется убрать несколько символов.

---

**Скользящее окно работает здесь потому, что лишние буквы невозможно убрать расширением вправо.**

Если во фрагменте уже три `A`, добавление новых символов не превратит их обратно в две. Значит, пока мы не передвинем левую границу, такое начало больше не пригодится.

После сжатия окна условие выполнено, а `left` находится настолько далеко слева, насколько возможно. Следовательно, найдено самое длинное допустимое окно с текущим правым концом. Мы рассматриваем каждый правый конец, поэтому среди этих окон обязательно встретится глобальный максимум.

Такое сохраняемое утверждение о состоянии алгоритма называют **инвариантом**. Для данного решения инвариант:

> После завершения `while` окно содержит не более `K` букв `A`, а его левая граница минимально возможна для данного правого конца.

Термин полезен, но важнее сама мысль: **ты должен уметь объяснить, что означают переменные после каждого шага**.

**Почему два вложенных цикла здесь не дают `O(n²)`?** Потому что `left` не возвращается назад. За всё выполнение `right` проходит строку один раз, и `left` тоже проходит её не более одного раза. Суммарно получается порядка 2n перемещений, то есть `O(n)`. Вложенные циклы сами по себе ещё не означают квадратичную сложность.

---

**Для самого длинного фрагмента с ровно `K` буквами можно использовать то же окно.**

Различие — ответ обновляется только при точном равенстве:

```python
s = 'BABAACB'
K = 2

left = 0
count_a = 0
best = 0

for right in range(len(s)):
    if s[right] == 'A':
        count_a += 1

    while count_a > K:
        if s[left] == 'A':
            count_a -= 1

        left += 1

    if count_a == K:
        best = max(best, right - left + 1)

print(best)
```

```output
5
```

Почему не нужно специально двигать границу, когда букв меньше `K`? Удаление символов не увеличит количество `A`. Значит, если даже в самом широком допустимом окне их недостаточно, более короткое окно с тем же правым концом не поможет. А если букв ровно `K`, самое широкое окно — как раз лучшее по длине.

Значение `best = 0` означает, что подходящий непустой фрагмент пока не найден. Если условие не гарантирует существование ответа, ситуацию отсутствия подходящих фрагментов нужно обрабатывать согласно условию.

---

**Поиск минимальной длины требует другой логики обновления ответа.**

Задача:

> Найти самый короткий фрагмент, содержащий не менее `K` букв `A`.

Здесь недостаток букв исправляется расширением вправо. Когда букв стало достаточно, пробуем уменьшать окно слева.

```python
s = 'BABAACB'
K = 2    # Здесь K >= 1

left = 0
count_a = 0
best = len(s) + 1

for right in range(len(s)):
    if s[right] == 'A':
        count_a += 1

    while count_a >= K:
        best = min(best, right - left + 1)

        if s[left] == 'A':
            count_a -= 1

        left += 1

if best == len(s) + 1:
    print('Подходящего фрагмента нет')
else:
    print(best)
```

```output
2
```

Начальное значение `len(s) + 1` больше длины любой подстроки. Поэтому любой найденный ответ окажется меньше. Если значение не изменилось, подходящего фрагмента не было.

**Почему ответ обновляется до удаления левого символа?** Пока условие `count_a >= K` выполнено, окно подходит. После удаления оно может перестать подходить. Поэтому сначала учитываем текущее окно, затем пробуем его сократить.

Сравни две схемы: при поиске максимальной длины с ограничением «не более `K`» внутренний цикл сжимает окно, **пока оно плохое**; при поиске минимальной длины с ограничением «не менее `K`» — **пока оно хорошее**, запоминая ответы.

Для одного ограничения на количество символа, без дополнительных требований, минимальный фрагмент с не менее `K` буквами будет содержать ровно `K`: лишние крайние вхождения можно отбросить. Но при дополнительных ограничениях на начало, конец или структуру такое рассуждение нужно проверять заново.

Также замечай простые случаи. «Максимальная длина фрагмента с не менее `K` буквами `A`»: если других ограничений нет и во всей строке достаточно `A`, ответ — длина всей строки. Не каждой формулировке нужен сложный алгоритм.

---

**Несколько верхних ограничений можно поддерживать одновременно.**

Например:

> Не более двух `A` и не более одной `B`.

Условие допустимости — `count_a <= 2 and count_b <= 1`. Значит, окно нужно сжимать, если `count_a > 2 or count_b > 1`: достаточно нарушения хотя бы одного ограничения.

```python
s = 'BABAACB'
left = 0
count_a = 0
count_b = 0
best = 0

for right in range(len(s)):
    if s[right] == 'A':
        count_a += 1

    if s[right] == 'B':
        count_b += 1

    while count_a > 2 or count_b > 1:
        if s[left] == 'A':
            count_a -= 1

        if s[left] == 'B':
            count_b -= 1

        left += 1

    best = max(best, right - left + 1)

print(best)
```

```output
4
```

Лучшие окна — `BAAC` и `AACB`. Если требуется **ровно две `A` и ровно одна `B`**, после сжатия ответ обновляют только при `count_a == 2 and count_b == 1`.

**Важно различать:** каждая буква из набора встречается не более двух раз — и суммарно буквы из набора встречаются не более двух раз. В первом случае нужны отдельные счётчики, во втором — один общий.

---

**Если контролируемых букв много, отдельные переменные заменяют словарём счётчиков.**

Ключ словаря — буква, значение — сколько раз она есть в окне. Сжимать окно нужно, только когда превышен счётчик той буквы, которую сейчас добавили: остальные ограничения уже выполнялись. Например, каждая из букв `A`, `B`, `C` — не более одного раза:

```python
s = 'BABAACB'
K = 1
count = {'A': 0, 'B': 0, 'C': 0}
left = 0
best = 0

for right in range(len(s)):
    c = s[right]
    if c in count:
        count[c] += 1
        while count[c] > K:
            if s[left] in count:
                count[s[left]] -= 1
            left += 1

    best = max(best, right - left + 1)

print(best)
```

```output
3
```

Лучшее окно — `ACB`. Символы, которых нет в словаре, ограничений не имеют и счётчиков не требуют.

---

**Пару букв в окне учитывают, только когда она целиком лежит внутри окна.**

Пусть ограничение задано не на букву, а на пару букв, например `TT`, и пары могут перекрываться: в `TTT` две пары `TT`. Пара начинается на позиции `i` и занимает символы `i` и `i + 1`. Поэтому:

- при добавлении символа справа новая пара появляется, если `s[right - 1:right + 1]` — это `TT` и её начало `right - 1` не левее `left`;
- при удалении символа слева пара уходит из окна, если `s[left:left + 2]` — это `TT` и её конец `left + 1` не правее `right`.

Пройди по шагам строку `TTATTTB` с ограничением «не более одной пары `TT`»:

%%string_window_stepper("TTATTTB", "TT", 1)%%

```python
s = 'TTATTTB'
word = 'TT'
K = 1
left = 0
count = 0
best = 0

for right in range(len(s)):
    start = right - 1
    if start >= left and s[start:right + 1] == word:
        count += 1

    while count > K:
        if s[left:left + 2] == word and left + 1 <= right:
            count -= 1
        left += 1

    best = max(best, right - left + 1)

print(best)
```

```output
4
```

Окна `TTAT` и `TATT` содержат по одной целой паре. В `TATTT` пар уже две — `TT` на позициях 3 и 4 перекрываются. Для условия «ровно `K` пар» ответ обновляют только при `count == K`, как для букв.

---

**Запрещённое слово тоже можно обрабатывать через границу окна.**

Задача:

> Найти самый длинный фрагмент без подстроки `ABC`.

Пусть новое запрещённое вхождение заканчивается на позиции `right`. Его начало — `start = right - len(word) + 1`. Чтобы фрагмент больше не содержал это вхождение целиком, достаточно поставить левую границу **после его первого символа**: `left = start + 1`. Не обязательно выбрасывать всё слово. Например, из `ABC` можно оставить `BC`.

```python
s = 'XABCYABZ'
word = 'ABC'
m = len(word)

left = 0
best = 0

for right in range(len(s)):
    if right >= m - 1:
        start = right - m + 1

        if s[start:right + 1] == word:
            left = max(left, start + 1)

    best = max(best, right - left + 1)

print(best)
```

```output
6
```

После обнаружения `ABC` остаётся возможным фрагмент `BCYABZ` длины 6. Это ещё один пример того, почему полный сброс счётчика часто неверен: значительная часть текущего фрагмента может оставаться подходящей.

---

**Итого.**

- Окно — фрагмент `s[left:right + 1]`; `right` идёт по одному символу, `left` только догоняет.
- «Не более `K`»: сжимать, пока окно плохое, затем обновлять максимум. «Ровно `K`»: то же окно, ответ — только при равенстве. «Не менее `K`» для минимума: сжимать, пока окно хорошее, обновляя минимум до удаления.
- Несколько ограничений — несколько счётчиков или словарь; «каждая» и «суммарно» — разные условия.
- Пара или слово учитываются, только когда целиком лежат в окне; запрещённое слово — `left = start + 1`.
- `left` не возвращается назад, поэтому вложенный `while` даёт `O(n)`.
