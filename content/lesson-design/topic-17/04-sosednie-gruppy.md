**Соседние пары и тройки перебираются по индексу начала, а граница перебора выводится из последнего индекса списка.** Соседние группы — в 75 задачах подборки из 85 и во всех 15 задачах реальных экзаменов; в 37 из них это тройки и четвёрки.

Считать, что в задании 17 всегда нужны только соседи, всё же нельзя: в подборке есть задачи, где пара — любые два элемента с разными номерами. Их разбирает дополнительный урок «Любые пары».

Вернёмся к последовательности 8, −12, 5, 20, −3, 14 из подтемы 1 — на ней разберём перебор и первую полную задачу.

---

**Соседние пары перебираются с шагом в один элемент.**

Соседние пары нашей последовательности — (8, −12), (−12, 5), (5, 20), (20, −3), (−3, 14). Обрати внимание: **пары пересекаются**. Число `-12` участвует как второй элемент первой пары и как первый элемент второй пары. Это правильно.

Если брать (8, −12), затем (5, 20), затем (−3, 14), мы пропустим две соседние пары.

Для перебора используется {{for|`range`}}: `range(m)` последовательно даёт целые числа 0, 1, 2, …, m − 1. Правая граница не включается. Пара с началом `i` — это элементы `a[i]` и `a[i + 1]`:

```python
a = [8, -12, 5, 20, -3, 14]
for i in range(len(a) - 1):
    x = a[i]
    y = a[i + 1]
    print(i, x, y)
```

```output
0 8 -12
1 -12 5
2 5 20
3 20 -3
4 -3 14
```

Теперь выведем границу цикла, а не просто запомним её. Пусть длина списка равна `n`:

1. В паре используются индексы i и i + 1.
2. Последний индекс списка — n − 1, значит, i + 1 ≤ n − 1.
3. Отсюда i ≤ n − 2: нужны начала 0, 1, …, n − 2.

Именно их даёт **`range(n - 1)`**.

<figure class="plate-figure">
%%seq_windows([8, -12, 5, 20, -3, 14], 2)%%
<figcaption>Каждая скобка — соседняя пара, у неё общий элемент с соседней скобкой. Последняя пара начинается с индекса i = 4 = n − 2: её второй элемент — последний элемент списка a[5].</figcaption>
</figure>

Для последовательности из `n` элементов при `n ≥ 2` существует `n - 1` соседняя пара.

---

**Для троек рассуждение такое же, но последний используемый индекс — `i + 2`.**

Перебор:

```python
for i in range(len(a) - 2):
    x = a[i]
    y = a[i + 1]
    z = a[i + 2]
```

Требуется i + 2 ≤ n − 1, поэтому i ≤ n − 3. Начала троек — 0, 1, …, n − 3. Их даёт **`range(n - 2)`**. Для нашего списка получаются (8, −12, 5), (−12, 5, 20), (5, 20, −3), (20, −3, 14):

<figure class="plate-figure">
%%seq_windows([8, -12, 5, 20, -3, 14], 3)%%
<figcaption>Четыре соседние тройки шести элементов: каждая следующая сдвинута на один элемент. Последняя начинается с индекса n − 3 = 3.</figcaption>
</figure>

Общее правило для группы из `k` соседних элементов:

```python
for i in range(len(a) - k + 1):
    ...
```

При `n ≥ k` таких групп n − k + 1. Например, соседние четвёрки — это `range(len(a) - 3)` и элементы `a[i]`, `a[i + 1]`, `a[i + 2]`, `a[i + 3]`.

Группу соседних элементов иногда называют **окном**. Перемещение её начала на одну позицию — движением окна по последовательности. Для задания 17 с парами и тройками за этим названием стоит именно описанный перебор.

---

**Теперь можно полностью решить первую задачу.**

Учебное условие:

> Найти количество соседних пар, в которых хотя бы одно число делится на четыре. Среди таких пар найти максимальную сумму.

Пока разберём ответ вручную для 8, −12, 5, 20, −3, 14:

| Пара | Хотя бы одно число кратно 4? | Сумма |
|---|---|---:|
| `(8, -12)` | Да | −4 |
| `(-12, 5)` | Да | −7 |
| `(5, 20)` | Да | 25 |
| `(20, -3)` | Да | 17 |
| `(-3, 14)` | Нет | 11 |

Подходят четыре пары. Их суммы −4, −7, 25, 17. Максимальная — `25`. Ответ: `4 25`.

Самый наглядный способ программирования — сохранять суммы подходящих пар в отдельный список. Функция {{agg|`max`}} возвращает наибольшее значение: `max([-4, -7, 25, 17])` равно 25.

Программа:

```python
with open("17.txt") as f:
    a = [int(part) for part in f.read().split()]

sums = []

for i in range(len(a) - 1):
    x = a[i]
    y = a[i + 1]

    if x % 4 == 0 or y % 4 == 0:
        sums.append(x + y)

if len(sums) > 0:
    print(len(sums), max(sums))
else:
    print("Подходящих пар нет")
```

```output
4 25
```

Почему `len(sums)` даёт количество пар? Потому что **на каждую подходящую пару добавляется ровно одна сумма**.

Если две разные пары имеют одинаковые суммы, одинаковое значение добавится дважды. Удалять такие повторения не нужно: пары разные.

Обрати внимание на отступ: `sums.append(x + y)` стоит внутри `if`, поэтому добавление происходит только после проверки. Если перенести `append` за пределы `if`, в список попадут суммы всех пар.

Последняя ветка с текстом — диагностическая. На экзамене, если подходящих групп нет, нужно действовать по условию: например, вывести `0 0`, **если именно это предписано**. Нельзя самостоятельно считать ноль универсальным значением отсутствующего максимума.

---

**Тот же ответ можно находить, не сохраняя все суммы.**

Нам нужны лишь количество найденных пар и наибольшая сумма среди уже найденных.

Для количества создадим переменную `count = 0`. Она называется **счётчиком**, потому что хранит количество событий. При обнаружении подходящей пары выполняется {{augassign|`count += 1`}}: к старому значению прибавляется единица, результат сохраняется обратно.

Для максимума нужно выбрать начальное состояние.

**Начинать максимум с нуля в общем случае неправильно.**

Предположим, подходящие суммы −15, −8, −20. Максимальная из них — `-8`. Если начать с нуля и заменять его только на большее число, останется `0`, которого среди результатов вообще нет.

Удобно использовать {{none|`best = None`}}. `None` — специальное значение, которым здесь обозначаем:

> Подходящего результата пока не было.

При появлении очередной суммы: если результата ещё не было, запоминаем первый; иначе заменяем его, только если новая сумма больше. Запусти пример по шагам и посмотри, как меняется `best`:

```python run best.py
sums = [-15, -8, -20]
best = None
for s in sums:
    if best is None or s > best:
        best = s
print(best)
```

```output
-8
```

Python проверяет части `or` слева направо. Когда `best is None` истинно, сравнение `s > best` уже не выполняется. Поэтому число не сравнивается с `None`.

Полная программа:

```python
with open("17.txt") as f:
    a = [int(part) for part in f.read().split()]

count = 0
best = None

for i in range(len(a) - 1):
    x = a[i]
    y = a[i + 1]

    if x % 4 == 0 or y % 4 == 0:
        count += 1
        current_sum = x + y

        if best is None or current_sum > best:
            best = current_sum

if count > 0:
    print(count, best)
else:
    print("Подходящих пар нет")
```

```output
4 25
```

Для поиска минимума изменяется знак сравнения: `if best is None or value < best:`.

Оба способа — список результатов и счётчик с лучшим значением — правильные.

| Способ | Что удобно |
|---|---|
| Список результатов | Легко посмотреть все найденные значения и проверить себя |
| Счётчик и лучшее значение | Не нужно хранить все результаты |

Для освоения темы список часто нагляднее. После понимания логики переход к счётчику несложен.

---

**Правильность такого решения можно объяснить без формальных доказательств.**

После обработки каждой очередной пары:

- `count` равен количеству подходящих пар среди уже проверенных;
- `best` равен максимальной сумме среди них либо остаётся `None`, если подходящих ещё не было.

Изначально проверенных пар нет, поэтому `count = 0`. Если очередная пара не подходит, ответ не меняется. Если подходит, количество увеличивается на единицу, а максимум при необходимости обновляется.

Цикл рассматривает каждое допустимое начало пары ровно один раз. Поэтому к его завершению учтены все нужные пары.

Это и есть смысл алгоритма: мы поддерживаем правильный частичный ответ и постепенно распространяем его на всю последовательность.

---

**Итого.**

- Соседние группы пересекаются; пара с началом `i` — `a[i]`, `a[i + 1]`.
- Граница выводится из последнего индекса: пары — `range(n - 1)`, тройки — `range(n - 2)`, группы из `k` — `range(n - k + 1)`.
- Ответ копится списком подходящих значений или счётчиком с лучшим значением.
- Лучшее значение начинается с `None`, а не с нуля: подходящие суммы бывают отрицательными.
- Если подходящих групп нет, выводится то, что предписано условием.
