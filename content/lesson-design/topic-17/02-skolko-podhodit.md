**Слова «хотя бы одно», «ровно одно», «не более двух» переводятся в код через количество выполненных проверок.** Такие формулировки есть в 44 задачах подборки из 85 и в половине задач 2025–2026 годов: «только одно число трёхзначное», «не менее двух четырёхзначных», «кратных трём больше, чем кратных пяти», «одно делится на три, а другое меньше среднего».

Будем проверять маленькие пары и тройки на одно свойство — «делится на три»: пары (6, 5), (5, 9), (6, 9) и тройку 6, 10, 15.

---

**Слова «и», «или», «не» соединяют простые проверки в более сложные.**

Пусть:

```python
p = x % 3 == 0
q = y % 3 == 0
```

Переменная `p` хранит ответ на вопрос «делится ли `x` на 3», а `q` — такой же ответ для `y`. Тогда {{andor|составные условия}} означают:

- `p and q` — выполнены **обе** проверки;
- `p or q` — выполнена **хотя бы одна** проверка;
- `not p` — проверка `p` **не** выполнена.

**«Хотя бы одно» допускает, что подходят оба.**

Поэтому `x % 3 == 0 or y % 3 == 0` подходит для пар (6, 5), (5, 9) и (6, 9). Не подходит только пара, где оба числа не делятся на три. А условие `x % 3 == 0 and y % 3 == 0` из этих трёх примеров пропускает только (6, 9):

:::pick Пара и две проверки
- *(6, 5) | «хотя бы одно делится на 3» — да; «оба делятся» — нет
- (5, 9) | «хотя бы одно» — да; «оба» — нет
- (6, 9) | «хотя бы одно» — да; «оба» — да
- (5, 7) | «хотя бы одно» — нет; «оба» — нет
:::

---

**«Ровно одно» удобно понимать как количество выполненных проверок.**

Для пары это означает два допустимых случая:

1. первое число подходит, второе не подходит;
2. первое не подходит, второе подходит.

Подробная запись — `(p and not q) or (not p and q)`. Для двух логических значений есть короткая запись `p != q`: она проверяет, что ответы различаются. Например, `(x % 3 == 0) != (y % 3 == 0)` означает: ровно одно число делится на три.

Но для троек и более сложных условий удобнее единый подход: **посчитать, сколько элементов обладает нужным свойством**.

Python позволяет преобразовать результаты проверок в числа: **`int(True)` равно 1, `int(False)` равно 0**. Такое явное преобразование делает подсчёт наглядным. Для тройки 6, 10, 15:

```python
x = 6
y = 10
z = 15
k = int(x % 3 == 0) + int(y % 3 == 0) + int(z % 3 == 0)
print(int(True), int(False), k)
```

```output
1 0 2
```

Здесь `k` — количество чисел, делящихся на три: k = 1 + 0 + 1 = 2.

Теперь любые количественные формулировки переводятся одинаково:

:::pick Формулировка для тройки и проверка
- ни одного подходящего числа | `k == 0`
- ровно одно | `k == 1`
- *ровно два | `k == 2`
- все три | `k == 3`
- хотя бы одно | `k >= 1`
- хотя бы два | `k >= 2`
- не более одного | `k <= 1`
- не более двух | `k <= 2`
- есть подходящие, но не все подходят | `0 < k < 3`
:::

«Не более двух» включает ноль, одно и два, а «не менее двух» — два и три. Это важно: иногда ученик видит слово «двух» и машинально пишет `k == 2`, хотя условие требует другое.

В решениях также встречается запись без `int`: `k = (x % 3 == 0) + (y % 3 == 0) + (z % 3 == 0)`. Она работает, потому что при таком сложении `True` ведёт себя как единица, а `False` — как ноль. На этапе обучения запись с `int` яснее показывает смысл.

---

**Разные свойства одной группы нужно считать независимо.**

Допустим, требуется:

> В тройке чисел, кратных трём, больше, чем чисел, кратных пяти.

Сначала считаем одно, затем другое и сравниваем:

```python
x = 6
y = 10
z = 15
k3 = int(x % 3 == 0) + int(y % 3 == 0) + int(z % 3 == 0)
k5 = int(x % 5 == 0) + int(y % 5 == 0) + int(z % 5 == 0)
print(k3, k5, k3 > k5)
```

```output
2 2 False
```

Число `15` попало **в оба количества**. Это правильно: оно делится и на три, и на пять. Не нужно насильно относить каждый элемент только к одной категории. Здесь кратных трём (6 и 15) столько же, сколько кратных пяти (10 и 15), поэтому условие не выполнено.

И не путай:

- количество подходящих **элементов внутри тройки**;
- количество подходящих **троек во всей последовательности**.

Если в тройке два числа делятся на три и этого достаточно для выполнения условия, сама тройка добавляет к ответу **единицу**, а не двойку.

---

**Скобки помогают сохранить смысл длинного условия.**

Предположим, требуется:

> Хотя бы одно число делится на три, а сумма пары больше 100.

Правильная запись: `(x % 3 == 0 or y % 3 == 0) and (x + y > 100)`. Здесь два крупных требования — хотя бы одно число делится на три и сумма больше ста, — соединённые через `and`.

Без скобок, `x % 3 == 0 or y % 3 == 0 and x + y > 100`, **Python сначала выполнит `and`**. В результате делимости первого числа окажется достаточно независимо от суммы. Проверим на паре (9, 20) с суммой 29:

```python
x = 9
y = 20
print((x % 3 == 0 or y % 3 == 0) and (x + y > 100))
print(x % 3 == 0 or y % 3 == 0 and x + y > 100)
```

```output
False
True
```

Удобный способ избежать путаницы — дать частям условия отдельные имена:

```python
has_multiple = x % 3 == 0 or y % 3 == 0
large_sum = x + y > 100

if has_multiple and large_sum:
    ...
```

Здесь `...` обозначает место для дальнейших действий. Такие переменные хранят результаты проверок. По ним проще сопоставить код с текстом задачи.

---

**Фразы «хотя бы одно… и хотя бы одно…» и «одно…, а другое…» требуют разных проверок.**

Это одна из самых содержательных тонкостей задания. Рассмотрим два свойства: число делится на три; число меньше `T`.

Первое условие:

> Хотя бы одно число пары делится на три, и хотя бы одно число пары меньше `T`.

Запись: `(x % 3 == 0 or y % 3 == 0) and (x < T or y < T)`. **Один и тот же элемент** может обеспечить выполнение обеих частей. Например, при `x = 3`, `y = 100`, `T = 10` число `3` и делится на три, и меньше десяти. Условие выполнено.

Теперь другое условие:

> Одно число пары делится на три, а другое меньше `T`.

Нужно распределить свойства между **двумя разными элементами**: `(x % 3 == 0 and y < T) or (y % 3 == 0 and x < T)`. Проверяются два возможных распределения ролей:

- делимость проверяем у `x`, сравнение — у `y`;
- делимость проверяем у `y`, сравнение — у `x`.

Пара (3, 100) при `T = 10` теперь не подходит.

Есть и третья формулировка:

> Хотя бы одно число одновременно делится на три и меньше `T`.

Здесь два свойства должны встретиться **у одного элемента**: `(x % 3 == 0 and x < T) or (y % 3 == 0 and y < T)`. Проверим все три на паре (3, 100):

```python
x = 3
y = 100
T = 10
first = (x % 3 == 0 or y % 3 == 0) and (x < T or y < T)
second = (x % 3 == 0 and y < T) or (y % 3 == 0 and x < T)
third = (x % 3 == 0 and x < T) or (y % 3 == 0 and y < T)
print(first, second, third)
```

```output
True False True
```

Удобно представить пару таблицей «число × свойство». Тогда три формулировки — три способа читать одну таблицу:

<figure class="plate-figure">
%%seq_roles([3, 100], 3, 10)%%
<figcaption>У пары (3, 100) оба свойства есть только у числа 3. «Хотя бы одно… и хотя бы одно…» читает таблицу по столбцам, «одно…, а другое…» — по диагонали, то есть ищет два разных числа, «одновременно» — по строке, то есть одно число.</figcaption>
</figure>

Эти три условия **нельзя взаимозаменять**.

Также фраза «одно…, а другое…» сама по себе не означает, что делиться на три обязано **ровно одно** число. Если оба элемента обладают обоими свойствами, распределить роли между ними всё равно можно.

---

**Итого.**

- «Хотя бы одно» допускает, что подходят оба; «оба» — это `and`.
- Количественные формулировки переводятся через счёт `k = int(…) + int(…) + …`: «ровно одно» — `k == 1`, «не более двух» — `k <= 2`, «не менее двух» — `k >= 2`.
- Разные свойства считаются независимо: один элемент может попасть в оба количества.
- Части длинного условия берутся в скобки или получают имена.
- «Одно…, а другое…» распределяет свойства между двумя разными элементами — проверяются оба распределения ролей.
