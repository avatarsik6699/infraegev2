**Если условие опирается на величину всей последовательности — наименьший элемент с нужным окончанием, количество кратных, среднее, — её находят заранее, отдельным проходом.** Так устроены 69 задач подборки из 85 и все 15 задач реальных экзаменов: «сумма тройки больше максимального элемента, оканчивающегося на 19», «сумма пары меньше количества чисел, кратных 23».

Главный пример подтемы — последовательность −47, 8, 17, −7, 4, 27, 10 и числа в ней, оканчивающиеся на 7. Ещё две полные задачи — на тройки и на среднее — разобраны на своих коротких последовательностях. Перебор соседних групп из подтемы 4 считаем знакомым.

---

**Иногда перед проверкой пар нужно узнать характеристику всей последовательности.**

Например:

> Сумма пары должна быть больше максимального элемента, оканчивающегося на 7.

Пока мы не просмотрели весь файл, этот максимум может быть неизвестен. Последний элемент файла способен оказаться больше всех предыдущих и изменить порог для проверки даже самой первой пары.

<figcaption>Наибольший элемент на 7 растёт по мере чтения: −47, затем 17, затем 27. Пара (8, 17) с суммой 25 прошла бы проверку с порогом 17, но окончательный порог — 27, и подходят только пары с суммами 31 и 37.</figcaption>

Поэтому задача естественно делится на этапы:

1. прочитать последовательность;
2. вычислить нужное значение по всей последовательности;
3. проверить пары или тройки с использованием уже известного значения.

Просмотр всех элементов от начала до конца называют **проходом по последовательности**.

Два последовательных прохода не означают перебор всех сочетаний. Например, при десяти тысячах элементов мы примерно дважды выполняем по десять тысяч действий.

---

**Предварительная характеристика может быть минимумом, максимумом, количеством, суммой или средним.**

Минимум возвращает {{agg|`min`}}, максимум — `max`, сумму элементов — `sum`:

```python
a = [4, 9, -2]
print(min(a), max(a), sum(a))
```

```output
-2 9 11
```

Если нужны только элементы с определённым свойством, **сначала отберём их**. В нашей последовательности это числа, оканчивающиеся на 7 — файл [17-sem.txt](topic-17/files/17-sem.txt):

```python
with open("17-sem.txt") as f:
    a = [int(part) for part in f.read().split()]

selected = []

for x in a:
    if abs(x) % 10 == 7:
        selected.append(x)
print(selected)
```

```output
[-47, 17, -7, 27]
```

Теперь `max(selected)` даёт максимальное **исходное число** среди отобранных. Короткая запись отбора — {{comp|списковое включение}} с условием:

```python
selected = [x for x in a if abs(x) % 10 == 7]
```

Её нужно читать так:

> Перебрать `x` из `a` и добавить `x`, если его запись заканчивается на 7.

Общий порядок:

> Сначала определить, какие элементы участвуют в вычислении, затем применить к ним нужную операцию.

:::pick Требование и запись после отбора в selected
- *количество таких элементов | `len(selected)` | так считают порог «количество чисел, кратных 23»
- сумма таких элементов | `sum(selected)`
- минимальный такой элемент | `min(selected)`
- максимальный такой элемент | `max(selected)`
- среднее арифметическое | `sum(selected) / len(selected)`
- квадрат количества | `len(selected) ** 2`
:::

Для нашей последовательности:

```python
selected = [x for x in a if abs(x) % 10 == 7]
print(len(selected), min(selected), max(selected))
```

```output
4 -47 27
```

У пустого списка нет обычного минимума и максимума: `min([])` и `max([])` приводят к ошибке. Среднее пустого списка также не определено: получится деление на ноль.

Поэтому нужно учитывать гарантию существования нужных элементов в условии либо отдельно обрабатывать их отсутствие. **Нельзя заменять отсутствующий минимум или максимум произвольным нулём.**

---

**При отборе по цифрам сравнивать обычно нужно исходные числа.**

Числа, оканчивающиеся на семь, у нас −47, 17, −7, 27. Минимальное из них — −47. Проверка окончания использует модуль: `abs(x) % 10 == 7`.

Но в список мы кладём **исходное число** — `selected.append(x)`, а не `selected.append(abs(x))`. Иначе будем искать минимум абсолютных величин — это другая задача.

Аналогично среди отрицательных чисел −900, −250, −710 максимальное — −250, поскольку оно ближе к нулю: −900 < −710 < −250.

---

**Разберём полную задачу с предварительным минимумом, окончаниями и квадратами.**

Учебное условие:

> Рассматриваются соседние пары целых чисел. Ровно одно число пары оканчивается на семь. Сумма квадратов чисел пары должна быть меньше квадрата минимального элемента всей последовательности, оканчивающегося на семь. Найти количество подходящих пар и максимальную сумму квадратов.

Предполагаем, что элемент для вычисления минимума существует.

Разделим текст на самостоятельные действия.

| Часть условия | Что делаем |
|---|---|
| Минимальный элемент всей последовательности, оканчивающийся на 7 | Находим заранее |
| Ровно одно число пары оканчивается на 7 | Считаем такие числа внутри пары |
| Сумма квадратов меньше квадрата минимума | Сравниваем две величины |
| Количество пар | Увеличиваем счётчик |
| Максимальная сумма квадратов | Обновляем максимум именно этой величины |

Для −47, 8, 17, −7, 4, 27, 10 минимум уже найден: m = −47, m² = 2209. Далее:

| Пара | Сколько чисел оканчиваются на 7 | Сумма квадратов | Подходит? |
|---|---:|---:|---|
| `(-47, 8)` | 1 | 2273 | Нет: слишком большая сумма квадратов |
| `(8, 17)` | 1 | 353 | Да |
| `(17, -7)` | 2 | 338 | Нет: подходят оба окончания |
| `(-7, 4)` | 1 | 65 | Да |
| `(4, 27)` | 1 | 745 | Да |
| `(27, 10)` | 1 | 829 | Да |

Ответ: `4 829`. Программа — файл [17-sem.txt](topic-17/files/17-sem.txt):

```python
with open("17-sem.txt") as f:
    a = [int(part) for part in f.read().split()]

selected = []

for x in a:
    if abs(x) % 10 == 7:
        selected.append(x)

m = min(selected)

count = 0
best = None

for i in range(len(a) - 1):
    x = a[i]
    y = a[i + 1]

    endings_count = (
        int(abs(x) % 10 == 7)
        + int(abs(y) % 10 == 7)
    )

    square_sum = x ** 2 + y ** 2

    if endings_count == 1 and square_sum < m ** 2:
        count += 1

        if best is None or square_sum > best:
            best = square_sum

if count > 0:
    print(count, best)
else:
    print("Подходящих пар нет")
```

```output
4 829
```

Здесь полезно обратить внимание на три независимых решения:

- для проверки окончания используется `abs`;
- для поиска минимума используются исходные значения;
- для ответа сравниваются суммы квадратов, а не обычные суммы.

Именно такие различия нужно удерживать при чтении длинного условия.

---

**В задачах на тройки обычно меняется число проверяемых элементов, а общий алгоритм остаётся прежним.**

Учебное условие:

> Последовательность содержит положительные целые числа. В соседней тройке ровно два числа должны быть четырёхзначными, хотя бы одно — делиться на три, а сумма должна превышать максимальный элемент всей последовательности, оканчивающийся на 17. Найти количество таких троек и максимальную сумму.

Предполагаем, что число для предварительного максимума существует. Пример: 1017, 2000, 6, 3001, 4001, 8, 123. Максимальное число с окончанием `17` — 1017.

| Тройка | Четырёхзначных | Кратных 3 | Сумма | Подходит? |
|---|---:|---:|---:|---|
| `(1017, 2000, 6)` | 2 | 2 | 3023 | Да |
| `(2000, 6, 3001)` | 2 | 1 | 5007 | Да |
| `(6, 3001, 4001)` | 2 | 1 | 7008 | Да |
| `(3001, 4001, 8)` | 2 | 0 | 7010 | Нет |
| `(4001, 8, 123)` | 1 | 1 | 4132 | Нет |

У четвёртой тройки сумма больше, чем у третьей. Но она не проходит условие, поэтому не может определять максимум ответа. Ответ: `3 7008`. Программа — файл [17-troyki.txt](topic-17/files/17-troyki.txt):

```python
with open("17-troyki.txt") as f:
    a = [int(part) for part in f.read().split()]

selected = [x for x in a if x % 100 == 17]
threshold = max(selected)

results = []

for i in range(len(a) - 2):
    x = a[i]
    y = a[i + 1]
    z = a[i + 2]

    four_digit_count = (
        int(1000 <= x <= 9999)
        + int(1000 <= y <= 9999)
        + int(1000 <= z <= 9999)
    )

    multiple_count = (
        int(x % 3 == 0)
        + int(y % 3 == 0)
        + int(z % 3 == 0)
    )

    current_sum = x + y + z

    condition_1 = four_digit_count == 2
    condition_2 = multiple_count >= 1
    condition_3 = current_sum > threshold

    if condition_1 and condition_2 and condition_3:
        results.append(current_sum)

if len(results) > 0:
    print(len(results), max(results))
else:
    print("Подходящих троек нет")
```

```output
3 7008
```

Здесь числа по условию положительные, поэтому `abs` не требуется ни при проверке количества цифр, ни при проверке окончания.

---

**Среднее арифметическое нужно вычислять по той группе элементов, которая названа в условии.**

Среднее — это сумма значений, делённая на их количество. Для чисел 2, 4, 12 получаем (2 + 4 + 12) / 3 = 6.

Если требуется среднее всех чётных элементов последовательности:

```python
even_numbers = [x for x in a if x % 2 == 0]

average = sum(even_numbers) / len(even_numbers)
```

Нельзя делить сумму чётных элементов на общее количество элементов файла. Знаменатель должен соответствовать той же группе, что и числитель.

Также не нужно использовать `//`: `sum(even_numbers) // len(even_numbers)` **округлит результат вниз** и может изменить проверки. Например, настоящее среднее равно `6.5`. Тогда число `6` меньше среднего. Но после округления до `6` проверка `6 < 6` уже ложна.

---

**Сравнение со средним можно выполнить точно, вообще не вычисляя дробное число.**

Пусть `S` — сумма выбранных элементов, `K` — их количество, `K > 0`. Тогда x < S / K. Умножаем обе части на положительное число `K`. **Направление неравенства не меняется**: x · K < S. В Python: `x * K < S`.

:::pick Сравнение со средним и запись без деления
- *`x < S / K` | `x * K < S`
- `x <= S / K` | `x * K <= S`
- `x > S / K` | `x * K > S`
- `x >= S / K` | `x * K >= S`
:::

Так мы сохраняем вычисления в целых числах.

Теперь учебная задача:

> В соседней паре одно число делится на три, а другое меньше среднего арифметического всех чётных элементов последовательности. Найти количество таких пар и максимальную сумму.

Последовательность 2, 9, 4, 7, 12. Чётные числа 2, 4, 12, их среднее равно 6.

| Пара | Подходит? | Почему |
|---|---|---|
| `(2, 9)` | Да | 9 кратно 3, а 2 меньше 6 |
| `(9, 4)` | Да | 9 кратно 3, а 4 меньше 6 |
| `(4, 7)` | Нет | Ни одно число не кратно 3 |
| `(7, 12)` | Нет | 12 кратно 3, но другое число 7 не меньше 6 |

Ответ: `2 13`. Программа без деления — файл [17-srednee.txt](topic-17/files/17-srednee.txt):

```python
with open("17-srednee.txt") as f:
    a = [int(part) for part in f.read().split()]

even_numbers = [x for x in a if x % 2 == 0]

even_sum = sum(even_numbers)
even_count = len(even_numbers)

# Предполагается, что чётные элементы существуют.

results = []

for i in range(len(a) - 1):
    x = a[i]
    y = a[i + 1]

    first_case = (
        x % 3 == 0
        and y * even_count < even_sum
    )

    second_case = (
        y % 3 == 0
        and x * even_count < even_sum
    )

    if first_case or second_case:
        results.append(x + y)

if len(results) > 0:
    print(len(results), max(results))
else:
    print("Подходящих пар нет")
```

```output
2 13
```

Даже если оба распределения ролей подходят, пара добавляется только один раз: у нас один `if` с объединением через `or`.

---

**Предварительные вычисления не стоит повторять внутри каждого шага цикла.**

Например:

```python
for i in range(len(a) - 1):
    if a[i] > sum(a) / len(a):
        ...
```

Здесь `sum(a)` заново проходит по всему списку на каждом повторении. Если список длинный, это создаёт много лишней работы. Лучше:

```python
average = sum(a) / len(a)

for i in range(len(a) - 1):
    if a[i] > average:
        ...
```

То же относится к `min(a)`, `max(a)` и отбору элементов всей последовательности.

Практическое правило:

> Если величина не зависит от текущего индекса `i`, подумай, можно ли вычислить её до цикла.

Но минимум текущей тройки `min(x, y, z)` зависит от рассматриваемых элементов, поэтому его как раз нужно находить внутри перебора.

---

**Есть несколько преобразований, которые почти всегда ломают задачу на соседство.**

1. **Сортировка всей последовательности** `a.sort()`. Она меняет порядок элементов. Например, 10, 1, 20 имеет соседние пары (10, 1) и (1, 20). После сортировки 1, 10, 20 получаются (1, 10) и (10, 20). Появилась другая пара.
2. **Предварительное удаление элементов**, которые сами по себе не обладают нужным свойством. Допустим, нужно проверить соседние пары, где хотя бы одно число чётное, в последовательности 2, 7, 4. Если сначала оставить только чётные 2, 4, мы создадим новую пару (2, 4), которой в исходной последовательности не было.
3. **Удаление повторов.** Оно меняет и количество элементов, и их соседство.

<figure class="plate-figure">
%%seq_broken([10, 1, 20], [2, 7, 4])%%
<figcaption>Слева пары исходной последовательности, справа — после сортировки и после отбора чётных. Пар (10, 20) и (2, 4) в исходной последовательности не было, а условие задачи говорит именно о ней.</figcaption>
</figure>

Отбирать отдельный список для вычисления глобального порога можно. Заменять им исходную последовательность для перебора соседей обычно нельзя.

Исходный список `a` лучше сохранять в том порядке и составе, в котором он прочитан из файла.

---

**Итого.**

- Величина всей последовательности считается до перебора групп: окончательный порог известен только после последнего элемента.
- Сначала отбираются нужные элементы (`[x for x in a if …]`), затем к ним применяется `min`, `max`, `len`, `sum`; в список кладутся исходные числа.
- Среднее считается по той же группе, что названа в условии, а сравнение с ним — без деления: `x * K < S`.
- Порог вычисляется один раз, до цикла; отобранный список не заменяет исходную последовательность.
