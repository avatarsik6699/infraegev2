**Округление в задании 7 определяется вопросом, а не привычкой «после пяти увеличивать».** Округлять ответ нужно в 17 задачах из 80, и в 10 из 23 задач 2025–2026 годов; ещё четыре задачи 2025 года требуют строгого неравенства и счёта файлов на носителях.

С округлением ты уже встречался в каждой подтеме: длину кода округляли вверх, наибольшую глубину — вниз, «наименьшее целое число Кбайт» — вверх, время передачи альбома — тремя разными способами. Здесь все случаи собраны в одно правило. Основной пример — объём 12,1 Кбайт и заголовок трека H Кбайт.

---

**Что спрашивают, то и определяет направление округления.** Разберём основные случаи:

| Что требуется | Что делать |
|---|---|
| Минимум целых единиц памяти, чтобы данные поместились | Округлить вверх |
| Максимальное число целых объектов в ограниченном объёме | Округлить вниз |
| Максимальная целая глубина при ограничении объёма или скорости | Округлить вниз |
| Целая часть положительного числа | Отбросить дробную часть |
| Округление до ближайшего целого | Использовать обычное округление по условию |
| Ответ по строгому неравенству | Проверить, разрешена ли сама граница |

Например, файл занимает 12,1 Кбайт. Ответ зависит от того, что спрашивают:

- минимальное целое количество Кбайт для хранения — 13: двенадцати не хватает;
- целую часть объёма — 12;
- объём, округлённый до ближайшего целого, — тоже 12.

Совпадение двух последних ответов не означает, что правила одинаковые. Для 12,8 целая часть — 12, а ближайшее целое — 13.

---

**Не округляй промежуточные результаты без необходимости.** Если время получилось 179,9 секунды, а спрашивают целую часть минут, то 179,9 / 60 = 2,9983…, и ответ — 2. Если сначала округлить секунды до 180, получится ошибочный ответ 3.

**Сначала переведи результат в запрошенную единицу, затем выполни требуемое округление.**

---

**В Python у каждого вопроса своя операция.** Целая часть положительного числа — `int(x)` или `a // b` для целых a и b, округление вверх — `ceil`, ближайшее целое — {{round|`round`}}:

```python
from math import ceil

x = 12.8
print(int(x), ceil(x), round(x))
print(round(12.5), round(13.5))
```

```output
12 13 13
12 14
```

Вторая строка — ловушка `round`: ровно половину он округляет **к чётному**, поэтому 12,5 → 12, а 13,5 → 14. Если в задаче получилось ровно x,5 и спрашивают ближайшее целое по школьному правилу, реши этот случай руками.

---

**Строгие неравенства требуют отдельного внимания.** Формулировки переводятся буквально:

:::pick Формулировка в условии и запись
- *Не более a | x ≤ a
- Не менее a | x ≥ a
- Меньше a | x < a
- Больше a | x > a
- Превышает a | x > a
:::

Пусть искомое число должно быть целым. Если x ≥ 10, минимальный ответ — 10. Если x > 10, минимальный ответ — **11**. Поэтому для строгого неравенства нельзя бездумно применять округление вверх: округление числа 10 вверх даёт 10, но оно не удовлетворяет x > 10.

---

**Наименьшее целое за строгой границей проверяют соседним значением.** Звуковые данные четырёх треков вместе занимают 600 Кбайт. Каждый трек содержит одинаковый заголовок размером H Кбайт, причём H — целое число. Канал передаёт 20 Кбайт/с. Известно, что скачивание **превышает** 32 секунды.

1. Полный объём 600 + 4H, время (600 + 4H) / 20.
2. По условию (600 + 4H) / 20 > 32. Умножаем обе стороны на положительное число 20: 600 + 4H > 640.
3. Вычитаем 600: 4H > 40. Делим на 4: H > 10.
4. Минимальное целое значение **H = 11 Кбайт**.

Проверка: при H = 10 время равно ровно 32 секундам — не подходит; при H = 11 время равно 644 / 20 = 32,2 секунды — подходит. **Проверка соседнего целого значения — надёжный способ проверить ответ на максимум или минимум.**

Ту же проверку можно поручить программе: увеличивать H, пока время ещё **не превышает** 32 секунды. Запусти её по шагам:

```python run header.py
h = 0
while (600 + 4 * h) / 20 <= 32:
    h += 1
print(h)
```

```output
11
```

Цикл выходит на первом H, при котором время стало больше 32 секунд. Условие цикла — отрицание условия задачи: «превышает» — `>`, значит, крутимся, пока `<=`. С крупными числами экзаменационной задачи программа та же, только шагов больше.

---

**Округлять нужно на том уровне, на котором выделяется память.** Допустим, одна запись содержит пять кодов по шесть бит: 5 · 6 = 30 бит. Если коды записываются подряд, а для всей записи выделяется целое число байтов, нужно ⌈30 / 8⌉ = 4 байта. Если условие требует целое число байтов **на каждый код**, каждый шестибитный код займёт один байт, всего пять байтов.

<figure class="plate-figure">

<figcaption>Тридцать битов подряд занимают 4 байта, два бита последнего байта свободны. Если каждому коду дан свой байт, в каждом пустуют два бита, и байтов уже 5.</figcaption>
</figure>

Другой пример: есть десять отдельных записей по 30 бит, и каждая занимает целое число байтов. Тогда 10 · 4 = 40 байт. Нельзя сначала сложить биты и округлить один раз: ⌈10 · 30 / 8⌉ = 38 — так мы разрешили бы одной записи использовать свободные биты байта другой записи, чего условие не допускает. Та же логика работает для выделения памяти целыми Кбайтами или блоками заданного размера.

Если никаких специальных правил хранения не дано, **не нужно** самостоятельно добавлять округление каждого пикселя, строки изображения или отсчёта до байта.

---

**На носитель помещается целое число файлов — округляем вниз; носителей нужно целое число — вверх.** Если один файл занимает V₁, а доступная память — M, то n · V₁ ≤ M, и максимальное количество файлов n = ⌊M / V₁⌋. Скобки ⌊ ⌋ означают округление вниз до целого.

Например, носитель вмещает 1000 Мбайт, а файл занимает 240 Мбайт: 1000 / 240 = 4,1666…, поместятся четыре целых файла. Если же надо определить число таких носителей для десяти файлов, и файлы нельзя разделять между носителями, сначала находим вместимость одного носителя — четыре файла. Затем ⌈10 / 4⌉ = 3.

<figure class="plate-figure">
%%vol_cards(1000, 240, 10, "Мбайт")%%
<figcaption>Пятый файл не помещается в оставшиеся 40 Мбайт первого носителя и уходит на второй. На каждом носителе остаётся свободное место, которое нельзя отдать части другого файла.</figcaption>
</figure>

При запрете делить файлы недостаточно просто сравнить суммарный объём с суммарной ёмкостью: на каждом носителе могут оставаться неиспользуемые промежутки. Это уточнение нужно учитывать только тогда, когда соответствующее ограничение есть в условии.

**Сколько файлов на заполненных носителях — это (число носителей − 1) · файлов на носителе.** В задачах 2025 года фотограф меняет карту памяти, когда на ней не хватает места для следующего снимка, и спрашивают, сколько снимков оказалось на всех картах, кроме последней. Все карты, кроме последней, заполнены одинаково — по ⌊M / V₁⌋ снимков.

Пусть снимки 4000 × 3000 пикселей с палитрой из 20 000 000 цветов, карта вмещает 64 Гбайт, сделано 10 000 снимков. Числа крупные, поэтому считает программа ({{intdiv|`//`}} — вниз, `ceil` — вверх):

```python
from math import ceil

photo = 4000 * 3000 * bits(20000000)
card = 64 * 2 ** 33
per_card = card // photo
cards = ceil(10000 / per_card)
print(per_card, cards, (cards - 1) * per_card)
```

```output
1832 6 9160
```

На карту помещается 1832 снимка, всего понадобилось 6 карт, и на первых пяти — 5 · 1832 = 9160 снимков. Остальные 840 снимков — на последней карте.

---

**Итого.**

- Направление округления задаёт вопрос: память — вверх, число объектов и глубина — вниз, «целая часть» — отбросить, «ближайшее» — к ближайшему.
- Сначала перевести в нужную единицу, потом округлять.
- Строгое «превышает»: при x > 10 ответ 11; проверяй соседнее целое.
- Округляют там, где выделяется память: 10 записей по 30 бит — 40 байт, а не 38.
- Файлов на носителе ⌊M / V₁⌋, носителей ⌈n / ⌊M / V₁⌋⌉; на заполненных — (носителей − 1) · файлов на носителе.

**Ответы для проверки:**
