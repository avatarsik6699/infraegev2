**Дополнительный урок — для продвинутых.** Он нужен для двух задач подборок без даты, где граница — 2⁶³ или 3⁴⁰ и даже подсчёт выбором позиций из подтемы 6 не помогает. На реальных экзаменах таких задач не было. Задачи основных подтем решаются без него, а опирается урок на подтемы 4 и 6.

**Если диапазон огромен, подходящие числа можно считать по цифрам, не перебирая каждое число.** Это более сложный приём. Он нужен для задач наподобие «сколько чисел до большой границы имеют заданную сумму цифр», в том числе с произведением цифр в другом основании.

Сначала разберём сумму цифр на числах до 250 с суммой цифр 6, потом произведение цифр.

---

**Числа до границы строят слева направо и помнят, совпадает ли начало с началом границы.** Представим, что граница равна 250. Будем строить числа слева направо, используя три позиции: 000, 001, 002, …, 250. Дополнительные нули слева не меняют сумму цифр. Каждое число представлено ровно одной такой записью.

Во время построения нужно помнить три вещи:

1. На какой позиции мы находимся.
2. Какую сумму ещё нужно набрать.
3. Совпадает ли уже построенное начало с началом границы.

Почему нужен третий пункт?

- Если первая цифра равна 1, мы уже меньше 250. Дальше можно ставить любые цифры.
- Если первая цифра равна 2, следующая цифра не должна превышать 5.
- Если уже записано 25, последняя цифра не должна превышать 0.

Разные начала могут приводить к одинаковой оставшейся задаче. Например, если начало уже меньше границы, остались две позиции и нужно набрать сумму 5, количество продолжений не зависит от того, какое именно меньшее начало было выбрано. Значит, такие задачи можно запоминать в кэше. Этот способ называют **динамическим программированием по цифрам**.

---

**Сначала нужна функция, которая возвращает цифры числа слева направо.**

```python
def digits_in_base(number, base):
    if number == 0:
        return [0]

    digits = []

    while number > 0:
        digits.append(number % base)
        number //= base

    digits.reverse()
    return digits
```

Здесь:

- `digits = []` создаёт пустой {{list|список}};
- `append` добавляет элемент в конец;
- сначала остатки дают цифры справа налево, и `reverse()` переворачивает список;
- `number //= base` означает `number = number // base` ({{augassign|сокращённое присваивание}}).

Теперь функция подсчёта:

```python
from functools import cache


def count_sum(bound, target, base=10):
    if bound < 0:
        return 0

    digits = digits_in_base(bound, base)

    @cache
    def solve(position, remaining, equal):
        if remaining < 0:
            return 0

        if position == len(digits):
            if remaining == 0:
                return 1
            return 0

        if equal:
            limit = digits[position]
        else:
            limit = base - 1

        total = 0

        for digit in range(limit + 1):
            new_equal = equal and digit == digits[position]

            total += solve(
                position + 1,
                remaining - digit,
                new_equal
            )

        return total

    return solve(0, target, True)
```

Здесь {{defarg|`base=10`}} означает: если основание отдельно не передано, использовать десятичную систему.

Функция `solve` описана внутри `count_sum`, поэтому может пользоваться подготовленным списком `digits`. Для каждого запуска `count_sum` создаётся свой {{cache|кэш}}.

Аргументы `solve` имеют следующий смысл:

| Аргумент | Что означает |
|---|---|
| `position` | Индекс следующей заполняемой позиции |
| `remaining` | Сумма, которую ещё нужно набрать |
| `equal` | Совпадает ли построенное начало с началом границы |

`True` означает «истина», `False` — «ложь». Операция {{andor|`and`}} даёт истину, когда истинны оба условия. `len(digits)` — количество цифр границы.

Выражение `equal and digit == digits[position]` означает: **новое начало совпадает с границей, если совпадало старое и текущая цифра тоже совпала**.

Почему в конце возвращается 1 или 0? Потому что функция здесь считает **число подходящих продолжений**:

- если все позиции заполнены и нужная сумма набрана — построен один подходящий вариант;
- если сумма не совпала — подходящих вариантов в этой завершённой ветви нет.

Это уже другая функция, чем исходная F(n): исходная вычисляла характеристику одного числа, а `solve` считает количество вариантов.

Пример использования:

```python
answer = count_sum(250, 6) - count_sum(99, 6)
print(answer)
```

```output
11
```

Получим 11: столько чисел от 100 до 250 имеют сумму цифр 6. Общий переход от верхней границы к отрезку:

количество на [L, R] = количество до R − количество до L − 1.

**Число состояний здесь определяется количеством позиций и возможных оставшихся сумм**, а не количеством чисел в диапазоне.

---

**Для произведения цифр нужно дополнительно различать ведущие нули и настоящие нули внутри числа.** Например, запись `006` обозначает число 6. Её произведение цифр числа равно 6, а не нулю. Но у числа 106 произведение цифр действительно равно нулю.

Поэтому при построении записи нужно помнить, началось ли число, то есть встретилась ли уже первая ненулевая цифра.

Для положительного требуемого произведения удобно хранить не накопленное произведение, а множитель, который ещё осталось набрать. Например, если цель 12, а мы поставили цифру 3, оставшиеся цифры должны дать произведение 12 / 3 = 4. Если цифра не делит оставшееся произведение нацело, такая ветвь не подходит.

Ниже функция для **положительного `target`**, считающая положительные числа до `bound`. Она использует уже описанную `digits_in_base`.

```python
from functools import cache


def count_product(bound, target, base=10):
    if bound < 1:
        return 0

    digits = digits_in_base(bound, base)

    @cache
    def solve(position, remaining, equal, started):
        if position == len(digits):
            if started and remaining == 1:
                return 1
            return 0

        if equal:
            limit = digits[position]
        else:
            limit = base - 1

        total = 0

        for digit in range(limit + 1):
            new_equal = equal and digit == digits[position]

            if not started and digit == 0:
                total += solve(
                    position + 1,
                    remaining,
                    new_equal,
                    False
                )

            elif digit > 0 and remaining % digit == 0:
                total += solve(
                    position + 1,
                    remaining // digit,
                    new_equal,
                    True
                )

        return total

    return solve(0, target, True, False)
```

Дополнительный аргумент `started` означает, что число уже началось. Условие `not started` означает «число ещё не началось». Пока ставим ведущие нули, оставшееся произведение не меняется. После начала числа ноль запрещён, поскольку положительное целевое произведение уже невозможно получить.

Проверка `digit > 0` стоит перед `remaining % digit == 0`: если цифра нулевая, Python не вычисляет вторую часть `and`, и деления на ноль не происходит.

В конце требуется `remaining == 1`, потому что все нужные множители уже должны быть набраны. Пример:

```python
print(count_product(500, 6))
```

```output
13
```

Для другого основания передаётся третий аргумент. Например, при основании 15 допустимые цифры имеют числовые значения от 0 до 14.

Случай целевого произведения 0 требует отдельного учёта нулевой цифры после начала числа; приведённый код рассчитан на положительную цель.

---

**Итого.**

- Числа до границы строят слева направо: состояние — позиция, что осталось набрать и совпадает ли начало с границей.
- Одинаковые состояния повторяются, поэтому `solve` кэшируют: состояний столько, сколько позиций и остатков, а не чисел.
- Отрезок [L, R] — разность подсчётов до R и до L − 1.
- Для произведения цифр помни, началось ли число: ведущие нули не обнуляют произведение, ноль внутри числа — обнуляет.
