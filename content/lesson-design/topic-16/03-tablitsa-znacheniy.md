**Таблицу значений из подтемы 1 можно заполнить программой: циклом по аргументу, без рекурсивных вызовов.** Так удобно считать две связанные функции и сумму всех предыдущих значений. А при аргументах в тысячи цикл не упирается в предел глубины рекурсии — это второй способ для задач с большими аргументами.

Почти всё время будем заполнять таблицу из подтемы 1: F(1) = 1, F(2) = 3, F(n) = F(n − 1) + 2F(n − 2), F(6) = 43. Начнём с ещё более простого случая — знакомой функции F(1) = 2, F(n) = F(n − 1) + 3n.

---

**Если каждое значение зависит только от непосредственно предыдущего, вычисления удобно выполнять одной переменной.** Для F(1) = 2, F(n) = F(n − 1) + 3n можно написать:

```python
value = 2

for n in range(2, 5):
    value = value + 3 * n

print(value)
```

```output
29
```

Здесь {{for|`range(2, 5)`}} задаёт числа 2, 3, 4: правая граница в `range` не включается. Цикл `for n in range(2, 5):` поочерёдно присваивает `n` эти значения и выполняет своё тело.

Перед первой итерацией — первым выполнением тела цикла — переменная `value` содержит F(1). Далее при n = 2 она становится F(2) = 8, при n = 3 — F(3) = 17, при n = 4 — F(4) = 29.

Строка `value = value + 3 * n` сначала вычисляет правую часть со старым значением `value`, затем записывает результат обратно. Сокращённая запись того же действия — {{augassign|`value += 3 * n`}}.

Смысл решения:

> Перед очередным шагом у нас уже есть F(n − 1). По формуле получаем F(n) и сохраняем его вместо предыдущего значения.

Это работает и для более сложных зависимостей от одного предыдущего значения. Например, F(n) = 3F(n − 1) + n переводится в обновление `value = 3 * value + n`.

Но **«одно предыдущее значение» не обязательно означает F(n − 1)**. Это может быть F(n − 2), F(n // 2) или другое значение. В таком случае порядок вычислений и способ хранения нужно выбирать с учётом конкретной зависимости.

---

**Таблицу нескольких предыдущих значений удобно хранить в списке.** У каждого элемента {{list|списка}} есть номер — **индекс**; в Python индексы начинаются с нуля. Договоримся хранить F(n) в элементе `f[n]`:

```python
N = 6

f = [0] * (N + 1)

f[1] = 1
f[2] = 3

for n in range(3, N + 1):
    f[n] = f[n - 1] + 2 * f[n - 2]

print(f[N])
```

```output
43
```

Строка `f = [0] * (N + 1)` создаёт список из `N + 1` нулей. Почему именно `N + 1`? Потому что нам нужны элементы с индексами 0, 1, 2, …, N. Всего их N + 1.

В этом примере элемент `f[0]` не используется. Его наличие **не означает**, что по условию F(0) = 0. Это лишь дополнительное место, позволяющее удобно сопоставить индекс и аргумент. Остальные нули до заполнения — тоже заготовки, а не вычисленные значения функции.

**Смысл правильного порядка:** когда мы вычисляем `f[n]`, элементы `f[n - 1]` и `f[n - 2]` уже заполнены. Для рассматриваемой формулы можно заполнить таблицу по возрастанию аргумента: 1, 2, 3, …, N.

Такое вычисление, при котором результаты небольших подзадач сохраняют и используют для следующих, называют **динамическим программированием**. В данной задаче за этим термином стоит именно заполнение таблицы в подходящем порядке.

Так же записывается таблица для функции с ветвями из подтемы 2 (F(n) = n при n ≤ 2, F(n − 1) + n при чётном n, 2F(n − 2) при нечётном): ветвь выбирается для каждого n, как и в рекурсии.

```python
N = 8
f = [0] * (N + 1)

for n in range(1, N + 1):
    if n <= 2:
        f[n] = n
    elif n % 2 == 0:
        f[n] = f[n - 1] + n
    else:
        f[n] = 2 * f[n - 2]

print(f[N])
```

```output
16
```

---

**Если будущим вычислениям нужны только два последних значения, всю таблицу хранить необязательно.** Для той же функции F(n) = F(n − 1) + 2F(n − 2) можно держать два числа: перед очередной итерацией `a` = F(n − 2), `b` = F(n − 1). На каждом шаге:

1. получаем `current` = F(n);
2. старое F(n − 1) становится предпоследним: `a = b`;
3. новое F(n) становится последним: `b = current`.

Пройди программу по шагам и следи за `a`, `b` и `current`:

```python run last_two.py
N = 6

a = 1
b = 3

for n in range(3, N + 1):
    current = b + 2 * a
    a = b
    b = current

print(b)
```

```output
43
```

Здесь **важен порядок присваиваний**. Ошибочная последовательность:

```python
a = b
b = b + 2 * a
```

В первой строке старое значение `a` потерялось. Во второй строке вместо двух разных предыдущих значений используется фактически одно. Промежуточная переменная `current` позволяет сначала вычислить новое значение, пока оба старых ещё доступны.

Однако полная таблица часто удобнее для проверки. Она также нужна, если в ответе используются несколько ранее вычисленных значений.

**При зависимости от большего аргумента таблицу обычно заполняют по убыванию.** Рассмотрим функцию из подтемы 2:

F(n) = 1, n ≥ 10;  
F(n) = n + F(n + 1), n < 10.

Найдём F(7): F(10) = 1, F(9) = 9 + 1 = 10, F(8) = 8 + 10 = 18, F(7) = 7 + 18 = 25. Табличная программа:

```python
f = [0] * 11
f[10] = 1

for n in range(9, 0, -1):
    f[n] = n + f[n + 1]

print(f[7])
```

```output
25
```

В записи `range(9, 0, -1)` последний аргумент задаёт шаг −1. Получаются числа 9, 8, 7, …, 1. Ноль не включается.

Главное правило:

> Перед вычислением значения должны быть готовы все результаты, которые используются в его формуле.

Поэтому:

:::pick Зависимость и подходящий порядок
- *F(n − 1), F(n − 2) | По возрастанию n
- F(n + 1), F(n + 2) | По убыванию n
- F(n // 2) при положительном n | По возрастанию или через короткую рекурсию
- Смешанные зависимости | Сначала отдельно выяснить порядок
:::

Если при n < K используется F(n + s), вызов может попасть не только в K, но и выше. Например, при шаге 3 могут потребоваться базовые значения для K, K + 1, K + 2. Границы хранения должны учитывать эти переходы.

---

**Несколько функций нужно рассматривать как несколько связанных таблиц значений.** Пусть:

F(1) = 1, G(1) = 2;  
F(n) = F(n − 1) + G(n − 1);  
G(n) = 2F(n − 1) + G(n − 1), n > 1.

Вычисляем по строкам:

| n | F(n) | G(n) |
|---:|---:|---:|
| 1 | 1 | 2 |
| 2 | 1 + 2 = 3 | 2 · 1 + 2 = 4 |
| 3 | 3 + 4 = 7 | 2 · 3 + 4 = 10 |
| 4 | 7 + 10 = 17 | 2 · 7 + 10 = 24 |
| 5 | 17 + 24 = 41 | 2 · 17 + 24 = 58 |

Оба новых результата используют значения из предыдущей строки. Код:

```python
N = 5

f = [0] * (N + 1)
g = [0] * (N + 1)

f[1] = 1
g[1] = 2

for n in range(2, N + 1):
    f[n] = f[n - 1] + g[n - 1]
    g[n] = 2 * f[n - 1] + g[n - 1]

print(f[N], g[N])
```

```output
41 58
```

Здесь обновление `f[n]` не мешает вычислению `g[n]`, поскольку для второго используется `f[n - 1]`.

А для другой системы — G(n) = G(n − 1) + 1, F(n) = G(n) + F(n − 1) — внутри цикла сначала нужно вычислять `g[n]`:

```python
g[n] = g[n - 1] + 1
f[n] = g[n] + f[n - 1]
```

Причина: F(n) использует новое значение G(n).

Если функции вызывают друг друга, такую рекурсию называют **взаимной**. При анализе нужно различать не только аргументы, но и имена функций: F(10) и G(10) — разные вычисления.

Если записываешь обе функции через `def`, первый реальный вызов делай после описания обеих.

---

**Иногда функция зависит от суммы всех предыдущих значений.** Например:

F(1) = 2;  
F(n) = F(1) + F(2) + … + F(n − 1) + n, n > 1.

В условии длинную сумму могут записать короче: F(n) = Σᵢ₌₁ⁿ⁻¹ F(i) + n. Знак Σ означает суммирование:

- снизу указано, с какого значения начинается индекс i;
- сверху — каким значением заканчивается;
- справа — что именно складывается.

Для n = 4: Σᵢ₌₁³ F(i) = F(1) + F(2) + F(3).

Начальные вычисления: F(1) = 2, F(2) = 2 + 2 = 4, F(3) = 2 + 4 + 3 = 9, F(4) = 2 + 4 + 9 + 4 = 19.

Можно каждый раз складывать все предыдущие элементы заново. Но сумма меняется просто: после получения нового значения оно добавляется к прежней сумме. Поэтому будем хранить накопленную сумму отдельно:

```python
N = 5

f = [0] * (N + 1)
f[1] = 2

total = f[1]

for n in range(2, N + 1):
    f[n] = total + n
    total += f[n]

print(f[N])
```

```output
39
```

Перед вычислением `f[n]` переменная `total` содержит F(1) + F(2) + … + F(n − 1). После вычисления добавляем к ней новое F(n). Порядок этих действий важен: в формуле требуется сумма предыдущих значений, **без текущего**.

Такую сумму начального отрезка последовательности называют **префиксной суммой**.

Если повторно складывать все предыдущие элементы, количество слагаемых составит примерно 1 + 2 + … + (N − 1). Оно растёт примерно как N². При сохранении накопленной суммы на каждом шаге требуется лишь несколько арифметических действий.

---

**Итого.**

- Зависимость от одного предыдущего значения — одна переменная и обновление `value = формула(value, n)`.
- Список `f` из N + 1 элементов хранит F(n) в `f[n]`; `f[0]` и нули до заполнения — заготовки, а не значения функции.
- Для двух последних значений новое значение сначала кладут в `current`, потом сдвигают `a` и `b`.
- Порядок заполнения задают зависимости: F(n − 1) — по возрастанию, F(n + 1) — по убыванию от верхней базы.
- Две функции — две таблицы, заполняемые строка за строкой; сумма всех предыдущих — накопленная `total`, к которой текущее значение добавляют после вычисления.
