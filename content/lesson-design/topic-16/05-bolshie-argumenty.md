**Перед вычислением больших значений нужно внимательно посмотреть на само выражение, которое требуется найти: часто огромные значения сокращаются, и ответ получается из нескольких шагов раскрытия.** Это главный тип задания с 2023 года: разность или отношение значений при аргументах в тысячи — 25 задач подборок, все экзаменационные задачи 2023–2026 годов, кроме одной, и демоверсии 2023–2025 годов.

Здесь же — цепочки с шагом, две функции с цепочками в разные стороны и точная арифметика.

Начнём с функции подтемы 1: F(1) = 2, F(n) = F(n − 1) + 3n — и найдём F(2026) − F(2023). Для отношений возьмём произведение F(n) = nF(n − 1).

---

**Разность близких значений сокращается: остаются только прибавления на последних шагах.** Пусть снова F(1) = 2; F(n) = F(n − 1) + 3n. Требуется F(2026) − F(2023).

Раскроем только большее значение: F(2026) = F(2025) + 3 · 2026. Ещё один шаг: F(2026) = F(2024) + 3 · 2025 + 3 · 2026. Ещё один:

F(2026) = F(2023) + 3 · 2024 + 3 · 2025 + 3 · 2026.

Теперь вычитаем F(2023):

F(2026) − F(2023) = 3 · 2024 + 3 · 2025 + 3 · 2026 = 3(2024 + 2025 + 2026) = 18225.

<figcaption>F(2026) — это всё значение F(2023) плюс три прибавления 6072, 6075 и 6078. Общая часть в разности сокращается, остаётся 18 225. Длины полос не в масштабе.</figcaption>
</figure>

**Значение F(2023) сократилось.** Вычислять его не понадобилось.

Общий принцип: если F(n) = F(n − 1) + a(n), где a(n) — добавляемое на шаге число, то при N > M:

F(N) − F(M) = a(M + 1) + a(M + 2) + … + a(N),

если на этих шагах действует указанное правило.

Почему сумма начинается с M + 1? Потому что переход от F(M) к F(M + 1) добавляет именно a(M + 1). Всё, что уже содержалось внутри F(M), при вычитании исчезает.

Это полезно и при шаге 2, 3 и так далее, но сравниваемые значения должны быть связаны соответствующей цепочкой переходов.

Ответ можно проверить и программой: цепочка из двух тысяч вызовов превышает {{reclimit|предел глубины рекурсии}}, поэтому его нужно поднять (подтема 4).

```python
import sys

sys.setrecursionlimit(5000)


def F(n):
    if n == 1:
        return 2
    return F(n - 1) + 3 * n


print(F(2026) - F(2023))
```

```output
18225
```

---

**Произведения часто сокращаются столь же удобно.** Рассмотрим F(1) = 1; F(n) = nF(n − 1), n > 1. Последовательно F(2) = 2, F(3) = 3 · 2, F(4) = 4 · 3 · 2, F(5) = 5 · 4 · 3 · 2.

Произведение натуральных чисел от 1 до n называют **факториалом** и обозначают n! = 1 · 2 · 3 · … · n. Для этой функции F(n) = n!.

Но узнавание факториала не обязательно. Достаточно раскрыть несколько шагов. Например:

F(2026) / F(2023) = 2026 · 2025 · 2024 · F(2023) / F(2023).

Поскольку F(2023) ≠ 0, сокращаем: F(2026) / F(2023) = 2026 · 2025 · 2024 = 8303763600.

Теперь более сложное выражение: (F(2026) + 2F(2025)) / F(2024). Приведём оба слагаемых числителя к F(2024): F(2026) = 2026 · 2025 · F(2024), F(2025) = 2025 · F(2024). Следовательно:

(2026 · 2025 · F(2024) + 2 · 2025 · F(2024)) / F(2024).

Выносим общий множитель: 2025(2026 + 2)F(2024) / F(2024) = 2025 · 2028 = 4106700. На Python достаточно:

```python
print(2025 * (2026 + 2))
```

```output
4106700
```

Важная привычка:

> Раскрывай формулы до появления общего значения функции, которое можно вынести за скобки или сократить.

При этом внимательно следи за множителем в условии:

:::pick Формулы и получающаяся функция
- *F(1) = 1, F(n) = nF(n − 1) | F(n) = n!
- F(1) = 1, F(n) = (n − 1)F(n − 1) | F(n) = (n − 1)!
- F(1) = 3, F(n) = nF(n − 1) | F(n) = 3 · n!
:::

Один сдвиг в множителе меняет все последующие вычисления.

---

**В выражениях с несколькими вычитаниями удобно обозначать общее неизвестное одной буквой.** Пусть:

F(n) = 1, n ≤ 2;  
F(n) = F(n − 2) + n, n > 2.

Нужно найти 3F(30) − F(28) − F(26) − F(24).

Обозначим **X = F(24)**. Тогда F(26) = X + 26, F(28) = X + 26 + 28 = X + 54, F(30) = X + 26 + 28 + 30 = X + 84. Подставляем:

3(X + 84) − (X + 54) − (X + 26) − X.

Раскрываем скобки: 3X + 252 − X − 54 − X − 26 − X. Все слагаемые с X сокращаются: 252 − 54 − 26 = 172.

Мы не вычисляли F(24), потому что доказали независимость ответа от этого значения.

**Произвольно заменять настоящее базовое значение нулём или единицей нельзя.** Такая замена допустима только после доказательства, что соответствующий вклад полностью сокращается.

---

**При переходах на несколько единиц нужно учитывать, в какую цепочку попадает аргумент.** Если функция использует F(n − 2), аргументы разделяются на две цепочки: 1, 3, 5, 7, … и 2, 4, 6, 8, … Если используется F(n − 3), цепочек уже три — по возможным остаткам от деления на 3.

Например:

F(n) = n, n ≤ 5;  
F(n) = F(n − 3) + 4, n > 5.

Найдём F(20). Аргументы: 20, 17, 14, 11, 8, 5. Сделано пять переходов, каждый добавляет 4. Поэтому F(20) = F(5) + 5 · 4 = 5 + 20 = 25.

Но для F(21) цепочка другая: 21, 18, 15, 12, 9, 6, 3. Здесь шесть переходов, а базовое значение F(3) = 3. Следовательно, F(21) = 3 + 6 · 4 = 27.

<figcaption>Шаг −3: цепочка от 20 входит в зону базы n ≤ 5 ровно в 5 после 5 переходов, цепочка от 21 — в 3 после 6 переходов. Конец цепочки зависит от остатка при делении на 3.</figcaption>
</figure>

**Нельзя автоматически считать, что цепочка закончится ровно на граничном аргументе 5.**

Количество переходов можно найти из неравенства. После k вычитаний тройки аргумент равен n − 3k. Нужно впервые получить n − 3k ≤ 5. Отсюда k ≥ (n − 5) / 3: берём наименьшее целое k, удовлетворяющее этому условию.

Для n > 5 на Python: `k = (n - 5 + 2) // 3`. Знак `//` для положительных чисел даёт целую часть частного, а прибавление 2 перед делением на 3 позволяет получить **округление вверх**.

Однако сначала полезно уверенно считать шаги по цепочке. Формула должна сокращать понятное рассуждение.

---

**Условия чётности можно сочетать с сокращением больших выражений.** Пусть F(1) = F(2) = 1; при n > 2:

F(n) = 3F(n − 2), если n нечётно;  
F(n) = 2nF(n − 1) + F(n − 3), если n чётно.

Требуется F(12) / F(7). Раскрываем, выбирая ветвь для каждого аргумента:

1. Аргумент 12 чётный: F(12) = 24F(11) + F(9).
2. Оба значения справа имеют нечётные аргументы: F(11) = 3F(9) = 9F(7), F(9) = 3F(7).
3. Подставляем: F(12) = 24 · 9F(7) + 3F(7) = 219F(7).

Следовательно, F(12) / F(7) = 219.

Здесь понадобились только значения с аргументами 12, 11, 9, 7. Вычислять подряд все значения от 1 до 12 не было необходимости.

---

**При увеличении аргумента в несколько раз результат часто определяется количеством переходов до базы.** Пусть:

F(n) = n, n > 100;  
F(n) = n + F(2n), 1 ≤ n ≤ 100;  
G(n) = F(n) / n.

Найдём G(7).

Цепочка аргументов: 7, 14, 28, 56, 112. Поэтому F(7) = 7 + 14 + 28 + 56 + 112. Выносим 7: F(7) = 7(1 + 2 + 4 + 8 + 16) = 7 · 31. Значит, G(7) = 31.

Что определило число 31? **Количество удвоений до пересечения границы**: их было четыре. Вообще, если требуется k удвоений, F(n) = n(1 + 2 + 4 + … + 2ᵏ), поэтому G(n) = 1 + 2 + 4 + … + 2ᵏ = 2ᵏ⁺¹ − 1.

<details class="proof" markdown="1">
<summary>Почему 1 + 2 + 4 + … + 2ᵏ = 2ᵏ⁺¹ − 1</summary>

Последнюю формулу можно получить вычитанием. Пусть S = 1 + 2 + 4 + … + 2ᵏ. Тогда 2S = 2 + 4 + 8 + … + 2ᵏ⁺¹. Все слагаемые, кроме крайних, совпадают, поэтому 2S − S = 2ᵏ⁺¹ − 1.

</details>

Теперь спросим: для каких натуральных n выполняется G(n) = G(7)? Нужны **ровно четыре удвоения**. После трёх аргумент ещё не должен превышать 100, а после четырёх — уже должен: 8n ≤ 100 и 16n > 100. Следовательно, 6,25 < n ≤ 12,5. Подходят 7, 8, 9, 10, 11, 12. Всего шесть чисел.

<figcaption>Удвоения до первого числа больше 100: у 7 и 12 их по четыре, поэтому G = 31; у 6 — пять удвоений, у 13 — три. Подходят ровно числа от 7 до 12.</figcaption>
</figure>

Так условие о рекурсивной функции превратилось в два неравенства.

---

**У связанных функций направления изменения аргумента могут различаться.** Разберём небольшой самостоятельный пример:

F(n) = F(n − 4) + 20, n ≥ 12;  
F(n) = 3(G(n − 2) − 1), n < 12;  
G(n) = n, n ≥ 30;  
G(n) = G(n + 7) + 2, n < 30.

Нужно найти F(39). Сначала движемся по функции F: 39, 35, 31, 27, 23, 19, 15, 11. Произошло семь переходов: F(39) = F(11) + 7 · 20.

Для аргумента 11 действует другое правило: F(11) = 3(G(9) − 1). Теперь вычисляем G(9). Здесь аргумент увеличивается: 9, 16, 23, 30. Три перехода добавляют по 2: G(9) = G(30) + 3 · 2 = 30 + 6 = 36.

Следовательно, F(11) = 3(36 − 1) = 105, F(39) = 105 + 140 = 245.

Заметь: прибавленные на внешних шагах 140 **не попадают под умножение на 3**.

Эту задачу можно записать без рекурсивных вызовов:

```python
def G(n):
    extra = 0

    while n < 30:
        extra += 2
        n += 7

    return n + extra


def F(n):
    extra = 0

    while n >= 12:
        extra += 20
        n -= 4

    return 3 * (G(n - 2) - 1) + extra


print(F(39))
```

```output
245
```

{{while|Команда `while`}} повторяет блок, пока условие истинно. Переменная `extra` хранит сумму накопленных прибавлений.

Такое накопление подходит здесь благодаря форме правил: на каждом переходе прибавляется константа. Для другой формулы порядок выполнения отложенных операций может быть существенным.

---

**Точное соблюдение арифметики особенно важно в задачах с большими значениями.** Обозначения операций Python — {{intdiv|`/`, `//`, `%` и `**`}}. Одна ловушка из них: `n ^ 2` **не означает квадрат**. Для квадрата нужно `n ** 2`.

Целые числа Python могут храниться точно и при очень большом количестве цифр; практические ограничения связаны с памятью и временем вычислений. Обычный тип {{num|`float`}}, используемый для приближённых вещественных значений, имеет ограниченную точность. Операция `/` над целыми числами создаёт результат типа `float`.

Поэтому если по математическому условию частное точно целое, предпочтительно `a // b`. Например, `print(F(2026) // F(2023))` при доказанной делимости.

Но здесь есть важная граница применимости: **целочисленный ответ всей задачи не означает, что все промежуточные деления можно заменить на `//`.** Например:

G(n) = n / 2, n ≥ 10;  
G(n) = 1 + G(n + 3), n < 10.

Нужно найти 2G(2).

Раскрываем: G(2) = 1 + G(5) = 2 + G(8) = 3 + G(11). По базе G(11) = 11 / 2 = 5,5. Следовательно, G(2) = 8,5, 2G(2) = 17.

Если заменить 11 / 2 на `11 // 2`, получится 5, и итоговый ответ будет неверным.

Для точной работы с обыкновенными дробями есть {{fraction|`Fraction`}}. Запись `Fraction(a, b)` хранит дробь a/b через точные целые числитель и знаменатель.

```python
from fractions import Fraction


def G(n):
    if n >= 10:
        return Fraction(n, 2)

    return 1 + G(n + 3)


print(2 * G(2))
```

```output
17
```

Если дробь нужна точно, создавай её как `Fraction(a, b)`, а не как `Fraction(a / b)`. Во втором случае сначала уже выполняется приближённое деление.

Также `//` округляет вниз. Для отрицательных чисел это отличается от отбрасывания дробной части:

```python
print(-3 // 2, int(-3 / 2))
```

```output
-2 -1
```

Поэтому внимательно читай, что именно требует условие: обычное деление, округление вниз или другое действие.

---

**Итого.**

- Разность F(N) − F(M) при F(n) = F(n − 1) + a(n) — сумма a(M + 1) + … + a(N): общая часть сокращается.
- В отношении раскрывай числитель до общего значения функции и выноси его за скобки; следи за множителем в условии.
- Несколько вычитаний — обозначь общее неизвестное X и убедись, что оно сокращается.
- При шаге k аргумент идёт по своей цепочке: считай переходы до базы для каждого аргумента отдельно; удвоения до границы задают G(n) = 2ᵏ⁺¹ − 1.
- У двух функций цепочки могут идти в разные стороны; прибавления внешних шагов не попадают под множитель внутреннего правила.
- Промежуточные деления считай точно: `Fraction(a, b)`, а `//` — только при доказанной делимости.
