**Одни условия зависят от того, где стоит число, а ответ задачи часто — не количество строк, а номер строки или число из неё.** Порядок, части строки и упорядоченная строка нужны в 9 задачах из 74, а ответ «номер, сумма номеров, число из найденной строки» — в 14; почти все они — задачи 2025–2026 годов.

Порядок разберём на строке 2, 5, 5, 9, ответы — снова на учебной таблице [9.txt](topic-9/files/9.txt). Сортированная копия строки — из подтемы о суммах и средних, частоты и множество — из подтемы о повторах.

**Возрастание и неубывание — разные требования.** Строгое возрастание a₁ < a₂ < a₃ < … < aₙ: каждое следующее число больше предыдущего, равенства запрещены. Неубывание a₁ ≤ a₂ ≤ a₃ ≤ … ≤ aₙ: следующее число может быть равно предыдущему.

Например, 2, 5, 5, 9 расположены в неубывающем порядке, но не в строго возрастающем. Аналогично строгое убывание использует `>`, а невозрастание — `>=`.

В Python неубывание можно проверить так: `a == sorted(a)`. Сравнение списков через `==` требует совпадения элементов на соответствующих позициях. Если исходная строка совпадает со своей отсортированной копией, она уже расположена по неубыванию. Для строгого возрастания можно добавить отсутствие повторов — `len(set(a)) == len(a)`:

```python
a = [2, 5, 5, 9]
print(a == sorted(a))
print(a == sorted(a) and len(set(a)) == len(a))
```

```output
True
False
```

Или проверить соседние элементы напрямую. Для этого пригодится {{for|`range(n)`}}: он выдаёт целые числа от 0 до n − 1.

```python
a = [2, 5, 5, 9]
increasing = True
for i in range(len(a) - 1):
    if a[i] >= a[i + 1]:
        increasing = False
print(increasing)
```

```output
False
```

Почему `len(a) - 1`? Последняя сравниваемая пара состоит из предпоследнего и последнего элементов. Последний индекс нельзя увеличивать ещё на 1.

**Сначала отсортировать строку, а потом проверять, упорядочена ли она, нельзя.** В таком случае проверяется уже изменённый порядок. В электронной таблице для шести чисел строгое возрастание и неубывание — цепочки сравнений соседей:

```excel
=И(A1<B1;B1<C1;C1<D1;D1<E1;E1<F1)
=И(A1<=B1;B1<=C1;C1<=D1;D1<=E1;E1<=F1)
```

---

**Условия о частях строки требуют сохранять позиции.** Например, строка из восьми чисел разделена на две четвёрки: первая — столбцы 1–4, вторая — столбцы 5–8. В Python часть списка можно получить с помощью {{slice|среза}}: `a[:4]` означает «от начала до индекса 4, не включая его», поэтому берутся индексы 0, 1, 2, 3; `a[4:]` — «от индекса 4 до конца».

Если требуется, чтобы максимум был единственным и находился в первой четвёрке, а среднее первой четвёрки было меньше среднего второй:

```python
a = [3, 9, 2, 6, 5, 4, 8, 7]
first = a[:4]
second = a[4:]
m = max(a)
print(first, second)
print(a.count(m) == 1, m in first, sum(first) < sum(second))
```

```output
[3, 9, 2, 6] [5, 4, 8, 7]
True True True
```

Операция `in` проверяет наличие значения в последовательности. Делить обе суммы на 4 здесь не нужно: четвёрки одного размера. Полная проверка соединяет три условия:

```python
if (
    a.count(m) == 1
    and m in first
    and sum(first) < sum(second)
):
    answer += 1
```

Сортировать всю строку перед этим нельзя: принадлежность числа первой или второй четвёрке изменится. В таблице у четвёрок свои диапазоны: `A1:D1` и `E1:H1`; «наибольшее в первой четвёрке» — `=МАКС(A1:D1)=МАКС(A1:H1)`, единственность — `=СЧЁТЕСЛИ(A1:H1;МАКС(A1:H1))=1`.

---

**Если условие говорит об упорядоченных числах, проверяют сортированную копию.** **Арифметическая прогрессия** — последовательность с одинаковой разностью между соседними элементами. Например, 2, 5, 8, 11: разности 5 − 2 = 3, 8 − 5 = 3, 11 − 8 = 3. Для четырёх чисел b − a = c − b = d − c.

Если в условии сказано, что числа образуют прогрессию **после упорядочивания**, сначала нужна сортировка:

```python
a = [11, 2, 8, 5]
b = sorted(a)
condition = (
    b[1] - b[0]
    == b[2] - b[1]
    == b[3] - b[2]
)
print(b, condition)
```

```output
[2, 5, 8, 11] True
```

Если же требуется прогрессия в исходном порядке, проверяется `a`. Разность может быть равна нулю: 5, 5, 5, 5 — тоже арифметическая прогрессия. Если повторения должны быть запрещены, такое ограничение должно присутствовать в условии отдельно.

В таблице строку не сортируют: упорядоченные значения дают `НАИМЕНЬШИЙ(…;1)`, `НАИМЕНЬШИЙ(…;2)` и так далее — их ставят во вспомогательные столбцы. Столбец `I` проверяет прогрессию, `J` — разбиение на пары с равными суммами (о нём следующий шаг):

```sheet Упорядоченные select=I1 edit=A1:D3
|   | A  | B | C | D | E                          | F                          | G                          | H                          | I                           | J
| 1 | 11 | 2 | 8 | 5 | =НАИМЕНЬШИЙ($A1:$D1;1) ⇒ 2 | =НАИМЕНЬШИЙ($A1:$D1;2) ⇒ 5 | =НАИМЕНЬШИЙ($A1:$D1;3) ⇒ 8 | =НАИМЕНЬШИЙ($A1:$D1;4) ⇒ 11 | =И(F1-E1=G1-F1;G1-F1=H1-G1) ⇒ ИСТИНА | =E1+H1=F1+G1 ⇒ ИСТИНА
| 2 | 7  | 3 | 8 | 4 |                            |                            |                            |                            | ⇒ ЛОЖЬ                      | ⇒ ИСТИНА
| 3 | 1  | 2 | 3 | 8 |                            |                            |                            |                            | ⇒ ЛОЖЬ                      | ⇒ ЛОЖЬ
fill E1:J3
```

**Четыре числа можно разбить на две пары с равными суммами, только если сумма крайних равна сумме средних.** Пусть исходные числа a, b, c, d. Есть только три способа разбить четыре позиции на две пары: a, b и c, d; a, c и b, d; a, d и b, c. Поэтому равные суммы существуют, если выполнено хотя бы одно из равенств a + b = c + d, a + c = b + d, a + d = b + c.

После сортировки a ≤ b ≤ c ≤ d достаточно проверить a + d = b + c. Посмотрим на все три разбиения чисел 7, 3, 8, 4:

<figure class="plate-figure">
%%tb_pairs([7, 3, 8, 4])%%
<figcaption>После сортировки 3 ≤ 4 ≤ 7 ≤ 8. В первых двух разбиениях пара с меньшими числами проигрывает: 7 < 15 и 10 < 12. Сравняться могут только крайние и средние: 3 + 8 = 4 + 7 = 11.</figcaption>
</figure>

<details class="proof" markdown="1">
<summary>Почему остальные разбиения не добавляют новых случаев</summary>

Если a + b = c + d, то меньшие элементы в сумме сравнялись с большими. При указанном порядке это возможно только при совпадении всех четырёх значений, и тогда a + d = b + c тоже верно.

Если a + c = b + d, то (b − a) + (d − c) = 0. Оба слагаемых неотрицательны, поэтому оба равны нулю: a = b, c = d. И снова a + d = b + c.

</details>

В Python — та же проверка по сортированной копии:

```python
for a in [[7, 3, 8, 4], [1, 2, 3, 8]]:
    b = sorted(a)
    can_split = b[0] + b[3] == b[1] + b[2]
    print(b, can_split, sum(a) % 2 == 0)
```

```output
[3, 4, 7, 8] True True
[1, 2, 3, 8] False True
```

Если требуется, чтобы разбить было **нельзя**, проверяют `b[0] + b[3] != b[1] + b[2]`. **Чётность общей суммы сама по себе недостаточна:** числа 1, 2, 3, 8 имеют чётную сумму 14, но получить две пары с суммой 7 невозможно. Заметь ещё, что любая прогрессия из четырёх чисел разбивается: у неё сумма крайних всегда равна сумме средних.

**Способ получения ответа нужно выбирать отдельно от проверки строки.** Рассмотрим две подходящие строки: строка 4 с суммой чисел 100 и строка 12 с суммой 40. Из одних и тех же данных могут требоваться разные ответы — выбери вопрос:

- *количество подходящих строк | 2
- наибольший номер подходящей строки | 12
- номер подходящей строки с наибольшей суммой | 4

Поэтому подчёркивай не только условия, но и заключительный вопрос задачи.

Чтобы при чтении файла получать одновременно номер и содержимое строки, используется {{enumerate|`enumerate`}}: в записи `for number, line in enumerate(f, start=1)` на каждом шаге `number` получает номер, а `line` — очередную строку. Параметр `start=1` задаёт начало нумерации с единицы. Это соответствует нумерации исходной таблицы, если первая строка файла — первая строка её данных и при преобразовании не были вставлены или удалены строки.

Возьмём учебную таблицу и условие «наименьшее число встречается в строке ровно два раза». Подходят строки 1, 3, 5 и 6. После того как установлено, что строка подходит, действия различаются:

```python
count = 0
last = 0
numbers_sum = 0
last_row_sum = 0
with open("9.txt") as f:
    for number, line in enumerate(f, start=1):
        a = [int(part) for part in line.split()]
        if a.count(min(a)) == 2:
            count += 1
            last = number
            numbers_sum += number
            last_row_sum = sum(a)
print(count, last, numbers_sum, last_row_sum)
```

```output
4 6 15 106
```

Выбери, что требуется, чтобы увидеть действие внутри проверки:

:::pick Что требуется и действие внутри проверки
- *количество строк | `answer += 1`
- сумма их номеров | `answer += number`
- сумма всех чисел подходящих строк | `answer += sum(a)`
- последний подходящий номер | `answer = number`
- сумма чисел последней подходящей строки | `answer = sum(a)`
:::

Почему присваивание даёт последнюю строку? Файл читается сверху вниз, и каждый новый подходящий результат заменяет предыдущий. Для первой подходящей строки после нахождения можно прекратить цикл: `answer = number` и сразу {{break|`break`}} — «завершить ближайший цикл». Если требуются только чётные номера подходящих строк — `if suitable and number % 2 == 0: answer += number`. Чётность номера строки не связана с чётностью чисел внутри неё.

---

**В электронной таблице номер строки даёт `СТРОКА()`.** {{xl-row|`=СТРОКА()`}} возвращает номер строки листа, где стоит формула. В подходящих строках её ставят вместо единицы признака, в остальных — пустой текст `""`; тогда `МИН` находит первую подходящую строку, `МАКС` — последнюю, а `СУММ` — сумму номеров:

```sheet Номер select=H10 edit=A1:F6
|    | A | B | C  | D  | E  | F  | G                                         | H
| 1  | 2 | 2 | 5  | 7  | 9  | 11 | =ЕСЛИ(СЧЁТЕСЛИ(A1:F1;МИН(A1:F1))=2;1;0) ⇒ 1 | =ЕСЛИ(G1=1;СТРОКА();"") ⇒ 1
| 2 | 5 | 5 | 1  | 3  | 7  | 9  | ⇒ 0                                       |
| 3 | 2 | 2 | 5  | 5  | 9  | 11 |                                           |

| 6 | 7 | 7 | 20 | 22 | 24 | 26 |                                           | ⇒ 6
| 7 |   |   |    |    |    |    |                                           |
| 8 |   |   |    |    |    |    | =СУММ(G1:G6) ⇒ 4                          | =МИН(H1:H6) ⇒ 1
| 9 |   |   |    |    |    |    |                                           | =МАКС(H1:H6) ⇒ 6
| 10 |   |   |    |    |    |    |                                           | =СУММ(H1:H6) ⇒ 15

```

Ответы совпадают с программой: 4 строки, последняя — шестая, сумма номеров 15. Перепечатай одну из семёрок шестой строки — строка перестанет подходить, и последней станет пятая.

Если затем планируется сортировка строк, исходные номера лучше закрепить как значения: скопировать столбец и вставить его значениями. Иначе формула `СТРОКА()` после перестановки будет показывать новое положение. Также различай номер строки листа и номер записи: при наличии заголовка это могут быть разные числа.

**Для поиска строки с наибольшей суммой нужно хранить и сумму, и номер.** Сначала подходящая строка ещё не найдена. Это удобно обозначить значением {{none|`None`}}, которое здесь означает «результата пока нет». Затем при каждой подходящей строке проверяем:

> Если это первая подходящая строка или её сумма больше ранее найденной, запомни новый результат.

Пройди по шагам на суммах трёх подходящих строк −7, −3 и −9:

```python run best.py
sums = [-7, -3, -9]
best_sum = None
best_number = None
for number, s in enumerate(sums, start=1):
    if best_sum is None or s > best_sum:
        best_sum = s
        best_number = number
print(best_number, best_sum)
```

```output
2 -3
```

Зачем `None`, если можно поставить ноль? Потому что при отрицательных входных числах все подходящие суммы могут быть отрицательными. Тогда начальный ноль окажется больше любой из них, хотя он не соответствует никакой строке.

При одинаковых максимальных суммах сравнение `>` сохранит первую строку, а сравнение `>=` будет заменять результат и сохранит последнюю. Нужный вариант определяется условием.

---

**Если в ответе требуется абсолютное значение, его нужно брать в указанном месте вычисления.** Абсолютное значение, или модуль числа, — его расстояние от нуля: |−8| = 8, |3| = 3. В Python это {{absval|`abs(x)`}}, в электронной таблице — `=ABS(A1)`.

Но операции «найти минимум, затем взять модуль» и «взять модули, затем найти минимум» различаются. Для чисел −8, −2 имеем |min(−8, −2)| = |−8| = 8, а минимум модулей min(8, 2) = 2. Если условие просит абсолютное значение найденного минимального числа, сначала нужно найти само число.

---

**Итого.**

- Возрастание — `<` между соседями, неубывание — `<=`; `a == sorted(a)` проверяет неубывание, сортировать саму строку перед проверкой нельзя.
- Части строки — срезы `a[:4]`, `a[4:]` и свои диапазоны в таблице; сортировка уничтожает позиции.
- Упорядоченные значения — `sorted(a)` или `НАИМЕНЬШИЙ(…;k)`; прогрессия — равные разности, две пары — `b[0] + b[3] == b[1] + b[2]`.
- Ответ выбирают отдельно от проверки: `answer += 1`, `+= number`, `= number`, `= sum(a)`, `break`; в таблице — `СТРОКА()` с `МИН`, `МАКС`, `СУММ`.
- Лучшая строка — с `None` вместо нуля; `>` сохраняет первую из равных, `>=` — последнюю; модуль — там, где сказано.
