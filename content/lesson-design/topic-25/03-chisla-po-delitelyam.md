Главная идея подтемы: **задача «найти числа с нужными делителями» — это перебор чисел из подтемы 1, внутри которого работает поиск делителей из подтемы 2**. Меняется только то, что мы вычисляем по найденным делителям и как выбираем ответ.

Функции `get_divisors` и `count_divisors` из подтемы 2 считаем определёнными выше в программе.

---

**Разберём полностью задачу на точное количество делителей.** Возьмём небольшой диапазон, чтобы результат можно было проверить вручную.

> Найти все числа от 10 до 30 включительно, у которых ровно два различных делителя, не считая единицы и самого числа. Вывести число и эти два делителя.

Переведём условие: перебираем `n` от 10 до 30, получаем все делители, исключаем 1 и `n`, проверяем, что осталось ровно два, и выводим нужные значения.

```python
for n in range(10, 31):
    D = [d for d in get_divisors(n) if 1 < d < n]

    if len(D) == 2:
        print(n, D[0], D[1])
```

```output
10 2 5
14 2 7
15 3 5
21 3 7
22 2 11
26 2 13
27 3 9
```

Проверим на отдельных числах. У 10 делители 1, 2, 5, 10: без крайних остаются 2 и 5 — подходит. У 12 остаются 2, 3, 4, 6 — четыре, не подходит. У 27 остаются 3 и 9 — подходит. Это хороший пример того, почему нельзя заменять условие «два делителя» условием «два простых делителя»: среди делителей 27 есть составное число 9.

Если требуются ровно четыре чётных делителя, меняются только отбор и количество. `print(n, *D)` выводит число, а затем все элементы списка через пробел: звёздочка передаёт элементы списка как отдельные аргументы.

```python
for n in range(10, 31):
    D = [d for d in get_divisors(n) if d % 2 == 0]

    if len(D) == 4:
        print(n, *D)
```

```output
12 2 4 6 12
16 2 4 8 16
20 2 4 10 20
28 2 4 14 28
30 2 6 10 30
```

Само число здесь может учитываться: условие требует чётные делители и не исключает `n`.

**В задачах на максимальное количество делителей нужно хранить текущий лучший результат.** Рассмотрим условие:

> Среди чисел от 10 до 30 найти число с наибольшим количеством делителей. Если таких чисел несколько, выбрать наименьшее.

Нужны две переменные: лучшее найденное количество делителей и число, которому оно соответствует.

```python
L = 10
R = 30

best_count = 0
best_number = L

for n in range(L, R + 1):
    current_count = count_divisors(n)

    if current_count > best_count:
        best_count = current_count
        best_number = n

print(best_count, best_number)
```

```output
8 24
```

Почему при равном количестве делителей сохраняется наименьшее число? Перебор идёт по возрастанию, и 24 встретится раньше 30. У обоих по восемь делителей, но проверка `current_count > best_count` при равенстве не выполнится, поэтому 24 не заменится на 30. Со знаком `>=` при равенстве предыдущее число заменялось бы новым, большим, и выбралось бы наибольшее из чисел с одинаковым количеством делителей.

**Знак `>` или `>=` здесь определяется правилом выбора при равенстве.**

---

**Буква M в условии обычно обозначает некоторую вычисляемую величину, а не особый алгоритм.** Нужно внимательно прочитать, как она определена. Например:

> M — сумма двух наибольших различных делителей числа, не считая самого числа и единицы. Если таких делителей меньше двух, M = 0.

```python
D = [d for d in get_divisors(n) if 1 < d < n]

if len(D) >= 2:
    M = D[-1] + D[-2]
else:
    M = 0
```

Для 48 отобранный список — D = [2, 3, 4, 6, 8, 12, 16, 24]. Два наибольших — 24 и 16, поэтому M = 24 + 16 = 40. Другие определения требуют других вычислений по такому же списку. Выберите определение, чтобы увидеть вычисление и его значение для 48:

:::pick Определение величины и вычисление после отбора
- *сумма всех выбранных делителей | `sum(D)` → 75
- разность наибольшего и наименьшего | `D[-1] - D[0]` → 22
- произведение двух наименьших | `D[0] * D[1]` → 6
- сумма трёх наибольших | `sum(D[-3:])` → 52
- количество выбранных делителей | `len(D)` → 8
:::

У каждой формулы нужно проверить, что нужные элементы существуют. Особенно внимательно относитесь к значению 0, которое задают при отсутствии делителей: проверка `M % 10 == 0` истинна и при `M == 0`. Поэтому, если условие требует **положительное** M, оканчивающееся нулём, проверка должна быть `M > 0 and M % 10 == 0`. Но если условие допускает ноль, исключать его самостоятельно нельзя.

**Наименьший и наибольший делители, кроме 1 и самого числа, связаны друг с другом.** Это позволяет иногда обойтись без полного списка.

Посмотрим на пары делителей 84:

<figure class="plate-figure">
%%arcs(84, emphasize=(2, 42), mute=(1, 84), ordinal=True)%%
<figcaption>Пары делителей 84; делители расставлены по порядку на равных расстояниях, чтобы подписи читались. Внешняя дуга (1, 84) по условию не учитывается — она пунктирная. Следующая, выделенная дуга (2, 42) — самая широкая из оставшихся: её левый конец — наименьший делитель больше 1, правый — наибольший делитель меньше 84.</figcaption>
</figure>

Дуги вложены друг в друга: чем левее начинается дуга, тем правее она заканчивается. Поэтому наименьший делитель больше 1 и наибольший делитель меньше n всегда оказываются концами одной дуги. Достаточно найти наименьший — второй получится делением. Для 84 наименьший делитель больше единицы — 2, значит, наибольший меньше 84 — это 84 : 2 = 42. Для 105 это 3 и 105 : 3 = 35.

<details class="proof" markdown="1">
<summary>Почему так для любого составного n</summary>

Пусть a — наименьший делитель числа n, больший единицы, и число составное, то есть a < n. Тогда b = n / a — наибольший делитель, меньший самого числа. Действительно, любой делитель b < n образует пару с a = n / b > 1. При фиксированном произведении n чем больше один множитель, тем меньше другой. Поэтому самому маленькому делителю больше 1 соответствует самый большой делитель меньше n.

</details>

Если M определено как сумма наименьшего и наибольшего делителей без единицы и самого числа, можно написать:

```python
def calc_m(n):
    for d in range(2, isqrt(n) + 1):
        if n % d == 0:
            return d + n // d

    return 0
```

Перебор начинается с 2, потому что единица исключена, и идёт по возрастанию. Поэтому первый найденный делитель — наименьший, а парный к нему — наибольший: функция сразу возвращает их сумму. Если делителей не найдено, она возвращает 0.

```python
print(calc_m(84), calc_m(105), calc_m(13))
```

```output
44 38 0
```

У числа 49 единственный делитель без 1 и 49 — это 7, он одновременно наименьший и наибольший. Для определения **«сумма наименьшего и наибольшего»** получится 7 + 7 = 14, если условие допускает такой случай. Но для определения **«сумма двух различных делителей»** одного делителя недостаточно. Это два разных условия, хотя формулировки выглядят похожими.

**Если нужно найти первые несколько подходящих чисел после заданной границы, верхнюю границу не следует придумывать.** Лучше продолжать поиск, пока не найдено нужное количество ответов. Для этого используется цикл {{while|`while`}} — «пока»: перед каждым повторением Python проверяет условие и, пока оно истинно, выполняет действия.

> Найти пять наименьших чисел, больших 100, для которых сумма наименьшего и наибольшего делителей без единицы и самого числа положительна и оканчивается на 0.

Функция `calc_m` уже определена выше.

```python
n = 101
found = 0

while found < 5:
    M = calc_m(n)

    if M > 0 and M % 10 == 0:
        print(n, M)
        found += 1

    n += 1
```

```output
111 40
116 60
125 30
136 70
141 50
```

Начинаем с 101, потому что требуется число **больше** 100. Счётчик `found` увеличиваем только после успешной проверки, а к следующему числу (`n += 1`) переходим всегда — подошло текущее или нет. Цикл продолжается, пока найдено меньше пяти.

Почему получаются именно пять наименьших? Числа просматриваются строго по возрастанию, и ни один кандидат не пропускается. Значит, первые пять успешных проверок соответствуют пяти наименьшим решениям. Такой поиск предполагает, что решения существуют; если задача задаёт конечный диапазон, нужно соблюдать и его верхнюю границу.

**Итого.**

- Сначала переводим определение величины из условия в код: какие делители отбираем, что по ним считаем, что делать, если делителей не хватает.
- Для «максимального количества» храним лучший результат. Знак `>` или `>=` выбираем по правилу при равенстве.
- Наименьший делитель больше 1 и наибольший меньше n — это одна пара: хватает поиска до первого делителя.
- «Первые пять после границы» ищем циклом `while` без придуманной верхней границы.
- Значение 0 «при отсутствии делителей» проверяем отдельно: `M > 0`, если условие требует положительное M.
