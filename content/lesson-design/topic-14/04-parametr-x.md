**Если x — целое число в выражении, а не цифра записи, перебирают x и для каждого значения заново считают цифры.** Так устроены задачи, где из суммы степеней вычитают x и ищут x по количеству нулей или других цифр. Если ответ лежит в десятках миллионов, нужен ещё приём подтемы 7.

Будем исследовать число 3⁸ − x при x от 1 до 100 и его троичную запись. Функцию `digits` из подтемы 3 считаем определённой выше в программе.

---

**Переменная в выражении может обозначать целое число, а не цифру.** Например, N = 3⁸ − x, 1 ≤ x ≤ 100. Требуется найти максимальный x, при котором троичная запись N содержит ровно пять цифр `2`. Здесь x не занимает место в записи числа. Поэтому ограничивать его диапазоном 0, …, 2 нельзя.

Действуем так:

1. берём очередной x;
2. вычисляем N;
3. получаем цифры N в основании 3;
4. считаем двойки;
5. если их пять, учитываем найденный x.

---

**Запись 3⁸ − x получается из восьми двоек вычитанием x − 1 без заимствований.** Из подтемы 2 мы знаем, что 3⁸ − 1 = 22222222₃. Поэтому 3⁸ − x = (3⁸ − 1) − (x − 1), а вычесть из восьми двоек число x − 1 можно поразрядно: в каждом разряде из 2 вычитается цифра 0, 1 или 2, и результат не отрицателен.

Например, при x = 10 получаем x − 1 = 9 = 00000100₃ и 22222222₃ − 00000100₃ = 22222122₃. **Двойки в N стоят там, где у x − 1 нули, а нули в N — там, где у x − 1 двойки.** Значит, пять двоек в N — это ровно пять нулей в восьмизначной записи x − 1.

Так же устроены задачи экзамена вида qᵐ + qⁿ − x: пока x не больше qⁿ, число равно qᵐ + (qⁿ − 1) − (x − 1). Значит, x − 1 вычитается из блока одинаковых цифр q − 1, а старшая часть записи не меняется.

---

**При переборе x по возрастанию последнее сохранённое подходящее значение — максимальное.** Переведём план в программу:

```python
answer = None

for x in range(1, 101):
    number = 3**8 - x
    ds = digits(number, 3)

    if ds.count(2) == 5:
        answer = x

print(answer)
```

```output
97
```

{{none|`None`}} означает, что подходящий x ещё не найден. Почему последнее сохранённое значение — максимальное? Потому что x перебирается по возрастанию: каждое следующее подходящее значение больше предыдущего. Если бы спрашивали минимальный x, остановились бы на первом подходящем с {{break|`break`}}.

Проверим найденное число: 3⁸ − 97 = 6464, его троичная запись 22212102₃ — в ней пять двоек.

<details class="proof" markdown="1">
<summary>Тот же ответ без программы</summary>

Нужно наибольшее x − 1 ≤ 99, у которого в восьмизначной троичной записи ровно пять нулей. Число до 99 занимает не больше пяти троичных цифр (99 = 10200₃), поэтому три старших разряда — всегда нули, и среди пяти младших нужно ещё ровно два нуля. Идём вниз от 99: 99 = 10200₃ (три нуля), 98 = 10122₃ и 97 = 10121₃ (по одному), 96 = 10120₃ — два. Значит, x − 1 = 96 и x = 97.

</details>

Поэтому из того, что для некоторого x условие выполнено, нельзя автоматически заключить, что оно выполнится и для всех меньших или больших значений. Перебор проверяет каждый допустимый вариант.

Если реализуешь подсчёт через `while` прямо внутри цикла по x, для каждого нового кандидата необходимо заново устанавливать `n = number` и `count = 0`. Иначе программа начнёт использовать результат обработки предыдущего кандидата.

---

**Если спрашивают о наибольшем количестве цифр, запоминают лучшее количество и x, при котором оно получено.** Найдём наименьший x от 1 до 100, при котором в троичной записи 3⁸ − x больше всего нулей. Здесь нужны две величины: само количество нулей и x, на котором оно достигнуто.

```python
best_count = None
best_x = None

for x in range(1, 101):
    zeros = digits(3**8 - x, 3).count(0)
    if best_count is None or zeros > best_count:
        best_count = zeros
        best_x = x

print(best_count, best_x)
```

```output
4 81
```

{{andor|`or`}} означает «или»: условие верно либо для первого x, когда лучшего ещё нет, либо когда новое количество больше сохранённого. Если первая часть истинна, Python уже не проверяет вторую, поэтому сравнение числа с `None` не выполняется. Строгое `>` оставляет **первый**, то есть наименьший x с лучшим количеством; если нужен наибольший такой x, ставят `>=`.

Ответ виден и без программы: нулей в N столько же, сколько двоек в x − 1. Среди чисел от 0 до 99 больше всего двоек у 80 = 2222₃ — четыре. Значит, x = 81 = 3⁴, и лучший x оказался степенью основания.

---

**Если верхней границы для x нет, перебирают циклом `while` до первого подходящего значения.** Найдём наименьшее натуральное x, при котором в троичной записи 3⁸ − x ровно три нуля. Рассуждение подсказывает ответ: у x − 1 должно быть три двойки, наименьшее такое число — 222₃ = 26, то есть x = 27. Программа:

```python
x = 1
while digits(3**8 - x, 3).count(0) != 3:
    x = x + 1
print(x)
```

```output
27
```

Цикл {{while|`while`}} останавливается на первом x, для которого условие выполнено, — оно и есть наименьшее, потому что все меньшие уже проверены.

**Перед таким перебором оцени, далеко ли ответ.** Для чисел из двух-трёх десятков цифр программа проверяет порядка миллиона значений x в секунду. Если ответ около тысячи — это мгновенно. Если цикл не закончился за несколько секунд, ответ, скорее всего, лежит очень далеко, и начало перебора нужно найти рассуждением о блоках записи — это разобрано в подтеме 7.

---

**Итого.**

- Параметр x — целое число выражения, а не цифра: его диапазон задаёт условие, а не основание.
- Для каждого x число вычисляют и разбирают на цифры заново; счётчики сбрасывают.
- Наибольший подходящий x — последний при переборе по возрастанию; наименьший — первый, с `break` или `while`.
- Лучшее количество хранят вместе с x: `>` оставляет наименьший x, `>=` — наибольший.
- qⁿ − x = (qⁿ − 1) − (x − 1): цифры q − 1 стоят там, где у x − 1 нули, — так проверяют ответ.
