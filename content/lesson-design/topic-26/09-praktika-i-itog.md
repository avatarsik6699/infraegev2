**Правильность решения удобнее контролировать через смысл переменных.**

Для каждой переменной нужно уметь закончить фразу «после обработки очередного объекта эта переменная хранит…». Выбери переменную:

:::pick Переменная → что она хранит после очередного шага
- *`used` | сумму уже выбранных размеров
- `last_finish` | окончание последнего принятого мероприятия
- `free_at[i]` | время освобождения конкретной ячейки
- `current` | длину серии, заканчивающейся в текущей позиции
:::

Такое утверждение, сохраняющееся по ходу цикла, называют **инвариантом**. Термин выглядит сложнее самой идеи: это просто точно сформулированный смысл состояния программы. Если переменная должна хранить число принятых заявок, увеличивать её при отказе нельзя. Если она должна хранить номер последней занятой ячейки, обновлять её при освобождении ячейки нельзя. Многие ошибки находятся именно так, без запуска на большом файле.

**Есть несколько пограничных случаев, которые особенно полезно проверять.**

Не нужно придумывать огромные тесты: часто достаточно пяти–восьми чисел. Выбери случай, чтобы увидеть, что он проверяет:

:::pick Случай → что проверяет
- *один объект | инициализацию, обращение к соседям
- все объекты помещаются | правильность счётчика после завершения цикла
- ничего не помещается | обработку отсутствия решения
- сумма точно равна лимиту | различие `<` и `<=`
- два одинаковых значения | сохранение кратности объектов
- полное равенство основных критериев | дополнительный критерий
- лучший результат находится в конце | обработку последней группы
- начало совпадает с окончанием | правила границ времени
:::

Особенно частые ошибки:

| Ошибка | Почему опасна |
|---|---|
| Прочитать количество объектов как обычный элемент | В данных появляется лишний объект |
| Отсортировать числа как строки | `"100"` может оказаться раньше `"20"` |
| Сортировать поля записей независимо | Разрушается связь характеристик |
| Удалить одинаковые цены через `set` | Исчезают реальные товары |
| Использовать индекс как количество | Индекс начинается с нуля |
| Забыть последнюю серию | Она не завершится разрывом внутри цикла |
| Выбрать максимальный номер ячейки вместо последней занятой | Это разные величины |
| Поставить `break` без обоснования | Можно пропустить подходящие объекты |
| Искать максимум второго показателя без фиксации первого | Нарушается порядок приоритетов |
| Удалять элементы списка во время прохода по нему | Можно перескочить через элементы |

Ещё одна скрытая проблема — повторная работа внутри цикла. Запись `total = sum(a[:i])` в цикле по `i` каждый раз заново создаёт срез и суммирует его — это O(N²). Если нужна постепенно растущая сумма, её копят: `total += x`; если нужны суммы разных начальных участков, заранее строят накопленные суммы, как в подтеме 2.

```python
a = [8, 12, 15, 19, 22, 34]
prefix = [0]
for x in a:
    prefix.append(prefix[-1] + x)
print(prefix[3], prefix[6] - prefix[3])
```

```output
35 75
```

`prefix[3]` — сумма первых трёх элементов, а разность двух накопленных сумм — сумма участка между ними, без повторного сложения.
