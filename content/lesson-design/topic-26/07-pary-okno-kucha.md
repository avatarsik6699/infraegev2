**Дополнительный урок — для продвинутых.** Он для тех, кто хочет закрыть все возможные случаи задания 26: пары чисел с проверкой по множеству и маршрут альпиниста со страховкой встречаются в подборках, но на реальных экзаменах таких задач не было. Задачи основных подтем решаются без него.

**Когда перебирать все пары или все участки слишком долго, помогает порядок: два указателя, скользящее окно и куча.** Каждый из этих приёмов работает только при определённом свойстве условия, и это свойство нужно уметь назвать.

Главный пример урока — отсортированные числа 1, 3, 4, 10, 11, 13; маршрут альпиниста разберём на высотах 30, 28, 23, 21, 17, 15, 9, 8. Два указателя знакомы по подтеме о цепочках и парах, камера хранения — по подтеме о моделировании.

---

**Подсчёт всех подходящих пар отличается от разбиения объектов на непересекающиеся пары.**

В подтеме о парах каждый объект использовался один раз. Но условие может требовать:

> Найти количество всех пар, сумма которых не превышает S.

Тогда одно число может участвовать во многих парах. Пусть список отсортирован по возрастанию. Если `a[left] + a[right] <= limit`, то с `a[left]` подходят все элементы с индексами `left + 1, …, right`: они не больше `a[right]`. Таких элементов `right − left`.

```python
a = [1, 3, 4, 10, 11, 13]
limit = 14
a.sort()
left = 0
right = len(a) - 1
count = 0
while left < right:
    if a[left] + a[right] <= limit:
        count += right - left
        left += 1
    else:
        right -= 1
print(count)
```

```output
9
```

Если сумма слишком велика, уменьшаем правую границу. Почему можно отбросить текущий правый элемент? Даже с минимальным доступным левым он не подходит, а с более крупными левыми сумма будет ещё больше. После сортировки оба индекса проходят список только один раз, поэтому сам подсчёт имеет порядок O(N). **Этот приём работает благодаря упорядоченному условию на сумму.**

---

**Если условие на пару не упорядочено, остаётся перебор всех пар, а множество ускоряет только проверку.**

Если требуется «среднее арифметическое пары должно встречаться в файле», одной такой логики движения указателей обычно недостаточно. Для проверки наличия значения удобно использовать {{set|множество}} `values = set(a)`: операция `x in values` проверяет наличие значения и в обычных условиях работает существенно быстрее последовательного просмотра списка.

```python
a = [2, 5, 8, 11, 14, 20]
values = set(a)
count = 0
best = None
for i in range(len(a)):
    for j in range(i + 1, len(a)):
        total = a[i] + a[j]
        if total % 2 == 0:
            average = total // 2
            if average in values:
                count += 1
                if best is None or average > best:
                    best = average
print(count, best)
```

```output
6 14
```

`total % 2 == 0` проверяет чётность суммы — это нужно, чтобы среднее было целым. Почему `j` начинается с `i + 1`? Чтобы не образовывать пару элемента с самим собой и не считать `(a, b)` и `(b, a)` дважды.

Здесь остаётся O(N²) пар: при N = 5000 это 12,5 миллиона проверок — несколько секунд, а при 100 000 уже почти пять миллиардов. **Множество ускоряет проверку наличия, но не отменяет сам перебор.** Допустимость такого решения зависит от размера входных данных; в задачах подборки чисел несколько тысяч.

---

**Скользящее окно используется, когда подходящий набор можно представить непрерывным участком отсортированного списка.**

Рассмотрим условие:

> Выбрать максимальное количество чисел так, чтобы разность максимального и минимального не превышала D.

После сортировки выбранные числа можно брать подряд. Почему? Если минимальное и максимальное допустимы, любое число между ними тоже можно добавить: границы диапазона не изменятся. Для чисел 1, 3, 4, 10, 11, 13 и D = 4 подходят, например, 1, 3, 4 и 10, 11, 13.

Храним две границы участка: `left` — левую, `right` — правую. Участок между ними называют **окном**. Правую границу двигаем вперёд; если условие нарушено, сдвигаем левую, пока оно снова не выполнится.

%%greedy_window([1, 3, 4, 10, 11, 13], 4)%%

```python
a = [1, 3, 4, 10, 11, 13]
distance = 4
a.sort()
left = 0
best = 0
for right in range(len(a)):
    while a[right] - a[left] > distance:
        left += 1
    length = right - left + 1
    if length > best:
        best = length
print(best)
```

```output
3
```

Длина — `right − left + 1`, потому что обе границы входят в участок: индексы от 2 до 4 включительно — это три элемента. Почему вложенный `while` не делает алгоритм квадратичным? **`left` за всю работу только увеличивается** и проходит не более N позиций; он не возвращается в начало для каждого `right`.

Принципиальное основание метода: при расширении окна нарушение исправляется удалением элементов слева, а пропущенные внутри элементы не нужны. Для произвольного набора ограничений это свойство нужно доказывать.

**Маршрут с ограниченным числом особых переходов сводится к окну, но только при дополнительном условии.**

Предположим: альпинист идёт по лагерям только на строго меньшую высоту; обычный переход имеет перепад не более D, специальный (со страховкой) — не более E, специальных переходов не больше K. Нужен самый длинный маршрут, а при равной длине — с наибольшей высотой последнего лагеря. Возникает вопрос: можно ли считать, что оптимальный маршрут проходит по всем высотам подряд в отсортированном списке?

Не всегда. Но это можно доказать, например, при целых высотах и условии **E < 2(D + 1)**. Минимальный целый перепад, уже требующий специального перехода, равен D + 1; два таких перепада вместе дают хотя бы 2(D + 1).

Если это больше E, один допустимый специальный прыжок не может перескочить сразу через два промежутка, каждый из которых требует специального перехода. Следовательно, добавление пропущенных промежуточных высот внутрь допустимого перехода не увеличивает число специальных переходов: обычный переход разбивается на обычные, а специальный — на обычные и не более одного специального. А лагерей в маршруте от этого только больше.

Значит, оптимальный маршрут можно искать среди непрерывных участков отсортированных различных высот. Перепад больше E разрывает участок; перепад от D + 1 до E расходует один специальный переход; при превышении K сдвигаем левую границу.

```python
heights = [30, 28, 23, 21, 17, 15, 9, 8]
normal_limit, special_limit, allowed_special = 3, 6, 1
heights = sorted(set(heights), reverse=True)
left = special_count = 0
best_length = best_finish = 0
for right in range(len(heights)):
    if right > 0:
        gap = heights[right - 1] - heights[right]
        if gap > special_limit:
            left = right
            special_count = 0
        elif gap > normal_limit:
            special_count += 1
    while special_count > allowed_special:
        if heights[left] - heights[left + 1] > normal_limit:
            special_count -= 1
        left += 1
    length = right - left + 1
    if (length, heights[right]) > (best_length, best_finish):
        best_length, best_finish = length, heights[right]
print(best_length, best_finish)
```

```output
4 21
```

Один из лучших маршрутов — 30 → 28 → 23 → 21: переход 28 → 23 специальный. Удаление повторных высот `set` допустимо именно потому, что маршрут строго убывает и у лагерей нет других различающих условий: на одной высоте можно посетить не более одного лагеря.

**Условие на D и E нельзя отбросить.** При D = 3, E = 12, K = 1 и высотах 53, 52, 51, 50, 44, 38, 37, 36, 35 можно пропустить 44 и пройти 53, 52, 51, 50, 38, 37, 36, 35 — восемь лагерей, один специальный переход 50 → 38. А прохождение через 44 потребовало бы двух специальных переходов, и окно найдёт только пять лагерей. Здесь 12 ≥ 2 · 4 — условие нарушено. Это пример того, почему для усложнённой задачи нужно заново обосновывать возможность свести выбор к соседним элементам.

**Если ячеек много, свободную ячейку с наименьшим номером быстро даёт очередь приоритетов — куча.**

Алгоритм камеры хранения из подтемы о моделировании в худшем случае проверяет `k` ячеек для каждой из `n` заявок — порядка O(N · K) действий. Если оба числа большие, это становится дорого. Нужны две операции: быстро узнать, какая занятая ячейка освободится раньше, и быстро выбрать минимальный номер среди уже свободных.

Для этого используют **очередь приоритетов** — структуру, из которой удобно извлекать элемент с наименьшим ключом. В Python её реализует модуль `heapq` (подключается так же, как другие модули: `from heapq import heapify, heappush, heappop`). Основные операции:

- `heapify(a)` — организовать существующий список как такую структуру;
- `heappush(a, value)` — добавить элемент;
- `heappop(a)` — удалить и вернуть минимальный элемент;
- `a[0]` — посмотреть минимальный элемент без удаления.

Остальные элементы при этом не обязаны идти в полностью отсортированном порядке: куча гарантирует только, что наименьший — первый. Каждая операция занимает порядка log N действий.

Храним `free_cells` — номера свободных ячеек и `busy` — пары «время освобождения, номер ячейки». На примере двух ячеек и пяти заявок:

```python
from heapq import heapify, heappush, heappop

k = 2
requests = [(1, 5), (2, 4), (3, 7), (4, 8), (5, 6)]
requests.sort(key=lambda x: x[0])
free_cells = list(range(k))
heapify(free_cells)
busy = []
accepted = 0
last_cell = None
for start, finish in requests:
    while busy and busy[0][0] <= start:
        _, cell = heappop(busy)
        heappush(free_cells, cell)
    if free_cells:
        cell = heappop(free_cells)
        heappush(busy, (finish, cell))
        accepted += 1
        last_cell = cell + 1
print(accepted, last_cell)
```

```output
4 1
```

`list(range(k))` создаёт список индексов 0, 1, …, k − 1. Почему нужны две структуры? В занятой ячейке нас интересует **время освобождения**, в свободной — **номер ячейки**; один и тот же порядок не решает обе задачи. Обработка после сортировки занимает порядка O(N log K). Если выбирается самая дешёвая свободная ячейка, а при равенстве — минимальный номер, в свободной очереди приоритетов можно хранить пары `(price, cell_number)`.

---

**Итого.**

- Все пары с упорядоченным условием на сумму считают двумя указателями за O(N); остальные — перебором O(N²) с проверкой по множеству.
- Окно — непрерывный участок отсортированного списка; `left` только растёт, поэтому работа O(N).
- Маршрут со специальными переходами сводится к окну по различным высотам только при E < 2(D + 1).
- Куча `heapq` даёт минимальный элемент за log N: занятые ячейки — по времени освобождения, свободные — по номеру.
