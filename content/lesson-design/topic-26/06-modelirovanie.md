**В задачах на моделирование ничего не выбирают: программа исполняет правила из условия и хранит состояние системы.** Так решаются задачи о камере хранения и окнах приёма, о парковке, об очередях, о заданных процедурах упаковки и размещения, о журнале сервера. К этой модели относятся и самые свежие экзаменационные задачи.

Главный пример урока — камера хранения из двух ячеек и пять заявок: (1, 5), (2, 4), (3, 7), (4, 8), (5, 6), где первое число — время сдачи багажа, второе — время освобождения ячейки.

---

**Некоторые задачи требуют выбрать лучший вариант, а другие — исполнить заданные правила.**

Это принципиальное различие. В первом случае ты сам выбираешь действия:

> Найдите максимальное количество непересекающихся мероприятий.

Можно отклонять одни заявки и принимать другие, чтобы получить лучший результат. Во втором случае порядок действий уже установлен:

> Клиенты приходят по времени. Каждый занимает свободное окно с наименьшим номером. Если свободных окон нет, клиент уходит.

Здесь нельзя отказаться от раннего клиента, чтобы потом обслужить больше людей. Нужно выполнить описанные правила. Воспроизведение такого процесса в программе называют **моделированием** или **симуляцией**.

При моделировании нужно хранить **состояние системы** — сведения о том, что происходит сейчас. Например, `free_at = [100, 140, 90]` может означать, что первое окно освободится в момент 100, второе — в момент 140, третье — в момент 90. По этому состоянию программа решает, куда направить следующего клиента. Перед поиском алгоритма спрашивай:

> Мне разрешено выбирать лучший вариант или я обязан выполнить конкретную процедуру?

---

**В камере хранения нужно хранить время освобождения каждой ячейки.**

Пусть есть `k` ячеек; заявка содержит начало и окончание хранения; выбирается свободная ячейка с минимальным номером; после освобождения ячейку можно занять сразу; если свободных нет, заявку отклоняют. Состояние — {{listmul|`free_at = [0] * k`}}: `free_at[i]` означает, в какой момент ячейка с индексом `i` станет свободной. При приходе в момент `start` ячейка свободна, если `free_at[i] <= start`. Заявки обрабатываем в порядке прихода:

```python
k = 2
requests = [(4, 8), (1, 5), (5, 6), (2, 4), (3, 7)]
requests.sort(key=lambda x: x[0])
free_at = [0] * k
accepted = 0
last_cell = None
for start, finish in requests:
    for i in range(k):
        if free_at[i] <= start:
            free_at[i] = finish
            accepted += 1
            last_cell = i + 1
            break
print(accepted, last_cell)
```

```output
4 1
```

%%greedy_cells(2, [[1, 5], [2, 4], [3, 7], [4, 8], [5, 6]])%%
<figcaption>Заявки (1, 5) и (2, 4) занимают ячейки 1 и 2; в момент 3 обе заняты — отказ; в момент 4 освобождается ячейка 2, в момент 5 — ячейка 1. Приняты четыре заявки, последняя — в ячейке 1.</figcaption>
</figure>

Почему `i + 1`? Индекс начинается с нуля, номер ячейки — с единицы. Почему нужен {{break|`break`}}? Одна заявка должна занять ровно одну ячейку; после размещения внутренний цикл завершает работу. Почему получаем минимальный номер? Индексы проверяются по возрастанию.

Если новая загрузка возможна только **после** указанного момента выдачи — «ячейка доступна со следующей минуты», — условие будет строгим: `free_at[i] < start`. Тогда в нашем примере заявка (4, 8) тоже получит отказ: ячейка 2 освобождается ровно в момент 4. Это определяется формулировкой.

Также нужно различать время окончания хранения и длительность: если дано начало и длительность, `finish = start + duration`. И ещё одна тонкость: при одинаковом времени прихода должен быть понятен порядок обработки заявок. Нельзя произвольно добавлять сортировку по окончанию, если по условию должен сохраняться порядок поступления — поэтому ключ здесь только `x[0]`, а {{listsort|сортировка устойчива}}.

**Если ячейки различаются ценой, свободную ячейку ищут в порядке «цена, номер».**

Пусть пассажир выбирает самую дешёвую свободную ячейку, а среди равных по цене — с наименьшим номером. Порядок просмотра ячеек от этого не меняется со временем, поэтому его вычисляют один раз — сортировкой номеров ячеек по ключу `(цена, номер)`:

```python
cost = [50, 30, 30]
requests = [(1, 5), (2, 3), (3, 4), (5, 2), (6, 4)]
order = sorted(range(len(cost)), key=lambda i: (cost[i], i))
free_at = [0] * len(cost)
total = 0
last_cell = None
for start, duration in requests:
    for i in order:
        if free_at[i] <= start:
            free_at[i] = start + duration
            total += cost[i]
            last_cell = i + 1
            break
print(total, last_cell)
```

```output
170 2
```

Ячейки просматриваются в порядке 2, 3, 1. В момент 5 ячейка 2 ещё занята до 6, поэтому заявка (5, 2) получает ячейку 3, а в момент 6 ячейка 2 уже свободна. Если ячеек и заявок десятки тысяч, просмотр всех ячеек для каждой заявки становится долгим — тогда помогает куча из дополнительной подтемы 7. В задачах подборки ячеек около сотни, и простого просмотра хватает.

**Если мест два вида, состояние хранят для каждого вида отдельно.**

Например, на парковке места для легковых машин и для микроавтобусов; легковая машина при нехватке своих мест может встать на место микроавтобуса, а микроавтобус на место легковой — нет. Тогда легковая машина проверяет сначала свой список, затем чужой, а микроавтобус — только свой:

```python
spots = {"A": [0], "B": [0]}
cars = [(0, 10, "A"), (2, 5, "A"), (3, 4, "B"), (8, 2, "A")]
parked_a = gone = 0
for arrival, duration, kind in cars:
    allowed = ["A", "B"] if kind == "A" else ["B"]
    placed = False
    for group in allowed:
        lst = spots[group]
        for i in range(len(lst)):
            if lst[i] <= arrival:
                lst[i] = arrival + duration
                placed = True
                break
        if placed:
            break
    parked_a += placed and kind == "A"
    gone += not placed
print(parked_a, gone)
```

```output
3 1
```

Вторая легковая машина встала на место микроавтобуса, поэтому микроавтобус в момент 3 уехал. К моменту 8 место микроавтобуса освободилось, и его заняла третья легковая.

**Очередь отличается от отказа тем, что клиент может начать обслуживание позже своего прихода.**

Для одного окна достаточно хранить время его освобождения. Пусть клиент пришёл в `arrival`, обслуживание длится `duration`, окно свободно с `free_at`. Тогда **`start = max(arrival, free_at)`** и `finish = start + duration`.

Почему максимум? Обслуживание не может начаться ни раньше прихода клиента, ни раньше освобождения окна. Время ожидания — `start − arrival`. Если клиент согласен ждать не более `max_wait`, пройди обслуживание по шагам:

```python run queue.py
clients = [(0, 5), (2, 3), (4, 4), (12, 2)]
max_wait = 3
free_at = 0
served = rejected = 0
for arrival, duration in clients:
    start = max(arrival, free_at)
    if start - arrival <= max_wait:
        free_at = start + duration
        served += 1
    else:
        rejected += 1
print(served, rejected)
```

```output
3 1
```

Третий клиент пришёл в 4, а окно освободится только в 8: ждать 4 минуты он не согласен. **При отказе нельзя менять `free_at`**: этот клиент не занял место в расписании, поэтому четвёртый начинает сразу.

Если нужно знать число людей, ещё находящихся в очереди, удобно хранить **времена окончания их обслуживания** в {{deque|очереди `deque`}} — в порядке прихода. Посмотрим на четырёх клиентах, которые ждут сколько угодно:

<figure class="plate-figure">
%%greedy_queue([[0, 4], [1, 3], [2, 5], [9, 2]])%%
<figcaption>Клиент 2 пришёл в 1, но окно занято до 4 — он ждёт 3 минуты; клиент 3 ждёт, пока закончат двое перед ним. К приходу клиента 4 в момент 9 первые двое уже ушли, а третий обслуживается до 12.</figcaption>
</figure>

Программа повторяет рисунок. В момент прихода сначала снимаем с начала очереди тех, кто уже закончил: их время окончания не больше момента прихода. Оставшиеся — люди в очереди, включая того, кого обслуживают. Новый клиент начнёт, когда закончит последний из них, `queue[-1]`, а если очередь пуста — сразу:

```python
from collections import deque

clients = [(0, 4), (1, 3), (2, 5), (9, 2)]
queue = deque()
for arrival, duration in clients:
    while queue and queue[0] <= arrival:
        queue.popleft()
    people = len(queue)
    start = max(arrival, queue[-1]) if queue else arrival
    queue.append(start + duration)
    print(arrival, people, start)
```

```output
0 0 0
1 1 4
2 2 7
9 1 12
```

Каждый клиент видит `people` — сколько людей перед ним ещё не закончили, — и начинает после последнего из них. Если условие считает длиной очереди только **ожидающих**, без обслуживаемого клиента, подсчёт нужно изменить.

Для нескольких очередей важно, **что именно минимизирует клиент**: количество людей, ожидаемое время, номер окна или стоимость услуги. Это разные правила: в первой очереди может стоять один человек, которому осталось 30 минут, а во второй — два человека, каждому нужна одна минута.

Для задач об очередях отдельно выписывай:

1. Кто учитывается в очереди?
2. Как выбирается окно?
3. Как разрешается равенство?
4. Когда клиент отказывается?
5. Учитываются начавшие обслуживание до закрытия или закончившие до закрытия?

**При упаковке грузов важно отличать заданную процедуру от поиска минимального количества контейнеров.**

Рассмотрим правило:

> Заполнять контейнер грузами по убыванию массы. Если очередной груз не помещается, пробовать следующие. Затем повторить для оставшихся грузов.

Это процедура, которую нужно воспроизвести:

```python
weights = [7, 6, 4, 3]
capacity = 10
remaining = sorted(weights, reverse=True)
loads = []
while remaining:
    next_remaining = []
    load = 0
    for weight in remaining:
        if load + weight <= capacity:
            load += weight
        else:
            next_remaining.append(weight)
    loads.append(load)
    remaining = next_remaining
print(loads)
```

```output
[10, 10]
```

`remaining` — грузы, ещё не размещённые; `load` — загрузка текущего контейнера; `next_remaining` — грузы для следующих контейнеров; `loads` — загрузки готовых контейнеров. В первый контейнер 7 помещается, 6 и 4 — нет, 3 — помещается. Предполагается, что каждый отдельный груз не тяжелее контейнера, иначе цикл никогда не завершится.

Почему нельзя делать `break`, когда груз не поместился? Потому что список убывает: следующие грузы легче и могут поместиться. **Это отличается от отбора маленьких файлов в возрастающем списке.**

Важно: эта процедура не всегда даёт минимальное число контейнеров. Для вместимости 10 и грузов 6, 5, 3, 2, 2, 2 она даст три контейнера — 6 + 3 = 9, 5 + 2 + 2 = 9 и 2, — а существует размещение в два: 6 + 2 + 2 = 10 и 5 + 3 + 2 = 10. Поэтому нельзя называть результат такого алгоритма оптимальным без доказательства. Если же он прямо предписан условием, нужно получить именно результат предписанной процедуры.

**Заданную процедуру выполняют буквально, даже если она выглядит необычно.**

Две процедуры из подборки показывают, что внимательное чтение важнее алгоритмической идеи.

**Первый подходящий контейнер.** Детали кладут по очереди; каждую — в контейнер с наименьшим номером, где ещё хватает места; если такого нет, деталь откладывают. Состояние — оставшееся место каждого контейнера:

```python
room = [10, 6, 8]
parts = [5, 7, 4, 6, 3]
placed = []
for part in parts:
    for i in range(len(room)):
        if room[i] >= part:
            room[i] -= part
            placed.append(part)
            break
print(len(placed), max(placed), room)
```

```output
4 7 [1, 0, 1]
```

Деталь 7 не помещается в контейнеры 1 и 2 и попадает в третий; для последней детали 3 места не осталось нигде.

**Размещение с двух концов.** У каждого изделия два времени, например шлифовки и покраски. Все 2N чисел упорядочивают по возрастанию; если очередное наименьшее число — время шлифовки, изделие ставят на первое свободное место от начала ленты, если покраски — на первое свободное место от конца; числа уже размещённых изделий пропускают:

```python
items = [(3, 8), (7, 1), (2, 5), (9, 6)]
values = sorted((v, kind, i)
                for i, pair in enumerate(items)
                for kind, v in enumerate(pair))
line = [None] * len(items)
front, back = 0, len(items) - 1
order = []
for v, kind, i in values:
    if i + 1 in line:
        continue
    if kind == 0:
        line[front] = i + 1
        front += 1
    else:
        line[back] = i + 1
        back -= 1
    order.append(i + 1)
print(order, line)
```

```output
[2, 3, 1, 4] [3, 1, 4, 2]
```

Наименьшее число 1 — покраска изделия 2: оно встаёт в конец. Затем 2 — шлифовка изделия 3, оно встаёт в начало. Последним размещено изделие 4; перед ним на ленте два изделия, после него — одно. Каждая запись `(значение, вид, номер)` хранит, откуда взято число, — это та же связь полей, что и в первой подтеме.

**Задачи о журналах и резервных копиях собираются из уже изученных приёмов.**

Пусть запись журнала содержит время, ID клиента и объём. Сервер накапливает данные; если очередной запрос не помещается в память, сервер создаёт резервную копию уже накопленного, очищает память и добавляет новый запрос. Понадобятся перевод времени, сортировка записей, накопление объёмов по клиентам и моделирование памяти.

Время вида `11:59:59` переводят в секунды: `hours, minutes, seconds = map(int, time_text.split(":"))` и `hours * 3600 + minutes * 60 + seconds` — {{split|`split(":")`}} разбивает строку по двоеточиям. Сравнивать строки времени тоже можно, если у всех две цифры в часах, но секунды надёжнее.

```python
log = [("08:00:05", 7, 40), ("07:59:59", 3, 50),
       ("09:10:00", 7, 30), ("11:30:00", 3, 60),
       ("12:00:00", 5, 70), ("13:15:00", 7, 20)]
capacity = 100
records = []
for text, client, volume in log:
    h, m, s = map(int, text.split(":"))
    records.append((h * 3600 + m * 60 + s, client, volume))
records.sort()

client_total = {}
used = 0
backups = []
for time, client, volume in records:
    client_total[client] = client_total.get(client, 0) + volume
    if used + volume > capacity:
        backups.append((time, used))
        used = 0
    used += volume
best = max(client_total, key=client_total.get)
print(best, *[u for t, u in backups if t < 12 * 3600])
```

```output
3 90
```

Почему резервную копию записываем **до** прибавления нового объёма? Потому что она содержит старые накопленные данные, а новый запрос поступает уже после очистки.

Почему условие строгое, `used + volume > capacity`? При точном заполнении памяти места пока хватает. Почему нельзя автоматически добавить резервную копию в конце программы? Завершение входного файла само по себе не означает, что сервер выполнял копирование. Здесь вторая копия создана ровно в 12:00:00, и условие «до полудня» её не берёт, а «не позднее 12:00:00» — взяло бы: смысл границы берут из условия.

Также различай две крупнейшие копии среди всех подходящих и две **соседние по времени** копии с максимальной суммой. Для первого случая достаточно выбрать два максимальных объёма, для второго проверяют соседние записи в хронологическом порядке.

---

**Итого.**

- Сначала решают, выбирать лучшее или исполнять правила; при моделировании хранят состояние.
- Камера хранения: `free_at` для каждой ячейки, заявки по времени прихода, `<=` или `<` — по формулировке, номер — индекс + 1.
- Цена ячейки — порядок просмотра `(цена, номер)`; два вида мест — состояние для каждого вида.
- Очередь: начало `max(приход, освобождение)`, отказ не меняет состояние, длина очереди — `deque` времён окончания.
- Заданная процедура выполняется буквально и не обязана быть оптимальной; журнал — секунды, сортировка, накопление по ключу и копия до добавления запроса.
