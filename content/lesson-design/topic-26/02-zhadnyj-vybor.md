**В задачах на максимальное количество объектов при ограниченной сумме нужно начинать с самых маленьких.** Это первая и самая частая модель задания: архив файлов, закупки изделий, скидки.

Почти весь урок держится на одном примере: на диске свободно 60, а размеры файлов — 8, 12, 15, 19, 22 и 34. Они записаны в файл `26.txt` из прошлой подтемы; чтение файла считаем знакомым.

---

**Жадный алгоритм делает последовательные выборы, каждый раз используя локальное правило.**

Например: «из оставшихся подходящих файлов берём самый маленький». Такой алгоритм называется **жадным**. Слово «жадный» не означает «всегда берёт самое большое»: он может выбирать самый маленький размер, самое раннее окончание, наибольшую допустимую коробку, самый дешёвый подходящий объект.

Главный вопрос к жадному алгоритму:

> Почему этот выбор не лишит нас лучшего итогового решения?

Одного ощущения «так выгоднее» недостаточно. Полезны два способа объяснения. **Первый: выбранный объект оставляет не меньше возможностей.** Файл поменьше оставляет больше места для следующих. **Второй: можно заменить чужой выбор нашим и не ухудшить результат.** Если в некотором лучшем наборе взят большой файл, а меньший не взят, их можно поменять: количество сохранится, занятое место не увеличится. Такое рассуждение называют **доказательством обменом**.

Важно учитывать всю формулировку. При вместимости 10 и размерах 4, 5, 6 лучший набор зависит от цели — выбери цель:

:::pick Цель → лучший набор при вместимости 10
- *больше всего объектов | 4 + 5 | два объекта, самые маленькие
- наибольшая сумма | 4 + 6 = 10 | самые маленькие дают только 9
- наибольший отдельный объект | 6 | один файл помещается целиком
:::

**Максимальное количество, максимальная сумма и максимальный отдельный элемент — разные цели.**

---

**Чтобы сохранить больше всего файлов, их набирают от самых маленьких.**

После сортировки последовательно добавляем файлы, пока следующий помещается:

<figure class="plate-figure">
%%greedy_fill([8, 12, 15, 19, 22, 34], 60)%%
<figcaption>Файлы 8, 12, 15 и 19 занимают 54 из 60; следующий, 22, уже не помещается: 54 + 22 = 76 > 60. Файл 34 ещё больше.</figcaption>
</figure>

Получили четыре файла. Почему пять сохранить невозможно? Потому что пять самых маленьких файлов имеют сумму 8 + 12 + 15 + 19 + 22 = 76 > 60, а **любые другие пять файлов имеют не меньшую сумму**. Это видно, если выписать оба набора по возрастанию друг под другом: i-й файл любого набора не меньше i-го самого маленького. На рисунке то же сравнение для наборов из четырёх файлов.

<figure class="plate-figure">
%%greedy_compare([8, 12, 15, 19, 22, 34], [8, 15, 22, 34])%%
<figcaption>Четыре самых маленьких и другой набор из четырёх, оба по возрастанию: каждый файл набора не меньше файла на той же позиции сверху, поэтому и сумма не меньше: 79 ≥ 54.</figcaption>
</figure>

<details class="proof" markdown="1">
<summary>Доказательство для любых размеров</summary>

Пусть отсортированные размеры a₁ ≤ a₂ ≤ … ≤ aₙ. У любого выбранного набора из k файлов после его собственной сортировки b₁ ≤ b₂ ≤ … ≤ bₖ. Обязательно b₁ ≥ a₁, b₂ ≥ a₂, …, bₖ ≥ aₖ: среди всех файлов есть по крайней мере i файлов, не больших bᵢ, — это b₁, …, bᵢ, — а aᵢ — i-е наименьшее значение, поэтому bᵢ ≥ aᵢ. Следовательно, b₁ + … + bₖ ≥ a₁ + … + aₖ. То есть **первые k элементов имеют минимальную возможную сумму среди всех наборов из k элементов**: если не помещаются они, не поместится никакой набор из k.

</details>

Код повторяет ручные действия. Пройди его по шагам:

```python run count.py
sizes = [19, 8, 34, 12, 22, 15]
capacity = 60
sizes.sort()
used = 0
count = 0
for size in sizes:
    if used + size > capacity:
        break
    used += size
    count += 1
print(count, used)
```

```output
4 54
```

Здесь `used` — уже занятый объём, `count` — количество выбранных файлов. Проверяем возможность добавления **до** изменения суммы.

Почему разрешён {{break|`break`}}? **Потому что список отсортирован по возрастанию**: если текущий файл не помещается, следующие ещё крупнее. Без сортировки такой выход из цикла мог бы пропустить маленький файл в конце списка: для `[19, 8, 34, ...]` цикл остановился бы на 34, не дойдя до 12 и 15.

**Второе условие про самый большой файл требует отдельного шага.**

Максимальное количество равно четырём, и первоначально выбраны 8, 12, 15, 19. Но наибольший файл, который может оказаться среди четырёх сохранённых, — **22**: набор 8, 12, 15, 22 занимает 57 ≤ 60.

Как получить это системно? Зафиксируем три самых маленьких файла — 8, 12, 15. Они занимают 35, для четвёртого остаётся 60 − 35 = 25. Из оставшихся файлов выбираем максимальный размер, не превышающий 25. Это 22.

<figure class="plate-figure">
%%greedy_room([8, 12, 15, 19, 22, 34], 60)%%
<figcaption>Три самых маленьких закреплены, свободно 25: файлы 19 и 22 помещаются, 34 — нет. Наибольший помещающийся — 22.</figcaption>
</figure>

Почему можно зафиксировать именно k − 1 самых маленьких? **Потому что они оставляют максимально возможное место для ещё одного файла.** Если некоторый файл x нельзя разместить даже вместе с k − 1 самыми маленькими, то с любыми другими k − 1 файлами он тем более не поместится.

Полная программа для формата `S N` в первой строке:

```python
with open("26.txt") as f:
    capacity, n = map(int, f.readline().split())
    a = [int(f.readline()) for i in range(n)]

a.sort()
used = 0
count = 0
for size in a:
    if used + size > capacity:
        break
    used += size
    count += 1

fixed_sum = used - a[count - 1]
limit = capacity - fixed_sum
largest = a[count - 1]
for size in a[count - 1:]:
    if size > limit:
        break
    largest = size

print(count, largest)
```

```output
4 22
```

Вторая половина программы — это рисунок выше: закрепили `count − 1` самых маленьких и ищем наибольший файл, который помещается в оставшееся место `limit`.

<details class="proof" markdown="1">
<summary>Разбор второй половины программы</summary>

`used` — сумма первых `count` файлов, `a[count - 1]` — последний из них; вычитая его, получаем сумму первых `count − 1` файлов. Перебор начинается с {{slice|`a[count - 1:]`}}, поэтому закреплённые первые `count − 1` файлов не используются повторно, а `break` снова держится на сортировке. Программа предполагает, что хотя бы один файл помещается; что выводить, если не помещается ни один, говорит условие.

</details>

**Этот приём максимизирует один файл. Он не является способом максимизировать общую сумму выбранного набора.**

**Если покупка идёт партиями, из каждой партии берут столько изделий, сколько позволяют деньги.**

Иногда в строке файла не одно изделие, а партия: цена одного изделия и их количество. Пусть на 500 рублей нужно купить как можно больше изделий A, а на остаток — как можно больше изделий B. Партии A: 5 штук по 20 и 10 штук по 35; партии B: 4 штуки по 25 и 30 штук по 15.

Для каждого типа идём по партиям от дешёвых к дорогим и из партии берём `min(q, money // p)` изделий: либо всю партию, либо сколько хватит денег. Деление нацело {{intdiv|`//`}} отвечает на вопрос «сколько раз цена помещается в остаток».

```python
money = 500
lots = {"A": [(20, 5), (35, 10)], "B": [(25, 4), (15, 30)]}
bought = {}
for kind in "AB":
    count = 0
    for price, q in sorted(lots[kind]):
        take = min(q, money // price)
        count += take
        money -= take * price
        if take < q:
            break
    bought[kind] = count
print(bought["A"], bought["B"], money)
```

```output
15 3 5
```

Все изделия A стоят 5 · 20 + 10 · 35 = 450, на остаток 50 покупаем 3 изделия B по 15 и остаётся 5. Почему после неполной партии можно остановиться? Денег не хватило даже на изделие этой партии, а следующие партии не дешевле.

**Если среди покупок есть разные типы, удобно отдельно рассмотреть количество объектов каждого типа.**

В подборке есть задачи с тремя приоритетами: купить максимальное общее количество изделий, затем максимальное количество изделий типа A, затем потратить минимальную сумму. Возьмём бюджет 36, цены изделий A — 4, 9, 14, изделий B — 3, 5, 6, 10.

Сначала определим максимальное общее количество. Все цены по возрастанию: 3, 4, 5, 6, 9, 10, 14. Пять самых дешёвых стоят 27, шесть — уже 37 > 36. Значит, нужно купить ровно пять изделий — это рассуждение прошлого шага.

Теперь спрашиваем: сколько из этих пяти может быть изделий A? Если берём x изделий A, изделий B должно быть 5 − x. **Для фиксированного x самая дешёвая покупка состоит из x самых дешёвых A и 5 − x самых дешёвых B.**

Значит, достаточно быстро находить суммы первых нескольких элементов. Для этого строят **накопленные суммы**, их также называют **префиксными суммами**: «префикс» — начальный участок последовательности. Для A = 4, 9, 14 получим PA = 0, 4, 13, 27: `PA[0]` — стоимость нуля изделий, `PA[1]` — одного самого дешёвого, `PA[2]` — двух, `PA[3]` — трёх. Каждая следующая накопленная сумма равна предыдущей плюс очередная цена. Для B: PB = 0, 3, 8, 14, 24.

| Количество A | Количество B | Минимальная стоимость | Подходит? |
|---:|---:|---:|---|
| 1 | 4 | 4 + 24 = 28 | Да |
| 2 | 3 | 13 + 14 = 27 | Да |
| 3 | 2 | 27 + 8 = 35 | Да |

Выбираем три A и два B. Остаток равен 1.

```python
budget = 36
a = sorted([4, 9, 14])
b = sorted([3, 5, 6, 10])
count = spent = 0
for price in sorted(a + b):
    if spent + price > budget:
        break
    spent += price
    count += 1

prefix_a = [0]
for price in a:
    prefix_a.append(prefix_a[-1] + price)
prefix_b = [0]
for price in b:
    prefix_b.append(prefix_b[-1] + price)

best_a = best_cost = 0
for count_a in range(count + 1):
    count_b = count - count_a
    if count_a > len(a) or count_b > len(b):
        continue
    cost = prefix_a[count_a] + prefix_b[count_b]
    if cost <= budget:
        best_a = count_a
        best_cost = cost
print(best_a, budget - best_cost)
```

```output
3 1
```

Здесь нет перебора всех наборов покупок: **перебирается только количество изделий A**, а лучший набор с таким количеством строится однозначно.

<details class="proof" markdown="1">
<summary>Почему программа выполняет все три условия</summary>

Первое — количество: `count` найден набором самых дешёвых, как в прошлом шаге. Второе — больше A: `count_a` перебирается по возрастанию, поэтому ответ можно просто перезаписывать — каждый следующий подходящий вариант содержит больше A. Третье — дешевле: для каждого состава мы уже берём самые дешёвые изделия обоих типов. {{continue|`continue`}} пропускает составы, для которых изделий одного из типов не хватает.

</details>

**В задачах на скидки сначала нужно выяснить, какие товары могут получить скидку.**

Фраза «каждый третий товар бесплатно» сама по себе ещё не определяет алгоритм. Возможны разные правила — выбери правило, чтобы увидеть, что влияет на решение:

:::pick Правило скидки → что влияет на решение
- *можно выбрать любые k товаров со скидкой | выгодно выбирать наиболее дорогие подходящие
- в каждой паре скидка на дешёвый товар | нужно выгодно составить пары
- в каждой тройке бесплатно самый дешёвый | нужно выгодно составить тройки
- продавец сам переставляет товары | нужно учитывать цель продавца
- скидка действует только выше порога | сначала выделяются подходящие товары
:::

Рассмотрим конкретное правило:

> Все товары нужно купить. Их можно разбить на тройки. В каждой полной тройке самый дешёвый товар бесплатный.

Цены: 100, 90, 80, 70, 60, 50, 40. Выгодные тройки — 100, 90, 80 и 70, 60, 50: бесплатно получаем 80 и 50, а 40 покупаем отдельно. Сумма всех цен 490, стоимость покупки 490 − 80 − 50 = 360. После сортировки по убыванию бесплатны элементы с индексами 2, 5, 8, …; третий параметр {{for|`range`}} — шаг:

```python
prices = [70, 100, 40, 90, 50, 80, 60]
prices.sort(reverse=True)
free_sum = 0
for i in range(2, len(prices), 3):
    free_sum += prices[i]
print(sum(prices) - free_sum)
```

```output
360
```

**Соседние тройки отсортированного списка дают наибольшую скидку**: каждый бесплатный товар получается настолько дорогим, насколько это вообще возможно.

<details class="proof" markdown="1">
<summary>Почему соседние тройки оптимальны</summary>

Чтобы получить один бесплатный товар некоторой цены, к нему нужны ещё два товара не дешевле. Значит, самый дорогой бесплатный товар не может быть дороже третьего по цене, второй по дороговизне бесплатный — не дороже шестого, третий — не дороже девятого. Разбиение отсортированного списка на соседние тройки достигает этих границ.

</details>

Правило может работать и в пользу покупателя: если в каждой тройке бесплатен **самый дорогой** товар, к каждому бесплатному нужны два более дешёвых спутника. Тогда бесплатными выгодно сделать ⌊n / 3⌋ самых дорогих товаров, а спутников взять из дешёвых: для тех же цен бесплатны 100 и 90.

Если товары **переставляет продавец** и хочет дать скидку поменьше, скидка достаётся самым дешёвым из подходящих товаров: продавец ставит их на чётные места. Например, «скидка 25 % на каждый второй товар дороже 50 рублей»: из k таких товаров скидку получат ⌊k / 2⌋ самых дешёвых.

Отдельный вопрос — округление. Пусть скидка 25 % применяется к товарам с суммарной исходной ценой D, а сумма всех цен — T. Тогда точная итоговая стоимость T − D/4 = (4T − D)/4. Если **всю итоговую сумму** нужно округлить вверх, {{ceil|округление вверх}} делают целочисленно: `(x + d - 1) // d` — это x/d, округлённое вверх, для неотрицательного целого x.

```python
prices = [65, 300, 45, 120, 200, 80]
big = sorted(p for p in prices if p > 50)
discount = big[:len(big) // 2]
total = sum(prices)
numerator = 4 * total - sum(discount)
print(discount, (numerator + 3) // 4)
```

```output
[65, 80] 774
```

Товаров дороже 50 пять, скидку получают два самых дешёвых из них — 65 и 80. Точная стоимость 810 − 145/4 = 773,75, после округления вверх — 774. **Нельзя округлять стоимость каждого товара отдельно**, если условие требует округлить только общую сумму.

---

**Итого.**

- Жадный выбор обосновывают: выбранное оставляет не меньше возможностей или заменяет чужой выбор без ухудшения (обмен).
- Больше всего объектов при ограниченной сумме — самые маленькие подряд; `break` разрешён только после сортировки.
- Наибольший отдельный объект при максимальном количестве: k − 1 самых маленьких закреплены, последний — наибольший из помещающихся.
- Партии — `min(q, money // p)`; два типа — перебор числа изделий A и накопленные суммы.
- Скидки: сначала понять, кто выбирает тройки или порядок и какие товары получают скидку; округлять только общую сумму.
