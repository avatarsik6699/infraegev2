**В задачах на вложенные коробки и на пары из двух наборов каждый выбор должен оставлять больше возможностей для продолжения.** Это вторая жадная модель задания: матрёшка из коробок, торт из коржей, грузы и контейнеры, детали двух видов. Она встречается и на экзаменах, и в демоверсиях.

Главный пример урока — семь коробок со сторонами 12, 18, 21, 27, 34, 40 и 45. Одну коробку можно вложить в другую, если её сторона меньше хотя бы на 6. Обоснование жадного выбора обменом знакомо по прошлой подтеме.

---

**Строить цепочку удобно снаружи: в каждую коробку вкладывают самую большую из подходящих.**

Требуется:

1. Максимальное количество вложенных коробок.
2. Максимальный возможный размер самой маленькой коробки при таком количестве.

Начнём снаружи. Самая большая коробка — 45. В неё можно поместить коробку размером не больше 45 − 6 = 39. Из подходящих выбираем **самую большую** — 34. Почему не 12? Потому что после выбора 12 внутри почти не останется возможностей; коробка 34 оставляет больше места для последующих вложений.

%%greedy_chain([12, 18, 21, 27, 34, 40, 45], 6)%%

Получилась цепочка 45 → 34 → 27 → 21 → 12 — пять коробок. Код: размеры по убыванию, коробка берётся, если она меньше последней выбранной хотя бы на зазор.

```python
sizes = [12, 18, 21, 27, 34, 40, 45]
gap = 6
sizes.sort(reverse=True)
selected = []
for size in sizes:
    if not selected or selected[-1] - size >= gap:
        selected.append(size)
print(len(selected), selected[-1])
```

```output
5 12
```

Здесь предполагается, что исходный список непустой и `gap > 0`. Условие {{truthy|`not selected`}} истинно, пока цепочка пуста: первая, самая большая коробка берётся без проверки. Благодаря короткому вычислению `or` к `selected[-1]` пустого списка программа не обращается.

---

**Жадная цепочка самая длинная, потому что на каждой глубине у неё самая большая возможная коробка.**

Алгоритм на каждой глубине выбирает максимально возможный размер: первая коробка максимально большая; вторая — максимально большая среди помещающихся в первую; третья — максимально большая среди помещающихся во вторую. Значит, **если любая другая цепочка может продолжиться, жадная тоже может**: её коробка на той же глубине не меньше, и в неё помещается всё, что помещалось в чужую. А среди цепочек максимальной длины последняя выбранная коробка получается максимально большой — это и есть второй критерий.

<details class="proof" markdown="1">
<summary>Доказательство для любых размеров</summary>

Пусть жадная цепочка g₁ > g₂ > …, а другая допустимая цепочка c₁ > c₂ > … > cₘ. Покажем по шагам, что gᵢ ≥ cᵢ для каждого i ≤ m. Для i = 1 это верно: g₁ — самая большая коробка вообще. Пусть gᵢ ≥ cᵢ. Коробка cᵢ₊₁ ≤ cᵢ − 6 ≤ gᵢ − 6, значит, она подходит для вложения в gᵢ, и жадный алгоритм найдёт подходящую коробку; он берёт наибольшую из подходящих, поэтому gᵢ₊₁ ≥ cᵢ₊₁. Следовательно, жадная цепочка не короче любой другой, а её i-я коробка не меньше i-й коробки любой другой цепочки — в том числе последняя.

</details>

---

**Направление построения связано и с допустимостью, и со вторым критерием.**

Если второй критерий другой — **минимизировать размер самой большой коробки**, — удобно строить цепочку **изнутри наружу**: отсортировать размеры по возрастанию, начать с самой маленькой и каждый раз брать наименьшую коробку, которая достаточно больше предыдущей. Рассуждение то же, только зеркальное: маленькая внешняя коробка на каждом шаге оставляет больше выбора для следующей.

```python
sizes = [12, 18, 21, 27, 34, 40, 45]
gap = 6
chain = []
for size in sorted(sizes):
    if not chain or size - chain[-1] >= gap:
        chain.append(size)
print(*chain)
```

```output
12 18 27 34 40
```

Пять коробок, внешняя имеет размер 40, а снаружи внутрь внешней была 45. Количество одинаковое, а второе число зависит от направления: **строй от той стороны, которую оптимизирует второй критерий**.

Этот разбор предполагает одинаковый минимальный зазор между соседними коробками и отсутствие других ограничений. Материалы и цвета, которые должны чередоваться, или зазор, растущий с номером коробки, — это усложнения из дополнительной подтемы 8: для них нужно новое обоснование.

---

**Два указателя помогают работать с отсортированными списками без перебора всех пар.**

**Указатель** здесь — обычная переменная, хранящая индекс текущего элемента: `left = 0` стоит в начале списка, `right = len(a) - 1` — в конце. Рассмотрим задачу:

> Каждый рейс перевозит не более двух человек. Суммарная масса не превышает вместимость. Нужно минимизировать количество рейсов.

Предполагается, что любой человек может ехать один. Сортируем массы и берём самого тяжёлого из оставшихся. **Если он не помещается вместе с самым лёгким, ни с кем другим он тоже не поместится** — значит, должен ехать один. Если помещается, их можно объединить.

%%greedy_trips([50, 60, 70, 80, 100, 130], 150)%%

```python
w = [80, 130, 50, 100, 70, 60]
capacity = 150
w.sort()
left = 0
right = len(w) - 1
trips = 0
while left <= right:
    if left < right and w[left] + w[right] <= capacity:
        left += 1
    right -= 1
    trips += 1
print(trips)
```

```output
4
```

При совместной поездке двигаются оба индекса: использованы два человека. Если вместе не помещаются, используется только тяжёлый — двигается правый индекс. При `left == right` остался один человек, и условие `left < right` не позволяет использовать его дважды. Каждый указатель проходит список один раз, поэтому после сортировки работа — O(N).

<details class="proof" markdown="1">
<summary>Почему самого тяжёлого можно посадить с самым лёгким</summary>

Обоснование строится обменом: самого тяжёлого можно объединить с самым лёгким, не ухудшая необходимое количество пар. Если в другом размещении они ехали с другими людьми, пары можно перестроить: тяжёлый поедет с лёгким, а их бывшие партнёры — вместе. Оставшиеся партнёры совместимы, поскольку каждый из них не тяжелее самого тяжёлого, а тот помещался с лёгким. Число рейсов от перестройки не растёт.

</details>

**Ограничение «не более двух» существенно.** Для произвольного числа объектов в рейсе этот алгоритм уже не является решением общей задачи упаковки.

**Грузы и контейнеры из двух независимых наборов сопоставляют по возрастанию: самый лёгкий груз — в самый маленький подходящий контейнер.**

Иногда в строке файла два числа, которые не связаны между собой: масса груза и вместимость контейнера, причём каждый контейнер берёт один груз любой массы, не большей его вместимости. Это то самое исключение из правила «сортировать записи целиком»: грузы и контейнеры — **два отдельных списка**, и сортируют их по отдельности.

Пусть массы грузов 15, 40, 25, 48, 30, а вместимости контейнеров 20, 10, 50, 35, 45. Чтобы отправить больше грузов, идём по грузам от лёгких и для каждого берём самый маленький из оставшихся подходящих контейнеров: 15 → 20, 25 → 35, 30 → 45, 40 → 50, а для 48 контейнера уже нет. Отправлено 4 груза.

Почему так правильно? Самому лёгкому грузу подходит любой контейнер, подходящий другим; отдавая ему самый маленький, **мы сохраняем большие контейнеры для тяжёлых грузов** — снова «оставить больше возможностей».

Второй вопрос — наибольшая масса отправленного груза при максимальном количестве — решается приёмом прошлой подтемы: закрепляем k − 1 = 3 самых лёгких груза в их самых маленьких контейнерах (20, 35, 45), а последний груз берём наибольший из тех, что помещаются в самый большой из оставшихся контейнеров — 50. Это 48, а не 40.

```python
goods = sorted([15, 40, 25, 48, 30])
boxes = sorted([20, 10, 50, 35, 45])
count = j = 0
for g in goods:
    while j < len(boxes) and boxes[j] < g:
        j += 1
    if j == len(boxes):
        break
    count += 1
    j += 1

used = [False] * len(boxes)
j = 0
for g in goods[:count - 1]:
    while boxes[j] < g:
        j += 1
    used[j] = True
    j += 1
room = max(b for b, u in zip(boxes, used) if not u)
print(count, max(g for g in goods[count - 1:] if g <= room))
```

```output
4 48
```

Первый цикл считает количество, второй закрепляет k − 1 самых лёгких грузов: {{listmul|`[False] * len(boxes)`}} отмечает, какие контейнеры они заняли. Указатель `j` по контейнерам только растёт: контейнер, который мал для лёгкого груза, тем более мал для следующих, более тяжёлых.

**Детали двух видов соединяют, начиная с крупнейших совместимых.**

Другая полезная модель — две разновидности деталей. Для изделия нужна одна деталь A и одна B, их размеры различаются не более чем на D, прибыль равна сумме размеров, все размеры положительные. Сортируем оба списка по убыванию. Если самая большая A больше самой большой B более чем на D, эта A не подойдёт ни к одной оставшейся B — её можно пропустить. Аналогично для слишком большой B. Если крупнейшие совместимы — объединяем их.

Пусть A = 50, 42, 30, 12, B = 47, 33, 20, 18, D = 5. Пара 50 и 47 подходит; 42 больше 33 + 5 — деталь 42 пропускаем; 30 и 33 подходят; 20 больше 12 + 5 — пропускаем 20, затем и 18. Получаем 2 изделия с прибылью 97 + 63 = 160.

```python
a = sorted([50, 42, 30, 12], reverse=True)
b = sorted([47, 33, 20, 18], reverse=True)
distance = 5
i = j = 0
count = profit = 0
while i < len(a) and j < len(b):
    if a[i] > b[j] + distance:
        i += 1
    elif b[j] > a[i] + distance:
        j += 1
    else:
        count += 1
        profit += a[i] + b[j]
        i += 1
        j += 1
print(count, profit)
```

```output
2 160
```

<details class="proof" markdown="1">
<summary>Почему можно объединить крупнейшие совместимые детали</summary>

Если в другом решении они соединены с другими партнёрами, эти две пары можно перестроить: крупнейшие — вместе, их бывшие партнёры — вместе. Меньшие оставшиеся партнёры сохранят совместимость: их разность ограничивается одной из уже допустимых разностей. Если одна из крупнейших деталей не использовалась, замена меньшей детали на неё не уменьшает прибыль.

Здесь доказательство использует конкретную совместимость по разности размеров и конкретную формулу прибыли. При других правилах оно может перестать работать. Проверка перебором на тысячах маленьких наборов подтверждает: этот проход даёт и наибольшую прибыль, и наибольшее количество изделий.

</details>

---

**Итого.**

- Цепочка снаружи внутрь: в каждую коробку — самую большую из подходящих; так получается самая длинная цепочка с наибольшей внутренней коробкой.
- Изнутри наружу — самая короткая внешняя коробка; направление выбирают по второму критерию.
- Два указателя по отсортированному списку заменяют перебор всех пар; самый тяжёлый едет с самым лёгким или один.
- Два независимых набора сортируют отдельно; самый лёгкий груз — в самый маленький подходящий контейнер; наибольший груз при максимальном количестве — через k − 1 самых лёгких.
- Детали A и B — крупнейшие совместимые вместе, несовместимую крупнейшую пропускают.
