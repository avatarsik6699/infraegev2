**Запись о пользователе складывается из пароля и дополнительных сведений, и её объём считают от целых байтов пароля.** Записи «пароль + сведения» нужны 53 задачам из 110; 31 из них решается приёмами этой подтемы — чаще всего «сколько байтов выделено на дополнительные сведения».

Пароль прежний — 7 символов из алфавита в 20 символов, 5 байтов; к нему добавим 11 байтов сведений и 128 пользователей. Функцию `bits` из подтемы 1 считаем определённой выше в программе.

---

**Добавим к паролю дополнительные сведения.** Данные об одном пользователе целиком будем называть **записью**: например, запись может включать пароль и сведения о пользователе. Разберём пример полностью.

> Пароль состоит из 7 символов алфавита мощностью 20. На дополнительные сведения выделено 11 байтов на пользователя. Нужно хранить данные о 128 пользователях.

Здесь каждый шаг отвечает на отдельный вопрос:

1. Сколько битов занимает символ? 16 < 20 ≤ 32, поэтому i = 5.
2. Сколько битов занимает пароль? 7 · 5 = 35 бит.
3. Сколько байтов выделяется паролю? B = ⌈35 / 8⌉ = 5 байтов.
4. Сколько байтов занимает вся запись? 5 + 11 = 16 байтов.
5. Сколько занимают все записи? 128 · 16 = 2048 байт = 2 Кбайт.

В общем виде: пусть пароль занимает B байтов, а под дополнительные сведения выделено D байтов на одного пользователя. Тогда запись занимает R = B + D байтов, а n записей — V = n(B + D) = n(⌈L · i / 8⌉ + D). Эта формула относится к модели, в которой дополнительным сведениям выделено целое число байтов, а пароль хранится минимальным необходимым образом.

Та же цепочка в программе — каждая строка отвечает на свой вопрос:

```python
from math import ceil

A, L, n, D = 20, 7, 128, 11
password_bytes = ceil(L * bits(A) / 8)
record_bytes = password_bytes + D
print(password_bytes, record_bytes, n * record_bytes)
```

```output
5 16 2048
```

---

**Если неизвестен объём дополнительных сведений, эту же цепочку проходят частично в обратном направлении.** Допустим, известны те же пароли (7 символов из алфавита мощностью 20), 128 пользователей и общий объём 2 Кбайт.

1. Переводим общий объём в байты: V = 2 · 1024 = 2048.
2. На одного пользователя приходится R = 2048 / 128 = 16 байтов.
3. Пароль занимает 5 байтов. Значит, дополнительные сведения D = 16 − 5 = 11 байтов.

В общем виде D = V / n − ⌈L · i / 8⌉. Здесь деление V / n не нужно произвольно округлять: если дан точный общий объём одинаковых записей, это точное деление. Если результат не согласуется с условием о целом числе байтов на запись, нужно перепроверить единицы, количество записей и устройство записи.

---

**Общий заголовок файла прибавляют один раз, а не к каждой записи.** Иногда существует заголовок, занимающий H байтов **один раз для всей базы**. Тогда V = H + n · R. Его нельзя автоматически прибавлять каждому пользователю. Например, если к нашим 128 записям добавить общий заголовок 64 байта, получится 64 + 2048 = 2112 байтов, а не 128 · (16 + 64).

---

**Дополнительные сведения в битах требуют отдельного внимания.** Нельзя автоматически считать, что пароль и дополнительные данные всегда занимают отдельные целые байты. Пусть пароль занимает 35 битов, а дополнительные данные — 13 битов. Объём записи зависит от правила хранения:

1. Части записаны подряд, целое число байтов выделяется всей записи: 35 + 13 = 48 бит = 6 байтов.
2. Каждой части выделяется своё целое число байтов: ⌈35 / 8⌉ + ⌈13 / 8⌉ = 5 + 2 = 7 байтов.

Покажем, как это меняет обратную задачу. Пусть на 50 записей выделено 900 байтов, запись содержит пароль из 9 символов набора мощностью 11 и дополнительные сведения, а целое число байтов задаётся для записи целиком. Нужно найти, сколько битов выделено сведениям.

1. Одна запись: 900 / 50 = 18 байтов = 144 бита.
2. Один символ: 8 < 11 ≤ 16, поэтому i = 4.
3. Код пароля: 9 · 4 = 36 бит.
4. Остальная часть записи — дополнительные сведения: 144 − 36 = 108 бит.

Здесь предварительное округление пароля до ⌈36 / 8⌉ = 5 байтов привело бы к неверному ответу: (18 − 5) · 8 = 104 бита.

<details class="proof" markdown="1">
<summary>Почему для сведений в целых байтах правило не важно</summary>

Если дополнительные сведения занимают именно целое число байтов D, то совместное округление даёт ⌈(L · i + 8D) / 8⌉ = ⌈L · i / 8⌉ + D: 8D битов сведений — ровно D целых байтов, и они не меняют остаток последнего байта пароля. Поэтому обычная формула для дополнительных сведений в байтах работает и при таком описании записи. Различие существенно тогда, когда отдельные части заданы в битах.

</details>

---

**Итого.**

- Запись — пароль и сведения: R = B + D байтов, V = n(B + D), где B = ⌈L · i / 8⌉.
- Обратная задача: D = V / n − B; V / n — точное деление, единицы — в байтах.
- Общий заголовок базы прибавляют один раз: V = H + n · R.
- Части в битах, записанные подряд, сначала складывают и только потом переводят в байты всей записи.
