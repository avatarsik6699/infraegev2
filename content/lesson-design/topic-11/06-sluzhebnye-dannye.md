**Иногда служебная часть зависит от размера самих данных: заголовков столько, сколько групп, а длина номера — от числа изделий.** Тогда объём нельзя получить одним умножением «число записей × размер записи»: сначала нужно учесть, как размер данных меняет служебную часть.

Здесь два случая, каждый со своим примером: сообщение, которое делят на группы по 4 байта с заголовками, и партия изделий с кодом из пяти букв и номером. Функцию `bits` из подтемы 1 считаем определённой выше в программе.

---

**Число заголовков равно числу групп, и неполная последняя группа тоже получает заголовок.** Рассмотрим условие:

> Сообщение занимает B байтов. Его разбивают на группы не более чем по 4 байта. К каждой группе добавляют заголовок размером 1 байт.

**Заголовок** здесь — дополнительная служебная часть, которую нужно передать вместе с группой. Чтобы получить минимальное количество групп, заполняем их максимально. Если сообщение занимает 10 байтов, получаются группы размером 4, 4 и 2 байта. Групп три, хотя последняя неполная, поэтому добавляется три заголовка.

<figure class="plate-figure">
%%pwd_groups(10, 4)%%
<figcaption>Десять байтов сообщения: две полные группы по 4 байта и неполная из 2. Заголовков три, всего 13 байтов.</figcaption>
</figure>

Количество групп g = ⌈B / 4⌉, общий объём B + ⌈B / 4⌉. Для 10 байтов 10 + 3 = 13 байтов.

**Наибольшее сообщение при ограничении ищут по объёму с заголовками, а затем переходят к символам.** Пусть алфавит сообщения содержит 40 символов, а общий объём с заголовками не должен превышать 20 байтов. На символ требуется i = 6 битов. Сначала найдём максимально допустимый объём собственно сообщения:

1. Для B = 16: 16 + ⌈16 / 4⌉ = 16 + 4 = 20 — помещается.
2. Для B = 17: 17 + ⌈17 / 4⌉ = 17 + 5 = 22 — уже больше 20.
3. Значит, сообщение может занимать не больше 16 байтов: 6L ≤ 16 · 8 = 128, Lₘₐₓ = 21.

Проверка:

- 21 символ — 126 битов, 16 байтов сообщения, 4 заголовка, всего 20 байтов;
- 22 символа — 132 бита, 17 байтов сообщения, 5 заголовков, всего 22 байта.

Здесь последовательно округляются две разные величины: сначала память сообщения, затем количество групп.

Программа повторяет первый пункт: увеличивает объём сообщения, пока следующий объём вместе с заголовками ещё помещается.

```python
from math import ceil

i = bits(40)
B = 0
while (B + 1) + ceil((B + 1) / 4) <= 20:
    B += 1
print(B, 8 * B // i)
```

```output
16 21
```

**Иногда неизвестное количество объектов влияет и на размер каждой записи.** Так бывает, если запись содержит номер объекта, а диапазон номеров зависит от общего числа объектов. Представим партию из n изделий. Запись каждого изделия содержит код партии из пяти заглавных латинских букв, номер изделия от 1 до n, записанный как двоичное число, и 10 байтов дополнительных данных.

Код партии занимает 5 · 5 = 25 бит. Но число битов на номер зависит от n: до номера 63 включительно достаточно 6 битов, для номеров 64–127 требуется 7 битов, начиная с 128 — 8 битов. Пусть j(n) — необходимое число битов на номер при выбранном n; запись j(n) означает, что величина j зависит от значения n. Если код партии и номер упаковываются вместе, общий объём

V(n) = n · (⌈(25 + j(n)) / 8⌉ + 10).

Здесь нельзя заранее выбрать произвольный постоянный объём записи и просто разделить на него всю память. Сначала нужно учесть зависимость от количества изделий.

При ограничении 1 Кбайт максимальное количество в этом примере равно 73. Для него j(73) = 7, код занимает ⌈(25 + 7) / 8⌉ = 4 байта, и V(73) = 73 · (4 + 10) = 1022 байта. Для 74 изделий V(74) = 74 · 14 = 1036 байтов, что уже превышает 1024.

---

**Такие задачи удобно решать перебором возможного количества объектов.** Можно и отдельно рассматривать диапазоны, внутри которых число битов на номер постоянно, но перебор проще проверить. Для задачи о партии ({{for|цикл for}} и {{if|условие if}}, длина номера — {{bitlength|`bit_length`}}):

```python
from math import ceil

limit = 1024
best = 0
for n in range(1, limit // 10 + 1):
    number_bits = n.bit_length()
    code_bytes = ceil((25 + number_bits) / 8)
    record_bytes = code_bytes + 10
    if n * record_bytes <= limit:
        best = n
print(best)
```

```output
73
```

`best` сохраняет последнее подходящее количество изделий. Верхняя граница перебора обоснована: одни дополнительные сведения требуют 10 байтов на изделие, поэтому больше чем `limit // 10` изделий поместиться не может.

---

**Итого.**

- Группы с заголовками: групп ⌈B / g⌉, всего B + ⌈B / g⌉; неполная группа тоже с заголовком.
- Наибольшее сообщение — сначала наибольший объём B вместе с заголовками, потом L · i ≤ 8B.
- Если номер изделия записан двоичным числом, его длина j(n) зависит от размера партии: V(n) = n · (⌈(код + j(n)) / 8⌉ + D), наибольшее n — перебором.
