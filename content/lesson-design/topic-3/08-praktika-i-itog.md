**Универсальный порядок решения начинается с последней фразы вопроса и смысла строк каждой таблицы, а заканчивается проверкой единицы и формы ответа.** Он подходит и для магазинов, и для других предметных областей. Ошибки удобнее ловить по этапу, на котором они возникают, и проверять на маленькой учебной книге, посчитанной руками.

Всё главное из подтем собрано на одной схеме. Номер раздела ведёт на его подтему, а ниже каждый шаг разобран подробнее.

%%cheatsheet("topic-3/cheatsheet.json")%%

---

**Перед формулами пройди вопрос по десяти шагам.**

1. **Прочитай последнюю часть вопроса.** Что требуется получить: записи, объекты, упаковки, килограммы, деньги, изменение запаса?
2. **Установи смысл строк каждой таблицы.** Где одна строка — объект, а где — операция или связь?
3. **Найди ключи и связи.** Какие поля позволяют перейти от одной таблицы к другой?
4. **Разложи условие на отдельные проверки.** Район, поставщик, название товара, дата, тип операции, числовые ограничения.
5. **Определи подходящие идентификаторы или добавь характеристики к основной таблице.** Например, получи район по ID магазина и поставщика по артикулу.
6. **Отбери нужные записи.** Проверь правильное сочетание И и ИЛИ, а также границы периода.
7. **Рассчитай вклад каждой записи.** Это может быть количество, масса, стоимость или количество со знаком.
8. **Если вопрос относится к итогам объектов, сначала сгруппируй записи.** Например, вычисли общую выручку каждого магазина.
9. **Выполни итоговое действие.** Сумма, количество разных объектов, максимум, минимум или проверка группового порога.
10. **Проверь единицу и формат ответа.** Не перепутаны ли упаковки и килограммы? Не посчитаны ли операции вместо магазинов? Нужна ли целая часть?

Для первого шага полезно заранее записать одну короткую фразу, которая удерживает смысл задачи во время работы с таблицами:

```text
Нужно найти сумму масс проданных товаров фабрики А
в Северном районе за указанный период.
```

Для задачи об изменении запаса:

```text
Нужно найти поступления минус продажи
нужного товара в нужных магазинах за период.
```

---

**Результат проверяют по смыслу, а не только пересчётом той же формулы.** Выбери, что проверяешь:

:::pick Проверка → что сделать
- *одна подходящая и одна неподходящая запись | вручную: операция 2 должна попасть в основной расчёт, операция 4 — исключена по району, операция 8 — по дате; если формулы ведут себя иначе, ошибка ещё до суммирования
- единицы | вопрос о килограммах — результат из количеств и размеров упаковок; о рублях — из количеств и соответствующих цен
- разумный диапазон | 22 упаковки по 0,5–1 кг весят от 22 · 0,5 = 11 до 22 · 1 = 22 кг; ответ 14,5 внутри промежутка, а 1450 кг сразу вызвал бы подозрение
- другое разбиение | массу 14,5 можно получить по товарам — 15 · 0,5 + 7 · 1 — и по магазинам — 8 + 6,5; совпадение независимых способов даёт хорошую проверку
- формат ячейки | не округляй промежуточные результаты: формат отображения может скрывать десятичную часть, хотя в вычислениях она сохраняется
:::

После этого полезно менять данные и заранее предсказывать последствия: перенеси операцию 8 с 11 июня на 10 июня — масса в основном вопросе должна вырасти на 4,5 кг, выручка — на 765 рублей, а изменение запаса товара 101 уменьшиться на 9. Так проверяются сразу и формулы, и понимание смысла.

---

**Ошибки удобнее проверять по тому, на каком этапе они возникают.**

| Ошибка | Что происходит | Как проверить |
|---|---|---|
| Перепутаны ID | Район ищется по артикулу или товар по ID операции | Сопоставить поле операции с ключом справочника |
| Связь по номеру строки | Используются сведения о другом объекте | Проверить совпадение ключей |
| Найден только один подходящий товар | Потеряна часть продаж | Проверить все совпадения по условию |
| Шаблон захватил лишнее | В отбор попали чужие товары или улица | Отфильтровать справочник тем же шаблоном |
| Взяты все операции района | Не учтён товар или поставщик | Проверить каждое требование вопроса |
| Учтены поступления вместо продаж | Рассчитана другая величина | Проверить тип операции |
| Исключён последний день | Потеряны граничные записи | Проверить «включительно» |
| Сложены упаковки вместо массы | Ответ имеет другую единицу | Проверить, нужен ли множитель из справочника |
| Использована одна цена при разных ценах | Неверная стоимость | Проверить цены всех подходящих записей |
| `СУММ` применена после фильтра | Учтены скрытые записи | Использовать итог видимых строк или условный расчёт |
| В изменении запаса стоит условие «Продажа» | Поступления пропали | Убрать условие на тип, знак — в столбце |
| Считаются строки вместо объектов | Один объект учтён несколько раз | Проверить необходимость разных ID |
| Порог проверяется до группировки | Потеряны объекты с большим общим итогом | Сначала вычислить итог каждого объекта |
| Диапазон поиска сдвигается | В нижних строках используется другой справочник | Закрепить нужный диапазон `$` |
| Ошибка поиска заменена нулём | Потерянные связи становятся незаметными | Разобраться с причиной ошибки |

Отдельно проверяй сортировку. Если сортировать только один столбец, не перемещая остальные поля вместе с ним, можно разрушить записи: количество одной операции окажется рядом с ID другой. **При сортировке должны перемещаться целые записи.** Сортировка сама по себе лишь меняет порядок, фильтрация определяет, какие записи видимы: эти действия выполняют разные задачи.
