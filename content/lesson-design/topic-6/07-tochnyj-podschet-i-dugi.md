**Когда фигура уже понятна, подсчёт можно поручить программе: она перебирает целые узлы и проверяет условие принадлежности, записанное по геометрии.** Сначала рисунок и неравенства — потом код; без условия, выведенного из фигуры, программа считает не то. Дуги появляются в 2 задачах подборок из 54. Основные задачи и итоговая страница эту подтему не требуют.

Главные примеры — прямоугольник 8 × 6 и треугольник со стороной 8 из подтем 3–5: программа должна получить уже известные 35, 63, 81 и 24.

---

**Автоматический подсчёт начинается с условия принадлежности точки.**

Например, точка строго внутри нашего прямоугольника удовлетворяет:

0<x<8

и:

0<y<6.

В Python:

```python
0 < x < 8 and 0 < y < 6
```

{{andor|`and`}} требует, чтобы выполнялись обе части. Перебираем целые координаты и считаем подходящие:

```python
count = 0

for x in range(-5, 16):
    for y in range(-5, 16):
        if 0 < x < 8 and 0 < y < 6:
            count += 1

print(count)
```

```output
35
```

{{nested|Два вложенных цикла}} перебирают все узлы квадрата −5 ≤ x, y ≤ 15; {{if|условие}} пропускает только внутренние, {{augassign|`count += 1`}} добавляет каждую подходящую точку ровно один раз.

Для точек вместе с границей меняются только сравнения:

```python
count = 0

for x in range(-5, 16):
    for y in range(-5, 16):
        if 0 <= x <= 8 and 0 <= y <= 6:
            count += 1

print(count)
```

```output
63
```

Сам перебор можно взять с запасом. Лишние внешние точки не будут учтены, потому что не пройдут условие.

Но диапазон должен включать все потенциально подходящие точки.

---

**При подсчёте по координатам масштаб уже не нужен.**

Рисование использует:

```python
t.goto(x * k, y * k)
```

потому что нужно показать точку на экране.

Проверка:

```python
0 < x < 8
```

работает с координатами из условия задачи.

Поэтому в неё не нужно добавлять `k`.

Это две разные операции:

| Операция | Какие координаты используются |
|---|---|
| Показать точку в окне | Экранные: xk, yk |
| Проверить её принадлежность области | Координаты задачи: x, y |

Если подставлять масштабированные координаты в условие, границы тоже пришлось бы масштабировать. Проще и понятнее выполнять математическую проверку в исходных единицах.

---

**Для двух прямоугольников можно отдельно проверять принадлежность каждой фигуре.**

Для нашего примера:

```python
in_A = 0 <= x <= 8 and 0 <= y <= 6
in_B = 3 <= x <= 10 and 2 <= y <= 7
```

Каждое выражение даёт {{truthy|логическое значение}} `True` или `False`. Имена `in_A` и `in_B` хранят ответы на вопросы:

> Принадлежит ли точка первой фигуре?

> Принадлежит ли точка второй фигуре?

Для пересечения:

```python
if in_A and in_B:
    count += 1
```

Для объединения:

```python
if in_A or in_B:
    count += 1
```

`or` означает «или»: достаточно принадлежности хотя бы одной фигуре. Если точка принадлежит обеим, она тоже подходит.

Для первой фигуры вне второй:

```python
if in_A and not in_B:
    count += 1
```

`not` меняет логическое значение на противоположное.

Для принадлежности ровно одной фигуре:

```python
if in_A != in_B:
    count += 1
```

Знак `!=` означает «не равно».

Два логических значения различаются, когда одно равно `True`, а другое `False`. Именно это и соответствует принадлежности ровно одной фигуре.

Каждое из этих условий нужно использовать в отдельном подсчёте, в зависимости от вопроса задачи. Например, объединение:

```python
count = 0

for x in range(-1, 12):
    for y in range(-1, 9):
        in_A = 0 <= x <= 8 and 0 <= y <= 6
        in_B = 3 <= x <= 10 and 2 <= y <= 7
        if in_A or in_B:
            count += 1

print(count)
```

```output
81
```

Это то же 63 + 48 − 30 из подтемы 4: программа не складывает фигуры, а проверяет каждую точку один раз, поэтому общие точки не удваиваются.

---

**Для треугольника автоматическая проверка опирается на уже найденные наклонные границы.**

Мы получили:

x/√3<y<8-x/√3.

Квадратный корень даёт `math.sqrt` из {{import|модуля}} `math` — это приближённое значение √3. Подсчёт:

```python
import math

count = 0

for x in range(1, 7):
    for y in range(1, 8):
        if x / math.sqrt(3) < y < 8 - x / math.sqrt(3):
            count += 1

print(count)
```

```output
24
```

Почему выбраны такие диапазоны?

По горизонтали:

0<x<4√3 ≈ 6,928.

Подходящие целые значения:

1,2,3,4,5,6.

Их даёт:

```python
range(1, 7)
```

По вертикали все внутренние точки должны находиться между уровнями 0 и 8. Поэтому проверяем:

```python
range(1, 8)
```

Наклонные стороны затем отсекают лишние точки внутри этого охватывающего прямоугольника.

Этот пример показывает, как рисунок помогает сформулировать точное условие для проверки.

---

**Подсчёт целых координат между нецелыми границами тоже можно сделать точно.**

Для начала вспомним целочисленные границы.

Если:

2≤ x≤6,

подходят:

2,3,4,5,6.

Количество:

6-2+1=5.

Если:

2<x<6,

подходят:

3,4,5.

Количество:

6-2-1=3.

Но при нецелых границах правило «длина плюс один» напрямую не работает.

Например:

2,3≤ x≤6,8.

Подходят:

3,4,5,6.

Чтобы описать общий способ, введём две операции.

{{ceil|**Округление вниз**}} — выбор наибольшего целого числа, которое не больше исходного:

⌊6,8⌋=6.

**Округление вверх** — выбор наименьшего целого числа, которое не меньше исходного:

⌈2,3⌉=3.

Для условия:

a≤ x≤ b

первое допустимое целое:

⌈a⌉,

последнее:

⌊b⌋.

Количество:

N=max(0,⌊b⌋-⌈a⌉+1).

`max(0, ...)` означает, что при отсутствии подходящих целых чисел результат принимается равным нулю.

Для строгого условия:

a<x<b

получаем:

N=max(0,⌈b⌉-⌊a⌋-1).

Эти формулы полезны для точного подсчёта в отдельных рядах наклонной фигуры.

На первых задачах удобнее выписывать допустимые числа непосредственно. Формулы становятся понятнее после нескольких таких примеров.

---

**Произвольный поворот фигуры может изменить количество целочисленных точек внутри.**

Площадь и длины сторон при повороте сохраняются. Но расположение фигуры относительно координатной решётки меняется.

Пример: квадрат со стороной 2.

Если его стороны идут вдоль осей и он занимает:

0≤ x≤2, 0≤ y≤2,

строго внутри находится одна целочисленная точка:

(1;1).

Если из начала координат построить квадрат той же стороны с начальным направлением 45°, затем каждый раз поворачивать направо на 90°, внутри окажутся две целочисленные точки:

(1;0), (2;0).

<figcaption>Тот же квадрат со стороной 2, начатый под 45°: внутри уже две целые точки, а не одна.</figcaption>

Поэтому произвольно менять начальный угол ради удобства нельзя.

Перенос всей фигуры на целое число единиц по каждой оси сохраняет количество целочисленных точек. Каждая целочисленная точка при таком переносе переходит в целочисленную.

Поворот всей фигуры на 90° вокруг начала координат тоже сохраняет решётку.

Но при полном алгоритме безопаснее точно соблюдать условие: неверное начальное направление может повлиять на все последующие перемещения и взаимное расположение фигур.

**Команду дуги вводит само условие: в нём сказано, где центр, какой радиус, в какую сторону и на какой угол поворачивает дуга.** Таких задач в подборке 2 из 54, все с исполнителем Цапля. Поскольку команда новая, её смысл нельзя угадывать — его читают из условия и проверяют на первом шаге.

Пусть, например, условие определяет: «Дуга R α — исполнитель идёт по окружности радиуса R, центр которой находится на расстоянии R слева от него, поворачиваясь налево на α градусов». Алгоритм

```algo
Направо 90
Вперёд 8
Налево 90
Дуга 4 180
```

из (0; 0) вверх: «Направо 90» и «Вперёд 8» ведут вдоль оси x в (8; 0), «Налево 90» поворачивает вверх. Центр дуги — в 4 слева, то есть (4; 0); полуокружность радиуса 4 заканчивается в (0; 0). Получилась верхняя половина круга с центром (4; 0) и радиусом 4.

---

**Криволинейную границу проверяют неравенством для расстояния до центра.** Точка (x; y) лежит строго внутри полукруга, когда она выше диаметра и ближе к центру, чем радиус:

y > 0 и (x − 4)² + y² < 16.

С границей — y ≥ 0 и (x − 4)² + y² ≤ 16. Корень не нужен: сравнивают квадраты расстояний, и всё остаётся в целых числах, без погрешности.

```python
count = 0

for x in range(0, 9):
    for y in range(0, 5):
        if y > 0 and (x - 4) ** 2 + y ** 2 < 16:
            count += 1

print(count)
```

```output
19
```

По рядам: при y = 1 и y = 2 подходят |x − 4| ≤ 3 — по 7 точек, при y = 3 — |x − 4| ≤ 2, 5 точек; 7 + 7 + 5 = 19. Вместе с границей добавляются 9 точек диаметра и вершина (4; 4) — всего 29. Других целых точек на дуге нет: 16 = a² + b² только при a, b ∈ {0, ±4}.

---

**Итого.**

- Программа подсчёта работает в координатах задачи, без масштаба `k`: перебор с запасом, условие принадлежности из геометрии.
- Строго внутри — `<`, с границей — `<=`; две фигуры — `and`, `or`, `and not`, `!=` для «ровно в одной».
- Для наклонных сторон условие берут из уравнений сторон; для дуги — из сравнения квадрата расстояния до центра с R².
- Целые числа между нецелыми границами: от ⌈a⌉ до ⌊b⌋, всего max(0, ⌊b⌋ − ⌈a⌉ + 1).
- Новую команду (дугу) читают из условия: центр, радиус, сторона, угол.
- Поворот фигуры сохраняет площадь, но не число целых точек.
