**Дополнительный урок — для продвинутых.** Он для тех, кто хочет закрыть все возможные случаи задания 23: условие может измениться сильнее, чем в демоверсии, и спросить количество путей, самый длинный путь или путь из ровно k рёбер. Здесь же — ещё два известных способа искать кратчайший путь. Для задачи демоверсии хватает основных подтем 1–5.

Главная идея подтемы: **те же рассуждения о лучшем ответе для вершины работают и для других вопросов — меняется только то, что мы делаем с вариантами и что храним для вершины**.

Сквозной пример подтемы — учебный граф: вершины 1, 40, 7, 100, четыре пути из 1 в 100 длиной 12, 8, 11 и 6.

---

**Есть ещё способ получить правильные стоимости за один проход по вершинам: расположить их в подходящем порядке.** В нашем учебном графе подходит порядок 1, 40, 7, 100. Почему? До обработки `40` уже обработана `1`. До обработки `7` уже обработаны `1` и `40`. До обработки `100` уже обработаны все вершины, из которых в неё можно прийти.

Такой порядок называется **топологическим порядком**: для каждого ребра его начало расположено раньше его конца. Получение такого порядка называется **топологической сортировкой**.

Это не обычная сортировка номеров. Для нашего графа сортировка чисел дала бы 1, 7, 40, 100. Она не подходит: есть ребро `40 → 7`, а `40` стоит после `7`.

Если обработать каждую вершину в таком неправильном порядке только один раз, улучшение до `7` может прийти слишком поздно.

Идея построения правильного порядка:

1. Найти вершину, в которую сейчас не входит ни одно ребро.
2. Записать её в порядок.
3. Удалить её вместе с исходящими рёбрами из рассматриваемого остатка графа.
4. Повторить.

Пройдите построение по шагам на учебном графе:

%%topo_stepper([(1, 40, 2), (1, 7, 5), (1, 100, 12), (40, 7, 1), (40, 100, 9), (7, 100, 3)])%%

Почему в ациклическом графе найдётся вершина без входящих рёбер? Предположим обратное: в каждую вершину что-то входит. Тогда можно от любой вершины постоянно переходить к её предшественнику. Граф конечный, поэтому одна из вершин обязательно повторится. Получится цикл — противоречие.

После построения такого порядка достаточно распространять стоимости по исходящим рёбрам каждой вершины один раз. Это ещё один способ использовать отсутствие циклов.

**Для положительных весов существует и алгоритм Дейкстры.** Его полезно понимать, чтобы не путать с ошибочной идеей «всегда выбирать самое дешёвое ребро» из подтемы 2. Алгоритм Дейкстры выбирает **ещё не обработанную вершину с наименьшей найденной полной стоимостью от начала**.

Порядок действий:

1. До начала стоимость `0`, до остальных вершин — бесконечность.
2. Выбираем ещё не обработанную вершину с наименьшей стоимостью.
3. Улучшаем стоимости через её исходящие рёбра.
4. Отмечаем вершину как обработанную.
5. Повторяем.

Для нашего графа:

| Выбранная вершина | Её стоимость | Что улучшаем |
|---|---:|---|
| `1` | 0 | До `40`: 2; до `7`: 5; до `100`: 12 |
| `40` | 2 | До `7`: 3; до `100`: 11 |
| `7` | 3 | До `100`: 6 |
| `100` | 6 | Цель обработана |

Почему выбранную вершину можно считать окончательно обработанной? Представь, что выбрана вершина со стоимостью `3`. Среди ещё не обработанных вершин нет найденной стоимости меньше `3`. Кроме того, продолжение любого пути добавляет неотрицательные веса.

Если бы существовал более дешёвый путь к выбранной вершине, на этом пути была бы первая ещё не обработанная вершина. До неё уже можно было бы получить стоимость не больше стоимости всего этого более дешёвого пути — то есть меньше `3`. Тогда алгоритм выбрал бы её раньше. Получается противоречие.

Дейкстра работает и при наличии циклов, если веса неотрицательные. Но при отрицательных весах это обоснование перестаёт действовать.

Для ориентирования полезно держать в голове такое сравнение:

| Способ | Основная идея | Подходящие условия |
|---|---|---|
| Рекурсия с запоминанием | Найти лучший остаток пути через ответы соседей | Граф без направленных циклов |
| Повторные улучшения, Беллман — Форд | Несколько раз просматривать все рёбра | Полностью подходит для задачи демоверсии |
| Топологический порядок | Обрабатывать вершины после всех их предшественников | Граф без направленных циклов |
| Дейкстра | Каждый раз выбирать ближайшую ещё не обработанную вершину | Неотрицательные веса |

Для решения задачи демоверсии достаточно уверенно понимать и уметь написать один из первых двух вариантов.

**Важно различать задачи, которые внешне похожи, но требуют разных вычислений.** Возьмём вопрос: сколько различных путей ведёт из начала в конец? Теперь нужна не минимальная стоимость, а количество вариантов.

Пусть c(v) — количество путей из вершины v до цели. Если из v можно перейти в `A` или `B`, то каждый путь начинается одним из этих переходов. Поэтому c(v) = c(A) + c(B): мы складываем количество вариантов. Для минимальной стоимости было иначе: f(v) = min(w(v, A) + f(A), w(v, B) + f(B)) — здесь выбирается лучший вариант.

:::pick Что требуется и что делаем с вариантами
- *количество путей | складываем количества | c(цель) = 1
- минимальная стоимость | выбираем минимум сумм | f(цель) = 0, тупик — +∞
- максимальная стоимость | выбираем максимум сумм | g(цель) = 0, тупик — −∞
:::

<figure class="plate-figure">
%%graph([(1, 40, ""), (1, 7, ""), (1, 100, ""), (40, 7, ""), (40, 100, ""), (7, 100, "")], values={100: "c = 1", 7: "c = 1", 40: "c = 2", 1: "c = 4"})%%
<figcaption>Количество путей до цели от каждой вершины: c(7) = c(100) = 1, c(40) = c(7) + c(100) = 2, c(1) = c(40) + c(7) + c(100) = 4. Веса здесь не нужны.</figcaption>
</figure>

Начальные значения тоже отличаются. Для минимальной оставшейся стоимости f(цель) = 0. Для количества путей c(цель) = 1. Почему один? Потому что, оказавшись в цели, мы имеем один способ успешно завершить путь: больше никуда не идти. Если поставить ноль, то путь, который пришёл в цель, не добавит ни одного успешного варианта. А для тупика, который не является целью, c(v) = 0, потому что из него нет ни одного пути до цели.

```python
from functools import cache

graph = {1: [40, 7, 100], 40: [7, 100], 7: [100]}


@cache
def count(v):
    if v == 100:
        return 1
    total = 0
    for next_vertex in graph.get(v, []):
        total += count(next_vertex)
    return total


print(count(40), count(1))
```

```output
2 4
```

Есть и техническая ловушка: **нельзя заменить улучшение минимума на прибавление количества в цикле многократных проходов** из подтемы 6 и оставить всё остальное как было. Если каждый проход снова выполнять `count[v] += count[u]`, одни и те же пути могут посчитаться повторно. Для подсчёта путей в ациклическом графе удобно использовать рекурсию с запоминанием или топологический порядок: вклад каждого перехода учитывается в нужный момент один раз.

---

**Если нужен самый длинный путь, отсутствие циклов становится особенно важным.** Для ациклического графа рассуждение об остатке пути сохраняется, но вместо минимума выбирается максимум: g(v) = max(w(v, A) + g(A), w(v, B) + g(B)), а в цели g(цель) = 0.

Недостижимость теперь нужно обозначать значением, которое хуже любого настоящего результата при поиске максимума: −∞. Тогда невозможное продолжение не выиграет у существующего пути.

```python
from decimal import Decimal
from functools import cache

NEG = Decimal("-Infinity")
graph = {1: [(40, 2), (7, 5), (100, 12)],
         40: [(7, 1), (100, 9)], 7: [(100, 3)]}


@cache
def longest(v):
    if v == 100:
        return Decimal(0)
    answer = NEG
    for next_vertex, weight in graph.get(v, []):
        candidate = weight + longest(next_vertex)
        if candidate > answer:
            answer = candidate
    return answer


print(longest(40), longest(1))
```

```output
9 12
```

Из `40` самый длинный путь — прямое ребро 40 → 100 за 9, а из `1` — прямое ребро за 12: обходные пути 2 + 9 = 11 и 5 + 3 = 8 короче. Автоматически переносить этот способ на граф с циклами нельзя. Например, при разрешённом повторном прохождении положительного цикла суммарную стоимость можно увеличивать сколько угодно.

---

**Если требуется ровно заданное количество переходов, одной стоимости на вершину уже недостаточно.** Допустим, в одну вершину можно попасть за `3`, использовав пять рёбер, или за `4`, использовав два ребра. При обычном поиске кратчайшего пути первый вариант лучше. Но если разрешено ровно три перехода, первый вариант вообще нельзя использовать.

Теперь нужно хранить две характеристики: D[k][v] — минимальную стоимость попадания в вершину v **ровно за k переходов**. Здесь k — дополнительная часть описания состояния.

Начало: D[0][S] = 0. До остальных вершин за ноль переходов попасть нельзя: D[0][v] = +∞ при v ≠ S. Переход по ребру u —w→ v: D[k + 1][v] = min(D[k + 1][v], D[k][u] + w). Смысл: чтобы попасть в `v` ровно за k + 1 переход, нужно сначала попасть в `u` ровно за k переходов и пройти ещё одно ребро.

```python
from decimal import Decimal

INF = Decimal("Infinity")
edges = [(1, 40, 2), (1, 7, 5), (1, 100, 12),
         (40, 7, 1), (40, 100, 9), (7, 100, 3)]
vertices = {1, 40, 7, 100}
K = 2

# D[k] — словарь: вершина -> стоимость ровно за k рёбер.
D = [{v: INF for v in vertices} for k in range(K + 1)]
D[0][1] = Decimal(0)

for k in range(K):
    for u, v, w in edges:
        if D[k][u] + w < D[k + 1][v]:
            D[k + 1][v] = D[k][u] + w

print(D[1][100], D[2][100])
```

```output
12 8
```

Ровно одним ребром до `100` можно дойти только за 12, ровно двумя — лучше всего через `7`: 5 + 3 = 8. Кратчайший путь 1 → 40 → 7 → 100 длиной 6 сюда не подходит: в нём три ребра.

При таком расчёте значения для следующего количества переходов хранятся отдельно от предыдущего — в `D[k + 1]`, а читаются из `D[k]`. Иначе обновлённая стоимость может сразу использоваться повторно, и число рёбер перестанет контролироваться. Строка `D = [... for k in range(K + 1)]` — {{comp|списковое включение}}: список из K + 1 словарей.

Это хороший пример общего принципа: **храни столько информации, сколько нужно для проверки ограничений и выбора дальнейших действий**.

---

**Итого.**

- Топологический порядок — каждое ребро идёт от более ранней вершины к более поздней; номера вершин его не задают.
- Дейкстра выбирает ближайшую по полной стоимости вершину, а не дешёвое ребро; нужны неотрицательные веса.
- Количество путей — сумма по соседям, c(цель) = 1, тупик — 0. Самый длинный путь — максимум, тупик — −∞.
- Ровно k рёбер — к вершине добавляется число переходов: D[k][v].
