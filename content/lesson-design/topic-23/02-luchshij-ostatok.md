Главная идея подтемы: **для каждой вершины достаточно знать одно число — стоимость лучшего пути от неё до цели, и это число складывается из ответов для соседних вершин**. На этой идее держится решение задания 23: ответ для вершины получается из уже известных ответов для её соседей. Когда она ясна, программа перестаёт быть набором команд, которые нужно запоминать.

Сквозной пример подтемы — учебный граф из подтемы 1: вершины 1, 40, 7, 100, кратчайший путь 1 → 40 → 7 → 100 длиной 6.

---

**Первая естественная идея — каждый раз выбирать самое дешёвое исходящее ребро. Она не гарантирует правильного результата.** Представь два варианта:

| Первый переход | Затем переход к цели | Общая стоимость |
|---|---|---:|
| Из начала в `A` за `1` | Из `A` к цели за `100` | `101` |
| Из начала в `B` за `5` | Из `B` к цели за `1` | `6` |

<figure class="plate-figure">
%%graph([("S", "A", 1), ("A", "T", 100), ("S", "B", 5), ("B", "T", 1)], path=["S", "B", "T"])%%
<figcaption>Из S дешевле всего шагнуть в A (1), но продолжение из A стоит 100. Лучший путь S → B → T начинается с более дорогого ребра: 5 + 1 = 6.</figcaption>
</figure>

Самый дешёвый первый шаг ведёт к дорогому полному пути. Причина проста: стоимость ближайшего перехода ничего не говорит о стоимости продолжения.

---

**Полный перебор всех путей правилен по смыслу, но путей бывает слишком много.** Количество путей может быть огромным даже при сравнительно небольшом графе. Если на каждом из 30 последовательных этапов есть два независимых выбора, получится 2³⁰ = 1 073 741 824 различных путей.

Нам поможет возможность **объединять информацию о путях, которые пришли в одну и ту же вершину**.

---

**Из вершины дальше можно двигаться одинаково, как бы мы в неё ни пришли.** Представь, что мы нашли два способа попасть в вершину `7`: первый стоит `5`, второй — `3`. Из `7` до цели можно пройти ещё за `3`. Тогда полные стоимости 5 + 3 = 8 и 3 + 3 = 6.

Более дорогой способ попасть в `7` не нужен для поиска минимальной стоимости. Из вершины `7` дальнейшие возможности одинаковы независимо от того, каким из этих двух путей мы пришли. Это рассуждение работает для любого продолжения: если оно стоит r, то 3 + r < 5 + r.

Значит, всё, что нужно знать о вершине `7` для дальнейшего пути, — **сколько стоит лучший путь от неё до цели**. Это центральная идея решения.

Здесь есть важное условие: дальнейшие возможности определяются текущей вершиной. Если условие дополнительно учитывает историю движения — например, сколько переходов уже сделано, — одного числа на вершину может оказаться недостаточно. Такие ограничения разобраны в подтемах 5 и 7.

---

**Обозначим f(v) — минимальную стоимость пути из вершины v до цели.** Запись f(7) читается «эф от семи»: это одно число, записанное для вершины `7`, — сколько стоит лучший путь от `7` до цели. А min(…) — наименьшее из чисел в скобках: min(4, 9) = 4.

Для нового способа сначала ответим на самый простой вопрос. Сколько осталось идти, если мы уже стоим в целевой вершине? Нисколько: f(100) = 0.

Теперь возьмём вершину `7`. Из неё есть переход в `100` за `3`. Значит, f(7) = 3 + f(100) = 3.

Из вершины `40` есть два варианта: перейти в `7` за `1`, а потом продолжить за f(7), или перейти в `100` за `9`, а потом продолжить за f(100). Поэтому f(40) = min(1 + f(7), 9 + f(100)) = min(1 + 3, 9 + 0) = 4.

Из `1` можно пойти в `40`, `7` или `100`: f(1) = min(2 + f(40), 5 + f(7), 12 + f(100)) = min(2 + 4, 5 + 3, 12 + 0) = 6. Это тот же ответ, что дал перебор всех путей.

Посмотрите тот же расчёт по шагам. Порядок важен: f вершины можно посчитать, только когда известны f всех вершин, куда из неё ведут рёбра. Поэтому идём от цели назад — 100, 7, 40, 1. На каждом шаге выделено ребро, которое дало минимум:

%%backward_stepper([(1, 40, 2), (1, 7, 5), (1, 100, 12), (40, 7, 1), (40, 100, 9), (7, 100, 3)])%%

Общее правило: **чтобы найти лучший путь от текущей вершины до цели, нужно рассмотреть каждый первый переход и прибавить к его весу лучший путь от следующей вершины**. Ни один путь не выписан целиком: каждое значение f собирает лучшие продолжения соседей.

Если функция для вершины вызывает такую же функцию для следующей вершины, это называется **рекурсией**. Она здесь соответствует естественному рассуждению: «чтобы ответить для этой вершины, сначала получу ответы для вершин, в которые из неё можно перейти».

---

**Очень важен случай, когда из вершины нельзя добраться до цели.** Допустим, есть два ребра: 1 —12→ 100 и 1 —2→ 81. Из `81` дальше идти некуда. Правильный ответ — `12`.

Если ошибочно считать f(81) = 0, программа сравнит 12 + 0 = 12 и 2 + 0 = 2, после чего выберет `2`. Но путь за `2` заканчивается в `81`, а не в `100`.

<figure class="plate-figure">
%%graph([(1, 100, 12), (1, 81, 2)], values={1: "f = 12", 100: "f = 0", 81: "f = ∞"})%%
<figcaption>Из 81 рёбер нет, до цели оттуда не дойти: f(81) = ∞. Поэтому ребро 1 → 81, хоть и дешёвое, в ответ не попадает.</figcaption>
</figure>

Нужно значение, которое будет хуже любой настоящей стоимости. Ставить `0` нельзя: это означало бы, что из тупика цель достигается бесплатно. Для этого используют положительную бесконечность +∞ — удобное обозначение состояния **«пути до цели нет»**. У неё нужные нам свойства: 5 < +∞ и +∞ + 3 = +∞. Любая настоящая стоимость лучше бесконечности, а продолжение через тупик так и останется бесконечным.

Поэтому два состояния обозначаются по-разному:

| Состояние | Значение |
|---|---:|
| Цель уже достигнута | 0 |
| Достичь цели невозможно | +∞ |

Встречаются решения, где для вершины без исходящих рёбер возвращается `0`. Для произвольного графа такая обработка тупика неверна, даже если на одном конкретном файле ответ случайно совпал.

---

**Итого.**

- Жадный выбор дешёвого ребра ошибается, полный перебор путей слишком долгий.
- Для вершины достаточно знать f(v) — стоимость лучшего пути от неё до цели.
- f(цель) = 0, f(тупик) = +∞, для остальных f(v) — минимум «вес ребра + f(следующей вершины)» по всем рёбрам из v.
- Функция, которая для ответа вызывает саму себя для соседних вершин, — рекурсия.
