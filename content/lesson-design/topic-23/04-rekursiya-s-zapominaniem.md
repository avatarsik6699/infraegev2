Главная идея подтемы: **функция `best(v)` считает f(v) по правилу из подтемы 2, а `@cache` запоминает каждый ответ, поэтому каждая вершина вычисляется один раз**. Это полное решение задачи демоверсии: прочитать файл, построить список смежности, вызвать `best(1)`.

Сквозной пример подтемы — файл `23.txt` с учебным графом. Чтение файла и список смежности `graph` — из подтемы 3.

---

**Правило из подтемы 2 записывается функцией почти дословно.** f(цель) = 0; иначе f(v) — минимум «вес ребра + f(следующей вершины)» по всем рёбрам из v; если рёбер нет или ни одно не ведёт к цели, остаётся +∞.

```python
def best(v):
    # Мы уже в цели.
    if v == TARGET:
        return Decimal(0)

    # Пока подходящий путь до цели не найден.
    answer = INF

    for next_vertex, weight in graph.get(v, []):
        candidate = weight + best(next_vertex)

        if candidate < answer:
            answer = candidate

    return answer
```

Функция {{def|`best`}} вызывает саму себя для следующей вершины — это {{rec|рекурсия}}. Базовый случай — цель: там ответ известен сразу.

Посмотри, как автоматически обрабатывается тупик. В начале `answer = INF`. Исходящих рёбер нет, поэтому цикл не выполняется, и функция возвращает `INF`. Если исходящие рёбра есть, но все они ведут в вершины, из которых цель недостижима, результат тоже останется бесконечным: w + ∞ = ∞.

При этом целевая вершина обрабатывается раньше цикла. Даже если из неё есть исходящие рёбра, идти по ним уже не требуется: цель достигнута.

---

**Рекурсивные ответы нужно запоминать.** Представь, что из нескольких вершин можно попасть в одну и ту же вершину `7`. Для каждой из них понадобится значение f(7). Но оно одинаково: граф и цель не меняются. Если каждый раз заново вычислять f(7), одни и те же участки графа будут обрабатываться повторно.

Лучше при первом вызове вычислить ответ, сохранить его, а при следующем таком же вызове сразу вернуть сохранённое значение. Это называется **запоминанием результатов**, или **мемоизацией**.

В Python для этого есть `cache` из модуля `functools`: {{import|`from functools import cache`}}. Строка `@cache` перед определением функции подключает автоматическое запоминание её результатов по аргументам. Такая запись с `@` называется декоратором; здесь достаточно понимать её конкретное действие: повторный вызов с той же вершиной использует сохранённый ответ.

Сравните вызовы на учебном графе. Слева каждый вызов `best` заново обходит всё, что ниже него. Справа повторный вызов сразу получает сохранённый ответ:

<figure class="plate-figure">
%%call_tree([(1, 40, 2), (1, 7, 5), (1, 100, 12), (40, 7, 1), (40, 100, 9), (7, 100, 3)])%%
<figcaption>Дерево вызовов best(1). Без запоминания best(7) считается дважды, best(100) — четыре раза. С @cache каждая вершина вычисляется один раз, остальные вызовы берут ответ из памяти.</figcaption>
</figure>

На четырёх вершинах разница невелика. Но на больших графах без запоминания она огромна. Если вершины 1, 2, …, 30 соединены рёбрами i → i + 1 и i → i + 2, а цель — 30, то `best` без `@cache` будет вызвана 2 178 308 раз, а с `@cache` — 30 раз, по разу на вершину.

---

**Посмотрим, как работает рекурсия с запоминанием на учебном графе.** Стек вызовов — цепочка функций, которые начали работу и ждут ответа от следующей. Значения f появляются под вершинами, как только они вычислены и сохранены:

%%best_stepper([(1, 40, 2), (1, 7, 5), (1, 100, 12), (40, 7, 1), (40, 100, 9), (7, 100, 3)])%%

`best(1)` сначала уходит вглубь до цели по рёбрам 1 → 40 → 7 → 100 и только на обратном пути получает числа. Когда `best(40)` и `best(1)` второй раз доходят до вершин 7 и 100, их ответы уже сохранены и берутся из памяти, без нового обхода.

---

**Соберём основное решение целиком.** Сохрани входные данные под именем `23.txt` в рабочей папке программы или подставь своё имя файла в `open`.

```python
from decimal import Decimal
from functools import cache

SOURCE = 1
TARGET = 100
INF = Decimal("Infinity")

# Читаем рёбра из файла.
edges = []

with open("23.txt") as f:
    for line in f:
        if not line.strip():
            continue

        parts = line.split()
        u = int(parts[0])
        v = int(parts[1])
        w = Decimal(parts[2])
        edges.append((u, v, w))

# Список смежности: вершина -> её исходящие переходы.
graph = {}

for u, v, w in edges:
    if u not in graph:
        graph[u] = []

    graph[u].append((v, w))


@cache
def best(v):
    if v == TARGET:
        return Decimal(0)

    answer = INF

    for next_vertex, weight in graph.get(v, []):
        candidate = weight + best(next_vertex)

        if candidate < answer:
            answer = candidate

    return answer


# По условию путь до TARGET существует.
print(int(best(SOURCE)))
```

```output
6
```

Строки файла `23.txt` идут не по порядку движения (`7 100 3.0` — первая), но рекурсии это не мешает: она сама идёт по рёбрам от вершины к вершине. Дробная часть отбрасывается только у полной суммы — в самой последней строке.

---

**Почему такая рекурсия завершается?** Каждый вложенный вызов соответствует движению по стрелке. Если бы функция могла бесконечно переходить к новым вложенным вызовам в конечном графе, какая-то вершина повторилась бы. Это означало бы наличие направленного цикла. По условию циклов нет, поэтому цепочка вызовов обязательно закончится — либо на целевой вершине, либо на вершине без исходящих рёбер.

Сам по себе `cache` не устраняет циклы. Если есть переходы A → B → A, результат для A ещё не вычислен к моменту повторного вызова A, поэтому брать из памяти пока нечего. Именно гарантия ацикличности делает этот рекурсивный способ подходящим.

Глубина вложенных вызовов не больше числа рёбер на самом длинном пути. В файле задания не больше 200 рёбер, а Python по умолчанию допускает около 1000 вложенных вызовов, так что запас есть.

Также сохранённые ответы относятся к конкретному графу и конкретной цели. Если менять их в уже работающей программе, старые результаты нельзя автоматически использовать для новой задачи.

---

**Сохранение ответов на подзадачи и построение через них более сложных ответов относится к динамическому программированию.** Подзадача здесь звучит так: найти лучшую стоимость от некоторой вершины до цели. Это название не означает какой-то особой команды Python. Речь о способе рассуждения:

1. Определить, какую информацию хранить.
2. Задать простейшие начальные значения.
3. Вывести правило получения новых значений.
4. Организовать вычисления так, чтобы не выполнять одну и ту же работу бессмысленно много раз.

В рекурсивном решении с запоминанием каждая нужная вершина полноценно вычисляется один раз, а её исходящие рёбра просматриваются один раз. Поэтому объём работы после построения графа оценивается как O(V + E), где V — количество вершин, E — количество рёбер. Обозначение O(…) описывает, как объём работы растёт вместе с размером данных. Для файла из 200 строк ответ получается мгновенно.

---

**Итого.**

- `best(v)`: в цели — `Decimal(0)`, иначе минимум `weight + best(next_vertex)` по рёбрам из `graph.get(v, [])`, начиная с `INF`.
- `@cache` запоминает ответы: каждая вершина вычисляется один раз, работа — O(V + E).
- Рекурсия завершается, потому что граф ациклический; на графе с циклом этот способ не работает.
- Целая часть берётся один раз, в конце: `int(best(SOURCE))`.
