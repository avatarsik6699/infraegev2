Главная идея подтемы: **ограничения на путь не требуют нового алгоритма: обязательная вершина делит путь на участки, запрещённая становится тупиком, а отсутствие пути видно по бесконечности**. Такие изменения условия уже встречаются в разборах задания 23, поэтому они входят в основные подтемы.

Сквозной пример подтемы — граф из задачи 6 подтемы 2: кратчайший путь 1 → 4 → 15 → 100 длиной 8.9. Чтение графа и функция `best` — из подтемы 4.

<figcaption>Граф подтемы: из 22 рёбер нет. Кратчайший путь из 1 в 100 — 1 → 4 → 15 → 100, его длина 2.5 + 0.6 + 5.8 = 8.9.</figcaption>

**Чтобы искать путь до любой вершины, цель делаем параметром функции.** В подтеме 4 цель была постоянной `TARGET`. Теперь `best(v, target)` — стоимость лучшего пути из `v` в `target`. `@cache` запоминает ответ для каждой пары аргументов, так что разные цели не смешиваются.

```python
from decimal import Decimal
from functools import cache

INF = Decimal("Infinity")
edges = [(1, 4, "2.5"), (1, 6, "4.1"), (4, 6, "1.2"),
         (4, 15, "0.6"), (6, 15, "2.9"), (6, 100, "7.4"),
         (15, 100, "5.8"), (15, 22, "0.3")]

graph = {}
for u, v, w in edges:
    if u not in graph:
        graph[u] = []
    graph[u].append((v, Decimal(w)))


@cache
def best(v, target):
    if v == target:
        return Decimal(0)
    answer = INF
    for next_vertex, weight in graph.get(v, []):
        candidate = weight + best(next_vertex, target)
        if candidate < answer:
            answer = candidate
    return answer


print(best(1, 100))
print(best(1, 6), best(6, 100))
print(best(1, 6) + best(6, 100))
```

```output
8.9
3.7 7.4
11.1
```

---

**Если путь должен пройти через определённую вершину, задачу можно разделить на части.** Пусть требуется пройти S → K → T, где S — начало, K — обязательная промежуточная вершина, T — цель. В ациклическом графе минимальная стоимость такого пути равна best(S, K) + best(K, T), если обе части существуют.

<figure class="plate-figure">
%%graph([(1, 4, "2.5"), (1, 6, "4.1"), (4, 6, "1.2"), (4, 15, "0.6"), (6, 15, "2.9"), (6, 100, "7.4"), (15, 100, "5.8"), (15, 22, "0.3")], path=[1, 4, 6, 100], must=[6])%%
<figcaption>Обязательная вершина 6. Лучший путь до неё — 1 → 4 → 6 за 3.7, лучший путь от неё — 6 → 100 за 7.4. Вместе 11.1 — дороже кратчайшего пути 8.9, который через 6 не проходит.</figcaption>
</figure>

Почему можно сложить два независимо найденных минимума? Любой подходящий путь состоит из части до K и части после K. Каждая из этих частей не может быть дешевле своего минимума. С другой стороны, два кратчайших участка можно соединить. В ациклическом графе они не могут иметь общую вершину, отличную от K: иначе возникло бы движение от этой вершины к K и обратно к ней, то есть цикл.

Если хотя бы одна часть недостижима, подходящего пути нет: сумма с бесконечностью останется бесконечностью. И здесь тоже сначала складывают полные стоимости, а целую часть берут только в конце.

Если обязательных вершин две, A и B, путь делится на три участка. В ациклическом графе пройти их можно только в одном порядке: если бы из A можно было попасть в B, а из B — в A, получился бы цикл. Порядок можно не угадывать — посчитать оба и взять меньший, недостижимый даст бесконечность:

```python
a, b = 6, 15
one = best(1, a) + best(a, b) + best(b, 100)
two = best(1, b) + best(b, a) + best(a, 100)
print(one, two, min(one, two))
```

```output
12.4 Infinity 12.4
```

Этот фрагмент продолжает программу выше: `best` уже определена. Через 6, затем 15: 3.7 + 2.9 + 5.8 = 12.4. Из 15 в 6 пути нет, второй порядок невозможен.

---

**Если вершину запрещено посещать, она становится тупиком.** Для запрещённой вершины K можно удалить все рёбра, которые ведут в K и выходят из K, и искать кратчайший путь в оставшемся графе. В рекурсии то же самое делается одной строкой: из запрещённой вершины цель недостижима, значит, её ответ — бесконечность.

```python
BANNED = {4}


@cache
def best_without(v, target):
    if v in BANNED:
        return INF
    if v == target:
        return Decimal(0)
    answer = INF
    for next_vertex, weight in graph.get(v, []):
        candidate = weight + best_without(next_vertex, target)
        if candidate < answer:
            answer = candidate
    return answer


print(best_without(1, 100))
```

```output
11.5
```

Проверка `v in BANNED` стоит первой: даже если запрещена сама цель, пройти в неё нельзя. Но сначала проверь, не запрещена ли сама начальная или конечная вершина. В таком случае обычного допустимого пути между ними не будет. Для запрета — отдельная функция со своим `@cache`: ответы `best` без запрета к ней не относятся.

---

**Если существование пути не гарантируется, перед выводом нужно проверить результат.** В демоверсии путь до цели есть. Но в изменённом условии — например, с запретом — его может не оказаться:

```python
answer = best(6, 4)

if answer == INF:
    print("Пути нет")
else:
    print(int(answer))
```

```output
Пути нет
```

Преобразовывать бесконечность в целое число нельзя: `int(INF)` завершит программу ошибкой.

---

**Итого.**

- Цель — параметр: `best(v, target)` с `@cache` отвечает для любой пары вершин.
- Обязательная вершина K: best(S, K) + best(K, T). Две обязательные — оба порядка, меньшая сумма.
- Запрещённая вершина — тупик: `if v in BANNED: return INF` первой строкой функции.
- Бесконечность в ответе означает «пути нет»; её проверяют до `int`.
