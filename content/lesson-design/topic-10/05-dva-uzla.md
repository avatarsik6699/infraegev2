**Два адреса при общей маске лежат в одной сети, пока граница маски не заходит дальше их совпадающих начальных битов.** Это 8 задач из 87, в том числе задачи досрочной волны ЕГЭ-2019 и основной волны ЕГЭ-2024: самая длинная общая маска или самая короткая маска, при которой сети уже разные.

Пример подтемы — адреса 172.20.74.10 и 172.20.79.200. Перебор длин префикса из подтемы 4 считаем известным: здесь он строит сразу две сети.

---

**Задачи о двух компьютерах решаются через совпадение их сетевых частей.** Если используется одна и та же маска M, два адреса принадлежат одной сети тогда и только тогда, когда I₁ И M = I₂ И M, то есть вычисленные адреса сетей совпадают.

Первые два октета наших адресов одинаковы — это уже 16 совпадающих битов. Третьи октеты: 74 = `01001010`, 79 = `01001111`. Первые пять битов третьего октета совпадают — `01001`, шестой различается. Следовательно, всего в начале совпадает 16 + 5 = 21 бит.

<figure class="plate-figure">
%%ip_pair("172.20.74.10", "172.20.79.200", "two")%%
<figcaption>Адреса 172.20.74.10 и 172.20.79.200 по битам: первые 21 бит одинаковы, 22-й различается. Пока граница маски левее этой черты, сетевые части совпадают.</figcaption>
</figure>

Если выбрать `/21`, все сетевые биты совпадут — адреса будут в одной сети. Если выбрать `/22`, различающийся бит попадёт в сетевую часть — адреса окажутся в разных сетях. Получаем: адреса в одной сети при p ≤ 21, в разных сетях при p ≥ 22. Отсюда самая длинная маска, при которой они ещё в одной сети, — `/21` = `255.255.248.0`; самая короткая маска, при которой они уже в разных сетях, — `/22` = `255.255.252.0`.

---

**После первого различия сравнивать дальше не нужно.** Почему? Потому что сетевой префикс непрерывен. Если он дошёл до первого различающегося бита, сетевые части уже различаются. Совпадения дальше этого не исправят. Общее правило для разных IP-адресов: если подряд совпадают первые C битов, то при общей маске адреса находятся в одной сети для p ≤ C и в разных сетях для p > C.

Если требуется **наименьшая сеть, содержащая оба адреса**, выбираем максимально возможное p, при котором они ещё вместе. В нашем примере p = 21, h = 11, 2¹¹ = 2048 адресов.

---

**Программа строит обе сети для каждой длины префикса и сравнивает их адреса сети.** Здесь у двух адресов намеренно используется одинаковое `p`: именно для общей маски мы вывели правило совпадающих начальных битов. Подходящие длины собираются в список:

```python
from ipaddress import ip_network

first = '172.20.74.10'
second = '172.20.79.200'
same = []
for p in range(33):
    net1 = ip_network(f'{first}/{p}', strict=False)
    net2 = ip_network(f'{second}/{p}', strict=False)
    if net1.network_address == net2.network_address:
        same.append(p)
print(min(same), max(same))
```

```output
0 21
```

Подходящие длины — от 0 до 21. Самое большое значение — 21: это максимально длинная маска, при которой адреса ещё находятся в одной сети.

Чтобы искать маски, при которых сети различаются, используется сравнение `!=` — «не равно» ({{eq|сравнение}}). Первая такая длина и есть самая короткая маска разных сетей, поэтому цикл можно остановить на ней ({{break|break}}). Запусти программу по шагам; перебор начат с 18, чтобы шагов было немного:

```python run differ.py
from ipaddress import ip_network

for p in range(18, 33):
    a = ip_network(f'172.20.74.10/{p}', strict=False)
    b = ip_network(f'172.20.79.200/{p}', strict=False)
    if a.network_address != b.network_address:
        break
print(p)
```

```output
22
```

**Узел не может совпадать с адресом сети или с широковещательным адресом, поэтому самая длинная общая маска иногда короче C.** Правило «одна сеть при p ≤ C» говорит только о совпадении битов. Но в задачах речь идёт об узлах — адресах компьютеров, а адрес сети и широковещательный адрес компьютеру не назначают (подтема 2).

Возьмём узлы 172.20.72.0 и 172.20.79.200. Третьи октеты 72 = `01001000` и 79 = `01001111` совпадают в первых пяти битах, поэтому C = 21, как в нашем примере. Но при `/21` адрес сети — 172.20.72.0: первый узел совпал бы с адресом сети. Значит, `/21` не годится, и **самая длинная общая маска — `/20`**: сеть 172.20.64.0 — 172.20.79.255, оба адреса внутри неё обычные.

<figure class="plate-figure">
%%ip_bits("172.20.72.0", 21)%%
<figcaption>Узел 172.20.72.0 и маска /21: все 11 битов его части узла — нули. При такой маске он и есть адрес сети, поэтому компьютеру этот адрес не назначают.</figcaption>
</figure>

Программа проверяет это прямо. Запись `b in net` ({{in|in}}) проверяет, что адрес `b` лежит в сети `net`, а пара `ends` ({{tuple|кортеж}}) — два края сети, которые узлу не подходят:

```python
from ipaddress import ip_address, ip_network

a = ip_address('172.20.72.0')
b = ip_address('172.20.79.200')
best = 0
for p in range(33):
    net = ip_network(f'{a}/{p}', strict=False)
    ends = (net.network_address, net.broadcast_address)
    if b in net and a not in ends and b not in ends:
        best = p
print(best)
```

```output
20
```

Для пары 172.20.74.10 и 172.20.79.200 эта проверка ничего не меняет: при `/21` оба адреса обычные. Но на экзамене встречались пары, где один из узлов при длине C оказывается адресом сети, — поэтому проверку стоит делать всегда.

---

**Итого.**

- При общей маске два адреса в одной сети, если их сетевые части совпадают: p ≤ C, где C — число совпадающих начальных битов.
- Самая длинная общая маска — `/C`, самая короткая маска разных сетей — `/(C + 1)`.
- Наименьшая сеть с обоими адресами — при наибольшем p: 2³²⁻ᶜ адресов.
- Узел не может быть адресом сети или широковещательным: при такой длине маска должна быть короче.
- Программа: две сети для каждого `p` и сравнение `network_address` через `==` или `!=`; проверка узлов — `b in net` и края сети.
