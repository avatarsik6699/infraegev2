**Если маску задаёт условие на биты, перебираются все 33 длины префикса, а адреса большой сети считаются сочетаниями, а не перебором.** В таких задачах нет ни адреса сети, ни второго узла: маску отбирает нестандартная проверка — например, «единиц в адресе сети столько же, сколько нулей в маске». Подходящая сеть бывает огромной, и перебор её адресов уже не успевает.

Начнём с сети 192.168.10.0/28 из подтемы 6 и её шести адресов с девятью единицами, а затем перейдём к условиям на маску. Перебор длин префикса (подтема 4) и подсчёт адресов по битам (подтема 6) считаем известными.

**Число адресов с нужным количеством единиц — это число способов выбрать позиции единиц среди свободных битов.** Почему в сети 192.168.10.0/28 ровно шесть адресов с девятью единицами? Мы выбираем две позиции из четырёх, в которых будут единицы. Первую позицию можно выбрать четырьмя способами, вторую — тремя: 4 · 3 = 12. Но каждая пара учтена дважды: например, «первая и третья» и «третья и первая» задают один и тот же набор позиций. Поэтому 4 · 3 / 2 = 6.

Все шесть способов — выбери набор позиций единиц:

:::pick-tokens Позиции двух единиц среди свободных битов | 1, 2, 3, 4
- *0011 | 3, 4 | последний октет 3
- 0101 | 2, 4 | последний октет 5
- 0110 | 2, 3 | последний октет 6
- 1001 | 1, 4 | последний октет 9
- 1010 | 1, 3 | последний октет 10
- 1100 | 1, 2 | последний октет 12
:::

Количество способов выбрать r позиций из h называют **числом сочетаний** и обозначают C(h, r).

<details class="proof" markdown="1">
<summary>Формула числа сочетаний через факториал</summary>

C(h, r) = h! / (r! · (h − r)!). Знак `!` обозначает факториал — произведение целых чисел от 1 до указанного числа: 4! = 1 · 2 · 3 · 4 = 24. Принимают 0! = 1: выбрать ни одной позиции можно одним способом — ничего не выбрать. Для нашего примера C(4, 2) = 24 / (2 · 2) = 6.

</details>

Если c — число единиц в фиксированной части, h — число свободных битов, k — требуемое число единиц во всём адресе, то в свободной части нужно выбрать r = k − c единиц. **Количество адресов — C(h, k − c), если 0 ≤ k − c ≤ h.** Если k − c < 0, фиксированная часть уже содержит слишком много единиц. Если k − c > h, свободных позиций не хватает. В обоих случаях ответ — ноль.

В Python число сочетаний считает `comb` из модуля `math` ({{comb|comb}}):

```python
from math import comb

print(comb(4, 2), 4 * 3 // 2)
print(comb(4, 0), comb(4, 5))
```

```output
6 6
1 0
```

---

**Функция подсчёта по формуле заменяет перебор адресов сети.** Она берёт c из адреса сети, h — из длины префикса и возвращает C(h, k − c) или ноль ({{def|функция}}):

```python
from ipaddress import ip_network
from math import comb


def count_ones(net, k):
    bits = format(int(net.network_address), '032b')
    c = bits.count('1')
    h = 32 - net.prefixlen
    if k < c:
        return 0
    return comb(h, k - c)
```

Проверим её на знакомой сети и на огромной — `/8`, где 16 777 216 адресов, а перебор занял бы заметное время:

```python
print(count_ones(ip_network('192.168.10.0/28'), 9))
print(count_ones(ip_network('10.0.0.0/8'), 20))
```

```output
6
134596
```

В сети 10.0.0.0/8 фиксированная часть — 10 = `00001010`, две единицы; в 24 свободных битах нужно 18 единиц: C(24, 18) = 134 596.

**Если маску задаёт условие, программа проверяет его для каждой из 33 длин префикса.** Пусть известно, что в двоичной записи адреса сети, к которой принадлежит узел 25.140.77.201, единиц столько же, сколько нулей в маске этой сети. Сколько адресов этой сети содержат ровно 12 единиц?

Нулей в маске `/p` — 32 − p, единиц в адресе сети считаем по битам. Перебираем все длины и оставляем те, где числа равны. Для найденной сети считаем адреса функцией `count_ones`:

```python
from ipaddress import ip_network

for p in range(33):
    net = ip_network(f'25.140.77.201/{p}', strict=False)
    c = format(int(net.network_address), '032b').count('1')
    if c == 32 - p:
        print(net, c, count_ones(net, 12))
```

```output
25.140.76.0/23 9 84
```

Подходит одна маска — `/23`: в адресе сети 25.140.76.0 девять единиц, в маске девять нулей. Свободных битов 9, нужно 12 − 9 = 3 единицы: C(9, 3) = 84. Если подходят несколько масок, задача спрашивает о наименьшем или наибольшем результате — его выбирают среди найденных, как в подтеме 4.

**Условие на номер узла сводится к тому же выбору позиций.** Пусть для узла 129.0.5.96 количество единиц в адресе сети равно количеству единиц в номере узла в пределах сети (номер — I − N, подтема 3). Какое наибольшее число узлов этой сети обладает тем же свойством, включая сам узел?

Номера адресов сети — все числа из h битов, от 0 до 2ʰ − 1. Номер с c единицами получается выбором c позиций из h, поэтому таких адресов C(h, c), где c — единицы адреса сети. Остаётся перебрать длины, где узел сам обладает свойством, и взять наибольшее C(h, c):

```python
from ipaddress import ip_address, ip_network
from math import comb

a = ip_address('129.0.5.96')
best = 0
for p in range(33):
    net = ip_network(f'{a}/{p}', strict=False)
    c = format(int(net.network_address), '032b').count('1')
    number = int(a) - int(net.network_address)
    if c == format(number, 'b').count('1'):
        print(p, c, comb(32 - p, c))
        best = max(best, comb(32 - p, c))
print(best)
```

```output
22 3 120
23 3 84
120
```

При `/22` номер узла 352 = `101100000` — три единицы, как у адреса сети 129.0.4.0; таких номеров из десяти битов C(10, 3) = 120. Адрес сети (номер 0, ноль единиц) в подсчёт не попадает, а широковещательный — только если c = h.

**Условие «в сети ровно столько-то подходящих адресов» тоже проверяется для каждой длины.** Пусть узел 77.1.130.9 принадлежит сети, в которой ровно 120 адресов содержат по девять единиц. Сколько единиц в маске? Для каждой длины считаем подходящие адреса функцией `count_ones` и оставляем длину, где их ровно 120:

```python
from ipaddress import ip_network

for p in range(33):
    net = ip_network(f'77.1.130.9/{p}', strict=False)
    if count_ones(net, 9) == 120:
        print(p, net)
```

```output
22 77.1.128.0/22
```

Без формулы пришлось бы перебирать адреса и самых больших сетей — `/0` содержит все 2³² адресов.

**Второй узел иногда задан описанием, и его строят по условию.** Например: «в сети узла 61.200.37.5 есть узел, у которого первый байт совпадает с четвёртым, а второй — с третьим». При маске длиннее 15 бит первые два байта у всех адресов сети те же — 61 и 200, значит, такой узел — 61.200.200.61. Дальше это задача о двух узлах (подтема 5): 37 = `00100101` и 200 = `11001000` различаются уже в первом бите третьего байта, C = 16. Самая маленькая сеть с обоими узлами — 61.200.0.0/16. Более короткие маски дают сети больше, и в задаче на наименьшее количество они не нужны.

---

**Итого.**

- Адресов с k единицами — C(h, k − c): c — единицы фиксированной части, h — свободные биты; при k − c < 0 или > h — ноль. В программе `comb` из `math`.
- Маска по условию: перебор всех 33 длин и проверка условия на `network_address`, `32 - p` или номер узла.
- Номеров с c единицами среди h бит — C(h, c).
- Большие сети считаются формулой: перебор адресов `/8` и шире слишком долгий.
- Узел, заданный описанием, строится явно, дальше — задача о двух узлах.

**Ответы для проверки:**

1. 10: c = 2 (10 = `00001010`), h = 5, C(5, 2).
2. 15 504: 172 = `10101100` — четыре единицы, первые четыре бита 16 — `0001`, одна; c = 5, h = 20, C(20, 5).
3. 35: подходит маска `/25`, в адресе сети семь единиц; h = 7, нужно три единицы, C(7, 3).
4. 70: подходит маска `/24`, в адресе сети восемь единиц; h = 8, C(8, 4).
5. 56: свойство есть только при `/24`, у адреса сети три единицы; C(8, 3).
6. 24: ровно 56 адресов с девятью единицами — только при `/24`, C(8, 3).
7. 1820: второй узел — 61.200.200.61, самая маленькая общая сеть 61.200.0.0/16; c = 5 + 3 = 8, h = 16, C(16, 4).
8. Позиции выбираются без учёта порядка: при h = 4 и двух единицах наборы 4 · 3 = 12 упорядоченных выборов дают каждую пару дважды, поэтому 6, а h · (k − c) = 8 ничего не считает — у /28 ровно 6 адресов с девятью единицами.
