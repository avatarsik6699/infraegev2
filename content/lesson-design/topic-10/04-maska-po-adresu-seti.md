**Если известны адрес узла и адрес сети, маску восстанавливают по битам: где единица адреса сохранилась, маска равна 1, где пропала — 0, а совпавшие нули маску не определяют.** Поэтому маска бывает не одна, и задача спрашивает о наименьшей или наибольшей из подходящих. Это 28 задач из 87 и главный тип экзаменов 2015–2020 годов.

Главный пример подтемы — адрес 172.20.174.93 и адрес сети 172.20.160.0: у них подходят две маски. Перед ним — один короткий пример, где маска находится однозначно. Поразрядное «И» (подтема 2) и длину префикса `/p` (подтема 1) считаем известными.

---

**Маску восстанавливают по битам, сравнивая адрес и адрес сети в каждой позиции.** Исходное равенство то же, N = I И M, — просто неизвестно теперь M. Разберём пример: IP `172.20.91.37`, адрес сети `172.20.80.0`. Первые два октета совпадают, сравниваем третий: 91 = `01011011`, 80 = `01010000`.

Проверяем слева. В четвёртой позиции IP и адрес сети содержат единицу — единица сохранилась, значит, четвёртый бит маски равен `1`. В пятой позиции IP содержит единицу, а адрес сети ноль — единица пропала, значит, пятый бит маски равен `0`. Маска непрерывна, поэтому первые четыре бита третьего октета маски — единицы, последние четыре — нули: 11110000₂ = 240. Полная маска — **255.255.240.0**.

Почему первые два октета — 255? Потому что единицы маски продолжаются до четвёртого бита третьего октета: до этого места нулей быть не может. Почему последний октет — 0? Потому что нули уже начались в третьем октете, и после них единицы появиться не могут.

---

**По одной позиции бит маски определён, только если в адресе стоит единица.** Все четыре случая:

| Бит IP | Бит адреса сети | Каким может быть бит маски | Причина |
|---:|---:|---|---|
| 0 | 0 | 0 или 1 | И с нулём в обоих случаях даст ноль |
| 0 | 1 | Никаким | Операция «И» не превращает исходный ноль в единицу |
| 1 | 0 | Только 0 | Исходную единицу нужно обнулить |
| 1 | 1 | Только 1 | Исходную единицу нужно сохранить |

Отсюда два важных вывода: если в IP и адресе сети стоят единицы, бит маски обязательно равен единице; если в IP единица, а в адресе сети ноль, бит маски обязательно равен нулю. Но совпадение двух нулей ничего однозначного о маске не говорит.

**Нельзя определять маску по правилу «совпало — ставим 1, не совпало — ставим 0».** Совпавшие нули могли оказаться как в сетевой, так и в узловой части. Дополнительно нужно соблюдать непрерывность маски: сначала единицы, затем нули.

---

**По одному IP-адресу и адресу сети маска может определяться неоднозначно.** Рассмотрим IP `172.20.174.93` и адрес сети `172.20.160.0`. Третий октет: 174 = `10101110`, 160 = `10100000`. Рассуждаем:

1. В третьей позиции адрес сети содержит единицу. Значит, первые три бита маски обязаны быть единицами.
2. В пятой позиции единица IP превратилась в ноль. Значит, пятый бит маски равен нулю.
3. Следовательно, пятый и все последующие биты маски — нули.
4. Четвёртая позиция содержит `0` и в IP, и в адресе сети. Здесь возможны оба значения маски.

Получаются две маски: третий октет `11100000` = 224 — маска `255.255.224.0`, и `11110000` = 240 — маска `255.255.240.0`. Обе дают нужный адрес сети. Проверим: 174 И 224 = 160; 174 И 240 = 160.

**Поэтому в задаче могут спрашивать разные величины, и для одного и того же условия ответы будут различаться.** Выбери вопрос:

:::pick Что спрашивают
- *наименьший третий октет | 224 | маска `/19`, `11100000`
- наибольший третий октет | 240 | маска `/20`, `11110000`
- меньше всего единиц | 19 | во всей маске `/19`
- больше всего единиц | 20 | во всей маске `/20`
- меньше всего нулей | 12 | 32 − 20
- больше всего нулей | 13 | 32 − 19
- меньше всего адресов | 2¹² = 4096 | самая длинная маска `/20`
- больше всего адресов | 2¹³ = 8192 | самая короткая маска `/19`
:::

**Для максимального количества адресов нужно оставить как можно больше свободных битов.** Следовательно, выбрать подходящую маску с минимальным количеством единиц. Для минимального количества адресов — наоборот.

---

**Все подходящие маски описывает одно неравенство: L ≤ p ≤ C.** Запиши IP-адрес и адрес сети ровно 32 битами. Позиции считаем слева, начиная с 1. Обозначим **L** — позицию самой правой единицы адреса сети, **C** — количество подряд совпадающих начальных битов IP-адреса и адреса сети. Тогда подходящая длина префикса удовлетворяет L ≤ p ≤ C. Почему?

- Чтобы сохранить самую правую единицу адреса сети, сетевой префикс должен доходить как минимум до неё: p ≥ L.
- Сетевой префикс не может включать место, где IP и адрес сети уже различаются: p ≤ C.

В нашем примере самая правая единица адреса сети стоит на позиции 16 + 3 = 19; первые 16 + 4 = 20 битов совпадают, следующая позиция различается. Получаем 19 ≤ p ≤ 20, то есть `/19` и `/20`.

Для полноты: если адрес сети полностью нулевой, принимаем L = 0. Если IP и адрес сети полностью совпадают, принимаем C = 32. Дополнительные ограничения условия, например требование обычного адреса узла, проверяются отдельно.

**Совпадение целого октета IP и сети не означает автоматически, что соответствующий октет маски равен 255.** Например, 192 И 192 = 192: октет сохранился, хотя маска в нём равна 192. А если исходный октет равен нулю, результат будет нулём при любом октете маски. Поэтому нулевой октет адреса сети сам по себе тоже не доказывает, что октет маски равен нулю.

---

**Если маска неизвестна, программа проверяет все возможные длины префикса.** Для IPv4 их всего 33: от 0 до 32 включительно. Маска `/0` не фиксирует ни одного бита, а `/32` фиксирует все. Поэтому перебирать нужно длины префикса, а не миллиарды произвольных 32-битных чисел.

Для каждой длины `p` ({{for|цикл for}}) программа строит сеть по адресу узла — строка `f'{address}/{p}'` подставляет число в запись ({{fstring|f-строка}}) — и сравнивает её адрес сети с заданным ({{if|условие if}}, {{eq|==}}). Чтобы пройти цикл по шагам, здесь взяты только длины от 18 до 21; в задаче перебирают все 33:

```python run masks.py
from ipaddress import ip_address, ip_network

expected = ip_address('172.20.160.0')
found = []
for p in range(18, 22):
    net = ip_network(f'172.20.174.93/{p}', strict=False)
    if net.network_address == expected:
        found.append(p)
print(found)
```

```output
[19, 20]
```

При `p = 18` адрес сети ещё 172.20.128.0, при `p = 21` — уже 172.20.168.0: граница прошла через единицу адреса, которую сеть должна была обнулить.

---

**Полная программа перебирает все 33 длины, а нужная величина берётся из списка найденных.** Для каждой подходящей маски она выводит четыре значения — длину префикса, маску, число свободных битов и количество адресов, — а после цикла наименьшую и наибольшую длину и число масок ({{agg|min и max}}):

```python
from ipaddress import ip_address, ip_network

address = '172.20.174.93'
expected = ip_address('172.20.160.0')
found = []
for p in range(33):
    net = ip_network(f'{address}/{p}', strict=False)
    if net.network_address == expected:
        found.append(p)
        print(p, net.netmask, 32 - p, net.num_addresses)
print(min(found), max(found), len(found))
```

```output
19 255.255.224.0 13 8192
20 255.255.240.0 12 4096
19 20 2
```

Наименьшее и наибольшее число единиц — `min` и `max` списка, нули — `32 - p`, сколько масок подходит — длина списка. **Эта программа находит все маски, удовлетворяющие равенству адресов сетей.** Если в задаче есть дополнительные ограничения, их тоже нужно проверить: например, отдельно может требоваться, чтобы заданный IP не был адресом сети или широковещательным адресом.

Если нужен октет маски, его извлекают из текстовой записи: `str(...)` превращает маску в текст `'255.255.224.0'`, `.split('.')` делит его по точкам, `[2]` выбирает третью часть — нумерация в Python начинается с нуля ({{listindex|индекс}}), — а `int(...)` превращает строку `'224'` в число:

```python
from ipaddress import ip_network

mask = ip_network('0.0.0.0/19').netmask
print(int(str(mask).split('.')[2]))
```

```output
224
```

Так решаются все вопросы переключателя выше: ответ — нужное значение из списка, а не первая найденная маска.

- Подходящие длины префикса: L ≤ p ≤ C — от последней единицы сети до первого различия адреса и сети.
