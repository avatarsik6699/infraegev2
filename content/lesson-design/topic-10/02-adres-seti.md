**Сеть — это все адреса от первого, где вся часть узла — нули, до последнего, где она вся из единиц.** Оба края находит программа с модулем `ipaddress`, а поразрядное «И» и блоки 256 − m позволяют проверить её вручную. Это 31 задача из 87, в том числе обе задачи основной волны ЕГЭ-2026: адрес сети и наибольший адрес, который можно назначить компьютеру.

Сначала продолжим с адресом 192.168.10.173 и маской `/26` из подтемы 1. Затем возьмём адрес 172.20.77.140 с маской `/22`: у неё граница проходит внутри третьего октета, и часть узла занимает больше одного октета.

---

**Адрес сети получают, сохраняя сетевую часть IP-адреса и заменяя всю часть узла нулями.** Для этого в условиях используют выражение **«поразрядная конъюнкция»**: разряд — позиция цифры в записи, поразрядная — действие выполняется отдельно в каждой позиции, конъюнкция — логическая операция «И».

Для двух битов операция «И» даёт единицу только тогда, когда оба бита равны единице: 0 И 0 = 0, 0 И 1 = 0, 1 И 0 = 0, 1 И 1 = 1. Для маски особенно полезны два следствия: x И 1 = x и x И 0 = 0. Иными словами, **единица маски сохраняет соответствующий бит адреса, ноль маски обнуляет его.** Именно поэтому операция «И» выделяет сетевую часть.

Обозначим I — IP-адрес, M — маску, N — адрес сети. Тогда **N = I И M**. Это действие над двоичными позициями.

---

**Найдём сеть для адреса `192.168.10.173` и маски `255.255.255.192`.** Первые три октета маски равны 255. Каждый из них состоит из восьми единиц, поэтому соответствующие октеты IP-адреса сохраняются. Нужно обработать только последний октет: 173 = `10101101`, маска 192 = `11000000`, результат «И» — `10000000` = 128. Ответ: **192.168.10.128**.

<figure class="plate-figure">
%%ip_and("192.168.10.173", 26)%%
<figcaption>Поразрядное «И» адреса 192.168.10.173 и маски /26: под единицами маски биты адреса сохраняются, под нулями становятся нулями. Получается адрес сети 192.168.10.128.</figcaption>
</figure>

В Python поразрядное «И» записывается знаком `&` ({{bitand|побитовое «И»}}). Октет с маской 255 не меняется, а последний октет даёт 128:

```python
print(168 & 255, 10 & 255, 173 & 192)
```

```output
168 10 128
```

**Адрес сети не обязан заканчиваться на `.0`.** В нашем примере он заканчивается на `.128`. Правильное правило другое: в адресе сети нулями заполнена вся часть узла. При `/26` это только последние шесть битов. Первые два бита последнего октета остаются сетевыми, поэтому весь октет может быть ненулевым.

---

**Сеть содержит все адреса от адреса сети до адреса, в котором вся часть узла — единицы.** Для `/26` последние шесть битов свободны, а первые два бита последнего октета равны `10`. Наименьшее значение получается при шести нулях: 10000000₂ = 128. Наибольшее — при шести единицах: 10111111₂ = 191. Значит, полный диапазон — 192.168.10.128 — 192.168.10.191, обе границы включены.

Количество адресов: 191 − 128 + 1 = 64. Единица добавляется потому, что учитываются и начальный, и конечный адреса. Например, чисел от 3 до 5 три: 3, 4, 5. Тот же результат через биты: 2⁶ = 64.

**Первый и последний адреса имеют особый смысл в обычной IPv4-подсети.**

- Первый — **адрес сети**: сетевая часть сохранена, часть узла состоит из нулей.
- Последний — **широковещательный адрес**: сетевая часть сохранена, часть узла состоит из единиц. Он используется для обращения ко всем узлам данной подсети.

В обычной подсети эти два адреса не назначают отдельным компьютерам. Тогда для нашего примера:

| Что требуется | Результат |
|---|---|
| Адрес сети | `192.168.10.128` |
| Широковещательный адрес | `192.168.10.191` |
| Первый обычный адрес узла | `192.168.10.129` |
| Последний обычный адрес узла | `192.168.10.190` |
| Всего адресов | 64 |
| Адресов для обычных узлов | 62 |

Отсюда получаются две разные формулы: **всего адресов 2ʰ**, а если два граничных адреса исключаются, **адресов для узлов 2ʰ − 2**.

**Вычитать два автоматически нельзя.** Сначала выясни, что именно считают: все адреса сети; адреса, допустимые для компьютеров при исключении двух специальных; адреса, удовлетворяющие дополнительному условию. В последнем случае вопрос ещё тоньше: специальные адреса могут вообще не удовлетворять условию — это разберём в подтеме 6.

У правила «минус два» есть и технические границы применения: `/31` используется для соединения двух узлов, где оба адреса могут быть адресами узлов; `/32` задаёт единственный адрес ([RFC 3021](https://www.rfc-editor.org/rfc/rfc3021.html)). Поэтому формула 2ʰ − 2 описывает обычную подсеть с исключаемыми адресом сети и широковещательным адресом, а не абсолютно любую конфигурацию.

**Модуль `ipaddress` находит адрес сети и другие характеристики сети одной функцией.** `ip_network(...)` создаёт представление сети; строка `'192.168.10.173/26'` — адрес и маска:

```python
from ipaddress import ip_network

net = ip_network('192.168.10.173/26', strict=False)

print(net.network_address)
print(net.broadcast_address)
print(net.netmask)
print(net.prefixlen)
print(net.num_addresses)
```

```output
192.168.10.128
192.168.10.191
255.255.255.192
26
64
```

Запись через точку даёт отдельную характеристику сохранённой сети:

- `net.network_address` — адрес сети;
- `net.broadcast_address` — последний, широковещательный адрес;
- `net.netmask` — маску в виде четырёх октетов;
- `net.prefixlen` — длину префикса;
- `net.num_addresses` — общее количество адресов.

Это те же 192.168.10.128, 192.168.10.191 и 64 адреса, что мы получили вручную.

**Параметр `strict=False` нужен, когда мы передаём адрес узла и хотим найти содержащую его сеть.** В примере передан `.173`, хотя адрес сети — `.128`. При обычной строгой проверке `ip_network` требует, чтобы узловые биты переданного адреса уже были нулевыми. Значение `strict=False` разрешает обнулить их при построении сети ([документация Python](https://docs.python.org/3/library/ipaddress.html)).

Маску можно задать и полностью — получится тот же ответ:

```python
from ipaddress import ip_network

net = ip_network(
    '192.168.10.173/255.255.255.192',
    strict=False
)
print(net.network_address)
```

```output
192.168.10.128
```

Если по условию дана именно предполагаемая запись **адреса сети**, её корректность иногда тоже нужно проверить. В таком случае бездумное применение `strict=False` может скрыть ошибку: программа исправит ненулевые узловые биты, хотя требовалось проверить исходную запись.

**К адресу можно прибавить число или вычесть его — получится соседний адрес.** Так находятся первый и последний обычные адреса узлов, а количество для компьютеров — вычитанием двух из `num_addresses`:

```python
from ipaddress import ip_network

net = ip_network('192.168.10.173/26', strict=False)
print(net.network_address + 1, net.broadcast_address - 1)
print(net.num_addresses, net.num_addresses - 2)
```

```output
192.168.10.129 192.168.10.190
64 62
```

**Граница может проходить внутри третьего октета, поэтому часть узла иногда занимает больше одного октета.** Рассмотрим IP `172.20.77.140` и маску `255.255.252.0`. Третий октет маски 252 = `11111100`: в нём шесть единиц и два нуля. В четвёртом октете ещё восемь нулей. Следовательно, p = 8 + 8 + 6 = 22, h = 2 + 8 = 10. Это сеть `/22`.

<figure class="plate-figure">
%%ip_bits("172.20.77.140", 22)%%
<figcaption>Адрес 172.20.77.140 и маска /22: граница проходит после шестого бита третьего октета. Часть узла — два последних бита третьего октета и весь четвёртый, 10 бит.</figcaption>
</figure>

Вычисляем третий октет адреса сети: 77 = `01001101`, маска 252 = `11111100`, результат `01001100` = 76. Четвёртый октет маски нулевой, поэтому четвёртый октет адреса сети тоже нулевой. Получаем **172.20.76.0**.

Чтобы найти последний адрес, заменяем все десять битов части узла единицами: последние два бита третьего октета становятся `11`, весь четвёртый октет — `11111111`. Третий октет 01001111₂ = 79, последний адрес — **172.20.79.255**. Количество 2¹⁰ = 1024.

Можно проверить другим способом: третий октет принимает четыре значения 76, 77, 78, 79, и для каждого из них четвёртый октет принимает 256 значений 0, 1, …, 255. Поэтому 4 · 256 = 1024, а без двух специальных адресов 1024 − 2 = 1022.

```python
from ipaddress import ip_network

net = ip_network('172.20.77.140/22', strict=False)
print(net.network_address, net.broadcast_address)
print(net.num_addresses, net.num_addresses - 2)
```

```output
172.20.76.0 172.20.79.255
1024 1022
```

**Адрес, заканчивающийся на `.0` или `.255`, не обязательно специальный.** Например, внутри этой `/22` адреса `172.20.77.0` и `172.20.76.255` — обычные адреса узлов. Почему? Часть узла занимает десять битов. Нужно рассматривать все десять, а не только последний октет. Только у `172.20.76.0` все десять равны нулю, а у `172.20.79.255` все десять равны единице.

---

**После понимания двоичного способа можно быстро находить сеть через размер блока.** Это удобная ручная проверка ответа программы. Возьмём маску `255.255.252.0`. В третьем октете свободны два младших бита. Поэтому значения третьего октета группируются блоками по 2² = 4: от 0 до 3, от 4 до 7, …, от 72 до 75, от 76 до 79, от 80 до 83. Число 77 попадает в блок от 76 до 79. Отсюда сразу видны третий октет адреса сети — 76 — и третий октет последнего адреса — 79.

<figure class="plate-figure">
%%ip_blocks(252, 77)%%
<figcaption>Октет маски 252 делит значения третьего октета на блоки по 4. Число 77 лежит в блоке 76–79: начало блока — ближайшее кратное 4, не большее 77.</figcaption>
</figure>

**Размер такого блока — d = 256 − m**, где m — значение рассматриваемого октета маски. Для 252: d = 256 − 252 = 4. Для 192: d = 256 − 192 = 64, поэтому при последнем октете маски 192 блоки такие: 0–63, 64–127, 128–191, 192–255 — и 173 из нашего первого примера лежит в блоке 128–191.

<details class="proof" markdown="1">
<summary>Почему размер блока равен 256 − m</summary>

Если свободны r младших битов, то их максимальное значение равно 2ʳ − 1. В маске эти биты нулевые, а все старшие — единицы. Поэтому значение октета маски m = 255 − (2ʳ − 1) = 256 − 2ʳ. Значит, 256 − m = 2ʳ, то есть как раз количество вариантов свободной части этого октета.

</details>

Порядок быстрого решения:

1. Найди первый слева октет маски, который меньше 255.
2. Вычисли d = 256 − m.
3. Найди ближайшее кратное d, которое не больше соответствующего октета IP.
4. Это будет октет адреса сети.
5. Все последующие октеты адреса сети заполни нулями.

Например, 77 = 19 · 4 + 1, значит, начало блока 19 · 4 = 76. Для последнего адреса блока 76 + 4 − 1 = 79, а последующие октеты последнего адреса заполняются значениями 255. В Python начало блока — `77 // 4 * 4`, то есть 76.

**Размер блока в одном октете и количество всех адресов сети могут различаться.** Для `255.255.252.0` размер блока третьего октета равен 4, но внутри него ещё полностью меняется четвёртый октет: 4 · 256 = 1024. Это частая причина ошибки.

**Ответ записывают в той форме, которую требует условие: буквами, суммой октетов или без точек.** Если в задаче ответ нужно записать буквами из таблицы, сначала полностью найди числовой адрес, а затем замени его четыре октета соответствующими буквами. Буквы записываются в порядке октетов, слева направо.

С 2025 года чаще просят сумму октетов найденного адреса или адрес без точек. Октеты получаются из текстовой записи адреса: `str(...)` превращает адрес в строку, {{split|split('.')}} делит её по точкам, а `int` превращает каждую часть в число ({{genexp|сумма по частям}}). Точки убирает `replace` ({{strmeth|метод строки}}). Наибольший адрес, который можно назначить компьютеру в нашей `/22`, — широковещательный минус один, наименьший — адрес сети плюс один:

```python
from ipaddress import ip_network

net = ip_network('172.20.77.140/22', strict=False)
last = net.broadcast_address - 1
first = net.network_address + 1
print(last, sum(int(x) for x in str(last).split('.')))
print(first, str(first).replace('.', ''))
```

```output
172.20.79.254 525
172.20.76.1 17220761
```

**Итого.**

- Адрес сети N = I И M: под единицами маски биты адреса сохраняются, под нулями обнуляются; в программе — `ip_network(…, strict=False).network_address`.
- Сеть — от адреса сети (часть узла — нули) до широковещательного (часть узла — единицы); всего 2ʰ адресов, для компьютеров обычно 2ʰ − 2.
- Наименьший и наибольший адрес компьютера — `network_address + 1` и `broadcast_address - 1`.
- Адреса `.0` и `.255` не обязательно особые: смотри на всю часть узла.
- Ручная проверка: начало блока — ближайшее кратное d = 256 − m в первом октете маски, меньшем 255.
- Ответ — в форме условия: буквы, сумма октетов, запись без точек.
