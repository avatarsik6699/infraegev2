**Когда процессов много, поиск поставщика по ID поручают функции `ВПР`: она находит строку с нужным ID и возвращает из неё момент окончания.** Это не новый тип задач, а запись уже понятного поиска из подтемы 2 — так решают таблицы экзаменного размера в десятки процессов.

Главный пример — те же восемь процессов и те же 14 мс. Формула начала станет одинаковой для всех строк, и её можно будет протянуть.

---

**`ВПР` ищет значение в первом столбце диапазона и возвращает значение из выбранного столбца той же строки.**

В обычном способе мы сами находили нужную строку и писали, например, `=E2`. Но если процессов несколько десятков, искать каждый ID глазами неудобно.

Нам нужна операция:

> Найди строку с указанным ID и возьми из неё момент окончания.

Это умеет делать **ВПР** — функция поиска значения в таблице; как она устроена, объясняет {{xl-lookup|урок о поиске по ключу}}. Её общий смысл:

```excel шаблон
=ВПР(что_ищем;где_ищем;какой_столбец_вернуть;точный_поиск)
```

Например, есть отдельная таблица:

| ID | Окончание |
|---:|---:|
| 10 | 5 |
| 20 | 8 |
| 30 | 12 |

Если она находится в A2:B4, формула `=ВПР(20;A2:B4;2;0)` даст 8.

| Аргумент | Значение |
|---|---|
| `20` | Ищем процесс с ID 20 |
| `A2:B4` | Ищем в этой таблице |
| `2` | Возвращаем значение из второго столбца диапазона |
| `0` | Нужен именно ID 20 |

Число 2 здесь означает **номер столбца внутри диапазона**, а не номер процесса. Точное совпадение обязательно: ID 19 или 21 не может заменять ID 20.

---

**Перед использованием `ВПР` список поставщиков делят на отдельные ячейки.**

В одной ячейке может находиться текст `3; 4`. ВПР должна отдельно искать ID 3 и отдельно ID 4. Поэтому подготовим такую структуру:

| A | B | C | D | E | F |
|---|---|---|---|---|---|
| ID | Длительность | Поставщик 1 | Поставщик 2 | Начало | Окончание |

В нашем примере у каждого процесса не больше двух поставщиков. Если в задаче их больше, нужно добавить столбцы поставщиков — и в формуле ещё по одному `ВПР` на каждый.

Список можно разделить средствами Excel ({{xl-csv|разделение текста по столбцам}}):

1. Выделить ячейки со списками зависимостей.
2. Открыть **Данные → Текст по столбцам**.
3. Выбрать данные с разделителями.
4. Указать разделитель **точка с запятой**.
5. Проверить предварительный просмотр.
6. Указать область, куда поместить результат.
7. Завершить разделение.

**Освободи нужные столбцы справа до разделения.** Иначе полученные значения могут занять ячейки с уже существующими данными. После разделения проверь, что ID поставщиков записаны числами и совпадают по типу с ID в основном столбце: число `3` и текст с лишними пробелами вокруг `3` могут вызвать проблемы поиска.

---

**Служебный процесс 0 с окончанием 0 позволяет одной формулой считать и независимые процессы.**

В строке 2 создадим служебную строку: ID 0, длительность 0, поставщики 0, начало и окончание — готовые нули. Настоящие процессы разместим начиная со строки 3. Пустые места в столбцах поставщиков тоже заполним числовыми нулями.

Зачем это нужно? Для процесса без поставщиков получим max(f₀; f₀) = max(0; 0) = 0. Для процесса с одним поставщиком, например 1: max(f₁; f₀) = max(f₁; 0) = f₁. Для процесса с двумя поставщиками — max(f₁; f₂). Отсутствующие поставщики больше не требуют отдельных специальных формул.

Служебный процесс 0 нельзя включать в ответ на вопрос о количестве настоящих процессов.

---

**Формула начала ищет поставщиков только в предыдущих строках — диапазоном, который растёт при протягивании.**

Сначала расположим реальные процессы в топологическом порядке: поставщики выше получателей. В `E3` вводим формулу начала, в `F3` — окончания, и протягиваем обе вниз:

```sheet ВПР select=E8 edit=B3:B10
|    | A  | B  | C           | D           | E                                                  | F
| 1  | ID | Длительность, мс | Поставщик 1 | Поставщик 2 | Начало, мс                               | Окончание, мс
| 2  | 0  | 0  | 0           | 0           | 0                                                  | 0
| 3  | 1  | 4  | 0           | 0           | =МАКС(ВПР(C3;$A$2:$F2;6;0);ВПР(D3;$A$2:$F2;6;0)) ⇒ 0 | =E3+B3 ⇒ 4
| 4  | 2  | 6  | 0           | 0           | ⇒ 0                                                | ⇒ 6
| 5  | 3  | 3  | 1           | 0           | ⇒ 4                                                | ⇒ 7
| 6  | 4  | 2  | 1           | 2           | ⇒ 6                                                | ⇒ 8
| 7  | 5  | 5  | 2           | 0           | ⇒ 6                                                | ⇒ 11
| 8  | 6  | 4  | 3           | 4           | ⇒ 8                                                | ⇒ 12
| 9  | 7  | 2  | 4           | 5           | ⇒ 11                                               | ⇒ 13
| 10 | 8  | 1  | 6           | 7           | ⇒ 13                                               | ⇒ 14
| 11 |    |    |             |             |                                                    |
| 12 |    |    |             |             | Все готовы, мс                                     | =МАКС(F3:F10) ⇒ 14
fill E3:F10
```

Что делает формула `E3`:

1. Берёт ID первого поставщика из `C3`.
2. Ищет его строку.
3. Возвращает окончание из столбца F.
4. Повторяет поиск для `D3`.
5. Выбирает самое позднее окончание.

Почему в ВПР стоит число 6? Диапазон начинается с A, и F — его шестой столбец. Если добавить столбец перед окончанием, номер возвращаемого столбца нужно будет изменить.

Выбери `E8` — начало процесса 6: рамки стоят на его поставщиках и на диапазоне `$A$2:$F7`, где идёт поиск. Значения столбцов совпадают с таблицей подтемы 2, итог — те же 14 мс.

---

**Знак `$` закрепляет начало диапазона, а конец растёт при копировании вниз.**

Диапазон `$A$2:$F2` при копировании вниз становится `$A$2:$F3`, затем `$A$2:$F4` и так далее. Начало диапазона `A2` закреплено полностью. У его конца `$F2` столбец F закреплён, а номер строки — нет ({{xl-ref|смешанные ссылки}}). Поэтому верхняя граница остаётся на строке 2, а нижняя растёт.

В текущей строке мы ищем только среди предыдущих строк, где расположены поставщики. Для процесса 3, находящегося в строке 5, формула ищет в диапазоне `$A$2:$F4`: там уже есть служебный процесс 0, процесс 1 и процесс 2.

**Почему не стоит сразу искать по всему столбцу собственных результатов.** Начала и окончания в таблице зависят друг от друга. Диапазон поиска по всей таблице усложняет эти связи и может привести к циклическим ссылкам. Понятнее организовать данные так, чтобы поставщики находились выше, а формула искала только в предыдущих строках: тогда вычисления явно идут от уже рассчитанных процессов к следующим.

Итог для восьми настоящих процессов — `=МАКС(F3:F10)`; служебную строку 2 в подсчёт количества процессов не включаем.

---

**В этом способе порядок строк важен: поставщик ниже текущей строки в диапазон предыдущих строк не попадёт.**

Если нужный поставщик находится ниже, `ВПР` не найдёт его и вернёт ошибку `#Н/Д`. Порядок данных нужно исправить до протягивания формул: сначала строки, у которых все поставщики уже выше. Сортировка по ID подходит, только если в данных зависимости всегда направлены от меньших ID к большим — в экзаменационных файлах это обычно так, но проверить нужно.

---

**Итого.**

- `ВПР(ID; диапазон; номер столбца; 0)` — точный поиск строки по ID и окончание из нужного столбца.
- Список поставщиков делят по столбцам; пустые места — нули; служебная строка 0 с окончанием 0.
- Начало = `МАКС` по `ВПР` каждого поставщика; диапазон `$A$2:$F2` растёт при протягивании и охватывает только предыдущие строки.
- Строки — в топологическом порядке; служебную строку не считают процессом.
