**Программа на Python записывает уже понятный подсчёт: рекурсия — дерево из подтемы 1 с запоминанием повторов, цикл — таблица из подтемы 2; вывод должен совпасть с ручным ответом.** Нового типа задач здесь нет: это проверка и вычисление для всех 82 основных задач, когда таблица становится длинной.

Главный пример — снова путь 2 → 12 командами «+1» и «×2» (ответ 10) и та же задача с обязательным 6 и запретом 9. Сначала читаем код на знакомых числах, потом используем его там, где таблица руками была бы долгой.

---

**В программе есть два разных числа: число на экране исполнителя и количество программ — их нельзя смешивать.**

Чтобы описать изменение числа в программе, используется {{eq|присваивание}}: вычислить новое значение и записать его вместо старого. Запись `x = x + 1` — «взять старое значение x, прибавить 1 и сохранить результат в x»; это не уравнение. `x = x * 2` — взять старое x, умножить на 2 и сохранить.

В решении задачи часто есть ещё одна переменная — количество способов. Например, `ways = ways + 3` увеличивает ранее подсчитанное количество способов на 3. Нужно всегда различать число на экране исполнителя и число программ, которые привели к нему.

---

**Рекурсия считает продолжения: f(x, y) — сколько программ ведёт из текущего x в цель y; она равна сумме по первой команде.**

Мы уже научились считать программы до каждого числа. Можно задать другой вопрос: сколько подходящих продолжений существует из текущего числа x до цели y?

Обозначим это количество f(x, y). Если из x можно перейти в x + 1 или 2x, то каждую программу-продолжение можно разделить по первой команде. Получаем:

**f(x, y) = f(x + 1, y) + f(2x, y).**

Функция справа обращается к самой себе, но уже для новых текущих чисел. Такой способ определения и вычисления функции называется {{rec|рекурсией}}. В нашем случае это буквально подсчёт дерева: чтобы узнать число успешных продолжений вершины, узнаём количества для её ветвей и складываем.

Если x > y, цель перепрыгнута и возвращаться вниз нельзя: продолжений ноль. Если x == y, мы уже на цели: один вариант закончить прямо сейчас. Эти ситуации называются базовыми случаями: в них ответ известен сразу, и они останавливают раскрытие дерева.

```python
def f(x, y):
    if x > y:
        return 0
    if x == y:
        return 1
    return f(x + 1, y) + f(x * 2, y)

print(f(2, 12))
```

```output
10
```

{{def|`def`}} задаёт функцию, `return` возвращает результат и завершает текущий вызов; {{if|`if`}} проверяет условие, `==` сравнивает, а одиночный `=` присваивает.

---

**У каждого вызова свои x и y: вызов f(2, 6) ждёт ответа f(3, 6), а потом отдельно вызывает f(4, 6).** Пройди раскрутку маленького примера по шагам:

```python run unwind.py
def f(x, y):
    if x > y:
        return 0
    if x == y:
        return 1
    return f(x + 1, y) + f(x * 2, y)

print(f(3, 6))
```

```output
2
```

Это удобно представлять как листки с одинаковым вопросом. На первом записано «сколько из 3 в 6?», на втором «сколько из 4 в 6?». Ответы на меньшие вопросы возвращаются на листок, где их запросили. Полностью для f(2, 6):

1. f(5, 6) = f(6, 6) + f(10, 6) = 1 + 0 = 1.
2. f(4, 6) = f(5, 6) + f(8, 6) = 1 + 0 = 1.
3. f(3, 6) = f(4, 6) + f(6, 6) = 1 + 1 = 2.
4. f(2, 6) = f(3, 6) + f(4, 6) = 2 + 1 = 3.

Обрати внимание: f(4, 6) встретилась дважды. Это повторный подсчёт одинакового вопроса, а не лишняя программа. Программы, которые пришли в 4 разными путями, должны обе учитываться. Но значение одинакового вопроса можно вычислить один раз и использовать повторно.

---

**Обязательные и запрещённые числа в коде — те же произведение и ноль, что в таблице.**

Для обязательного числа 6 и для обязательных 4 и 8 (функция f — та же, что выше):

```python
print(f(2, 6) * f(6, 12))
print(f(2, 4) * f(4, 8) * f(8, 12))
```

```output
6
4
```

Для запрета на 6 добавляем базовый случай, который возвращает 0 для запрещённого состояния:

```python
def g(x, y):
    if x == 6 or x > y:
        return 0
    if x == y:
        return 1
    return g(x + 1, y) + g(x * 2, y)

print(g(2, 12))
```

```output
4
```

{{andor|`or`}} — «или»: ноль возвращается, если выполнено хотя бы одно из двух условий. Проверку запрета ставим перед проверкой достижения цели. Тогда запрещённая цель даст 0. Если первой проверить `x == y`, запрещённая цель ошибочно будет принята как успешный конец.

---

**Запоминание результатов избавляет от повторного подсчёта одинаковых вопросов, но не убирает программы.**

Рекурсия раскрывает дерево и может многократно считать один и тот же вопрос. Чем больше цель, тем больше повторов. Мы можем сохранить ответ для каждой пары x и y: при следующем таком же вопросе Python возьмёт готовый результат. В Python для этого есть {{cache|`@cache`}} из модуля [functools](https://docs.python.org/3/library/functools.html#functools.cache).

Для задачи 2 → 20 через 6 без 9 полный код выглядит так:

```python
from functools import cache

@cache
def h(x, y):
    if x == 9 or x > y:
        return 0
    if x == y:
        return 1
    return h(x + 1, y) + h(x * 2, y)

print(h(2, 6) * h(6, 20))
```

```output
9
```

Можно использовать одну функцию для двух участков, потому что цель y является аргументом. Вопрос h(6, 6) отличается от вопроса h(6, 20), и ответы сохраняются отдельно.

Предположим, из 4 в 6 одна программа. Если в 4 можно прийти двумя разными путями, эта одна программа-продолжение нужна для обоих путей. Кэш возвращает число 1 дважды в двух местах суммы. Он устраняет повторное вычисление, но не устраняет повторное использование результата.

Если функция использует внешний запрет, а затем ты меняешь запрет без изменения аргументов и без очистки сохранённых ответов, ранее вычисленные значения станут неверными для новых условий. Либо определяй новую функцию для новой задачи, либо очищай сохранённые результаты командой `h.cache_clear()`, либо передавай ограничения аргументами.

**Убывающий исполнитель в коде отличается только направлением: ветка безуспешна, когда x < y.**

```python
from functools import cache

@cache
def down(x, y):
    if x < y:
        return 0
    if x == y:
        return 1
    result = down(x - 1, y)
    if x % 2 == 0:
        result += down(x // 2, y)
    return result

print(down(12, 2))
```

```output
10
```

Точное деление добавляется только для чётного числа: `x % 2 == 0` — {{intdiv|остаток}} от деления на 2 равен нулю, после этой проверки `x // 2` даёт точный результат. Если команда делит нацело любое число, условие чётности убирают — получится другой исполнитель (19 программ, подтема 5).

**Табличный цикл — та же таблица, что на бумаге: список, где номер ячейки совпадает с числом исполнителя.**

Даже с запоминанием цепочка вызовов при команде «+1» может быть очень длинной. Python ограничивает глубину вложенных вызовов, и при большой цели рекурсия завершится ошибкой `RecursionError` ([ограничение глубины](https://docs.python.org/3/library/sys.html#sys.setrecursionlimit)). Табличный вариант идёт циклом и такой цепочки не создаёт.

{{list|Список}} `[0] * (finish + 1)` создаёт finish + 1 нулевых ячеек с индексами от 0 до finish; `dp[6]` хранит количество программ, которые привели в число 6.

```python
def count_programs(start, finish, forbidden=()):
    if start > finish:
        return 0
    if start in forbidden or finish in forbidden:
        return 0

    dp = [0] * (finish + 1)
    dp[start] = 1

    for x in range(start, finish + 1):
        if x in forbidden:
            continue
        for next_x in (x + 1, x * 2):
            if next_x <= finish and next_x not in forbidden:
                dp[next_x] += dp[x]

    return dp[finish]

print(count_programs(2, 12))
print(count_programs(2, 12, (6,)))
print(count_programs(2, 6) * count_programs(6, 12))
print(count_programs(2, 6, (9,)) *
      count_programs(6, 20, (9,)))
```

```output
10
4
6
9
```

Цикл переносит количество вперёд — по исходящим переходам, как во втором способе подтемы 2. `for next_x in (x + 1, x * 2)` по очереди берёт результаты первой и второй команд; {{tuple|кортеж}} сохраняет повторения, и если обе команды дали одинаковое число, оно будет обработано дважды — что правильно. Кортеж из одного элемента записывается `(6,)` с запятой. {{continue|`continue`}} пропускает запрещённое x: способы из него дальше не распространяются.

{{augassign|`dp[next_x] += dp[x]`}} прибавляет новые способы к старым. Простое присваивание `dp[next_x] = dp[x]` уничтожило бы способы, пришедшие ранее по другим переходам.

Все команды увеличивают число. Значит, все способы, которые могли привести к x, пришли из меньших чисел, и к моменту обработки x они уже обработаны. Если начать с больших чисел, часть способов до x ещё не будет подсчитана.

**Таблицу можно заполнять и по входящим переходам — это прямой перенос ручной формулы.**

```python
start = 2
finish = 12
dp = [0] * (finish + 1)
dp[start] = 1

for n in range(start + 1, finish + 1):
    dp[n] = dp[n - 1]
    if n % 2 == 0:
        dp[n] += dp[n // 2]

print(dp[finish])
```

```output
10
```

Ячейки ниже start остаются нулевыми и автоматически дают нулевой вклад. Нельзя заменить условие делимости безусловным `dp[n // 2]`: для нечётного n это добавило бы переход от округлённого вниз числа, которое умножением на 2 не даёт n.

В Python отрицательный индекс допустим и означает обращение с конца списка: `dp[-1]` — последняя ячейка. Поэтому при формуле с n − 2 или n − 3 нужно защищаться от отрицательных индексов, если они возможны. Математическое соглашение «значения ниже старта равны нулю» язык сам не применяет.

---

**Для условной команды в цикле сначала собирают список разрешённых результатов, потом переносят количество по каждому.**

Цифра единиц числа — `x % 10`, цифра десятков — `(x // 10) % 10`. Перестановка разрешена только при t < u и даёт `x + 9 * (u - t)`:

```python
start, finish = 10, 24
dp = [0] * (finish + 1)
dp[start] = 1
for x in range(start, finish + 1):
    results = [x + 1]
    t, u = (x // 10) % 10, x % 10
    if t < u:
        results.append(x + 9 * (u - t))
    for y in results:
        if y <= finish:
            dp[y] += dp[x]
print(dp[finish])
```

```output
2
```

Столько же, сколько в ручном разборе подтемы 4: 14 команд «+1» или программа через 12 → 21.

**W(n) из таблицы и f(x, y) из рекурсии отвечают на разные вопросы — от старта до n и от x до цели.**

W(n) в ручной таблице отвечает на вопрос «сколько программ от фиксированного старта до n?». Рекурсивная f(x, y) отвечает на вопрос «сколько продолжений из x до фиксированной цели y?».

Первая формула смотрит на последнюю команду и предшественников. Вторая — на первую команду продолжения и следующие числа. Оба способа считают одни и те же полные программы, но значения промежуточных функций имеют разный смысл.

Для пути 2 → 6 мы получали W(4) = 2: из 2 в 4 две программы. При этом f(4, 6) = 1: из 4 в 6 одно продолжение. Противоречия нет, это разные участки пути. Нельзя подставлять W(4) вместо f(4, 6) просто потому, что в записи появилось одно и то же число 4.

---

**Итого.**

- Число на экране и количество программ — разные переменные.
- Рекурсия: f(x, y) — сумма по первой команде; базовые случаи — перепрыгнули цель (0) и достигли (1); запрет проверяют до достижения.
- `@cache` убирает повторное вычисление, но не повторное использование; при смене условий кэш очищают.
- Табличный цикл: список по номерам чисел, порядок обработки — по направлению команд, вклады прибавляют `+=`.
- Условная команда: список разрешённых результатов для каждого x.
- W(n) — от старта, f(x, y) — до цели; программа проверяет ручной ответ.
