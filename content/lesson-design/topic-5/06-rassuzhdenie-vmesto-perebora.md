**Когда входов слишком много, ответ находят рассуждением: формула результата или доказанный рост R сводят поиск к нескольким числам.** Перебор миллиарда входов в Python займёт много минут, а проверка двух-трёх кандидатов — мгновение. Все инструменты для этого уже есть: формулы дописывания из подтемы 2, инверсия из подтемы 3 и рост результата из подтемы 5.

Начнём с троичной замены 0 ↔ 2, а затем вернёмся к алгоритму из подтемы 2: чётному N слева `1` и справа `0`, нечётному — слева `11` и справа `1`. Функцию `to_base` из подтемы 1 считаем определённой выше в программе.

**Замена цифр иногда позволяет полностью отказаться от большого перебора.** Рассмотрим алгоритм:

1. построить троичную запись N;
2. поменять местами `0` и `2`, оставив `1` без изменений;
3. получить число M;
4. вычислить R = |N − M|.

Вертикальные черты обозначают **модуль**. Для разности двух чисел это расстояние между ними: |18 − 8| = 10, |8 − 18| = 10.

Найдём минимальное N, для которого R = 10.

Если длина троичной записи равна L, то по подтеме 3 M = 3ᴸ − 1 − N. Следовательно:

R = |N − (3ᴸ − 1 − N)| = |2N − (3ᴸ − 1)|.

Получаем уравнение |2N − (3ᴸ − 1)| = 10. Оно означает, что выражение внутри модуля равно либо 10, либо −10.

Сначала исключим длины меньше трёх. Для одно- и двухзначных троичных записей оба числа N и M лежат между 0 и 8. Их разность по модулю не может превышать 8. Значит, R = 10 при таких длинах невозможен.

Для L = 3: 3³ − 1 = 26. Поэтому |2N − 26| = 10. Первый случай: 2N − 26 = 10, 2N = 36, N = 18. Второй: 2N − 26 = −10, 2N = 16, N = 8.

Но при L = 3 исходное число должно удовлетворять 9 ≤ N ≤ 26. Поэтому 8 к этому случаю не относится. Остаётся 18: 18 = 200₃, после замены 200 → 022, 022₃ = 8, |18 − 8| = 10.

Числа с четырьмя и более троичными цифрами начинаются с 27, поэтому меньшего входа среди них быть не может. Ответ: **18**.

Здесь одновременно понадобились смысл замены цифр, формула для её результата, длина записи и проверка найденного числа на принадлежность нужному диапазону.

Дополнительное наблюдение: для этого алгоритма R всегда чётно, потому что и 2N, и 3ᴸ − 1 чётные. Если бы требовалось получить нечётное R, можно было бы сразу доказать невозможность.

Тот же ответ даёт перебор — им удобно проверить рассуждение. А когда R задано большим, перебор доходит до миллионов входов, и формула остаётся единственным быстрым способом:

```python
def swap02(n):
    s = to_base(n, 3)
    m = ''
    for digit in s:
        m = m + str(2 - int(digit))
    return abs(n - int(m, 3))


for n in range(1, 100):
    if swap02(n) == 10:
        print(n)
        break
```

```output
18
```

**Если внутри ветви R растёт вместе с N, наибольший результат даёт наибольший вход этой ветви.** Вернёмся к алгоритму из подтемы 2 и спросим: какое наибольшее R получается при N ≤ 10⁹? Перебирать миллиард входов не нужно.

Запишем результат формулой. Пусть у записи N длина L. Чётному N справа дописывают одну цифру — старая запись удваивается, а единица слева встаёт над L + 1 разрядами: R = 2ᴸ⁺¹ + 2N. Нечётному слева дописывают `11`, то есть 3, тоже над L + 1 разрядами, а справа единицу: R = 3 · 2ᴸ⁺¹ + 2N + 1.

Внутри одной длины L обе формулы растут вместе с N, а нечётная ветвь всегда больше чётной: её левый блок втрое тяжелее. Длинные записи дают больше, чем короткие, потому что их левый блок стоит над старшими разрядами. Значит, лучший вход — наибольшее нечётное N ≤ 10⁹, то есть 999 999 999. Его запись имеет 30 цифр, как и у самого 10⁹, поскольку 2²⁹ ≤ 10⁹ < 2³⁰.

```python
def transform(n):
    s = bin(n)[2:]
    if n % 2 == 0:
        s = '1' + s + '0'
    else:
        s = '11' + s + '1'
    return int(s, 2)


print(transform(999_999_999), transform(10 ** 9))
near = range(10 ** 9 - 1000, 10 ** 9 + 1)
print(max(transform(n) for n in near))
```

```output
8442450943 4147483648
8442450943
```

Последняя строка — проверка рассуждения на тысяче входов у верхней границы: среди них лучший действительно 999 999 999. Запись `999_999_999` — то же число, подчёркивания Python разрешает для удобства чтения.

**Где это не работает.** Рассуждение держится на двух фактах: ветви сохраняют исходную запись, а длина дописанных блоков в ветви постоянна. Если ветвь заменяет цифры или дописывает запись вычисленного числа разной длины, рост внутри ветви нужно доказывать заново или делить ветвь дальше.

---

**Количество результатов на огромном отрезке считают по крайним входам.** Пусть справа всегда дописываются три цифры — копия трёх последних цифр двоичной записи (N ≥ 4). Тогда R = 8N + (N mod 8). По подтеме 5 такой результат строго растёт вместе с N: разные входы дают разные результаты, а подходящие входы для отрезка [A; B] идут подряд.

Поэтому достаточно найти наименьший вход с R ≥ A и наибольший вход с R ≤ B. Оба лежат рядом с A / 8 и B / 8: R отличается от 8N меньше чем на 8. Начнём чуть левее и сдвинемся на несколько шагов — по шагам видно, что циклам `while` хватает одного-двух повторов.

```python run copy3.py
def copy3(n):
    s = bin(n)[2:]
    return int(s + s[-3:], 2)


a, b = 10 ** 6, 2 * 10 ** 6
lo = a // 8 - 1
while copy3(lo) < a:
    lo = lo + 1
hi = b // 8 + 1
while copy3(hi) > b:
    hi = hi - 1
print(lo, hi, hi - lo + 1)
```

```output
125000 250000 125001
```

Входы от 125 000 до 250 000 дают 125 001 различный результат на отрезке. Программа сделала несколько шагов вместо миллиона.

Без доказанного роста этот способ неверен: если результаты разных N перемешаны или совпадают, между крайними входами могут оказаться входы с R вне отрезка, а одно R может получиться дважды.

---

**Итого.**

- Замена d → q − 1 − d даёт формулу R через N и длину записи; уравнение решают по длинам и проверяют, что корень имеет нужную длину.
- Если ветви сохраняют запись и дописывают блоки постоянной длины, внутри ветви R растёт вместе с N: лучший результат — у крайнего входа ветви.
- Когда R строго растёт вместе с N, результаты на отрезке [A; B] дают подряд идущие входы; их считают по двум крайним.
- Рассуждение проверяют перебором на маленьких числах или у границы диапазона.
