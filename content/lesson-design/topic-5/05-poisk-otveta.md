**Найти минимальное N, дающее подходящий результат, и найти N, дающее минимальный подходящий результат, — разные задачи.** Половина задач подборок (35 из 69) спрашивает о лучшем результате или о входе, который его даёт, ещё 11 — о входе по заданному результату. Сам алгоритм в них переводится в код буквально; ошибаются в другом — в том, что именно искать, где остановиться и докуда перебирать.

Будем искать ответы для алгоритмов, которые уже встречались в прошлых подтемах: дописывание блоков по чётности N, дважды дописанный остаток суммы цифр, троичный алгоритм с копией двух цифр. Функцию `to_base` из подтемы 1 считаем определённой выше в программе.

**Поиск ответа начинается с вопроса: что именно нужно минимизировать или максимизировать?** В задании могут попросить разные вещи. Проверка во всех случаях — буквальный перевод условия, а выбирают и выводят разное. Выберите формулировку:

:::pick Формулировка вопроса и что выбираем
- *наименьшее N, для которого R > T | проверяем R > T | выбираем минимальное N
- наибольшее N, для которого R ≤ T | проверяем R ≤ T | выбираем максимальное N
- наименьшее возможное R > T | проверяем R > T | выбираем минимальное R
- наибольшее возможное R ≤ T | проверяем R ≤ T | выбираем максимальное R
- N, при котором R минимально среди R > T | проверяем R > T | сначала минимизируем R, затем выводим соответствующее N
:::

Последний вариант особенно важен. Рассмотрим учебный алгоритм: если N чётное, справа дописать `111`; если нечётное — дописать `0`. По подтеме 2 это R = 8N + 7 для чётного N и R = 2N для нечётного.

best_n = 0

**Останавливать перебор на первом подходящем числе можно только с понятным обоснованием.** Команда {{break|`break`}} завершает ближайший цикл. Если мы перебираем N = 1, 2, 3, … и ищем **минимальное N**, то первый подходящий вариант действительно минимален: все меньшие уже проверены. Зависимость R от N при этом может быть любой.

Но если ищем **минимальное R**, первый подходящий вход не обязательно даст лучший результат. Это показал предыдущий пример.

Есть важный случай, когда остановка допустима и для минимального результата. Пусть исходная запись N полностью сохраняется, справа всегда дописывается одно и то же количество k цифр, основание q фиксировано. Тогда R = N · qᵏ + A, где 0 ≤ A ≤ qᵏ − 1. Посмотрим, где лежат результаты соседних N при k = 2 в двоичной системе:

<figure class="plate-figure">

<figcaption>При дописывании двух двоичных цифр результат для N лежит в блоке от 4N до 4N + 3. Блок N = 5 — числа 20…23, блок N = 6 начинается с 24. Блоки не перекрываются, поэтому больший вход всегда даёт больший результат.</figcaption>

Для N результаты находятся в блоке 4N, 4N + 1, 4N + 2, 4N + 3. Для следующего числа начинается следующий блок: 4N + 4, … Они не перекрываются. Следовательно, **при таком преобразовании результат строго растёт вместе с N** — даже если дописываемые цифры выбираются по сложному условию.

<details class="proof" markdown="1">
<summary>Доказательство для любого основания q и любого k</summary>

Для данного N: N · qᵏ ≤ R ≤ N · qᵏ + qᵏ − 1.

А для следующего числа N + 1 результат не меньше (N + 1) · qᵏ = N · qᵏ + qᵏ. Это уже больше максимума для предыдущего N. Значит, любой результат входа N + 1 больше любого результата входа N.

</details>

**Если длина дописываемого блока меняется или исходные цифры заменяются, это доказательство уже неприменимо.**

---

**Границы перебора должны следовать из задачи, а не из привычки писать `range(1, 1000)`.** Перебор — последовательная проверка всех кандидатов из выбранного диапазона. Он даёт обоснованный ответ, если выполнены два условия:

1. каждый кандидат обрабатывается точно по алгоритму;
2. все кандидаты, способные повлиять на ответ, входят в диапазон.

Пусть справа всегда дописывают k цифр в системе с основанием q. Тогда R = N · qᵏ + A ≥ N · qᵏ. Если требуется R ≤ T, то обязательно N · qᵏ ≤ T. Следовательно:

**N ≤ ⌊T / qᵏ⌋.**

Например, справа дописывают две троичные цифры и требуют R ≤ 300: 9N ≤ 300, N ≤ 33. Больше 33 проверять не требуется.

Если количество дописываемых цифр меняется, но их всегда **не меньше двух**, то оценка R ≥ 9N по-прежнему верна.

Другой полезный случай: алгоритм только дописывает цифры, сохраняя исходную запись. Тогда R ≥ N. Пусть ищем минимальное подходящее R и уже нашли какой-то результат R₀. Любой результат лучше него будет не больше R₀. Значит, для такого результата N ≤ R ≤ R₀. Поэтому все входы N > R₀ можно исключить. Это даёт строгую границу даже без знания окончательного ответа.

При удалении цифр, инверсии или замене начала записи неравенство R ≥ N может быть неверным. Его нельзя использовать автоматически.

---

**Теперь полностью решим задачу с двумя последовательными проверками суммы цифр.** Учебное условие:

1. получить двоичную запись N;
2. справа дописать остаток от деления суммы её цифр на 2;
3. повторить действие для новой записи;
4. найти минимальное N, для которого R > 100.

Мы уже вывели в подтеме 4: R = 4N или R = 4N + 2. Следовательно, R ≤ 4N + 2. Если N ≤ 24, то R ≤ 4 · 24 + 2 = 98. Поэтому все N ≤ 24 точно не подходят.

Проверим 25: 25₁₀ = 11001₂. В записи три единицы — нечётное количество. Значит, дописывается `10`: 11001 → 1100110, R = 4 · 25 + 2 = 102. Условие выполнено: 102 > 100. Следовательно, **N_min = 25**. Здесь мы не просто нашли подходящее число, но и доказали, что меньших нет.

Программа, буквально повторяющая условие:

```python
def transform_binary(n):
    s = bin(n)[2:]

    remainder = s.count('1') % 2
    s = s + str(remainder)

    remainder = s.count('1') % 2
    s = s + str(remainder)

    return int(s, 2)


for n in range(1, 27):
    r = transform_binary(n)

    if r > 100:
        print(n)
        break
```

```output
25
```

`range(1, 27)` задаёт числа от 1 до 26 включительно: правая граница в {{for|`range`}} не входит. Почему диапазона достаточно? При N = 26: R ≥ 4 · 26 = 104 > 100. То есть хотя бы один подходящий вход гарантированно встретится не позднее 26.

Если бы вопрос был о минимальном R > 100, ответом было бы 102. Здесь это следует и из доказанного роста R вместе с N: справа всегда дописываются ровно две цифры.

**При решении по отдельным ветвям условие ветви нужно сохранять до конца.** Учебный алгоритм: если N чётное, справа дописывается `10`; если нечётное — `01`. Найти минимальное N, для которого R > 150.

Переводим действия в формулы: R = 4N + 2 для чётного N, R = 4N + 1 для нечётного.

Рассмотрим чётные N: 4N + 2 > 150, 4N > 148, N > 37. Минимальное чётное число, большее 37, — это 38. Проверка: R = 4 · 38 + 2 = 154.

Теперь нечётные N: 4N + 1 > 150, 4N > 149, N > 37,25. Первое целое число после 37,25 — это 38. **Но оно чётное и к этой ветви не относится.** Первое подходящее нечётное число — 39. Проверка: R = 4 · 39 + 1 = 157.

Сравниваем найденные входы: min(38, 39) = 38. Ответ: **38**.

Так же нужно поступать с ветвями вида «N кратно 3», «остаток от деления N на 5 равен 2», «в записи чётное количество единиц», «сумма цифр делится на 3». Полученное из неравенства число обязательно проверяется на принадлежность рассматриваемой ветви.

---

**Иногда удобнее идти от результата обратно к исходному числу.** Предположим, известно, что алгоритм сохраняет исходную запись и дописывает две двоичные цифры. Тогда R = 4N + A, 0 ≤ A ≤ 3. Отсюда N = R // 4, A = R mod 4. То есть исходное число получаем удалением последних двух двоичных цифр, а дописанный блок — это последние две цифры.

Возьмём алгоритм с двумя последовательными проверками суммы цифр и проверим, может ли он выдать R = 100. 100 = 1100100₂. Разделяем запись: `11001 | 00`. Предполагаемый вход 11001₂ = 25. У числа 25 три единицы. Значит, по алгоритму нужно дописать `10`, а не `00`. Следовательно, 100 получить нельзя.

Проверим 102 = 1100110₂. Разделяем: `11001 | 10`. Вход снова равен 25, хвост правильный. Значит, 102 получить можно.

**Удаление хвоста находит предполагаемый вход. Затем всё равно нужно проверить, что алгоритм действительно создаёт именно такой хвост.** Одного подходящего окончания результата недостаточно: оно должно согласовываться с исходной частью.

---

**Если задан результат, программа ищет вход проверкой равенства, а различные результаты собирает множество.** Обратный ход удобен руками, но программе проще пройти по входам и сравнить результат с заданным. Граница перебора берётся из того же рассуждения: алгоритм только дописывает цифры, значит R ≥ N, и входы больше R проверять не нужно.

Когда спрашивают количество **различных результатов**, одинаковые значения R, полученные от разных входов, учитывают один раз. Их удобно складывать в {{set|множество}}: оно хранит значения без повторов.

```python
results = set()
for n in range(1, 103):
    r = transform_binary(n)
    results.add(r)
    if r == 102:
        print(n)

print(100 in results, len(results))
```

```output
25
False 102
```

Вход для 102 — это 25; число 100 не получается ни из одного входа. Различных результатов 102 — столько же, сколько входов: при дописывании ровно двух цифр разные N дают разные R. Для алгоритма, который отбрасывает цифры, это уже не так.

**Разберём троичный алгоритм, в котором длина дописываемого блока меняется.** Учебное условие:

1. построить троичную запись N;
2. если N делится на 3, дописать справа две последние цифры этой записи;
3. иначе остаток от деления N на 3 умножить на 7, перевести произведение в троичную систему и дописать справа;
4. найти максимальное R, не превышающее 300.

Разделим все входы по остатку от деления на 3. Если остаток равен 0, дописываются две последние цифры: R = 9N + (N mod 9). Если остаток равен 1: 1 · 7 = 7 = 21₃, дописали две цифры, R = 9N + 7. Если остаток равен 2: 2 · 7 = 14 = 112₃, дописали уже три цифры, R = 27N + 14.

Например, N = 2 даёт R = 68, а N = 3 — R = 30. Результат уменьшился при увеличении входа. Поэтому нельзя остановиться, впервые получив значение больше 300, и считать дальнейший поиск бесполезным.

Но можно строго ограничить входы. Во всех ветвях дописывается не меньше двух троичных цифр: R ≥ 9N. При R ≤ 300 получаем N ≤ 33.

Программа перебирает N от 1 до 33 и запоминает наибольший подходящий результат; она использует функцию `to_base`:

```python
def transform_ternary(n):
    s = to_base(n, 3)

    if n % 3 == 0:
        s = s + s[-2:]
    else:
        extra = (n % 3) * 7
        s = s + to_base(extra, 3)

    return int(s, 3)


best_r = -1

for n in range(1, 34):
    r = transform_ternary(n)

    if r <= 300:
        if r > best_r:
            best_r = r

print(best_r)
```

```output
286
```

`best_r` хранит лучший результат среди уже проверенных. Начальное значение `-1` выбрано потому, что все возможные результаты неотрицательны. Поэтому первый подходящий результат окажется больше него. Мы сравниваем именно `r`, поскольку вопрос требует максимальное **выходное число**.

<details class="proof" markdown="1">
<summary>Тот же ответ без программы: разбор по ветвям</summary>

Найдём лучший вариант в каждой ветви и сравним их. Для остатка 0 кандидаты около верхней границы — 30 и 33: N = 33 даёт R = 9 · 33 + 6 = 303 — не подходит; N = 30 даёт R = 9 · 30 + 3 = 273. При меньших положительных кратных 3, то есть N ≤ 27, R ≤ 9 · 27 + 6 = 249. Значит, лучший результат этой ветви — 273.

Для остатка 1: 9N + 7 ≤ 300, N ≤ 32,55… Наибольшее целое с остатком 1 при делении на 3 — это 31: R = 9 · 31 + 7 = 286.

Для остатка 2: 27N + 14 ≤ 300, N ≤ 10,59… Наибольшее подходящее N с остатком 2 — это 8: R = 27 · 8 + 14 = 230.

Сравниваем: max(273, 286, 230) = 286. Ответ: **286**.

</details>

**При поиске входа, дающего минимальный результат, нужно сохранять сразу оба числа.** Рассмотрим более сложный учебный алгоритм:

1. N ≥ 8;
2. строится восьмеричная запись;
3. если N делится на 3, справа копируются последние две цифры;
4. иначе остаток от деления N на 3 умножается на 5, и восьмеричная запись произведения приписывается слева.

Требуется найти **такое N, при котором R минимально среди результатов, превышающих 350**.

Посмотрим на несколько входов. При N = 8: 8 = 10₈. Остаток от деления на 3 равен 2: 2 · 5 = 10₁₀ = 12₈. Приписываем слева: `12` + `10` = `1210`, R = 1210₈ = 648. Это уже подходящий результат, но он необязательно минимальный.

При N = 10: 10 = 12₈. Остаток равен 1, поэтому слева дописывается `5`: 512₈ = 330. Этот результат не превышает 350.

При N = 31: 31 = 37₈, остаток равен 1: 537₈ = 351. Получен результат 351. Он минимален среди всех целых чисел, строго больших 350, потому что между 350 и 351 других целых чисел нет. Следовательно, **N = 31**.

Обрати внимание: первый проверенный вход N = 8 уже давал R > 350, но ответом был другой вход.

```python
def transform_octal(n):
    s = oct(n)[2:]

    if n % 3 == 0:
        s = s + s[-2:]
    else:
        extra = (n % 3) * 5
        s = oct(extra)[2:] + s

    return int(s, 8)


best_n = 8
best_r = transform_octal(8)

upper = best_r

for n in range(9, upper + 1):
    r = transform_octal(n)

    if r > 350:
        if r < best_r:
            best_r = r
            best_n = n

print(best_n, best_r)
```

```output
31 351
```

Почему можно закончить на 648? Алгоритм только дописывает цифры, поэтому R ≥ N. Уже найден подходящий результат 648. Для его улучшения нужно получить R < 648, а при N > 648 это невозможно.

Здесь переменные имеют разные роли: `best_r` — минимальный найденный подходящий результат, `best_n` — вход, на котором этот результат получен.

Если условие допускает несколько входов с одинаковым лучшим результатом и задаёт дополнительное правило выбора, например минимальное N, это правило тоже нужно учитывать.

---

**Итого.**

- Сначала выпиши, что ищем: наименьшее или наибольшее N, лучший R или вход для лучшего R.
- На первом подходящем N можно остановиться, только если ищем минимальное N или доказано, что R растёт вместе с N (справа всегда ровно k цифр).
- Границу перебора выводят из преобразования: R ≥ N · qᵏ даёт N ≤ T / qᵏ, а R ≥ N ограничивает поиск найденным результатом.
- По ветвям: решение неравенства проверяют на принадлежность ветви, затем сравнивают ветви.
- Для лучшего результата хранят и результат, и вход; заданный R ищут проверкой равенства, различные результаты — множеством.

3. Для N = 14 примени троичный алгоритм: при кратности 3 скопировать последние две цифры, иначе дописать троичную запись числа 7 · (N mod 3). Найди R.
4. Для алгоритма «чётному N дописать справа `111`, нечётному — `0`» найди наименьший результат R > 30 и вход, при котором он получается.
5. Алгоритм всегда дописывает справа ровно три двоичные цифры. Какие N достаточно проверить, чтобы найти наибольшее R ≤ 500?
6. Почему в задаче 1 можно остановиться на первом N с R > 100, даже если спросят наименьший R > 100, а в задаче 4 — нельзя?
7. На вход алгоритма подаётся натуральное число N > 1. Строится двоичная запись N. Если N делится на 3, справа к ней дописываются две её последние цифры; иначе остаток от деления N на 3 умножается на 3, и двоичная запись произведения дописывается слева. Полученная запись — двоичная запись числа R. Укажите наибольшее R, не превышающее 200.
8. На вход алгоритма подаётся натуральное число N. Строится троичная запись N. Если сумма её цифр чётная, справа дописывается `1`; иначе слева дописывается `2`. Полученная запись — троичная запись числа R. Укажите такое N, при котором R — наименьшее среди чисел, больших 1000.
9. Двоичная запись N переворачивается, ведущие нули отбрасываются, получившаяся запись — двоичная запись числа R. Сколько различных значений R получается при N от 1 до 100?

**Ответы для проверки:**

1. N = 25: для нечётного 25 получается 4 · 25 + 1 = 101; для чётных нужно N ≥ 26.
2. Нет: предполагаемый вход 25 требует хвост `10`, а у 100 хвост `00`.
3. 392: 14 = 112₃, дописываем `112`; 14 · 27 + 14 = 392.
4. R = 34 при N = 17: нечётные дают 2N, чётное N = 2 даёт только 23, а чётные N ≥ 4 — не меньше 8 · 4 + 7 = 39.
5. N от 1 до 62: R ≥ 8N, значит 8N ≤ 500 и N ≤ 62.
6. В задаче 1 справа всегда ровно две цифры — R растёт вместе с N. В задаче 4 блоки разной длины: N = 4 даёт 39, а N = 17 — только 34.
7. 192 при N = 48: 110000₂ → `11000000`₂. Дописывание не убирает цифр, поэтому R ≥ N и хватает N ≤ 200.
8. 334: 334 = 110101₃, сумма цифр 4, R = 1101011₃ = 1003. R ≥ N, поэтому входы больше 1003 проверять не нужно.
9. 50: у чётного N в конце записи ноль, после переворота он становится ведущим и отбрасывается — 2N даёт тот же R, что и N.
