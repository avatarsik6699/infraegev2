**Чётность числа и чётность суммы его цифр — разные условия.** Почти треть задач подборок (22 из 69) выбирает дописываемую цифру по сумме цифр записи или по количеству единиц и нулей, ещё 6 смотрят на цифры десятичной записи. Ошибка здесь почти всегда одна: проверили не ту величину или не ту версию записи.

Сквозной пример снова 13 = 1101₂: сумма его двоичных цифр равна 3, а само число нечётное. Функцию `to_base` из подтемы 1 считаем определённой выше в программе.

---

**Чётность самого числа видна по последней двоичной цифре, а сумма цифр зависит от всей записи.** Чётное число делится на 2 без остатка. Для двоичной записи чётность самого числа определяется последней цифрой: `0` — число чётное, `1` — нечётное.

Причина видна из формулы N = 2Q + d. Число 2Q чётное, поэтому остаток при делении N на 2 определяется последней цифрой d.

Но сумма двоичных цифр зависит от **всей записи**:

| N | Двоичная запись | Чётность N | Сумма двоичных цифр |
|---:|---|---|---:|
| 3 | `11` | Нечётное | 2 — чётная |
| 8 | `1000` | Чётное | 1 — нечётная |
| 6 | `110` | Чётное | 2 — чётная |
| 7 | `111` | Нечётное | 3 — нечётная |

Из таблицы видно: эти свойства могут совпадать, а могут различаться.

В двоичной записи сумма цифр равна количеству единиц: 1 + 1 + 0 + 1 = 3. Нули ничего не добавляют, каждая единица добавляет 1. Поэтому условия «сумма двоичных цифр чётная» и «количество единиц в двоичной записи чётное» равносильны. Но они не равносильны условию «N чётное».

**При чтении условия каждый раз уточняй, чётность чего проверяют: числа, количества единиц, суммы цифр или длины записи.**

---

**В других системах счисления нужно заново учитывать смысл цифр.** В троичной записи `212` количество единиц — 1, количество двоек — 2, а сумма цифр 2 + 1 + 2 = 5. Поэтому считать только единицы уже недостаточно. Сумму троичных цифр можно получить так: количество единиц + 2 · количество двоек.

Также нельзя автоматически переносить привычные признаки делимости из десятичной системы. Например, 3₁₀ = 10₃: само число делится на 3, но сумма цифр его троичной записи равна 1 и на 3 не делится. И наоборот, 5₁₀ = 12₃: сумма троичных цифр равна 3, но число 5 на 3 не делится.

В системе с основанием 3 делимость самого числа на 3 определяется **последней цифрой**, поскольку N = 3Q + d.

Для чётности в троичной системе есть другая полезная связь: все степени тройки нечётные. Поэтому чётность числа совпадает с чётностью суммы его троичных цифр. Например, 11₃ = 4: последняя цифра — `1`, но число чётное, поскольку сумма цифр 1 + 1 = 2.

Отсюда полезное правило: в системе с чётным основанием чётность числа определяется последней цифрой, в системе с нечётным основанием — чётностью суммы цифр. Для задания чаще достаточно вычислить нужную величину непосредственно, но понимание этой связи помогает проверять себя.

---

**Сумму цифр нужно вычислять по той записи, которую указывает условие.** Для двоичной строки `s.count('1')` — одновременно количество единиц и сумма цифр. Для троичной строки — `s.count('1') + 2 * s.count('2')`. Более общий вариант для систем с цифрами `0`–`9` проходит по строке циклом {{for|`for digit in s`}}: он по очереди подставляет в переменную `digit` каждый символ строки.

```python
s = to_base(23, 3)
print(s, s.count('1') + 2 * s.count('2'))

total = 0
for digit in s:
    total = total + int(digit)
print(total)
```

```output
212 5
5
```

Здесь 23 = 212₃. Цикл прибавляет 2, затем 1, затем 2. Преобразование `int(digit)` нужно потому, что символ `'2'` — текст, а для сложения требуется число 2.

Если запись содержит буквенные цифры, например шестнадцатеричные, значение одного символа можно получить через `int(digit, q)`.

**Повторный шаг обычно применяется к записи, полученной на предыдущем шаге.** Рассмотрим важный алгоритм:

1. строится двоичная запись N;
2. вычисляется сумма её цифр;
3. остаток от деления суммы на 2 дописывается справа;
4. для получившейся записи то же действие выполняется ещё раз.

Возьмём N = 13, s = `1101`. Первая сумма 1 + 1 + 0 + 1 = 3. Остаток от деления 3 на 2 равен 1: `1101 → 11011`. Теперь считаем сумму **новой** записи: 1 + 1 + 0 + 1 + 1 = 4. Остаток равен 0: `11011 → 110110`. Получаем R = 110110₂ = 54.

Почему второй дописанный разряд всегда равен нулю? Возможны два случая. Если единиц было чётное количество, первым дописывается 0 и количество остаётся чётным. Если нечётное, первым дописывается 1 и количество становится чётным. В обоих случаях перед вторым шагом единиц чётное количество, и второй разряд — 0.

Следовательно, итоговый хвост — `00`, если исходное количество единиц чётное, и `10`, если нечётное. Отсюда:

**R = 4N**, если количество единиц чётное; **R = 4N + 2**, если нечётное.

Это свойство именно **последовательного пересчёта**. Если алгоритм говорит «найти остаток один раз и дописать его дважды», результаты другие: `00` или `11`. Различие всего в нескольких словах условия, а числа на выходе меняются. Запусти обе версии по шагам и сравни, сколько раз считается `count`:

```python run parity.py
def parity_twice(n):
    s = bin(n)[2:]
    s = s + str(s.count('1') % 2)
    s = s + str(s.count('1') % 2)
    return int(s, 2)


def parity_copied(n):
    s = bin(n)[2:]
    bit = str(s.count('1') % 2)
    return int(s + bit + bit, 2)


print(parity_twice(13), parity_copied(13))
```

```output
54 55
```

В `parity_twice` второй `count` считает единицы уже новой строки — это и есть пересчёт. В `parity_copied` остаток посчитан один раз, поэтому к 13 дописывается `11`, и R = 4 · 13 + 3 = 55.

**Десятичную запись обрабатывают так же, как двоичную, — через строку.** Сумма десятичных цифр числа — это сумма цифр строки `str(n)`. В задачах с десятичной записью могут рассматриваться и все соседние пары или тройки цифр.

Пусть N = 30042. Все тройки соседних цифр: `300`, `004`, `042`. Они перекрываются: после каждой тройки начало сдвигается на одну позицию. Как числа это 300, 4, 42. Если результат — разность максимального и минимального значения, R = 300 − 4 = 296. В программе по шагам видно, как `i` пробегает начала троек, а список `values` пополняется:

```python run windows.py
def transform_windows(n):
    s = str(n)
    values = []

    for i in range(len(s) - 2):
        part = s[i:i + 3]
        values.append(int(part))

    return max(values) - min(values)


print(transform_windows(30042))
```

```output
296
```

Здесь `values = []` создаёт пустой {{list|список}}, `append` добавляет в его конец новое значение, а {{agg|`max` и `min`}} находят наибольшее и наименьшее. Функция предполагает, что в записи не меньше трёх цифр.

Почему `range(len(s) - 2)`? При длине 5 тройка может начинаться с индекса 0, 1 или 2. Начать с индекса 3 нельзя: останется только два символа. В общем случае для фрагментов длины k число возможных начал равно L − k + 1. Поэтому используют `range(len(s) - k + 1)`.

**Перед числовым сравнением фрагменты нужно превратить в числа.** Например, строки `'11'` и `'100'` сравниваются посимвольно. Это не то же самое, что сравнение чисел 11 и 100 или двоичных чисел 11₂ и 100₂.

---

**Итого.**

- Чётность числа и чётность суммы его цифр — разные проверки; в двоичной записи сумма цифр — количество единиц, `s.count('1')`.
- В троичной записи сумма цифр учитывает двойки; чётность числа там совпадает с чётностью суммы цифр, а делимость на 3 видна по последней цифре.
- Повторный шаг считает сумму по новой записи: дважды дописанный остаток суммы на 2 даёт хвост `00` или `10`, то есть R = 4N или 4N + 2.
- Десятичные цифры и соседние фрагменты берут из `str(n)` и переводят в числа перед сравнением.
