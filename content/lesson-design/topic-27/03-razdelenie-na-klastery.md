**Чтобы разделить точки на кластеры, сначала смотрят на их расположение, а потом записывают правило, которое однозначно относит каждую точку к одной группе.** В 47 задачах из 50 таким правилом служат координатные границы, найденные по рисунку; в семи, в том числе в демоверсии 2026 года, часть точек — аномалии, которые не входят ни в один кластер; в трёх, в том числе в демоверсии 2027 года, группы разделяет не координата, а вычисленная величина.

Точки файла `example27.txt` и функция `read_points` из подтемы 2 — наш первый пример; функцию считаем определённой выше в программе.

**Чтобы понять, как разделять точки, полезно сначала увидеть их расположение.** Такой рисунок называется **диаграммой рассеяния**: каждой записи файла соответствует отдельная точка.

В табличном редакторе для этого выбирают два столбца координат и строят **точечную диаграмму XY**. Нужна именно диаграмма по координатам, а не обычный линейный график, который может располагать записи по их порядковым номерам. Для построения такого рисунка не нужно соединять точки линиями в порядке их появления в файле: порядок строк обычно ничего не говорит о соседстве точек.

Одинаковый масштаб важен: иначе круг может выглядеть вытянутым эллипсом, а расстояния по горизонтали и вертикали будут восприниматься неправильно.

**Строй рисунок по самому файлу.** Картинка в условии может быть только иллюстрацией и не соответствовать данным задания — такое предупреждение прямо встречается в условиях подборки.

После построения рисунка спроси себя:

- Сколько отчётливых групп видно?
- Есть ли между ними пустые полосы?
- Можно ли провести разделяющую прямую?
- Есть ли отдельно стоящие точки?
- Похожи ли группы на компактные облака, дуги, кольца или вытянутые цепочки?

Ответы определят способ кластеризации.

**Самый простой способ разделения — использовать координатные границы.** На рисунке все точки одной группы находятся левее `x = 5`, а все точки другой — правее. Тогда:

```python
points = read_points("example27.txt", has_header=True)

for point in points:
    x, y = point

    if x < 5:
        clusters[0].append(point)
    else:
        clusters[1].append(point)

print(len(clusters[0]), len(clusters[1]))
print(clusters[1])
```

**Если групп три, условия комбинируют цепочкой `if / elif / else`, и порядок проверок существенен.** {{if|`elif`}} означает «иначе, если». Например:

1. Сначала выделяется нижняя группа: `y < 3`.
2. Среди оставшихся точек выделяется левая: `x < 5`.
3. Всё остальное попадает в третью.

```python run regions.py
for x, y in [(2, 1), (3, 6), (8, 7)]:
    if y < 3:
        clusters[0].append((x, y))
    elif x < 5:
        clusters[1].append((x, y))
```


Для `(2, 1)` проверка в строке 4 истинна, и до строки 6 дело не доходит. Такой код допустим только тогда, когда рисунок и данные действительно соответствуют этим условиям.

**Почему часто удобнее `if / elif / else`, а не несколько независимых `if`?** При независимых проверках точка может удовлетворить сразу двум условиям:

```python
if x < 5:
    clusters[0].append(point)

if y < 3:
    clusters[1].append(point)
```

Если у точки одновременно `x < 5` и `y < 3`, она попадёт в оба списка. Цепочка `if / elif / else` выполняет только одну ветвь. Но и она не исправляет неправильно выбранные границы: она лишь предотвращает многократное добавление в рамках этой цепочки.

---

**Точки-аномалии обрабатывают только по правилам конкретной задачи.** Аномалия здесь означает запись, которая не относится ни к одному из требуемых кластеров. Например, в демоверсии 2026 года сказано, что в файле Б есть три лишние точки, которые нужно исключить.

При наличии аномалий **последнее `else` может быть опасным**. Оно отправит в последний кластер вообще всё, что не подошло раньше, включая лишние точки.

В таком случае лучше **выделять допустимые области явно**, а остальные точки сохранять отдельно — {{andor|`and`}} требует, чтобы одновременно выполнялись оба условия. Так устроен наш файл `27-2.txt`: три кластера и три аномалии.

**Разделяющая граница не обязана быть вертикальной или горизонтальной.** Иногда две группы удобно разделить наклонной прямой y = 2x + 1. Точки выше неё удовлетворяют условию y > 2x + 1, а ниже — y < 2x + 1. В коде:

```python
if y < 2 * x + 1:
    clusters[0].append(point)
else:
    clusters[1].append(point)
```

Чтобы понять проверку, возьми конкретное `x`. Выражение `2*x + 1` вычисляет высоту прямой при этом `x`. Затем программа сравнивает с ней высоту точки.

В некоторых задачах сказано, что кластеры помещаются в прямоугольники или квадраты заданных размеров. Это **ограничение на расположение точек**, а не готовая инструкция, как их разделить. Из него нельзя автоматически заключить:

- что границы проходят через начало координат;
- что точки нужно группировать по `x // W`;
- что стороны прямоугольников параллельны осям;
- что ширину прямоугольника можно использовать как порог соседства.

В подборке есть условия, прямо разрешающие поворот квадратов относительно осей. Если прямоугольник заведомо расположен параллельно осям, для его точек необходимо x_max − x_min ≤ W и y_max − y_min ≤ H.

Но для повёрнутого прямоугольника **его проекции на оси могут быть шире соответствующих сторон**. Поэтому такая проверка уже не является универсальной.

**Если форма кластеров необычная, полезно искать признак, который их разделяет.** Это может быть не сама координата `x` или `y`, а вычисленная по ним величина.

Например, группы могут располагаться в разных кольцевых областях вокруг известной точки C = (x₀; y₀). Тогда вычисляем расстояние до неё, r = √((x − x₀)² + (y − y₀)²), и разделяем точки по диапазонам `r`:

```python
r = dist(point, (x0, y0))

if r < 3:
    ...
elif r < 7:
    ...
else:
    ...
```

Границы опять выбираются по конкретным данным. Здесь точка `C`, относительно которой расположены кольца, не обязана быть тем «центром кластера», который затем требуется найти по сумме расстояний. У этих точек разное назначение.

Если группы лежат в разных **секторах**, разделяющим признаком может быть направление от известной точки `C`. Сектор можно представить как кусок круга между двумя лучами. Для точки, не совпадающей с `C`, угол направления вычисляется так:

```python
from math import atan2, degrees

angle = degrees(atan2(y - y0, x - x0))
angle = angle % 360
```

Здесь `atan2` определяет угол направления с учётом обеих координат; `degrees` переводит его из радиан в градусы; `% 360` приводит угол к диапазону от 0 включительно до 360 не включительно. Направление вправо соответствует 0°, вверх — 90°, влево — 180°.

Почему лучше не использовать обычное деление `(y-y0)/(x-x0)`? Потому что оно не различает все направления и приводит к делению на ноль на вертикальном луче.

Есть тонкость: направления 359° и 1° очень близки. Их нельзя считать далёкими только потому, что одно число почти 360, а другое почти 0. Чтобы проверить сектор, начинающийся с угла `start` и имеющий ширину `width`, удобно написать:

```python
relative_angle = (angle - start) % 360

if relative_angle <= width:
    ...
```

```python
clusters = [[], [], []]

for x, y in points:

    for k in range(3):
        if (angle - starts[k]) % 360 <= 20:
```

**Признаком может быть величина, вычисленная по нескольким столбцам строки.** В демоверсии 2027 года частицы делят на кластеры по кинетической энергии: модуль разности энергий любых двух частиц одного кластера не больше R = 2. Координаты здесь вообще ни при чём. Посчитаем энергию каждой частицы файла `27-4.txt` функцией `energy` из подтемы 2 и посмотрим на неё так же, как на точки, — только на одной оси:

<figure class="plate-figure">

<figcaption>Энергии всех 402 частиц файла 27-4.txt — штрихи на одной оси. Видны четыре группы и три пустых промежутка шириной около 1,6–2; пунктирные границы 3,5, 7 и 10,5 стоят в этих промежутках.</figcaption>

Без рисунка большие промежутки находит программа: отсортируем энергии и выведем соседние значения, между которыми больше 0,5. Затем делим по границам из этих промежутков. Номер группы частицы — сколько границ её энергия уже превысила:

```python
def energy_groups(particles, bounds):
    groups = [[] for _ in range(len(bounds) + 1)]

    for p in particles:
        k = 0
        while k < len(bounds) and energy(p) > bounds[k]:
            k += 1
        groups[k].append(p)

    return groups
```

Проверим и условие задачи: в каждой группе наибольшая и наименьшая энергии должны отличаться не больше чем на 2.

```python
particles = read_particles("27-4.txt")
es = sorted(energy(p) for p in particles)

for a, b in zip(es, es[1:]):
    if b - a > 0.5:
        print(round(a, 3), round(b, 3))

groups = energy_groups(particles, [3.5, 7, 10.5])

for g in groups:
    e = [energy(p) for p in g]
    print(len(g), round(max(e) - min(e), 3))
```

```output
6.174 8.127
9.879 11.745
125 1.736
103 1.751
93 1.752
81 1.596
```

`zip(es, es[1:])` даёт пары соседних значений отсортированного списка, а {{comp|включение}} `[[] for _ in …]` создаёт нужное число пустых групп (имя `_` пишут для переменной, которая не нужна). Ширина каждой группы меньше 2, значит, разбиение подходит под условие.

**Итого.**

- Сначала рисунок по самому файлу, в одинаковом масштабе по осям; потом правило.
- Границы записывают цепочкой `if / elif / else`: каждая точка попадает ровно в одну группу, порядок проверок важен.
- При аномалиях кластеры задают явными областями, а всё остальное откладывают в `noise`; проверяют, что аномалий столько, сколько сказано в условии.
- Размеры прямоугольников из условия — ограничение, а не способ разделения; повёрнутый прямоугольник шире своей стороны на оси.
- Признаком может быть вычисленная величина: расстояние до точки, угол направления, энергия частицы.
