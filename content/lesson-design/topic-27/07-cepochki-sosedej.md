**Дополнительный урок — для продвинутых.** Он для тех, кто хочет второй, автоматический способ разделения на кластеры. Ни одна задача подборок его не требует: во всех файлах кластеры отделяются координатными границами или углом. Но цепочки соседей разделяют группы без подбора границ по рисунку и помогают проверить границы. Задачи основных подтем решаются без него.

**Другой важный способ кластеризации — объединять точки через цепочки близких соседей.** Он полезен, когда группы разделены промежутками, но провести простые границы неудобно.

Начнём с трёх точек на одной горизонтальной прямой: A = (0; 0), B = (0,8; 0), C = (1,6; 0). Функции `read_points` и `center_sum` из основных подтем считаем определёнными выше в программе.

---

**Две точки считаем соседями, если расстояние между ними не больше порога.** Сначала выбирается число ε, которое будем называть **порогом соседства**. Две точки — соседи, если d(A, B) ≤ ε.

Возьмём ε = 0,9. Тогда d(A, B) = 0,8 ≤ 0,9 и d(B, C) = 0,8 ≤ 0,9, но d(A, C) = 1,6 > 0,9. Тем не менее все три точки образуют **одну связную группу**: от `A` до `C` можно пройти через `B`, причём каждый шаг достаточно короткий.

**Внутри такой группы не требуется, чтобы каждая точка была близка к каждой.** Требуется возможность добраться от одной точки до другой по цепочке соседей.

Если нарисовать отрезки между всеми парами соседей, получится **граф**: точки называются его вершинами, соединяющие их отрезки — рёбрами. Группа вершин, между которыми можно пройти по рёбрам и к которой нельзя присоединить другие достижимые вершины, называется **компонентой связности**. Термин выглядит сложнее самой идеи: это отдельный связный кусок рисунка.

Листай кадры схемы: в каждом свой порог. При маленьком значении точкам не хватает связей, при подходящем возникают две группы, при слишком большом они сливаются.

---

**Группу строят от любой точки, добавляя соседей добавленных точек.** Алгоритм построения одной такой группы:

1. Взять любую ещё не распределённую точку.
2. Найти её нераспределённых соседей.
3. Добавить их в текущую группу.
4. Найти соседей у добавленных точек.
5. Продолжать, пока все точки текущей группы не будут обработаны.

После этого берём следующую нераспределённую точку и начинаем новую группу.

Здесь принципиально важен четвёртый шаг. Если искать соседей только у первой точки, мы получим лишь её непосредственное окружение, а не весь кластер. Вот реализация:

```python
from math import dist


def split_clusters(points, eps):
    remaining = points.copy()
    clusters = []

    while remaining:
        cluster = [remaining.pop()]
        pos = 0

        while pos < len(cluster):
            point = cluster[pos]
            rest = []

            for other in remaining:
                if dist(point, other) <= eps:
                    cluster.append(other)
                else:
                    rest.append(other)

            remaining = rest
            pos += 1

        clusters.append(cluster)

    return clusters
```

Разберём устройство кода.

- `remaining` содержит точки, которые ещё не отнесены ни к одной группе. {{listops|Метод `copy()`}} создаёт отдельный список: сам исходный список `points` мы не будем опустошать.
- {{while|`while remaining:`}} — цикл продолжается, пока список не пуст.
- `cluster = [remaining.pop()]`: `pop()` извлекает последний элемент списка и удаляет его из списка. Эта точка становится первой точкой новой группы.
- `pos` — номер точки текущей группы, соседей которой мы сейчас будем искать.
- `while pos < len(cluster):` — размер `cluster` может увеличиваться по мере работы. Поэтому цикл обработает и исходную точку, и всех добавленных соседей.
- В `rest` соберём точки, которые пока остались нераспределёнными. Если точка близка к обрабатываемой — `cluster.append(other)`, если нет — `rest.append(other)`.
- После прохода `remaining = rest`: точки, присоединённые к кластеру, исчезают из списка нераспределённых.
- `pos += 1` — переходим к следующей точке растущей группы.

Пройдём алгоритм по шагам на точках A, B, C и ещё двух точках D = (3,5; 0), E = (4,2; 0,4) с порогом 0,9:

%%cl_split_stepper([(0, 0), (0.8, 0), (1.6, 0), (3.5, 0), (4.2, 0.4)], 0.9)%%

---

**Почему алгоритм находит всю связную группу?** Каждая добавленная точка рано или поздно обрабатывается. Значит, будут найдены её ещё не добавленные соседи. Затем соседи этих соседей — и так далее.

Если существует цепочка из коротких шагов от начальной точки до некоторой другой, алгоритм последовательно пройдёт по ней.

И наоборот: точка добавляется только потому, что близка к уже включённой. Значит, случайно перескочить в группу, с которой вообще нет связей, алгоритм не может.

Однако здесь есть важное ограничение: **алгоритм точно находит компоненты связности для выбранного порога. Совпадут ли они с кластерами из условия — отдельный вопрос.**

---

**В примере `example27.txt` вместо границы `x = 5` можно использовать порог.** У каждой группы точки соединяются через расстояния √2 < 1,5, а между группами нет близких пар:

```python
points = read_points("example27.txt", has_header=True)
clusters = split_clusters(points, eps=1.5)

print("Количество групп:", len(clusters))

for cluster in clusters:
    print(len(cluster), center_sum(cluster))
```

```output
Количество групп: 2
3 (11.0, 1.0)
5 (1.0, 1.0)
```

Центры те же, что при разделении границей: (11; 1) и (1; 1). Но значения `5` и `1.5` подходят **именно этому примеру**. Первой получилась правая группа: `pop()` начал с последней точки файла.

---

**Порог соседства нужно обосновать по данным.** Для правильного разделения описанным способом должны выполняться два требования:

1. Внутри каждого требуемого кластера точки соединяются цепочками шагов длиной не больше ε.
2. Между разными требуемыми кластерами нет ни одной пары точек на расстоянии не больше ε.

Обрати внимание: первое требование относится к **цепочкам**, а не к наибольшему расстоянию между любыми двумя точками внутри кластера. Вытянутый кластер может иметь длину 20 единиц, но состоять из точек с промежутками по 0,2. Для его связности вовсе не нужен порог 20.

Если порог слишком маленький, одна настоящая группа может распасться на несколько. Если слишком большой, отдельные группы могут соединиться.

При этом даже правильное количество получившихся групп ещё ничего не доказывает. Например, один настоящий кластер распался на два, а два других слились в один. Общее количество осталось прежним, но распределение неверно.

После автоматического разделения полезно вывести размеры и проверить несколько близких значений порога. В файле `27-6.txt` две дуги вложены одна в другую: вертикальная или горизонтальная граница здесь не помогает, а цепочки — помогают:

Если в некотором диапазоне порогов сохраняется одно и то же разумное разделение, это полезный признак устойчивости. Но он не заменяет проверку геометрии и требований условия.

Секторы файла `27-5.txt` показывают обе ошибки порога. У вершины `C` точки разных секторов сходятся, а на дальнем краю сектора точки редкие:

```python
points = read_points("27-5.txt")

    clusters = split_clusters(points, eps)
    print(eps, sorted([len(c) for c in clusters], reverse=True))
```

```output

```

При 1,2 третий сектор из 69 точек распался на куски 63, 3 и 3; при 5 все секторы слились через вершину; при 3 разделение верное. Угол направления из подтемы 3 разделяет эти точки без подбора порога.

**Иногда единого подходящего порога вообще нет.** Например, внутри одного разреженного кластера промежутки больше, чем расстояние между двумя другими кластерами. Тогда увеличение порога, необходимое для соединения первого, уже склеит два других. Поэтому разделение по соседям — важный инструмент, но не универсальная замена анализу условия.

Также не следует смешивать три разных понятия: радиус круга, упомянутого в условии; расстояние от вычисленного центра до самой далёкой точки; порог соседства ε. Это могут быть совершенно разные числа.

---

**Маленькие группы после автоматического разделения — ещё не обязательно аномалии.** Допустим, после разделения получились группы размеров `2400, 3100, 2800, 1, 2`. Если по условию должно быть три содержательных кластера и три аномальные точки, последние две группы могут оказаться аномалиями. Но важно проверить:

- где они находятся;
- почему их нужно исключить;
- действительно ли исключается три точки;
- не является ли маленькая группа допустимым кластером.

**Число аномальных точек и число маленьких групп — не одно и то же.** Три аномалии могут образовывать три одиночные группы, одну группу из трёх точек или группы размеров 1 и 2. Нельзя без обоснования писать:

```python
# Нельзя считать это универсальным правилом!
if len(cluster) > 10:
    ...
```

В одной задаче это может сработать, в другой удалит настоящий кластер.

Есть ещё проблема: аномальная точка может оказаться близко к настоящему кластеру и присоединиться к нему при обработке по порогу. Несколько аномалий могут даже образовать «мостик» между группами. Поэтому автоматическое выделение маленьких компонент не решает любую задачу с шумом.

Возможно, ты встретишь название **DBSCAN**. Это метод, который дополнительно учитывает плотность: важно не только расстояние до соседей, но и их количество. У него есть параметры `eps` и `min_samples`. Описанное выше обычное объединение по цепочкам не следует без пояснений считать полноценным алгоритмом фильтрации шума.

Для понимания заданий сначала достаточно уверенно владеть координатными границами и компонентами связности.

---

**Автоматическое выделение компонент и поиск центров — две разные по времени операции.** Наивное выделение соседей тоже может потребовать порядка N² проверок, где N — число всех точек файла. Если кластеры легко разделяются несколькими координатными условиями, это позволяет распределить точки за один проход, без попарного поиска соседей. Поэтому более «автоматический» способ не всегда является более быстрым.

---

**Итого.**

- Соседи — точки на расстоянии не больше ε; группа — все точки, связанные цепочками соседей.
- `split_clusters` обрабатывает каждую добавленную точку, поэтому находит всю компоненту связности.
- Порог обосновывают по данным: цепочки внутри кластеров короче ε, пары между кластерами длиннее; устойчивость проверяют несколькими порогами.
- Единого порога может не быть; тогда нужен другой признак.
- Маленькие группы — кандидаты в аномалии, но их число и положение проверяют по условию.
