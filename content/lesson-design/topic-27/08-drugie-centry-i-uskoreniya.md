**Другое определение центра использует расстояние до самой далёкой точки.** В нём для каждого кандидата сначала ищут максимальное расстояние, а затем выбирают кандидата с наименьшим таким максимумом.

Развернём фразу «минимально максимальное расстояние»:

1. Представили, что точка `P` — центр.
2. Нашли самую далёкую от неё точку кластера.
3. Запомнили, насколько далеко она находится.
4. Повторили для других кандидатов.
5. Выбрали того, у кого самое далёкое расстояние меньше всего.

Это можно понимать как поиск точки, из которой **хуже всего расположенный объект всё равно находится как можно ближе**. Такой принцип называют **минимаксом**: минимум среди вычисленных максимумов.

| Кандидат | Сумма расстояний | Самое большое расстояние |
|---|---:|---:|
| `(0, 0)` | 18 | 10 |
| `(1, 0)` | 15 | 9 |
| `(2, 0)` | **14** | 8 |
| `(5, 0)` | 17 | **5** |
| `(10, 0)` | 32 | 10 |

По сумме расстояний центр — `(2, 0)`. По минимальному максимальному расстоянию — `(5, 0)`. Это **разные задачи с разными ответами**.

Код для второго определения:

```python
from math import dist


def center_minimax(cluster):
    best_point = cluster[0]
    best_radius = float("inf")

    for candidate in cluster:
        radius = 0.0

        for point in cluster:
            d = dist(candidate, point)

            if d > radius:
                radius = d

        if radius < best_radius:
            best_radius = radius
            best_point = candidate

    return best_point, best_radius
```

```python
line = [(0, 0), (1, 0), (2, 0), (5, 0), (10, 0)]

center, radius = center_minimax(line)
print(center, radius)
print(center_sum(line))
```

```output
(5, 0) 5.0
(2, 0)
```

Функция возвращает два значения: `center` — выбранную точку, `radius` — расстояние от неё до самой далёкой точки. Такое определение встречается в задачах подборки, где кластеры — круги, а ответ — средний радиус.

**Если центр по условию обязан быть точкой кластера, нельзя свободно поставить его между точками.** Например, для двух точек `(0, 0)` и `(10, 0)` геометрическая середина `(5, 0)` покрывает их кругом радиуса 5. Но если разрешено выбирать центр только из этих двух точек, минимальное максимальное расстояние равно 10. Ограничение на допустимые центры принципиально меняет задачу.

**«Антицентр», «антипод» и «самая далёкая точка» нужно переводить в точное правило из условия.** По одному названию угадывать алгоритм нельзя. Возможны, например, такие определения — выбери, чтобы увидеть, что вычислять для кандидата и как выбирать:

:::pick Что требуется → что вычисляем для кандидата → как выбираем
- *минимум суммы расстояний | сумму расстояний до точек кластера | наименьшую сумму
- максимум суммы расстояний | ту же сумму | наибольшую сумму
- минимум максимального расстояния | самое большое расстояние до точки кластера | наименьший максимум
- самая далёкая точка от уже найденного центра | одно расстояние до этого центра | наибольшее расстояние
:::

Последние две части каждой строки помогают буквально перевести предложение на язык циклов.

Если «антицентр» определён как точка с **максимальной суммой** расстояний, в функции `center_sum` меняются начальное значение `best_sum = -float("inf")` и сравнение `if total > best_sum:`. Всё остальное устройство сохраняется.

Но найти точку с максимальной суммой расстояний и найти точку, самую далёкую от центра, — это не одно и то же вычисление. Для самой далёкой от уже известного центра:

```python
center = (2, 0)
farthest_point = line[0]
max_distance = -1.0

for point in line:
    d = dist(center, point)

    if d > max_distance:
        max_distance = d
        farthest_point = point

print(farthest_point, max_distance)
```

```output
(10, 0) 8.0
```

Здесь нет суммирования: каждой точке соответствует только одно расстояние.

Получаем:

> Минимизировать сумму квадратов расстояний — значит выбрать допустимую точку, ближайшую к средней точке кластера.

Если разрешена любая точка плоскости, минимум достигается в самой средней точке. Если разрешены только точки исходного кластера, нужно выбрать ближайшую из них.

<details class="proof" markdown="1">
<summary>Почему сумма квадратов зависит только от расстояния до средней точки</summary>

Пусть в кластере m точек: (x₁; y₁), …, (xₘ; yₘ). Проверяем кандидата P = (x; y). Нужная сумма:

T(P) = Σᵢ ((x − xᵢ)² + (y − yᵢ)²).

Знак Σ означает суммирование. Индекс i последовательно принимает значения от 1 до m. То есть формула — сокращённая запись ((x − x₁)² + (y − y₁)²) + … + ((x − xₘ)² + (y − yₘ)²).

Обозначим средние координаты: x̄ = (x₁ + … + xₘ) / m, ȳ = (y₁ + … + yₘ) / m.

После раскрытия скобок и группировки слагаемых получается:

T(P) = m · ((x − x̄)² + (y − ȳ)²) + Σᵢ ((xᵢ − x̄)² + (yᵢ − ȳ)²).

Посмотрим на смысл двух частей. Первая, m · ((x − x̄)² + (y − ȳ)²), — количество точек, умноженное на квадрат расстояния от кандидата до средней точки. Вторая часть зависит только от исходных точек. При смене кандидата она **не изменяется**.

Поэтому при сравнении кандидатов достаточно сравнивать первую часть. А множитель m одинаков для всех.

Чтобы увидеть источник преобразования, достаточно раскрыть одну часть:

Σᵢ (x − xᵢ)² = m · x² − 2x · Σᵢ xᵢ + Σᵢ xᵢ².

Поскольку Σᵢ xᵢ = m · x̄, получаем квадрат m · (x − x̄)² и остаток, не зависящий от `x`. С координатой `y` происходит то же самое.

</details>

Код:

```python
def center_squared(cluster):
    sum_x = 0.0
    sum_y = 0.0

    for x, y in cluster:
        sum_x += x
        sum_y += y

    mean_x = sum_x / len(cluster)
    mean_y = sum_y / len(cluster)

    best_point = cluster[0]
    best_value = float("inf")

    for point in cluster:
        x, y = point

        value = (x - mean_x) ** 2 + (y - mean_y) ** 2

        if value < best_value:
            best_value = value
            best_point = point

    return best_point
```

```python
cluster = [(0, 0), (1, 0), (2, 0), (3, 0), (100, 0)]
print(center_squared(cluster), center_sum(cluster))
```

```output
(3, 0) (2, 0)
```

Мы дважды прошли по точкам, а не сравнивали каждую с каждой. Это ускорение следует из формулы, поэтому сохраняет правильность. Но оно относится именно к **сумме квадратов евклидовых расстояний**. Доказанное выше ускорение через ближайшую к среднему точку нельзя переносить на другую формулу расстояния — например, на манхэттенскую — автоматически.

**Первое точное ускорение поиска центра использует симметрию расстояния.** В исходном алгоритме расстояние между `A` и `B` вычисляется дважды: когда кандидатом является `A` и когда кандидатом является `B`. Но d(A, B) = d(B, A). Можно вычислить его один раз и добавить одновременно в обе суммы.

Для этого создаём отдельную сумму для каждой точки: `totals = [0.0] * len(cluster)`. Если точек четыре, получится `[0.0, 0.0, 0.0, 0.0]`. Полная функция:

```python
def center_sum_pairs(cluster):
    n = len(cluster)
    totals = [0.0] * n

    for i in range(n):
        for j in range(i + 1, n):
            d = dist(cluster[i], cluster[j])

            totals[i] += d
            totals[j] += d

    best_index = totals.index(min(totals))

    return cluster[best_index]
```

`range(n)` создаёт последовательность номеров 0, 1, 2, …, n − 1. Внутренний цикл начинается с `i + 1`, поэтому перебираются только пары, в которых второй номер больше первого. Для четырёх точек это (0, 1), (0, 2), (0, 3), (1, 2), (1, 3), (2, 3).

Пара `(1, 0)` не нужна: она уже учтена как `(0, 1)`. Расстояние от точки до самой себя тоже не вычисляется.

<figure class="plate-figure">

<figcaption>Все пары номеров четырёх точек: нужны только 6 клеток над диагональю. Диагональ — расстояние до себя, под ней — те же пары в обратном порядке.</figcaption>
</figure>

Число различных пар — m(m − 1) / 2, примерно вдвое меньше исходных m². После завершения циклов `min(totals)` находит наименьшую сумму, {{listops|`totals.index(...)`}} — номер её первого появления, и по этому номеру возвращаем исходную точку `cluster[best_index]`:

```python
print(center_sum_pairs(cluster), center_sum_pairs(line))
```

```output
(2, 0) (2, 0)
```

Порядок роста остаётся квадратичным, но вычислений расстояния становится меньше. При этом нам не нужна таблица всех попарных расстояний: достаточно списка сумм длины m. Хранить огромную матрицу расстояний ради единственного поиска центра обычно излишне.

**Второе точное ускорение — досрочно прекращать проверку заведомо проигравшего кандидата.** Допустим, для уже проверенной точки сумма равна 500. Для нового кандидата посчитана только часть расстояний, а сумма уже равна 520.

Оставшиеся расстояния неотрицательны. Следовательно, итоговая сумма **не станет меньше 520** и не сможет улучшить результат 500. Можно остановить внутренний цикл — {{break|`break`}} завершает ближайший цикл, внутри которого находится, здесь — внутренний. Запусти по шагам на двух точках и посмотри, на каком кандидате срабатывает `break`:

```python run center_sum_early.py
from math import dist


def center_sum_early(cluster):
    best_point = cluster[0]
    best_sum = float("inf")

    for candidate in cluster:
        total = 0.0

        for point in cluster:
            total += dist(candidate, point)

            if total >= best_sum:
                break

        if total < best_sum:
            best_sum = total
            best_point = candidate

    return best_point


print(center_sum_early([(0, 0), (5, 0)]))
```

```output
(0, 0)
```

Первый кандидат (0; 0) даёт сумму 0 + 5 = 5. У второго, (5; 0), уже первое слагаемое 5 не меньше лучшей суммы 5 — внутренний цикл прерывается, второе слагаемое не считается. Равный результат не заменяет найденную точку.

Условие `>=` безопасно, если нас интересует любое улучшение строгого минимума, а равный результат не должен заменять уже найденную точку.

Почему ускорение точное? Потому что мы отбрасываем кандидата только после доказательства, что он уже не может улучшить ответ. Это отличается от предположения «точка выглядит слишком далёкой, поэтому проверять её не будем».

Такое ускорение не меняет худший квадратичный порядок работы и не обязано давать одинаковый выигрыш на любых данных. Парный подсчёт и досрочное прекращение — два разных способа организации вычислений. Не нужно пытаться механически вставить один в другой.

---

**Некоторые популярные сокращения поиска не дают гарантии правильного ответа.** Например:

- проверить только несколько ближайших к среднему точек;
- взять случайную часть данных;
- округлить координаты перед поиском центра;
- проверять каждую десятую строку;
- найти приблизительный центр на рисунке и взять ближайшую точку.

Такие способы могут оказаться полезными для предварительного анализа, но как окончательное решение требуют отдельного доказательства. Если правильный центр не попал в рассмотренную часть точек, программа его уже не найдёт.

Для построения чернового рисунка иногда можно показать часть очень большого набора. Для окончательного поиска центра по условию обычно нужны все соответствующие точки.

Метод `k-means`, который тоже встречается в материалах о кластеризации, работает с другой постановкой и использует средние координаты. Его результат нельзя автоматически считать ответом на задачу о точке кластера с минимальной суммой обычных расстояний.

Тебе важнее научиться переводить определение из условия в вычисление, чем запоминать названия методов.

---

**Итого.**

- Минимакс: для кандидата — наибольшее расстояние, выбираем наименьшее; радиус — это и есть найденный максимум.
- Антицентр по наибольшей сумме — тот же перебор с `-float("inf")` и `>`; самая далёкая от центра точка — одно расстояние без суммы.
- Центр по сумме квадратов — ближайшая к средней точке исходная точка; только для квадратов евклидовых расстояний.
- Парный подсчёт и досрочный `break` ускоряют перебор, не меняя ответ; выборки и округления — меняют.
