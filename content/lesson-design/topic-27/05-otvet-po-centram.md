**После нахождения центров начинается отдельная часть задачи: вычисление ответа.** Её легко недооценить. Даже идеально найденные центры не помогут, если затем усреднить не те координаты или посчитать расстояние между не теми объектами. Средние и минимумы координат центров нужны в 36 задачах подборок, выбор наименьшего или наибольшего кластера и исключение кластера — в 20.

Будем собирать ответ из центров кластеров. Функции `read_points` (подтема 2) и `center_sum` (подтема 4) считаем определёнными выше в программе; в конце соберём от файла до ответа пример `example27.txt`.

---

**Сначала познакомимся с короткой записью перебора, которая часто встречается в решениях.** Запись `xs = [point[0] for point in centers]` означает: для каждой точки из `centers` взять первую координату и собрать результаты в список. Это {{comp|списковое включение}} — короткая запись цикла с `append`.

А выражение `sum(point[0] for point in centers)` последовательно передаёт координаты функции `sum`, которая их складывает, — это {{genexp|генераторное выражение}}. По такому же принципу работают `min` и `max`:

```python
centers = [(-4, 10), (6, 2)]

xs = [point[0] for point in centers]
print(xs)
print(sum(point[0] for point in centers))
print(min(point[0] for point in centers))
print(max(point[1] for point in centers))
```

```output
[-4, 6]
2
-4
10
```

Теперь разберём основные варианты.

---

**Если нужно среднее арифметическое координат центров, каждый центр учитывается один раз.** Пусть центры C₁ = (x₁; y₁), …, Cₖ = (xₖ; yₖ). Тогда Pₓ = (x₁ + … + xₖ) / k и P_y = (y₁ + … + yₖ) / k:

```python
px = sum(center[0] for center in centers) / len(centers)
py = sum(center[1] for center in centers) / len(centers)
print(px, py)
```

```output
1.0 6.0
```

Если один кластер содержит 100 точек, а другой — 5000, их центры всё равно имеют одинаковый вес, когда условие требует именно среднее **центров**. Не нужно усреднять все точки файла или дополнительно умножать координаты центра на размер его кластера.

---

**Если нужны минимальные координаты центров, минимумы ищутся независимо.**

```python
px = min(center[0] for center in centers)
py = min(center[1] for center in centers)
print(px, py)
```

```output
-4 2
```

Для центров (−4; 10) и (6; 2) минимальная абсцисса −4, минимальная ордината 2, пара результата — (−4; 2). Она не совпадает ни с одним центром. Это нормально: условие просит две отдельные характеристики.

---

**Если нужно сравнить самый маленький и самый большой кластеры, сначала сохраняем связь между кластером и его центром.** Удобно упорядочить кластеры по числу точек: `clusters = sorted(clusters, key=len)`. `sorted` создаёт новый упорядоченный список. {{sortkey|`key=len`}} означает: сравнивать элементы по их длинам. Поскольку каждый элемент — кластер, его длина равна числу точек.

Обрати внимание: передаётся сама функция `len`, без скобок. Мы сообщаем, каким способом получать величину для сравнения.

Теперь `clusters[0]` — самый маленький, `clusters[-1]` — самый большой: индекс `-1` означает последний элемент. После этого найдём центры в том же порядке. Возьмём кластеры файла `example27.txt` — левый из пяти точек и правый из трёх:

```python
clusters = [
    [(0, 0), (0, 2), (1, 1), (2, 0), (2, 2)],
    [(10, 0), (12, 0), (11, 1)]
]
clusters = sorted(clusters, key=len)

centers = []

for cluster in clusters:
    centers.append(center_sum(cluster))

print([len(c) for c in clusters], centers)
print(dist(centers[0], centers[-1]))
```

```output
[3, 5] [(11, 1), (1, 1)]
10.0
```

Последняя строка — расстояние между центрами самого маленького и самого большого кластеров. Если центры были вычислены до сортировки кластеров, а затем переставили только кластеры, соответствие может нарушиться. Также нужно проверить, гарантирует ли условие однозначность выбора при одинаковых размерах.

---

**Кластер выбирают и по числу объектов нужного вида.** В обеих задачах основной волны ЕГЭ-2026 нужен кластер, где больше всего или меньше всего звёзд определённого вида. Если кластер выбирается по количеству объектов некоторого вида, это не то же самое, что выбор по общему количеству точек.

Ключом сортировки может быть и своя функция: она получает кластер и возвращает число, по которому его сравнивают. Разделим звёзды файла `27-3.txt` по границам из подтемы 3 и посчитаем в каждом кластере красных гигантов. Функции `read_stars` и `parse_kind` — из подтемы 2.

```python
def split_stars(stars):
    clusters = [[], [], []]

    for s in stars:
        if s[1] < 5:
            clusters[0].append(s)
        elif s[0] < 10:
            clusters[1].append(s)
        else:
            clusters[2].append(s)

    return clusters


def red_giants(cluster):
    count = 0

    for s in cluster:
        cls, sub, lum = parse_kind(s[2])
        if cls == "M" and lum == "III":
            count += 1

    return count
```

```python
clusters = split_stars(read_stars("27-3.txt"))
print([len(c) for c in clusters])
print([red_giants(c) for c in clusters])

by_red = sorted(clusters, key=red_giants)
print(len(by_red[0]), len(by_red[-1]))
```

```output
[231, 198, 172]
[11, 17, 9]
172 198
```

Меньше всего красных гигантов (9) — в кластере из 172 звёзд, больше всего (17) — в кластере из 198 звёзд, хотя самый большой кластер — из 231. Кластеризацию по расположению, поиск центра и последующий подсчёт объектов определённого типа нужно выполнять в том порядке, который задан условием.

---

**Теперь об исключении целых кластеров.** Если условие требует удалить самый маленький кластер, это отдельное действие после правильного разделения. При гарантии единственности самого маленького:

```python
clusters = sorted(clusters, key=len)
clusters = clusters[1:]
```

Срез `[1:]` берёт все элементы, начиная со второго. После исключения вычисляем нужные характеристики оставшихся кластеров. Если требуется удалить самый большой — `clusters = clusters[:-1]`: срез `[:-1]` берёт все элементы, кроме последнего.

Важно не спутать:

- удалить один кластер с минимальным размером;
- удалить все кластеры минимального размера;
- удалить все кластеры, в которых меньше заданного числа точек.

Это разные правила. И после удаления нужно делить среднее на **новое** количество кластеров — `average_radius = sum(radii) / len(radii)`, а не на исходное число групп.

---

**Последний этап — масштабирование и получение целого числа.** Пусть по условию нужно вывести целую часть произведения результата на 10 000. Для неотрицательного `value` ответ — `int(value * 10000)`. Например, value = 2,718281, value · 10000 = 27182,81, ответ 27182.

Здесь нельзя заменять `int` на `round`. **При отрицательных значениях нужно понимать поведение Python:** `int` отбрасывает дробную часть в направлении нуля, а округление вниз `floor` даёт другое число:

```python
from math import floor

print(int(2.718281 * 10000))
print(int(2.9), round(2.9))
print(int(-2.9), floor(-2.9))
```

```output
27182
2 3
-2 -3
```

На числовой оси разница видна наглядно:

<figure class="plate-figure">
%%cl_trunc_line()%%
<figcaption>Для 2,9 int и floor совпадают — обе дают 2, round даёт 3. Для −2,9 int идёт к нулю (−2), а floor и round — к −3.</figcaption>
</figure>

Поведение `int` прямо описано в документации Python. Если условие допускает отрицательный итог, нужно внимательно различать отбрасывание дробной части и требование округления вниз.

Если требуется модуль — `int(abs(value) * 10000)`. Но модуль нужно брать **именно на том шаге, который указан в условии**.

Например, абсциссы центров −6 и 4. Модуль среднего: |(−6 + 4) / 2| = 1. Среднее модулей: (|−6| + |4|) / 2 = 5. Это разные ответы.

Аналогично `abs(min(values))` и `min(abs(value) for value in values)` неравнозначны:

```python
values = [-8, 3]
print(abs(min(values)), min(abs(v) for v in values))
```

```output
8 3
```

Также не нужно округлять каждый центр перед усреднением. Сначала выполняются требуемые вычисления с исходными координатами, затем преобразуется конечный результат. Множитель тоже нельзя заучивать: в конкретной задаче могут требоваться 100, 1000, 10 000 или разные множители для разных величин.

---

**У дробных вычислений есть ещё одна особенность: `float` хранит многие десятичные числа приближённо.** Например, математически целое произведение иногда может оказаться в памяти чуть меньше или чуть больше целого. Поэтому полезно помнить:

- не округлять координаты заранее;
- не добавлять произвольное `0.0001` «для надёжности»;
- при подозрительно близком к целому итоговом значении проверить вычисления с большей точностью;
- при почти равных суммах кандидатов отдельно проверить, действительно ли их различие устойчиво.

Функция `math.fsum` может уменьшить ошибку суммирования: `total = fsum(dist(candidate, point) for point in cluster)`. Но это **не превращает все вычисления с `float` в абсолютно точные**.

Для обычного первоначального решения достаточно понять алгоритм и использовать исходные значения без лишнего округления. Повышенную точность имеет смысл подключать при конкретном обнаруженном пограничном случае.

---

**Соберём полноценный небольшой пример от файла до ответа.** Файл `example27.txt` содержит:

```example27.txt
X Y
0 0
0 2
1 1
2 0
2 2
10 0
12 0
11 1
```

Условие нашего учебного примера:

- точки образуют два кластера;
- первый расположен левее `x = 5`, второй — правее;
- центр — исходная точка с минимальной суммой расстояний;
- нужно найти средние координаты двух центров;
- вывести целые части этих средних, умноженных на 10 000.

Полная программа:

```python
from math import dist


def read_points(filename):
    points = []

    with open(filename, encoding="utf-8-sig") as f:
        f.readline()  # В нашем файле есть заголовок X Y

        for line in f:
            if not line.strip():
                continue

            sx, sy = line.replace(",", ".").split()

            x = float(sx)
            y = float(sy)

            points.append((x, y))

    return points


def center_sum(cluster):
    best_point = cluster[0]
    best_sum = float("inf")

    for candidate in cluster:
        total = 0.0

        for point in cluster:
            total += dist(candidate, point)

        if total < best_sum:
            best_sum = total
            best_point = candidate

    return best_point


points = read_points("example27.txt")

clusters = [[], []]

for point in points:
    x, y = point

    if x < 5:
        clusters[0].append(point)
    else:
        clusters[1].append(point)

centers = []

for cluster in clusters:
    centers.append(center_sum(cluster))

sum_x = 0.0
sum_y = 0.0

for x, y in centers:
    sum_x += x
    sum_y += y

px = sum_x / len(centers)
py = sum_y / len(centers)

print(int(px * 10000), int(py * 10000))
```

```output
60000 10000
```

Центры кластеров — (1; 1) и (11; 1), их средние координаты Pₓ = (1 + 11) / 2 = 6 и P_y = (1 + 1) / 2 = 1, отсюда 60000 и 10000. Значение `5` в этом примере подходит **именно этому файлу**.

<details class="proof" markdown="1">
<summary>Ручная проверка центров</summary>

Первый кластер — `(0, 0)`, `(0, 2)`, `(1, 1)`, `(2, 0)`, `(2, 2)`. Его центр — (1; 1). Расстояния от него до четырёх углов одинаковы и равны √2: S = 4√2 ≈ 5,657. Для любого угла сумма 2 + 2 + 2√2 + √2 = 4 + 3√2 ≈ 8,243. Значит, `(1, 1)` действительно лучше.

Второй кластер — `(10, 0)`, `(12, 0)`, `(11, 1)`. Для `(11, 1)`: S = √2 + √2 = 2√2. Для каждой из двух других точек: S = 2 + √2. Поскольку 2√2 < 2 + √2, центр второго кластера — (11; 1).

</details>

---

**Итого.**

- Среднее, минимум и максимум по центрам — `sum`, `min`, `max` от генераторного выражения; каждый центр учитывается один раз.
- Минимальные координаты ищутся независимо; пара минимумов не обязана быть центром.
- `sorted(clusters, key=len)` упорядочивает кластеры по размеру; центры ищут после сортировки, чтобы не потерять соответствие. Ключом может быть и своя функция — число объектов нужного вида.
- После исключения кластера делят на новое количество.
- `int(value * 10000)` — целая часть; `round` и `floor` дают другое; модуль берут на том шаге, который указан в условии.
