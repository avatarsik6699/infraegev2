## Goal

Восстановить почасовую ограниченную очистку артефактов аккаунтов по действующему контракту [SPEC](../SPEC.md) §7–8 и [runbook](../runbooks/backup-restore.md). На production с 2026-09-26 таймер завершился ошибкой не менее 80 раз: скрипт запускает системный `python`, который не видит SQLAlchemy из `/app/.venv`. В том же change установить причину высокого расхода памяти API-контейнера (около 93–96% лимита 384 МиБ при проверке 2026-09-29), прежде чем менять код или лимит.

## Gate Checks

> Critical Gate and Release Gate are defined in [docs/STACK.md](../STACK.md); this section records change-specific evidence.

- Контрактный тест должен запускать production-команду через fake Docker и отклонять системный `python`; дополнительно нужен успешный запуск модуля в реальном API-образе с изолированной БД. Никакой тест не обращается к production-базе.
- Проверка T1 использует read-only метрики/инвентаризацию. Если появится правка памяти, её критерии и затронутые проверки добавляются в этот Backlog до исполнения.
- Закрытие production-инцидента требует отдельного разрешённого release и сохранённого результата двух последовательных запусков timer из I3. Ответственный за релиз проверяет journal и агрегатные счётчики без чувствительных данных; при неуспехе оставляет инцидент открытым, фиксирует ошибку и начинает исправление через Backlog. Эта production-проверка не блокирует локальный `/ship`.

## Implementation Notes

- На 2026-09-30 cgroup API показывал 372/384 МиБ, RSS единственного Python-процесса 111 МиБ: anon 86 МиБ, slab_reclaimable 284 МиБ, slab_unreclaimable менее 1 МиБ. За последние сутки SRE собрал 8619 точек памяти API: 83,93–99,93% лимита, последняя 92,8%; CPU обычно около 0,24%, без устойчивого роста памяти. Контейнер не перезапускался с 2026-09-26, `oom`/`oom_kill` равны 0, `memory.pressure` сейчас 0; `memory.events max=76` указывает на уже происходившее ограничение с успешным возвратом памяти. Причина высокого учёта — преимущественно освобождаемый slab, доказательств роста Python heap или необходимости менять лимит нет. Критерий нового риска: рост `oom`/`oom_kill`, устойчивое ненулевое `memory.pressure`, повторные ошибки readiness или нарастающий RSS при той же нагрузке; тогда добавить Backlog ID для предметного исправления.
- Предрелизный browser gate дважды поймал разницу ширины 1,32 px: тест измерял `boundingBox` до клика в состоянии CSS hover scale(1.02), а при `aria-busy` это преобразование исчезало. Это эффект указателя, а не изменение layout. Page Object убирает hover перед сравнением; два повторных изолированных production-browser прогона (6/6 каждый) прошли.
- Для 23 публичных вложений банка сверены `storage_key`, `checksum`, размер и фактический SHA-256; один дайджест был разрешён ранее, остальные 22 добавлены как точные исключения только на пути банка. Контроль с новым значением на этом пути и разрешённым значением вне пути по-прежнему даёт 2 находки Gitleaks; скан текущего дерева и 337 коммитов чист.
- Три вызова `eval` в локальном валидаторе учебных задач заменены ограниченным AST-интерпретатором; 255 задач сохранили прежний результат (149 совпадений, 5 расхождений, 101 неразобранная), шесть вредоносных выражений отклонены. Динамический импорт видео-сцен ограничен файлами репозитория и снабжён точечным Semgrep-обоснованием. Общий SAST: 0 находок.
