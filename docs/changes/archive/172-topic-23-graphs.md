## Goal

Transfer EGE topic 23 from the approved demo stand (`docs/artifacts/lesson-design/topic-23/`) to the
site: stage 9 of the binding [lesson pipeline](../../runbooks/lesson-pipeline.md), the second topic
after Change 171. The catalog topic «Анализ графов» gets its lesson for the first time. It has:
- seven subtopics, five core and two advanced, plus «Практика и итог»;
- original bank tasks on our own graph files.

Architect decisions (2026-10-09, stand review, recorded in `topic-23/map.md`):
1. Task 23 is new (demo 2027; one task in the collection). Levels follow the demo task, not frequency.
2. The core solution is recursion with `@cache`. Repeated passes (Bellman–Ford) are advanced.
3. The lesson does not mention «Решу ЕГЭ». Exam-format tasks use generated files `topic-23/files/23-*.txt`.
4. Stand iteration 2 (beginner audit) is approved: path sandbox, backward f stepper, adjacency figure, call tree, topological sort stepper.

The Change 171 platform blocks are reused unchanged where possible. New platform work:
- the `PathBuilder` sandbox;
- the lesson's program checks against a data file.

Contract: [SPEC](../../SPEC.md) §1.4, §2.2–§2.3, §3, §5; [FRONTEND](../../FRONTEND.md); [DESIGN](../../../DESIGN.md); [lesson-authoring](../../runbooks/lesson-authoring.md).

## Implementation Notes

- F2 (`frontend-architecture` consulted): `export_media` writes the sandbox's graph geometry as
  data (manifest kind `graph`, `figures.WIDGET_DATA`) and `PathBuilder` draws it in React from
  state, like `RemainderExplorer`. Rejected: shipping the interactive SVG markup and mutating its
  attributes in an effect. `figures.graph_layout` is the one layout for the stand picture and the
  site sandbox. Path lengths are summed exactly from the weight strings (`decimalSum`).
- T1: a figure whose positional arguments are only lists (a graph's edge list) gets a media key
  with a short hash of its arguments and keywords; `stepperLabels` may name the builder instead
  of that key. Topic 25 keys and both manifests are unchanged (`--check`).
- Stand texts adjusted for the tools, without changing content: «Задачи основного уровня в
  формате экзамена» heading, numeric written answers («4 вершины», «2 прохода»), subtopic 3
  task 7 asks one number, two table intros. `checks.py` and `verify_code.py` rerun.
- `topic-catalog.test.tsx` searches «РЕКУРСИВ» instead of «РЕКУРС»: the topic 23 summary names
  recursion with memoisation, so the shorter query now matches two topics.
- The practice catalog gains «23 номер. Анализ графов» from `practice-registry.mjs`.
- The topic 23 practice page offers 14 attached graph files (every lesson task with a file).
- F8: data-file fences are named by the file — ```` ```23.txt ```` for the real learning file
  (subtopic 6), ```` ```file.txt ```` for one-line examples (subtopics 1, 3), since `40 7 1.3` is not
  a line of `23.txt`. `CodeBlock` gained optional `fileName` (header text in place of «Python»).
- F9: student-facing wording only — the tree group «Дополнительные уроки · для продвинутых», the
  item, head and pager mark «дополнительный урок», cheat sheet and outcomes, the advanced lesson
  intros («Дополнительный урок — для продвинутых. Он для тех, кто хочет закрыть все возможные
  случаи задания NN…»), «основной уровень освоен» → «основные подтемы освоены», the stand index,
  and the runbook template. The methodology term «уровень» stays in the level rule, `topic.json`
  keys, `map.md`, `frequency.md` and quality records (architect-facing). The final-page task heading
  became «Задачи основных подтем…» (`TASK_BLOCK` in `export_lesson.py`, both `bank.py`, two tests).
- F6 left a stale unit test (`shared-components` expected the line number in code text); fixed to
