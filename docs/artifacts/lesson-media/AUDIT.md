## Принятые риски

- **Вес.** WebM 296–552 КБ, MP4 197–457 КБ на ролик, около 1,3 МБ WebM на страницу урока; ориентир 300 КБ мягкий. Видео загружается при просмотре (`preload="metadata"`, старт по видимости), не всё сразу.
- **Браузеры.** Проверено в Chromium (Playwright) и реальном Chrome (Playwriter). Safari, Firefox и iOS не проверялись; для Safari есть Range, но сам просмотр не выполнен.
- **Скринридер** вручную не проверялся: доступность проверена axe в E2E и структурой (имена кнопки и полосы, одна подпись).
- **Без JS** виден постер без движения и без управления, а не проигрывание: так выполняется reduced motion для всех.
- **Проверки движка** запускаются вручную и перечислены в STACK; в обычную CI они не входят (политика: обычные тесты не в CI).
- **Стиль кода** скриптов в `docs/artifacts/lesson-media/` не входит в gate `ruff check` (только форматирование теста); замечания по длине строк не критичны.

## Дорожная карта для более сложных схем

1. **Статичные иллюстрации.** Движок умеет (`KIND = "still"`, WebP). Нужен компонент `LessonFigure` с тем же правилом подписи и минимальным зазором, создаётся при первом потребителе; `Diagram` заменить или убрать.
2. **Примитивы.** Фигурные скобки, выноски с изломом, маркерное выделение, штриховка, групповое смещение, камера (масштаб, панорама), моноширинный рукописный текст для кода. Каждый — вместе с образцом на листе и тестом.
3. **Составление сцен.** Общие блоки (`rekursiya_chain.py`) станут библиотекой шаблонов схем: ряд, дерево, таблица, граф, стек, при втором потребителе.
4. **Последовательности.** Вспомогательный курсор времени вместо ручных `t += …`, если сцены станут длиннее.
5. **Производительность.** Кэш неизменных слоёв, параллельный рендер кадров, если ролик превысит несколько минут сборки.
6. **Доступность длинных роликов.** При роликах свыше минуты рассмотреть расшифровку и оглавление по времени.
7. **Автоматизация.** Запуск тестов движка и `lesson-media-nginx.test.sh` в изолированном ship/release-проходе; проверка веса страницы в Lighthouse-аудите.
8. **Другие уроки.** Использовать ролики там, где идею несёт порядок или изменение во времени (алгоритмы, стек, очередь, рекурсия), и не там, где хватает одного кадра.
