Главная идея подтемы: **файл превращается в граф без потерь: номера вершин — целые числа, веса — точные десятичные дроби, а рёбра раскладываются по начальным вершинам**. В демоверсии граф дан именно файлом, и ошибка при чтении портит ответ так же, как ошибка в рассуждении.

Сквозной пример подтемы — строка `40 7 1.3` и учебный граф из подтем 1 и 2, записанный в файл `23.txt`.

---

**В файле каждая строка описывает одно ребро.** Строка

```file.txt
40 7 1.3
```

означает: `40` — откуда идём, `7` — куда идём, `1.3` — сколько стоит переход.

В этом формате первая строка тоже описывает ребро. Отдельного заголовка с количеством вершин или рёбер нет. Поэтому нельзя автоматически пропускать первую строку через `f.readline()`: так мы потеряем одно ребро.

---

**Строку разбивает на части `split`, а номера вершин превращает в числа `int`.** Пробелов между числами может быть несколько, также могут встречаться табуляции. Подходящая команда — {{split|`line.split()`}}: она разбивает строку на части по пробельным символам.

```python
line = "40     7\t1.3"
parts = line.split()
print(parts)

u = int(parts[0])
v = int(parts[1])
print(parts[0] + parts[1], u + v)
```

```output
['40', '7', '1.3']
407 47
```

Все три элемента после `split` пока являются текстом: кавычки показывают, что это строки. Строка `'40'` и число `40` — разные значения. Строки при сложении склеиваются (`'407'`), а с числами выполняется арифметика (`47`). Для номеров вершин подходит преобразование {{num|`int`}}. Счёт элементов в списке Python начинается с нуля: `parts[0]` — первый элемент, `parts[1]` — второй, `parts[2]` — третий.

С весом нужно поступить иначе, потому что он может быть дробным.

---

**Дробную часть веса нельзя отбрасывать во время чтения.** Допустим, путь состоит из двух рёбер: 2.8 + 3.6 = 6.4. Целая часть полной суммы равна 6. Если сначала отбросить дробные части отдельных весов, получим 2 + 3 = 5. Это уже неверный результат.

Правильный порядок: прочитать веса с дробными частями, найти минимальную полную сумму и только после этого взять целую часть.

Отдельно различай получение целой части и округление:

```python
print(int(7.9), round(7.9))
```

```output
7 8
```

В нашей задаче требуется первая операция: `int` отбрасывает дробную часть, а `round` округляет до ближайшего целого.

---

**Обычные дробные числа `float` могут храниться приближённо.** Причина в том, что компьютер представляет их в двоичной системе. Некоторые конечные десятичные дроби, например `0.1`, не имеют конечной двоичной записи. Поэтому хранится очень близкое приближение. Сложим 0.1 десять раз:

```python
total = 0.0

for step in range(10):
    total = total + 0.1

print(total)
print(int(total))
```

```output
0.9999999999999999
0
```

Математически сумма равна единице, но небольшая погрешность перед взятием целой части изменила ответ.

---

**Точные десятичные веса даёт `Decimal` — стандартный тип Python для десятичных чисел.** Он подключается строкой `from decimal import Decimal` и создаётся непосредственно из текста:

```python
from decimal import Decimal

print(Decimal("2.8") + Decimal("3.6"))
print(Decimal("1.3"))
print(Decimal(1.3))

INF = Decimal("Infinity")
print(INF > Decimal("100000"), INF + 3)
```

```output
6.4
1.3
1.3000000000000000444089209850062616169452667236328125
True Infinity
```

Пиши именно `Decimal("1.3")`, а не `Decimal(1.3)`: во втором случае сначала создаётся приближённый `float`, и третья строка вывода показывает, что именно он хранит. `Decimal` точно принимает десятичную запись из строки, а арифметику выполняет с заданной точностью; по умолчанию это 28 значащих цифр. Для файлов задания этого достаточно. Это не бесконечная точность: для необычных данных с десятками дробных знаков её пришлось бы увеличить.

Положительную бесконечность из подтемы 2 записывают как `Decimal("Infinity")`. Она больше любого числа и остаётся бесконечностью после прибавления. `INF` — выбранное нами имя переменной. Заглавные буквы здесь лишь подчёркивают, что это вспомогательное постоянное значение.

---

**Прочитанные рёбра храним в списке троек.** Пустой {{list|список}} создаётся квадратными скобками: `edges = []`. Одно ребро будем хранить как тройку `(u, v, w)`. Такая группа значений в круглых скобках называется **кортежем**. Здесь он объединяет три характеристики одного ребра. Добавить ребро в конец списка — `edges.append((u, v, w))`.

Чтение файла целиком:

```python
from decimal import Decimal

edges = []

with open("23.txt") as f:
    for line in f:
        # Пропускаем пустые строки, если они встретятся.
        if not line.strip():
            continue

        parts = line.split()

        u = int(parts[0])
        v = int(parts[1])
        w = Decimal(parts[2])

        edges.append((u, v, w))

print(len(edges))
print(edges[0])
```

```output
6
(7, 100, Decimal('3.0'))
```

{{file|`with open("23.txt") as f:`}} открывает файл и позволяет работать с ним через имя `f`. После завершения блока файл автоматически закрывается. Цикл `for line in f:` последовательно получает строки файла.

Команда `line.strip()` убирает пробельные символы с начала и конца строки. Если строка содержала только пробелы или перевод строки, результат будет пустым. Условие `if not line.strip():` проверяет именно этот случай. Команда `continue` пропускает оставшуюся часть текущего повторения цикла и переходит к следующему. Поэтому для пустой строки программа сразу начинает читать следующую строку.

В файле `23.txt` записан учебный граф, но строки идут в другом порядке: первая — `7 100 3.0`. Порядок строк файла ничего не говорит о порядке движения по графу.

---

**Для поиска пути удобнее хранить рёбра по начальным вершинам.** Нужно быстро отвечать: куда можно перейти из вершины `v` и сколько стоит каждый переход? Для этого подходит {{dict|словарь}}: он хранит соответствия «ключ → значение». У нас ключ — номер вершины, значение — список исходящих переходов.

```python
edges = [(7, 100, 3), (40, 7, 1), (40, 100, 9),
         (1, 100, 12), (1, 7, 5), (1, 40, 2)]

graph = {}

for u, v, w in edges:
    if u not in graph:
        graph[u] = []

    graph[u].append((v, w))

print(graph[40])
print(graph[1])
print(graph.get(100, []))
```

```output
[(7, 1), (100, 9)]
[(100, 12), (7, 5), (40, 2)]
[]
```

Запись `for u, v, w in edges:` по очереди берёт каждую тройку из списка рёбер и раскладывает её по трём переменным. Если очередное ребро — `(40, 7, 1)`, то внутри этого повторения цикла `u = 40`, `v = 7`, `w = 1`.

Условие `if u not in graph:` проверяет, есть ли в словаре запись для вершины `u`. Если её ещё нет, создаём пустой список, а затем добавляем переход. В итоге `graph[40]` — это `[(7, 1), (100, 9)]`: из `40` можно перейти в `7` за `1` и в `100` за `9`. Такое представление называют **списком смежности**. Смежность здесь означает наличие непосредственного соединения ребром.

<figure class="plate-figure">
%%adjacency([(7, 100, "3"), (40, 7, "1"), (40, 100, "9"), (1, 100, "12"), (1, 7, "5"), (1, 40, "2")], focus=40)%%
<figcaption>Каждая строка файла попадает в список своей начальной вершины. Строки 40 7 1 и 40 100 9 стоят в разных местах файла, но обе оказываются в graph[40]. У цели 100 исходящих рёбер нет, и записи для неё не появляется.</figcaption>
</figure>

Здесь `40` — ключ словаря. Нам не нужно создавать 41 элемент, чтобы обратиться к ключу `40`. Поэтому словарь удобен, когда номера вершин идут с пропусками: в файлах задания они бывают до 1000.

Чтобы получить исходящие переходы, используем `graph.get(v, [])`: вернуть значение для ключа `v`, если оно есть, иначе вернуть пустой список `[]`. У цели `100` и у тупиков исходящих рёбер нет, и записи в словаре для них не появилось. `graph[100]` вызвал бы ошибку, а `graph.get(100, [])` спокойно возвращает пустой список. Таким образом, вершина без исходящих рёбер тоже обрабатывается нормально.

---

**Итого.**

- Строку файла разбивает `split()`; номера вершин — `int`, веса — `Decimal` из строки. Первую строку не пропускаем: заголовка нет.
- Дробную часть отбрасываем только у полной суммы, через `int`, а не `round`.
- Рёбра храним списком кортежей `(u, v, w)`, а для поиска пути — словарём `graph`: вершина → список переходов `(v, w)`.
- Исходящие переходы берём через `graph.get(v, [])`, чтобы вершины без рёбер не ломали программу.
