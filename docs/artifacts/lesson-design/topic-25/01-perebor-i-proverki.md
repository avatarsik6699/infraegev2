В задании 25 важно понимать две вещи: **как проверить свойства отдельного числа** и **как организовать поиск, чтобы не перебирать лишнее**. Если освоить обе, многие внешне разные задачи окажутся небольшими изменениями одного алгоритма.

Ниже — подробный разбор на Python: от смысла деления с остатком до поиска делителей, работы с простыми множителями и генерации чисел по маске. Новые конструкции Python буду объяснять перед использованием или сразу рядом с первым примером.

В задании 25 встречаются задачи на количество и свойства делителей, поиск числа с максимальным количеством делителей, а также числа, одновременно удовлетворяющие маске и условию делимости. Поэтому разберём не только отдельные шаблоны, но и то, как их объединять.

Тема разбита на подтемы двух уровней. **Основные подтемы 1–5** покрывают большинство задач экзамена, в том числе все задачи реальных экзаменов 2022–2026 годов. **Подтема 6 — дополнительный уровень**: она нужна для редких задач с очень большими диапазонами, где без теории перебор не успевает.

Эта подтема — фундамент для остальных. Главная идея: **любое условие задания 25 состоит из простых проверок, а каждую проверку можно буквально перевести в код** — делимость, сравнение, цифры записи числа.

**Любую такую задачу сначала полезно разделить на четыре действия.** Это позволит понимать назначение каждой части программы.

1. **Получить числа, среди которых будем искать.** Например, все числа от 100 до 200 или только числа, кратные 23.
2. **Проверить условие для очередного числа.** Например, найти его делители и посчитать их.
3. **Вычислить величину, которую требует условие.** Это может быть само число, сумма делителей, наибольший делитель или частное от деления.
4. **Вывести результаты в нужном порядке.**

Число, которое мы сейчас рассматриваем, будем называть **кандидатом**: оно потенциально подходит, но ещё должно пройти проверку.

Например, задача:

> Найти числа от 10 до 30, имеющие ровно четыре натуральных делителя.

Рассуждение:

- кандидаты — числа 10, 11, 12, …, 30;
- для каждого кандидата находим все делители;
- считаем их;
- если получилось ровно четыре, число подходит.

Пока здесь не требуется никакой сложной математики. Но если проверять каждое число неудачным способом, программа может работать слишком долго. Поэтому дальше мы отдельно разберём правильность и скорость поиска.

**Основа задания — деление с остатком.** Если разделить 17 на 5, пятёрка помещается в 17 три раза и ещё две единицы остаются: 17 = 5 · 3 + 2. Число 3 — целая часть частного, 2 — остаток.

%%remainder_widget(17, 5)%%

В общем виде для натурального n и делителя d всегда можно записать n = d · q + r, где 0 ≤ r < d. Остаток меньше делителя: будь он хотя бы d, из него выделилась бы ещё одна полная порция. В Python целую часть частного даёт `n // d`, а остаток — `n % d`.

Посмотрите на схеме два крайних случая. Если разделить 20 на 5, порции заполнятся без остатка: `20 % 5` равно 0. Если число меньше делителя, полной порции не набирается: `3 // 7` равно 0, а `3 % 7` — всё число, 3.

Отсюда главная проверка задания: **число делится на другое без остатка тогда и только тогда, когда остаток равен нулю**, то есть {{eq|`n % d == 0`}}. Так, `18 % 3 == 0` даёт `True`, а `18 % 5 == 0` — `False`.

Обычное деление `/` здесь почти не нужно: `18 / 3` даёт дробное `6.0`, а `18 // 3` — целое `6`. Для отрицательных чисел `//` округляет вниз, но в задании числа натуральные, и это не мешает. Понадобится ещё степень — для больших границ вроде 10⁹. В Python её записывают через `**`: `10 ** 9`, а не через `^`.

**Условие задачи переводим в код буквально.** Похожие формулировки часто отличаются одним словом, а проверки — одним знаком. «Кратно» значит, что остаток равен нулю, «не кратно» — что не равен. «Больше 100» не пропускает само 100, а «не меньше 100» — пропускает. Выберите формулировку, чтобы увидеть её проверку:

:::pick Формулировка условия и её проверка
- кратно 7 | `n % 7 == 0` | остаток равен нулю
- *не кратно 7 | `n % 7 != 0` | остаток не ноль; `!=` — «не равно»
- чётное | `n % 2 == 0` | кратно 2
- нечётное | `n % 2 != 0` | не кратно 2
- больше 100 | `n > 100` | само 100 не подходит
- не меньше 100 | `n >= 100` | 100 подходит
- меньше 100 | `n < 100` | само 100 не подходит
- не превышает 100 | `n <= 100` | 100 подходит
- на отрезке [100; 200] | `100 <= n <= 200` | обе границы входят
:::

Если должны выполняться оба условия сразу, их соединяют {{andor|`and`}}, если достаточно одного — `or`:

```python
n % 3 == 0 and n % 5 == 0  # и на 3, и на 5
n % 3 == 0 or n % 5 == 0   # хотя бы на одно
```

Второе условие выполнено в трёх случаях: число делится только на 3, только на 5 или на оба сразу. То есть `or` не означает «строго одно из двух».

**Чтобы проверить много чисел подряд, нужен цикл.** Запись {{for|`for n in range(10, 15)`}} по очереди даёт переменной `n` значения от 10 до 14:

```python
for n in range(10, 15):
    print(n)
```

```output
10
11
12
13
14
```

Числа 15 в выводе нет: **правая граница `range` не включается**. Поэтому для отрезка [L; R], где обе границы входят, пишут `range(L, R + 1)`.

Проверку внутри цикла делает {{if|`if`}}, а отступы показывают, какие команды к нему относятся. Выведем числа отрезка [10; 30], кратные 3:

```python
for n in range(10, 31):
    if n % 3 == 0:
        print(n)
```

```output
12
15
18
21
24
27
30
```

Программа берёт очередное число от 10 до 30, проверяет делимость на 3 и, если проверка прошла, выводит число. Граница 31 — чтобы проверить и само 30.

**Для работы с масками нужно различать число и строку.** `1234` — число, а `"1234"` — {{str|строка}} из четырёх символов. С числами выполняются арифметические действия, а строки при сложении склеиваются:

```python
print(12 + 34)
print("12" + "34")
```

```output
46
1234
```

Переходить между ними помогают `str` и `int`. Поэтому запись числа можно собрать из частей как строку, а затем превратить в число. Количество цифр натурального числа — это {{len|`len(str(n))`}}:

```python
s = "12" + "7" + "34"
n = int(s)
print(n, len(str(n)))
```

```output
12734 5
```

**Операции с цифрами позволяют проверять дополнительные требования к числу.** Некоторые условия удобнее проверять арифметически, другие — через строку.

Арифметически цифры достаются делением на 10, 100, 1000: остаток `n % 100` — это последние две цифры, а `n // 100` — число без них. Выберите операцию, чтобы увидеть её результат для n = 50721:

:::pick Операции с цифрами числа 50721
- *последняя цифра | `n % 10` → 1
- без последней цифры | `n // 10` → 5072
- последние две цифры | `n % 100` → 21
- без последних двух цифр | `n // 100` → 507
- цифра сотен | `(n // 100) % 10` → 7
:::

Почему остаток от деления на 10 даёт последнюю цифру? Любое неотрицательное целое число можно записать как n = 10q + r, где 0 ≤ r < 10. Часть 10q — все полные десятки, а остаток r — единицы, то есть последняя цифра. Так же n = 100q + r с 0 ≤ r < 100 оставляет в остатке последние два разряда. Поэтому `n % 100 == 37` проверяет окончание на 37.

Если окончание начинается с нулей, остаток не различает, например, число 7 и число, оканчивающееся на `07`. Через строку такое окончание проверяется явно: `str(n).endswith("07")` — «запись заканчивается на 07».

Сумму цифр считает цикл по символам записи: `int(ch)` превращает символ цифры в число.

```python
n = 50721
digit_sum = 0
for ch in str(n):
    digit_sum += int(ch)
print(digit_sum)
```

```output
15
```

Повторы цифр удобно искать через {{set|множество}} `set(s)`: в нём остаются только различные символы. Если их столько же, сколько всех цифр, повторов нет:

```python
s = str(50721)
print(len(set(s)) == len(s))
```

```output
True
```

**Проверить, встречается ли в записи числа цифра или группа цифр, можно через `in`.**

В задачах последних лет часто встречаются условия вроде «в записи числа есть цифра 1 и цифра 6» или «запись содержит последовательность цифр 53». Это проверки **строки**, а не арифметики: {{in|`"1" in s`}} истинно, если символ `1` встречается в записи хотя бы раз, а `s.count("16")` считает, сколько раз в ней встречается группа `16`.

```python
s = str(1677016)

print("1" in s and "6" in s)
print(s.count("16"))
```

```output
True
2
```

Выберите формулировку, чтобы увидеть её проверку:

:::pick Формулировка про цифры записи и её проверка
- *содержит цифру 7 | `"7" in str(n)`
- не содержит цифру 0 | `"0" not in str(n)`
- есть и 1, и 6 | `"1" in s and "6" in s`
- есть 2 или 3 | `"2" in s or "3" in s`
- «53» ровно один раз | `s.count("53") == 1`
:::

**«Встречается ровно один раз» и `count` совпадают не всегда.** `count` считает непересекающиеся вхождения: найдя группу, продолжает поиск после неё.

```python
s = "7777"
print(s.count("77"))
```

```output
2
```

Но если считать все места, где начинается `77`, их три: позиции 0, 1 и 2. Сравните на схеме:

<figure class="plate-figure">
%%overlap("7777", "77")%%
<figcaption>Жирные отрезки — то, что находит <code>count</code>: после вхождения с позиции 0 поиск продолжается с позиции 2. Вхождение с позиции 1 перекрывается с уже найденным и пропускается.</figcaption>
</figure>

Для групп вроде `53` или `567` перекрытие невозможно — у них начало не совпадает с концом, и `count` даёт верный ответ. Для групп вроде `77` или `121` нужно уточнить, что считает условие.

**Иногда числа нужно перебирать по убыванию.** Например, когда спрашивают о наибольших подходящих числах. Третий аргумент `range` — шаг, отрицательный шаг ведёт вниз, а правая граница по-прежнему не включается:

```python
for n in range(10, 4, -2):
    print(n)
```

```output
10
8
6
```

Найдём три наибольших числа меньше 1000, которые делятся на 7 и оканчиваются цифрой 3. Как только найдено третье, {{break|`break`}} завершает цикл:

```python
found = []

for n in range(999, 0, -1):
    if n % 7 == 0 and n % 10 == 3:
        found.append(n)
        if len(found) == 3:
            break

print(found)
```

```output
[973, 903, 833]
```

**Нижняя граница в таком поиске обязательна.** Если искать те же три числа меньше 200 циклом `while`, который просто уменьшает `n`, найдутся 133 и 63, а третьим окажется −7: подходящих положительных чисел всего два, и цикл ушёл в отрицательные числа. `range(199, 0, -1)` остановится на 1 и честно вернёт только два числа.

---

**Итого.** Решение любой задачи этой темы собирается из одних и тех же частей:

1. перебрать нужные числа — `range(L, R + 1)`, по убыванию или с шагом;
2. перевести каждую часть условия в проверку — `%`, сравнения, `and`, `or`, проверки строки;
3. вывести то, что просит условие, в нужном порядке.

Делители, простые числа и маски в следующих подтемах — это новые проверки, которые встраиваются в ту же схему.
