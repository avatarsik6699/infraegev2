Главная идея подтемы: **маска описывает запись числа, а не его арифметические свойства, поэтому кандидатов можно либо проверять по маске, либо сразу строить по ней**. Маски с делимостью стабильно встречаются на экзамене с 2022 года: по подборкам это больше трети задач задания 25.

Работу со строками — `str`, `int`, `len` — мы разобрали в подтеме 1. Функция `get_divisors` из подтемы 2 понадобится в конце.

---

**Теперь перейдём к маскам: они описывают не арифметические свойства числа, а его запись цифрами.**

Маска — образец, с которым сравнивается десятичная запись числа.

В стандартных условиях задания:

- обычная цифра должна стоять на указанном месте;
- `?` заменяет ровно одну произвольную цифру;
- `*` заменяет последовательность цифр любой длины, в том числе нулевой.

Например:

```text
12?4
```

Ей соответствуют:

```text
1204
1214
1224
...
1294
```

Маске:

```text
12*4
```

соответствуют:

```text
124
1204
1234
12004
1234564
```

Здесь звёздочка последовательно обозначает:

- пустую строку;
- `0`;
- `3`;
- `00`;
- `3456`.

**Пустая строка и цифра 0 — разные вещи.**

Для маски:

```text
12*4
```

получаем:

| Что подставили вместо `*` | Число |
|---|---:|
| Ничего | 124 |
| `0` | 1204 |
| `00` | 12004 |

Если забыть пустой вариант, часть подходящих чисел будет потеряна.

Рассмотрим более сложную маску:

```text
12*3?
```

У неё фиксировано:

- начало `12`;
- затем произвольная вставка;
- затем цифра `3`;
- затем ровно одна цифра.

| Число | Подходит? | Разбор |
|---:|---|---|
| 1234 | Да | `12` + пустая строка + `3` + `4` |
| 12934 | Да | `12` + `9` + `3` + `4` |
| 120034 | Да | `12` + `00` + `3` + `4` |
| 12304 | Нет | Перед последней цифрой стоит 0, а требуется 3 |
| 123 | Нет | Не хватает обязательной цифры для `?` |

Тот же разбор на схеме: каждая цифра числа становится под ту часть маски, которой она соответствует.

<figure class="plate-figure">
%%mask_align("12*3?", ["1234", "120034", "12934", "12304", "123"])%%
<figcaption>Числа, разложенные по частям маски 12*3?. Звёздочка может забрать любое количество цифр, в том числе ни одной. Серые клетки — числа, которые разложить по маске нельзя.</figcaption>
</figure>

Если в маске несколько вопросительных знаков, каждый заполняется независимо. Они не обязаны обозначать одинаковые цифры.

Попробуй сам: поменяй маску или число и посмотри, как цифры распределяются по её частям. Например, проверь 12304, 1203 и 1239934 для маски `12*3?` или придумай свою маску.

Это удобно для определения возможной длины звёздочки.

Если маска:

```text
12*3?
```

то обязательных цифр четыре:

- две в `12`;
- одна `3`;
- одна для `?`.

Поэтому при ограничении до шестизначных чисел звёздочка может содержать:

0, 1, 2

цифры.

При произвольном ограничении `limit` безопасная верхняя оценка:

```python
max_star_length = len(str(limit)) - 4
```

После генерации всё равно нужно проверить:

```python
n <= limit
```

Количество цифр само по себе не гарантирует выполнение численной границы.

Например, числа 120000 и 999999 оба шестизначные, но при ограничении 200000 второе уже не подходит.

Также помни:

10⁹=1000000000

имеет **десять** цифр. Формулировки «меньше 10⁹» и «не больше 10⁹» отличаются включением этой границы.

---

**Проверить соответствие готового числа маске можно стандартной функцией `fnmatch`.**

Подключаем её:

```python
from fnmatch import fnmatch
```

Использование:

```python
fnmatch("1234", "12*3?")
```

Результат:

```text
True
```

А:

```python
fnmatch("12304", "12*3?")
```

даст:

```text
False
```

Общий вид:

```python
fnmatch(str(n), mask)
```

Первый аргумент — проверяемая строка, второй — маска.

Функция сопоставляет строку с шаблоном целиком. В самой `fnmatch` знаки `?` и `*` работают с произвольными символами; когда передаём `str(n)` для натурального числа, строка состоит только из цифр, поэтому это соответствует смыслу числовой маски. [Python 3.14.8 documentation](https://docs.python.org/3/library/fnmatch.html)

Например:

```python
from fnmatch import fnmatch

n = 120034

if fnmatch(str(n), "12*3?"):
    print(n)
```

Число будет выведено.

При этом `fnmatch` проверяет только маску. Она не проверяет автоматически:

- делимость числа;
- верхнюю границу;
- количество делителей;
- дополнительные ограничения.

Их нужно учитывать отдельно.

---

**Если число должно делиться на k, выгодно перебирать только кратные k.** Это первый основной способ решения задач на маски.

Положительные числа, кратные k:

k, 2k, 3k, 4k,…

Для их перебора у `range` есть третий аргумент — шаг:

```python
range(start, stop, step)
```

Например:

```python
for n in range(7, 31, 7):
    print(n)
```

Выведет:

```text
7
14
21
28
```

Каждый следующий кандидат больше предыдущего на 7.

Учебная задача:

> Найти числа не больше 99 999, запись которых соответствует маске `12*3?`, а сами числа делятся на 13. Вывести числа и частные.

```python
from fnmatch import fnmatch

limit = 99_999
divisor = 13

for n in range(divisor, limit + 1, divisor):
    if fnmatch(str(n), "12*3?"):
        print(n, n // divisor)
```

Подчёркивание в числе `99_999` нужно только для удобства чтения. Это то же значение, что `99999`.

Результат:

```text
1235 95
12038 926
12233 941
12337 949
12532 964
12636 972
12831 987
12935 995
```

Здесь уже обеспечено:

- положительность чисел — начали с 13;
- делимость на 13 — идём с шагом 13;
- верхняя граница — ограничили `range`;
- порядок возрастания — так устроен перебор.

Внутри цикла остаётся проверить маску.

Дополнительная проверка:

```python
n % 13 == 0
```

в этом конкретном цикле не нужна: она всегда будет истинной.

---

**При поиске кратных внутри отрезка важно правильно выбрать первое число.**

Ошибочная идея:

```python
for n in range(L, R + 1, k):
```

с предположением, что так перебираются кратные `k`.

На самом деле здесь перебираются:

L, L+k, L+2k,…

Если само `L` не кратно `k`, остальные числа тоже будут иметь тот же ненулевой остаток.

Например:

```python
range(100, 151, 23)
```

даёт:

```text
100, 123, 146
```

Ни одно из них не кратно 23.

Нужно сначала найти первое кратное, не меньше `L`.

Понятный вариант:

```python
start = L

if L % k != 0:
    start = L + (k - L % k)
```

Пример:

100=23·4+8.

До следующего кратного не хватает:

23-8=15.

Поэтому:

start=100+15=115.

Теперь:

```python
for n in range(start, R + 1, k):
    ...
```

будет давать нужные кратные.

Ту же границу можно вычислить одной формулой:

```python
start = ((L + k - 1) // k) * k
```

Она округляет отношение L/k вверх до целого, а затем умножает на `k`.

Для понимания достаточно сначала уверенно пользоваться вариантом через остаток.

---

**Второй основной способ решения масок — создавать числа сразу по маске.** Иногда это значительно быстрее перебора кратных.

Посмотрим на число проверок.

Если нужно искать до 10⁹ среди кратных 23, получится примерно:

10⁹/23 ≈ 43,5 млн

кандидатов.

Но если маска содержит только два вопросительных знака и больше никаких переменных мест, ей соответствуют всего:

10·10=100

записей — при условии, что первая цифра уже фиксирована и не равна нулю.

То есть вместо десятков миллионов проверок можно выполнить сто.

В задании № 45259 из вашей подборки используется маска `12345?7?8`, требуется делимость на 23, а верхняя граница равна 10⁹. [inf-ege.sdamgia.ru](https://inf-ege.sdamgia.ru/test?theme=246)

Обозначим цифры на местах вопросительных знаков через `a` и `b`.

```text
12345 a 7 b 8
```

Каждая принимает значения от 0 до 9.

```python
answers = []

for a in range(10):
    for b in range(10):
        s = "12345" + str(a) + "7" + str(b) + "8"
        n = int(s)

        if n <= 10 ** 9 and n % 23 == 0:
            answers.append(n)

for n in sorted(answers):
    print(n, n // 23)
```

`range(10)` означает:

```text
0, 1, 2, ..., 9
```

Вложенные циклы означают:

- для каждого значения `a`;
- перебрать все десять значений `b`.

Результат:

```text
123450798 5367426
123451718 5367466
123453788 5367556
123454708 5367596
123456778 5367686
123459768 5367816
```

Соответствие маске здесь гарантируется самим способом построения числа.

Можно собрать то же число арифметически:

n=123450708+1000a+10b.

Почему такие коэффициенты?

- `a` стоит в разряде тысяч;
- `b` стоит в разряде десятков.

Тогда внутренняя часть программы будет:

```python
n = 123450708 + 1000 * a + 10 * b
```

Строковый вариант обычно проще читать, а арифметический помогает увидеть связь маски с разрядами числа.

---

**Количество кандидатов нужно оценивать до запуска программы.** Это помогает выбрать между перебором кратных и генерацией по маске.

Для маски без звёздочек с q вопросительными знаками число комбинаций обычно:

10^q.

Если вопросительный знак стоит первым, нельзя разрешать ему принимать 0 в обычной записи многозначного числа.

Для одной звёздочки длиной от 0 до s количество вариантов её заполнения:

1+10+10²+…+10^s.

Почему первый член равен 1?

Потому что пустая строка — один вариант.

Далее:

- длина 1 — десять вариантов: `0`–`9`;
- длина 2 — сто вариантов: `00`–`99`;
- длина 3 — тысяча вариантов: `000`–`999`.

Если дополнительно есть q вопросительных знаков, количество сочетаний при фиксированном ненулевом начале:

10^q(1+10+…+10^s).

Пример:

```text
12*3?
```

При ограничении до шести цифр:

- один вопросительный знак;
- длина звёздочки от 0 до 2.

Получаем:

10(1+10+100)=1110

кандидатов.

Сравниваем это число с количеством кратных в разрешённом диапазоне и выбираем более короткий перебор.

При этом учитывать нужно и стоимость проверки. Найти остаток от деления обычно дешевле, чем полностью найти делители большого числа.

---

**Генерация звёздочки требует сохранять нули внутри подстановки.** Это одна из самых частых ошибок в задачах на маски.

Допустим, звёздочка должна заменять две цифры.

Нужны все варианты:

```text
00, 01, 02, ..., 09, 10, ..., 99
```

Но:

```python
str(7)
```

даёт:

```text
7
```

а не:

```text
07
```

Если напрямую использовать числа от 0 до 99, вставки `00`–`09` не будут представлены как двухсимвольные строки.

Для дополнения строки нулями слева есть метод `zfill`:

```python
str(7).zfill(2)     # "07"
str(0).zfill(2)     # "00"
str(42).zfill(2)    # "42"
str(7).zfill(3)     # "007"
```

Метод — это действие, вызываемое через точку у некоторого объекта. Здесь у строки вызывается действие «дополнить нулями до нужной длины».

Теперь построим числа по маске:

```text
12*3?
```

Уже знакомое условие:

- `n <= 99_999`;
- число кратно 13.

```python
limit = 99_999
divisor = 13

mandatory_length = 4
max_star_length = len(str(limit)) - mandatory_length

answers = []

for length in range(max_star_length + 1):
    for value in range(10 ** length):
        if length == 0:
            star = ""
        else:
            star = str(value).zfill(length)

        for digit in range(10):
            s = "12" + star + "3" + str(digit)
            n = int(s)

            if n <= limit and n % divisor == 0:
                answers.append(n)

for n in sorted(answers):
    print(n, n // divisor)
```

Разберём устройство по порядку.

```python
mandatory_length = 4
```

В маске четыре обязательные цифры. Звёздочка может добавить к ним новые.

```python
for length in range(max_star_length + 1):
```

Перебираем возможную длину вставки, начиная с нулевой.

```python
for value in range(10 ** length):
```

Перебираем значения, которыми можно заполнить вставку этой длины.

При `length == 2` это:

```text
0, 1, ..., 99
```

После `zfill(2)` получаем:

```text
00, 01, ..., 99
```

Но нулевая длина обрабатывается отдельно:

```python
if length == 0:
    star = ""
```

Почему это необходимо?

При нулевой длине:

```python
range(10 ** 0)
```

это `range(1)`, то есть один проход со значением 0.

Однако нам нужна не строка `"0"`, а отсутствие символов — `""`.

В данном примере верхняя граница пятизначная, поэтому звёздочка имеет длину 0 или 1. Если заменить `limit` на `999_999`, та же программа автоматически начнёт рассматривать и двухсимвольные вставки, включая `00`.

**Нули внутри числа не исчезают при преобразовании всей записи в `int`.**

Например:

```python
int("12" + "00" + "3" + "4")
```

даёт:

```text
120034
```

Проблема возникает тогда, когда мы потеряли нужные нули ещё до соединения частей.

---

**Начальные нули и несколько звёздочек требуют отдельного внимания.**

Обычная десятичная запись натурального числа не начинается с нуля.

Например:

```python
int("0123")
```

даёт число 123.

Его запись:

```python
str(123)
```

равна `"123"`, а не `"0123"`.

Поэтому при генерации четырёхзначного числа по маске:

```text
?123
```

первый вопросительный знак должен принимать значения от 1 до 9:

```python
for first_digit in range(1, 10):
    n = int(str(first_digit) + "123")
```

Если маска начинается со звёздочки или устроена сложнее, полезно дополнительно проверять уже полученное число:

```python
fnmatch(str(n), mask)
```

Это позволяет сравнить с маской именно обычную запись числа.

При нескольких звёздочках одно число иногда можно получить разными способами.

Например, маска:

```text
1*2*3
```

Число 1223 можно собрать так:

```text
1 + "" + 2 + "2" + 3
```

или так:

```text
1 + "2" + 2 + "" + 3
```

Число одно, а способов подстановки два.

Если генерация допускает такие совпадения, результаты удобно складывать в множество:

```python
answers = set()
```

Добавление в множество:

```python
answers.add(n)
```

После завершения:

```python
for n in sorted(answers):
    print(n)
```

Повторов не будет.

Для масок с несколькими звёздочками перебор кратных с проверкой `fnmatch` часто оказывается проще по устройству. Его всё равно нужно предварительно оценить по количеству кандидатов.

---

**Условия на маску и делители можно объединять в одной программе.** Здесь полезно сначала выполнять проверки, которые быстро отбрасывают неподходящие числа.

Предположим, задача требует:

- число соответствует маске;
- делится на заданное `k`;
- имеет ровно определённое количество делителей.

Разумный порядок:

1. получить кратные `k` или сразу сгенерировать числа по маске;
2. проверить оставшееся простое условие;
3. только затем искать делители.

Иллюстрация:

```python
from fnmatch import fnmatch

limit = 100_000
k = 37

for n in range(k, limit + 1, k):
    if fnmatch(str(n), "1?2*"):
        D = get_divisors(n)

        if len(D) == 8:
            print(n)
```

Сначала отбирается небольшая часть кандидатов по маске. Полный поиск делителей выполняется только для них.

Аналогично маска может относиться не к исходному числу, а к его делителю:

```python
selected = []

for d in get_divisors(n):
    if fnmatch(str(d), "1*7"):
        selected.append(d)
```

Здесь ищутся делители, запись которых начинается на 1 и заканчивается на 7 с допустимой вставкой между ними.

Сначала нужно определить **объект условия**:

- маска самого числа;
- маска делителя;
- окончание суммы делителей;
- простота вычисленной величины.

В коде эти проверки могут выглядеть похоже, но выполняться над разными переменными.

---

**Определение знаков маски всегда читаем в условии.** В тренировочных работах встречаются маски, где `?` означает не любую цифру, а только **чётную** или только **нечётную**.

`fnmatch` позволяет записать набор допустимых символов в квадратных скобках: `[02468]` — одна чётная цифра, `[13579]` — одна нечётная.

Например, если `?` в маске `5?8*1` означает чётную цифру, ту же маску для `fnmatch` пишем так:

```python
from fnmatch import fnmatch

count = 0

for n in range(701, 10 ** 7 + 1, 701):
    if fnmatch(str(n), "5[02468]8*1"):
        count += 1

print(count)
```

Программа выведет:

```text
9
```

Здесь перебираются кратные 701 не больше 10⁷, и подсчитываются числа, подходящие под маску с чётной цифрой на втором месте.

Если же генерируешь числа по маске сам, вместо `range(10)` для такого `?` перебирай `[0, 2, 4, 6, 8]`.

---

**Коротко.**

- `?` — ровно одна цифра; `*` — любая последовательность, **в том числе пустая**.
- Готовое число проверяем `fnmatch(str(n), mask)`. Сама маска не проверяет делимость и границы.
- При делимости на k перебираем кратные: `range(первое_кратное, R + 1, k)`.
- Если переменных мест мало, строим числа по маске. Вставки звёздочки дополняем нулями: `zfill`.
- Перед запуском оцениваем число кандидатов обоими способами и выбираем меньший перебор.
