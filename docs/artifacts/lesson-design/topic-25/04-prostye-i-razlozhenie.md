Главная идея подтемы: **каждое число больше 1 раскладывается на простые множители, и по этому разложению сразу видны все его простые делители**. Это самый частый приём в задачах 2025–2026 годов: он нужен в 16 из 27 задач этих лет, в том числе в задачах основной волны ЕГЭ-2026.

Функцию `get_divisors` из подтемы 2 считаем определённой выше в программе.

---

**Простые числа нужны тогда, когда условие говорит именно о простых делителях или простых множителях.** Дадим точное определение.

**Простое число** — натуральное число больше 1, имеющее ровно два натуральных делителя:

1 и само число.

Например:

2, 3, 5, 7, 11, 13, 17.

**Составное число** — натуральное число больше 1, имеющее делитель, отличный от 1 и самого числа.

Например, 12 составное, поскольку делится на 2, 3, 4 и 6.

Число 1:

- не простое;
- не составное.

У него только один натуральный делитель.

Чтобы проверить простоту, не обязательно искать все делители. Достаточно попытаться найти хотя бы один делитель между 2 и √n.

```python
def is_prime(n):
    if n < 2:
        return False

    for d in range(2, isqrt(n) + 1):
        if n % d == 0:
            return False

    return True
```

Логика:

1. Числа меньше 2 не являются простыми.
2. Если найден хотя бы один нетривиальный делитель, число составное.
3. Если весь необходимый перебор закончился и делителей нет, число простое.

Почему достаточно корня?

Если число составное, оно представляется произведением двух чисел больше 1. Хотя бы одно из них не превосходит корня. Это уже доказанное свойство пар делителей.

Почему `return True` стоит после цикла?

После одной неудачной попытки деления ещё нельзя объявлять число простым.

Например, 25 не делится на 2. Но оно делится на 5. Если вернуть `True` сразу после проверки 2, получится ошибка.

Проверки:

```python
is_prime(1)    # False
is_prime(2)    # True
is_prime(49)   # False
is_prime(97)   # True
```

У 2 цикл не выполнится ни разу: между 2 и `isqrt(2)` нет проверяемых чисел. После предварительной проверки `n < 2` это нормальная ситуация, и функция вернёт `True`.

Теперь можно найти простые делители:

```python
n = 84
D = get_divisors(n)

prime_divisors = []

for d in D:
    if is_prime(d):
        prime_divisors.append(d)

print(prime_divisors)
```

Получим:

```text
[2, 3, 7]
```

Такой способ понятен, но если требуются только простые делители, удобнее использовать разложение на простые множители.

---

**Разложение на простые множители показывает, из каких простых чисел составлено исходное число.** Это не то же самое, что список всех его делителей.

Например:

72=2·2·2·3·3.

Одинаковые множители можно объединить в степени:

72=2³·3².

Здесь:

- двойка встречается три раза;
- тройка встречается два раза.

Сравним три разных объекта:

| Что рассматриваем | Для числа 72 |
|---|---|
| Все натуральные делители | 1, 2, 3, 4, 6, 8, 9, 12, 18, 24, 36, 72 |
| Различные простые делители | 2, 3 |
| Простые множители с повторениями | 2, 2, 2, 3, 3 |

Поэтому:

- различных простых делителей — 2;
- простых множителей с учётом повторений — 5;
- всех натуральных делителей — 12.

Эти количества нельзя смешивать.

Разложение можно получить последовательным делением.

Возьмём:

360.

Делим на 2, пока это возможно:

360 → 180 → 90 → 45.

Мы извлекли три двойки.

Теперь делим оставшееся 45 на 3:

45 → 15 → 5.

Извлекли две тройки.

Остался простой множитель 5:

360=2³·3²·5.

В тетради такое разложение удобно записывать «лесенкой»: слева то, что осталось от числа, справа — простой множитель, на который делим.

<figure class="plate-figure">
%%ladder(360)%%
<figcaption>Разложение 360 лесенкой. Каждая строка — одно деление. Правый столбец сверху вниз и есть все простые множители с повторениями.</figcaption>
</figure>

Программа:

```python
def prime_factors(n):
    factors = []
    m = n
    d = 2

    while d * d <= m:
        while m % d == 0:
            factors.append(d)
            m //= d

        d += 1

    if m > 1:
        factors.append(m)

    return factors
```

Разберём несколько непривычных моментов.

```python
m = n
```

Создаём рабочую копию числа. Её будем уменьшать делением.

```python
m //= d
```

означает:

```python
m = m // d
```

Внутренний цикл:

```python
while m % d == 0:
```

нужен, чтобы извлечь **все повторения** множителя `d`.

Если написать здесь `if`, получится удалить только один множитель. Например, у 72 будет извлечена только одна двойка вместо трёх.

Посмотрим, как программа работает на числе 1050. На нём видно всё сразу: множитель 5 повторяется, составной кандидат 4 проверяется, но ничего не делит, а после цикла остаётся последний множитель.

%%factor_stepper(1050)%%

Теперь ответим на два вопроса, которые возникают при чтении кода.

Почему перебираем не только простые значения `d`, но в список всё равно попадают простые множители?

Когда мы дойдём до составного `d`, его меньшие простые множители уже были полностью удалены из `m`. Поэтому составное `d` уже не сможет разделить оставшееся число.

Почему после цикла остаток `m > 1` можно добавить как простой множитель?

Если бы остаток был составным, у него существовал бы делитель не больше квадратного корня. Такой делитель должен был быть найден в процессе проверки. Раз цикл завершился после удаления меньших множителей, оставшееся число больше 1 является простым.

Пример:

```python
print(prime_factors(360))
```

Результат:

```text
[2, 2, 2, 3, 3, 5]
```

Чтобы удалить повторения, можно использовать **множество** — коллекцию, в которой каждое значение хранится один раз:

```python
set([2, 2, 2, 3, 3, 5])
```

содержит только 2, 3 и 5.

Если нужен упорядоченный список:

```python
unique_factors = sorted(set(prime_factors(360)))
print(unique_factors)
```

Получим:

```text
[2, 3, 5]
```

Множество само по себе не следует использовать как отсортированный список. Для выбора первого, последнего и других элементов сначала применяем `sorted`.

---

**Простые делители числа — это различные множители его разложения.**

Чтобы получить их по возрастанию, достаточно убрать повторы и отсортировать:

```python
print(sorted(set(prime_factors(84))))
print(sorted(set(prime_factors(72))))
```

Программа выведет:

```text
[2, 3, 7]
[2, 3]
```

Это быстрее, чем искать все делители и проверять каждый на простоту. Разложение делает не больше √n шагов и сразу выдаёт только простые числа.

Теперь любые величины из условия получаются из этого списка `P`:

| Что требуется | Выражение |
|---|---|
| Наименьший простой делитель | `P[0]` |
| Наибольший простой делитель | `P[-1]` |
| Сумма наименьшего и наибольшего | `P[0] + P[-1]` |
| Сумма всех различных простых делителей | `sum(P)` |
| Количество различных простых делителей | `len(P)` |

**«Не считая самого числа» меняет ответ только для простых чисел.** У простого числа 97 разложение — `[97]`. Его единственный простой делитель — оно само. Если условие говорит «не считая самого числа», список становится пустым, и величину нужно взять такой, как велит условие (обычно 0).

```python
def prime_divisors(n):
    P = sorted(set(prime_factors(n)))
    return [p for p in P if p != n]

print(prime_divisors(84))
print(prime_divisors(97))
print(prime_divisors(49))
```

Программа выведет:

```text
[2, 3, 7]
[]
[7]
```

У 49 = 7·7 простой делитель 7 не совпадает с самим числом, поэтому он остаётся.

---

**«Произведение ровно двух простых множителей» и «ровно два различных простых делителя» — разные условия.**

| Число | Разложение | Множителей с повторениями | Различных простых делителей |
|---:|---|---:|---:|
| 15 | 3 · 5 | 2 | 2 |
| 9 | 3 · 3 | 2 | 1 |
| 12 | 2 · 2 · 3 | 3 | 2 |
| 30 | 2 · 3 · 5 | 3 | 3 |
| 8 | 2 · 2 · 2 | 3 | 1 |

Поэтому:

- «представимо в виде произведения ровно двух простых множителей, **не обязательно различных**» — `len(prime_factors(n)) == 2`. Подходят 15 и 9;
- «имеет ровно два **различных** простых делителя» — `len(set(prime_factors(n))) == 2`. Подходят 15 и 12.

Слова «не обязательно различных» в условии важны: они разрешают квадраты простых чисел вроде 9 = 3 · 3.

**Условие на цифры множителей проверяется у каждого множителя отдельно.**

Учебное условие:

> Найти три наименьших числа, больших 100, которые представимы в виде произведения ровно двух простых множителей, не обязательно различных, и каждый из множителей содержит в записи цифру 1.

Рабочая запись:

```text
Для n = 101, 102, …:
  разложить n на простые множители;
  множителей ровно два?
  в записи каждого есть цифра 1?
Остановиться после третьего найденного.
```

Программа:

```python
n = 101
found = 0

while found < 3:
    f = prime_factors(n)
    if len(f) == 2 and all("1" in str(p) for p in f):
        print(n, f)
        found += 1
    n += 1
```

Программа выведет:

```text
121 [11, 11]
143 [11, 13]
169 [13, 13]
```

Новая конструкция:

```python
all("1" in str(p) for p in f)
```

`all` возвращает `True`, если условие выполнено **для каждого** элемента. Её можно прочитать так:

> Для каждого множителя `p` из `f` проверить, что в его записи есть `1`; ответ «да», только если это верно для всех.

Похожая функция `any` возвращает `True`, если условие выполнено **хотя бы для одного** элемента. В условии «хотя бы один из множителей содержит цифру…» нужна она.

Обрати внимание на 121 = 11 · 11: множители одинаковые, и условие «не обязательно различных» это разрешает.

---

**Разложение работает быстро даже для чисел около 10¹⁰.** Цикл проверяет d только пока d·d не больше оставшегося числа. В худшем случае, когда число простое, это около √n шагов. Для числа около 5·10⁹ это примерно 70 тысяч проверок, а для большинства чисел намного меньше: маленькие множители быстро уменьшают m.

Поэтому задачи вида «перебирать числа больше 4 500 000 000 и найти первые пять подходящих» решаются прямым перебором с разложением. Нужные числа встречаются часто, и перебрать придётся немного.

---

**Коротко.**

- Простое число имеет ровно два делителя; 1 не простое. Простоту проверяем до √n.
- Разложение: делим на d, пока делится (`while`, не `if`), потом переходим к следующему d; остаток больше 1 — последний простой множитель.
- Простые делители — `sorted(set(prime_factors(n)))`; «не считая самого числа» убирает n у простых чисел.
- «Ровно k простых множителей» — длина разложения с повторениями; «k различных простых делителей» — длина множества.
- Условие на цифры каждого множителя — `all(...)`, хотя бы одного — `any(...)`.
