**Даже правильный алгоритм может оказаться слишком медленным, если не учитывать размер всего поиска.**

Для одного числа поиск делителей до корня требует примерно:

√n

проверок делимости.

Если проверяем N чисел примерно одного размера, количество таких проверок будет порядка:

N√n.

Например, для 100 тысяч чисел около 10⁹:

100 000·31 622 ≈ 3,16 млрд.

Это уже очень много.

Поэтому фраза «я использовал перебор до корня» ещё не гарантирует достаточную скорость всей программы.

Полезно сравнивать способы:

| Ситуация | Подход |
|---|---|
| Небольшой отрезок, нужны делители | Перебор чисел и поиск пар делителей |
| Нужно только количество делителей | Счётчик без списка |
| Нужно ровно `k` делителей | Прекращать проверку после превышения `k` |
| Нужен минимальный делитель | Остановиться на первом найденном |
| Нужны минимальный и максимальный делители без 1 и `n` | Найти минимальный и получить парный |
| Маска с немногими переменными цифрами | Генерировать числа по маске |
| Маска сложная, а кратных в диапазоне немного | Перебирать кратные и проверять маску |
| Задано небольшое точное количество делителей | Проверить, можно ли вывести форму числа |
| Несколько ограничений | Сначала применять дешёвые проверки |

Не стоит запоминать утверждения вроде «`fnmatch` всегда быстрый» или «генерация по маске всегда лучше».

Сравнивать нужно конкретные количества кандидатов в конкретной задаче.

**Правильность решения удобно проверять тремя вопросами.**

**Первый: может ли программа пропустить подходящее число?**

Например:

- включена ли правая граница;
- начинается ли поиск с правильного значения;
- учтена ли пустая звёздочка;
- сохраняются ли подстановки с нулями;
- все ли пары делителей рассматриваются.

**Второй: может ли программа принять неподходящее число?**

Например:

- исключены ли 1 и само число, если это требуется;
- проверяется ли именно нужная величина;
- не перепутаны ли «ровно» и «не менее»;
- не заменена ли проверка двух различных делителей повторным использованием одного.

**Третий: соответствует ли вывод условию?**

В разных задачах могут требоваться:

- сами числа;
- только делители;
- число и сумма;
- число и частное;
- количество делителей и само число;
- результаты в порядке возрастания другой величины.

Если задача просит только делители, дополнительный столбец с исходным числом не нужен.

Если найденные числа уже идут по возрастанию, но вывод требуется по значению M, порядок чисел не гарантирует нужный порядок M. Тогда следует сохранить результаты и упорядочить их по требуемому признаку.

Например, если первым элементом каждой сохранённой строки сделать M, обычная сортировка сначала сравнит именно его:

```python
rows = []

# При нахождении ответа:
rows.append((M, n))
```

Запись `(M, n)` — пара значений. Такие пары Python сравнивает сначала по первому элементу, а при равенстве — по второму.

```python
for M, n in sorted(rows):
    print(n, M)
```

Так вывод будет упорядочен по M, а при равных M — по `n`.

Использовать такое правило нужно только тогда, когда оно соответствует условию.

**Перед большой задачей полезно проверить вспомогательную функцию на нескольких маленьких числах.** Эти примеры обнаруживают разные классы ошибок.

Для `get_divisors`:

| Число | Ожидаемые делители | Что проверяем |
|---:|---|---|
| 1 | `[1]` | Совпадение единицы и самого числа |
| 2 | `[1, 2]` | Маленькое простое число |
| 12 | `[1, 2, 3, 4, 6, 12]` | Обычные пары |
| 16 | `[1, 2, 4, 8, 16]` | Корень должен встретиться один раз |
| 49 | `[1, 7, 49]` | Корень нельзя пропускать |

Для маски `12*3?`:

| Строка | Ожидаемый результат |
|---|---|
| `"1234"` | Подходит: звёздочка пустая |
| `"12034"` | Подходит: звёздочка равна `"0"` |
| `"120034"` | Подходит: звёздочка равна `"00"` |
| `"12304"` | Не подходит |
| `"123"` | Не подходит |

Основные алгоритмы и численные примеры выше проверены программно. При написании собственных вариантов особенно следи за следующими ошибками:

| Ошибка | Почему возникает неверный результат |
|---|---|
| `range(L, R)` для включённого отрезка | Число `R` не проверяется |
| Перебор до корня без включения корня | Теряется делитель у квадратов |
| Безусловное добавление обоих членов пары | Корень учитывается дважды |
| Выбор `D[-1]` до сортировки | Последний найденный делитель не обязательно максимальный |
| Возврат успеха, как только найдено `k` делителей | Дальше могут найтись дополнительные |
| Проверка только чётных маленьких делителей | Теряются чётные парные делители нечётных чисел |
| Исключение 1 и `n` без указания в условии | Считается другое множество делителей |
| Смешение простых делителей и множителей с повторениями | Получается другое количество |
| Пропуск пустой звёздочки | Теряются числа минимальной длины |
| Подстановка `str(value)` без учёта длины | Теряются вставки с начальными нулями |
| Сортировка записей чисел как строк | Порядок может отличаться от числового |
| Проверка `M % k == 0` без внимания к `M = 0` | Ноль может ошибочно попасть в ответ |

Например:

```python
sorted(["2", "10", "100"])
```

даёт:

```text
["10", "100", "2"]
```

Потому что строки сравниваются по символам.

А:

```python
sorted([2, 10, 100])
```

даёт правильный числовой порядок:

```text
[2, 10, 100]
```
