**Даже правильный алгоритм может оказаться слишком медленным, если не учитывать размер всего поиска.**

Для одного числа поиск делителей до корня требует примерно √n проверок делимости. Если проверяем N чисел примерно одного размера, проверок будет порядка N√n. Для 100 тысяч чисел около 10⁹ это 100 000 · 31 622 ≈ 3,16 млрд — уже очень много. Поэтому фраза «я использовал перебор до корня» ещё не гарантирует достаточную скорость всей программы.

Подход выбирают по ситуации. Выберите ситуацию, чтобы увидеть подходящий приём:

:::pick Ситуация в задаче и подходящий подход
- *небольшой отрезок, нужны делители | перебор чисел и поиск пар делителей
- нужно только количество делителей | счётчик без списка
- нужно ровно `k` делителей | прекращать проверку после превышения `k`
- нужен минимальный делитель | остановиться на первом найденном
- минимальный и максимальный без 1 и `n` | найти минимальный и получить парный
- маска с немногими переменными цифрами | генерировать числа по маске
- маска сложная, кратных немного | перебирать кратные и проверять маску
- задано небольшое точное количество делителей | проверить, можно ли вывести форму числа
- несколько ограничений | сначала применять дешёвые проверки
:::

Не стоит запоминать утверждения вроде «`fnmatch` всегда быстрый» или «генерация по маске всегда лучше». Сравнивать нужно конкретные количества кандидатов в конкретной задаче.

**Правильность решения удобно проверять тремя вопросами.**

**Первый: может ли программа пропустить подходящее число?** Включена ли правая граница, начинается ли поиск с правильного значения, учтена ли пустая звёздочка, сохраняются ли подстановки с нулями, все ли пары делителей рассматриваются.

**Второй: может ли программа принять неподходящее число?** Исключены ли 1 и само число, если это требуется; проверяется ли именно нужная величина; не перепутаны ли «ровно» и «не менее»; не заменена ли проверка двух различных делителей повторным использованием одного.

**Третий: соответствует ли вывод условию?** Задачи просят разное: сами числа, только делители, число и сумму, число и частное, количество делителей и само число, результаты в порядке возрастания другой величины. Если задача просит только делители, дополнительный столбец с исходным числом не нужен.

Если найденные числа идут по возрастанию, а вывод требуется по значению M, порядок чисел не гарантирует нужный порядок M. Тогда результаты сохраняют и упорядочивают по требуемому признаку. Удобно сделать M первым элементом каждой сохранённой пары `(M, n)`: такие пары Python сравнивает сначала по первому элементу, а при равенстве — по второму.

```python
rows = []

# При нахождении ответа:
rows.append((M, n))
```

```python
for M, n in sorted(rows):
    print(n, M)
```

Так вывод будет упорядочен по M, а при равных M — по `n`. Использовать такое правило нужно только тогда, когда оно соответствует условию.

**Перед большой задачей полезно проверить вспомогательную функцию на нескольких маленьких числах.** Эти примеры обнаруживают разные классы ошибок.

Для `get_divisors` хватает пяти чисел: у 1 единица и само число совпадают, 2 — маленькое простое, у 12 обычные пары, а у 16 и 49 корень должен встретиться ровно один раз и не потеряться.

```python
for n in [1, 2, 12, 16, 49]:
    print(n, get_divisors(n))
```

```output
1 [1]
2 [1, 2]
12 [1, 2, 3, 4, 6, 12]
16 [1, 2, 4, 8, 16]
49 [1, 7, 49]
```

Для маски `12*3?` проверяем пустую звёздочку (`1234`), звёздочку `0` и `00` (`12034`, `120034`) и два неподходящих числа:

```python
from fnmatch import fnmatch

for s in ["1234", "12034", "120034", "12304", "123"]:
    print(s, fnmatch(s, "12*3?"))
```

```output
1234 True
12034 True
120034 True
12304 False
123 False
```

Основные алгоритмы и численные примеры выше проверены программно. При написании собственных вариантов особенно следите за типичными ошибками — выберите ошибку, чтобы увидеть, почему она даёт неверный результат:

:::pick Типичная ошибка и почему результат неверен
- *`range(L, R)` для отрезка | число `R` не проверяется
- корень не включён | теряется делитель у квадратов
- оба члена пары без проверки | корень учитывается дважды
- `D[-1]` до сортировки | последний найденный делитель не обязательно максимальный
- «успех» при k делителях | дальше могут найтись дополнительные
- только чётные маленькие `d` | теряются чётные парные делители нечётных чисел
- лишнее исключение 1 и `n` | считается другое множество делителей
- простые делители и множители | смешение даёт другое количество
- пустая звёздочка забыта | теряются числа минимальной длины
- `str(value)` без длины | теряются вставки с начальными нулями
- сортировка записей как строк | порядок отличается от числового
- `M % k == 0` при `M = 0` | ноль может ошибочно попасть в ответ
:::

Последняя ловушка со строками видна на примере: строки сравниваются по символам, поэтому `"2"` оказывается после `"100"`.

```python
print(sorted(["2", "10", "100"]))
print(sorted([2, 10, 100]))
```

```output
['10', '100', '2']
[2, 10, 100]
```
