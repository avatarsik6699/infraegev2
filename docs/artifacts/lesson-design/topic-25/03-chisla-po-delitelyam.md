Главная идея подтемы: **задача «найти числа с нужными делителями» — это перебор чисел из подтемы 1, внутри которого работает поиск делителей из подтемы 2**. Меняется только то, что мы вычисляем по найденным делителям и как выбираем ответ.

Функции `get_divisors` и `count_divisors` из подтемы 2 считаем определёнными выше в программе.

---

**Разберём полностью задачу на точное количество делителей.** Возьмём небольшой диапазон, чтобы результат можно было проверить вручную.

Учебное условие:

> Найти все числа от 10 до 30 включительно, у которых ровно два различных делителя, не считая единицы и самого числа. Вывести число и эти два делителя.

Сначала переведём условие:

- перебираем `n` от 10 до 30;
- получаем все делители;
- исключаем 1 и `n`;
- проверяем, что осталось ровно два;
- выводим нужные значения.

```python
for n in range(10, 31):
    D = [d for d in get_divisors(n) if 1 < d < n]

    if len(D) == 2:
        print(n, D[0], D[1])
```

Результат:

```text
10 2 5
14 2 7
15 3 5
21 3 7
22 2 11
26 2 13
27 3 9
```

Посмотрим на отдельные числа.

Для 10:

1, 2, 5, 10.

После исключения 1 и 10:

2, 5.

Осталось два — подходит.

Для 12:

1, 2, 3, 4, 6, 12.

После исключения крайних:

2, 3, 4, 6.

Осталось четыре — не подходит.

Для 27:

1, 3, 9, 27.

После исключения крайних:

3, 9.

Подходит.

Это хороший пример того, почему нельзя заменять условие «два делителя» условием «два простых делителя». У числа 27 среди выбранных делителей находится составное число 9.

Если требуются ровно четыре чётных делителя, изменение небольшое:

```python
for n in range(10, 31):
    D = [d for d in get_divisors(n) if d % 2 == 0]

    if len(D) == 4:
        print(n, *D)
```

Здесь `print(n, *D)` выводит число `n`, а затем все элементы списка `D` через пробел. Звёздочка перед списком означает передачу его элементов как отдельных аргументов функции.

Результат:

```text
12 2 4 6 12
16 2 4 8 16
20 2 4 10 20
28 2 4 14 28
30 2 6 10 30
```

Само число здесь может учитываться: условие требует чётные делители и не исключает `n`.

**В задачах на максимальное количество делителей нужно хранить текущий лучший результат.** Рассмотрим условие:

> Среди чисел от 10 до 30 найти число с наибольшим количеством делителей. Если таких чисел несколько, выбрать наименьшее.

Нам нужны две переменные:

- лучшее найденное количество делителей;
- число, которому это количество соответствует.

```python
L = 10
R = 30

best_count = 0
best_number = L

for n in range(L, R + 1):
    current_count = count_divisors(n)

    if current_count > best_count:
        best_count = current_count
        best_number = n

print(best_count, best_number)
```

Результат:

```text
8 24
```

Почему при равном количестве делителей сохраняется минимальное число?

Перебор идёт по возрастанию. Число 24 встретится раньше 30.

У обоих по восемь делителей, но проверка:

```python
current_count > best_count
```

не выполнится при равенстве. Поэтому 24 не будет заменено на 30.

Если при той же организации перебора написать:

```python
current_count >= best_count
```

то при равенстве предыдущее число будет заменяться новым, большим. В итоге выберется максимальное из чисел с одинаковым количеством делителей.

**Знак `>` или `>=` здесь определяется правилом выбора при равенстве.**

---

**Буква M в условии обычно обозначает некоторую вычисляемую величину, а не особый алгоритм.** Нужно внимательно прочитать, как она определена.

Например:

> M — сумма двух наибольших различных делителей числа, не считая самого числа и единицы. Если таких делителей меньше двух, M=0.

Перевод в код:

```python
D = [d for d in get_divisors(n) if 1 < d < n]

if len(D) >= 2:
    M = D[-1] + D[-2]
else:
    M = 0
```

Для 48:

D=[2,3,4,6,8,12,16,24].

Два наибольших:

24, 16.

Поэтому:

M=24+16=40.

Другие определения потребуют других действий:

| Определение величины | Вычисление после нужного отбора |
|---|---|
| Сумма всех выбранных делителей | `sum(D)` |
| Разность наибольшего и наименьшего | `D[-1] - D[0]` |
| Произведение двух наименьших | `D[0] * D[1]` |
| Сумма трёх наибольших | `sum(D[-3:])` |
| Количество выбранных делителей | `len(D)` |

У каждой формулы должны быть проверены условия существования нужных элементов.

Особенно внимательно относись к значению 0, которое иногда задаётся при отсутствии делителей.

Например:

```python
M % 10 == 0
```

истинно и при `M == 0`.

Следовательно, если по условию требуется **положительное** значение M, оканчивающееся нулём, проверка должна быть такой:

```python
M > 0 and M % 10 == 0
```

Но если условие допускает ноль, исключать его самостоятельно нельзя.

**Наименьший и наибольший делители, кроме 1 и самого числа, связаны друг с другом.** Это позволяет иногда обойтись без полного списка.

Посмотрим на пары делителей 84:

<figure class="plate-figure">
%%arcs(84, emphasize=(2, 42), mute=(1, 84), ordinal=True)%%
<figcaption>Пары делителей 84; делители расставлены по порядку на равных расстояниях, чтобы подписи читались. Внешняя дуга (1, 84) по условию не учитывается — она пунктирная. Следующая, жирная дуга (2, 42) — самая широкая из оставшихся: её левый конец — наименьший делитель больше 1, правый — наибольший делитель меньше 84.</figcaption>
</figure>

Дуги вложены друг в друга: чем левее начинается дуга, тем правее она заканчивается. Поэтому наименьший делитель больше 1 и наибольший делитель меньше n всегда оказываются концами одной дуги. Достаточно найти наименьший — второй получится делением.

Почему так всегда? Пусть a — наименьший делитель числа n, больший единицы. Предполагаем, что такой делитель меньше самого n, то есть число составное.

Тогда:

b=n/a

— наибольший делитель, меньший самого числа.

Почему?

Любой делитель b<n образует пару с:

a=n/b>1.

Чем больше один множитель при фиксированном произведении n, тем меньше другой.

Поэтому:

- самому маленькому делителю больше 1;
- соответствует самый большой делитель меньше n.

Например, для 84 наименьший делитель больше единицы — 2.

Значит, наибольший делитель меньше 84:

84:2=42.

Для 105 наименьший делитель больше единицы — 3.

Значит, наибольший:

105:3=35.

Если M определено как сумма наименьшего и наибольшего делителей без единицы и самого числа, можно написать:

```python
def calc_m(n):
    for d in range(2, isqrt(n) + 1):
        if n % d == 0:
            return d + n // d

    return 0
```

Здесь:

- начинаем с 2, потому что единица исключена;
- перебираем по возрастанию;
- первый найденный делитель — наименьший;
- парный к нему — наибольший;
- сразу возвращаем их сумму;
- если делителей не найдено, возвращаем 0.

Например:

```python
calc_m(84)    # 2 + 42 = 44
calc_m(105)   # 3 + 35 = 38
calc_m(13)    # 0
```

У числа 49 единственный делитель без 1 и 49 — это 7. Он одновременно наименьший и наибольший.

Поэтому для определения **«сумма наименьшего и наибольшего»** получится:

7+7=14,

если условие допускает такой случай.

Но для определения **«сумма двух различных делителей»** одного делителя недостаточно.

Это два разных условия, хотя формулировки выглядят похожими.

**Если нужно найти первые несколько подходящих чисел после заданной границы, верхнюю границу не следует придумывать.** Лучше продолжать поиск, пока не найдено нужное количество ответов.

Для этого используется цикл `while` — «пока».

```python
while условие:
    действия
```

Перед каждым повторением Python проверяет условие. Пока оно истинно, действия выполняются.

Рассмотрим учебную задачу:

> Найти пять наименьших чисел, больших 100, для которых сумма наименьшего и наибольшего делителей без единицы и самого числа положительна и оканчивается на 0.

Функция `calc_m` уже определена выше.

```python
n = 101
found = 0

while found < 5:
    M = calc_m(n)

    if M > 0 and M % 10 == 0:
        print(n, M)
        found += 1

    n += 1
```

Результат:

```text
111 40
116 60
125 30
136 70
141 50
```

Разберём устройство поиска.

```python
n = 101
```

Начинаем с 101, поскольку требуется число **больше** 100.

```python
found = 0
```

Пока не найдено ни одного подходящего числа.

```python
while found < 5:
```

Продолжаем поиск, пока найдено меньше пяти.

```python
found += 1
```

Увеличиваем счётчик только после успешной проверки.

```python
n += 1
```

Переходим к следующему числу независимо от того, подошло текущее или нет.

Почему получаются именно пять наименьших?

Мы просматриваем числа строго по возрастанию и не пропускаем ни одного кандидата. Значит, первые пять успешных проверок соответствуют пяти наименьшим решениям.

Такой поиск предполагает, что требуемые решения существуют. Если задача задаёт конечный диапазон, нужно соблюдать и его верхнюю границу.

**Коротко.**

- Сначала переводим определение величины из условия в код: какие делители отбираем, что по ним считаем, что делать, если делителей не хватает.
- Для «максимального количества» храним лучший результат. Знак `>` или `>=` выбираем по правилу при равенстве.
- Наименьший делитель больше 1 и наибольший меньше n — это одна пара: хватает поиска до первого делителя.
- «Первые пять после границы» ищем циклом `while` без придуманной верхней границы.
- Значение 0 «при отсутствии делителей» проверяем отдельно: `M > 0`, если условие требует положительное M.
