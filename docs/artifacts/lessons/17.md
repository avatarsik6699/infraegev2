**Последовательность — это числа, расположенные в определённом порядке.**

Например:

```text
8, -12, 5, 20, -3, 14
```

Здесь шесть элементов.

Слово «элемент» означает число **на определённом месте**. Порядок существенен: последовательности

```text
8, -12, 5
```

и

```text
5, 8, -12
```

содержат одинаковые числа, но соседство у них разное.

Одинаковые значения могут встречаться несколько раз:

```text
7, 7, 12
```

Первые две семёрки — два разных элемента, потому что находятся на разных местах.

Отсюда сразу два важных правила:

- нельзя удалять повторяющиеся значения, если этого не требует условие;
- нельзя переставлять числа, если задача связана с их расположением.

**Количество элементов и величина элементов — разные характеристики.**

В последовательности

```text
10000, -5000, 300
```

три элемента. Число `10000` — значение первого элемента, а не длина последовательности.

Если в условии сказано «числа по модулю не превышают 100 000», это ограничивает их значения. Из этого не следует, что в файле ровно 100 000 чисел.

**В Python последовательность удобно хранить в списке.**

Список — это упорядоченное хранилище значений:

```python
a = [8, -12, 5, 20, -3, 14]
```

Здесь:

- `a` — имя переменной, через которую мы обращаемся к списку;
- `=` — присваивание: справа вычисляется значение, затем оно связывается с именем слева;
- квадратные скобки обозначают список.

Обратиться к отдельному элементу можно по его **индексу** — номеру позиции, который в Python начинается с нуля.

| Обычный номер элемента | Индекс в Python | Значение | Обращение |
|---:|---:|---:|---|
| 1 | 0 | 8 | `a[0]` |
| 2 | 1 | −12 | `a[1]` |
| 3 | 2 | 5 | `a[2]` |
| 4 | 3 | 20 | `a[3]` |
| 5 | 4 | −3 | `a[4]` |
| 6 | 5 | 14 | `a[5]` |

Количество элементов возвращает `len`:

```python
len(a)
```

Для нашего списка результат равен `6`.

`len` — встроенная функция: готовое действие, которому мы передаём данные в скобках и от которого получаем результат.

Если:

```python
n = len(a)
```

то допустимые неотрицательные индексы:

\[
0,\;1,\;2,\;\ldots,\;n-1.
\]

**Последний индекс равен `n - 1`, а не `n`.**

Для списка из шести элементов обращение `a[6]` приведёт к ошибке: седьмого элемента нет.

**Сначала файл нужно превратить в список чисел.**

В текстовом файле числа записаны символами. Запись `"-12"` в тексте и число `-12`, с которым можно выполнять вычисления, — не одно и то же.

Для чтения нам понадобятся следующие действия:

| Запись | Что делает |
|---|---|
| `open("17.txt")` | Открывает файл |
| `f.read()` | Считывает его содержимое как текст |
| `.split()` | Разделяет текст по пробелам, переводам строк и другим пробельным символам |
| `int(...)` | Превращает текстовую запись целого числа в число |
| `a.append(x)` | Добавляет `x` в конец списка `a` |

Например, после разделения текста файла получится:

```python
["8", "-12", "5", "20", "-3", "14"]
```

Нам нужно получить:

```python
[8, -12, 5, 20, -3, 14]
```

Подробная запись чтения:

```python
a = []

with open("17.txt") as f:
    parts = f.read().split()

    for part in parts:
        number = int(part)
        a.append(number)
```

Разберём новые конструкции.

`a = []` создаёт пустой список.

Конструкция:

```python
with open("17.txt") as f:
```

открывает файл и позволяет работать с ним под именем `f`. После окончания блока файл автоматически закрывается.

Конструкция:

```python
for part in parts:
```

по очереди берёт каждый элемент списка `parts` и помещает его в переменную `part`. Повторяемые таким образом действия называются **циклом**.

На каждом повторении:

```python
number = int(part)
a.append(number)
```

текст превращается в число, а число добавляется в список.

**Отступы в Python показывают, какие команды относятся к циклу или другому блоку.**

Позже ту же операцию можно записывать короче:

```python
with open("17.txt") as f:
    a = [int(part) for part in f.read().split()]
```

Внутри квадратных скобок записано:

> Для каждой части текста получить `int(part)` и собрать результаты в список.

Это называется **списковым включением**. Оно заменяет создание пустого списка и последовательные добавления.

Для задания 17 такой способ чтения удобен: он работает и при одном числе в строке, и при нескольких числах, разделённых пробелами.

**Не удаляй первую строку автоматически.**

В некоторых задачах первая строка содержит количество последующих чисел. В других — это уже первый элемент последовательности. Решение определяется описанием файла.

Если условие прямо говорит, что первое число — количество элементов, после чтения можно отделить его:

```python
n = a[0]
a = a[1:]
```

Запись `a[1:]` означает «все элементы начиная с индекса `1` до конца». Такая выборка части списка называется **срезом**.

Если количества в начале файла нет, эти две строки удалят настоящее число и испортят ответ.

Также проверь имя и расположение файла. Относительное имя `"17.txt"` ищется в рабочей папке запуска программы. При необходимости можно указать полный путь:

```python
with open("C:/EGE/17.txt") as f:
    a = [int(part) for part in f.read().split()]
```

**Условие задачи переводится в проверки, каждая из которых даёт ответ «да» или «нет».**

Например:

```python
x > 10
```

проверяет, больше ли `x` десяти.

В Python результат проверки обозначается:

- `True` — условие выполнено;
- `False` — условие не выполнено.

Основные сравнения:

| Математический смысл | Python |
|---|---|
| Равно | `x == y` |
| Не равно | `x != y` |
| Больше | `x > y` |
| Меньше | `x < y` |
| Больше или равно | `x >= y` |
| Меньше или равно | `x <= y` |

Не путай:

```python
x = 10
```

и:

```python
x == 10
```

Первое присваивает значение. Второе проверяет равенство.

Слова из условия нужно переводить буквально:

| Формулировка | Проверка |
|---|---|
| Больше 100 | `x > 100` |
| Не меньше 100 | `x >= 100` |
| Меньше 100 | `x < 100` |
| Не больше 100 | `x <= 100` |
| От 100 до 999 включительно | `100 <= x <= 999` |

Последняя запись означает одновременное выполнение двух сравнений:

```python
100 <= x and x <= 999
```

Слово `and` мы подробно разберём чуть дальше.

Чтобы выполнить действие только при истинном условии, используют `if`:

```python
if x > 10:
    print(x)
```

`print` выводит данные на экран. Здесь число будет выведено только тогда, когда оно больше десяти.

**Остаток от деления — основной инструмент для проверки делимости и цифр.**

Вспомним деление с остатком:

\[
23 = 5\cdot4 + 3.
\]

Это означает:

- при делении `23` на `5` целая часть частного равна `4`;
- остаток равен `3`.

В Python:

```python
23 // 5   # 4
23 % 5    # 3
```

Текст после `#` — комментарий. Python его не выполняет.

Для неотрицательных целых чисел:

- `//` даёт целую часть частного;
- `%` даёт остаток.

Обычное деление записывается через `/`:

```python
23 / 5    # 4.6
```

**Число делится на `d` без остатка тогда и только тогда, когда остаток равен нулю.**

Поэтому:

```python
x % d == 0
```

означает «`x` кратно `d`».

Здесь предполагается, что `d` не равно нулю.

| Условие | Python |
|---|---|
| Число кратно 3 | `x % 3 == 0` |
| Число не кратно 3 | `x % 3 != 0` |
| Число чётное | `x % 2 == 0` |
| Число нечётное | `x % 2 != 0` |
| Остаток от деления на 7 равен 4 | `x % 7 == 4` |
| Остатки двух чисел при делении на 5 одинаковы | `x % 5 == y % 5` |
| Остатки различаются | `x % 5 != y % 5` |

Для отрицательных чисел проверка делимости тоже работает:

```python
-12 % 3 == 0
```

даёт `True`.

И ещё:

```python
0 % 3 == 0
```

тоже даёт `True`.

**Ноль кратен любому ненулевому целому числу.** Поэтому условие «кратно 3» само по себе не исключает ноль.

Если нужны положительные кратные трём числа:

```python
x > 0 and x % 3 == 0
```

**Условия на сумму или произведение нужно проверять для самой суммы или произведения.**

Например:

```python
(x + y) % 7 == 0
```

означает, что сумма кратна семи.

Это не то же самое, что требовать делимости каждого числа на семь.

Для чисел `2` и `5`:

\[
2+5=7,
\]

хотя ни `2`, ни `5` на семь не делятся.

Аналогично:

```python
(x * y) % 10 == 0
```

проверяет делимость произведения на десять.

Числа `2` и `5` дают произведение `10`. Поэтому заменять эту проверку на:

```python
x % 10 == 0 or y % 10 == 0
```

нельзя.

Другие часто нужные выражения:

| Что требуется | Выражение |
|---|---|
| Сумма пары | `x + y` |
| Произведение пары | `x * y` |
| Разность | `x - y` |
| Абсолютная разность | `abs(x - y)` |
| Квадрат числа | `x ** 2` |
| Сумма квадратов | `x ** 2 + y ** 2` |
| Квадрат суммы | `(x + y) ** 2` |

`abs` возвращает **модуль**, то есть абсолютную величину числа:

```python
abs(-12)   # 12
abs(12)    # 12
abs(0)     # 0
```

Например:

\[
|3-8|=5.
\]

Модуль разности позволяет измерить, насколько числа отличаются, независимо от того, какое записано первым.

**Сумма квадратов и квадрат суммы — разные выражения.**

Для `3` и `4`:

\[
3^2+4^2=9+16=25,
\]

а:

\[
(3+4)^2=7^2=49.
\]

В Python степень обозначается `**`. Символ `^` для возведения в степень не подходит.

**Слова «и», «или», «не» соединяют простые проверки в более сложные.**

Пусть:

```python
p = x % 3 == 0
q = y % 3 == 0
```

Переменная `p` хранит ответ на вопрос «делится ли `x` на 3», а `q` — такой же ответ для `y`.

Тогда:

```python
p and q
```

означает: выполнены **обе** проверки.

```python
p or q
```

означает: выполнена **хотя бы одна** проверка.

```python
not p
```

означает: проверка `p` не выполнена.

| `p` | `q` | `p and q` | `p or q` |
|---|---|---|---|
| `False` | `False` | `False` | `False` |
| `False` | `True` | `False` | `True` |
| `True` | `False` | `False` | `True` |
| `True` | `True` | `True` | `True` |

Обрати внимание на последнюю строку.

**«Хотя бы одно» допускает, что подходят оба.**

Поэтому:

```python
x % 3 == 0 or y % 3 == 0
```

подходит для пар:

```text
(6, 5)
(5, 9)
(6, 9)
```

Не подходит только пара, где оба числа не делятся на три.

А условие:

```python
x % 3 == 0 and y % 3 == 0
```

из этих трёх примеров пропускает только `(6, 9)`.

**«Ровно одно» удобно понимать как количество выполненных проверок.**

Для пары это означает два допустимых случая:

1. первое число подходит, второе не подходит;
2. первое не подходит, второе подходит.

Подробная запись:

```python
(p and not q) or (not p and q)
```

Для двух логических значений есть короткая запись:

```python
p != q
```

Она проверяет, что ответы различаются.

Например:

```python
(x % 3 == 0) != (y % 3 == 0)
```

означает: ровно одно число делится на три.

Но для троек и более сложных условий удобнее единый подход: **посчитать, сколько элементов обладает нужным свойством**.

Python позволяет преобразовать результаты проверок в числа:

```python
int(True)    # 1
int(False)   # 0
```

Такое явное преобразование делает подсчёт наглядным. [Python 3.14.8 documentation](https://docs.python.org/3/library/stdtypes.html?utm_source=chatgpt.com)

Для тройки:

```python
k = int(x % 3 == 0) + int(y % 3 == 0) + int(z % 3 == 0)
```

Здесь `k` — количество чисел, делящихся на три.

Для тройки:

```text
6, 10, 15
```

получаем:

\[
k=1+0+1=2.
\]

Теперь любые количественные формулировки переводятся одинаково:

| Формулировка для тройки | Проверка |
|---|---|
| Ни одного подходящего числа | `k == 0` |
| Ровно одно | `k == 1` |
| Ровно два | `k == 2` |
| Все три | `k == 3` |
| Хотя бы одно | `k >= 1` |
| Хотя бы два | `k >= 2` |
| Не более одного | `k <= 1` |
| Не более двух | `k <= 2` |
| Есть подходящие, но не все подходят | `0 < k < 3` |

**«Не более двух» включает ноль, одно и два.**

**«Не менее двух» включает два и три.**

Это важно: иногда ученик видит слово «двух» и машинально пишет `k == 2`, хотя условие требует другое.

В решениях также встречается запись без `int`:

```python
k = (x % 3 == 0) + (y % 3 == 0) + (z % 3 == 0)
```

Она работает, потому что при таком сложении `True` ведёт себя как единица, а `False` — как ноль. На этапе обучения запись с `int` яснее показывает смысл.

**Разные свойства одной группы нужно считать независимо.**

Допустим, требуется:

> В тройке чисел, кратных трём, больше, чем чисел, кратных пяти.

Сначала считаем одно:

```python
k3 = int(x % 3 == 0) + int(y % 3 == 0) + int(z % 3 == 0)
```

Затем другое:

```python
k5 = int(x % 5 == 0) + int(y % 5 == 0) + int(z % 5 == 0)
```

Проверяем:

```python
k3 > k5
```

Число `15` попадёт **в оба количества**. Это правильно: оно делится и на три, и на пять.

Не нужно насильно относить каждый элемент только к одной категории.

И не путай:

- количество подходящих **элементов внутри тройки**;
- количество подходящих **троек во всей последовательности**.

Если в тройке два числа делятся на три и этого достаточно для выполнения условия, сама тройка добавляет к ответу **единицу**, а не двойку.

**Скобки помогают сохранить смысл длинного условия.**

Предположим, требуется:

> Хотя бы одно число делится на три, а сумма пары больше 100.

Правильная запись:

```python
(x % 3 == 0 or y % 3 == 0) and (x + y > 100)
```

Здесь два крупных требования:

1. хотя бы одно число делится на три;
2. сумма больше ста.

Они соединены через `and`.

Без скобок:

```python
x % 3 == 0 or y % 3 == 0 and x + y > 100
```

Python сначала выполнит `and`. В результате делимости первого числа окажется достаточно независимо от суммы.

Удобный способ избежать путаницы — дать частям условия отдельные имена:

```python
has_multiple = x % 3 == 0 or y % 3 == 0
large_sum = x + y > 100

if has_multiple and large_sum:
    ...
```

Здесь `...` обозначает место для дальнейших действий.

Такие переменные хранят результаты проверок. По ним проще сопоставить код с текстом задачи.

**Фразы «хотя бы одно… и хотя бы одно…» и «одно…, а другое…» требуют разных проверок.**

Это одна из самых содержательных тонкостей задания.

Рассмотрим два свойства:

- число делится на три;
- число меньше `T`.

Первое условие:

> Хотя бы одно число пары делится на три, и хотя бы одно число пары меньше `T`.

Запись:

```python
(x % 3 == 0 or y % 3 == 0) and (x < T or y < T)
```

Один и тот же элемент может обеспечить выполнение обеих частей.

Например:

```text
x = 3
y = 100
T = 10
```

Число `3` и делится на три, и меньше десяти. Условие выполнено.

Теперь другое условие:

> Одно число пары делится на три, а другое меньше `T`.

Нужно распределить свойства между **двумя разными элементами**:

```python
(x % 3 == 0 and y < T) or (y % 3 == 0 and x < T)
```

Проверяются два возможных распределения ролей:

- делимость проверяем у `x`, сравнение — у `y`;
- делимость проверяем у `y`, сравнение — у `x`.

Пара `(3, 100)` при `T = 10` теперь не подходит.

Есть и третья формулировка:

> Хотя бы одно число одновременно делится на три и меньше `T`.

Здесь два свойства должны встретиться **у одного элемента**:

```python
(x % 3 == 0 and x < T) or (y % 3 == 0 and y < T)
```

Эти три условия нельзя взаимозаменять.

Также фраза «одно…, а другое…» сама по себе не означает, что делиться на три обязано **ровно одно** число. Если оба элемента обладают обоими свойствами, распределить роли между ними всё равно можно.

---

**Для проверки последних цифр отрицательного числа сначала нужен модуль.**

Для положительного числа:

```python
347 % 10    # 7
347 % 100   # 47
```

Почему это работает?

\[
347=34\cdot10+7.
\]

При делении на десять остатком остаётся последняя цифра.

А:

\[
347=3\cdot100+47.
\]

При делении на сто остатком остаются последние две цифры.

Но в Python:

```python
-17 % 10    # 3
```

Причина связана с правилами деления отрицательных чисел:

\[
-17=(-2)\cdot10+3.
\]

При положительном делителе Python возвращает неотрицательный остаток, меньший делителя. Операция `//` округляет частное вниз:

```python
-17 // 10   # -2
```

Поэтому `% 10` для отрицательного числа нельзя напрямую трактовать как последнюю цифру его записи. [Python 3.14.8 documentation](https://docs.python.org/3/reference/expressions.html?utm_source=chatgpt.com)

Чтобы проверить окончание записи:

```python
abs(x) % 10 == 7
```

Так подойдут:

```text
7, 17, 127, -7, -17, -127
```

Другие примеры:

| Свойство записи числа | Проверка |
|---|---|
| Оканчивается на 3 | `abs(x) % 10 == 3` |
| Оканчивается на 17 | `abs(x) % 100 == 17` |
| Оканчивается на 123 | `abs(x) % 1000 == 123` |
| Последние цифры двух чисел одинаковы | `abs(x) % 10 == abs(y) % 10` |

**Модуль нужен для работы с цифрами, но не должен добавляться во все проверки подряд.**

Если условие говорит:

> Остаток от деления числа на пять равен двум,

то проверяется:

```python
x % 5 == 2
```

Для `x = -8` это истинно:

\[
-8=(-2)\cdot5+2.
\]

Но:

```python
abs(-8) % 5
```

равно `3`.

Замена `x` на `abs(x)` здесь меняет условие.

Есть небольшая тонкость с окончаниями, начинающимися с нуля. Проверка:

```python
abs(x) % 100 == 7
```

выполнена и для числа `7`. Если требуется именно запись, заканчивающаяся двумя символами `07`, у числа должно быть достаточно цифр:

```python
abs(x) >= 10 and abs(x) % 100 == 7
```

---

**Количество цифр надёжно проверяется через числовые границы.**

Положительное трёхзначное число находится между `100` и `999`.

Поэтому:

```python
100 <= x <= 999
```

Если отрицательные числа тоже допускаются как трёхзначные, знак минус не считается цифрой:

```python
100 <= abs(x) <= 999
```

| Требование | Проверка |
|---|---|
| Двузначное по модулю | `10 <= abs(x) <= 99` |
| Трёхзначное по модулю | `100 <= abs(x) <= 999` |
| Четырёхзначное по модулю | `1000 <= abs(x) <= 9999` |
| Пятизначное по модулю | `10000 <= abs(x) <= 99999` |
| Положительное трёхзначное | `100 <= x <= 999` |
| Отрицательное трёхзначное | `-999 <= x <= -100` |

Можно использовать верхнюю границу без включения:

```python
100 <= abs(x) < 1000
```

Для целых чисел это то же самое, что:

```python
100 <= abs(x) <= 999
```

Ровно два четырёхзначных числа в тройке:

```python
k4 = (
    int(1000 <= abs(x) <= 9999)
    + int(1000 <= abs(y) <= 9999)
    + int(1000 <= abs(z) <= 9999)
)

if k4 == 2:
    ...
```

Переносы внутри круглых скобок позволяют записать длинное выражение на нескольких строках.

Можно определять количество цифр через текст:

```python
len(str(abs(x)))
```

Здесь `str` превращает значение в строку, а `len` считает символы.

Но запись:

```python
len(str(x))
```

для отрицательного числа посчитает и знак минус:

```python
str(-123)       # "-123"
len(str(-123))  # 4
```

Проверка диапазона обычно проще для чтения и проверки.

---

**Знак числа нужно проверять с учётом нуля.**

Основные случаи:

| Свойство | Проверка |
|---|---|
| Положительное | `x > 0` |
| Отрицательное | `x < 0` |
| Неотрицательное | `x >= 0` |
| Неположительное | `x <= 0` |

Ноль не является ни положительным, ни отрицательным числом.

Ровно одно отрицательное число в паре:

```python
int(x < 0) + int(y < 0) == 1
```

Или:

```python
(x < 0) != (y < 0)
```

Пара:

```text
(-8, 0)
```

подходит: отрицательное число в ней ровно одно.

А проверка:

```python
x * y < 0
```

для этой пары не выполнена.

Она означает другое:

> Одно число строго положительное, другое строго отрицательное.

Поэтому:

- «ровно одно отрицательное» — проверяем количество отрицательных;
- «числа разных знаков» в смысле положительного и отрицательного — можно использовать `x * y < 0`.

Для тройки все числа одного знака:

```python
(x > 0 and y > 0 and z > 0) or (x < 0 and y < 0 and z < 0)
```

Или через количество положительных и отрицательных:

```python
positive_count = int(x > 0) + int(y > 0) + int(z > 0)
negative_count = int(x < 0) + int(y < 0) + int(z < 0)

same_sign = positive_count == 3 or negative_count == 3
```

Проверять только знак произведения трёх чисел нельзя. Например:

```text
-2, -3, 5
```

имеют положительное произведение, но не одинаковые знаки.

---

**Соседние пары перебираются с шагом в один элемент.**

Вернёмся к последовательности:

```text
8, -12, 5, 20, -3, 14
```

Её соседние пары:

| Индекс начала | Пара |
|---:|---|
| 0 | `(8, -12)` |
| 1 | `(-12, 5)` |
| 2 | `(5, 20)` |
| 3 | `(20, -3)` |
| 4 | `(-3, 14)` |

Обрати внимание: пары пересекаются.

Число `-12` участвует:

- как второй элемент первой пары;
- как первый элемент второй пары.

Это правильно.

Если брать `(8, -12)`, затем `(5, 20)`, затем `(-3, 14)`, мы пропустим две соседние пары.

Для перебора используется:

```python
for i in range(len(a) - 1):
    x = a[i]
    y = a[i + 1]
```

`range(m)` последовательно даёт целые числа:

```text
0, 1, 2, ..., m - 1
```

Правая граница не включается.

Например:

```python
range(5)
```

даёт индексы `0, 1, 2, 3, 4`.

Теперь выведем границу цикла, а не просто запомним её.

Пусть длина списка равна `n`.

В паре используются индексы:

\[
i,\quad i+1.
\]

Последний индекс списка — `n - 1`. Значит:

\[
i+1\le n-1.
\]

Отсюда:

\[
i\le n-2.
\]

Нужны начала:

\[
0,\;1,\;\ldots,\;n-2.
\]

Именно их даёт:

```python
range(n - 1)
```

Для последовательности из `n` элементов при `n ≥ 2` существует `n - 1` соседняя пара.

---

**Для троек рассуждение такое же, но последний используемый индекс — `i + 2`.**

Перебор:

```python
for i in range(len(a) - 2):
    x = a[i]
    y = a[i + 1]
    z = a[i + 2]
```

Требуется:

\[
i+2\le n-1,
\]

поэтому:

\[
i\le n-3.
\]

Начала троек:

\[
0,\;1,\;\ldots,\;n-3.
\]

Их даёт `range(n - 2)`.

Для списка:

```text
8, -12, 5, 20, -3, 14
```

получаются:

```text
(8, -12, 5)
(-12, 5, 20)
(5, 20, -3)
(20, -3, 14)
```

Общее правило для группы из `k` соседних элементов:

```python
for i in range(len(a) - k + 1):
    ...
```

При `n ≥ k` таких групп:

\[
n-k+1.
\]

Группу соседних элементов иногда называют **окном**. Перемещение её начала на одну позицию — движением окна по последовательности. Для задания 17 с парами и тройками за этим названием стоит именно описанный перебор.

---

**Теперь можно полностью решить первую задачу.**

Учебное условие:

> Найти количество соседних пар, в которых хотя бы одно число делится на четыре. Среди таких пар найти максимальную сумму.

Пока разберём ответ вручную:

```text
8, -12, 5, 20, -3, 14
```

| Пара | Хотя бы одно число кратно 4? | Сумма |
|---|---|---:|
| `(8, -12)` | Да | −4 |
| `(-12, 5)` | Да | −7 |
| `(5, 20)` | Да | 25 |
| `(20, -3)` | Да | 17 |
| `(-3, 14)` | Нет | 11 |

Подходят четыре пары.

Их суммы:

```text
-4, -7, 25, 17
```

Максимальная — `25`.

Ответ:

```text
4 25
```

Самый наглядный способ программирования — сохранять суммы подходящих пар в отдельный список.

Функция `max` возвращает наибольшее значение:

```python
max([-4, -7, 25, 17])   # 25
```

Программа:

```python
with open("17.txt") as f:
    a = [int(part) for part in f.read().split()]

sums = []

for i in range(len(a) - 1):
    x = a[i]
    y = a[i + 1]

    if x % 4 == 0 or y % 4 == 0:
        sums.append(x + y)

if len(sums) > 0:
    print(len(sums), max(sums))
else:
    print("Подходящих пар нет")
```

Почему `len(sums)` даёт количество пар?

Потому что **на каждую подходящую пару добавляется ровно одна сумма**.

Если две разные пары имеют одинаковые суммы, одинаковое значение добавится дважды. Удалять такие повторения не нужно: пары разные.

Обрати внимание на отступ:

```python
if x % 4 == 0 or y % 4 == 0:
    sums.append(x + y)
```

Добавление происходит только после проверки.

Если перенести `append` за пределы `if`, в список попадут суммы всех пар.

Последняя ветка с текстом — диагностическая. На экзамене, если подходящих групп нет, нужно действовать по условию: например, вывести `0 0`, **если именно это предписано**. Нельзя самостоятельно считать ноль универсальным значением отсутствующего максимума.

---

**Тот же ответ можно находить, не сохраняя все суммы.**

Нам нужны лишь:

- количество найденных пар;
- наибольшая сумма среди уже найденных.

Для количества создадим переменную:

```python
count = 0
```

Она называется **счётчиком**, потому что хранит количество событий.

При обнаружении подходящей пары:

```python
count = count + 1
```

Справа используется старое значение, к нему прибавляется единица, результат сохраняется обратно.

Короткая запись:

```python
count += 1
```

Для максимума нужно выбрать начальное состояние.

**Начинать максимум с нуля в общем случае неправильно.**

Предположим, подходящие суммы:

```text
-15, -8, -20
```

Максимальная из них — `-8`.

Если начать с нуля и заменять его только на большее число, останется `0`, которого среди результатов вообще нет.

Удобно использовать:

```python
best = None
```

`None` — специальное значение, которым здесь обозначаем:

> Подходящего результата пока не было.

При появлении очередной суммы:

```python
if best is None or current_sum > best:
    best = current_sum
```

Смысл:

- если результата ещё не было, запоминаем первый;
- иначе заменяем его, только если новая сумма больше.

Python проверяет части `or` слева направо. Когда `best is None` истинно, сравнение `current_sum > best` уже не выполняется. Поэтому число не сравнивается с `None`.

Полная программа:

```python
with open("17.txt") as f:
    a = [int(part) for part in f.read().split()]

count = 0
best = None

for i in range(len(a) - 1):
    x = a[i]
    y = a[i + 1]

    if x % 4 == 0 or y % 4 == 0:
        count += 1
        current_sum = x + y

        if best is None or current_sum > best:
            best = current_sum

if count > 0:
    print(count, best)
else:
    print("Подходящих пар нет")
```

Для поиска минимума изменяется знак сравнения:

```python
if best is None or value < best:
    best = value
```

Оба способа — список результатов и счётчик с лучшим значением — правильные.

| Способ | Что удобно |
|---|---|
| Список результатов | Легко посмотреть все найденные значения и проверить себя |
| Счётчик и лучшее значение | Не нужно хранить все результаты |

Для освоения темы список часто нагляднее. После понимания логики переход к счётчику несложен.

---

**Правильность такого решения можно объяснить без формальных доказательств.**

После обработки каждой очередной пары:

- `count` равен количеству подходящих пар среди уже проверенных;
- `best` равен максимальной сумме среди них либо остаётся `None`, если подходящих ещё не было.

Изначально проверенных пар нет, поэтому `count = 0`.

Если очередная пара не подходит, ответ не меняется.

Если подходит:

- количество увеличивается на единицу;
- максимум при необходимости обновляется.

Цикл рассматривает каждое допустимое начало пары ровно один раз. Поэтому к его завершению учтены все нужные пары.

Это и есть смысл алгоритма: мы поддерживаем правильный частичный ответ и постепенно распространяем его на всю последовательность.

---

**Иногда перед проверкой пар нужно узнать характеристику всей последовательности.**

Например:

> Сумма пары должна быть больше максимального элемента, оканчивающегося на 17.

Пока мы не просмотрели весь файл, этот максимум может быть неизвестен.

Последний элемент файла способен оказаться больше всех предыдущих и изменить порог для проверки даже самой первой пары.

Поэтому задача естественно делится на этапы:

1. прочитать последовательность;
2. вычислить нужное значение по всей последовательности;
3. проверить пары или тройки с использованием уже известного значения.

Просмотр всех элементов от начала до конца называют **проходом по последовательности**.

Два последовательных прохода не означают перебор всех сочетаний. Например, при десяти тысячах элементов мы примерно дважды выполняем по десять тысяч действий.

---

**Предварительная характеристика может быть минимумом, максимумом, количеством, суммой или средним.**

Минимум возвращает `min`, максимум — `max`, сумму элементов — `sum`:

```python
minimum = min(a)
maximum = max(a)
total = sum(a)
```

Для непустого списка:

```python
a = [4, 9, -2]
```

получаем:

```text
minimum = -2
maximum = 9
total = 11
```

Если нужны только элементы с определённым свойством, сначала отберём их.

Например, числа, оканчивающиеся на `17`:

```python
selected = []

for x in a:
    if abs(x) % 100 == 17:
        selected.append(x)
```

Теперь:

```python
threshold = max(selected)
```

получает максимальное **исходное число** среди отобранных.

Короткая запись отбора:

```python
selected = [x for x in a if abs(x) % 100 == 17]
```

Её нужно читать так:

> Перебрать `x` из `a` и добавить `x`, если его запись заканчивается на 17.

Общий порядок:

> Сначала определить, какие элементы участвуют в вычислении, затем применить к ним нужную операцию.

| Требование | После отбора в `selected` |
|---|---|
| Количество таких элементов | `len(selected)` |
| Сумма таких элементов | `sum(selected)` |
| Минимальный такой элемент | `min(selected)` |
| Максимальный такой элемент | `max(selected)` |
| Среднее арифметическое | `sum(selected) / len(selected)` |
| Квадрат количества | `len(selected) ** 2` |

У пустого списка нет обычного минимума и максимума:

```python
min([])
max([])
```

приводят к ошибке.

Среднее пустого списка также не определено: получится деление на ноль.

Поэтому нужно учитывать гарантию существования нужных элементов в условии либо отдельно обрабатывать их отсутствие. **Нельзя заменять отсутствующий минимум или максимум произвольным нулём.**

---

**При отборе по цифрам сравнивать обычно нужно исходные числа.**

Допустим, числа, оканчивающиеся на семь:

```text
-47, 17, -7, 27
```

Минимальное из них:

```text
-47
```

Проверка окончания использует модуль:

```python
abs(x) % 10 == 7
```

Но в список мы кладём исходное число:

```python
selected.append(x)
```

а не:

```python
selected.append(abs(x))
```

Иначе будем искать минимум абсолютных величин — это другая задача.

Аналогично среди отрицательных чисел:

```text
-900, -250, -710
```

максимальное — `-250`, поскольку оно ближе к нулю:

\[
-900<-710<-250.
\]

---

**Разберём полную задачу с предварительным минимумом, окончаниями и квадратами.**

Учебное условие:

> Рассматриваются соседние пары целых чисел. Ровно одно число пары оканчивается на семь. Сумма квадратов чисел пары должна быть меньше квадрата минимального элемента всей последовательности, оканчивающегося на семь. Найти количество подходящих пар и максимальную сумму квадратов.

Предполагаем, что элемент для вычисления минимума существует.

Разделим текст на самостоятельные действия.

| Часть условия | Что делаем |
|---|---|
| Минимальный элемент всей последовательности, оканчивающийся на 7 | Находим заранее |
| Ровно одно число пары оканчивается на 7 | Считаем такие числа внутри пары |
| Сумма квадратов меньше квадрата минимума | Сравниваем две величины |
| Количество пар | Увеличиваем счётчик |
| Максимальная сумма квадратов | Обновляем максимум именно этой величины |

Последовательность:

```text
-47, 8, 17, -7, 4, 27, 10
```

Числа с нужным окончанием:

```text
-47, 17, -7, 27
```

Поэтому:

\[
m=-47,\qquad m^2=2209.
\]

Далее:

| Пара | Сколько чисел оканчиваются на 7 | Сумма квадратов | Подходит? |
|---|---:|---:|---|
| `(-47, 8)` | 1 | 2273 | Нет: слишком большая сумма квадратов |
| `(8, 17)` | 1 | 353 | Да |
| `(17, -7)` | 2 | 338 | Нет: подходят оба окончания |
| `(-7, 4)` | 1 | 65 | Да |
| `(4, 27)` | 1 | 745 | Да |
| `(27, 10)` | 1 | 829 | Да |

Ответ:

```text
4 829
```

Программа:

```python
with open("17.txt") as f:
    a = [int(part) for part in f.read().split()]

selected = []

for x in a:
    if abs(x) % 10 == 7:
        selected.append(x)

m = min(selected)

count = 0
best = None

for i in range(len(a) - 1):
    x = a[i]
    y = a[i + 1]

    endings_count = (
        int(abs(x) % 10 == 7)
        + int(abs(y) % 10 == 7)
    )

    square_sum = x ** 2 + y ** 2

    if endings_count == 1 and square_sum < m ** 2:
        count += 1

        if best is None or square_sum > best:
            best = square_sum

if count > 0:
    print(count, best)
else:
    print("Подходящих пар нет")
```

Здесь полезно обратить внимание на три независимых решения:

- для проверки окончания используется `abs`;
- для поиска минимума используются исходные значения;
- для ответа сравниваются суммы квадратов, а не обычные суммы.

Именно такие различия нужно удерживать при чтении длинного условия.

---

**В задачах на тройки обычно меняется число проверяемых элементов, а общий алгоритм остаётся прежним.**

Учебное условие:

> Последовательность содержит положительные целые числа. В соседней тройке ровно два числа должны быть четырёхзначными, хотя бы одно — делиться на три, а сумма должна превышать максимальный элемент всей последовательности, оканчивающийся на 17. Найти количество таких троек и максимальную сумму.

Предполагаем, что число для предварительного максимума существует.

Пример:

```text
1017, 2000, 6, 3001, 4001, 8, 123
```

Максимальное число с окончанием `17`:

```text
1017
```

Тройки:

| Тройка | Четырёхзначных | Кратных 3 | Сумма | Подходит? |
|---|---:|---:|---:|---|
| `(1017, 2000, 6)` | 2 | 2 | 3023 | Да |
| `(2000, 6, 3001)` | 2 | 1 | 5007 | Да |
| `(6, 3001, 4001)` | 2 | 1 | 7008 | Да |
| `(3001, 4001, 8)` | 2 | 0 | 7010 | Нет |
| `(4001, 8, 123)` | 1 | 1 | 4132 | Нет |

У четвёртой тройки сумма больше, чем у третьей. Но она не проходит условие, поэтому не может определять максимум ответа.

Ответ:

```text
3 7008
```

Программа:

```python
with open("17.txt") as f:
    a = [int(part) for part in f.read().split()]

selected = [x for x in a if x % 100 == 17]
threshold = max(selected)

results = []

for i in range(len(a) - 2):
    x = a[i]
    y = a[i + 1]
    z = a[i + 2]

    four_digit_count = (
        int(1000 <= x <= 9999)
        + int(1000 <= y <= 9999)
        + int(1000 <= z <= 9999)
    )

    multiple_count = (
        int(x % 3 == 0)
        + int(y % 3 == 0)
        + int(z % 3 == 0)
    )

    current_sum = x + y + z

    condition_1 = four_digit_count == 2
    condition_2 = multiple_count >= 1
    condition_3 = current_sum > threshold

    if condition_1 and condition_2 and condition_3:
        results.append(current_sum)

if len(results) > 0:
    print(len(results), max(results))
else:
    print("Подходящих троек нет")
```

Здесь числа по условию положительные, поэтому `abs` при проверке количества цифр не требуется.

**Среднее арифметическое нужно вычислять по той группе элементов, которая названа в условии.**

Среднее — это сумма значений, делённая на их количество.

Для чисел:

```text
2, 4, 12
```

получаем:

\[
\frac{2+4+12}{3}=6.
\]

Если требуется среднее всех чётных элементов последовательности:

```python
even_numbers = [x for x in a if x % 2 == 0]

average = sum(even_numbers) / len(even_numbers)
```

Нельзя делить сумму чётных элементов на общее количество элементов файла. Знаменатель должен соответствовать той же группе, что и числитель.

Также не нужно использовать `//`:

```python
average = sum(even_numbers) // len(even_numbers)
```

Это округлит результат вниз и может изменить проверки.

Например, настоящее среднее равно `6.5`.

Тогда число `6` меньше среднего. Но после округления до `6` проверка `6 < 6` уже ложна.

---

**Сравнение со средним можно выполнить точно, вообще не вычисляя дробное число.**

Пусть:

- `S` — сумма выбранных элементов;
- `K` — их количество;
- `K > 0`.

Тогда:

\[
x<\frac{S}{K}.
\]

Умножаем обе части на положительное число `K`. Направление неравенства не меняется:

\[
xK<S.
\]

В Python:

```python
x * K < S
```

Аналогично:

| Сравнение со средним | Без деления |
|---|---|
| `x < S / K` | `x * K < S` |
| `x <= S / K` | `x * K <= S` |
| `x > S / K` | `x * K > S` |
| `x >= S / K` | `x * K >= S` |

Так мы сохраняем вычисления в целых числах.

Теперь учебная задача:

> В соседней паре одно число делится на три, а другое меньше среднего арифметического всех чётных элементов последовательности. Найти количество таких пар и максимальную сумму.

Последовательность:

```text
2, 9, 4, 7, 12
```

Чётные числа:

```text
2, 4, 12
```

Их среднее равно `6`.

Проверяем:

| Пара | Подходит? | Почему |
|---|---|---|
| `(2, 9)` | Да | 9 кратно 3, а 2 меньше 6 |
| `(9, 4)` | Да | 9 кратно 3, а 4 меньше 6 |
| `(4, 7)` | Нет | Ни одно число не кратно 3 |
| `(7, 12)` | Нет | 12 кратно 3, но другое число 7 не меньше 6 |

Ответ:

```text
2 13
```

Программа без деления:

```python
with open("17.txt") as f:
    a = [int(part) for part in f.read().split()]

even_numbers = [x for x in a if x % 2 == 0]

even_sum = sum(even_numbers)
even_count = len(even_numbers)

# Предполагается, что чётные элементы существуют.

results = []

for i in range(len(a) - 1):
    x = a[i]
    y = a[i + 1]

    first_case = (
        x % 3 == 0
        and y * even_count < even_sum
    )

    second_case = (
        y % 3 == 0
        and x * even_count < even_sum
    )

    if first_case or second_case:
        results.append(x + y)

if len(results) > 0:
    print(len(results), max(results))
else:
    print("Подходящих пар нет")
```

Даже если оба распределения ролей подходят, пара добавляется только один раз: у нас один `if` с объединением через `or`.

---

**В длинных формулировках особенно важно соблюдать порядок операций.**

Рассмотрим:

> Квадрат минимального элемента.

Сначала находим минимум, затем возводим его в квадрат:

```python
min(a) ** 2
```

А:

> Минимальный квадрат элемента

означает сначала возведение каждого элемента в квадрат, затем поиск минимума:

```python
min([x ** 2 for x in a])
```

Для:

```text
-20, -3, 8
```

получаем:

\[
(\min a)^2=(-20)^2=400,
\]

но:

\[
\min(400,9,64)=9.
\]

Разница огромна.

Точно так же:

> Абсолютное значение максимальной суммы

означает:

```python
abs(max(results))
```

А:

> Максимальное абсолютное значение суммы

означает:

```python
max([abs(value) for value in results])
```

Для сумм:

```text
-20, -3
```

первое выражение даёт `3`, второе — `20`.

Полезно разбирать формулировку как последовательность действий:

| Формулировка | Порядок |
|---|---|
| Квадрат минимального числа | Найти минимум → возвести в квадрат |
| Минимум квадратов чисел | Возвести числа в квадрат → найти минимум |
| Модуль максимальной суммы | Вычислить суммы → найти максимум → взять модуль |
| Максимальный модуль суммы | Вычислить суммы → взять их модули → найти максимум |
| Квадрат количества элементов | Посчитать элементы → возвести количество в квадрат |
| Сумма квадратов элементов | Возвести элементы в квадрат → сложить |

Поэтому нельзя заранее брать модуль всех результатов, если в условии требуется модуль только окончательного максимума.

---

**Величина, по которой проверяют группу, может отличаться от величины, которую нужно вывести.**

Например:

> Сумма пары больше порога. Найти минимальную сумму квадратов подходящих пар.

Тогда:

```python
if x + y > threshold:
    results.append(x ** 2 + y ** 2)
```

А ответ:

```python
print(len(results), min(results))
```

При условии существования подходящих пар.

Здесь:

- проверка относится к `x + y`;
- сохраняется `x ** 2 + y ** 2`;
- из сохранённого выбирается минимум.

В каждой задаче полезно отдельно выписать:

1. **условие отбора**;
2. **величину, которую сравниваем между подходящими группами**;
3. **окончательное преобразование ответа**, если оно требуется.

Так ты не будешь машинально искать максимум суммы в любой задаче.

---

**Остаток минимального элемента и минимальный остаток — тоже разные вещи.**

Предположим:

```text
8, 12
```

Минимальный элемент — `8`.

Его остаток при делении на пять:

\[
8\bmod5=3.
\]

Но остатки всех элементов:

```text
3, 2
```

и минимальный из них равен `2`.

Поэтому:

```python
min(a) % 5
```

и:

```python
min([x % 5 for x in a])
```

не равны в общем случае.

Ещё одно различие:

| Формулировка | Проверка |
|---|---|
| Остаток `x` равен минимальному элементу последовательности | `x % 5 == minimum` |
| Остаток `x` равен остатку минимального элемента | `x % 5 == minimum % 5` |

Нельзя добавлять `% 5` справа, если его нет в смысле условия.

Для задачи:

> У ровно одного числа тройки остаток от деления на пять совпадает с остатком минимального элемента всей последовательности,

пишем:

```python
minimum = min(a)
target_remainder = minimum % 5
```

А внутри перебора троек:

```python
matching_count = (
    int(x % 5 == target_remainder)
    + int(y % 5 == target_remainder)
    + int(z % 5 == target_remainder)
)

condition = matching_count == 1
```

Предварительный минимум вычисляем один раз, до цикла.

**Для работы с наибольшими и наименьшими числами внутри тройки удобно создать маленький список.**

```python
triple = [x, y, z]
```

Теперь доступны:

```python
min(triple)
max(triple)
sum(triple)
```

Если нужна сумма двух наибольших элементов, можно из общей суммы вычесть один наименьший:

```python
two_largest_sum = sum(triple) - min(triple)
```

Почему это работает?

Из трёх элементов мы убираем наименьший. Остаются два наибольших.

Для:

```text
4, 10, 7
```

получаем:

\[
4+10+7-4=17.
\]

Это сумма `10` и `7`.

Аналогично:

```python
two_smallest_sum = sum(triple) - max(triple)
```

Средний по величине элемент:

```python
middle = sum(triple) - min(triple) - max(triple)
```

Повторяющиеся значения не мешают.

Для:

```text
5, 5, 5
```

сумма двух наибольших:

\[
15-5=10.
\]

Не нужно удалять все вхождения минимального значения: вычитается значение **одного** элемента.

Если нужно более подробно расположить три значения по величине, используется:

```python
ordered = sorted(triple)
```

`sorted` создаёт новый список с элементами по возрастанию.

Тогда:

```python
smallest = ordered[0]
middle = ordered[1]
largest = ordered[2]
```

Это сортировка только текущей тройки. Исходная последовательность `a` не изменяется, поэтому соседство в ней сохраняется.

---

**«Два наибольших числа» выбираются до возведения в квадрат, если именно так сформулировано условие.**

Пусть тройка:

```text
-10, 3, 4
```

Два наибольших числа — `3` и `4`.

Сумма их квадратов:

\[
3^2+4^2=25.
\]

Два наибольших квадрата — уже `100` и `16`, их сумма равна `116`.

Поэтому для суммы квадратов двух наибольших **чисел**:

```python
ordered = sorted([x, y, z])

value = ordered[1] ** 2 + ordered[2] ** 2
```

Сначала выбираем числа, затем возводим в квадрат.

Можно обойтись без сортировки:

```python
value = (
    x ** 2 + y ** 2 + z ** 2
    - min(x, y, z) ** 2
)
```

Из суммы трёх квадратов вычитается квадрат наименьшего **исходного** числа.

Функции `min` и `max` умеют принимать как список, так и несколько отдельных значений.

Для других формулировок:

| Требуемая величина | Выражение |
|---|---|
| Произведение минимума и максимума тройки | `min(triple) * max(triple)` |
| Сумма модулей минимума и максимума | `abs(min(triple)) + abs(max(triple))` |
| Модуль суммы минимума и максимума | `abs(min(triple) + max(triple))` |

Последние две строки тоже различаются.

Для минимума `-9` и максимума `5`:

\[
|-9|+|5|=14,
\]

но:

\[
|-9+5|=4.
\]

**В задачах на треугольники сначала нужно проверить, могут ли числа быть длинами сторон.**

Пусть три числа после упорядочивания:

\[
p\le q\le r.
\]

Для существования обычного, невырожденного треугольника нужно:

\[
p>0
\]

и:

\[
p+q>r.
\]

Почему достаточно проверить сумму двух меньших сторон?

Другие неравенства выполняются автоматически:

- `p + r > q`, потому что `r >= q` и `p > 0`;
- `q + r > p`, потому что `q >= p` и `r > 0`.

А вот две меньшие стороны могут оказаться слишком короткими.

Например:

```text
1, 2, 3
```

не образуют треугольник:

\[
1+2=3.
\]

Получается вырожденный случай: стороны можно расположить на одной прямой, а треугольника с ненулевой площадью нет.

После проверки существования:

| Вид треугольника | Критерий |
|---|---|
| Прямоугольный: один угол равен \(90^\circ\) | \(p^2+q^2=r^2\) |
| Остроугольный: все углы меньше \(90^\circ\) | \(p^2+q^2>r^2\) |
| Тупоугольный: один угол больше \(90^\circ\) | \(p^2+q^2<r^2\) |

Сравниваем именно с квадратом **наибольшей стороны**.

Прямоугольный случай — теорема Пифагора. Остальные критерии можно понять через угол напротив наибольшей стороны: увеличение этого угла при фиксированных двух других сторонах увеличивает противоположную сторону. При угле меньше прямого её квадрат меньше суммы квадратов двух других сторон, при угле больше прямого — больше.

Примеры:

| Стороны | Проверка | Результат |
|---|---|---|
| `3, 4, 5` | \(9+16=25\) | Прямоугольный |
| `4, 5, 6` | \(16+25>36\) | Остроугольный |
| `2, 3, 4` | \(4+9<16\), при этом \(2+3>4\) | Тупоугольный |
| `1, 2, 3` | \(1+2=3\) | Треугольника нет |

Для прямоугольного треугольника:

```python
ordered = sorted([x, y, z])

p = ordered[0]
q = ordered[1]
r = ordered[2]

is_triangle = p > 0 and p + q > r
is_right = p ** 2 + q ** 2 == r ** 2

if is_triangle and is_right:
    ...
```

Проверка положительности нужна. Иначе тройка:

```text
0, 5, 5
```

удовлетворит равенству:

\[
0^2+5^2=5^2,
\]

но стороной длины ноль обычный треугольник обладать не может.

Если по условию при отсутствии подходящих троек требуется `0 0`, полный фрагмент обработки выглядит так:

```python
results = []

for i in range(len(a) - 2):
    ordered = sorted([a[i], a[i + 1], a[i + 2]])

    p = ordered[0]
    q = ordered[1]
    r = ordered[2]

    is_triangle = p > 0 and p + q > r
    is_right = p ** 2 + q ** 2 == r ** 2

    if is_triangle and is_right:
        results.append(p + q + r)

if len(results) == 0:
    print(0, 0)
else:
    print(len(results), max(results))
```

**Если пара означает любые два разных элемента, перебор соседей не подходит.**

Возьмём последовательность:

```text
4, 6, 11, 9
```

Соседних пар три:

```text
(4, 6)
(6, 11)
(11, 9)
```

Но всех пар из разных позиций шесть:

| Индексы | Значения |
|---|---|
| `(0, 1)` | `(4, 6)` |
| `(0, 2)` | `(4, 11)` |
| `(0, 3)` | `(4, 9)` |
| `(1, 2)` | `(6, 11)` |
| `(1, 3)` | `(6, 9)` |
| `(2, 3)` | `(11, 9)` |

Чтобы перебрать их:

```python
for i in range(len(a) - 1):
    for j in range(i + 1, len(a)):
        x = a[i]
        y = a[j]
```

Внутренний цикл находится внутри внешнего. Это означает:

> Для каждого выбранного `i` перебрать все допустимые значения `j`.

Запись:

```python
range(start, stop)
```

даёт значения от `start` включительно до `stop` не включительно.

Почему начинаем `j` с `i + 1`?

Потому что рассматриваем только:

\[
i<j.
\]

Так одновременно обеспечивается:

- элемент не соединяется с самим собой;
- одна пара не считается дважды в разном порядке.

Например, после `(0, 2)` пара `(2, 0)` уже не рассматривается.

Это решение применяется, когда порядок элементов в паре не важен. Если условие специально различает упорядоченные пары, нужно учитывать это отдельно.

**Разные элементы не обязательно имеют разные значения.**

Для последовательности:

```text
5, 5, 5
```

существуют три пары разных позиций:

```text
(0, 1), (0, 2), (1, 2)
```

Все они имеют значения `(5, 5)`.

Добавлять проверку:

```python
a[i] != a[j]
```

можно только тогда, когда условие требует именно неравенства **значений**.

---

**Для произвольных пар полезно оценить количество проверок.**

Из `n` элементов получается:

\[
\frac{n(n-1)}{2}
\]

неупорядоченных пар разных позиций.

Почему?

Для первого элемента есть `n - 1` партнёров справа, для второго — `n - 2`, затем `n - 3` и так далее до одного:

\[
(n-1)+(n-2)+\ldots+1=\frac{n(n-1)}2.
\]

При `n = 10 000`:

- соседних пар — `9 999`;
- произвольных пар — `49 995 000`.

Разница существенная.

Когда число действий растёт примерно пропорционально `n`, говорят о **линейной сложности**, обозначают \(O(n)\).

Когда оно растёт примерно пропорционально \(n^2\), говорят о **квадратичной сложности**, обозначают \(O(n^2)\).

Эти обозначения описывают рост работы при увеличении данных, а не точное время в секундах.

Перебор всех произвольных пар логически прост, но на больших файлах может быть медленным. Скорость зависит от размера файла, проверяемых условий и среды выполнения.

---

**Некоторые задачи на произвольные пары можно ускорить, объединяя числа с одинаковыми свойствами.**

Этот приём сложнее основного перебора соседей. Он полезен для понимания того, как решать большие задачи на любые пары.

Учебное условие:

> Среди любых двух элементов с разными индексами найти количество пар с суммой, кратной пяти, и максимальную сумму.

Остатки от деления на пять:

```text
0, 1, 2, 3, 4
```

Какие остатки совместимы?

| Остаток первого числа | Нужный остаток второго |
|---:|---:|
| 0 | 0 |
| 1 | 4 |
| 2 | 3 |
| 3 | 2 |
| 4 | 1 |

Например:

\[
(5k+2)+(5m+3)=5(k+m+1).
\]

Сумма кратна пяти.

Будем двигаться слева направо. Для каждого нового числа рассматриваем только уже встреченные элементы.

Если новое число имеет остаток `2`, оно образует подходящую пару с каждым предыдущим числом остатка `3`.

Необязательно заново просматривать эти числа. Достаточно знать:

1. сколько их;
2. какое из них максимальное.

Количество нужно для подсчёта пар.

Максимум нужен для максимальной суммы: при фиксированном новом `x` сумма `x + y` тем больше, чем больше `y`.

Создадим:

```python
counts = [0] * 5
best_by_remainder = [None] * 5
```

Запись `[0] * 5` создаёт:

```python
[0, 0, 0, 0, 0]
```

Значение `counts[r]` будет означать количество предыдущих чисел с остатком `r`.

`best_by_remainder[r]` — наибольшее предыдущее число с таким остатком либо `None`, если их ещё не было.

Код обработки:

```python
counts = [0] * 5
best_by_remainder = [None] * 5

count = 0
best = None

for x in a:
    remainder = x % 5
    needed = (-remainder) % 5

    count += counts[needed]

    previous = best_by_remainder[needed]

    if previous is not None:
        current_sum = x + previous

        if best is None or current_sum > best:
            best = current_sum

    counts[remainder] += 1

    if (
        best_by_remainder[remainder] is None
        or x > best_by_remainder[remainder]
    ):
        best_by_remainder[remainder] = x

if count > 0:
    print(count, best)
else:
    print("Подходящих пар нет")
```

Запись:

```python
needed = (-remainder) % 5
```

вычисляет остаток, который в сумме с текущим даст число, кратное пяти. Например:

```text
remainder = 2 → needed = 3
remainder = 0 → needed = 0
```

**Сначала используем сведения о предыдущих числах, затем добавляем текущее.**

Если сделать наоборот, число с остатком ноль может образовать пару с самим собой.

Каждая настоящая пара учитывается при обработке её правого элемента. Поэтому повторного подсчёта нет.

Для:

```text
4, 6, 11, 9
```

подходят:

```text
(4, 6)   → 10
(4, 11)  → 15
(6, 9)   → 15
(11, 9)  → 20
```

Ответ:

```text
4 20
```

Этот конкретный алгоритм предназначен для произвольных пар и делимости суммы. Его нельзя переносить на соседние пары: он учитывает всех предыдущих партнёров, а не только ближайшего.

Общая идея ускорения — хранить количество и нужные характеристики ранее встреченных чисел по признаку, от которого зависит совместимость. Но сам признак нужно выводить из конкретного условия.

---

**Предварительные вычисления не стоит повторять внутри каждого шага цикла.**

Например:

```python
for i in range(len(a) - 1):
    if a[i] > sum(a) / len(a):
        ...
```

Здесь `sum(a)` заново проходит по всему списку на каждом повторении.

Если список длинный, это создаёт много лишней работы.

Лучше:

```python
average = sum(a) / len(a)

for i in range(len(a) - 1):
    if a[i] > average:
        ...
```

То же относится к:

```python
min(a)
max(a)
```

и отбору элементов всей последовательности.

Практическое правило:

> Если величина не зависит от текущего индекса `i`, подумай, можно ли вычислить её до цикла.

Но минимум текущей тройки:

```python
min(x, y, z)
```

зависит от рассматриваемых элементов, поэтому его как раз нужно находить внутри перебора.

---

**Есть несколько преобразований, которые почти всегда ломают задачу на соседство.**

Первое — сортировка всей последовательности:

```python
a.sort()
```

Она меняет порядок элементов.

Например:

```text
10, 1, 20
```

имеет соседние пары:

```text
(10, 1), (1, 20)
```

После сортировки:

```text
1, 10, 20
```

получаются:

```text
(1, 10), (10, 20)
```

Появилась другая пара.

Второе — предварительное удаление элементов, которые сами по себе не обладают нужным свойством.

Допустим, нужно проверить соседние пары, где хотя бы одно число чётное:

```text
2, 7, 4
```

Если сначала оставить только чётные:

```text
2, 4
```

мы создадим новую пару `(2, 4)`, которой в исходной последовательности не было.

**Отбирать отдельный список для вычисления глобального порога можно. Заменять им исходную последовательность для перебора соседей обычно нельзя.**

Третье — удаление повторов. Оно меняет и количество элементов, и их соседство.

Исходный список `a` лучше сохранять в том порядке и составе, в котором он прочитан из файла.

---

**Для решения новой задачи полезен один и тот же порядок рассуждения.**

1. **Определи объект перебора.**  
   Отдельные элементы, соседние пары, соседние тройки или любые пары разных позиций?

2. **Уточни допустимые значения.**  
   Возможны ли отрицательные числа и ноль? Нужно ли учитывать знак при проверке количества цифр?

3. **Выдели сведения обо всей последовательности.**  
   Минимум, максимум, количество, сумма, среднее? По всем элементам или по некоторой их части?

4. **Разложи условие группы на отдельные проверки.**  
   Например: «ровно два четырёхзначных», «есть кратное пяти», «сумма меньше порога».

5. **Отдельно выпиши, что требуется вывести.**  
   Количество и максимум суммы? Количество и минимум суммы квадратов? Модуль окончательного максимума?

6. **Выбери способ накопления ответа.**  
   Список подходящих значений либо счётчик и лучшее значение.

7. **Проверь решение на короткой последовательности.**  
   Желательно такой, где одни группы подходят, другие — нет.

8. **Запусти программу на файле и перенеси ответ в нужном порядке.**

Например, из длинного условия может получиться такая рабочая запись:

```text
Перебор: соседние тройки.

Заранее:
минимальное положительное трёхзначное число.

Условия тройки:
1) не более двух трёхзначных чисел;
2) сумма не меньше найденного минимума.

Ответ:
количество троек;
максимальная сумма среди них.
```

После такой записи код становится переводом уже понятного решения.

---

**Проверять программу нужно на случаях, где возможна конкретная ошибка.**

Необязательно придумывать большой файл. Небольшие данные часто лучше обнаруживают неверную логику.

| Что проверяем | Полезный случай |
|---|---|
| «Хотя бы одно» | Подходят оба числа пары |
| «Ровно одно» | Подходят оба — пара должна быть исключена |
| Работа со знаком | Есть отрицательное число и ноль |
| Начальное значение максимума | Все подходящие суммы отрицательны |
| Граница количества цифр | `99`, `100`, `999`, `1000` |
| Строгое или нестрогое сравнение | Значение в точности равно порогу |
| Пересечение групп | Подходят две пары с общим элементом |
| Разные элементы с одинаковыми значениями | Повторяющиеся числа |
| Конец цикла | Подходящей оказывается последняя пара или тройка |
| Порядок операций | Максимальная сумма отрицательна, а в ответе нужен её модуль |

Во время отладки можно выводить проверяемые элементы:

```python
for i in range(len(a) - 1):
    x = a[i]
    y = a[i + 1]

    condition = x % 4 == 0 or y % 4 == 0

    print(i, x, y, condition, x + y)
```

Так видно:

- какие пары действительно перебираются;
- чему равно условие;
- какая величина вычислена.

После проверки вспомогательный вывод убирают.

Также полезно проверить разумные границы количества:

- соседних пар не может быть больше `n - 1`;
- соседних троек — больше `n - 2`;
- неупорядоченных пар разных позиций — больше `n * (n - 1) // 2`.

Если программа превышает соответствующую границу, она что-то считает повторно.

**Теперь можно закрепить материал на небольших задачах.**

Сначала реши их вручную. Затем напиши программу и сравни результат. Во всех задачах ниже подходящие группы существуют.

1. Последовательность:

   ```text
   4, 7, 10, 3, -2
   ```

   Найди количество соседних пар, где хотя бы одно число чётное, и максимальную сумму.

2. Последовательность:

   ```text
   -8, 0, 5, -3, 2
   ```

   Найди количество соседних пар, где ровно одно число отрицательное, и максимальную сумму.

3. Последовательность:

   ```text
   7, 12, 17, -7, 4
   ```

   Найди количество соседних пар, где ровно одно число оканчивается на семь, и минимальную сумму квадратов.

4. Последовательность:

   ```text
   100, 5, 200, 300, 7, 400
   ```

   Найди количество соседних троек, где ровно два числа трёхзначные, и максимальную сумму.

   ```text
   -31, 6, 21, -4, 11
   ```

   Найди минимальный элемент, оканчивающийся на один. Затем найди соседние пары, в которых ровно одно число оканчивается на один, а сумма квадратов меньше квадрата найденного минимума. Выведи количество пар и максимальную сумму квадратов.

6. Последовательность:

   ```text
   4, 6, 11, 9
   ```

   Рассматривай любые два элемента с разными индексами. Найди количество пар с суммой, кратной пяти, и максимальную сумму.

7. Последовательность:

   ```text
   3, 4, 5, 6, 8, 10
   ```

   Найди количество соседних троек, которые могут быть сторонами прямоугольного треугольника, и максимальную сумму их элементов.

**Ответы для самопроверки приведены ниже.**

| Задача | Ответ | Ключевой момент |
|---:|---|---|
