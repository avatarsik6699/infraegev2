# Задание № 5 ЕГЭ: преобразование записей чисел

Этот материал посвящён одному подтипу задания № 5: алгоритм получает натуральное число `N`,
строит его запись в заданной системе счисления, изменяет последовательность цифр и получает число
`R`. Другие формы задания № 5 могут использовать исполнителей и иные алгоритмы; этот урок не
претендует на их полное покрытие.

Главная идея:

> Внутри такого алгоритма число временно превращается в строку цифр. Правила изменяют именно
> запись, после чего новая строка снова интерпретируется как число.

Всегда различайте четыре стадии:

$$
N_{10}
\longrightarrow
\text{запись }N\text{ в системе с основанием }b
\longrightarrow
\text{изменённая запись}
\longrightarrow
R_{10}.
$$

Например:

$$
13_{10}\longrightarrow1101_2\longrightarrow110111_2\longrightarrow55_{10}.
$$

Здесь `13` — исходное число `N`, `1101` — его двоичная запись, `110111` — изменённая
двоичная запись, а `55` — результат `R`.

## 1. Число и его запись

Число и его запись — не одно и то же. Одно количество можно записать в разных системах:

$$
13_{10}=1101_2=111_3.
$$

| Система | Запись | Десятичное значение |
| --- | ---: | ---: |
| Десятичная | $13_{10}$ | 13 |
| Двоичная | $1101_2$ | 13 |
| Троичная | $111_3$ | 13 |

Индекс указывает основание системы. Поэтому одинаковая строка цифр может обозначать разные числа:

$$
1101_2=1\cdot2^3+1\cdot2^2+0\cdot2^1+1\cdot2^0=13,
$$

$$
1101_3=1\cdot3^3+1\cdot3^2+0\cdot3^1+1\cdot3^0=37.
$$

Строка `1101` без указанного основания неоднозначна.

В задачах встречаются двоичная, троичная и другие позиционные системы. Механика преобразования
одинакова; меняются основание и алфавит допустимых цифр.

| Система | Основание | Допустимые цифры |
| --- | ---: | --- |
| Двоичная | 2 | `0`, `1` |
| Троичная | 3 | `0`, `1`, `2` |
| Четверичная | 4 | `0`, `1`, `2`, `3` |
| Пятеричная | 5 | `0`, `1`, `2`, `3`, `4` |

Маленькая буква `b` ниже обозначает основание системы, а большая `N` — входное число.

## 2. Универсальная схема решения

Задачу этого подтипа удобно исполнять в пять этапов.

1. Взять исходное число `N`.
2. Перевести `N` в требуемую систему счисления и сохранить запись строкой.
3. Проверить условие алгоритма: свойство `N`, суммы цифр или самой записи.
4. Изменить строку строго по правилам.
5. Интерпретировать изменённую строку в исходном основании и получить `R`.

Для `N = 13` и двоичной системы начало выглядит так:

```python
n = 13
s = bin(n)[2:]
```

`bin(13)` возвращает строку `'0b1101'`; срез `[2:]` удаляет служебный префикс `0b`, а не цифры
числа. После изменения `s` обратный перевод выполняется так:

```python
r = int(s, 2)
```

Важно не смешивать стадии: условие может требовать проверить само число `N`, исходную запись или
уже изменённую запись.

## 3. Основные операции со строкой

### Дописать цифру справа

```python
s = '1101'
s += '1'  # '11011'
```

Это склеивание строк, а не арифметическое сложение:

```python
'1101' + '1' == '11011'
```

### Приписать цифру слева

```python
s = '1101'
s = '1' + s  # '11101'
```

Порядок важен: `s + '1'` добавляет справа, `'1' + s` — слева.

### Взять крайние цифры

```python
s = '101101'
s[-1]   # '1'
s[-2]   # '0'
s[-2:]  # '01'
s[-3:]  # '101'
s[0]    # '1'
s[:2]   # '10'
s[:3]   # '101'
```

Например, «дописать две последние цифры»:

```python
s += s[-2:]  # '101101' → '10110101'
```

### Заменить или удалить крайние цифры

```python
s = '112' + s[2:]  # заменить первые две цифры на '112'
s = s[1:]          # удалить первую цифру
s = s[:-1]         # удалить последнюю цифру
```

Индексы начинаются с нуля, поэтому остаток строки после первых двух символов начинается с `s[2:]`.

### Заменить цифры одновременно

Для замены `0 → 2`, `2 → 0`, `1 → 1` нельзя последовательно вызывать два `replace`:

```python
# Неверно: вторая замена затронет и двойки, полученные из исходных нулей.
s = s.replace('0', '2').replace('2', '0')
```

Надёжный вариант рассматривает каждую исходную цифру ровно один раз:

```python
s = ''.join(
    '2' if digit == '0'
    else '0' if digit == '2'
    else '1'
    for digit in s
)
```

Или использует таблицу перевода:

```python
s = s.translate(str.maketrans('012', '210'))
```

## 4. Почему приписывание справа означает умножение

В десятичной системе приписывание цифры `5` к записи `37` даёт:

$$
375=37\cdot10+5.
$$

В двоичной системе приписывание `1` к `1101₂ = 13` даёт:

$$
11011_2=13\cdot2+1=27.
$$

В троичной системе:

$$
1022_3=11\cdot3+2=35.
$$

В системе с основанием `b` общая формула такова:

$$
R=N\cdot b+d,
$$

где `d` — приписанная справа цифра. Если приписывается блок из `k` цифр, то

$$
R=N\cdot b^k+D,
$$

где `D` — значение приписанного блока в системе с основанием `b`.

Например, к `102₃ = 11` приписали блок `22₃ = 8`:

$$
10222_3=11\cdot3^2+8=107.
$$

## 5. Повторное добавление бита чётности

Рассмотрим алгоритм:

1. Построить двоичную запись `N`.
2. Дописать справа остаток от деления суммы её цифр на 2.
3. Повторить предыдущий пункт ещё раз.
4. Перевести полученную запись в десятичную систему и получить `R`.

Исполним алгоритм для `N = 13`.

$$
13_{10}=1101_2.
$$

Сумма цифр равна `3`, поэтому первый дописанный бит равен `3 mod 2 = 1`:

```text
1101 → 11011
```

На втором шаге сумму нужно считать уже для изменённой записи: теперь она равна `4`, значит второй
бит равен `0`:

```text
11011 → 110110
```

$$
110110_2=32+16+4+2=54.
$$

Следовательно, `R = 54`.

Выражение `sum(map(int, s)) % 2` показывает чётность количества единиц: нули сумму не меняют.

```python
s = '1101'
digit_sum = sum(map(int, s))  # 3
parity_bit = digit_sum % 2    # 1
```

Типичная ошибка — заранее вычислить оба бита по исходной строке. После первого добавления строка
изменилась, поэтому второй бит может быть другим.

## 6. Поиск минимального N

Пусть для предыдущего алгоритма требуется найти минимальное `N`, при котором `R > 100`.

```python
for n in range(1, 1000):
    s = bin(n)[2:]

    s += str(sum(map(int, s)) % 2)
    s += str(sum(map(int, s)) % 2)

    r = int(s, 2)

    if r > 100:
        print(n, r, s)
        break
```

Программа выводит:

```text
25 102 1100110
```

Первый найденный `N` минимален не потому, что функция `R(N)` обязательно монотонна, а потому что
кандидаты `N = 1, 2, 3, …` проверяются по возрастанию и перебор останавливается при первом успехе.

## 7. Ветвление в троичной системе

Рассмотрим алгоритм:

1. Построить троичную запись `N`.
2. Если `N` делится на 3, приписать слева `1`, а справа `02`.
3. Иначе дважды дописать справа остаток от деления `N` на 3.
4. Получить десятичное значение `R`.

Для `N = 11`:

$$
11_{10}=102_3,\qquad11\bmod3=2,
$$

поэтому `102 → 10222`, а

$$
10222_3=81+18+6+2=107.
$$

Для `N = 12` срабатывает другая ветвь:

```text
110 → 1 + 110 + 02 → 111002
```

$$
111002_3=353.
$$

У Python нет встроенного аналога `bin()` для произвольного основания, поэтому используем функцию:

```python
def to_base(n, base):
    digits = ''

    while n > 0:
        digits = str(n % base) + digits
        n //= base

    return digits or '0'
```

Полный перебор для максимального `N`, при котором `R ≤ 350`:

```python
answers = []

for n in range(1, 351):
    s = to_base(n, 3)

    if n % 3 == 0:
        s = '1' + s + '02'
    else:
        digit = str(n % 3)
        s += digit * 2

    r = int(s, 3)

    if r <= 350:
        answers.append(n)

print(max(answers))
```

Ответ — `38`. Проверка:

$$
38_{10}=1102_3,\qquad110222_3=350.
$$

## 8. Почему первая неудача не даёт максимум

В алгоритме с ветвлением соседние `N` могут обрабатываться по разным формулам:

| N | Ветка | R |
| ---: | --- | ---: |
| 11 | не делится на 3 | 107 |
| 12 | делится на 3 | 353 |
| 13 | не делится на 3 | 121 |

Последовательность `107, 353, 121` не возрастает. Поэтому после `N = 12` нельзя заключить, что
все следующие числа тоже дадут `R > 350`.

- Для минимального `N` можно перебирать снизу вверх и остановиться на первом подходящем.
- Для максимального `N` безопаснее проверить весь обоснованный диапазон, собрать подходящие
  значения и применить `max()`.

Границу перебора тоже нужно обосновывать. Если алгоритм только приписывает цифры, то обычно
`R ≥ N`; при условии `R ≤ 350` значения `N > 350` не подходят. Но при удалении цифр, замене больших
цифр меньшими или отбрасывании части записи может быть `R < N`, и тогда нужна другая граница.

## 9. Одновременная замена и ведущие нули

Пусть в троичной записи все `0` одновременно заменяются на `2`, все `2` — на `0`, а `1` не
меняются. Для строки `10220` получаем:

```text
1 0 2 2 0
↓ ↓ ↓ ↓ ↓
1 2 0 0 2
```

Результат — `12002`. Если первая цифра превратилась в ноль, ведущие нули удаляют:

```python
s = s.translate(str.maketrans('012', '210'))
s = s.lstrip('0') or '0'
r = int(s, 3)
```

Часть `or '0'` не даёт получить пустую строку, если после удаления не осталось цифр.

## 10. Сумма цифр и делимость числа

Для `N = 14` десятичная запись — `14`, и сумма её цифр равна `1 + 4 = 5`. Троичная запись:

$$
14_{10}=112_3,
$$

а сумма её цифр равна `1 + 1 + 2 = 4`. Поэтому фраза «сумма цифр троичной записи» требует сначала
получить строку `s = to_base(n, 3)` и только затем вычислять `sum(map(int, s))`.

Условия тоже нельзя подменять:

```python
n % 3 == 0                    # само число N делится на 3
sum(map(int, s)) % 3 == 0     # сумма цифр записи делится на 3
```

Даже если в некоторых системах признаки делимости связывают эти свойства, исполнять нужно ровно
то условие, которое дано в алгоритме.

## 11. Универсальный программный шаблон

```python
def to_base(n, base):
    digits = ''

    while n > 0:
        digits = str(n % base) + digits
        n //= base

    return digits or '0'


answers = []

for n in range(1, 10000):
    s = to_base(n, 3)

    if CONDITION:
        s = TRANSFORMATION_1
    else:
        s = TRANSFORMATION_2

    r = int(s, 3)

    if RESULT_CONDITION:
        answers.append((n, r))
```

Финальный запрос определяет, какую величину извлекать:

```python
min(n for n, r in answers)  # минимальное N
max(n for n, r in answers)  # максимальное N
min(r for n, r in answers)  # минимальное R
max(r for n, r in answers)  # максимальное R
```

«Минимальное `N`» и «минимальное `R`» — разные вопросы.

## 12. Перевод типичных формулировок на Python

| Формулировка | Python |
| --- | --- |
| `N` чётно | `n % 2 == 0` |
| `N` кратно 3 | `n % 3 == 0` |
| сумма цифр чётна | `sum(map(int, s)) % 2 == 0` |
| количество единиц чётно | `s.count('1') % 2 == 0` |
| дописать `10` справа | `s += '10'` |
| приписать `2` слева | `s = '2' + s` |
| дописать последнюю цифру | `s += s[-1]` |
| дописать две последние цифры | `s += s[-2:]` |
| удалить последнюю цифру | `s = s[:-1]` |
| заменить первую цифру на `12` | `s = '12' + s[1:]` |
| заменить две первые цифры на `112` | `s = '112' + s[2:]` |

## 13. Итоговый алгоритм решения

1. Выписать отдельно `N`, исходную запись, изменённую запись и `R`.
2. Зафиксировать основание системы и допустимые цифры.
3. Перевести `N` в строку без служебного префикса.
4. Исполнить условия и строковые операции в указанном порядке.
5. При повторении шага использовать уже изменённую строку.
6. Перевести результат через `int(s, base)`.
7. Проверить, спрашивают `N` или `R`, минимум или максимум.
8. Для максимума при ветвлении не останавливаться после первой неудачи.
9. Обосновать границы перебора.
10. Вручную проверить хотя бы один подходящий кандидат и соседнее граничное значение.

Главная опорная модель остаётся прежней:

$$
N_{10}\rightarrow\text{запись в системе }b\rightarrow
\text{изменённая запись}\rightarrow R_{10}.
$$
