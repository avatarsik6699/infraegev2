**Строка — это последовательность символов, у которых есть определённый порядок.**

Например:

```python
s = 'AB12CA'
```

В строке шесть символов:

```python
'A', 'B', '1', '2', 'C', 'A'
```

Здесь `'1'` и `'2'` — символы, а не числа.

Поэтому:

```python
'1' + '2'    # Получится строка '12'
```

А здесь выполняется сложение чисел:

```python
int('1') + int('2')    # Получится число 3
```

Функция `int()` преобразует подходящую строку в целое число.

Это понадобится, например, если в условии требуется сравнивать суммы соседних цифр.

**В большинстве задач 24 нас интересует непрерывный фрагмент исходной строки.** Его также называют **подстрокой**.

Пусть дана строка:

```python
s = 'ABCDE'
```

Тогда:

- `'ABC'` — подстрока;
- `'BCD'` — подстрока;
- `'E'` — подстрока;
- `'ABCDE'` — подстрока;
- `'ACE'` — не подстрока: для её получения пришлось пропустить символы.

Вообще последовательность с пропусками называют *подпоследовательностью*. В формулировках задач это слово иногда используется вместе с уточнением «непрерывная» или «идущие подряд». Именно это уточнение определяет, разрешены ли пропуски.

**Если сказано «идущие подряд», нельзя удалять внутренние символы, переставлять их или склеивать раздельные участки.**

Например, в строке:

```text
AAAXAAAA
```

самая длинная цепочка букв `A` имеет длину `4`, а не `7`.

**Чтобы указывать на символы строки, используются их номера — индексы.** В Python нумерация начинается с нуля.

Возьмём строку:

```python
s = 'CABAC'
```

| Индекс | 0 | 1 | 2 | 3 | 4 |
|---|---:|---:|---:|---:|---:|
| Символ | C | A | B | A | C |

Обращение к одному символу:

```python
s[0]    # 'C'
s[2]    # 'B'
s[4]    # 'C'
```

Количество символов:

```python
len(s)    # 5
```

Поэтому последний неотрицательный индекс равен:

```python
len(s) - 1
```

Обращение `s[5]` в этом примере приведёт к ошибке: шестого символа нет.

Python также позволяет считать с конца:

```python
s[-1]    # Последний символ
s[-2]    # Предпоследний символ
```

Отсюда возникает важная ловушка:

```python
s[i - 1]
```

При `i = 0` это не «несуществующий предыдущий символ», а **последний символ строки**.

Поэтому при сравнении с предыдущим символом обычно начинают с индекса `1` либо отдельно проверяют, что `i > 0`.

**Несколько соседних символов можно получить срезом.**

```python
s[1:4]    # 'ABA'
```

Запись:

```python
s[a:b]
```

означает:

> Взять символы от индекса `a` включительно до индекса `b` не включительно.

Поэтому длина такого среза, если границы находятся внутри строки, равна:

\[
b-a.
\]

Часто удобнее рассуждать о двух **включённых** границах: `left` и `right`.

Тогда:

```python
s[left:right + 1]
```

А длина:

```python
right - left + 1
```

Почему появляется `+1`? Например, позиции `2`, `3`, `4` — это три символа:

\[
4-2+1=3.
\]

Полезно сразу различать три величины:

| Что требуется | Формула для позиций `left` и `right` |
|---|---|
| Длина фрагмента вместе с обоими концами | `right - left + 1` |
| Количество символов строго между концами | `right - left - 1` |
| Разность номеров позиций | `right - left` |

Если задача использует слово «расстояние», нужно проверить по условию и примеру, какая именно величина имеется в виду.

if c == 'A':

else:

Отступы показывают, какие действия относятся к каждой ветке.

for c in s:

for i in range(len(s)):

Например:

range(5)       # 0, 1, 2, 3, 4

**Прежде чем решать задачу, нужно правильно прочитать файл.**

Если в файле одна строка с исходной последовательностью:

```python
with open('24.txt') as f:
    s = f.readline().rstrip('\r\n')
```

Здесь:

- `open('24.txt')` открывает файл;
- `with` обеспечивает его закрытие после чтения;
- `readline()` читает одну строку;
- `rstrip('\r\n')` удаляет с правого края символы перевода строки.

Перевод строки — тоже символ. Если его оставить, программа иногда посчитает его частью последовательности.

Например, проверка:

```python
c != 'A'
```

истинна и для буквы `B`, и для символа перевода строки.

Поэтому лишний перевод строки способен увеличить ответ.

Часто встречается сокращение:

```python
s = open('24.txt').readline().strip()
```

`strip()` удаляет пробельные символы с обоих краёв. Для последовательности из букв и цифр это обычно подходит. Но если пробелы являются частью данных, удалять их без причины нельзя.

Также не стоит автоматически писать:

```python
s = f.readline()[:-1]
```

Это удаляет **последний символ независимо от того, является ли он переводом строки**. Если файл заканчивается без перевода строки, потеряется полезный символ.

Если нужно прочитать весь файл:

```python
with open('24.txt') as f:
    s = f.read()
```

Но `read()` сохраняет внутренние переводы строк. Поэтому сначала выясняем, что дано:

- одна последовательность;
- несколько независимых строк;
- последовательность, специально разбитая на строки.

Если строки независимы, обрабатываем их отдельно:

```python
with open('24.txt') as f:
    for line in f:
        s = line.rstrip('\r\n')

        # Здесь обработка одной строки.
```

Комментарий начинается с `#`; Python его не выполняет.

**Перед написанием кода полезно разделить условие на три вопроса.**

1. **Какие фрагменты допустимы?**  
   Например, содержат не более трёх букв `A`.

2. **Что нужно оптимизировать?**  
   Например, длину: найти самую большую.

3. **Что нужно вывести?**  
   Длину, начальную позицию, количество фрагментов, букву, значение выражения?

Последние два вопроса могут иметь разные ответы.

Например:

> Найдите самый длинный подходящий фрагмент и укажите номер его первого символа.

Здесь выбираем по длине, а выводим позицию.

Ещё пример:

> Найдите букву, образующую самую длинную цепочку, и укажите количество этой буквы во всей строке.

Здесь длина цепочки определяет выбор, но сама по себе не является ответом.

Это одна из причин, по которым механическое использование шаблонов приводит к ошибкам.

**Полный перебор всех подстрок обычно слишком медленный.**

В строке длины `n`:

- с первой позиции начинается `n` непустых подстрок;
- со второй — `n - 1`;
- с третьей — `n - 2`;
- с последней — одна.

Всего:

\[
n+(n-1)+\ldots+1=\frac{n(n+1)}2.
\]

При миллионе символов это примерно:

\[
5\cdot10^{11}
\]

фрагментов.

Причём каждый фрагмент ещё нужно проверить.

Поэтому задача обычно состоит в том, чтобы **не рассматривать каждую подстроку отдельно**.

Если число действий растёт примерно пропорционально длине строки, говорят о **линейном алгоритме** и обозначают его сложность как `O(n)`.

Если число действий растёт примерно как квадрат длины строки — `O(n²)`.

Для задания 24 особенно полезны алгоритмы, которые проходят по данным один или несколько раз.

---

**Первый основной приём — хранить длину подходящей цепочки, заканчивающейся в текущем месте.**

Начнём с простой задачи:

> Найти максимальное количество букв `X`, идущих подряд.

Например:

```text
XXAXXXXBXX
```

Ответ: `4`.

Нужны две переменные:

```python
current = 0
best = 0
```

`current` — длина цепочки `X`, которая продолжается прямо сейчас.

`best` — наибольшая длина среди всех уже просмотренных цепочек.

Алгоритм:

```python
current = 0
best = 0

for c in s:
    if c == 'X':
        current += 1
    else:
        current = 0

    best = max(best, current)

print(best)
```

Рассмотрим начало строки:

| Прочитанный символ | Что произошло | `current` | `best` |
|---|---|---:|---:|
| X | Началась цепочка | 1 | 1 |
| X | Цепочка продолжилась | 2 | 2 |
| A | Цепочка прервалась | 0 | 2 |
| X | Началась новая цепочка | 1 | 2 |
| X | Она продолжилась | 2 | 2 |
| X | Она стала длиннее предыдущей | 3 | 3 |
| X | Ещё одно продолжение | 4 | 4 |

**Почему при `A` мы записываем ноль?**

Потому что подходящий фрагмент должен состоять только из `X`. Сам символ `A` не может входить даже в цепочку длины один.

**Почему максимум обновляется после каждого символа?**

Так мы автоматически учитываем и цепочку в конце файла.

Если обновлять максимум только в момент разрыва, последняя цепочка может остаться неучтённой.

Та же идея работает для разных условий на отдельный символ:

```python
if c in 'ABC':
```

— цепочка только из `A`, `B`, `C`;

```python
if c != 'D':
```

— цепочка без `D`;

```python
if c in '0123456789':
```

— цепочка десятичных цифр.

У всех этих задач одинаковая логика:

> Текущий символ сам по себе либо допустим, либо полностью разрывает цепочку.

---

**Если условие связывает соседние символы, при разрыве часто остаётся цепочка длины один.**

Теперь требуется:

> Найти самую длинную цепочку одинаковых символов.

Например:

```text
AABBBBCCAAA
```

Ответ: `4`.

```python
current = 0
best = 0

for i in range(len(s)):
    if i > 0 and s[i] == s[i - 1]:
        current += 1
    else:
        current = 1

    best = max(best, current)

print(best)
```

Почему здесь `current = 1`, а не `0`?

Допустим, после нескольких `A` встретилась `B`.

Цепочка из `A` закончилась. Но символ `B` **сам образует новую подходящую цепочку длины один**.

Это различие нужно понимать, а не заучивать:

| Условие | Что происходит при нарушении |
|---|---|
| Фрагмент состоит только из `X`, встретилась `A` | `A` непригодна сама по себе → длина `0` |
| Все символы фрагмента одинаковы, после `A` встретилась `B` | `B` начинает новую цепочку → длина `1` |

Проверка:

```python
i > 0 and s[i] == s[i - 1]
```

сначала проверяет `i > 0`. Если это неправда, вторая часть не вычисляется. Поэтому в начале строки мы не сравниваем первый символ с последним.

**Условие «каждые два соседних символа различны» проверяется почти так же.**

Подходит строка:

```text
ABACA
```

Несмотря на повторение `A`, каждая соседняя пара состоит из разных символов.

Алгоритм:

```python
current = 0
best = 0

for i in range(len(s)):
    if i > 0 and s[i] != s[i - 1]:
        current += 1
    else:
        current = 1

    best = max(best, current)

print(best)
```

На строке:

```text
ABBACAB
```

получим:

| Индекс | Символ | `current` |
|---|---|---:|
| 0 | A | 1 |
| 1 | B | 2 |
| 2 | B | 1 |
| 3 | A | 2 |
| 4 | C | 3 |
| 5 | A | 4 |
| 6 | B | 5 |

Ответ: `5`, фрагмент `BACAB`.

**Не путай два разных требования:**

- соседние символы различны;
- все символы фрагмента различны.

В `ABACA` первое требование выполнено, второе — нет.

Для второго позже понадобится другой алгоритм.

---

**Запрет на определённые соседние пары тоже решается через текущую длину.**

Например:

> Никакие две буквы из набора `ABC` не должны стоять рядом, в том числе одинаковые.

Запрещены:

```text
AA AB AC BA BB BC CA CB CC
```

Нарушение возникает, когда **оба** соседних символа принадлежат набору:

```python
s[i - 1] in 'ABC' and s[i] in 'ABC'
```

Код:

```python
current = 0
best = 0

for i in range(len(s)):
    if i == 0:
        current = 1
    elif s[i - 1] in 'ABC' and s[i] in 'ABC':
        current = 1
    else:
        current += 1

    best = max(best, current)

print(best)
```

`elif` означает: «иначе, если выполнено следующее условие».

При запрещённой паре отбрасываем предыдущую цепочку, но оставляем текущий символ.

Например:

```text
DXABY
```

Пара `AB` запрещена. Однако фрагмент `BY` допустим.

Поэтому обнулить длину на `B` было бы ошибкой.

**Иногда условие проверяется по тройкам, а при нарушении нужно сохранить два последних символа.**

Пусть строка состоит из цифр. Требуется максимальный фрагмент, в котором для каждых трёх соседних цифр:

> Сумма первых двух больше третьей.

Например, тройка `245` подходит:

\[
2+4>5.
\]

А `124` не подходит:

\[
1+2\not>4.
\]

Если встретилась плохая тройка `124`, фрагмент `24` всё ещё допустим: в нём пока нет ни одной тройки, нарушающей правило.

Поэтому:

```python
current = min(len(s), 2)
best = current

for i in range(2, len(s)):
    a = int(s[i - 2])
    b = int(s[i - 1])
    c = int(s[i])

    if a + b > c:
        current += 1
    else:
        current = 2

    best = max(best, current)

print(best)
```

Первоначально учитываем первые два символа. Если строка короче, берём её фактическую длину.

Этот алгоритм предполагает, что фрагменты длины один и два разрешены. Если условие отдельно требует хотя бы три символа, это ограничение нужно учитывать при обновлении ответа.

**Общая причина сбросов `0`, `1`, `2` теперь видна:**

> После нарушения нужно оставить самый длинный конец текущего фрагмента, который всё ещё удовлетворяет условию.

В других задачах его длина может быть и больше двух.

**Для поиска короткого образца нужно перебрать все возможные позиции его начала.**

Пусть требуется посчитать вхождения:

```python
word = 'ABA'
```

В строке:

```text
ABABA
```

есть два вхождения:

- с позиции `0`: символы `0–2`;
- с позиции `2`: символы `2–4`.

Они имеют общий символ, то есть **перекрываются**.

Проверяем каждый возможный старт:

```python
word = 'ABA'
m = len(word)
count = 0

for i in range(len(s) - m + 1):
    if s[i:i + m] == word:
        count += 1

print(count)
```

Почему диапазон заканчивается на `len(s) - m + 1`?

Последнее возможное начало имеет индекс:

```python
len(s) - m
```

Но правая граница `range()` не включается. Поэтому прибавляем один.

**Метод `count()` не всегда заменяет такой перебор.**

```python
'ABABA'.count('ABA')    # 1
```

Он считает неперекрывающиеся вхождения. Поэтому при допустимых перекрытиях нужно проверять позиции самостоятельно. [Python 3.15.0 documentation](https://docs.python.org/3/library/stdtypes.html?utm_source=chatgpt.com)

Для одного символа проблемы нет:

```python
s.count('A')
```

корректно считает все буквы `A`.

Ещё пример условия на короткие фрагменты:

> Сколько троек имеют одинаковые крайние символы?

```python
count = 0

for i in range(len(s) - 2):
    if s[i] == s[i + 2]:
        count += 1

print(count)
```

Средний символ здесь может быть любым, если условие не говорит обратного.

---

**Для повторяющейся последовательности важно знать, какой символ должен идти следующим.**

Рассмотрим цепочку:

```text
ABCABCABC...
```

Пусть она должна начинаться с `A`, а последний блок может быть неполным.

Тогда подходят:

```text
A
AB
ABC
ABCA
ABCAB
ABCABC
```

Но не подходит `BCA`, если начало именно с `A` обязательно.

Обозначим уже набранную длину через `current`.

| `current` | Что уже набрано | Следующий ожидаемый символ |
|---:|---|---|
| 0 | ничего | A |
| 1 | A | B |
| 2 | AB | C |
| 3 | ABC | A |
| 4 | ABCA | B |
| 5 | ABCAB | C |

Ожидание повторяется через каждые три символа.

Операция `%` находит остаток от деления:

```python
0 % 3    # 0
1 % 3    # 1
2 % 3    # 2
3 % 3    # 0
4 % 3    # 1
```

Поэтому ожидаемый символ:

```python
pattern[current % 3]
```

где:

```python
pattern = 'ABC'
```

Полный код:

```python
pattern = 'ABC'
current = 0
best = 0

for c in s:
    expected = pattern[current % 3]

    if c == expected:
        current += 1
    elif c == 'A':
        current = 1
    else:
        current = 0

    best = max(best, current)

print(best)
```

При несовпадении:

- новый `A` начинает новую цепочку;
- `B` или `C` не могут её начать.

**Этот простой перезапуск нельзя без проверки переносить на любой повторяющийся образец.**

Например, для образца `AAB` в строке `AAAB` при несовпадении нужно сохранить две последние `A`. Сброс до одной `A` потеряет правильное начало.

Для `ABC` показанный алгоритм работает благодаря структуре образца.

Если разрешены только целые блоки `ABC`, длина должна быть кратна трём. В рамках именно этой модели из найденной максимальной длины можно убрать неполный последний блок:

```python
answer = best - best % 3
```

---

**Цепочки из пар или троек нужно отличать от проверки всех соседних пар или троек.**

Сравни:

> Каждые две соседние буквы различны.

Проверяются пары с началами `0`, `1`, `2`, `3`…

И другое условие:

> Фрагмент состоит из пар «согласная + гласная».

Здесь фрагмент разбивается на непересекающиеся пары:

```text
BA CE FA
```

Начала пар отличаются на два.

Но подходящая цепочка может начаться как на чётной, так и на нечётной позиции исходной строки.

Поэтому проверяем оба варианта:

```python
consonants = 'BCDF'
vowels = 'AE'

best_pairs = 0

for offset in range(2):
    current_pairs = 0

    for i in range(offset, len(s) - 1, 2):
        if s[i] in consonants and s[i + 1] in vowels:
            current_pairs += 1
        else:
            current_pairs = 0

        best_pairs = max(best_pairs, current_pairs)

print(best_pairs)
```

Третий аргумент `range()` — шаг:

```python
range(1, 8, 2)    # 1, 3, 5, 7
```

Сначала проверяем пары с началами `0, 2, 4, ...`, затем — `1, 3, 5, ...`.

Если спрашивают количество пар, выводим:

```python
best_pairs
```

Если количество символов:

```python
2 * best_pairs
```

Для блоков длины три аналогично проверяют три возможных смещения.

---

**Когда нужно посчитать частоты разных символов, удобно хранить отдельный счётчик для каждого.**

Например:

> Какая буква чаще всего встречается непосредственно после `A`?

Строка:

```text
ABACABAD
```

После `A` стоят:

```text
B, C, B, D
```

Значит:

- `B` — два раза;
- `C` — один;
- `D` — один.

Для хранения соответствий «буква → количество» используется **словарь**.

```python
freq = {}
```

Пустые фигурные скобки создают пустой словарь.

Запись:

```python
freq['B'] = 2
```

означает: для буквы `B` сохранено значение `2`.

Чтобы увеличить счётчик:

```python
freq[c] = freq.get(c, 0) + 1
```

`freq.get(c, 0)` возвращает:

- уже сохранённое значение, если буква есть в словаре;
- `0`, если её пока нет.

Полный подсчёт:

```python
freq = {}

for i in range(len(s) - 1):
    if s[i] == 'A':
        c = s[i + 1]
        freq[c] = freq.get(c, 0) + 1
```

Последнюю позицию не рассматриваем как начало пары: после неё нет символа.

Допустим, при равных частотах нужно выбрать букву, которая раньше в алфавите:

```python
answer = ''
best_count = 0

for c in sorted(freq):
    if freq[c] > best_count:
        best_count = freq[c]
        answer = c

print(answer)
```

`sorted(freq)` перебирает буквы в отсортированном порядке.

Почему сравнение строгое — `>`?

Первой встретится меньшая по алфавиту буква. При равной частоте следующая буква её не заменит.

Если требовалась последняя по алфавиту, можно было бы обновлять ответ и при равенстве.

**Если нужно сохранить все буквы с максимальной частотой, выбрать одну нельзя.** Например:

```python
winners = []
best_count = 0

for c in freq:
    best_count = max(best_count, freq[c])

for c in freq:
    if freq[c] == best_count:
        winners.append(c)
```

Здесь `[]` создаёт **список** — последовательность элементов, а `append()` добавляет элемент в его конец.

При обработке многих строк внимательно различай:

- счётчики внутри одной строки;
- общий результат по всему файлу.

Внутренние счётчики обычно создаются заново для каждой строки.

---

**Для максимального расстояния между одинаковыми буквами достаточно помнить их первые появления.**

Предположим, буква `A` встретилась на позициях:

```text
2, 7, 11, 18
```

Самое большое расстояние между двумя `A`:

\[
18-2.
\]

Нет необходимости проверять все пары позиций.

При движении слева направо для каждой новой `A` выгоднее всего брать самую первую `A`.

```python
first = {}
best = 0

for i in range(len(s)):
    c = s[i]

    if c in first:
        distance = i - first[c]
        best = max(best, distance)
    else:
        first[c] = i

print(best)
```

`first[c]` не обновляется после первого появления.

Это общий принцип:

> Если при фиксированной правой границе выгодна максимально ранняя левая, сохраняй самое раннее подходящее положение.

Позже этот принцип появится снова.

---

**Второй основной приём — хранить две границы фрагмента и постепенно их передвигать.** Такой рассматриваемый фрагмент называют **окном**.

Пусть:

```python
left = 2
right = 6
```

Тогда окно:

```python
s[2:7]
```

Правая граница обычно двигается по строке по одному символу. Левая — сдвигается, когда это нужно для выполнения условия.

Такой способ называют **скользящим окном** или **методом двух указателей**. Указателями здесь служат обычные индексы `left` и `right`.

Начнём с задачи:

> Найти самый длинный фрагмент, содержащий не более двух букв `A`.

Возьмём:

```text
BABAACB
```

Индексы:

| Индекс | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Символ | B | A | B | A | A | C | B |

Будем хранить:

```python
left = 0
count_a = 0
best = 0
```

При добавлении символа справа увеличиваем счётчик, если это `A`.

Если букв `A` стало больше двух, удаляем символы слева, пока ограничение снова не выполнится.

```python
K = 2

left = 0
count_a = 0
best = 0

for right in range(len(s)):
    if s[right] == 'A':
        count_a += 1

    while count_a > K:
        if s[left] == 'A':
            count_a -= 1

        left += 1

    best = max(best, right - left + 1)

print(best)
```

Пошагово:

| `right` | Добавили | `left` после исправления | Число `A` | Окно | Длина |
|---:|---|---:|---:|---|---:|
| 0 | B | 0 | 0 | B | 1 |
| 1 | A | 0 | 1 | BA | 2 |
| 2 | B | 0 | 1 | BAB | 3 |
| 3 | A | 0 | 2 | BABA | 4 |
| 4 | A | 2 | 2 | BAA | 3 |
| 5 | C | 2 | 2 | BAAC | 4 |
| 6 | B | 2 | 2 | BAACB | 5 |

Ответ: `5`.

Разберём самый важный момент — добавление `A` на позиции `4`.

Получилось:

```text
BABAA
```

Три буквы `A`, условие нарушено.

Удаляем первый `B`:

```text
ABAA
```

Букв `A` всё ещё три.

Удаляем первую `A`:

```text
BAA
```

Теперь их две.

**Поэтому нужен `while`, а не одноразовый `if`.** Для исправления окна иногда требуется убрать несколько символов.

---

**Скользящее окно работает здесь потому, что лишние буквы невозможно убрать расширением вправо.**

Если во фрагменте уже три `A`, добавление новых символов не превратит их обратно в две.

Значит, пока мы не передвинем левую границу, такое начало больше не пригодится.

После сжатия окна:

- условие выполнено;
- `left` находится настолько далеко слева, насколько возможно;
- следовательно, найдено самое длинное допустимое окно с текущим правым концом.

Мы рассматриваем каждый правый конец, поэтому среди этих окон обязательно встретится глобальный максимум.

Такое сохраняемое утверждение о состоянии алгоритма называют **инвариантом**.

Для данного решения инвариант:

> После завершения `while` окно содержит не более `K` букв `A`, а его левая граница минимально возможна для данного правого конца.

Термин полезен, но важнее сама мысль: **ты должен уметь объяснить, что означают переменные после каждого шага**.

**Почему два вложенных цикла здесь не дают `O(n²)`?**

Потому что `left` не возвращается назад.

За всё выполнение:

- `right` проходит строку один раз;
- `left` тоже проходит её не более одного раза.

Суммарно получается порядка `2n` перемещений, то есть `O(n)`.

Вложенные циклы сами по себе ещё не означают квадратичную сложность.

---

**Для самого длинного фрагмента с ровно `K` буквами можно использовать то же окно.**

Различие — ответ обновляется только при точном равенстве:

```python
K = 2

left = 0
count_a = 0
best = 0

for right in range(len(s)):
    if s[right] == 'A':
        count_a += 1

    while count_a > K:
        if s[left] == 'A':
            count_a -= 1

        left += 1

    if count_a == K:
        best = max(best, right - left + 1)

print(best)
```

Почему не нужно специально двигать границу, когда букв меньше `K`?

Удаление символов не увеличит количество `A`. Значит, если даже в самом широком допустимом окне их недостаточно, более короткое окно с тем же правым концом не поможет.

А если букв ровно `K`, самое широкое окно — как раз лучшее по длине.

Значение `best = 0` означает, что подходящий непустой фрагмент пока не найден. Если условие не гарантирует существование ответа, ситуацию отсутствия подходящих фрагментов нужно обрабатывать согласно условию.

---

**Поиск минимальной длины требует другой логики обновления ответа.**

Задача:

> Найти самый короткий фрагмент, содержащий не менее `K` букв `A`.

Здесь недостаток букв исправляется расширением вправо.

Когда букв стало достаточно, пробуем уменьшать окно слева.

```python
K = 2    # Здесь K >= 1

left = 0
count_a = 0
best = len(s) + 1

for right in range(len(s)):
    if s[right] == 'A':
        count_a += 1

    while count_a >= K:
        best = min(best, right - left + 1)

        if s[left] == 'A':
            count_a -= 1

        left += 1

if best == len(s) + 1:
    print('Подходящего фрагмента нет')
else:
    print(best)
```

Начальное значение:

```python
len(s) + 1
```

больше длины любой подстроки. Поэтому любой найденный ответ окажется меньше.

Если значение не изменилось, подходящего фрагмента не было.

**Почему ответ обновляется до удаления левого символа?**

Пока условие `count_a >= K` выполнено, окно подходит. После удаления оно может перестать подходить.

Поэтому сначала учитываем текущее окно, затем пробуем его сократить.

Сравни две схемы:

| Что ищем | Что делает внутренний цикл |
|---|---|
| Максимальную длину при «не более `K`» | Сжимает окно, пока оно плохое |
| Минимальную длину при «не менее `K`» | Сжимает окно, пока оно хорошее, запоминая ответы |

Для одного ограничения на количество символа, без дополнительных требований, минимальный фрагмент с не менее `K` буквами будет содержать ровно `K`: лишние крайние вхождения можно отбросить.

Но при дополнительных ограничениях на начало, конец или структуру такое рассуждение нужно проверять заново.

Также замечай простые случаи:

> Максимальная длина фрагмента с не менее `K` буквами `A`.

Если других ограничений нет и во всей строке достаточно `A`, ответ — длина всей строки.

Не каждой формулировке нужен сложный алгоритм.

---

**Несколько верхних ограничений можно поддерживать одновременно.**

Например:

> Не более двух `A` и не более одной `B`.

Условие допустимости:

```python
count_a <= 2 and count_b <= 1
```

Значит, окно нужно сжимать, если:

```python
count_a > 2 or count_b > 1
```

Достаточно нарушения хотя бы одного ограничения.

```python
left = 0
count_a = 0
count_b = 0
best = 0

for right in range(len(s)):
    if s[right] == 'A':
        count_a += 1

    if s[right] == 'B':
        count_b += 1

    while count_a > 2 or count_b > 1:
        if s[left] == 'A':
            count_a -= 1

        if s[left] == 'B':
            count_b -= 1

        left += 1

    best = max(best, right - left + 1)

print(best)
```

Если требуется **ровно две `A` и ровно одна `B`**, после сжатия добавляем:

```python
if count_a == 2 and count_b == 1:
    best = max(best, right - left + 1)
```

Если контролируемых букв много, отдельные переменные заменяют словарём счётчиков.

**Важно различать:**

- каждая буква из набора встречается не более двух раз;
- суммарно буквы из набора встречаются не более двух раз.

В первом случае нужны отдельные счётчики, во втором — один общий.

---

**Если все символы фрагмента должны быть различными, полезно помнить последние позиции их появления.**

Пример:

```text
ABCADEB
```

Здесь нельзя просто сравнивать соседние символы.

Будем хранить словарь:

```python
last = {}
```

`last[c]` — последний просмотренный индекс символа `c`.

Если текущий символ уже встречался внутри окна, левую границу нужно перенести за его предыдущее появление:

```python
left = 0
best = 0
last = {}

for right in range(len(s)):
    c = s[right]

    if c in last:
        left = max(left, last[c] + 1)

    last[c] = right

    best = max(best, right - left + 1)

print(best)
```

Почему:

```python
max(left, last[c] + 1)
```

а не просто:

```python
left = last[c] + 1
```

Потому что предыдущее появление символа могло уже остаться левее окна.

Рассмотрим:

```text
ABBA
```

После второй `B` левый край уже сдвинут на позицию `2`.

У последней `A` предыдущее появление — позиция `0`.

Нельзя вернуть `left` на позицию `1`: тогда внутрь снова попадут две `B`.

Левая граница должна двигаться только вперёд.

---

**Запрещённое слово тоже можно обрабатывать через границу окна.**

Задача:

> Найти самый длинный фрагмент без подстроки `ABC`.

Пусть новое запрещённое вхождение заканчивается на позиции `right`.

Его начало:

```python
start = right - len(word) + 1
```

Чтобы фрагмент больше не содержал это вхождение целиком, достаточно поставить левую границу **после его первого символа**:

```python
left = start + 1
```

Не обязательно выбрасывать всё слово.

Например, из `ABC` можно оставить `BC`.

```python
word = 'ABC'
m = len(word)

left = 0
best = 0

for right in range(len(s)):
    if right >= m - 1:
        start = right - m + 1

        if s[start:right + 1] == word:
            left = max(left, start + 1)

    best = max(best, right - left + 1)

print(best)
```

Для строки:

```text
XABCYABZ
```

после обнаружения `ABC` остаётся возможным фрагмент:

```text
BCYABZ
```

Его длина — `6`.

Это ещё один пример того, почему полный сброс счётчика часто неверен: значительная часть текущего фрагмента может оставаться подходящей.

---

**Третий основной приём — хранить позиции только тех символов, которые влияют на условие.**

Допустим, нас интересуют буквы `A`.

Создадим список их индексов:

```python
positions = []

for i in range(len(s)):
    if s[i] == 'A':
        positions.append(i)
```

Для:

```text
BABAACB
```

получим:

```python
[1, 3, 4]
```

Теперь некоторые задачи удобнее решать по этому списку.

Пусть нужен самый короткий фрагмент с `K` буквами `A`.

Если выбраны `K` последовательных вхождений с номерами:

```text
j, j + 1, ..., j + K - 1
```

то самый короткий охватывающий их фрагмент начинается на первой `A` и заканчивается на последней:

\[
\text{длина}
=
positions[j+K-1]-positions[j]+1.
\]

```python
K = 2
best = len(s) + 1

for j in range(len(positions) - K + 1):
    length = positions[j + K - 1] - positions[j] + 1
    best = min(best, length)

if best == len(s) + 1:
    print('Подходящего фрагмента нет')
else:
    print(best)
```

Здесь `K >= 1`.

Почему достаточно последовательных вхождений?

Если между выбранными `A` есть ещё одна `A`, она всё равно попадёт внутрь непрерывного фрагмента. Пропустить её нельзя.

---

**Для максимальной длины с ровно `K` буквами нужно растянуть границы до соседних лишних вхождений.**

Пусть позиции `A`:

```text
p₀, p₁, p₂, ...
```

Выбираем группу из `K` последовательных `A`.

Тогда:

- левее первой выбранной `A` можно идти до предыдущей `A`, не включая её;
- правее последней — до следующей `A`, не включая её.

Чтобы одинаково обрабатывать начало и конец строки, добавим две искусственные позиции:

```python
-1
len(s)
```

Это **не настоящие символы**, а удобные обозначения границ.

```python
positions = [-1]

for i in range(len(s)):
    if s[i] == 'A':
        positions.append(i)

positions.append(len(s))
```

Для нашего примера:

```python
[-1, 1, 3, 4, 7]
```

Если первая выбранная `A` находится в `positions[j]`, то:

- предыдущая лишняя `A` — `positions[j - 1]`;
- следующая лишняя `A` — `positions[j + K]`.

Следовательно:

```python
left = positions[j - 1] + 1
right = positions[j + K] - 1
```

Длина:

\[
right-left+1
=
positions[j+K]-positions[j-1]-1.
\]

Код:

```python
K = 2
best = 0

for j in range(1, len(positions) - K):
    length = positions[j + K] - positions[j - 1] - 1
    best = max(best, length)

print(best)
```

Для первых двух `A` максимальное окно — `BABA`, длина `4`.

Для последних двух — `BAACB`, длина `5`.

**Смысл искусственных границ стоит запомнить:**

> Они позволяют применить одну формулу и к середине строки, и к фрагментам, упирающимся в её края.

---

**Позиционный подход работает и для нескольких вхождений слова, в том числе перекрывающихся.**

Пусть ищем минимальный фрагмент с `K` вхождениями слова `ABA`.

Сначала получаем позиции всех начал:

```python
word = 'ABA'
m = len(word)

positions = []

for i in range(len(s) - m + 1):
    if s[i:i + m] == word:
        positions.append(i)
```

Для:

```text
ABABABA
```

это:

```python
[0, 2, 4]
```

Самый короткий фрагмент с двумя вхождениями — `ABABA`, длина `5`.

Почему не `6`?

Потому что вхождения перекрываются.

Если первое выбранное слово начинается на `positions[j]`, а последнее — на `positions[j + K - 1]`, его конец находится на:

```python
positions[j + K - 1] + m - 1
```

Поэтому:

\[
\text{длина}
=
positions[j+K-1]-positions[j]+m.
\]

```python
K = 2
best = len(s) + 1

for j in range(len(positions) - K + 1):
    length = positions[j + K - 1] - positions[j] + m
    best = min(best, length)
```

Для одного символа `m = 1`, и получается уже знакомая формула.

При поиске максимума с ограничением на число вхождений слова можно также двигать левую границу за начало лишнего вхождения. При этом важно считать только слова, целиком лежащие внутри окна.

---

**Четвёртый приём — заранее посчитать накопленные количества, чтобы быстро отвечать на вопросы об отдельных фрагментах.**

Предположим, нужно много раз узнавать:

> Сколько букв `A` между позициями `left` и `right`?

Можно каждый раз писать:

```python
s[left:right + 1].count('A')
```

Но это создаёт срез и повторно просматривает его.

Вместо этого построим список:

```python
prefix[i]
```

который хранит количество `A` **среди первых `i` символов**.

Начальный участок строки называется **префиксом**, отсюда название.

```python
prefix = [0] * (len(s) + 1)

for i in range(len(s)):
    prefix[i + 1] = prefix[i]

    if s[i] == 'A':
        prefix[i + 1] += 1
```

Запись:

```python
[0] * (len(s) + 1)
```

создаёт список нужной длины, заполненный нулями.

Для:

```text
BABA
```

получится:

| `i` | Первые `i` символов | `prefix[i]` |
|---:|---|---:|
| 0 | пусто | 0 |
| 1 | B | 0 |
| 2 | BA | 1 |
| 3 | BAB | 1 |
| 4 | BABA | 2 |

Количество `A` в окне с включёнными границами:

```python
prefix[right + 1] - prefix[left]
```

Почему?

- `prefix[right + 1]` учитывает всё до правого конца включительно;
- `prefix[left]` учитывает всё, что находится строго левее окна;
- вычитание убирает лишнюю левую часть.

Это называют **префиксными суммами**, хотя здесь мы суммируем количества символов.

---

**Совмещённые условия часто решаются сочетанием позиций и накопленных количеств.**

Рассмотрим учебную задачу:

> Найти самый длинный фрагмент, в котором ровно `K` букв `Y` и не менее `T` вхождений `ABA`.

Можно действовать так:

1. По позициям `Y` перебрать самые широкие окна с ровно `K` такими буквами.
2. Для каждого окна быстро проверить количество `ABA`.
3. Среди подходящих окон выбрать самое длинное.

Сначала накопим количество **начал** `ABA`.

```python
word = 'ABA'
m = len(word)
n = len(s)

prefix = [0] * (n + 1)

for i in range(n):
    prefix[i + 1] = prefix[i]

    if s[i:i + m] == word:
        prefix[i + 1] += 1
```

Здесь `prefix[t]` означает:

> Сколько вхождений слова начинается на позициях, меньших `t`.

Теперь важная граница.

Чтобы слово длины `m` целиком лежало в `[left, right]`, его начало должно находиться от:

```python
left
```

до:

```python
right - m + 1
```

включительно.

Поэтому число вхождений внутри окна:

```python
prefix[right - m + 2] - prefix[left]
```

если длина окна хотя бы `m`.

Полный пример:

```python
K = 2
T = 2

word = 'ABA'
m = len(word)
n = len(s)

prefix = [0] * (n + 1)

for i in range(n):
    prefix[i + 1] = prefix[i]

    if s[i:i + m] == word:
        prefix[i + 1] += 1

positions = [-1]

for i in range(n):
    if s[i] == 'Y':
        positions.append(i)

positions.append(n)

best = 0

for j in range(1, len(positions) - K):
    left = positions[j - 1] + 1
    right = positions[j + K] - 1

    count_word = 0

    if right - left + 1 >= m:
        count_word = prefix[right - m + 2] - prefix[left]

    if count_word >= T:
        best = max(best, right - left + 1)

print(best)
```

Почему достаточно самых широких окон с выбранными `Y`?

Если в самом широком окне недостаточно вхождений `ABA`, то в его части их не станет больше.

А если вхождений достаточно, самое широкое окно лучше по длине.

Здесь мы используем не просто сочетание двух шаблонов, а свойство условия «не менее»: расширение фрагмента не уменьшает количество уже имеющихся вхождений.

Для условия «ровно `T` вхождений» такое упрощение уже не подходит.

---

**Не каждое условие позволяет сжимать окно по правилу «пока плохо».**

Например:

> Найти самый длинный фрагмент, в котором одинаковое количество `A` и `B`.

При добавлении символов условие может то выполняться, то нарушаться, то выполняться снова.

На строке:

```text
AABB
```

префиксы имеют такие количества:

| Фрагмент | `A` | `B` | Равенство |
|---|---:|---:|---|
| A | 1 | 0 | нет |
| AA | 2 | 0 | нет |
| AAB | 2 | 1 | нет |
| AABB | 2 | 2 | да |

Если начать удалять символы сразу после нарушения равенства, можно потерять будущий ответ.

Здесь помогает **накопленная разность**:

- за `A` прибавляем `1`;
- за `B` вычитаем `1`.

Эту разность удобно называть балансом.

Если на двух границах баланс одинаков, значит между ними суммарное изменение равно нулю:

\[
\#A-\#B=0.
\]

То есть количеств поровну.

Для строки только из `A` и `B`:

```python
balance = 0
first = {0: -1}
best = 0

for i in range(len(s)):
    if s[i] == 'A':
        balance += 1
    else:
        balance -= 1

    if balance in first:
        best = max(best, i - first[balance])
    else:
        first[balance] = i

print(best)
```

Запись:

```python
first = {0: -1}
```

говорит:

> До начала строки, на условной позиции `-1`, баланс был равен нулю.

Для каждого баланса сохраняем самое раннее положение. Тогда при его повторении получаем самый длинный фрагмент.

Если в алфавите есть другие символы, нужно отдельно решить по условию, дают ли они нулевой вклад или разрывают допустимый фрагмент. В таком случае безусловный `else: balance -= 1` уже использовать нельзя.

**Замены и разбиение строки удобны, когда они сохраняют смысл задачи.**

Пусть запрещена буква `X`.

```python
parts = s.split('X')
```

`split()` разбивает строку по указанному разделителю.

Для:

```python
s = 'ABXXCDEFXGH'
```

получится:

```python
['AB', '', 'CDEF', 'GH']
```

Самый длинный фрагмент без `X`:

```python
best = 0

for part in s.split('X'):
    best = max(best, len(part))

print(best)
```

Пустые фрагменты возникают, например, между соседними разделителями. Здесь они не мешают.

Если запрещены `X` и `Y`, можно превратить их в общий разделитель:

```python
t = s.replace('X', ' ').replace('Y', ' ')

best = 0

for part in t.split():
    best = max(best, len(part))

print(best)
```

`replace()` возвращает строку с заменами. Исходная строка сама не изменяется.

`split()` без аргумента разбивает по пробельным промежуткам и не создаёт пустых частей.

**Опасная замена — удаление символа вместо создания границы.**

```python
s = 'AAAXAAAA'
t = s.replace('X', '')
```

Теперь:

```text
AAAAAAA
```

Но такой непрерывной цепочки в исходной строке не было.

Также будь осторожен с заменой длинного слова одним символом:

```python
s.replace('ABC', '*')
```

Она меняет длину и позиции. Иногда это полезно, но тогда нужно отдельно восстанавливать длину исходного фрагмента.

Прежде чем применять замену, спроси:

> Не создам ли я соседство, которого раньше не было? Не потеряю ли перекрывающиеся вхождения? Смогу ли восстановить исходные позиции?

---

**Если разделители перекрываются и удаляются с разбиением строки, нужно пометить все занятые ими позиции.**

Допустим, разделителем является любая тройка, содержащая по одному разу `A`, `B`, `C`.

В строке:

```text
QABCABR
```

есть перекрывающиеся разделители:

```text
ABC
BCA
CAB
```

Они вместе покрывают весь участок `ABCAB`.

После удаления с разбиением остаются отдельные фрагменты:

```text
Q
R
```

Их нельзя склеить в `QR`.

Для проверки состава тройки удобно **множество**.

```python
set('ABCA')    # Множество различных символов: A, B, C
```

Множество хранит различные элементы; повторения не учитывает.

Поскольку в тройке ровно три позиции, условие:

```python
set(s[i:i + 3]) == {'A', 'B', 'C'}
```

означает, что каждая из этих букв встретилась ровно один раз.

Сначала пометим все позиции разделителей:

```python
removed = [False] * len(s)

for i in range(len(s) - 2):
    if set(s[i:i + 3]) == {'A', 'B', 'C'}:
        for j in range(i, i + 3):
            removed[j] = True
```

Потом найдём максимальную цепочку непомеченных позиций:

```python
current = 0
best = 0

for i in range(len(s)):
    if not removed[i]:
        current += 1
    else:
        current = 0

    best = max(best, current)

print(best)
```

Здесь все разделители определяются **в исходной строке**. Последовательное удаление и повторный поиск могли бы изменить соседства и привести к другому результату.

**Регулярные выражения полезны, когда фрагмент описывается повторяющейся структурой.**

Например:

- одна или несколько цифр;
- число, затем несколько пар «операция + число»;
- буква, затем цифры, затем буква.

**Регулярное выражение** — это запись правил, которым должна соответствовать строка.

В Python для такой записи используется стандартный модуль `re`:

```python
import re
```

Модуль — набор готовых средств, подключаемый к программе. Устанавливать `re` отдельно не нужно.

Начнём с небольшого набора обозначений:

| Запись | Значение |
|---|---|
| `A` | Буква `A` |
| `[ABC]` | Один символ: `A`, `B` или `C` |
| `[0-9]` | Одна десятичная цифра |
| `[A-Z]` | Одна заглавная латинская буква |
| `[0-9]+` | Одна или несколько цифр |
| `[0-9]*` | Ноль или несколько цифр |
| `[0-9]?` | Ноль или одна цифра |
| `[0-9]{3}` | Ровно три цифры |
| `[0-9]{2,5}` | От двух до пяти цифр |
| `(?:ABC)` | Сгруппировать последовательность `ABC` |
| `(?:ABC)+` | Один или несколько целых блоков `ABC` |
| `A\|B` в смысле выбора: `A|B` | Вариант `A` или вариант `B` |

Последнюю запись в самом Python пишут просто:

```python
r'A|B'
```

Обозначение `(?:...)` объединяет элементы, чтобы повторение относилось ко всей группе.

Например:

```python
r'ABC+'
```

означает `AB`, затем одну или несколько `C`.

А:

```python
r'(?:ABC)+'
```

означает один или несколько блоков `ABC`.

Префикс `r` у строкового литерала удобен для шаблонов: он сохраняет обратные косые черты для обработки самим регулярным выражением.

**Найти группы цифр можно так:**

```python
import re

for match in re.finditer(r'[0-9]+', s):
    print(match.group())
```

`finditer()` последовательно выдаёт найденные совпадения.

Для каждого совпадения:

```python
match.group()    # Найденный текст
match.start()    # Индекс начала
match.end()      # Индекс сразу после конца
```

Поэтому длина:

```python
match.end() - match.start()
```

Важно: обычные `finditer()` и `findall()` возвращают **неперекрывающиеся** совпадения. Это свойство нужно учитывать при выборе шаблона. [Python 3.15.0 documentation](https://docs.python.org/3/library/re.html?utm_source=chatgpt.com)

**Чтобы составить шаблон арифметического выражения, сначала нужно точно определить допустимое число.**

Предположим:

- разрешены десятичные неотрицательные целые числа;
- ведущие нули запрещены;
- отдельное число `0` разрешено;
- разрешены операции `+` и `*`;
- унарных знаков нет, то есть выражение не начинается с `+` или `-`.

Подходящие числа:

```text
0
5
10
204
```

Неподходящие:

```text
00
03
007
```

Значит, число — это либо:

```text
0
```

либо:

> Ненулевая цифра, после которой идёт любое количество цифр.

Шаблон:

```python
number = r'(?:0|[1-9][0-9]*)'
```

Разберём:

- `0` — отдельный ноль;
- `|` — выбор другого варианта;
- `[1-9]` — первая ненулевая цифра;
- `[0-9]*` — остальные цифры, которых может не быть;
- `(?:...)` — объединение вариантов в одну группу.

Теперь структура выражения:

> Сначала число, затем ноль или больше повторений «операция + число».

Почему так?

- выражение начинается числом;
- между числами ровно одна операция;
- выражение заканчивается числом;
- соседних операций нет.

Шаблон:

```python
pattern = number + r'(?:[+*]' + number + r')*'
```

Внутри `[+*]` символы `+` и `*` обозначают сами знаки операций.

Полный поиск максимальной длины:

```python
import re

number = r'(?:0|[1-9][0-9]*)'
pattern = number + r'(?:[+*]' + number + r')*'

best = 0

for match in re.finditer(pattern, s):
    best = max(best, match.end() - match.start())

print(best)
```

Например:

```text
03+5**7+0*12
```

Самый длинный подходящий фрагмент:

```text
7+0*12
```

Длина: `6`.

Заметь: наличие `03` в исходной строке не запрещает начать подходящий фрагмент с символа `3`. Мы ищем подстроку, а не обязательно используем всю соседнюю группу цифр.

Если по условию нужно брать только целые группы цифр, ограниченные другими символами, это уже дополнительное требование к границам.

**Вычислять значение выражения для поиска его длины не нужно.** Здесь проверяется структура записи.

Если условие разрешает только некоторые цифры или накладывает особые ограничения на ноль, шаблон числа нужно изменить. Например, запрет ведущих нулей и запрет знака операции рядом с любой цифрой `0` — разные условия.

---

**Перекрывающиеся совпадения особенно важны, если подходящие фрагменты могут делить общую границу.**

Пусть дано:

```text
A12A345A
```

Ищем фрагменты вида:

> `A`, затем цифры, затем `A`.

Есть два:

```text
A12A
A345A
```

Они используют общую `A`.

Обычный поиск первого совпадения займёт эту букву и может пропустить начало второго.

Для проверки совпадений без «занятия» найденного текста существует конструкция:

```python
(?=...)
```

Она называется **просмотром вперёд**: проверяет, что с текущей позиции начинается нужная последовательность.

```python
import re

best = 0

for match in re.finditer(r'(?=(A[0-9]+A))', s):
    fragment = match.group(1)
    best = max(best, len(fragment))

print(best)
```

Обычные круглые скобки внутри сохраняют найденный фрагмент в группу номер `1`.

Поэтому здесь используется:

```python
match.group(1)
```

Сам внешний просмотр ничего не занимает, и поиск может проверить следующее начало.

Но этот приём не следует механически добавлять в любую задачу. Если с каждой позиции повторно просматриваются длинные одинаковые участки, программа может работать медленно.

Для фиксированного короткого слова явный перебор позиций часто проще и понятнее.

---

**Ограничение на количество чисел в выражении лучше переносить на последовательность самих чисел.**

Например:

> Найти самое длинное корректное выражение, содержащее не более двух чисел.

Строка:

```text
1+2+345678
```

Лучший ответ:

```text
2+345678
```

Длина: `8`.

Если искать неперекрывающиеся выражения сразу с ограничением в два числа, можно получить сначала:

```text
1+2
```

а затем:

```text
345678
```

и пропустить лучший фрагмент.

Надёжный подход:

1. Найти длинные корректные выражения без ограничения на количество чисел.
2. Внутри каждого выписать границы чисел.
3. Рассмотреть окна из не более `K` последовательных чисел.

Для простоты возьмём числа из цифр `1–9`, операции `+` и `*`:

```python
import re

K = 2    # K >= 1
best = 0

expression_pattern = r'[1-9]+(?:[+*][1-9]+)*'

for expression_match in re.finditer(expression_pattern, s):
    expression = expression_match.group()

    numbers = list(re.finditer(r'[1-9]+', expression))

    for j in range(len(numbers)):
        i = max(0, j - K + 1)

        length = numbers[j].end() - numbers[i].start()
        best = max(best, length)

print(best)
```

`list(...)` собирает найденные совпадения в список.

Для каждого правого числа `j` берём максимально раннее левое число, при котором их не больше `K`.

Почему невыгодно начинать посередине первого числа?

Это уменьшит длину, но не уменьшит количество чисел.

Почему невыгодно заканчивать посередине последнего?

По той же причине.

Так задача о строке превращается в задачу о последовательности чисел с известными позициями.

---

**Дополнительные требования к выражениям нужно рассматривать отдельно от их обычной корректности.**

Например:

> Порядок действий слева направо совпадает с порядком по правилам математики.

Сравним:

```text
2*3+4
```

и:

```text
2+3*4
```

В первом случае обычное движение слева направо соответствует приоритетам.

Во втором сначала нужно выполнить умножение, которое находится правее сложения.

Для выражений с `+`, `-`, `*`, без скобок, это означает:

> После появления сложения или вычитания в выбранном фрагменте не должно быть умножения.

То есть сначала могут идти умножения, затем — сложения и вычитания.

Можно работать с уже выделенными числами и знаками:

- пока условие соблюдается, продолжаем фрагмент;
- если встретилось умножение после сложения или вычитания, переносим начало к числу после последней такой операции.

Здесь проверяется именно **порядок операций**, а не случайное совпадение итоговых значений.

Другой вариант:

> Найти выражение с наибольшим значением.

Это тоже не то же самое, что максимальная длина.

Например, среди выражений, начинающихся сразу после `B`:

```text
B20-300+4
```

самое длинное выражение имеет значение `-276`, а короткий допустимый фрагмент `20` имеет большее значение.

Если разрешены только сложение и вычитание неотрицательных чисел, нужно учитывать результаты допустимых начальных частей выражения. Проверки только самого длинного совпадения недостаточно.

**Всегда разделяй:**

- корректность записи;
- длину записи;
- количество чисел или операций;
- значение выражения;
- правила выбора при равенстве.

---

**Число в задаче может означать либо запись в системе счисления, либо целую группу цифр с заданными границами.**

Это разные модели.

Если ищется запись числа в основании `14`, допустимы символы:

```text
0123456789ABCD
```

Буквы `E`, `F`, … разрывают такую запись.

Если ищется максимальное числовое значение, сначала нужно разобраться с ведущими нулями.

Например:

```text
00099
100
```

У первой записи больше символов, но второе число больше.

После удаления незначащих ведущих нулей:

> Любое положительное число с большим количеством цифр в одной системе счисления больше любого числа с меньшим количеством цифр.

Для основания `b`:

- наименьшее положительное `L`-значное число — \(b^{L-1}\);
- наибольшее число с `L-1` цифрами — \(b^{L-1}-1\).

При одинаковой длине сравниваются цифры слева направо.

Для стандартной записи цифрами `0–9`, затем заглавными буквами `A–Z`, порядок символов соответствует порядку значений цифр.

**Чётность по последней цифре определяется только в чётном основании.**

В основании `14` число чётное, если последняя цифра имеет чётное значение:

```text
0 2 4 6 8 A C
```

Потому что `A = 10`, `C = 12`.

В нечётном основании правило другое: все степени основания нечётны, поэтому чётность зависит от суммы значений цифр.

Если в допустимом блоке ищется максимальное чётное число в чётном основании, обычно выгодно:

1. убрать незначащие нули слева;
2. закончить на самой правой допустимой чётной цифре;
3. сравнить получившийся кандидат с другими.

Случай числа `0` рассматривается отдельно: после удаления ведущих нулей запись не должна ошибочно превратиться в «несуществующее число».

---

**Если «число» определено как группа цифр между буквами, границы становятся частью условия.**

Например:

```text
A123B4C5D
```

Здесь группы цифр:

```text
123
4
5
```

Но если искомая подстрока должна сама содержать обе ограничивающие буквы, то для двух последних чисел нужен фрагмент:

```text
B4C5D
```

Длина — `5`.

Вырезать только `4C5` в такой постановке нельзя: у крайних чисел внутри фрагмента не будет обеих буквенных границ.

Порядок действий:

1. Найти все полные объекты «буква — цифры — буква».
2. Сохранить их начала и концы.
3. Для `K` последовательных объектов взять от начала первого до конца последнего.

Объекты могут делить общую букву.

Для заглавных латинских букв:

```python
import re

starts = []
ends = []

for match in re.finditer(r'(?=([A-Z][0-9]+[A-Z]))', s):
    starts.append(match.start(1))
    ends.append(match.end(1) - 1)
```

Указание `(1)` означает границы первой сохранённой группы.

Теперь:

```python
K = 2
best = len(s) + 1

for j in range(len(starts) - K + 1):
    length = ends[j + K - 1] - starts[j] + 1
    best = min(best, length)
```

Это та же идея, что и для `K` вхождений слова. Только теперь у объектов разная длина.

Нужно внимательно читать определение и пример: иногда ограничивающие символы должны входить в искомую подстроку, иногда границы объектов определяются только в исходном файле.

---

**Ограничения на начало и конец фрагмента часто позволяют резко сократить перебор.**

Например:

> Фрагмент заканчивается гласной, содержит только одну гласную и ровно `K` букв `T`. Нужна минимальная длина.

Вместо перебора любых правых концов достаточно рассмотреть позиции гласных.

Для каждой такой позиции:

- предыдущая гласная не должна попасть внутрь;
- берём последние `K` букв `T`, расположенные после предыдущей гласной;
- начало ставим на первую из этих `K` букв.

```python
K = 3
vowels = 'AEIOUY'

positions_t = []
best = len(s) + 1

for i in range(len(s)):
    if s[i] == 'T':
        positions_t.append(i)

    elif s[i] in vowels:
        if len(positions_t) >= K:
            left = positions_t[-K]
            best = min(best, i - left + 1)

        positions_t = []
```

`positions_t[-K]` — `K`-й элемент с конца.

Почему после каждой гласной список очищается?

Следующий подходящий фрагмент не может пересекать эту гласную: иначе гласных будет уже две.

Набор гласных берём именно из условия задачи. Например, включение `Y` должно определяться формулировкой.

Другой пример:

> Начало и конец — одинаковые цифры, внутри только буквы.

Тогда концами могут быть только **соседние цифры исходной строки**.

Если между выбранными крайними цифрами находится третья цифра, условие уже нарушено.

Поэтому достаточно перебрать соседние позиции цифр, проверить:

- равенство крайних цифр;
- необходимую чётность;
- наличие букв между ними;
- дополнительные условия на эти буквы.

Такое выделение возможных границ нередко проще общего скользящего окна.

---

**Требование «встречаются все символы набора» тоже нужно сочетать с остальными условиями.**

Например:

> Найти самый длинный фрагмент только из цифр, содержащий все десять цифр.

Сначала последовательность разбивается буквами на цифровые блоки.

Если некоторый цифровой блок содержит все десять цифр, для максимума выгодно брать его целиком: дополнительные цифры не нарушают условие.

Можно поддерживать длину текущего цифрового блока и множество встреченных цифр:

```python
digits = '0123456789'

current = 0
seen = set()
best = 0

for c in s:
    if c in digits:
        current += 1
        seen.add(c)
    else:
        current = 0
        seen = set()

    if len(seen) == 10:
        best = max(best, current)

print(best)
```

`set()` создаёт пустое множество.

`seen.add(c)` добавляет символ. Повторное добавление того же символа не увеличивает размер множества.

Здесь `len(seen) == 10` означает, что встретились все десять различных цифр.

А вот для **минимального** фрагмента, содержащего все нужные символы, потребуется сжимать окно, пока каждый нужный символ ещё представлен хотя бы один раз.

Снова видно, что слова «минимальный» и «максимальный» меняют алгоритм.

---

**При равенстве основного критерия нужно явно реализовать дополнительный.**

Например:

> Найти самый длинный фрагмент; если таких несколько, выбрать начинающийся правее.

Храним:

```python
best_length = 0
best_start = -1
```

Для каждого найденного кандидата:

```python
length = right - left + 1

if length > best_length:
    best_length = length
    best_start = left

elif length == best_length and left > best_start:
    best_start = left
```

Если нужно вывести начальную позицию:

```python
print(best_start)
```

А не:

```python
print(best_length)
```

Обрати внимание и на нумерацию:

- если в условии позиции считаются с нуля, используем индекс Python;
- если с единицы — прибавляем один.

Не следует автоматически прибавлять единицу только потому, что в обычной речи говорят «первый символ».

---

**Выбирать алгоритм удобно по тому, какая информация определяет допустимость фрагмента.**

| Что определяет условие | Основная идея |
|---|---|
| Допустимость каждого отдельного символа | Текущая длина цепочки |
| Отношение соседних символов | Сравнение соседей и текущая длина |
| Условие на каждую соседнюю тройку | Проверка тройки и сохранение допустимого конца |
| Повторение фиксированного цикла | Следующий ожидаемый символ |
| Цепочка целых пар или троек | Проверка блоков по всем возможным смещениям |
| Количество коротких образцов | Перебор позиций начала |
| Частоты букв в определённом окружении | Словарь счётчиков |
| Максимум при верхних ограничениях | Расширять окно, сжимать при нарушении |
| Минимум при нижних ограничениях | Расширять до выполнения, затем сжимать |
| Все символы различны | Последние позиции и левая граница |
| `K` вхождений символа или слова | Список позиций |
| Много запросов о количестве внутри фрагментов | Префиксные суммы |
| Равенство количеств двух типов | Накопленный баланс |
| Числа и арифметические записи | Описание структуры, выделение чисел |
| Особые начало и конец | Перебор возможных границ |
| Несколько условий | Сочетание подходящих методов |

Эта таблица — ориентир. Перед использованием метода нужно объяснить, почему он подходит именно к данному условию.

---

**Проверка решения должна начинаться с маленьких строк, для которых ответ очевиден.**

Полезные случаи:

| Случай | Пример | Что проверяет |
|---|---|---|
| Один символ | `A` | Начальные значения |
| Вся строка подходит | `AAAAA` | Учёт последней цепочки |
| Ни один символ не подходит | `BBBBB` при поиске `A` | Возможный ответ `0` |
| Лучший фрагмент в начале | `AAAABC` | Левый край |
| Лучший фрагмент в конце | `BCAAAA` | Правый край |
| Несколько равных максимумов | `AAABAAA` | Правило выбора при равенстве |
| Соседние запрещённые символы | `ABXXCD` | Пустые части после разбиения |
| Перекрывающиеся слова | `ABABA` и образец `ABA` | Правильный подсчёт вхождений |
| Ровно нужное число вхождений | `BAAB`, `K = 2` | Отличие `<` от `<=` |
| Одно лишнее вхождение | `BAAAB`, `K = 2` | Сжатие окна |
| Ведущие нули | `0012+3` | Правило записи чисел |
| Соседние операции | `12++3` | Граница корректного выражения |

Для сложного алгоритма можно временно написать медленное решение, перебирающее все подстроки **короткой** строки, и сравнивать результаты.

Такой перебор не годится для большого экзаменационного файла, но отлично помогает проверить рассуждение.

---

**Вот ошибки, которые стоит научиться замечать ещё до запуска программы.**

- **Подмена количества длиной.**  
  Пять букв `A` внутри фрагмента не означают, что длина фрагмента равна пяти.

- **Подмена «ровно» на «не более».**  
  Окно с одной `A` не подходит, если требуется ровно две.

- **Неправильный сброс.**  
  Нужно объяснить, почему остаётся именно `0`, `1`, `2` или другая длина.

- **Потеря последнего фрагмента.**  
  Особенно если ответ обновляется только при разрыве.

- **Лишний или недостающий символ на границе.**  
  Проверяй различие между включённым концом и правой границей среза.

- **Перемещение левой границы назад.**  
  В алгоритмах с последними позициями часто нужен `max()`.

- **Использование `count()` для перекрывающихся слов.**

- **Удаление разделителей со склеиванием частей.**

- **Чтение только первой строки многострочного файла.**

- **Сохранение счётчиков между независимыми строками.**

- **Слишком дорогая операция внутри цикла.**  
  Например, на каждом шаге создавать длинный срез и заново выполнять `.count()`.

- **Вывод величины, по которой выбирали, вместо величины, которую спрашивают.**

- **Замена латинской буквы похожей русской.**  
  Например, латинская `A` и русская `А` для Python — разные символы.

**Для закрепления сначала реши следующие небольшие задачи вручную, затем напиши программу.** Важно не только получить число, но и назвать подходящий фрагмент и объяснить состояние переменных.

1. В строке `XXAXXXXBXX` найди самую длинную цепочку `X`.

2. В строке `ABBACAB` найди самый длинный фрагмент, в котором соседние символы различны.

3. В строке `BABAACB` найди максимальную длину фрагмента с не более чем двумя `A`.
