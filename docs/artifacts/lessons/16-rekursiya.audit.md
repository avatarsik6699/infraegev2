## Находки

### P0 — материал не подводит к реальным задачам

Сверка с ФИПИ смещает акцент: официальная рекомендация — **сначала упрощать**, потом считать. Раздел урока про сокращение
на верном пути, но охватывает одну «чистую» формулу и не назван первым шагом алгоритма; порядок решения в уроке должен быть
«упростить → выбрать способ (рекурсия с кешем / цикл) → проверить условие завершения».

1. **Нет ветвления и условий с константами.** Формулы вида «одна ветка для чётных, другая для нечётных, база при `n ≤ 1`»
   встречаются в трети банка и в половине пролога темы 214. В уроке — ни примера, ни задачи, ни Mistake.
2. **Нет рекурсии вверх и шагов не на 1.** `F(n+k)` с базой при больших `n`, `F(n−3)`, `F(n//2)`, `F(n//10)`.
   Шаг алгоритма «Считайте снизу вверх» на такие задачи не переносится, а `//` и `%` нигде не объяснены; ловушка `/` → `float`
   не упомянута.
3. **Две функции F и G, «сколько n» и дерево вызовов** заявлены в шаге 3 алгоритма, но не изучаются.
4. **Прикладная линия «цикл надёжнее» расходится с задачами.** Подраздел 5 и вопрос `checkpoint-loop-choice` внушают: рекурсия —
   для малых n, иначе цикл. В банке, наоборот, много задач, где естественна рекурсия с кешем (`n//2`, `n+3`, F/G, подсчёт по диапазону).
   В уроке не сказано число лимита (1000), нет `sys.setrecursionlimit`, нет `@lru_cache(None)` (в подразделе 7 — лишь абзац про `@cache`, доступный только в Python ≥ 3.9; решение — учить `@lru_cache(None)`). Проверено на примере из банка: `F(42999)` с двумя функциями падает в `RecursionError` даже при
   `setrecursionlimit(100000)` — этот случай решается либо циклом (одномерный шаг), либо потоком с увеличенным стеком, и ученик должен знать оба пути.
5. **Приём для больших n показан один раз и только для «чистого» случая.** 70 задач на разность и 22–55 на отношение: телескопирование
   арифметической прогрессии (`F(n)=2n+3+F(n−1)`), нечистое отношение `n·F(n−1) − 1` с «целой частью» (сокращение не работает), большие степени
   десяти в цифровых рекурсиях. Callout обещает «разность соседних значений», но примера нет.

### P1 — дидактика и последовательность

6. **Подраздел 3 («Почему это вообще определяет функцию»)** — индукция без примера и ошибки. Занимает место, которого не хватает
   реальным приёмам; естественнее слить его с подразделом 2 в два абзаца.
7. **Стек вызовов объясняется не там, где назван.** Подраздел 4 называется `code-and-call-stack`, но стек и `RecursionError` появляются только
   в подразделе 5. Дерева вызовов нет вообще, хотя оно нужно для подраздела 7 (повторные вычисления) и задач «сколько вызовов/символов».
8. **Формулы меняются без связки.** В подразделе 4 — `2·F(n−1)+1`, в подразделе 5 — `n·F(n−1)`, в примерах — ещё три разные. Каждый новый пример
   должен нести новую идею; сейчас часть просто заменяет формулу.
9. **Нарушен порядок «полный пример → задача с пропуском → самостоятельно» (SPEC §2.3).** Подраздел 5 — только код, без разобранного примера; 3 и 9 — без блока «ошибка».
   Задач-упражнений «с пропуском» в теории нет.
10. **Ошибки-«соломенные чучела».** «F(2) по формуле для n>3», «F(n−1) ≈ F(n)−1». Реальные ловушки не показаны:
    `/` вместо `//`, `n < 10` вместо `n ≤ 10`, порядок веток, отсутствие базы при `n+k` (бесконечная рекурсия), отсутствие кеша (медленно), `range` без `+1` повторено 4 раза
    (ошибка, вопрос, шаблон, алгоритм).
11. **Названия «Фибоначчи/трибоначчи»** (тема 275) появляются только в задаче банка; в теории не названы.

### Что нельзя взять как есть (риски для понимания)

1. **`@lru_cache()` без аргументов — ловушка.** У него `maxsize=128`: старые значения вытесняются, и в задачах с большим диапазоном
   (например, счёт по `n` до `10**6`) возможны повторные вычисления и замедление. Мы уже приняли `@lru_cache(None)`; урок должен *объяснить*
   разницу (`maxsize=128` vs без ограничения), а не только показать строку.
2. **«Магические» границы прогрева** (`3212`, `15`, `3000`): без объяснения ученик заучит числа. Нужно вывести правило: кеш заполняем в порядке, в котором значения
   становятся вычислимыми без глубокой рекурсии — от базы к цели; направление определяется знаком шага (`n+3` — вниз по `n`, `n−3` — вверх).
3. **`setrecursionlimit` — «точечное решение»** (слова авторов): не выдавать за универсальное. Показать 3 инструмента и *когда* каждый: сократить/упростить,
   прогреть кеш, увеличить лимит.
4. **Порядок «код → ответ» без предварительного упрощения.** Авторы сразу пишут программу; ФИПИ рекомендует сначала упростить. Для F(40)−F(44)
   надо показать оба пути и сверить ответ.
5. **Глобальный `count` для счёта вызовов** — приём для исследования, а не для решения; пометить как «инструмент измерения».
6. Статья 282 ставит функции и рекурсию рядом; для нашего урока это пререквизит, а не содержание — дублировать курс Python не нужно.

### Принцип для правок: смысл важнее приёмов

Каждый приём вводится по схеме **«проблема → наблюдение → идея → приём → проверка»**:
ученик сначала сталкивается с проблемой (счётчик вызовов, `RecursionError`, минута ожидания), формулирует, *что именно* повторяется или *куда* растёт цепочка,
и только затем получает инструмент. К каждому приёму — вопрос «почему это работает» и «когда не сработает»; итоговая проверка — вторым способом
(кеш ↔ упрощение, вверх ↔ вниз). Приёмы вроде порядка прогрева выводятся из направления зависимостей, а не запоминаются.
