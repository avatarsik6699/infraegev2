# ЕГЭ № 17 — проверка качества практики

Статус: локальная редакторская проверка завершена 27 сентября 2026 года; архитектор подтвердил готовность урока к `/ship`. Задачи и наборы чисел придуманы для этого урока; формулировки и данные не копировались из внешних банков. Урок и задачи имеют статус `published`, чтобы локальная страница совпадала с будущим публичным видом. Публикация в production выполняется отдельно.

## Последовательность заданий

| ID           | Навык и переход                                                        | Ответ | Сложность |
| ------------ | ---------------------------------------------------------------------- | ----: | --------: |
| `task-17-01` | Подсчёт отдельных чисел по двум условиям                               |     7 |         1 |
| `task-17-02` | Поиск максимума среди отдельных подходящих чисел                       |    52 |         1 |
| `task-17-03` | Подсчёт соседних пар по сумме                                          |     9 |         1 |
| `task-17-04` | Поиск максимальной суммы пары с проверкой порядка                      |    23 |         2 |
| `task-17-05` | Подсчёт строгих локальных максимумов в тройках с проверкой равенства   |     5 |         2 |
| `task-17-06` | Поиск максимальной суммы тройки по условию на середину                 |    44 |         2 |
| `task-17-07` | Первый проход для среднего значения, второй для пар и равенства порогу |   109 |         3 |
| `task-17-08` | Два прохода по 128 значениям, общий порог и границы тройки             |    31 |         3 |

Каждая задача имеет отдельный текстовый файл с целыми числами по одному на строку. Файлы адресуются SHA-256; метаданные, длина, перевод строк и содержимое проверяются автоматически. Все задачи состоят в `number-sequences` в позициях 0–7, имеют `exam_numbers: []` и `catalog_visible: false`; теория связана с одним из шести согласованных разделов.

Файл `task-17-05` содержит 22 строки; тройка `(15, 17, 17)` проверяет равенство с одним соседом. Файлы `task-17-07` и `task-17-08` содержат соответственно 120 и 128 строк, то есть требуют обработки всей последовательности программой. В обоих файлах используются повторяющиеся, но не одинаковые блоки чисел с заранее рассчитанным общим средним и проверяемыми переходами между блоками. В № 17-07 десять соседних пар имеют сумму ровно 50, равную среднему по файлу; строгая проверка их исключает. В № 17-08 у части середин значение ровно 50, у других — выше среднего; также проверяются тройки на стыке блоков.

## Независимая проверка ответов

Для каждого задания ответ повторно вычислен по прикреплённым целым числам отдельным выражением подсчёта или отбора. Также запущен код из объяснения с соответствующим `numbers.txt`; его вывод совпал с ответом. Checker принимает ожидаемое число и отклоняет указанное контрольное ошибочное значение.

| ID           | Контрольный ошибочный ответ | Итог проверки |
| ------------ | --------------------------: | ------------- |
| `task-17-01` |                           6 | 7             |
| `task-17-02` |                          51 | 52            |
| `task-17-03` |                           8 | 9             |
| `task-17-04` |                          22 | 23            |
| `task-17-05` |                           4 | 5             |
| `task-17-06` |                          43 | 44            |
| `task-17-07` |                         108 | 109           |
| `task-17-08` |                          30 | 31            |

Граничные сравнения проверены отдельно: если для № 17-05 заменить оба строгих сравнения середины на `>=`, ответ меняется с 5 на 6 из-за тройки `(15, 17, 17)`. Если для № 17-07 заменить `>` на `>=`, ответ меняется с 109 на 119: в подсчёт добавятся десять пар с суммой ровно 50. В № 17-08 замена условия для середины с `>` на `>=` увеличивает число подходящих троек с 31 до 63; равные порогу середины не должны засчитываться.

Публичная проекция отдельно проверена на отсутствии checker, вариантов ответа и приватного источника. Файл остаётся доступным через обычную публичную доставку вложений; его имя, checksum и размер согласованы с банком.

Проверки выполнены командами `pnpm format:check`, `cd apps/api && uv run ruff check app tests migrations` и `cd apps/api && uv run pytest -q tests/test_task_17_bank.py`: формат и lint проходят, тесты — **10 passed**. Они покрывают модель банка, ссылки и порядок, размеры и контрольные суммы файлов, независимый подсчёт, исполнение всех восьми примеров, правильный/неправильный ответ, строгие границы, отсутствие стадии `review` в активной схеме и публичную проекцию для всех восьми задач. Общая content validation подтвердила регистрацию материала и шести разделов в release registry.

## Решение редактора

Архитектор оценил готовую локальную страницу и разрешил завершить Change 149. Замечания к объяснениям, иллюстрации и оформлению внесены в Backlog и исправлены до `/ship`. Финальный аудит дополнительно проверил исполнение законченных примеров Python, пробелы в готовом HTML и повтор настройки E2E-фикстур.
