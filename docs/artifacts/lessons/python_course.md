## 0 Как работать с учебником

У чтения кода и написания кода разные задачи. Когда читаешь, попробуй заранее предсказать результат. Когда пишешь, сначала объясни будущие действия по-русски. Проверяй не только совпадение ответа, но и своё понимание причин.

Для каждого примера полезен такой порядок:

1. Прочитай условие и выпиши исходные данные.
2. Предскажи результат программы до запуска.
3. Выполни её и сравни результат с прогнозом.
4. Измени одно значение: например, положительное число на отрицательное, непустую строку на пустую.
5. Объясни, почему результат изменился или остался прежним.
6. Через некоторое время восстанови решение без подсматривания.

**Как читать примеры.** Блок с пометкой Python содержит код. Строки после знака `#` — пояснения, не команды. Ожидаемый результат часто указан в таком пояснении. Код, специально демонстрирующий ошибку, отдельно помечен; его нельзя бездумно вставлять в рабочую программу.

Короткий фрагмент иногда продолжает предыдущий: если в нём используется уже введённое имя, сохрани предыдущие строки. Законченные программы и функции содержат необходимые определения. Команды для терминала отличаются от кода Python: их запускают в командной строке операционной системы.

**Критерий понимания.** Недостаточно знать, что цикл «что-то перебирает». Нужно уметь сказать, какое значение он рассматривает сейчас, какие данные уже обработаны и что означает каждая изменяющаяся переменная.

## 1 Программа и её выполнение

### 1.1 От задачи к программе

Предположим, нужно найти стоимость трёх тетрадей по 40 рублей. Человек может сразу получить 120. Для компьютера нужно описать действия: взять количество, взять цену, перемножить их, показать результат.

**Алгоритм** — точное описание действий для решения задачи. **Программа** — запись этих действий на языке, который может обрабатывать компьютер. Один алгоритм можно записать на Python, другом языке или сначала обычными словами.

**Исходный код** — текст программы. Python — и название языка, и привычное название программы, которая выполняет код. Такую исполняющую программу называют **интерпретатором**. Он разбирает записи и организует вычисления. В распространённой реализации CPython исходный текст сначала преобразуется во внутренние инструкции. Для первых программ достаточно понимать наблюдаемое поведение; представление «компьютер буквально исполняет каждую напечатанную строку по очереди» позднее нужно уточнить: условия пропускают блоки, циклы повторяют их, функции выполняются при вызове.

### 1.2 Как запустить первый пример

Установи Python 3 с официального сайта [python.org](https://www.python.org/downloads/) или используй уже установленную учебную среду. **Редактор** помогает писать текст; **интерпретатор** выполняет его. **IDE** — среда, объединяющая редактор, запуск и средства поиска ошибок. Для обучения достаточно редактора и способа запустить файл; IDLE входит во многие установки Python.

Создай файл `main.py`. Расширение `.py` обозначает исходный файл Python. Запиши:

```python
print("Привет!")
print(3 * 40)
```

В IDLE сохрани файл и выбери Run Module. При запуске из терминала перейди в папку файла и выполни одну подходящую команду:

```shell
python main.py
```

На некоторых компьютерах команда называется `python3`, а в Windows может быть доступна `py`. Используй ту, для которой проверка версии показывает Python 3:

```shell
python --version
```

Терминал — окно, принимающее команды операционной системы. Он отличается от интерактивной оболочки Python, где приглашение часто выглядит как `>>>`. В оболочку вводят Python-код, а не команду `python main.py`. Само приглашение `>>>` в файл копировать не надо.

`print` — готовая функция вывода. Пока считай функцию именованным действием, которому можно передать данные. Скобки после имени означают **вызов**: просьбу выполнить это действие. Переданные внутри скобок данные называются **аргументами**. В первом вызове передаётся текст, во втором — результат умножения.

### 1.3 Выражение и инструкция

**Выражение** вычисляет значение: `3 * 40`, `2 + 5`, `"Привет!"`. **Инструкция** задаёт действие программы: присваивание, условие, цикл. Вызов функции тоже является выражением, хотя на первых шагах нас часто интересует его действие — например, вывод.

В интерактивной оболочке результат введённого выражения обычно показывается автоматически. В файле строка `3 * 40` сама по себе ничего не напечатает. Чтобы увидеть результат, используй `print(3 * 40)`.

### 1.4 Программа не догадывается о намерениях

Python различает `price` и `Price`. Пропущенная кавычка, неверный знак или отступ могут изменить смысл либо сделать запись недопустимой. Правила допустимой записи называются **синтаксисом**. Если правила записи соблюдены, это ещё не доказывает, что решена нужная задача.

Практика: напиши программу, выводящую своё имя, затем результат `12 + 8`, затем текст `12 + 8`. Объясни разницу двух последних строк.

<details markdown="1">

<summary>Разбор</summary>

```python
print("Владислав")
print(12 + 8)       # 20
print("12 + 8")     # 12 + 8
```

Кавычки превращают запись в текстовые данные. Python не вычисляет арифметику внутри обычной строки.

</details>

## 2 Значения типы и переменные

### 2.1 Почему число и текст отличаются

`27` и `"27"` выглядят похоже, но решают разные задачи. Первое — число, второе — последовательность символов. С числом выполняют арифметику; текст можно соединять с другим текстом.

**Тип** определяет, как устроено значение и какие операции для него имеют смысл.

| Тип | Название | Примеры | Зачем нужен |
| --- | --- | --- | --- |
| `int` | Целое число | `0`, `18`, `-7` | Количество, счётчик, точные целые вычисления |
| `float` | Число с плавающей точкой | `2.5`, `-0.125` | Приближённые измерения и дробные вычисления |
| `str` | Строка | `"Python"`, `"27"`, `""` | Текст |
| `bool` | Логическое значение | `True`, `False` | Ответ на вопрос «выполнено ли условие» |
| `NoneType` | Тип отсутствующего значения | `None` | Явно обозначить отсутствие результата |

Названия других типов появятся вместе с задачами, для которых они нужны. `None` — специальное значение, а не строка `"None"`, не число 0 и не пустой текст.

### 2.2 Присваивание выполняется справа налево по смыслу

```python
price = 40
quantity = 3
cost = price * quantity
print(cost)  # 120
```

В строке `cost = price * quantity` сначала вычисляется выражение справа. Затем имя `cost` связывается с полученным значением. Такая операция называется **присваиванием**, а имя для обращения к значению — **переменной**.

Знак `=` здесь не утверждает математическое равенство навсегда. Он задаёт действие в конкретный момент:

```python
x = 5
y = x + 2
x = 100
print(y)  # 7
```

При создании `y` выражение `x + 2` уже вычислено. В `y` не сохраняется формула, которая автоматически пересчитывается при изменении `x`.

| После строки | `x` | `y` |
| --- | ---: | ---: |
| `x = 5` | 5 | ещё не определена |
| `y = x + 2` | 5 | 7 |
| `x = 100` | 100 | 7 |

### 2.3 Почему допустимо x равно x плюс один

```python
count = 4
count = count + 1
print(count)  # 5
```

Сначала читается прежнее значение `count`, к нему прибавляется 1, и имя связывается с результатом. Сокращённая запись для этого случая — `count += 1`. У Python нет операции увеличения `count++`. Позднее увидим, что для изменяемых коллекций `+=` может именно менять существующий объект.

### 2.4 Имена и объекты

Удобная первая метафора — «переменная хранит значение». Более точная модель Python: в памяти существуют **объекты**, а имена ссылаются на них. Объект — конкретные данные с типом и состоянием. Если два имени относятся к одному изменяемому списку, изменение через одно имя будет видно через второе. Эту важную ситуацию подробно разберём в главе о списках.

Тип принадлежит объекту. Одно имя разрешено сначала связать с целым числом, затем со строкой:

```python
value = 10
print(type(value))  # <class 'int'>
value = "десять"
print(type(value))  # <class 'str'>
```

`type(...)` сообщает тип. Возможность менять тип значения у имени называют динамической типизацией. Это не означает, что Python автоматически складывает любые данные: `10 + "5"` вызовет ошибку несовместимых типов.

### 2.5 Как выбирать имена

Используй понятные имена: `total`, `count`, `max_value`, `student_name`. Слова обычно разделяют подчёркиваниями. Имя не начинается с цифры, не содержит пробелов и не совпадает со служебным словом языка, например `if` или `for`. Регистр различается.

Не называй переменные `list`, `str`, `sum`, `max`: это имена полезных встроенных средств. Такое присваивание разрешено, но закрывает доступ к прежнему значению имени в этой области программы. Для короткого номера позиции обычно уместно `i`, а для суммы — `total`.

Комментарий объясняет причину, условие или назначение, которое неочевидно из кода:

```python
discount = 10  # Скидка в процентах, а не в рублях
```

Практика: предскажи вывод `a = 3; b = a; a += 4; print(a, b)`. Точка с запятой здесь лишь разделяет инструкции; в собственном коде запиши их на отдельных строках.

<details markdown="1">

<summary>Разбор</summary>

Вывод — `7 3`. Изменение привязки имени `a` к новому целому числу не меняет значение, к которому относится `b`.

</details>

## 3 Числа и арифметические операции

### 3.1 Основные операции

| Запись | Значение | Пример |
| --- | --- | --- |
| `a + b` | Сложение | `8 + 3` → `11` |
| `a - b` | Вычитание | `8 - 3` → `5` |
| `a * b` | Умножение | `8 * 3` → `24` |
| `a / b` | Деление | `8 / 2` → `4.0` |
| `a // b` | Частное с округлением вниз | `8 // 3` → `2` |
| `a % b` | Остаток | `8 % 3` → `2` |
| `a ** b` | Возведение в степень | `2 ** 5` → `32` |

Для целых `a` и `b` с ненулевым `b` выполняется:

`a = (a // b) * b + a % b`.

Это объясняет одновременно частное и остаток. В числе 23 содержатся четыре полные пятёрки и ещё 3: `23 // 5 == 4`, `23 % 5 == 3`.

Умножение записывается явно: `2 * x`, а не `2x`. Степень обозначается `**`, а не `^`. Знак `^` имеет другое назначение, которое будет объяснено в главе о битах.

### 3.2 Отрицательные числа требуют точного понимания

«Отбросить дробную часть» и «округлить вниз» — разные действия:

```python
print(-7 / 3)       # приблизительно -2.3333333333333335
print(-7 // 3)      # -3
print(-7 % 3)       # 2
print(int(-7 / 3))  # -2
```

Вниз означает к меньшему числу: среди целых, не превышающих −2.333…, наибольшее — −3. Остаток согласован с частным: `-7 = (-3) * 3 + 2`. При положительном делителе остаток неотрицателен и меньше делителя. В общем случае ненулевой остаток имеет знак делителя.

`int` для конечного дробного числа отбрасывает дробную часть по направлению к нулю. Поэтому заменять `//` на `int(a / b)` нельзя: мешают и отрицательные значения, и потеря точности при переходе больших целых во `float`.

### 3.3 Приоритет операций

Сначала выполняются выражения в скобках, затем степени, умножение и деления, затем сложение и вычитание. Операции одной обычной арифметической ступени выполняются слева направо. Для степеней есть особенность: цепочка группируется справа.

```python
print(2 + 3 * 4)     # 14
print((2 + 3) * 4)   # 20
print(2 ** 3 ** 2)   # 512, то есть 2 ** (3 ** 2)
print(-3 ** 2)       # -9, то есть -(3 ** 2)
print((-3) ** 2)     # 9
```

Не превращай знание приоритетов в соревнование. Скобки полезны, если по ним сразу понятен математический смысл.

### 3.4 Целые числа и приближённые числа

Python умеет работать с целыми намного больше привычных 32- или 64-битных диапазонов: например, `2 ** 200` остаётся точным целым. Ограничения задаются ресурсами компьютера, а операции с огромными числами занимают больше времени. «Целое произвольной точности» не означает «вычисления любой величины бесплатны».

`float` хранит приближение числа в двоичной форме. Так же как десятичная запись 1/3 бесконечна, некоторые короткие десятичные дроби не имеют конечной двоичной записи.

```python
print(0.1 + 0.2 == 0.3)  # False
print(0.1 + 0.2)         # 0.30000000000000004
```

Это свойство выбранного представления, а не случайная поломка Python. Для проверки целочисленной делимости используй `%`, не дробное деление. Если задача по смыслу целочисленная, сохраняй целые как можно дольше.

Для сравнения результатов приближённых вычислений подходит `math.isclose`, который появится после знакомства с модулями. Допуск зависит от масштаба и смысла задачи, его нельзя выбирать механически.

### 3.5 Полезные встроенные действия

```python
print(abs(-12))       # 12 — модуль числа
print(min(5, 2, 9))   # 2
print(max(5, 2, 9))   # 9
print(round(2.5))     # 2
print(round(3.5))     # 4
```

`round` округляет до ближайшего; при точном равенстве расстояний используется ближайшее чётное. Из-за представления `float` некоторые десятичные «половинки» внутри компьютера не точные половинки: поэтому `round(2.675, 2)` даёт `2.67`. Для денежных сумм часто подходят целые копейки или `Decimal` из стандартной библиотеки.

### 3.6 Делимость и цифры

Условие «`n` делится на `d`» означает нулевой остаток: `n % d == 0`. Нельзя делить на ноль. Чётность проверяется как `n % 2 == 0`, в том числе для отрицательных целых.

Если `n` — неотрицательное целое, то `n % 10` — последняя десятичная цифра, а `n // 10` — число без неё. Почему? Любое такое число представимо как `10 * q + r`, где `r` — от 0 до 9. Эти `q` и `r` и вычисляют две операции.

```python
n = 472
print(n % 10)         # 2
print(n // 10)        # 47
print(n // 10 % 10)   # 7
```

Для цифр отрицательного числа обычно сначала берут `abs(n)`: знак не является цифрой.

Практика: даны `seconds = 3671`. Получи часы, минуты и секунды внутри последней минуты.

<details markdown="1">

<summary>Разбор</summary>

```python
seconds = 3671
hours = seconds // 3600
minutes = seconds % 3600 // 60
remaining_seconds = seconds % 60
print(hours, minutes, remaining_seconds)  # 1 1 11
```

Остаток от деления на 3600 удаляет полные часы. Деление оставшегося количества на 60 выделяет полные минуты. Для неотрицательной длительности это именно требуемое разложение.

</details>

## 4 Ввод преобразование и вывод данных

### 4.1 Что возвращает input

`input()` ждёт строку, введённую пользователем, и возвращает её как `str`. Нажатие Enter завершает ввод, а завершающий перевод строки не входит в результат.

```python
name = input("Как тебя зовут? ")
print("Привет,", name)
```

Введённое `25` будет строкой `"25"`. Python не может знать, является это возрастом, кодом товара или частью телефонного номера. Поэтому решение о преобразовании принимает автор программы.

```python
age_text = input()
age = int(age_text)
print(age + 1)
```

Сокращённая запись `age = int(input())` означает те же этапы: сначала внутренний вызов `input`, затем преобразование его результата с помощью `int`.

### 4.2 Когда преобразование возможно

```python
print(int("-12"))     # -12
print(float("2.75"))  # 2.75
print(str(123))       # текст 123
```

`int("2.75")` вызывает `ValueError`: строка не записывает целое число в ожидаемом формате. `int(2.75)` допустимо и даёт 2 — здесь исходное значение уже является числом. `float("2,75")` тоже не подходит: десятичный разделитель Python — точка. Если формат входа специально использует запятую, её заменяют осознанно после знакомства со строковыми методами.

Преобразование не исправляет смысл само. Например, индекс предмета `"007"` после `int` превратится в 7. Если ведущие нули значимы, оставь текст.

### 4.3 Вывод нескольких значений

```python
print(10, 20, 30)                 # 10 20 30
print(10, 20, 30, sep="; ")       # 10; 20; 30
print("Начало", end=" ")
print("продолжение")              # на той же строке
```

Обычные аргументы — значения для вывода. `sep=` задаёт разделитель между ними, `end=` — окончание вывода. Такая запись передаёт аргумент по имени. По умолчанию разделитель — пробел, окончание — перевод строки.

### 4.4 Подстановка в строку

```python
count = 7
price = 12.5
print(f"Количество: {count}; стоимость: {count * price:.2f}")
```

Буква `f` перед кавычками включает подстановку выражений из фигурных скобок. `count * price` вычисляется обычным образом. Часть `:.2f` задаёт формат вывода: две цифры после десятичной точки. Она меняет представление при выводе, а не превращает исходное число в точное десятичное.

При автоматической проверке задач обычно выводят только требуемые значения. Подсказки внутри `input("Введите...")` удобны человеку, но становятся лишним текстом для проверяющей системы.

Практика: введи длину и ширину прямоугольника на двух отдельных строках. Выведи площадь и периметр. Сначала реши для целых значений, затем для дробных.

<details markdown="1">

<summary>Разбор</summary>

```python
length = float(input())
width = float(input())
area = length * width
perimeter = 2 * (length + width)
print(area, perimeter)
```

Если по условию данные целые и нужен точный целочисленный результат, замени `float` на `int`.

</details>

## 5 Логические выражения

### 5.1 Выражение может отвечать на вопрос

```python
temperature = 18
is_warm = temperature >= 15
print(is_warm)  # True
```

Результат сравнения — логическое значение: `True` означает «истина», `False` — «ложь». Это не текстовые подписи, а значения типа `bool`.

| Запись | Вопрос |
| --- | --- |
| `a == b` | Равны ли значения? |
| `a != b` | Различаются ли значения? |
| `a < b` | Меньше ли первое? |
| `a <= b` | Меньше либо равно? |
| `a > b` | Больше ли первое? |
| `a >= b` | Больше либо равно? |

`=` присваивает, `==` сравнивает. В записи `is_warm = temperature >= 15` правая часть отвечает на вопрос, левая сохраняет ответ под именем.

### 5.2 Составные условия

`and` означает совместное выполнение условий, `or` — выполнение хотя бы одного, `not` — отрицание. Для логических значений:

| `a` | `b` | `a and b` | `a or b` | `a != b` |
| --- | --- | --- | --- | --- |
| False | False | False | False | False |
| False | True | False | True | True |
| True | False | False | True | True |
| True | True | True | True | False |

Последний столбец означает «ровно одно условие истинно». Здесь `a` и `b` именно логические значения. Для произвольных чисел `a != b` означает различие чисел, а не различие их истинности.

Интервал удобно записывать цепочкой:

```python
x = 12
print(5 <= x < 20)           # True
print(x % 2 == 0 and x > 0)  # True
```

`5 <= x < 20` означает выполнение обоих сравнений. Частая ошибочная идея: записать «x равно 2 или 3» как `x == 2 or 3`. Нужно `x == 2 or x == 3`. Иначе справа стоит отдельное число 3, которое рассматривается как истинное значение.

### 5.3 Короткое вычисление

Python не вычисляет часть условия, которая уже не влияет на ответ. В `a and b` значение `b` не нужно, если `a` ложно. В `a or b` значение `b` не нужно, если `a` истинно.

```python
x = 0
print(x != 0 and 10 / x > 2)  # False, деления на ноль нет
```

Порядок частей значим: безопасная проверка должна стоять раньше действия, которому она даёт разрешение.

### 5.4 Истинность обычных значений

В условии ноль, пустая строка и `None` считаются ложными; ненулевые числа и непустые строки — истинными. Позднее к ложным добавятся пустые коллекции.

`bool(value)` явно получает логическую оценку. `bool("False")` равно `True`, потому что строка непустая. Python не переводит её английский текст в логическое значение.

Для произвольных объектов `and` и `or` возвращают один из операндов, а не обязательно `bool`:

```python
print("" or "Без названия")  # Без названия
print(5 and 8)              # 8
```

В первом случае первая строка ложна, поэтому возвращается запасная. Во втором первый операнд истинен, поэтому результатом становится второй. При обычных сравнениях операнды уже логические, поэтому результат тоже выглядит как `True` или `False`.

### 5.5 Отрицание и импликация

Выражение `not (a and b)` истинно, когда хотя бы одно из условий ложно; оно равносильно `(not a) or (not b)`. Аналогично `not (a or b)` равносильно `(not a) and (not b)`.

**Импликация** «если A, то B» ложна только при истинном A и ложном B. Её можно записать `(not A) or B`. Это полезно в задачах на формальную логику; не путай такую проверку логического отношения с инструкцией `if`, которая управляет выполнением кода.

Практика: запиши условие «число делится на 3 или на 5, но не на оба сразу».

<details markdown="1">

<summary>Разбор</summary>

```python
n = 15
by_three = n % 3 == 0
by_five = n % 5 == 0
answer = by_three != by_five
print(answer)  # False
```

Подойдут, например, 9 и 10. Не подойдут 7 и 15. Эти четыре проверки покрывают все комбинации двух признаков.

</details>

## 6 Условное выполнение

### 6.1 Зачем нужно ветвление

Программа расчёта доставки может действовать по-разному: при большой сумме заказа доставка бесплатна, иначе стоит 300 рублей. **Ветвление** — выбор действий на основании условия.

```python
order_total = 2400
if order_total >= 2000:
    delivery = 0
else:
    delivery = 300
print(delivery)
```

`if` проверяет условие. Двоеточие открывает блок связанных инструкций. Строки с одинаковым увеличенным отступом принадлежат блоку. Обычно используют четыре пробела. `else` означает альтернативу, когда условие `if` ложно. После возврата к прежнему отступу выполнение продолжается вне ветвления.

**Отступ — часть смысла программы.** Это не украшение, как выравнивание текста в тетради. Не смешивай табуляции и пробелы.

### 6.2 Несколько исключающих друг друга случаев

```python
score = 73
if score >= 85:
    level = "высокий"
elif score >= 60:
    level = "средний"
else:
    level = "начальный"
print(level)
```

`elif` — следующая проверка, если предыдущие не подошли. Здесь выбирается ровно одна ветка. Во вторую ветку попадают значения от 60 до 84: верхняя граница уже следует из неуспеха первой проверки.

Если сначала проверить `score >= 60`, а потом `score >= 85`, высокий результат захватит первая ветка. Поэтому порядок проверок нужно выводить из условий, а не выбирать наугад.

### 6.3 Когда нужны отдельные if

Если у числа одновременно может быть несколько признаков, нужны независимые проверки:

```python
n = 12
if n % 2 == 0:
    print("чётное")
if n % 3 == 0:
    print("делится на 3")
```

Будут напечатаны обе строки. Замена второго `if` на `elif` запретила бы второй вывод после успешного первого.

### 6.4 Вложенность и определённость имён

Внутри ветки может находиться ещё одно ветвление. Это полезно, когда вторая проверка имеет смысл только после первой. Однако несколько уровней вложенности трудно читать: иногда составное условие или ранний выход из функции проще.

Проверь, что имя получит значение на каждом пути, где оно понадобится:

```python
x = -2
if x > 0:
    result = "положительное"
else:
    result = "неположительное"
print(result)
```

Если убрать `else`, при `x = -2` имя `result` в свежем запуске не появится. Интерактивная среда может скрыть ошибку, если от прошлого запуска осталось старое значение; поэтому регулярно запускай весь файл заново.

Для простого выбора значения есть условное выражение:

```python
x = -2
absolute = x if x >= 0 else -x
```

Сначала проверяется условие, затем вычисляется только выбранная часть. Для сложных действий обычный `if` читается лучше.

Практика: по трём целым числам найди наибольшее без `max`. Разреши равные числа и отрицательные значения.

<details markdown="1">

<summary>Разбор</summary>

```python
a = -5
b = -2
c = -9
best = a
if b > best:
    best = b
if c > best:
    best = c
print(best)  # -2
```

Начальное значение взято из данных. Если начать с нуля, все отрицательные значения ошибочно проиграют числу, которого среди данных нет.

</details>

## 7 Цикл while и состояние программы

### 7.1 Повторение по условию

**Цикл** повторяет блок действий. `while` перед каждым повторением проверяет условие. Если оно истинно, выполняется тело цикла; затем проверка начинается заново.

```python
i = 1
while i <= 4:
    print(i)
    i += 1
```

Будут напечатаны числа 1, 2, 3, 4. Затем `i` станет 5, условие окажется ложным. Одно выполнение тела называют **итерацией**.

Если перед первой проверкой условие ложно, тело не выполняется ни разу. Если забыть изменение `i`, в примере выше условие будет оставаться истинным — получится бесконечный цикл. Его можно остановить кнопкой остановки среды или обычно сочетанием Ctrl+C.

### 7.2 Счётчик и накопитель

Найдём сумму чисел от 1 до 4:

```python
i = 1
total = 0
while i <= 4:
    total += i
    i += 1
print(total)  # 10
```

`i` указывает следующее добавляемое число. `total` хранит сумму уже обработанных чисел. Такая переменная называется **накопителем**. Если переменная хранит количество событий, её называют **счётчиком**.

| Перед проверкой | `i` | `total` | Что уже сложено |
| --- | ---: | ---: | --- |
| Первый раз | 1 | 0 | ничего |
| Второй раз | 2 | 1 | 1 |
| Третий раз | 3 | 3 | 1 + 2 |
| Четвёртый раз | 4 | 6 | 1 + 2 + 3 |
| Пятый раз | 5 | 10 | 1 + 2 + 3 + 4 |

Сумма начинается с 0, потому что прибавление 0 не меняет результат. Произведение обычно начинают с 1 по аналогичной причине. Если начать произведение с нуля, оно навсегда останется нулевым.

### 7.3 Почему цикл даёт правильный ответ

Утверждение «перед проверкой `total` равен сумме чисел от 1 до `i - 1`» верно перед первой итерацией. Тело добавляет число `i` и увеличивает `i`, поэтому утверждение остаётся верным. Когда цикл останавливается при `i = 5`, обработаны именно числа от 1 до 4.

Утверждение, сохраняющееся на одинаковом этапе каждой итерации, называется **инвариантом цикла**. Это способ понимать и доказывать решение, а не дополнительная команда Python.

Отдельно объясни завершение: `i` возрастает на 1 и неизбежно превышает 4. Правильное состояние без гарантии завершения ещё не даёт работающего алгоритма.

### 7.4 Обработка цифр

```python
number = -5072
n = abs(number)
digit_sum = 0
while n > 0:
    digit = n % 10
    digit_sum += digit
    n //= 10
print(digit_sum)  # 14
```

После выделения последней цифры она удаляется из рабочего числа. Поэтому следующая итерация рассматривает соседнюю цифру слева. `number` сохраняет исходное значение; `n` — рабочая копия привязки к целому значению. Для числа 0 сумма цифр тоже 0: ноль итераций здесь дают правильный результат.

Но для **количества** цифр ноль — отдельный случай: в его записи одна цифра. Аналогично нельзя оставить отрицательное `n` и ожидать, что `n //= 10` обязательно доведёт его до нуля: `-1 // 10` остаётся −1. Поэтому сначала берут модуль.

### 7.5 break и continue

`break` немедленно завершает ближайший окружающий цикл. `continue` пропускает оставшуюся часть текущей итерации и переходит к следующей проверке.

```python
total = 0
while True:
    n = int(input())
    if n == 0:
        break
    total += n
print(total)
```

Здесь 0 — заранее выбранный признак окончания ввода, а не часть суммы. `while True` сам по себе бесконечен; выход задаёт `break`. Нужно понимать, что будет, если пользователь никогда не введёт 0.

При `continue` легко пропустить изменение управляющей переменной. Если оно стоит ниже `continue`, программа может застрять на одном значении.

Практика: найди наименьшее целое `k >= 0`, для которого `2 ** k >= n`, где `n` — положительное целое. Не используй логарифм.

<details markdown="1">

<summary>Разбор</summary>

```python
n = 17
k = 0
power = 1
while power < n:
    power *= 2
    k += 1
print(k)  # 5
```

На каждом шаге `power == 2 ** k`. Цикл прекращается при первом достижении границы. Для `n = 1` ответ 0 получается без единой итерации.

</details>

## 8 Цикл for и диапазоны

### 8.1 Повторение для набора значений

`for` по очереди получает элементы некоторого источника и выполняет тело для каждого. Источник, из которого можно последовательно получать элементы, называют **перебираемым объектом**. Примерами будут строка, диапазон и список.

```python
for letter in "CODE":
    print(letter)
```

На каждой итерации `letter` связывается с очередной буквой. Получатся четыре строки. Имя можно выбрать другое; слово `letter` не является специальной командой.

### 8.2 Что такое range

`range` описывает арифметическую последовательность целых чисел. Он хранит её параметры, а не заранее созданный список всех чисел.

| Запись | Получаемые значения |
| --- | --- |
| `range(4)` | 0, 1, 2, 3 |
| `range(2, 6)` | 2, 3, 4, 5 |
| `range(2, 9, 3)` | 2, 5, 8 |
| `range(5, 0, -2)` | 5, 3, 1 |
| `range(5, 0)` | ни одного |

В форме `range(start, stop, step)` начало включено, остановка исключена. При положительном шаге перебор продолжается, пока значение меньше `stop`; при отрицательном — пока больше `stop`. Шаг 0 запрещён.

Чтобы пройти целые от `a` до `b` включительно при `a <= b`, используют `range(a, b + 1)`. Исключённая правая граница удобна: количество целых от 0 до `n - 1` равно `n`; соседние диапазоны `range(0, k)` и `range(k, n)` не перекрываются.

### 8.3 for не равен ручному увеличению переменной

```python
for i in range(3):
    print(i)
    i = 100
```

Вывод — 0, 1, 2. Присваивание меняет текущее имя, но не источник будущих значений. Следующая итерация снова получает очередной элемент `range`. Для изменения правил перехода чаще нужен `while`.

### 8.4 Вложенные циклы

```python
for row in range(2):
    for column in range(3):
        print(row, column)
```

Для каждого `row` внутренний цикл выполняется целиком: пары `(0, 0)`, `(0, 1)`, `(0, 2)`, затем `(1, 0)`, `(1, 1)`, `(1, 2)`. Всего 2 × 3 итерации внутреннего тела. `break` внутри него завершает только внутренний цикл.

### 8.5 Поиск первого подходящего значения

```python
answer = None
for n in range(100, 201):
    if n % 17 == 0:
        answer = n
        break
print(answer)  # 102
```

Перебор идёт по возрастанию, поэтому первый найденный результат минимален. Если подходящего числа нет, сохраняется `None`. Проверять отсутствие результата следует как `answer is None`; слово `is` сравнивает тождественность объектов. Подробно отличим его от `==` в главе о списках.

У цикла также бывает `else`: он выполняется при нормальном исчерпании перебора, если `break` не был выполнен. Для `while` это завершение по ложному условию. `else` может выполниться и при нуле итераций. Это конструкция «не встретился выход через break», а не «условие последней итерации было ложным». Пока такая запись непривычна, явное `answer = None` обычно понятнее.

Практика: найди количество и сумму чисел от 1 до 100 включительно, кратных 7.

<details markdown="1">

<summary>Разбор</summary>

```python
count = 0
total = 0
for n in range(1, 101):
    if n % 7 == 0:
        count += 1
        total += n
print(count, total)  # 14 735
```

Можно перебирать только нужные числа с помощью `range(7, 101, 7)`. Такой переход полезен, когда понятно, почему он охватывает все и только нужные значения.

</details>

## 9 Строки как последовательности символов

### 9.1 Что хранит строка

Строка — упорядоченная последовательность символов. У неё есть длина, элементы и фрагменты. Порядок существенен: `"кот"` и `"ток"` состоят из одинаковых букв, но являются разными строками.

```python
word = "PYTHON"
print(len(word))  # 6
print(word[0])   # P
print(word[2])   # T
print(word[-1])  # N
```

`len` получает количество элементов. **Индекс** — номер позиции. Положительные индексы начинаются с 0: это удобно понимать как число шагов от начала. Для строки длины `n` допустимы индексы от 0 до `n - 1`. Отрицательные индексы считают с конца: −1 — последний элемент, −2 — предпоследний.

| Символ | P | Y | T | H | O | N |
| --- | --- | --- | --- | --- | --- | --- |
| Индекс от начала | 0 | 1 | 2 | 3 | 4 | 5 |
| Индекс с конца | -6 | -5 | -4 | -3 | -2 | -1 |

Обращение к `word[6]` вызывает `IndexError`: такой позиции нет. У пустой строки `""` длина 0, поэтому в ней нет даже элемента с индексом 0. Отдельного встроенного типа «символ» в Python нет: `word[0]` тоже строка, просто длины 1.

### 9.2 Срезы и их границы

**Срез** получает последовательность элементов по правилу `s[start:stop:step]`. Остановка не включается, как в `range`.

```python
s = "ABCDEFG"
print(s[1:4])    # BCD
print(s[:3])     # ABC
print(s[4:])     # EFG
print(s[::2])    # ACEG
print(s[::-1])   # GFEDCBA
print(s[5:1:-1]) # FEDC
```

Для положительного шага пропущенное начало означает начало строки, пропущенная остановка — её конец. Для отрицательного шага значения по умолчанию меняются: движение начинается с конца и идёт до начала. Поэтому `s[::-1]` разворачивает всю строку.

Важно различать пропущенную границу и явно написанное `-1`. В `s[5:-1:-1]` явное `-1` сначала означает последний индекс. При строке длины 7 движение от позиции 5 назад к границе 6 не даёт ни одного элемента. Пропущенная остановка при отрицательном шаге — особое обозначение движения за начало.

Срез за пределами длины обычно обрезается: `s[:100]` вернёт всю строку. Одиночный неверный индекс вызывает ошибку. Срез может быть пустым; это нормальный результат. Шаг 0 недопустим.

### 9.3 Строка неизменяема

**Неизменяемость** означает, что нельзя заменить элемент внутри существующей строки. Инструкция `s[0] = "Z"` вызывает ошибку. Можно построить новую строку и связать с ней имя:

```python
s = "кот"
s = "р" + s[1:]
print(s)  # рот
```

`+` соединяет строки. Это действие называют **конкатенацией**. `"ab" * 3` повторяет текст и создаёт `"ababab"`. Старый объект не переписывается, даже если имя переменной осталось прежним.

### 9.4 Что такое метод

Метод — именованное действие, связанное с объектом. Запись `s.lower()` означает «вызвать действие `lower` для строки `s`». Точка связывает действие с объектом, скобки запускают его.

| Операция | Значение |
| --- | --- |
| `s.lower()` / `s.upper()` | Создать строку в нижнем / верхнем регистре |
| `s.strip()` | Удалить пробельные символы по краям |
| `s.replace(old, new)` | Создать строку с заменами |
| `s.replace(old, new, 1)` | Заменить только первое вхождение |
| `s.find(part)` | Индекс первого вхождения или −1 |
| `s.count(part)` | Число неперекрывающихся вхождений |
| `s.startswith(part)` | Начинается ли строка указанным фрагментом |
| `s.endswith(part)` | Заканчивается ли указанным фрагментом |
| `part in s` | Есть ли фрагмент внутри строки |

Методы не меняют исходную строку. Вызов `s.replace("a", "b")` с проигнорированным результатом не обновляет `s`; для этого нужно присваивание.

```python
s = "  Python  "
clean = s.strip().lower()
print(clean)  # python
```

Сначала `strip` создаёт промежуточную строку без крайних пробелов; затем `lower` вызывается уже для неё. Это два последовательных действия. `strip("ab")` убирает по краям любой набор символов `a` и `b`, а не обязательно целую подстроку `"ab"`. Для удаления ровно одного известного префикса существует `removeprefix`.

Не проверяй поиск как `if s.find(part):`: индекс 0 ложен, а отсутствие с индексом −1 истинно. Используй `part in s` или явное сравнение с −1.

### 9.5 Перекрывающиеся фрагменты

В `"AAAA"` фрагмент `"AA"` начинается на позициях 0, 1 и 2. Но `"AAAA".count("AA")` возвращает 2: после найденного совпадения поиск продолжится за ним.

Для подсчёта всех начал можно проверить каждую позицию:

```python
s = "AAAA"
part = "AA"
count = 0
for i in range(len(s) - len(part) + 1):
    if s[i:i + len(part)] == part:
        count += 1
print(count)  # 3
```

Последнее допустимое начало — `len(s) - len(part)`. Именно поэтому верхняя граница `range` на 1 больше. Если шаблон длиннее текста, диапазон пуст. Пустой шаблон имеет отдельную математическую семантику; в задачах поиска сначала уточни, допускается ли он.

### 9.6 Специальные символы и Unicode

`\n` внутри обычной строки означает перевод строки, `\t` — табуляцию, `\\` — один обратный слеш. Чтобы увидеть представление со специальными символами, используй `repr`:

```python
s = "A\nB"
print(len(s))   # 3: A, перевод строки, B
print(repr(s))  # 'A\nB'
```

Python хранит строки как Unicode-текст. `ord("A")` возвращает код символа, `chr(65)` — символ по коду. Обычная сортировка строк основана на кодах, а не на словарных правилах русского языка. Некоторые визуально единые знаки, особенно эмодзи с модификаторами, состоят из нескольких кодовых точек: `len` считает именно кодовые точки, а не всегда видимые «картинки».

Строковые методы `isdigit()` и `isalpha()` работают шире набора английских букв и цифр ASCII. Если условие разрешает строго цифры `0`–`9`, проверяй соответствующий набор. Пустая строка для `isdigit()` даёт `False`.

Практика: проверь, читается ли слово одинаково слева направо и справа налево. Такое слово называют палиндромом. Сначала считай, что вводится одно слово в одном регистре.

<details markdown="1">

<summary>Разбор</summary>

```python
word = "топот"
print(word == word[::-1])  # True
```

Для фразы сначала нужно определить правила: учитываются ли пробелы, пунктуация и регистр. Удалять их без условия нельзя, потому что это меняет задачу.

</details>

## 10 Списки и изменяемые данные

### 10.1 Когда одной переменной недостаточно

Для тысячи измерений неудобно создавать тысячу имён. **Список** хранит последовательность элементов под одним именем:

```python
temperatures = [18, 21, 19, 23]
print(temperatures[1])  # 21
print(len(temperatures)) # 4
```

Индексы и срезы работают похоже на строки. Главное различие: список изменяем. Он может хранить значения разных типов, но для обработки чисел обычно удобен однородный список.

```python
numbers = [4, 7, 2]
numbers[1] = 10
numbers.append(8)
print(numbers)  # [4, 10, 2, 8]
```

`append` добавляет один элемент в конец. Если элементом является другой список, он добавляется целиком как один вложенный элемент. `extend` поочерёдно добавляет элементы переданного источника.

| Действие | Что делает |
| --- | --- |
| `a.append(x)` | Добавляет один элемент |
| `a.extend(items)` | Добавляет элементы из `items` |
| `a.insert(i, x)` | Вставляет перед позицией `i` |
| `a.pop()` | Удаляет и возвращает последний элемент |
| `a.pop(i)` | Удаляет и возвращает элемент на позиции `i` |
| `a.remove(x)` | Удаляет первое равное значение; ошибка, если нет |
| `del a[i]` | Удаляет элемент по индексу |
| `a.clear()` | Удаляет все элементы |
| `a.index(x)` | Индекс первого равного элемента; ошибка, если нет |
| `a.count(x)` | Число вхождений значения |

Методы вроде `append`, `extend` и `sort` меняют список и возвращают `None`. Поэтому `a = a.append(5)` теряет связь имени `a` со списком: результат метода — `None`.

### 10.2 Проход по значениям и по индексам

```python
a = [4, 7, 2]
for value in a:
    print(value)

for i in range(len(a)):
    a[i] *= 2
print(a)  # [8, 14, 4]
```

Первый вариант удобен, когда нужны сами элементы. Второй — когда нужны позиции, соседние значения или замена элементов. Инструкция `value *= 2` в первом цикле с целыми числами изменила бы только привязку имени `value`, а не список.

Не удаляй элементы из того же списка во время обычного прямого обхода, если не контролируешь смещение позиций: после удаления следующий элемент может быть пропущен. Проще собрать новый список подходящих элементов.

### 10.3 Присваивание не копирует список

```python
a = [1, 2]
b = a
b.append(3)
print(a)  # [1, 2, 3]
```

`a` и `b` — два имени одного объекта. Поэтому изменение видно через оба имени. Чтобы создать отдельный внешний список, используют `a.copy()`, `a[:]` или `list(a)`.

```python
a = [1, 2]
b = a.copy()
b.append(3)
print(a)       # [1, 2]
print(b)       # [1, 2, 3]
print(a == b)  # False
print(a is b)  # False
```

`==` сравнивает содержимое, `is` — являются ли значения одним и тем же объектом. Два разных списка `[1, 2]` могут быть равны по содержимому. Для чисел и строк сравнивай значения через `==`; детали повторного использования объектов не должны влиять на программу. Уместное применение `is` — `value is None`.

### 10.4 Вложенные списки и поверхностная копия

Список может содержать другие списки: так удобно представлять таблицу. Но копирование внешнего списка не копирует автоматически его внутренние элементы.

```python
a = [[1, 2], [3, 4]]
b = a.copy()
b[0][0] = 99
print(a)  # [[99, 2], [3, 4]]
```

Созданы два внешних списка, но их элементы указывают на прежние общие строки таблицы. Такая копия называется **поверхностной**. Позднее познакомимся с `copy.deepcopy`, создающей глубокую копию подходящих вложенных структур.

Особенно опасна запись:

```python
table = [[0] * 3] * 2
table[0][0] = 9
print(table)  # [[9, 0, 0], [9, 0, 0]]
```

Внешнее умножение повторило ссылку на одну строку. Создай каждую строку отдельно:

```python
table = []
for row in range(2):
    table.append([0] * 3)
table[0][0] = 9
print(table)  # [[9, 0, 0], [0, 0, 0]]
```

`[0] * 3` безопасно для последующей замены отдельных чисел: целые неизменяемы, а присваивание элементу заменяет ссылку. Проблема возникает при изменении повторённых вложенных объектов.

### 10.5 Из текста в список и обратно

`split` разбивает строку и возвращает список частей:

```python
print("  10   20  30 ".split())  # ['10', '20', '30']
print("a,,b".split(","))         # ['a', '', 'b']
```

Без аргумента разделителями служат серии пробельных символов, лишние края исчезают. Явный разделитель имеет другую семантику: соседние разделители дают пустую часть. Поэтому `.split()` и `.split(" ")` не взаимозаменяемы.

Разберём несколько чисел из одной строки без сокращений:

```python
line = "10 20 30"
parts = line.split()
numbers = []
for part in parts:
    numbers.append(int(part))
print(numbers)  # [10, 20, 30]
```

Обратное соединение строк выполняет `join`:

```python
words = ["Учимся", "писать", "программы"]
print(" ".join(words))  # Учимся писать программы
```

Объект перед точкой — разделитель. Элементы должны быть строками: целые сначала преобразуют. Для последовательного вывода чисел позже пригодится также `print(*numbers)`.

Практика: из `[5, -2, 0, 8, -1]` создай отдельный список неотрицательных значений. Исходный список должен сохраниться.

<details markdown="1">

<summary>Разбор</summary>

```python
source = [5, -2, 0, 8, -1]
result = []
for value in source:
    if value >= 0:
        result.append(value)
print(result)  # [5, 0, 8]
```

Пустой результат допустим. Отдельное имя `result` сразу обозначает отдельный созданный список, а не вторую ссылку на исходный.

</details>

## 11 Кортежи распаковка и совместный перебор

### 11.1 Неизменяемая последовательность

**Кортеж** (`tuple`) похож на список, но нельзя заменить его элемент, добавить или удалить позицию. Он подходит для небольшой записи: координат, пары «имя и результат», нескольких возвращаемых значений.

```python
point = (3, 5)
print(point[0])  # 3
single = (8,)
empty = ()
```

Кортеж создаёт запятая, а не только круглые скобки. `(8)` — просто число в скобках, `(8,)` — кортеж из одного элемента. Неизменяемость внешнего кортежа не делает неизменяемым список внутри него: содержимое такого списка по-прежнему можно менять.

### 11.2 Распаковка

**Распаковка** связывает несколько имён с элементами последовательности:

```python
point = (3, 5)
x, y = point
print(x, y)  # 3 5

a = 10
b = 20
a, b = b, a
print(a, b)  # 20 10
```

Справа сначала вычисляются прежние значения `b` и `a`, затем выполняется присваивание. Обычные последовательные строки `a = b; b = a` обмена не дадут: прежнее `a` будет потеряно.

Количество значений должно совпадать с количеством имён. Можно обозначить имя для остальных элементов звёздочкой:

```python
first, *middle, last = [10, 20, 30, 40]
print(first, middle, last)  # 10 [20, 30] 40
```

`middle` получает список. Распаковка работает и для списков, строк и других перебираемых объектов, а не только кортежей.

### 11.3 enumerate и zip

`enumerate` выдаёт пары «номер и элемент»:

```python
names = ["Анна", "Илья", "Марк"]
for position, name in enumerate(names, start=1):
    print(position, name)
```

`start=1` меняет выдаваемые номера, но не индексы исходного списка. В каждой итерации пара распаковывается в два имени.

`zip` соединяет несколько источников по позициям:

```python
names = ["Анна", "Илья"]
scores = [91, 84]
for name, score in zip(names, scores):
    print(name, score)
```

Обычный `zip` заканчивается при исчерпании самого короткого источника. Если длины по смыслу обязаны совпадать, используй `zip(names, scores, strict=True)` в Python 3.10+ или отдельно проверь длины: так потеря данных не пройдёт незаметно.

Звёздочка в вызове функции означает ещё одно применение распаковки:

```python
numbers = [10, 20, 30]
print(*numbers)  # 10 20 30
```

Элементы передаются отдельными аргументами, как в `print(10, 20, 30)`. Это не умножение: значение знака зависит от его места в синтаксисе.

Практика: есть список пар `[("Анна", 91), ("Илья", 84)]`. Выведи только имена тех, у кого результат не меньше 90.

<details markdown="1">

<summary>Разбор</summary>

```python
students = [("Анна", 91), ("Илья", 84)]
for name, score in students:
    if score >= 90:
        print(name)
```

Пара из списка сразу распаковывается: обращаться к `student[0]` и `student[1]` не требуется.

</details>

## 12 Словари и подсчёт частот

### 12.1 Доступ по смысловому ключу

В списке элемент ищут по позиции. Иногда нужен доступ по имени: «балл Анны», «количество буквы A». **Словарь** (`dict`) хранит соответствия между ключами и значениями.

```python
scores = {"Анна": 91, "Илья": 84}
print(scores["Анна"])  # 91
scores["Марк"] = 88
scores["Анна"] = 95
```

Ключ уникален: новое присваивание тому же ключу заменяет его значение. Значения могут повторяться. Чтение отсутствующего ключа через квадратные скобки вызывает `KeyError`.

```python
print(scores.get("Ольга", 0))  # 0
print("Анна" in scores)        # True
```

`get(key, default)` возвращает значение либо указанное значение по умолчанию; ключ от этого не добавляется. Без второго аргумента значение по умолчанию — `None`. Операция `in` для словаря проверяет ключи, а не значения.

### 12.2 Почему не всякий объект может быть ключом

Для быстрого поиска словарь использует **хеш** — вычисляемую характеристику ключа. Равные ключи должны иметь равные хеши; совпадение хешей само по себе не означает равенства, поэтому словарь дополнительно сравнивает ключи.

Ключ должен быть **хешируемым**: его хеш и поведение равенства должны оставаться согласованными, пока он служит ключом. Для обычных задач используй строки, числа и кортежи из хешируемых элементов. Список, словарь и обычное множество ключами быть не могут. Кортеж, содержащий список, тоже не годится. Это точнее правила «любой неизменяемый объект подходит».

Значения словаря такими ограничениями не связаны: можно хранить под именем пользователя целый список его результатов.

### 12.3 Обход и порядок

```python
scores = {"Анна": 91, "Илья": 84}
for name in scores:
    print(name)

for name, score in scores.items():
    print(name, score)
```

`.items()` позволяет получать пары, `.keys()` — ключи, `.values()` — значения. Это представления данных словаря, а не обязательно отдельные списки. `list(scores)` создаёт список ключей.

В Python 3.7+ сохраняется порядок добавления ключей. Это не сортировка: ключи не выстраиваются автоматически по алфавиту или величине. Замена значения существующего ключа не переносит его в конец. Не меняй количество ключей во время обхода того же словаря.

### 12.4 Частотная таблица

**Частота** — число появлений значения. Пройдём по буквам и увеличим соответствующий счётчик:

```python
text = "BANANA"
counts = {}
for letter in text:
    counts[letter] = counts.get(letter, 0) + 1
print(counts)  # {'B': 1, 'A': 3, 'N': 2}
```

Если буква встретилась впервые, `get` даёт 0. После прибавления записывается 1. При следующих появлениях читается накопленное значение. Инвариант: после обработки первых `k` символов словарь содержит точные частоты в этой части текста.

Ключи `1`, `1.0` и `True` сравниваются равными и используются как один ключ. Поэтому в смысловых идентификаторах лучше не смешивать числа и логические значения без необходимости.

Практика: по списку `['a', 'b', 'a', 'c', 'b', 'a']` найди значение с наибольшей частотой. При равенстве выбери то, которое впервые встретилось раньше.

<details markdown="1">

<summary>Разбор</summary>

```python
items = ['a', 'b', 'a', 'c', 'b', 'a']
counts = {}
for item in items:
    counts[item] = counts.get(item, 0) + 1

best_item = None
best_count = 0
for item, count in counts.items():
    if count > best_count:
        best_item = item
        best_count = count
print(best_item, best_count)  # a 3
```

Строгое `>` оставляет прежнего победителя при равенстве. Порядок словаря совпадает с порядком первых появлений. Для пустого входа ответ остаётся `None, 0` — это выбранное обозначение отсутствия результата.

</details>

## 13 Множества и выбор структуры данных

### 13.1 Только различные значения

**Множество** (`set`) хранит различные хешируемые элементы и удобно для проверки принадлежности.

```python
values = [3, 1, 3, 2, 1]
unique = set(values)
print(len(unique))  # 3
print(2 in unique)  # True
```

Множество не сохраняет смыслового порядка и не поддерживает обращение по индексу. То, что в отдельном запуске вывод выглядит упорядоченным, не даёт права на это рассчитывать. Для отсортированного результата используй `sorted(unique)` после главы о сортировке.

Пустое множество — `set()`. Запись `{}` создаёт пустой словарь. Непустое множество можно записать `{1, 2, 3}`.

### 13.2 Изменение и операции

```python
a = {1, 2, 3}
b = {3, 4}
print(a | b)  # объединение: элементы из любого множества
print(a & b)  # пересечение: элементы одновременно в обоих
print(a - b)  # разность: элементы a, отсутствующие в b
print(a ^ b)  # элементы ровно одного из двух множеств
print({1, 2} <= a)  # True: первое множество — подмножество a
```

`add(x)` добавляет элемент, `discard(x)` удаляет, если он присутствует. `remove(x)` тоже удаляет, но отсутствие вызывает ошибку. `frozenset` — неизменяемое множество, которое может быть ключом словаря.

У одинакового знака могут быть разные операции для разных типов: для целых `&` работает с битами, для множеств находит пересечение. Значение определяется типами операндов. Логическое `and` — отдельная операция.

### 13.3 Что выбрать

| Структура | Когда подходит | Что важно помнить |
| --- | --- | --- |
| `str` | Текст | Неизменяема |
| `list` | Последовательность с изменением элементов | Сохраняет порядок и повторы |
| `tuple` | Небольшая неизменяемая запись | Вложенные элементы могут быть изменяемыми |
| `dict` | Соответствие ключ → значение | Уникальные хешируемые ключи |
| `set` | Различные значения и принадлежность | Порядка и индексов нет |

Выбор зависит от нужных действий, а не только от вида исходных данных. Чтобы посчитать **количество разных** слов, достаточно множества. Чтобы посчитать **частоту каждого**, нужен словарь.

Практика: есть два списка участников. Найди людей, присутствующих в обоих. Пока порядок результата не важен.

<details markdown="1">

<summary>Разбор</summary>

```python
first = ["Анна", "Илья", "Анна"]
second = ["Илья", "Марк"]
common = set(first) & set(second)
print(common)  # {'Илья'}
```

Повторяющаяся Анна в первом списке не создаёт вторую копию человека во множестве. Если повторы означают отдельные события и должны учитываться, множество теряет нужную информацию.

</details>

## 14 Компактное построение коллекций

### 14.1 Сначала понять обычный цикл

Построим квадраты чисел:

```python
squares = []
for n in range(1, 6):
    squares.append(n * n)
print(squares)  # [1, 4, 9, 16, 25]
```

Тот же смысл можно выразить **списковым включением** — записью правила построения списка:

```python
squares = [n * n for n in range(1, 6)]
```

Читай по смыслу: «для каждого `n` из диапазона взять `n * n`». Хотя выражение результата стоит слева, значение `n` появляется из части `for`.

### 14.2 Фильтрация и выбор значения

```python
even_squares = [n * n for n in range(1, 8) if n % 2 == 0]
print(even_squares)  # [4, 16, 36]
```

`if` после источника — фильтр: неподходящий элемент вовсе не попадает в результат. Условное выражение перед `for` решает другую задачу:

```python
a = [-3, 0, 5]
labels = ["plus" if x > 0 else "other" for x in a]
print(labels)  # ['other', 'other', 'plus']
```

Здесь результат имеет столько же элементов, сколько исходный список. Меняется выбираемое значение, а не число элементов.

### 14.3 Несколько циклов

```python
pairs = [(x, y) for x in range(2) for y in range(3)]
```

Части `for` идут в том же порядке, что обычные вложенные циклы. Внешний — по `x`, внутренний — по `y`. Не используй чрезмерно длинные включения: если пояснение становится труднее исходного цикла, лучше оставить цикл.

Независимые строки таблицы теперь можно создавать так:

```python
table = [[0] * 3 for _ in range(2)]
```

Каждое повторение вычисляет `[0] * 3` заново. Имя `_` — обычная переменная, которой по соглашению обозначают ненужное значение.

### 14.4 Другие включения и полезные функции

```python
unique_lengths = {len(word) for word in ["кот", "дом", "окно"]}
squares_by_number = {n: n * n for n in range(4)}
print(unique_lengths)      # множество со значениями 3 и 4
print(squares_by_number)   # {0: 0, 1: 1, 2: 4, 3: 9}
```

`sum(a)` складывает элементы, `min(a)` и `max(a)` находят крайние значения. `sum([])` равно 0, но `min([])` и `max([])` без значения по умолчанию вызывают ошибку: у пустого набора нет минимума или максимума.

`all(...)` проверяет, что все элементы истинны, `any(...)` — что истинен хотя бы один. Они останавливаются, когда ответ уже известен. Для пустого источника `all` возвращает `True`, а `any` — `False`: нет ни одного нарушения первого требования и ни одного подтверждения второго.

```python
numbers = [2, 4, 8]
print(all([x % 2 == 0 for x in numbers]))  # True
print(any([x < 0 for x in numbers]))      # False
```

Позднее уберём создание промежуточного списка с помощью генераторного выражения. На этом этапе явный список помогает увидеть логические значения, которые получает функция.

Практика: преобразуй строку `"10 -2 7"` в список целых одной понятной записью.

<details markdown="1">

<summary>Разбор</summary>

```python
line = "10 -2 7"
numbers = [int(part) for part in line.split()]
print(numbers)  # [10, -2, 7]
```

В этой строке нет новой магии: `split` создаёт части, цикл перебирает их, `int` преобразует каждую, включение собирает список.

</details>

## 15 Собственные функции

### 15.1 Выделить понятное действие

Если одну проверку приходится повторять или её смысл теряется среди остальных строк, полезно дать ей имя. **Функция** объединяет инструкции в действие с входными данными и, возможно, возвращаемым результатом.

```python
def rectangle_area(width, height):
    return width * height

area = rectangle_area(3, 5)
print(area)  # 15
```

`def` создаёт функцию. `rectangle_area` — её имя. `width` и `height` — **параметры**, то есть локальные имена для входных данных. В вызове числа 3 и 5 — **аргументы**, конкретные переданные значения.

При выполнении определения тело не запускается. Оно выполняется при вызове. Поэтому одинаковую функцию можно вызвать много раз с разными аргументами. Программа должна успеть выполнить определение до момента вызова; определение другой функции может находиться ниже, если до реального вызова оно уже будет выполнено.

### 15.2 return и print делают разное

`return` завершает текущий вызов и передаёт значение тому месту, где он произошёл. `print` показывает текст, но не делает этот текст возвращаемым результатом.

```python
def square(number):
    return number * number

result = square(4) + square(3)
print(result)  # 25
```

Если вместо `return` поставить `print`, квадраты будут видны на экране, но сложение результатов вызовов не сработает: оба вызова вернут `None`.

Функция без выполненного `return` со значением возвращает `None`. Запись `return` без выражения тоже возвращает `None`. Инструкции после выполненного `return` в этом вызове уже не исполняются.

```python
def describe_sign(number):
    if number > 0:
        return "положительное"
    if number < 0:
        return "отрицательное"
    return "ноль"
```

Ранний возврат позволяет последовательно исключить случаи без лишней вложенности.

### 15.3 Локальные имена и область видимости

**Область видимости** — часть программы, в которой имя разрешается определённым способом. Параметры и присваивания внутри функции обычно создают локальные имена, существующие для данного вызова.

```python
x = 10

def calculate():
    x = 3
    return x + 1

print(calculate())  # 4
print(x)            # 10
```

Внутреннее `x` не заменяет внешнее. При поиске имени Python рассматривает локальную область, окружающие области функций, область модуля и встроенные имена. Этот порядок часто сокращают как LEGB; полезнее понимать сами уровни, чем заучивать буквы.

Если внутри функции есть присваивание имени, Python обычно считает его локальным во всём теле. Поэтому попытка сначала прочитать его, а потом присвоить может привести к `UnboundLocalError`. Конструкции `global` и `nonlocal` позволяют явно выбрать внешнюю область, но для первых программ чаще проще передать нужное значение параметром и вернуть новое.

У `if` и `for` нет собственной отдельной области имён, как у функции. Переменная, присвоенная внутри выполненной ветки, остаётся доступной после неё в окружающей области.

### 15.4 Передача объектов и побочные изменения

Аргументы передаются как объекты, а параметры связываются с ними. Присваивание параметру и изменение переданного объекта — разные действия:

```python
def rebind(items):
    items = [99]

def mutate(items):
    items.append(99)

a = [1, 2]
rebind(a)
print(a)  # [1, 2]
mutate(a)
print(a)  # [1, 2, 99]
```

В `rebind` заменяется локальная связь имени. В `mutate` меняется тот же список, на который ссылается внешнее `a`. Изменение данных вне возвращаемого результата называют **побочным эффектом**. Вывод и запись файла — тоже побочные эффекты.

В описании функции полезно явно указывать, меняет ли она переданную коллекцию. Если изменение не нужно, создавай отдельный результат.

### 15.5 Позиционные и именованные аргументы

```python
def final_price(price, discount=0):
    return price * (100 - discount) / 100

print(final_price(200))               # 200.0
print(final_price(200, 10))           # 180.0
print(final_price(discount=10, price=200))
```

`discount=0` в определении — значение по умолчанию. В вызове именованные аргументы уточняют, какому параметру соответствует значение. Обычные позиционные аргументы записывают перед именованными. Одному параметру нельзя передать значение дважды.

Значения по умолчанию вычисляются при выполнении определения, а не заново для каждого вызова. Поэтому изменяемый список в параметре по умолчанию будет общим между вызовами.

```python
def add_item(item, items=None):
    if items is None:
        items = []
    items.append(item)
    return items

print(add_item(1))  # [1]
print(add_item(2))  # [2]
```

`None` обозначает отсутствие переданного списка. В таком случае создаётся новый. Если пользователь явно передал список, функция изменит именно его. Эта договорённость должна быть понятна из описания.

### 15.6 Несколько результатов и произвольные аргументы

```python
def quotient_and_remainder(a, b):
    return a // b, a % b

q, r = quotient_and_remainder(23, 5)
print(q, r)  # 4 3
```

Фактически возвращается один кортеж, который распаковывается. Для этой конкретной операции уже существует `divmod(a, b)`, но пример показывает общую механику.

Параметр `*values` собирает произвольное число позиционных аргументов в кортеж. `**options` собирает именованные аргументы в словарь. Это другой контекст знакомых знаков.

```python
def total_of(*values):
    return sum(values)

print(total_of(2, 3, 5))  # 10
```

Звёздочка без имени в списке параметров заставляет последующие параметры передавать по имени: `def show(value, *, label="Результат"):`. Символ `/` в сигнатуре означает, что предшествующие параметры только позиционные. Эти формы полезно узнавать в документации; для собственных первых функций они не обязательны.

### 15.7 Функции как значения и lambda

Имя функции можно передать другой функции. Без скобок это сама функция; со скобками — результат её вызова.

```python
def last_digit(number):
    return abs(number) % 10

rule = last_digit
print(rule(47))  # 7
```

`lambda number: abs(number) % 10` создаёт короткую функцию с одним выражением. Это эквивалентно показанной `last_digit`, если не учитывать имя и некоторые свойства описания. Она автоматически возвращает результат выражения. Несколько инструкций в `lambda` не помещают: используй `def`.

### 15.8 Как проектировать функцию

Сначала сформулируй **договорённость**: что функция принимает, что возвращает, какие случаи допускаются, меняет ли аргументы. Например: «принимает целое число, возвращает сумму цифр его модуля».

```python
def digit_sum(number):
    """Вернуть сумму десятичных цифр модуля целого числа."""
    number = abs(number)
    total = 0
    while number > 0:
        total += number % 10
        number //= 10
    return total
```

Первая строка текста в теле функции — **строка документации**, или docstring. Её может показывать `help(digit_sum)`. Тройные кавычки позволяют записывать многострочный текст; это не особый вид комментария.

Практика: напиши `count_even(numbers)`, возвращающую количество чётных элементов без изменения списка.

<details markdown="1">

<summary>Разбор</summary>

```python
def count_even(numbers):
    count = 0
    for number in numbers:
        if number % 2 == 0:
            count += 1
    return count

print(count_even([0, 3, -4, 7]))  # 2
```

Возврат стоит после цикла. Если поставить его внутри тела, функция закончится после первого элемента. Для пустого списка корректно возвращается 0.

</details>

## 16 Сортировка и выбор лучших элементов

### 16.1 Изменить список или получить новый

```python
a = [8, 2, 5]
b = sorted(a)
print(a)  # [8, 2, 5]
print(b)  # [2, 5, 8]
a.sort(reverse=True)
print(a)  # [8, 5, 2]
```

`sorted` принимает перебираемый источник и возвращает новый список. `.sort()` доступен у списка, меняет его на месте и возвращает `None`. Параметр `reverse=True` задаёт обратный порядок.

Строки из цифр сортируются как текст: `"100"` идёт раньше `"20"`, потому что сначала сравниваются первые символы. Если нужен числовой порядок, преобразуй данные в числа либо задай числовой ключ.

### 16.2 Что делает key

**Ключ сортировки** — значение, по которому сравнивают элемент. Сам элемент при этом остаётся прежним.

```python
words = ["арбуз", "кот", "дом", "окно"]
print(sorted(words, key=len))
# ['кот', 'дом', 'окно', 'арбуз']
```

Передаётся функция `len`, а не результат `len(...)`. При сортировке Python применяет функцию ключа к каждому элементу и использует полученные значения для упорядочивания. Это также избавляет от ручного сравнения каждой пары строк.

### 16.3 Несколько критериев

Кортежи сравниваются **лексикографически**: сначала первые элементы; если они равны — вторые, и так далее. Это похоже на порядок слов в словаре, но применяется к любым сравнимым элементам.

```python
students = [("Анна", 91), ("Илья", 84), ("Марк", 91)]
ordered = sorted(students, key=lambda student: (-student[1], student[0]))
print(ordered)
# [('Анна', 91), ('Марк', 91), ('Илья', 84)]
```

Балл сортируется по убыванию благодаря минусу: 91 превращается в −91, что меньше −84. При равных баллах имя сортируется по возрастанию. `reverse=True` для всего кортежа развернул бы оба критерия, поэтому это не то же самое.

### 16.4 Устойчивость и один лучший элемент

Сортировка Python **устойчива**: элементы с одинаковым ключом сохраняют взаимный исходный порядок. Например, слова `"кот"` и `"дом"` имеют одинаковую длину и останутся в исходной последовательности.

Если нужен только лучший элемент, нет необходимости сортировать всё:

```python
words = ["арбуз", "кот", "дом", "окно"]
longest = max(words, key=len)
print(longest)  # арбуз
```

При одинаковом максимальном ключе `max` вернёт первый встретившийся элемент. Для возможно пустого источника можно указать `default=None`. Аргумент `default` применяется к форме с одним перебираемым источником.

### 16.5 Сортировка не доказывает жадное решение

Выбор «самого выгодного сейчас» называют **жадным алгоритмом**. Иногда его правильность можно доказать. Например, если нужно купить максимум предметов при ограниченном бюджете и все цены неотрицательны, выгодно брать самые дешёвые: любой набор из `k` предметов стоит не меньше суммы `k` минимальных цен.

Но сортировка по одному показателю не решает произвольный выбор оптимального набора. Если у предметов разные цены и полезности, выбор по цене или отношению полезности к цене для неделимых предметов может оказаться неверным. Сначала доказательство подхода, затем код.

Практика: отсортируй `[31, 22, 13, 42, 11]` по последней цифре, а при равенстве — по самому числу.

<details markdown="1">

<summary>Разбор</summary>

```python
numbers = [31, 22, 13, 42, 11]
result = sorted(numbers, key=lambda n: (n % 10, n))
print(result)  # [11, 31, 22, 42, 13]
```

Для отрицательных чисел сначала уточни смысл «последней цифры»: обычно нужен `abs(n) % 10`.

</details>

## 17 Файлы и внешние данные

### 17.1 Оперативная память и сохранённый файл

Переменные обычного запуска исчезают после завершения процесса. **Файл** сохраняет байты на носителе. Чтобы прочитать текст, программа должна знать путь к файлу и способ преобразовать байты в символы — **кодировку**.

**Путь** указывает расположение файла. Абсолютный путь задаётся от корня файловой системы. Относительный отсчитывается от текущей рабочей папки процесса. Она может не совпадать с папкой исходного `.py`-файла, особенно в IDE.

```python
with open("numbers.txt", "r", encoding="utf-8") as file:
    text = file.read()
print(text)
```

Этот пример требует существующего `numbers.txt`. `open` открывает файл. `"r"` означает чтение. `with` организует работу с ресурсом так, чтобы файл закрылся при выходе из блока, в том числе при обычной ошибке внутри. `as file` даёт имя открытому объекту.

Файловая позиция перемещается при чтении. Если вызвать `file.read()` второй раз, не вернувшись к началу, обычно получится пустая строка: всё уже прочитано. Можно открыть файл заново либо использовать `file.seek(0)` для возврата к началу.

### 17.2 Читать целиком или по строкам

Если файл небольшой и содержит целые числа, разделённые пробельными символами:

```python
with open("numbers.txt", encoding="utf-8") as file:
    numbers = [int(part) for part in file.read().split()]
print(sum(numbers))
```

`read()` загружает весь текст в память. Если файл большой и одна строка содержит одно число, можно обрабатывать постепенно:

```python
total = 0
count = 0
with open("numbers.txt", encoding="utf-8") as file:
    for line in file:
        number = int(line)
        total += number
        count += 1
print(count, total)
```

`int` допускает окружающие пробельные символы, включая перевод строки, поэтому `.strip()` здесь не требуется. Пустая строка вызовет ошибку — и это полезно, если формат обещал число на каждой строке. Пропускать пустые или повреждённые данные следует только при явно выбранном правиле.

Для задач обработки текста не удаляй все пробелы через `.strip()` автоматически: крайние пробелы могут быть частью данных. Если нужно снять только окончание строки, подходит `.rstrip("\r\n")`.

### 17.3 Заголовок файла — часть формата

Файл может начинаться количеством записей или настройками. Нельзя автоматически считать каждое число полезным измерением:

```python
with open("numbers.txt", encoding="utf-8") as file:
    expected_count = int(file.readline())
    numbers = [int(line) for line in file]

if len(numbers) != expected_count:
    print("Количество записей не совпадает с заголовком")
else:
    print(sum(numbers))
```

`readline()` читает одну строку, дальнейший обход продолжает с текущей позиции. Если первая строка содержит сразу два числа, сначала разбей её через `split`, затем преобразуй и распакуй.

```python
header = "100 2500"
count, capacity = [int(part) for part in header.split()]
```

Реальный формат диктует условие. Иногда заголовка нет вообще. Самая частая ошибка работы с файлами — правильно написать цикл для неверно понятой структуры входа.

### 17.4 Запись и режимы открытия

| Режим | Смысл |
| --- | --- |
| `r` | Чтение существующего файла |
| `w` | Запись с созданием или обнулением существующего содержимого |
| `a` | Добавление в конец |
| `x` | Создание нового файла; ошибка, если он уже есть |
| `b` | Дополнение режима для байтов, например `rb` |

```python
with open("result.txt", "w", encoding="utf-8") as file:
    file.write("Готово\n")
    file.write(str(42) + "\n")
```

`write` принимает строку и сам не добавляет перевод строки. Другой способ — `print(42, file=file)`. Не открывай входной файл в режиме `w`: он будет очищен ещё до записи новых данных.

### 17.5 pathlib и предсказуемые пути

**Модуль** — отдельная часть Python-кода, которую можно подключить. Подробно изучим модули позже; здесь `from pathlib import Path` делает доступным готовое средство работы с путями.

```python
from pathlib import Path

path = Path("data") / "numbers.txt"
print(path.resolve())
```

Знак `/` между объектом `Path` и строкой соединяет части пути; он не выполняет арифметическое деление. `resolve()` помогает увидеть абсолютное расположение. В обычном скрипте путь рядом с ним можно построить как `Path(__file__).resolve().parent / "numbers.txt"`. Специальное имя `__file__` задаётся для файла модуля; в интерактивной оболочке или ноутбуке его может не быть.

### 17.6 CSV и JSON

**CSV** — текстовая таблица, где записи занимают строки, а поля разделяются заданным разделителем. Некоторые поля содержат кавычки, разделители и даже переводы строк. Поэтому простое `split(",")` не является универсальным чтением CSV. В стандартной библиотеке есть модуль `csv`:

```python
import csv

with open("students.csv", encoding="utf-8", newline="") as file:
    reader = csv.DictReader(file, delimiter=";")
    for row in reader:
        print(row["name"], int(row["score"]))
```

Предполагается заголовок `name;score`. `DictReader` сопоставляет имена столбцов со строковыми значениями. Параметр `newline=""` передаёт обработку переводов строк CSV-модулю.

**JSON** — формат записи вложенных объектов из словарей, списков, строк, чисел и нескольких специальных значений. В JSON нет произвольных объектов Python; например, множества напрямую не сохраняются.

```python
import json

data = {"name": "Анна", "scores": [91, 84]}
text = json.dumps(data, ensure_ascii=False, indent=2)
restored = json.loads(text)
print(restored == data)  # True
```

`dumps` создаёт текст, `loads` разбирает текст. `dump` и `load` работают с файловым объектом. У JSON строковые ключи; JSON-массив восстанавливается как список, даже если перед сохранением использовался кортеж. `ensure_ascii=False` сохраняет читаемую кириллицу, `indent=2` добавляет отступы.

Практика: файл содержит по одному целому числу на строке, без заголовка. Найди максимальное отрицательное число или сообщи, что отрицательных нет.

<details markdown="1">

<summary>Разбор</summary>

```python
best = None
with open("numbers.txt", encoding="utf-8") as file:
    for line in file:
        value = int(line)
        if value < 0 and (best is None or value > best):
            best = value

if best is None:
    print("Отрицательных чисел нет")
else:
    print(best)
```

`None` явно обозначает отсутствие подходящего элемента. Короткое вычисление `or` не допускает сравнения числа с `None`. При пустом файле программа также даёт осмысленный результат.

</details>

## 18 Ошибки исключения и отладка

### 18.1 Три разных проблемы

**Синтаксическая ошибка** означает, что запись нельзя корректно разобрать: забыто двоеточие, не закрыта кавычка. **Исключение при выполнении** означает, что очередная операция не может завершиться обычным образом: например, деление на ноль. **Логическая ошибка** означает, что программа выполняется, но вычисляет не то, что требуется.

| Сообщение | Типичная причина |
| --- | --- |
| `SyntaxError` | Недопустимая запись кода |
| `IndentationError` | Нарушены отступы |
| `NameError` | Имя не определено |
| `TypeError` | Неподходящий тип или способ вызова |
| `ValueError` | Тип подходит, конкретное значение — нет |
| `IndexError` | Нет такой позиции последовательности |
| `KeyError` | Нет такого ключа словаря |
| `ZeroDivisionError` | Деление на ноль |
| `FileNotFoundError` | Файл не найден по указанному пути |
| `RecursionError` | Превышена допустимая глубина вложенных вызовов |

**Traceback** — сообщение с цепочкой мест, через которые выполнение дошло до ошибки. Начни с последней строки: там тип и пояснение. Затем найди последнюю относящуюся к твоему коду строку и проверь значения её частей. Иногда синтаксическая ошибка обнаруживается строкой ниже настоящей причины: например, незакрытой скобки.

### 18.2 Перехват ожидаемой ошибки

```python
text = "abc"
try:
    number = int(text)
except ValueError:
    print("Нужно ввести целое число")
else:
    print(number * 2)
```

`try` выполняет потенциально неуспешное действие. `except ValueError` обрабатывает только ожидаемую проблему преобразования. `else` выполняется, если блок `try` завершился без исключения.

Можно добавить `finally`: его код выполняется при выходе из конструкции, включая выход из-за обычного исключения или `return`. Это используют для освобождения ресурсов. `with` для файла уже решает соответствующую задачу закрытия. Аварийное завершение процесса операционной системой — отдельная ситуация, где Python не гарантирует выполнение завершающего кода.

Не окружай всю программу `except: pass`: это скроет и ошибки автора. Перехватывай конкретные ожидаемые исключения и решай, что делать с причиной. В задаче с гарантированно корректным входом ошибка чтения часто должна остановить программу и обратить внимание на неверный формат.

### 18.3 Сообщить об ошибке самому

`raise` создаёт исключение, когда нарушена договорённость функции:

```python
def average(numbers):
    if not numbers:
        raise ValueError("Нельзя вычислить среднее пустого набора")
    return sum(numbers) / len(numbers)
```

Это лучше, чем вернуть 0 и сделать вид, будто пустой набор имеет среднее 0. Но в другой программе договорённость может явно предусматривать `None` для отсутствующего среднего. Важно выбрать и документировать поведение.

### 18.4 Поиск ошибки по состоянию

**Отладка** — исследование программы для нахождения причин неверной работы. Один способ — временно печатать промежуточные значения:

```python
numbers = [3, -1, 4]
total = 0
for i, value in enumerate(numbers):
    total += value
    print("шаг", i, "элемент", value, "сумма", total)
```

Другой способ — **отладчик**, инструмент остановки и пошагового выполнения. Точка останова указывает, где приостановить программу; затем можно смотреть значения и выполнять следующую строку. Из Python встроенный `breakpoint()` обычно открывает отладчик, а многие IDE предлагают графическое управление.

Отладочный вывод не должен оставаться в окончательном ответе автоматической проверке.

### 18.5 assert и проверка предположений

```python
def double(number):
    return number * 2

assert double(4) == 8
assert double(-3) == -6
```

`assert condition` при ложном условии вызывает `AssertionError`. Он удобен для простых проверок разработчика. При запуске с оптимизацией `python -O` проверки `assert` могут отключаться, поэтому они не должны быть единственной защитой для обязательной проверки пользовательского ввода.

### 18.6 Как выбирать примеры проверки

Проверь обычный случай, минимальные размеры, крайние границы, отсутствие подходящего ответа, повторяющиеся значения и отрицательные числа, если они разрешены. Не надо проверять недопустимые входы, если функция по договорённости их не поддерживает, но эту границу нужно явно понимать.

Для максимума по отрицательным числам особенно полезен набор `[-9, -2, -7]`: он сразу выявляет неверное начальное значение 0. Для пары соседей — списки длины 0, 1 и 2. Для цикла от `a` до `b` — случай `a == b`.

## 19 Модули библиотеки и организация проекта

### 19.1 Откуда берутся готовые средства

**Модуль** обычно соответствует Python-файлу с определениями и инструкциями. **Библиотека** — набор готовых средств для решения задач. **Стандартная библиотека** поставляется вместе с Python; сторонние библиотеки устанавливаются отдельно. **Пакет** организует связанные модули под общим именем; в обычном варианте это папка с файлом `__init__.py`.

```python
import math

print(math.isqrt(50))  # 7
print(math.gcd(18, 24)) # 6
```

`import math` делает доступным имя модуля. Точка выбирает средство внутри него. `isqrt` возвращает точную целую часть квадратного корня неотрицательного целого. `gcd` находит наибольший общий делитель.

Другая форма импорта:

```python
from math import isqrt
print(isqrt(50))  # 7
```

Теперь в текущую область добавлено непосредственно имя `isqrt`. Запись `import math as m` задаёт короткое имя `m`. Обычно избегай `from module import *`: становится труднее понимать происхождение имён и конфликты.

Не называй свой файл `math.py`, `random.py` или `json.py`, если собираешься импортировать одноимённый стандартный модуль: локальный файл может его заслонить.

### 19.2 Собственный модуль и основной запуск

Файл `calculations.py` может содержать:

```python
def square(number):
    return number * number
```

В соседнем `main.py`:

```python
from calculations import square

def main():
    print(square(7))

if __name__ == "__main__":
    main()
```

При обычном прямом запуске файла его специальное имя `__name__` равно `"__main__"`. При импорте оно обычно равно имени модуля. Поэтому условие позволяет отделить использование определений от запуска пользовательского сценария.

При первом импорте в обычном процессе выполняется код верхнего уровня модуля. Повторный импорт обычно использует уже загруженный модуль. Определения функций выполняются, но их тела ждут вызова. Поэтому нежелательные `input()` на верхнем уровне могут неожиданно остановить даже импорт.

### 19.3 Сторонние зависимости и виртуальная среда

**Зависимость** — библиотека, которую использует проект. **Виртуальная среда** хранит отдельный набор установленных пакетов для проекта, чтобы разные проекты не мешали друг другу версиями. Она не является защитной песочницей для недоверенного кода.

Команды терминала:

```shell
python -m venv .venv
```

`-m` запускает модуль как программу. Здесь стандартный `venv` создаёт папку окружения. Можно использовать интерпретатор из неё напрямую, без активации:

```shell
# Windows
.venv\Scripts\python -m pip --version

# Linux и macOS
.venv/bin/python -m pip --version
```

`pip` управляет установкой пакетов. Общая форма установки — `python -m pip install имя_пакета`, выполненная нужным интерпретатором. Важна связь: пакет установлен в конкретное окружение, а не «во все Python на компьютере». Для примеров этого учебника дополнительные пакеты не нужны.

Зависимости проекта можно перечислить с версиями в `requirements.txt`, а устанавливать командой `python -m pip install -r requirements.txt`. Для распространяемых современных проектов метаданные часто задаются в `pyproject.toml`; подробная упаковка — отдельный следующий этап.

### 19.4 Небольшая программа тоже выигрывает от разделения

Удобно отделять чтение данных, вычисление ответа и вывод. Тогда вычисляющую функцию можно проверять на обычных списках без подготовки файлов. Не нужно создавать десятки модулей ради десяти строк: разделяй по реальным самостоятельным задачам.

## 20 Итераторы генераторы и стандартные инструменты

### 20.1 Источник и устройство выдачи элементов

Мы уже использовали перебираемые объекты в `for`. Теперь уточним механизм. **Итератор** — объект, который помнит текущую позицию и умеет выдавать следующий элемент. **Перебираемый объект** умеет предоставить итератор. Список можно обходить заново; отдельный итератор обычно движется только вперёд.

```python
numbers = [10, 20, 30]
iterator = iter(numbers)
print(next(iterator))  # 10
print(next(iterator))  # 20
print(list(iterator))  # [30]
print(list(iterator))  # []
```

`iter` получает итератор, `next` запрашивает следующий элемент. После исчерпания `next` без запасного значения вызывает `StopIteration`. Цикл `for` обрабатывает этот сигнал как нормальное окончание. Можно использовать `next(iterator, None)`, чтобы при исчерпании получить указанное значение, но нужно отличать его от настоящего элемента `None`, если такой допустим.

Это объясняет, почему прочитанный файл и использованный `map` не стоит бездумно обходить второй раз: это источники с текущим состоянием. `range`, напротив, — повторно перебираемый объект, а не одноразовый итератор.

### 20.2 map и filter без загадок

`map(function, source)` постепенно применяет функцию к каждому элементу. `filter(function, source)` постепенно пропускает только элементы с истинным результатом проверки.

```python
parts = "10 -2 7".split()
converted = map(int, parts)
numbers = list(converted)
print(numbers)          # [10, -2, 7]
print(list(converted))  # []
```

`map` ещё не список. `list` потребляет его и собирает результаты. Поэтому запись `a, b = map(int, input().split())` означает: прочитать строку, разбить, последовательно преобразовать две части, распаковать в два имени. Если частей не две, распаковка завершится ошибкой.

Списковое включение `[int(x) for x in parts]` часто читается не хуже. Выбор между ними — вопрос ясности, а не обязательный приём профессионального кода.

### 20.3 Генераторные выражения

```python
numbers = [2, 4, 6]
total = sum(x * x for x in numbers)
print(total)  # 56
```

Выражение `x * x for x in numbers` выдаёт результаты по одному. Оно называется **генераторным выражением**. В отличие от спискового включения, оно не создаёт сразу весь список квадратов. Если оно единственный аргумент вызова, отдельные внешние скобки можно не писать.

Это экономит память, когда элементы нужны только один раз. Но генератор также исчерпывается. И он не делает автоматически быстрым алгоритм, который всё равно рассматривает миллиард комбинаций.

### 20.4 Собственный генератор с yield

```python
def squares_up_to(limit):
    n = 1
    while n * n <= limit:
        yield n * n
        n += 1

print(list(squares_up_to(20)))  # [1, 4, 9, 16]
```

`yield` выдаёт значение и приостанавливает функцию, сохранив её локальное состояние. При следующем запросе выполнение продолжается после `yield`. Обычный `return` завершает вызов окончательно.

Функция, в теле которой есть `yield`, при вызове создаёт генератор. Её тело начинает выполняться при запросе элементов. Это важно, если внутри находятся проверка аргументов, чтение файла или другие действия: они произойдут не обязательно в момент создания генератора.

### 20.5 Полезные части стандартной библиотеки

| Средство | Назначение | Что надо понять перед использованием |
| --- | --- | --- |
| `math` | Математические функции | Точный или приближённый нужен результат |
| `collections.Counter` | Подсчёт частот | Как устроен словарь частот |

Примеры:

```python
from collections import Counter, defaultdict
from fractions import Fraction
from decimal import Decimal
from math import isclose

counts = Counter("BANANA")
print(counts["A"])  # 3
print(counts["Z"])  # 0

groups["python"].append("Анна")
print(groups["python"])  # ['Анна']

print(Decimal("0.1") + Decimal("0.2")) # 0.3
print(isclose(0.1 + 0.2, 0.3))        # True
```

`defaultdict(list)` получает функцию `list` без вызова: при новом ключе она создаёт новый список. Для Decimal использованы строки: `Decimal(0.1)` перенёс бы уже имеющееся двоичное приближение. Decimal тоже имеет настраиваемую точность вычислений; деление 1 на 3 не превращается в конечную точную десятичную дробь.

`isclose(a, b)` сравнивает разность с допусками. Около нуля часто нужен явно выбранный `abs_tol`: например, `isclose(value, 0.0, abs_tol=1e-9)`, если именно такая абсолютная погрешность допустима по смыслу измерений. Запись `1e-9` означает 10 в степени −9.

Практика: почему `sum(x * x for x in range(1_000_000))` требует меньше дополнительной памяти, чем `sum([x * x for x in range(1_000_000)])`?

## 21 Как оценивать скорость и память

### 21.1 Время зависит от количества данных

Программа может давать правильный ответ на десяти элементах и быть непригодной для миллиона. Нужно оценить, сколько действий она выполняет при размере входа `n`.

**Временная сложность** описывает рост затрат при увеличении входа. Запись `O(n)` означает верхнюю оценку, пропорциональную `n` с точностью до постоянного множителя при достаточно большом `n`. На практике часто так называют характерный порядок роста конкретного алгоритма. Это не обещание времени в секундах.

| Порядок | Пример | Что происходит при росте n |
| --- | --- | --- |
| `O(1)` | Доступ к элементу списка по индексу | Число основных действий не зависит от длины |
| `O(log n)` | Деление области поиска пополам | Число шагов растёт медленно |
| `O(n)` | Один проход по данным | Удвоение размера примерно удваивает работу |
| `O(n log n)` | Обычная эффективная сортировка | Затраты растут как n, умноженное на логарифм n |
| `O(n²)` | Все пары элементов | Удвоение размера примерно учетверяет работу |
| `O(2ⁿ)` | Все подмножества n объектов | Каждый новый объект удваивает число вариантов |
| `O(n!)` | Все перестановки различных элементов | Очень быстрый рост числа вариантов |

При `n = 100_000` полный перебор всех упорядоченных пар даёт около 10 миллиардов шагов; один проход — 100 тысяч. Такой разрыв важнее небольших синтаксических сокращений.

### 21.2 Считать нужно реальные границы циклов

Два вложенных цикла не всегда означают `O(n²)`. Если внутренний цикл всегда делает 10 шагов, общее количество — `10n`, то есть `O(n)`. Если оба проходят `n` элементов, получается `n²`. Если внутренний проходит только значения после `i`, число пар равно `n(n - 1) / 2`, но порядок всё равно квадратичный.

Если переменная на каждом шаге делится на 2, после `k` шагов размер уменьшается примерно в `2 ** k` раз. Поэтому нужно около `log₂(n)` шагов. Логарифм здесь возникает из вопроса «сколько раз можно делить пополам», а не из специальной функции Python.

### 21.3 Стоимость скрыта и внутри операций

Для обычных реализаций Python полезны такие ориентиры:

| Операция | Обычная оценка |
| --- | --- |
| `len(list)` и `list[i]` | `O(1)` |
| `x in list` | До `O(n)` сравнений |
| `list.append(x)` | В среднем по длинной серии операций `O(1)` |
| `list.pop()` | В среднем по серии операций `O(1)` |
| `list.pop(0)` | `O(n)` из-за сдвига |
| Срез длины k | `O(k)` времени и новой памяти |
| `sum`, `min`, `max` | `O(n)` прохода |
| Поиск в dict/set | Обычно `O(1)`, в худших случаях хуже |
| `sorted` | В худшем случае `O(n log n)` сравнений, иногда быстрее |

Эти оценки предполагают, что сами сравнения, хеширование и арифметика рассматриваемых элементов недороги. Для длинных строк, огромных целых или пользовательских объектов это дополнительная работа.

Сравнивать `a[i:i + k]` в цикле не бесплатно: каждый срез создаёт до `k` элементов. Повторно строить `set(a)` внутри каждого запроса тоже неудачно — множество нужно построить один раз.

### 21.4 Дополнительная память

**Пространственная сложность** описывает память алгоритма. Проход по файлу с одним счётчиком может использовать почти постоянную дополнительную память. Чтение всех чисел в список требует памяти, растущей с их количеством. Словарь частот требует места по числу различных значений.

Генераторы помогают избежать промежуточных коллекций, но если конечная функция делает `sorted`, все элементы всё равно нужно собрать для сортировки. Рекурсия хранит незавершённые вызовы, а кэш — ранее вычисленные результаты; это тоже память.

### 21.5 Измерение времени

```python
from time import perf_counter

start = perf_counter()
answer = sum(range(1_000_000))
elapsed = perf_counter() - start
print(answer, elapsed)
```

`perf_counter` даёт показания часов для измерения длительности; важна разность, не абсолютное значение. Один запуск шумный: влияют другие процессы, прогрев и среда. Для небольших повторяемых фрагментов есть `timeit`. Сначала улучши порядок роста алгоритма, затем измеряй и уточняй узкие места.

Практика: нужно проверить миллион запросов принадлежности среди ста тысяч различных целых. Какая структура подходит?

<details markdown="1">

<summary>Разбор</summary>

Множество, построенное один раз. При обычных условиях получаем линейную стоимость подготовки и примерно постоянную стоимость каждого поиска. Повторный поиск по всему списку для каждого запроса может потребовать до ста миллиардов сравнений.

</details>

## 22 Алгоритмы для целых чисел и двоичных данных

### 22.1 Пары делителей и квадратный корень

Положительное `d` является делителем положительного `n`, если `n % d == 0`. Тогда вторым делителем является `n // d`. Делители образуют пары произведением `n`.

Если оба числа в паре больше квадратного корня из `n`, их произведение больше `n`. Значит, в каждой паре хотя бы одно число не превосходит корня. Поэтому достаточно проверить кандидатов до корня включительно.

```python
from math import isqrt

def divisors(n):
    if n < 1:
        raise ValueError("Ожидается положительное целое")
    result = []
    for d in range(1, isqrt(n) + 1):
        if n % d == 0:
            other = n // d
            result.append(d)
            if other != d:
                result.append(other)
    return sorted(result)

print(divisors(36))  # [1, 2, 3, 4, 6, 9, 12, 18, 36]
```

Для точного квадрата пара может состоять из одинаковых чисел: у 36 это 6 и 6. Проверка не допускает повторного добавления. `isqrt` избегает погрешности дробного корня. Ноль не входит в область функции: у него нет конечного набора всех положительных делителей.

### 22.2 Простое число

**Простое число** — целое больше 1, имеющее ровно два положительных делителя: 1 и себя. Один не простое. Проверим отсутствие других делителей:

```python
from math import isqrt

def is_prime(n):
    if n < 2:
        return False
    for d in range(2, isqrt(n) + 1):
        if n % d == 0:
            return False
    return True
```

Второй `return` расположен после цикла: простота подтверждается лишь после всех неудачных попыток найти делитель. Эта проверка требует `O(sqrt(n))` пробных делений. Для всех чисел до большой границы выгоден другой подход — решето.

```python
from math import isqrt

def prime_flags(limit):
    if limit < 0:
        raise ValueError("Граница должна быть неотрицательной")
    prime = [True] * (limit + 1)
    prime[0] = False
    if limit >= 1:
        prime[1] = False
    for p in range(2, isqrt(limit) + 1):
        if prime[p]:
            for multiple in range(p * p, limit + 1, p):
                prime[multiple] = False
    return prime
```

**Решето Эратосфена** заранее помечает составные числа. Для простого `p` вычёркиваются кратные. Начать можно с `p * p`: меньшие кратные уже имеют меньший простой делитель и были обработаны. Список занимает `O(limit)` памяти; привычная оценка количества пометок — `O(limit log log limit)`. Для проверки одного огромного числа строить список до него невыгодно.

### 22.3 Алгоритм Евклида

Если `a = q * b + r`, общий делитель `a` и `b` делит также `r = a - q * b`. Обратно, общий делитель `b` и `r` делит `a`. Следовательно, набор общих делителей сохраняется при замене пары `(a, b)` на `(b, a % b)`.

```python
def gcd_euclid(a, b):
    a, b = abs(a), abs(b)
    while b != 0:
        a, b = b, a % b
    return a

print(gcd_euclid(48, 18))  # 6
```

Ненулевые остатки уменьшаются, поэтому процесс заканчивается. Возвращаемое значение — наибольший общий делитель. Для `(0, 0)` функция по принятому соглашению возвращает 0. В рабочем коде обычно достаточно `math.gcd`.

### 22.4 Системы счисления

Число само по себе не «двоичное» или «десятичное»: так называют его запись. У записи с основанием `base` разряды имеют веса `1`, `base`, `base ** 2` и далее. Например, `1011` в двоичной записи означает `1*8 + 0*4 + 1*2 + 1 = 11`.

Последний разряд определяется остатком `n % base`, остальные остаются в `n // base`. Повторное деление даёт цифры справа налево, поэтому их нужно развернуть:

```python
def to_base(n, base):
    if not 2 <= base <= 36:
        raise ValueError("Основание должно быть от 2 до 36")
    if n == 0:
        return "0"
    sign = "-" if n < 0 else ""
    n = abs(n)
    alphabet = "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ"
    digits = []
    while n > 0:
        digits.append(alphabet[n % base])
        n //= base
    return sign + "".join(reversed(digits))

print(to_base(47, 2))  # 101111
print(to_base(255, 16)) # FF
print(int("101111", 2)) # 47
```

`reversed` выдаёт элементы в обратном порядке. `int(text, base)` разбирает запись в заданном основании. Встроенные `bin`, `oct`, `hex` создают записи с префиксами `0b`, `0o`, `0x`. Для неотрицательного числа часто используют `bin(n)[2:]`. Для отрицательного такой срез неверен из-за начального минуса; обрабатывай знак отдельно.

### 22.5 Битовые операции

**Бит** — двоичный разряд. Побитовые операции независимо обрабатывают соответствующие разряды целых. Возьмём `a = 6`, то есть двоичное `110`, и `b = 3`, то есть `011`.

| Операция | Правило для одного разряда | Результат примера |
| --- | --- | --- |
| `a & b` | 1, только если оба бита 1 | `010`, то есть 2 |
| `a \| b` | 1, если хотя бы один бит 1 | `111`, то есть 7 |
| `a ^ b` | 1, если биты различаются | `101`, то есть 5 |
| `a << 1` | Сдвинуть влево на разряд | `1100`, то есть 12 |
| `a >> 1` | Сдвинуть вправо на разряд | `11`, то есть 3 |

Сдвиг влево на `k >= 0` соответствует умножению на `2 ** k`, вправо — целочисленному делению на `2 ** k`. `~n` для Python-целых равно `-n - 1`: целые не ограничены автоматически восьмью или тридцатью двумя битами. Для отрицательных чисел важно понимать представление, поэтому начинай с неотрицательных.

`n.bit_count()` считает единицы в двоичной записи модуля числа. `n.bit_length()` даёт число разрядов модуля без ведущих нулей; для 0 это 0, хотя текстовая запись `"0"` имеет длину 1.

### 22.6 Адреса IPv4

IPv4-адрес содержит 32 бита, обычно записанных четырьмя числами от 0 до 255. Маска сети отделяет общую часть адреса от части узла. Для вычисления адреса сети используют побитовое И адреса и маски. В Python есть готовый модуль:

```python
from ipaddress import ip_network

network = ip_network("192.168.1.10/24", strict=False)
print(network.network_address)  # 192.168.1.0
print(network.num_addresses)    # 256
```

`/24` задаёт 24 начальных бита сетевой части. `strict=False` разрешает передать адрес внутри сети и получить соответствующую сеть. Обход `for address in network` включает все адреса сети, а `.hosts()` применяет правила допустимых адресов узлов с особенностями для маленьких префиксов. В задачах нужно читать, какие адреса требуется считать, а не автоматически заменять одно другим.

Практика: объясни, почему у числа с нечётным количеством положительных делителей обязательно целый квадратный корень.

<details markdown="1">

<summary>Разбор</summary>

Каждый делитель объединяется с `n // d` в пару. Нечётное общее количество возможно лишь при одном непарном значении, равном своему партнёру. Тогда `d * d == n`. Обратно, у точного квадрата такой делитель есть, а остальные разбиваются на пары.

</details>

## 23 Перебор комбинаций маски и регулярные выражения

### 23.1 Полный перебор как доказательство полноты

**Полный перебор** рассматривает все допустимые варианты и проверяет нужное свойство. Он надёжен, если набор действительно полный, проверка верна и число вариантов посильно. Перед кодом ответь: из чего состоит один вариант, как его породить без пропусков и сколько вариантов получится.

`itertools.product` создаёт все комбинации выбора по позициям, разрешая повторения:

```python
from itertools import product

count = 0
for letters in product("ABC", repeat=3):
    word = "".join(letters)
    if word.count("A") == 1:
        count += 1
print(count)  # 12
```

На каждой позиции три выбора, всего `3 ** 3 = 27` слов. Подходящих 12: выбрать одну из трёх позиций A, затем по два варианта для двух оставшихся. Это независимая ручная проверка программы.

### 23.2 Перестановки и сочетания

| Средство | Порядок важен | Повтор одной позиции разрешён | Пример применения |
| --- | --- | --- | --- |
| `product(items, repeat=k)` | Да | Да | Слова длины k |
| `permutations(items, k)` | Да | Нет | Расстановка разных предметов |
| `combinations(items, k)` | Нет | Нет | Выбор группы |
| `combinations_with_replacement(items, k)` | Нет | Да | Выбор с повторениями без порядка |

Функции считают различными позиции исходного источника. Если в нём одинаковые символы, текстовые результаты перестановок могут повторяться. `set(permutations(...))` устраняет дубликаты, но сначала может потребовать огромного перебора и памяти.

Если данные образуют запись числа, первый разряд обычно не ноль. Ограничение на первую цифру нужно добавить отдельно. Не сохраняй все варианты в `list`, если достаточно обрабатывать их по одному.

### 23.3 Ограничить перебор до действительно возможного

Если число должно делиться на `d`, можно перебирать только кратные:

```python
left = 100
right = 200
d = 17
start = ((left + d - 1) // d) * d
for n in range(start, right + 1, d):
    print(n)
```

Здесь `d > 0`. Формула даёт первое кратное, не меньшее `left`. Она сокращает число кандидатов примерно в `d` раз. Это математическое исключение невозможных вариантов, а не рискованный пропуск «похожих» значений.

### 23.4 Числовая маска и fnmatch

В распространённой записи масок `?` означает ровно один символ, а `*` — любую последовательность, включая пустую. Для строк, состоящих только из цифр, это соответствует одной цифре и произвольному количеству цифр.

```python
from fnmatch import fnmatchcase

print(fnmatchcase("102", "1?2*"))    # True: * пустая
print(fnmatchcase("15200", "1?2*"))  # True
print(fnmatchcase("12", "1?2*"))     # False
```

Сам `fnmatchcase` не ограничивает подстановки цифрами. Ограничение обеспечивается тем, что проверяется `str(n)` для неотрицательного целого. Функция проверяет всю строку. `case` указывает на сравнение с учётом регистра; для цифр это несущественно, но поведение не зависит от нормализации регистра платформой.

```python
from fnmatch import fnmatchcase

answers = []
for n in range(7, 10_000, 7):
    if fnmatchcase(str(n), "1?2*"):
        answers.append((n, n // 7))
print(answers[:5])
```

Граница исключает 10 000. Перебор по возрастанию даёт упорядоченные ответы без дополнительной сортировки. `?` нельзя заменить пустотой; `*` может означать ноль символов — этот случай легко забыть при ручном построении кандидатов.

### 23.5 Регулярные выражения — другой язык шаблонов

**Регулярное выражение** описывает текстовый шаблон с собственными правилами. В нём `*` не значит «любой текст»: это повторение предыдущего элемента ноль или более раз.

| Запись regex | Значение |
| --- | --- |
| `[0-9]` | Одна ASCII-цифра |
| `[ABC]` | Один символ из набора |
| `.` | Любой символ, обычно кроме перевода строки |
| `X*` | Ноль или более повторений X |
| `X+` | Одно или более повторений X |
| `X?` | Ноль или одно повторение X |
| `X{3}` | Ровно три повторения X |
| `X{2,4}` | От двух до четырёх повторений X |
| `A\|B` | Альтернатива A или B |
| `(AB)` | Группа элементов |

Эквивалент маски `1?2*` для десятичных записей — `1[0-9]2[0-9]*`:

```python
import re

pattern = r"1[0-9]2[0-9]*"
print(re.fullmatch(pattern, "15200") is not None)  # True
```

Префикс `r` создаёт сырую строку, удобную для обратных слешей в шаблоне. Сам regex всё равно понимает свои специальные символы. `fullmatch` требует совпадения со всей строкой; `search` ищет где угодно; `match` — только с начала, но не обязательно до конца. Успех возвращается объектом совпадения, неуспех — `None`.

`findall` обычно возвращает неперекрывающиеся совпадения, а наличие захватывающих групп меняет форму результата. Не заменяй им поиск пересекающихся фрагментов без анализа. Сложные регулярные выражения иногда много раз возвращаются к прежним выборам и работают медленно; простой цикл бывает яснее и надёжнее.

Практика: сколько двоичных строк длины 4 содержат ровно две единицы?

Выбираем две позиции единиц среди четырёх. Возможные пары: 01, 02, 03, 12, 13, 23. Нумерация позиций с нуля здесь даёт шесть вариантов.

## 24 Последовательности и фрагменты данных

### 24.1 Соседние элементы и произвольные пары

Для списка длины `n` соседняя пара имеет индексы `i` и `i + 1`. Первый индекс может быть от 0 до `n - 2`, поэтому:

```python
numbers = [4, 7, -2, 5]
pair_count = 0
best_sum = None
for i in range(len(numbers) - 1):
    left = numbers[i]
    right = numbers[i + 1]
    if (left % 2 == 0) != (right % 2 == 0):
        pair_count += 1
        current_sum = left + right
        if best_sum is None or current_sum > best_sum:
            best_sum = current_sum
print(pair_count, best_sum)  # 3 11
```

Это проход по соседним парам с ровно одним чётным числом. Один элемент может входить в две разные соседние пары, и это нормально. При длине меньше 2 диапазон пуст; результатом остаются 0 пар и отсутствие максимальной суммы.

Для соседней тройки будут нужны `i`, `i + 1`, `i + 2` и `range(n - 2)`. Для блока длины `k` — `range(n - k + 1)` при положительном `k`.

Произвольная пара — другая задача:

```python
numbers = [4, 7, -2, 5]
for i in range(len(numbers)):
    for j in range(i + 1, len(numbers)):
        print(numbers[i], numbers[j])
```

Условие `j > i` исключает повтор пары в обратном порядке и использование одной позиции дважды. Числа на разных позициях могут быть равны — позиции всё равно различны.

### 24.2 Самая длинная непрерывная серия

Ищем самый длинный подряд идущий участок одинаковых символов:

```python
def longest_equal_run(text):
    if not text:
        return 0
    current = 1
    best = 1
    for i in range(1, len(text)):
        if text[i] == text[i - 1]:
            current += 1
        else:
            current = 1
        best = max(best, current)
    return best

print(longest_equal_run("AABBBAAC"))  # 3
```

`current` означает длину подходящей серии, которая заканчивается **ровно в текущей позиции**. `best` — лучшая длина среди всех уже просмотренных. Если символ изменился, он всё равно начинает новую серию длины 1. Для пустой строки нет ни одной серии, поэтому ответ 0.

Не смешивай «подряд» и «можно пропускать». Подстрока занимает непрерывный участок. Подпоследовательность сохраняет порядок, но может пропускать элементы; алгоритмы для неё часто другие.

### 24.3 Фиксированное скользящее окно

**Окно** — рассматриваемый непрерывный фрагмент. Нужно найти максимальную сумму `k` соседних элементов. Наивное решение каждый раз заново складывает `k` чисел. Но соседние окна почти одинаковы: один элемент выходит слева и один приходит справа.

```python
def max_window_sum(numbers, k):
    if not 1 <= k <= len(numbers):
        raise ValueError("Длина окна должна быть от 1 до длины списка")
    current = sum(numbers[:k])
    best = current
    for right in range(k, len(numbers)):
        current += numbers[right] - numbers[right - k]
        best = max(best, current)
    return best

print(max_window_sum([3, -1, 4, 2, -5], 3))  # 6
```

Первое окно — индексы 0…`k - 1`. Когда приходит позиция `right`, уходящая позиция равна `right - k`. После обновления `current` содержит сумму ровно текущего окна. Алгоритм линейный и работает также с отрицательными числами: правило перемещения здесь не зависит от знака.

### 24.4 Префиксные суммы

**Префикс** — начальный фрагмент последовательности. Сохраним сумму каждого такого фрагмента: `prefix[i]` — сумма первых `i` элементов. Поэтому `prefix[0] = 0`, а длина массива префиксов на 1 больше исходной.

```python
numbers = [3, -1, 4, 2]
prefix = [0]
for value in numbers:
    prefix.append(prefix[-1] + value)

left = 1
right = 4
print(prefix[right] - prefix[left])  # 5: -1 + 4 + 2
```

Сумма на полуинтервале `[left, right)` равна `prefix[right] - prefix[left]`. Из суммы первых `right` элементов вычитается лишнее начало перед `left`. Это работает при любых знаках. Подготовка требует `O(n)` времени и памяти, каждый запрос суммы — `O(1)`. Если список изменился, прежние префиксы уже не соответствуют новым данным.

### 24.5 Окно переменной длины и его условие применимости

Найдём самый длинный фрагмент с суммой не больше `limit`, **если все элементы неотрицательны** и `limit >= 0`.

```python
def longest_sum_at_most(numbers, limit):
    if limit < 0 or any(x < 0 for x in numbers):
        raise ValueError("Нужны неотрицательные элементы и граница")
    left = 0
    total = 0
    best = 0
    for right, value in enumerate(numbers):
        total += value
        while total > limit:
            total -= numbers[left]
            left += 1
        best = max(best, right - left + 1)
    return best

print(longest_sum_at_most([2, 1, 3, 1, 1], 5))  # 3
```

После добавления справа сумма может стать слишком большой. Тогда удаляем элементы слева, пока условие не восстановится. При неотрицательных элементах удаление не увеличивает сумму, а добавление справа не уменьшает. Эти свойства позволяют больше не возвращать отброшенные начала.

Хотя в коде вложенный `while`, левая граница за весь запуск сдвигается не более `n` раз. Поэтому общее время линейное.

С отрицательными значениями эта логика ломается. Для `[4, -3]` и границы 2 весь фрагмент имеет сумму 1, но поспешное удаление 4 после первого шага потеряет этот вариант. Не копируй окно без проверки свойства монотонности — направленного изменения условия при движении границ.

### 24.6 Двоичный поиск

Если список отсортирован, можно каждый раз исключать половину области поиска. Найдём позицию первого элемента, не меньшего `target`. Если такого нет, вернём длину списка.

```python
def lower_bound(numbers, target):
    left = 0
    right = len(numbers)
    while left < right:
        middle = (left + right) // 2
        if numbers[middle] < target:
            left = middle + 1
        else:
            right = middle
    return left

print(lower_bound([2, 4, 4, 7], 4))  # 1
print(lower_bound([2, 4, 4, 7], 9))  # 4
```

Все позиции раньше `left` уже известны как слишком маленькие. Все реальные позиции от `right` — как подходящие. Неизвестная часть находится в `[left, right)`. Если середина мала, её и всё левее можно исключить. Иначе она остаётся кандидатом на первую подходящую позицию, поэтому правая граница становится равной `middle`.

Интервал уменьшается на каждом шаге. Когда границы совпадают, найден раздел между двумя группами. В стандартной библиотеке такую операцию даёт `bisect_left`. Поиск места занимает `O(log n)`, но вставка в середину обычного списка затем всё равно требует `O(n)` сдвигов.

Практика: почему нельзя отсортировать список перед поиском максимальной суммы соседней пары?

<summary>Разбор</summary>

Соседство относится к исходному порядку. Сортировка создаёт другие пары. Например, `[100, -100, 99]` имеет соседние суммы 0 и −1. После сортировки появляется пара 99 и 100 с суммой 199, которой в исходных данных не было.

## 25 Рекурсия запоминание и динамическое программирование

### 25.1 Задача через меньшую задачу

**Рекурсия** — вызов функции из самой себя, напрямую или через другие функции. Она удобна, когда решение естественно выражается через решение меньшего случая.

Факториал неотрицательного целого `n` — произведение чисел от 1 до `n`, причём `0! = 1`. Отсюда `n! = n * (n - 1)!` при `n > 0`.

```python
def factorial(n):
    if n < 0:
        raise ValueError("Факториал здесь определён для n >= 0")
    if n == 0:
        return 1
    return n * factorial(n - 1)

print(factorial(4))  # 24
```

Ветка `n == 0` — **базовый случай**, решаемый без дальнейшего обращения. Остальное — переход к меньшему случаю. Для корректности нужно убедиться, что переходы обязательно приводят к базе.

### 25.2 Что происходит с незавершёнными вызовами

Для `factorial(4)` вызов ждёт результата `factorial(3)`, тот — `factorial(2)`, затем `factorial(1)` и `factorial(0)`. После базы возвращения идут в обратном порядке: 1, 1, 2, 6, 24.

Каждый незавершённый вызов хранит собственные параметры и место продолжения. Эта последовательность хранится в **стеке вызовов**. Стек — структура «последним вошёл, первым вышел»: первым завершается самый глубокий вызов.

| Вызов | Что ему нужно для завершения |
| --- | --- |
| `factorial(4)` | 4 × результат для 3 |
| `factorial(3)` | 3 × результат для 2 |
| `factorial(2)` | 2 × результат для 1 |
| `factorial(1)` | 1 × результат для 0 |
| `factorial(0)` | Уже известное значение 1 |

У Python ограничена глубина рекурсивных вызовов. Без необходимости поднимать её до огромного числа нельзя считать исправлением алгоритма: стек и память конечны. Python не превращает автоматически хвостовую рекурсию в цикл. Для длинной цепочки зачастую лучше обычный цикл.

### 25.3 Повторные вычисления

Пусть последовательность задана как `F(0) = 0`, `F(1) = 1`, а далее `F(n) = F(n - 1) + F(n - 2)`. Прямой рекурсивный код многократно вычисляет одинаковые значения. Например, при вычислении F(5) значение F(3) понадобится и прямо, и внутри F(4).

**Мемоизация** — сохранение результата для уже рассмотренных аргументов. При следующем таком же запросе результат берётся из памяти. В Python есть `cache`:

```python
from functools import cache

@cache
def fibonacci(n):
    if n < 0:
        raise ValueError("Нужен неотрицательный индекс")
    if n < 2:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)

print(fibonacci(10))  # 55
```

Запись `@cache` — применение **декоратора**, средства, которое получает функцию и возвращает обёрнутую версию с дополнительным поведением. Здесь дополнительное поведение — поиск результата в памяти и его сохранение. Смысл близок к `fibonacci = cache(fibonacci)` после определения. Механизм собственных декораторов рассмотрим дальше.

Теперь каждое значение индекса вычисляется один раз: число разных состояний линейно по `n`. Но глубина первого спуска остаётся линейной, а кэш хранит все результаты. Кэш не устраняет ограничения рекурсивной глубины.

Аргументы кэшируемой функции должны быть хешируемыми. Результат должен определяться аргументами. Если функция зависит от изменяющейся глобальной переменной, файла или времени, кэш может возвращать устаревшие данные. Очистить его можно `fibonacci.cache_clear()`.

### 25.4 Вычисление снизу вверх

Можно начать с базы и последовательно строить большие случаи:

```python
def fibonacci_iterative(n):
    if n < 0:
        raise ValueError("Нужен неотрицательный индекс")
    previous = 0
    current = 1
    for _ in range(n):
        previous, current = current, previous + current
    return previous
```

Перед очередным шагом хранятся два соседних значения последовательности. Одновременное присваивание использует прежние значения обеих переменных. Полная таблица не нужна, потому что следующий результат зависит только от двух предыдущих.

**Динамическое программирование** — подход, при котором задачу разбивают на состояния, устанавливают зависимости между ними и вычисляют каждое нужное состояние без избыточных повторов. Мемоизация идёт от запроса к зависимостям, таблица — от известных значений к следующим. Рекурсия и динамическое программирование не синонимы: рекурсия может не иметь повторяющихся состояний, а динамическая программа может быть полностью циклической.

### 25.5 Подсчёт способов достижения

Из числа 1 можно переходить к `x + 1` или `2 * x`. Найдём число последовательностей команд, приводящих к `target`, причём значения только возрастают.

```python
def count_programs(target):
    if target < 1:
        return 0
    ways = [0] * (target + 1)
    ways[1] = 1
    for x in range(1, target + 1):
        for next_x in (x + 1, 2 * x):
            if next_x <= target:
                ways[next_x] += ways[x]
    return ways[target]

print(count_programs(4))  # 4
```

`ways[x]` — число способов прийти в `x`. В начальное состояние есть один способ: ничего не делать. Каждый известный способ можно продлить каждой разрешённой командой, поэтому количества прибавляются.

При `x = 1` обе разные команды дают 2. Код считает разные **последовательности команд**, поэтому добавляет оба варианта. Если по условию различаются только последовательности состояний, одинаковые переходы нужно объединить. Это различие задаёт не Python, а смысл задачи.

Порядок по возрастанию годится потому, что все переходы ведут к большим числам. При переходах назад или циклах такой однократный проход может быть неверен.

### 25.6 Игры и смысл any и all

В игре с полной информацией состояние должно включать всё, что влияет на разрешённые ходы и исход: размеры куч, ограничения и при необходимости историю. Если оценка задаётся для игрока, которому предстоит ход, смена игрока уже учитывается сменой смысла состояния.

Упрощённая конечная игра: в куче `stones` камней, за ход разрешено взять 1 или 2, выиграет взявший последний. При 0 камней игрок, которому досталась очередь, уже проиграл. Позиция выигрышная, если **существует** ход в проигрышную для противника:

```python
from functools import cache

@cache
def can_win(stones):
    if stones == 0:
        return False
    outcomes = []
    for take in (1, 2):
        if take <= stones:
            outcomes.append(can_win(stones - take))
    return any(not outcome for outcome in outcomes)

print([n for n in range(1, 10) if not can_win(n)])  # [3, 6, 9]
```

Аргумент предполагается неотрицательным. Если все ходы ведут в выигрышные позиции противника, текущая позиция проигрышна. «Могу выбрать удачный ход» соответствует `any`; «должно сработать при любом ответе соперника» соответствует `all`.

Задачи «выиграть ровно вторым ходом», «не может выиграть первым», «после неудачного хода» требуют дополнительных условий и учёта числа ходов. Этот код решает только описанную игру без ограничения горизонта. Нельзя механически объявлять его универсальным решением всех задач о стратегиях.

Практика: почему `ways[start] = 1`, а не 0, если в начале ещё не выполнено ни одной команды?

<details markdown="1">

<summary>Разбор</summary>

Считается количество способов, а не количество команд. Пустая последовательность команд — один способ находиться в стартовом состоянии. Если поставить 0, ни один переход не получит ненулевого количества, и вся таблица останется нулевой.

</details>

## 26 Графы зависимости и координаты

### 26.1 Объекты и связи

**Граф** описывает объекты и связи между ними. Объекты называют **вершинами**, связи — **рёбрами**. У ориентированного графа связь имеет направление. Путь — последовательность переходов по рёбрам. Цикл позволяет вернуться к исходной вершине, пройдя хотя бы одно ребро.

Города с дорогами, страницы со ссылками, состояния игры и зависимости вычислений можно представить графами. В коде удобно хранить для каждой вершины список соседей:

```python
graph = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A", "D"],
    "D": ["B", "C"],
}
```

Для неориентированной дороги A—B обе стороны указаны явно. Здесь предполагается, что каждый упомянутый сосед также существует как ключ словаря.

### 26.2 Поиск в ширину и очередь

**Очередь** работает по правилу «первым пришёл, первым вышел». Для неё подходит `deque`: добавление справа через `append`, извлечение слева через `popleft`.

**Поиск в ширину** сначала рассматривает старт, затем вершины на расстоянии одного ребра, затем двух и так далее:

```python
from collections import deque

def distances_from(graph, start):
    distance = {start: 0}
    queue = deque([start])
    while queue:
        vertex = queue.popleft()
        for neighbor in graph[vertex]:
            if neighbor not in distance:
                distance[neighbor] = distance[vertex] + 1
                queue.append(neighbor)
    return distance
```

Вершина помечается при добавлении в очередь, чтобы не добавить её много раз. Первое обнаружение даёт кратчайшее число рёбер, потому что очередь соблюдает порядок слоёв. Это верно для невзвешенного графа либо одинаковой стоимости рёбер. При разных весах такая функция не находит кратчайшую сумму весов.

Если список смежности содержит `V` вершин и `E` рёбер, время обхода — `O(V + E)`. Неориентированное ребро просматривается с двух сторон, но постоянный множитель порядок не меняет.

### 26.3 Поиск в глубину и компоненты

**Поиск в глубину** сначала продвигается по выбранной ветви как можно дальше. Его можно сделать рекурсией или собственным стеком — списком с `append` и `pop`.

```python
def reachable_vertices(graph, start):
    seen = {start}
    stack = [start]
    while stack:
        vertex = stack.pop()
        for neighbor in graph[vertex]:
            if neighbor not in seen:
                seen.add(neighbor)
                stack.append(neighbor)
    return seen
```

Стек берёт последнюю добавленную вершину. Для определения достижимости порядок обхода несущественен. **Компонента связности** неориентированного графа — группа взаимно достижимых вершин. Чтобы найти все компоненты, запускают обход из ещё не посещённой вершины, затем повторяют для оставшихся.

### 26.4 Динамика по зависимостям

Если процесс может начаться только после завершения всех предшественников, его раннее время окончания равно собственной длительности плюс **максимум** времён окончания предшественников. Не сумма: независимые предшественники могут выполняться одновременно, если ресурсов достаточно.

Если в ориентированном графе нет циклов, можно расположить вершины так, чтобы каждое ребро шло от более ранней к более поздней. Это **топологический порядок**. Он позволяет последовательно вычислять времена или количество путей. При цикле зависимостей «A ждёт B, B ждёт A» такого порядка нет.

Подсчёт путей требует суммы количеств из предшественников; кратчайшее расстояние — минимума подходящих продолжений; ожидание завершения всех независимых работ — максимума. Вид операции выводится из смысла, а не запоминается по номеру задания.

### 26.5 Точки и расстояния

Точка плоскости хранится как `(x, y)`. Обычное расстояние между точками равно корню из суммы квадратов разностей координат:

```python
from math import dist

p = (1.0, 2.0)
q = (4.0, 6.0)
print(dist(p, q))  # 5.0
```

Для сравнения отдельного расстояния с порогом можно сравнить квадраты, если порог неотрицателен. Но минимизация **суммы** расстояний и суммы квадратов расстояний — разные задачи: извлечение корня нельзя просто убрать из каждого слагаемого.

### 26.6 Группировка точек и выбор центра

**Кластер** — группа объектов, объединённая выбранным правилом близости. Само слово не задаёт алгоритм: сначала нужно узнать правило из задачи. Иногда группы разделены линиями, иногда известны условия расстояния, иногда разбиение нужно получить из данных.

Если по условию точки связаны при расстоянии не больше `radius`, можно построить граф близости и найти компоненты. Важно: цепочка близких соседей может связать далёкие крайние точки. Компонента не обязана иметь попарные расстояния меньше порога. Произвольный подбор порога по красивой картинке без проверки не даёт доказательства нужного разбиения.

Два разных понятия центра:

| Центр | Определение | Обязан быть исходной точкой |
| --- | --- | --- |
| Средняя точка | Средние арифметические координат | Нет |
| Медоид | Исходная точка с минимальной суммой расстояний до остальных | Да |

```python
from math import dist

def medoid(points):
    if not points:
        raise ValueError("Кластер пуст")
    best_point = None
    best_total = None
    for candidate in points:
        total = sum(dist(candidate, point) for point in points)
        if best_total is None or total < best_total:
            best_total = total
            best_point = candidate
    return best_point
```

Код проверяет каждого допустимого кандидата, поэтому находит минимум именно по исходным точкам. При равенстве сумм оставляет первого кандидата. Сложность для `m` точек — `O(m²)` вычислений расстояния. Погрешность `float`, правила разрешения равенства и ограничения размера проверяют по условию конкретной задачи.

Средняя точка минимизирует сумму квадратов евклидовых расстояний среди всех точек плоскости, а медоид решает указанную выше задачу с ограничением кандидатов. Подменять одну другой нельзя.

Практика: для точек на прямой 0, 1 и 10 найди среднее и медоид.

<details markdown="1">

<summary>Разбор</summary>

Среднее — `11 / 3`, приблизительно 3.667. Суммы расстояний для кандидатов 0, 1, 10 равны 11, 10, 19. Поэтому медоид — 1. Среднее даже не входит в исходный набор.

</details>

## 27 Классы и организация связанных данных

### 27.1 Зачем нужен ещё один способ описания данных

Словарь способен хранить название книги, число страниц и текущую позицию чтения. Но если таких записей много, хочется одинаково создавать их и одинаково изменять. **Класс** описывает новый тип объектов с данными и связанными действиями. **Экземпляр** — конкретный объект этого класса.

Это основа **объектно-ориентированного программирования**, сокращённо ООП. Оно особенно полезно, когда программа моделирует несколько сущностей со своим состоянием. Для суммы чисел отдельный класс обычно не нужен.

```python
class ReadingProgress:
    def __init__(self, title, total_pages):
        if total_pages <= 0:
            raise ValueError("Число страниц должно быть положительным")
        self.title = title
        self.total_pages = total_pages
        self.current_page = 0

    def advance(self, pages):
        if pages < 0:
            raise ValueError("Нельзя продвинуться на отрицательное число страниц")
        self.current_page = min(self.total_pages, self.current_page + pages)

    def fraction(self):
        return self.current_page / self.total_pages

book = ReadingProgress("Python", 200)
book.advance(30)
print(book.title, book.current_page)  # Python 30
print(book.fraction())               # 0.15
```

Предполагаются целые числа страниц. `class` определяет класс. `__init__` — специальный метод начальной настройки уже созданного экземпляра. Вызов класса создаёт экземпляр и организует его инициализацию. `__init__` не должен возвращать вместо него произвольный результат.

### 27.2 Что означает self

`self` — обычное имя первого параметра метода, принятое по соглашению. Оно обозначает экземпляр, для которого выполняется действие. При `book.advance(30)` Python автоматически передаёт `book` первым аргументом. Смысл близок к `ReadingProgress.advance(book, 30)`.

**Атрибут** — именованное значение, связанное с объектом. `self.title` и `self.current_page` сохраняются внутри экземпляра. Обычная локальная переменная `pages` существует только во время вызова и сама по себе не запоминается в объекте.

Создай второй экземпляр — у него будет независимая текущая страница:

```python
another_book = ReadingProgress("Алгоритмы", 300)
print(another_book.current_page)  # 0
```

### 27.3 Атрибуты экземпляра и атрибуты класса

Переменная в теле класса вне методов относится к классу и может использоваться всеми экземплярами. Это подходит для общей константы. Изменяемый список, который по ошибке объявили там вместо `self.items = []` в `__init__`, станет общим для объектов.

```python
class Notebook:
    def __init__(self):
        self.notes = []

first = Notebook()
second = Notebook()
first.notes.append("Циклы")
print(second.notes)  # []
```

Каждый вызов `__init__` создаёт отдельный список. Это та же идея независимых вложенных списков, а не отдельное исключение ООП.

### 27.4 Инкапсуляция и свойства

**Инкапсуляция** означает организацию данных и правил обращения с ними так, чтобы остальная программа работала с понятными действиями. Например, `advance` контролирует допустимое изменение позиции вместо разрозненных присваиваний в разных местах.

Имя с одним начальным подчёркиванием, например `_current_page`, обозначает внутреннюю деталь по соглашению. Это не запрет доступа. Два начальных подчёркивания вызывают преобразование имени для уменьшения случайных конфликтов в наследовании; это тоже не механизм защиты секретных данных.

`@property` позволяет читать вычисляемое свойство как атрибут:

```python
class Rectangle:
    def __init__(self, width, height):
        self.width = width
        self.height = height

    @property
    def area(self):
        return self.width * self.height

rectangle = Rectangle(3, 5)
print(rectangle.area)  # 15, без скобок
```

Декоратор преобразует метод в свойство. В приведённой форме присвоить `rectangle.area = ...` нельзя: способ записи свойства не определён. Ширина и высота здесь не проверяются; при необходимости проверку добавляют в договорённость класса и его реализацию.

### 27.5 Наследование и композиция

**Наследование** создаёт класс на основе другого и позволяет уточнить его поведение. Оно уместно, если новый объект действительно можно использовать вместо объекта базового вида.

```python
class NamedItem:
    def __init__(self, name):
        self.name = name

    def label(self):
        return self.name

class Task(NamedItem):
    def __init__(self, name, done=False):
        super().__init__(name)
        self.done = done

    def label(self):
        mark = "✓" if self.done else "○"
        return f"{mark} {self.name}"
```

`Task(NamedItem)` обозначает наследование. `super()` в этом простом случае позволяет вызвать реализацию базового класса. Более общий смысл — продолжить поиск по порядку наследования; при сложном множественном наследовании это не просто «всегда прямой родитель».

`label` переопределён: одинаковый вызов на разных объектах может выполнять разную реализацию. Это пример **полиморфизма** — работы через общую форму действия. В Python для него не обязательно общее наследование: достаточно, чтобы объект поддерживал нужную операцию.

**Композиция** означает, что объект содержит другие объекты. Например, учебный курс содержит список уроков. Для отношения «содержит» обычно естественна композиция, а не наследование «курс является уроком».

### 27.6 Специальные методы и dataclass

Специальные методы связывают класс с обычными средствами языка. `__repr__` задаёт представление для разработчика, `__str__` — текстовое представление, `__len__` — поведение `len`, `__eq__` — сравнение через `==`. Не нужно придумывать произвольные имена с двойными подчёркиваниями: у известных имён есть определённые протоколы.

Если класс в основном хранит запись, модуль `dataclasses` сокращает однотипный код:

```python
from dataclasses import dataclass

@dataclass
class Point:
    x: float
    y: float

p = Point(1.0, 2.0)
q = Point(1.0, 2.0)
print(p)       # Point(x=1.0, y=2.0)
print(p == q)  # True
```

Декоратор создаёт инициализацию и некоторые стандартные методы на основе полей. Записи `x: float` и `y: float` — аннотации ожидаемых типов, которые объясним в главе о качестве кода. Они не преобразуют аргументы автоматически.

Для независимого изменяемого поля применяют фабрику:

```python
from dataclasses import dataclass, field

@dataclass
class Course:
    name: str
    lessons: list[str] = field(default_factory=list)
```

`default_factory=list` создаёт новый список для каждого экземпляра. Мы снова видим общую закономерность: изменяемые данные требуют явного решения о совместном или независимом владении.

Практика: когда для точки лучше кортеж, а когда класс?

<details markdown="1">

<summary>Разбор</summary>

Для короткого численного алгоритма `(x, y)` может быть достаточно. Если важны понятные имена полей, дополнительные правила и действия с точками в большой программе, класс делает договорённость явной. Наличие класса само по себе не повышает качество; важно, уменьшает ли он сложность задачи.

</details>

## 28 Дополнительные механизмы языка

Эту главу можно читать после уверенного освоения функций. Механизмы ниже полезны для понимания библиотек, но не обязательны в каждом решении.

### 28.1 Замыкание

Функция может быть создана внутри другой функции и использовать её локальные имена. Если такая внутренняя функция продолжает использовать окружающие связи после завершения внешней, возникает **замыкание**.

```python
def make_multiplier(factor):
    def multiply(number):
        return number * factor
    return multiply

triple = make_multiplier(3)
print(triple(7))  # 21
```

Возвращается сама функция `multiply`, не её вызов. Она сохраняет доступ к `factor` этого конкретного вызова `make_multiplier`.

Замыкание обычно сохраняет доступ к переменной, а не обязательно снимок её значения в момент создания. Поэтому функции, созданные внутри цикла и обращающиеся к одной переменной цикла, при последующем вызове могут все увидеть её последнее значение. Если нужен снимок, часто используют параметр по умолчанию или отдельный вызов создающей функции.

### 28.2 Собственный декоратор

Декоратор получает функцию и возвращает объект, который будет использоваться под её именем. В простом варианте возвращается функция-обёртка:

```python
from functools import wraps

def announce(function):
    @wraps(function)
    def wrapper(*args, **kwargs):
        print("Вызов", function.__name__)
        result = function(*args, **kwargs)
        return result
    return wrapper

@announce
def add(a, b):
    return a + b

print(add(2, 5))  # Сначала сообщение о вызове, затем 7
```

`*args` собирает позиционные аргументы, `**kwargs` — именованные; при вызове `function(*args, **kwargs)` они распаковываются обратно. `wraps` сохраняет полезные метаданные исходной функции, например имя и документацию. `__name__` — имя функции как атрибут.

Если забыть `return result`, обёртка будет всегда возвращать `None`, даже если исходная функция вычисляла число. Сохранение поведения — часть договорённости декоратора.

### 28.3 Контекстный менеджер

Объект, поддерживающий вход и выход из блока `with`, называют **контекстным менеджером**. У обычных классов это методы `__enter__` и `__exit__`. Удобно также создавать их через `contextlib.contextmanager`:

```python
from contextlib import contextmanager
from time import perf_counter

@contextmanager
def measured(label):
    start = perf_counter()
    try:
        yield
    finally:
        elapsed = perf_counter() - start
        print(label, elapsed)

with measured("Вычисление"):
    result = sum(range(100_000))
```

Код до `yield` выполняется при входе, блок пользователя — в момент паузы, завершающая часть — при выходе. Здесь генератор должен передать управление ровно один раз. `finally` обеспечивает измерение и при возникновении обычного исключения внутри блока.

### 28.4 Структурное сопоставление match

В Python 3.10+ конструкция `match` проверяет форму значения. Она полезна для разбора небольших команд и вложенных данных:

```python
command = "move 3 5".split()
match command:
    case ["move", x, y]:
        print(int(x), int(y))
    case ["quit"]:
        print("Завершение")
    case _:
        print("Неизвестная команда")
```

Шаблон `['move', x, y]` требует последовательность из трёх элементов с первым элементом `"move"`, а остальные связывает с именами. Это не просто другая запись цепочки сравнений. Обычное имя в шаблоне чаще захватывает значение, а не сравнивает его с прежней переменной; для сравнения констант необходимо понимать правила шаблонов. Новичку нередко проще обычный `if`.

### 28.5 Текст и байты

Строка `str` — символы. `bytes` — последовательность целых значений от 0 до 255, представляющих сырые байты. Для перевода между ними нужна кодировка:

```python
text = "Привет"
data = text.encode("utf-8")
restored = data.decode("utf-8")
print(restored == text)  # True
print(len(text), len(data))  # 6 12
```

Количество байтов и количество символов не обязаны совпадать. Чтение файла в режиме `rb` даёт байты. Преобразование `str(data)` не заменяет декодирование: оно создаёт текстовое представление байтового объекта.

### 28.6 Что означают асинхронность и параллельность

Когда программа ждёт сеть или другой внешний источник, она могла бы в это время обслужить другую задачу. **Асинхронное выполнение** позволяет описать такие ожидания и передавать управление между задачами. Это не обязательно одновременные вычисления на разных ядрах.

```python
import asyncio

async def report(name, delay):
    await asyncio.sleep(delay)
    return name

async def main():
    results = await asyncio.gather(
        report("A", 0.02),
        report("B", 0.01),
    )
    print(results)  # ['A', 'B']

if __name__ == "__main__":
    asyncio.run(main())
```

`async def` создаёт асинхронную функцию; её вызов создаёт объект корутины, выполнение которого надо организовать. `await` ожидает результат, позволяя циклу событий выполнять другую готовую работу. `gather` организует совместное выполнение переданных операций и возвращает результаты в порядке аргументов, а не порядке завершения. `asyncio.run` запускает внешний цикл событий в обычном скрипте. В среде с уже работающим циклом, например некоторых ноутбуках, используют её собственный способ запуска, часто `await main()`.

Обычное тяжёлое вычисление без точек ожидания блокирует такой цикл. Замена `def` на `async def` сама по себе не ускоряет перебор делителей. Потоки и отдельные процессы — другие механизмы конкурентного выполнения с собственными правилами общего состояния. Их стоит изучать под конкретную задачу после этой основы.

Практика: почему функция с `yield` не возвращает сразу обычный список?

<details markdown="1">

<summary>Разбор</summary>

Она описывает процесс последовательной выдачи. Вызов создаёт объект с сохраняемым состоянием, а результаты появляются по запросу. При необходимости все элементы можно собрать `list(generator)`, если источник конечен и помещается в память.

</details>

## 29 Читаемость аннотации и тестирование

### 29.1 Код должен объяснять задачу

Ясные имена, короткие функции и явные условия обычно полезнее сокращения числа строк. Имя `count` говорит о количестве, `total` — о сумме, `best` — о выбранном лучшем результате. Если рядом существуют максимум значения и максимум суммы пары, назови их по-разному.

Избегай **магических чисел** — необъяснённых констант. Если 86400 обозначает число секунд в сутках, имя `SECONDS_PER_DAY` делает смысл видимым. Заглавные буквы — соглашение о постоянном значении; Python не запрещает его изменить.

Комментарий должен объяснять решение, ограничение или причину. Комментарий «увеличиваем i» рядом с `i += 1` обычно менее полезен, чем «левая граница больше не может дать допустимое окно».

### 29.2 Аннотации типов

**Аннотация типа** сообщает читателю и инструментам, какие данные ожидаются:

```python
def count_positive(numbers: list[int]) -> int:
    return sum(number > 0 for number in numbers)
```

После параметра стоит ожидаемый тип, после `->` — тип результата. `list[int]` означает список целых. Логические значения в арифметике ведут себя как 0 и 1, поэтому сумма истинных сравнений считает их количество.

Python обычно не проверяет эти аннотации автоматически при вызове. Для анализа без запуска используют отдельные инструменты проверки типов. Они помогают находить несоответствия, но не доказывают математическую правильность алгоритма.

```python
def maximum_negative(numbers: list[int]) -> int | None:
    best = None
    for number in numbers:
        if number < 0 and (best is None or number > best):
            best = number
    return best
```

`int | None` в Python 3.10+ означает один из двух вариантов результата. Это помогает помнить про отсутствие ответа. Если функция принимает любой перебираемый источник, точнее будет `Iterable[int]` из `collections.abc`, а не обязательно `list[int]`.

Аннотация — часть описания договорённости. Проверку диапазона, запрет пустого входа и изменение аргументов часто надо описать отдельно в документации.

### 29.3 Модульные проверки

**Тест** — программа, сравнивающая фактическое поведение с ожидаемым. **Модульный тест** проверяет небольшую самостоятельную часть, например функцию. Разделённые вычисление и ввод позволяют делать это без ручного набора данных.

```python
import unittest

def maximum_negative(numbers):
    best = None
    for number in numbers:
        if number < 0 and (best is None or number > best):
            best = number
    return best

class MaximumNegativeTests(unittest.TestCase):
    def test_mixed_values(self):
        self.assertEqual(maximum_negative([5, -9, -2, 0]), -2)

    def test_no_negative_values(self):
        self.assertIsNone(maximum_negative([0, 4]))

    def test_empty_input(self):
        self.assertIsNone(maximum_negative([]))

if __name__ == "__main__":
    unittest.main()
```

`unittest.TestCase` предоставляет методы проверок. Имя метода начинается с `test_`, чтобы система обнаружила тест. `assertEqual` требует равенство, `assertIsNone` — значение `None`. В отличие от инструкции `assert`, это обычные методы тестовой библиотеки, они не исчезают из-за `-O`.

### 29.4 Быстрое решение против медленного эталона

Оптимизированный алгоритм может быть трудно проверить глазами. Для маленьких данных напиши очевидный полный перебор, затем сравнивай результаты. Медленный вариант здесь служит независимым образцом, поэтому желательно, чтобы он не повторял ту же самую хитрую логику.

Например, для максимальной суммы окна эталон может прямо сложить каждый срез:

```python
def max_window_sum_slow(numbers, k):
    return max(sum(numbers[i:i + k])
               for i in range(len(numbers) - k + 1))
```

Договорённость — `1 <= k <= len(numbers)`. Затем сравни обе реализации на разных небольших списках. При случайной генерации используй фиксированное начальное состояние генератора, например `random.Random(42)`, чтобы ошибку можно было воспроизвести. Случайные тесты дополняют, а не заменяют специально выбранные границы.

### 29.5 Свойства вместо отдельных ответов

Иногда полезно проверять общие свойства. После сортировки должны сохраниться количество и набор элементов с учётом повторов. Для перевода основания `int(to_base(n, base), base)` должно давать исходное число. Каждый найденный делитель обязан делить число без остатка, а список делителей должен содержать 1 и само положительное число.

Однако отдельное свойство может пропустить ошибку: список `[1, n]` содержит только настоящие делители, но не все. Поэтому проверяй и допустимость найденного, и полноту решения.

Практика: достаточно ли теста `is_prime(7) == True`?

<summary>Разбор</summary>

Нет: функция, всегда возвращающая `True`, его пройдёт. Нужны хотя бы простое 2, обычное простое, составное чётное, составное нечётное, точный квадрат вроде 49, а также 0, 1 и отрицательное число, если функция обещает их обрабатывать.

</details>

## 30 Законченная программа анализа файла

### 30.1 Формулируем договорённость

Сделаем программу, которая читает текстовый файл с одним целым на строке и выводит количество, сумму, минимум, максимум и среднее. Заголовка нет. Пустой файл разрешён; пустая строка внутри непустого файла считается нарушением формата. Числа могут быть отрицательными. Программа рассчитана на обычные по величине целые; среднее вычисляется приближённо через `float`.

Путь передаётся аргументом командной строки. Командная строка — способ передать программе настройки при запуске. Если путь не указан, читается `numbers.txt` в рабочей папке. Вычисление сделаем отдельной функцией, чтобы оно не зависело от файла.

### 30.2 Полный код

Сохрани следующий код в `analyze_numbers.py`. Все его определения находятся в одном блоке; другие главы для запуска копировать не нужно.

```python
import sys
from pathlib import Path


def read_numbers(path):
    numbers = []
    with path.open(encoding="utf-8") as file:
        for line_number, line in enumerate(file, start=1):
            try:
                number = int(line)
            except ValueError as error:
                raise ValueError(
                    f"Строка {line_number}: ожидалось целое число"
                ) from error
            numbers.append(number)
    return numbers


def summarize(numbers):
    if not numbers:
        return {
            "count": 0,
            "total": 0,
            "minimum": None,
            "maximum": None,
            "average": None,
        }
    total = sum(numbers)
    return {
        "count": len(numbers),
        "total": total,
        "minimum": min(numbers),
        "maximum": max(numbers),
        "average": total / len(numbers),
    }


def main():
    if len(sys.argv) > 2:
        print("Использование: python analyze_numbers.py [путь]", file=sys.stderr)
        return 2
    path = Path(sys.argv[1]) if len(sys.argv) == 2 else Path("numbers.txt")
    try:
        numbers = read_numbers(path)
    except (OSError, ValueError) as error:
        print(f"Не удалось прочитать данные: {error}", file=sys.stderr)
        return 1

    report = summarize(numbers)
    print("Количество:", report["count"])
    print("Сумма:", report["total"])
    if report["count"] == 0:
        print("Файл пуст: минимум, максимум и среднее не определены")
    else:
        print("Минимум:", report["minimum"])
        print("Максимум:", report["maximum"])
        print(f"Среднее: {report['average']:.3f}")
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

### 30.3 Разбираем новые детали

`sys.argv` — список аргументов запуска. Первый элемент содержит имя запускаемого скрипта; следующие — переданные пользователем строки. Если в пути есть пробелы, в терминале его заключают в кавычки.

`except ValueError as error` даёт имя пойманному исключению. `raise ... from error` сохраняет исходную причину и добавляет понятный контекст с номером строки. `OSError` объединяет проблемы доступа к файлу и другие ошибки операционной системы. `UnicodeDecodeError` при неверной кодировке относится к семейству `ValueError` и также будет обработан.

`sys.stderr` — стандартный поток ошибок, отдельный от обычного вывода. `SystemExit` завершает программу с кодом: 0 обычно означает успех, ненулевое значение — проблему. Это полезно при запуске из других программ. Мы не перехватываем все возможные исключения: ошибка внутри вычисляющей функции должна быть замечена при разработке.

### 30.4 Пример запуска

Файл `numbers.txt`:

```text

-2
10
7
```

Команда:

```shell
python analyze_numbers.py numbers.txt
```

Результат:

```text

Сумма: 20
Минимум: -2
Максимум: 10

```

Проверь также пустой файл, одну строку `-5`, отсутствующий файл и строку `abc`. Для неверной строки программа должна сообщить её номер, а не незаметно пропустить запись.

### 30.5 Как развивать программу осмысленно

Для огромного файла список не обязателен: можно одновременно обновлять количество, сумму, минимум и максимум по мере чтения. Здесь список оставлен, чтобы функция `summarize` легко принимала готовые данные и чтобы было видно разделение ответственности.

Следующие самостоятельные улучшения: добавить отдельный JSON-отчёт, подсчёт чётных значений, проверку точного количества строк по заголовку или обработку нескольких файлов. Каждое изменение сначала сформулируй как новую договорённость, затем проверь старые и новые случаи.

## 31 Самостоятельная практика с разборами

Задачи этой главы проверяют перенос знаний. Сначала сформулируй решение словами, выбери структуру данных, оцени границы и только затем пиши код. Разборы показывают один из возможных способов; совпадение текста программы не является целью.

### 31.1 Последняя цифра степени

Даны неотрицательное целое `power` и целое `base`. Найди последнюю десятичную цифру `base ** power` для неотрицательного `base`, не создавая большое число. Для `power = 0` используй обычное для Python значение степени 1, включая `0 ** 0`.

<details markdown="1">

<summary>Решение и объяснение</summary>

```python
def last_digit_of_power(base, power):
    if base < 0 or power < 0:
        raise ValueError("Нужны неотрицательные значения")
    result = 1
    for _ in range(power):
        result = (result * base) % 10
    return result

print(last_digit_of_power(7, 4))  # 1
```

Для последней цифры достаточно остатка по модулю 10. Если заменить промежуточное произведение на его остаток, будущий остаток произведения не изменится: отброшенная часть кратна 10 и после умножения останется кратна 10.

Этот вариант выполняет `power` шагов. Стандартная `pow(base, power, 10)` считает модульную степень существенно эффективнее за счёт последовательного возведения в квадрат. Третий аргумент — модуль, а не точность округления.

</details>

### 31.2 Второе различное максимальное значение

Для списка целых найди второе по величине **различное** значение. Если различных значений меньше двух, верни `None`.

<details markdown="1">

<summary>Решение и объяснение</summary>

```python
def second_distinct_maximum(numbers):
    unique = sorted(set(numbers), reverse=True)
    if len(unique) < 2:
        return None
    return unique[1]

print(second_distinct_maximum([9, 9, 4, 7]))  # 7
```

Множество убирает повторы, сортировка задаёт порядок. Если бы требовался второй элемент по величине с учётом повторов, ответ для этого примера был бы 9. Можно разработать вариант за один проход с двумя лучшими различными значениями, но сначала нужно точно понимать требование.

</details>

### 31.3 Удалить повторы с сохранением порядка

Из списка хешируемых элементов создай список первых появлений. Например, `[3, 1, 3, 2, 1]` должен превратиться в `[3, 1, 2]`.

<details markdown="1">

<summary>Решение и объяснение</summary>

```python
def unique_in_order(items):
    seen = set()
    result = []
    for item in items:
        if item not in seen:
            seen.add(item)
            result.append(item)
    return result
```

Множество отвечает за быструю проверку, список — за порядок результата. У каждой структуры отдельное назначение. Более короткое `list(dict.fromkeys(items))` использует порядок словаря, но первый вариант лучше раскрывает алгоритм.

</details>

### 31.4 Частоты без учёта регистра

Для текста посчитай частоты букв, игнорируя регистр и небуквенные символы. Пусть используются обычные буквы русского и английского алфавитов без дополнительных правил нормализации Unicode.

<details markdown="1">

<summary>Решение и объяснение</summary>

```python
def letter_counts(text):
    counts = {}
    for letter in text.lower():
        if letter.isalpha():
            counts[letter] = counts.get(letter, 0) + 1
    return counts

print(letter_counts("Аа! Б"))  # {'а': 2, 'б': 1}
```

Сначала приводим регистр, затем отбираем буквы. Метод `isalpha` принимает и буквы других письменностей; если по задаче они недопустимы, нужно отдельно ограничить алфавит. Для универсального сравнения текста по регистру существует `casefold`, но правила языкового сравнения — самостоятельная задача.

</details>

### 31.5 Самое длинное слово и равенство длин

В строке слова разделены пробельными символами. Верни первое самое длинное слово или `None`, если слов нет. Пунктуацию считай частью слова — это явная договорённость упражнения.

<details markdown="1">

<summary>Решение и объяснение</summary>

```python
def first_longest_word(text):
    return max(text.split(), key=len, default=None)

print(first_longest_word("кот дом окно"))  # окно
print(first_longest_word("кот дом"))       # кот
```

`max` с одинаковым ключом оставляет первый элемент. Дополнительная сортировка дала бы больше работы без необходимости. Определение слова здесь специально простое; для естественного языка потребуются другие правила.

</details>

### 31.6 Скобки одного вида

Проверь правильность строки из символов `(` и `)`. Правильная строка не закрывает скобку до открытия и к концу закрывает все открытые. Пустая строка считается правильной. Другие символы считаются ошибкой.

<details markdown="1">

<summary>Решение и объяснение</summary>

```python
def valid_parentheses(text):
    balance = 0
    for char in text:
        if char == "(":
            balance += 1
        elif char == ")":
            balance -= 1
        else:
            return False
        if balance < 0:
            return False
    return balance == 0
```

`balance` — число ещё не закрытых открывающих скобок. Равенство общего количества открывающих и закрывающих недостаточно: `)(` имеет одинаковые количества, но неверный порядок. Для нескольких видов скобок нужен стек, чтобы помнить не только количество, но и вид последней незакрытой скобки.

</details>

### 31.7 Найти пару с заданной суммой

Верни индексы двух разных позиций, значения на которых дают `target`. Достаточно любой пары. Если её нет, верни `None`.

<details markdown="1">

<summary>Решение и объяснение</summary>

```python
def find_pair_with_sum(numbers, target):
    positions = {}
    for i, number in enumerate(numbers):
        needed = target - number
        if needed in positions:
            return positions[needed], i
        positions[number] = i
    return None

print(find_pair_with_sum([4, 7, 2, 9], 11))  # (0, 1)
print(find_pair_with_sum([5, 5], 10))        # (0, 1)
```

В словаре находятся только прежние позиции. Поэтому одна позиция не используется дважды. Проверка выполняется **до** добавления текущего числа: иначе единственная пятёрка могла бы ошибочно составить пару сама с собой. Обычная ожидаемая сложность — `O(n)` времени и `O(n)` памяти.

</details>

### 31.8 Максимум завершённых встреч

Встречи заданы парами `(start, end)`, где `start < end`. Один человек посещает непересекающиеся встречи. Следующая может начинаться ровно в момент окончания предыдущей. Выбери максимум встреч.

<details markdown="1">

<summary>Решение и объяснение</summary>

```python
def choose_meetings(meetings):
    selected = []
    last_end = None
    for start, end in sorted(meetings, key=lambda meeting: meeting[1]):
        if last_end is None or start >= last_end:
            selected.append((start, end))
            last_end = end
    return selected

print(choose_meetings([(0, 3), (1, 2), (2, 4), (3, 5)]))
# [(1, 2), (2, 4)]
```

Выбирается доступная встреча, которая заканчивается раньше всех. Почему это допустимо? Возьми оптимальное расписание и замени его первую встречу на самую раннюю по окончанию. Новая встреча заканчивается не позже, поэтому не мешает остальным выбранным. Количество не уменьшается. Затем тот же аргумент применяется к оставшейся части времени.

Это доказательство зависит от цели «максимум количества». Для максимальной суммарной ценности встреч тот же жадный выбор не гарантирует оптимальность.

</details>

### 31.9 Количество фрагментов с заданной суммой

Для списка целых, включая отрицательные, посчитай число непустых непрерывных фрагментов с суммой `target`.

<details markdown="1">

<summary>Решение и объяснение</summary>

```python
def count_sum_segments(numbers, target):
    seen_prefixes = {0: 1}
    prefix = 0
    count = 0
    for number in numbers:
        prefix += number
        count += seen_prefixes.get(prefix - target, 0)
        seen_prefixes[prefix] = seen_prefixes.get(prefix, 0) + 1
    return count

print(count_sum_segments([1, -1, 1], 1))  # 3
```

Для фрагмента сумма равна разности двух префиксов. Если текущий префикс равен `prefix`, нужен прежний префикс `prefix - target`. Словарь хранит количество его прежних появлений. Начальный префикс 0 присутствует один раз, чтобы считать фрагменты с начала списка.

Текущий префикс добавляется после подсчёта: иначе при `target = 0` возник бы лишний пустой фрагмент. В отличие от простого окна по ограничению суммы, этот алгоритм работает с отрицательными элементами. Ожидаемая сложность — линейная при обычных свойствах словаря.

</details>

### 32.2 Ошибки которые полезно узнавать сразу

| Ошибочная идея | Почему неверна | Правильный вопрос |
| --- | --- | --- |
| `range(a, b)` включает b | Остановка исключена | Какая последняя допустимая позиция? |
| `x == 2 or 3` | Второй операнд не сравнение | Повторено ли сравнение с x? |
| Максимум начинается с 0 | Данные могут быть отрицательными | Есть ли гарантированный допустимый первый кандидат? |
| `b = a` копирует список | Имена могут указывать на один объект | Нужны общие или отдельные данные? |
| `a = a.sort()` | sort возвращает None | Нужна мутация или новый список? |
| `return` внутри первого шага поиска | Проверка заканчивается слишком рано | Когда уже достаточно оснований вернуть ответ? |
| `cache` решает проблему глубины | Запоминание не убирает первый спуск | Можно ли вычислять снизу вверх? |
| Окно суммы всегда работает | Нужное свойство может исчезнуть при отрицательных | Как меняется допустимость при сдвиге границы? |
| `int(x)` округляет к ближайшему | Он отбрасывает дробную часть к нулю | Что именно требует условие? |
| `eval(input())` удобно читает число | eval выполняет выражение как код | Какой конкретный тип и формат нужно разобрать? |

`eval` не нужен для обычного ввода чисел: используй `int`, `float` и разбор структуры. Умение выбрать узкое понятное средство — часть понимания программы.
