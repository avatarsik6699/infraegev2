**Начнём с того, что именно находится в файле.** Обычно каждая строка описывает одну точку на плоскости:

```text
1.5 3.2
2.1 4.8
7.3 1.4
```

У точки есть две координаты:

- `x` — положение по горизонтали;
- `y` — положение по вертикали.

Например, запись

\[
A=(2;\,5)
\]

означает: точка расположена на 2 единицы правее начала координат и на 5 единиц выше него.

Отрицательная координата задаёт противоположное направление:

\[
B=(-3;\,4)
\]

— это 3 единицы влево и 4 единицы вверх.

В условиях часто используют слова **абсцисса** и **ордината**. За ними не скрывается ничего дополнительного:

| Слово в условии | Что это |
|---|---|
| Абсцисса | Координата `x` |
| Ордината | Координата `y` |

Звёзды, результаты эксперимента, населённые пункты — это сюжет. Для программы во всех этих случаях важны прежде всего пары чисел.

В Python одну точку удобно хранить так:

```python
point = (2.0, 5.0)
```

Такая упорядоченная группа значений называется **кортежем**. Здесь в нём два элемента.

Нумерация элементов в Python начинается с нуля:

```python
point[0]   # координата x
point[1]   # координата y
```

Можно сразу разложить пару по двум переменным:

```python
x, y = point
```

После этого:

```python
x == 2.0
y == 5.0
```

Несколько точек будем хранить в **списке**:

```python
points = [
    (2.0, 5.0),
    (-3.0, 4.0),
    (7.0, 1.0)
]
```

Список отличается от кортежа, в частности, тем, что его удобно изменять: добавлять и удалять элементы.

```python
points.append((8.0, 2.0))
```

Метод `append` добавляет один элемент в конец списка.

Количество элементов:

```python
len(points)
```

Перебрать все точки можно так:

```python
for point in points:
    print(point)
```

Переменная `point` будет последовательно принимать значения каждой точки.

Или сразу получать координаты:

```python
for x, y in points:
    print(x, y)
```

Обе записи перебирают одни и те же точки.

**Кластер в программе — это тоже список точек.** А все кластеры вместе — список таких списков:

```python
clusters = [
    [(0, 0), (1, 1), (2, 0)],
    [(10, 8), (11, 9), (12, 8)]
]
```

Здесь:

```python
clusters[0]        # первый кластер
clusters[1]        # второй кластер

len(clusters)     # количество кластеров
len(clusters[0])  # количество точек первого кластера
```

Важно различать эти два количества: **сколько групп** и **сколько точек внутри группы**.

**Расстояние между точками получается из теоремы Пифагора.** Пусть даны:

\[
A=(x_1,y_1),\qquad B=(x_2,y_2).
\]

Разность координат по горизонтали:

\[
x_2-x_1.
\]

Разность координат по вертикали:

\[
y_2-y_1.
\]

Эти два перемещения образуют катеты прямоугольного треугольника, а отрезок между точками — его гипотенузу.

Поэтому длина отрезка:

\[
d(A,B)=\sqrt{(x_2-x_1)^2+(y_2-y_1)^2}.
\]

Буквой \(d\) здесь обозначено расстояние.

Например:

\[
A=(1,2),\qquad B=(4,6).
\]

По горизонтали точки отличаются на 3, по вертикали — на 4:

\[
d(A,B)=\sqrt{3^2+4^2}=\sqrt{25}=5.
\]

Такое расстояние называется **евклидовым**: это обычная длина прямого отрезка.

В Python формулу можно записать самостоятельно:

```python
def distance(a, b):
    dx = a[0] - b[0]
    dy = a[1] - b[1]

    return (dx ** 2 + dy ** 2) ** 0.5
```

Здесь:

- `def` создаёт функцию — именованный фрагмент программы;
- `a` и `b` — значения, которые мы передаём функции;
- `** 2` означает возведение в квадрат;
- `** 0.5` означает извлечение квадратного корня;
- `return` возвращает результат.

Например:

```python
print(distance((1, 2), (4, 6)))
```

Получим:

```text
5.0
```

Но в стандартном модуле `math` уже есть нужная функция:

```python
from math import dist

print(dist((1, 2), (4, 6)))
```

`from math import dist` означает: взять функцию `dist` из математического модуля. Она вычисляет евклидово расстояние между точками. Дальше будем в основном использовать её. [Python 3.14.8 documentation](https://docs.python.org/3/library/math.html?utm_source=chatgpt.com)

Заметь несколько свойств:

\[
d(A,B)=d(B,A);
\]

\[
d(A,A)=0;
\]

\[
d(A,B)\geqslant 0.
\]

Они пригодятся при объяснении алгоритмов и ускорений.

**Иногда достаточно квадрата расстояния.** Если нужно лишь проверить:

\[
d(A,B)\leqslant r,
\]

где \(r\geqslant 0\), можно проверить равносильное условие:

\[
(x_2-x_1)^2+(y_2-y_1)^2\leqslant r^2.
\]

Например:

```python
dx = a[0] - b[0]
dy = a[1] - b[1]

if dx * dx + dy * dy <= r * r:
    print("Точки достаточно близки")
```

Корень не понадобился.

Почему это допустимо? Для неотрицательных чисел возведение в квадрат сохраняет порядок: если одно расстояние меньше другого, его квадрат тоже меньше.

**Но заменять сумму расстояний суммой их квадратов нельзя.** Это уже другая величина. Ниже мы разберём конкретный пример, где из-за такой замены выбирается другая точка.

**Перед написанием алгоритма нужно посмотреть первые строки файла.** В разных заданиях формат немного различается.

Возможен файл без заголовка:

```text
1.25 3.70
2.80 4.10
```

Возможен файл с заголовком:

```text
X Y
1.25 3.70
2.80 4.10
```

Дробная часть может отделяться запятой:

```text
1,25 3,70
2,80 4,10
```

Для Python запись `"1,25"` не является стандартной записью дробного числа. Перед преобразованием запятую заменяют точкой.

Разберём одну строку:

```python
line = "1,25 3,70"
```

Заменим запятые:

```python
line = line.replace(",", ".")
```

Теперь строка содержит:

```text
1.25 3.70
```

Разделим её на части:

```python
parts = line.split()
```

Получится:

```python
["1.25", "3.70"]
```

`split()` без аргументов разделяет строку по пробельным символам. Поэтому ему подходят и несколько пробелов подряд, и табуляция.

Пока элементы списка — **строки**, то есть текст. Превратим их в числа:

```python
x = float(parts[0])
y = float(parts[1])
```

`float` используется для чисел с дробной частью.

Полная функция чтения:

```python
def read_points(filename, has_header=False):
    points = []

    with open(filename, encoding="utf-8-sig") as f:
        if has_header:
            f.readline()

        for line in f:
            if not line.strip():
                continue

            sx, sy = line.replace(",", ".").split()

            x = float(sx)
            y = float(sy)

            points.append((x, y))

    return points
```

Что здесь происходит:

- `filename` — имя файла.
- `has_header` сообщает, есть ли в начале строка с названиями столбцов.
- `False` — значение «нет». Оно используется по умолчанию.
- `with open(...) as f` открывает файл, а после окончания блока автоматически его закрывает.
- `f.readline()` читает одну строку. В данном случае мы её намеренно пропускаем.
- `for line in f` перебирает оставшиеся строки.
- `line.strip()` убирает пробелы и перевод строки по краям.
- `if not line.strip()` проверяет, не является ли строка пустой.
- `continue` пропускает оставшуюся часть текущего прохода цикла.
- `encoding="utf-8-sig"` подходит для UTF-8 и корректно обрабатывает возможную служебную метку в начале такого файла.

Применение:

```python
points = read_points("27_A.txt", has_header=True)
```

Или без заголовка:

```python
points = read_points("27_A.txt")
```

**Не пропускай первую строку автоматически в любом файле.** Если заголовка нет, так потеряется первая точка.

Если в начале указано количество точек, эту строку тоже нужно обрабатывать отдельно, но уже в соответствии с таким форматом.

После чтения полезно проверить:

```python
print("Количество точек:", len(points))
print("Первые точки:", points[:5])
```

Запись `points[:5]` означает: взять первые пять элементов списка.

На этом этапе нужно убедиться, что программа действительно прочитала ожидаемые данные.

**Чтобы понять, как разделять точки, полезно сначала увидеть их расположение.** Такой рисунок называется **диаграммой рассеяния**: каждой записи файла соответствует отдельная точка.

В табличном редакторе для этого выбирают два столбца координат и строят **точечную диаграмму XY**.

Нужна именно диаграмма по координатам, а не обычный линейный график, который может располагать записи по их порядковым номерам.

В Python можно использовать `matplotlib`, если эта библиотека доступна в твоей среде:

```python
import matplotlib.pyplot as plt

xs = []
ys = []

for x, y in points:
    xs.append(x)
    ys.append(y)

plt.scatter(xs, ys, s=3)
plt.axis("equal")
plt.grid()
plt.show()
```

Здесь:

- `scatter` рисует отдельные точки;
- `s=3` задаёт небольшой размер маркеров;
- `axis("equal")` устанавливает одинаковый масштаб по обеим осям;
- `grid()` добавляет сетку;
- `show()` показывает рисунок.

Назначение `scatter` и его аргументов соответствует документации библиотеки. [Matplotlib 3.11.2 documentation](https://matplotlib.org/stable/api/_as_gen/matplotlib.pyplot.scatter.html?utm_source=chatgpt.com)

Одинаковый масштаб важен: иначе круг может выглядеть вытянутым эллипсом, а расстояния по горизонтали и вертикали будут восприниматься неправильно.

Для построения такого рисунка не нужно соединять точки линиями в порядке их появления в файле. Порядок строк обычно ничего не говорит о соседстве точек.

После построения рисунка спроси себя:

- Есть ли между ними пустые полосы?
- Можно ли провести разделяющую прямую?
- Есть ли отдельно стоящие точки?
- Похожи ли группы на компактные облака, дуги, кольца или вытянутые цепочки?

**Самый простой способ разделения — использовать координатные границы.** Допустим, все точки одной группы находятся левее `x = 5`, а все точки другой — правее.

Тогда:

```python
clusters = [[], []]

for point in points:
    x, y = point

    if x < 5:
        clusters[0].append(point)
    else:
        clusters[1].append(point)
```

Почему это работает?

Мы нашли правило, которое однозначно определяет принадлежность каждой точки:

\[
x<5 \quad\Rightarrow\quad \text{первый кластер};
\]

\[
x\geqslant5 \quad\Rightarrow\quad \text{второй кластер}.
\]

Число `5` здесь — **граница для конкретных данных**, а не универсальная константа задания 27.

Если группы разделены горизонтально, используется координата `y`:

```python
if y < 8:
    ...
else:
    ...
```

Если групп три, можно комбинировать условия:

```python
clusters = [[], [], []]

for point in points:
    x, y = point

    if y < 3:
        clusters[0].append(point)
    elif x < 5:
        clusters[1].append(point)
    else:
        clusters[2].append(point)
```

`elif` означает «иначе, если».

Здесь порядок проверок существенен:

1. Сначала выделяется нижняя группа.
2. Среди оставшихся точек выделяется левая.
3. Всё остальное попадает в третью.

Такой код допустим только тогда, когда рисунок и данные действительно соответствуют этим условиям.

**Почему часто удобнее `if / elif / else`, а не несколько независимых `if`?**

При независимых проверках точка может удовлетворить сразу двум условиям:

```python
if x < 5:
    clusters[0].append(point)

if y < 3:
    clusters[1].append(point)
```

Если у точки одновременно `x < 5` и `y < 3`, она попадёт в оба списка.

Цепочка `if / elif / else` выполняет только одну ветвь. Но и она не исправляет неправильно выбранные границы: она лишь предотвращает многократное добавление в рамках этой цепочки.

При наличии аномалий последнее `else` может быть опасным. Оно отправит в последний кластер вообще всё, что не подошло раньше, включая лишние точки.

В таком случае лучше выделять допустимые области явно, а остальные точки сохранять отдельно.

Например:

```python
clusters = [[], []]
noise = []

for point in points:
    x, y = point

    if 0 <= x <= 3 and 0 <= y <= 4:
        clusters[0].append(point)

    elif 8 <= x <= 12 and 5 <= y <= 9:
        clusters[1].append(point)

    else:
        noise.append(point)
```

`and` означает, что должны одновременно выполняться оба условия.

И здесь все границы — только учебный пример.

---

**Разделяющая граница не обязана быть вертикальной или горизонтальной.** Иногда две группы удобно разделить наклонной прямой:

\[
y=2x+1.
\]

Точки выше неё удовлетворяют условию:

\[
y>2x+1,
\]

а ниже:

\[
y<2x+1.
\]

В коде:

```python
if y < 2 * x + 1:
    clusters[0].append(point)
else:
    clusters[1].append(point)
```

Чтобы понять проверку, возьми конкретное `x`. Выражение `2*x + 1` вычисляет высоту прямой при этом `x`. Затем программа сравнивает с ней высоту точки.

В некоторых задачах сказано, что кластеры помещаются в прямоугольники или квадраты заданных размеров. Это **ограничение на расположение точек**, а не готовая инструкция, как их разделить.

Из него нельзя автоматически заключить:

- что границы проходят через начало координат;
- что точки нужно группировать по `x // W`;
- что стороны прямоугольников параллельны осям;
- что ширину прямоугольника можно использовать как порог соседства.

В подборке есть условия, прямо разрешающие поворот квадратов относительно осей. [inf-ege.sdamgia.ru](https://inf-ege.sdamgia.ru/test?theme=428\&ttest=true\&utm_source=chatgpt.com)

Если прямоугольник заведомо расположен параллельно осям, для его точек необходимо:

\[
x_{\max}-x_{\min}\leqslant W,
\]

\[
y_{\max}-y_{\min}\leqslant H.
\]

Но для повёрнутого прямоугольника его проекции на оси могут быть шире соответствующих сторон. Поэтому такая проверка уже не является универсальной.

**Другой важный способ кластеризации — объединять точки через цепочки близких соседей.** Он полезен, когда группы разделены промежутками, но провести простые границы неудобно.

Сначала выбирается число \(\varepsilon\), которое будем называть **порогом соседства**.

Две точки считаем соседями, если:

\[
d(A,B)\leqslant\varepsilon.
\]

Теперь представь три точки на одной горизонтальной прямой:

\[
A=(0,0),\qquad B=(0.8,0),\qquad C=(1.6,0).
\]

Возьмём:

\[
\varepsilon=0.9.
\]

Тогда:

\[
d(A,B)=0.8\leqslant0.9;
\]

\[
d(B,C)=0.8\leqslant0.9;
\]

но:

\[
d(A,C)=1.6>0.9.
\]

Тем не менее все три точки образуют **одну связную группу**: от `A` до `C` можно пройти через `B`, причём каждый шаг достаточно короткий.

**Внутри такой группы не требуется, чтобы каждая точка была близка к каждой.** Требуется возможность добраться от одной точки до другой по цепочке соседей.

Если нарисовать отрезки между всеми парами соседей, получится **граф**:

- точки называются его вершинами;
- соединяющие их отрезки — рёбрами.

Группа вершин, между которыми можно пройти по рёбрам и к которой нельзя присоединить другие достижимые вершины, называется **компонентой связности**.

Термин выглядит сложнее самой идеи: это отдельный связный кусок рисунка.

В схеме можно менять порог. При маленьком значении точкам не хватает связей, при подходящем возникают две группы, при слишком большом они сливаются.







Алгоритм построения одной такой группы:

1. Взять любую ещё не распределённую точку.
2. Найти её нераспределённых соседей.
3. Добавить их в текущую группу.
4. Найти соседей у добавленных точек.
5. Продолжать, пока все точки текущей группы не будут обработаны.

После этого берём следующую нераспределённую точку и начинаем новую группу.

Здесь принципиально важен четвёртый шаг. Если искать соседей только у первой точки, мы получим лишь её непосредственное окружение, а не весь кластер.

Вот реализация:

```python
from math import dist

def split_clusters(points, eps):
    remaining = points.copy()
    clusters = []

    while remaining:
        cluster = [remaining.pop()]
        pos = 0

        while pos < len(cluster):
            point = cluster[pos]
            rest = []

            for other in remaining:
                if dist(point, other) <= eps:
                    cluster.append(other)
                else:
                    rest.append(other)

            remaining = rest
            pos += 1

        clusters.append(cluster)

    return clusters
```

Разберём устройство кода.

`remaining` содержит точки, которые ещё не отнесены ни к одной группе.

```python
remaining = points.copy()
```

Метод `copy()` создаёт отдельный список. Сам исходный список `points` мы не будем опустошать.

```python
while remaining:
```

Цикл продолжается, пока список не пуст.

```python
cluster = [remaining.pop()]
```

`pop()` извлекает последний элемент списка и удаляет его из списка. Эта точка становится первой точкой новой группы.

```python
pos = 0
```

`pos` — номер точки текущей группы, соседей которой мы сейчас будем искать.

```python
while pos < len(cluster):
```

Размер `cluster` может увеличиваться по мере работы. Поэтому цикл обработает и исходную точку, и всех добавленных соседей.

```python
rest = []
```

В этот список соберём точки, которые пока остались нераспределёнными.

Если точка близка к обрабатываемой:

```python
cluster.append(other)
```

Если нет:

```python
rest.append(other)
```

После прохода:

```python
remaining = rest
```

Точки, присоединённые к кластеру, исчезают из списка нераспределённых.

Наконец:

```python
pos += 1
```

Переходим к следующей точке растущей группы.

**Почему алгоритм находит всю связную группу?**

Каждая добавленная точка рано или поздно обрабатывается. Значит, будут найдены её ещё не добавленные соседи. Затем соседи этих соседей — и так далее.

Если существует цепочка из коротких шагов от начальной точки до некоторой другой, алгоритм последовательно пройдёт по ней.

И наоборот: точка добавляется только потому, что близка к уже включённой. Значит, случайно перескочить в группу, с которой вообще нет связей, алгоритм не может.

Однако здесь есть важное ограничение:

> Алгоритм точно находит компоненты связности для выбранного порога. Совпадут ли они с кластерами из условия — отдельный вопрос.

---

**Порог соседства нужно обосновать по данным.** Для правильного разделения описанным способом должны выполняться два требования:

1. Внутри каждого требуемого кластера точки соединяются цепочками шагов длиной не больше \(\varepsilon\).
2. Между разными требуемыми кластерами нет ни одной пары точек на расстоянии не больше \(\varepsilon\).

Обрати внимание: первое требование относится к **цепочкам**, а не к наибольшему расстоянию между любыми двумя точками внутри кластера.

Вытянутый кластер может иметь длину 20 единиц, но состоять из точек с промежутками по 0.2. Для его связности вовсе не нужен порог 20.

Если порог слишком маленький, одна настоящая группа может распасться на несколько.

Если слишком большой, отдельные группы могут соединиться.

При этом даже правильное количество получившихся групп ещё ничего не доказывает. Например:

- один настоящий кластер распался на два;
- два других слились в один.

Общее количество осталось прежним, но распределение неверно.

После автоматического разделения полезно вывести размеры:

```python
clusters = split_clusters(points, eps=1.0)

print("Количество групп:", len(clusters))

for cluster in clusters:
    print(len(cluster))
```

Число `1.0` здесь тоже лишь пример.

Можно проверить несколько близких значений порога:

```python
for eps in [0.7, 0.8, 0.9, 1.0]:
    clusters = split_clusters(points, eps)

    sizes = []

    for cluster in clusters:
        sizes.append(len(cluster))

    print(eps, sizes)
```

Если в некотором диапазоне порогов сохраняется одно и то же разумное разделение, это полезный признак устойчивости. Но он не заменяет проверку геометрии и требований условия.

**Иногда единого подходящего порога вообще нет.** Например, внутри одного разреженного кластера промежутки больше, чем расстояние между двумя другими кластерами.

Тогда увеличение порога, необходимое для соединения первого, уже склеит два других.

Поэтому разделение по соседям — важный инструмент, но не универсальная замена анализу условия.

Также не следует смешивать три разных понятия:

- радиус круга, упомянутого в условии;
- расстояние от вычисленного центра до самой далёкой точки;
- порог соседства \(\varepsilon\).

Это могут быть совершенно разные числа.

---

**Точки-аномалии обрабатывают только по правилам конкретной задачи.** Аномалия здесь означает запись, которая не относится ни к одному из требуемых кластеров.

Например, в № 81811 указаны три лишние точки в файле Б, которые нужно исключить. [inf-ege.sdamgia.ru](https://inf-ege.sdamgia.ru/problem?id=81811\&utm_source=chatgpt.com)

Допустим, после разделения получились группы размеров:

```text
2400, 3100, 2800, 1, 2
```

Если по условию должно быть три содержательных кластера и три аномальные точки, последние две группы могут оказаться аномалиями.

Но важно проверить:

- где они находятся;
- почему их нужно исключить;
- действительно ли исключается три точки;
- не является ли маленькая группа допустимым кластером.

**Число аномальных точек и число маленьких групп — не одно и то же.** Три аномалии могут образовывать три одиночные группы, одну группу из трёх точек или группы размеров 1 и 2.

Нельзя без обоснования писать:

```python
# Нельзя считать это универсальным правилом!
if len(cluster) > 10:
    ...
```

В одной задаче это может сработать, в другой удалит настоящий кластер.

Есть ещё проблема: аномальная точка может оказаться близко к настоящему кластеру и присоединиться к нему при обработке по порогу. Несколько аномалий могут даже образовать «мостик» между группами.

Поэтому автоматическое выделение маленьких компонент не решает любую задачу с шумом.

Возможно, ты встретишь название **DBSCAN**. Это метод, который дополнительно учитывает плотность: важно не только расстояние до соседей, но и их количество. У него есть параметры `eps` и `min_samples`. Описанное выше обычное объединение по цепочкам не следует без пояснений считать полноценным алгоритмом фильтрации шума. [scikit-learn 1.9.1 documentation](https://scikit-learn.org/stable/modules/clustering.html?utm_source=chatgpt.com)

Для понимания заданий сначала достаточно уверенно владеть координатными границами и компонентами связности.

---

**Если форма кластеров необычная, полезно искать признак, который их разделяет.** Это может быть не сама координата `x` или `y`, а вычисленная по ним величина.

Например, группы могут располагаться в разных кольцевых областях вокруг известной точки:

\[
C=(x_0,y_0).
\]

Тогда вычисляем расстояние до неё:

\[
r=\sqrt{(x-x_0)^2+(y-y_0)^2}.
\]

И разделяем точки по диапазонам `r`:

```python
r = dist(point, (x0, y0))

if r < 3:
    ...
elif r < 7:
    ...
else:
    ...
```

Границы опять выбираются по конкретным данным.

Здесь точка `C`, относительно которой расположены кольца, не обязана быть тем «центром кластера», который затем требуется найти по сумме расстояний. У этих точек разное назначение.

Если группы лежат в разных **секторах**, разделяющим признаком может быть направление от известной точки `C`.

Сектор можно представить как кусок круга между двумя лучами.

Для точки, не совпадающей с `C`, угол направления вычисляется так:

```python
from math import atan2, degrees

angle = degrees(atan2(y - y0, x - x0))
angle = angle % 360
```

Здесь:

- `atan2` определяет угол направления с учётом обеих координат;
- `degrees` переводит его из радиан в градусы;
- `% 360` приводит угол к диапазону от 0 включительно до 360 не включительно.

Направление вправо соответствует 0°, вверх — 90°, влево — 180°.

Почему лучше не использовать обычное деление `(y-y0)/(x-x0)`? Потому что оно не различает все направления и приводит к делению на ноль на вертикальном луче.

Есть тонкость: направления 359° и 1° очень близки. Их нельзя считать далёкими только потому, что одно число почти 360, а другое почти 0.

Чтобы проверить сектор, начинающийся с угла `start` и имеющий ширину `width`, удобно написать:

```python
relative_angle = (angle - start) % 360

if relative_angle <= width:
    ...
```

Например, сектор от 350° до 10° имеет ширину 20° и пересекает границу 0°.

**Не дели угол на ширину сектора автоматически.** Из того, что ширина равна 20°, не следует, что границы проходят именно по 0°, 20°, 40° и так далее. Положение секторов тоже нужно установить.

Такой подход нужен, в частности, для понимания геометрии задач вроде № 78083, где группы описаны секторами. [inf-ege.sdamgia.ru](https://inf-ege.sdamgia.ru/problem?id=78083\&utm_source=chatgpt.com)

**Теперь предположим, что кластеры уже выделены правильно.** Следующая задача — найти требуемый центр каждого кластера.

Начнём с распространённого определения:

> Среди точек кластера нужно выбрать ту, от которой сумма расстояний до остальных точек минимальна.

В этой фразе важны обе части:

- выбираем **одну из имеющихся точек**;
- сравниваем **суммы расстояний**.

Такую точку в математической терминологии часто называют **медоидом**. В условиях ЕГЭ для неё могут использовать слово «центр» или «центроид». При решении следует руководствоваться данным в условии определением.

Представим один кластер из пяти точек на горизонтальной прямой:

\[
(0,0),\ (1,0),\ (2,0),\ (3,0),\ (100,0).
\]

На одной горизонтали расстояние равно модулю разности координат `x`.

Для точки `(0, 0)` сумма расстояний до остальных:

\[
1+2+3+100=106.
\]

Для `(1, 0)`:

\[
1+1+2+99=103.
\]

Для `(2, 0)`:

\[
2+1+1+98=102.
\]

Получим:

| Кандидат в центры | Сумма расстояний |
|---|---:|
| `(0, 0)` | 106 |
| `(1, 0)` | 103 |
| `(2, 0)` | **102** |
| `(3, 0)` | 103 |
| `(100, 0)` | 394 |

Следовательно, искомый центр:

\[
(2,0).
\]

Слово **кандидат** означает точку, которую мы сейчас проверяем: «А что, если именно она будет центром?»

Общий алгоритм повторяет ручные действия:

1. Выбрать очередного кандидата.
2. Посчитать расстояния от него до всех точек кластера.
3. Сложить расстояния.
4. Сравнить сумму с лучшей найденной.
5. При улучшении запомнить и сумму, и самого кандидата.

Код:

```python
from math import dist

def center_sum(cluster):
    best_point = cluster[0]
    best_sum = float("inf")

    for candidate in cluster:
        total = 0.0

        for point in cluster:
            total += dist(candidate, point)

        if total < best_sum:
            best_sum = total
            best_point = candidate

    return best_point
```

Функция рассчитана на непустой кластер.

`float("inf")` — положительная бесконечность. Любая конечная сумма окажется меньше неё. Это позволяет первому кандидату автоматически стать начальным лучшим результатом.

Внешний цикл:

```python
for candidate in cluster:
```

перебирает возможные центры.

Внутренний цикл:

```python
for point in cluster:
```

перебирает точки, до которых мы считаем расстояния.

Строка:

```python
total = 0.0
```

стоит внутри внешнего цикла, потому что **для каждого нового кандидата нужна новая сумма**.

Если поставить её до внешнего цикла, расстояния разных кандидатов начнут накапливаться вместе, и смысл вычисления потеряется.

Строка:

```python
total += dist(candidate, point)
```

равносильна:

```python
total = total + dist(candidate, point)
```

После окончания внутреннего цикла сумма полностью посчитана. Только теперь можно сравнивать её с лучшим результатом.

**Почему функция гарантированно найдёт нужную точку?** Потому что она рассматривает всех допустимых кандидатов и точно вычисляет для каждого именно ту величину, которую требуется минимизировать.

Мы не пытаемся угадать центр по рисунку и не ограничиваем поиск несколькими «подходящими на вид» точками.

---

**Расстояние от кандидата до самого себя можно оставить в сумме.** Оно равно нулю:

\[
d(P,P)=0.
\]

Поэтому:

\[
\text{сумма до всех остальных точек}
=
\text{сумма до всех точек, включая себя}.
\]

Специальная проверка:

```python
if point != candidate:
```

для этой задачи не нужна.

Более того, она может мешать в других вычислениях, если разные записи файла имеют одинаковые координаты.

**Не удаляй совпадающие точки без указания в условии.** Если две строки описывают два наблюдения с одинаковыми координатами, их повторение влияет на количество точек и на суммы расстояний от других точек.

Для кластера из одной точки наша функция тоже работает: сумма равна нулю, центром становится эта точка.

Для пустого списка центр не определён. Если после разделения возник пустой кластер, это повод проверить границы или сам способ создания групп.

Если несколько точек дают одну и ту же минимальную сумму, код с `<` сохраняет первую встретившуюся. Код с `<=` сохранял бы последнюю.

Когда условие гарантирует единственность центра, математической неоднозначности нет. Если такой гарантии нет, нужно посмотреть, предусмотрено ли дополнительное правило выбора.

---

**Среднее арифметическое координат обычно не является ответом на задачу о минимуме суммы расстояний.**

Среднее арифметическое — это сумма чисел, разделённая на их количество.

Для наших пяти точек:

\[
\overline{x}=\frac{0+1+2+3+100}{5}=21.2,
\]

\[
\overline{y}=0.
\]

Средняя точка:

\[
(21.2,0).
\]

Но:

- такой точки вообще нет среди исходных;
- правильный центр по сумме расстояний — `(2, 0)`.

Интуитивная причина: далёкая точка сильно смещает среднее арифметическое, а минимум суммы обычных расстояний определяется иначе.

Возникает следующая идея:

> Тогда найдём среднюю точку и выберем ближайшую к ней исходную.

Проверим её.

Ближайшая исходная точка к `(21.2, 0)` — `(3, 0)`.

Но её сумма расстояний равна 103, тогда как у `(2, 0)` — 102.

Значит, **даже ближайшая к среднему точка не обязана быть правильным центром по сумме обычных расстояний**.

Это важный пример: он опровергает сразу два привлекательных, но неверных общих правила.

---

**Если в условии минимизируется среднее расстояние, выбор центра часто остаётся тем же.** Пусть в кластере \(m\) точек, где \(m>1\).

Для кандидата \(P\) обозначим сумму расстояний до остальных точек через \(S(P)\).

Тогда среднее расстояние до остальных:

\[
\frac{S(P)}{m-1}.
\]

Число \(m-1\) одинаково для всех кандидатов одного кластера.

Если две суммы удовлетворяют условию:

\[
S(A)<S(B),
\]

то после деления на одно и то же положительное число порядок сохранится:

\[
\frac{S(A)}{m-1}<\frac{S(B)}{m-1}.
\]

Поэтому для **выбора точки** достаточно минимизировать сумму.

Но если требуется вывести само среднее расстояние, деление выполнить нужно.

Также нужно различать:

- среднее до **остальных** точек — деление на \(m-1\);
- среднее по всем точкам, включая саму точку с расстоянием 0, — деление на \(m\).

Выбранный центр будет одинаковым, а числовое значение среднего — разным.

---

**Другое определение центра использует расстояние до самой далёкой точки.** В нём для каждого кандидата сначала ищут максимальное расстояние, а затем выбирают кандидата с наименьшим таким максимумом.

Развернём фразу «минимально максимальное расстояние»:

1. Представили, что точка `P` — центр.
2. Нашли самую далёкую от неё точку кластера.
3. Запомнили, насколько далеко она находится.
4. Повторили для других кандидатов.
5. Выбрали того, у кого самое далёкое расстояние меньше всего.

Это можно понимать как поиск точки, из которой **хуже всего расположенный объект всё равно находится как можно ближе**.

Такой принцип называют **минимаксом**: минимум среди вычисленных максимумов.

Пример:

\[
(0,0),\ (1,0),\ (2,0),\ (5,0),\ (10,0).
\]

| Кандидат | Сумма расстояний | Самое большое расстояние |
|---|---:|---:|
| `(0, 0)` | 18 | 10 |
| `(1, 0)` | 15 | 9 |
| `(2, 0)` | **14** | 8 |
| `(5, 0)` | 17 | **5** |
| `(10, 0)` | 32 | 10 |

По сумме расстояний центр — `(2, 0)`.

По минимальному максимальному расстоянию — `(5, 0)`.

Это **разные задачи с разными ответами**.

Код для второго определения:

```python
from math import dist

def center_minimax(cluster):
    best_point = cluster[0]
    best_radius = float("inf")

    for candidate in cluster:
        radius = 0.0

        for point in cluster:
            d = dist(candidate, point)

            if d > radius:
                radius = d

        if radius < best_radius:
            best_radius = radius
            best_point = candidate

    return best_point, best_radius
```

Функция возвращает два значения:

```python
center, radius = center_minimax(cluster)
```

- `center` — выбранную точку;
- `radius` — расстояние от неё до самой далёкой точки.

Такое определение встречается, например, в № 73882. [inf-ege.sdamgia.ru](https://inf-ege.sdamgia.ru/problem?id=73882\&utm_source=chatgpt.com)

**Если центр по условию обязан быть точкой кластера, нельзя свободно поставить его между точками.**

Например, для двух точек `(0, 0)` и `(10, 0)` геометрическая середина `(5, 0)` покрывает их кругом радиуса 5.

Но если разрешено выбирать центр только из этих двух точек, минимальное максимальное расстояние равно 10.

Ограничение на допустимые центры принципиально меняет задачу.

---

**«Антицентр», «антипод» и «самая далёкая точка» нужно переводить в точное правило из условия.** По одному названию угадывать алгоритм нельзя.

Возможны, например, такие определения:

| Что требуется | Что вычисляем для кандидата | Как выбираем |
|---|---|---|
| Минимум суммы расстояний | Сумму расстояний до точек кластера | Наименьшую сумму |
| Максимум суммы расстояний | Ту же сумму | Наибольшую сумму |
| Минимум максимального расстояния | Самое большое расстояние до точки кластера | Наименьший максимум |
| Самая далёкая точка от уже найденного центра | Одно расстояние до этого центра | Наибольшее расстояние |

Последние два столбца помогают буквально перевести предложение на язык циклов.

Если «антицентр» определён как точка с **максимальной суммой** расстояний, в функции `center_sum` меняются:

```python
best_sum = -float("inf")
```

и:

```python
if total > best_sum:
```

Всё остальное устройство сохраняется.

Но найти точку с максимальной суммой расстояний и найти точку, самую далёкую от центра, — это не одно и то же вычисление.

Для самой далёкой от уже известного центра:

```python
farthest_point = cluster[0]
max_distance = -1.0

for point in cluster:
    d = dist(center, point)

    if d > max_distance:
        max_distance = d
        farthest_point = point
```

Здесь нет суммирования: каждой точке соответствует только одно расстояние.

---

**Для суммы квадратов расстояний существует отдельное точное ускорение.** Начнём с различия самих выражений.

Сумма обычных расстояний:

\[
d_1+d_2+\dots+d_m.
\]

Сумма квадратов расстояний:

\[
d_1^2+d_2^2+\dots+d_m^2.
\]

Квадрат всей суммы:

\[
(d_1+d_2+\dots+d_m)^2.
\]

Это три разных выражения.

Возьмём снова точки с координатами `x`:

```text
0, 1, 2, 3, 100
```

Для кандидата `2` сумма обычных расстояний равна:

\[
102.
\]

Для кандидата `3`:

\[
103.
\]

Первый кандидат лучше.

Но суммы квадратов:

\[
2^2+1^2+0^2+1^2+98^2=9610;
\]

\[
3^2+2^2+1^2+0^2+97^2=9423.
\]

Теперь лучше кандидат `3`.

Причина в том, что возведение в квадрат сильнее увеличивает большие расстояния. Сокращение очень большого расстояния может перевесить увеличение нескольких маленьких.

**Для минимума суммы квадратов ближайшая к средней точке исходная точка действительно подходит.** Давай выведем почему.

Пусть в кластере \(m\) точек:

\[
(x_1,y_1),\ldots,(x_m,y_m).
\]

Проверяем кандидата:

\[
P=(x,y).
\]

Нужная сумма:

\[
T(P)=\sum_{i=1}^{m}\left((x-x_i)^2+(y-y_i)^2\right).
\]

Знак \(\sum\) означает суммирование. Индекс \(i\) последовательно принимает значения от 1 до \(m\).

То есть формула — сокращённая запись:

\[
\bigl((x-x_1)^2+(y-y_1)^2\bigr)
+\ldots+
\bigl((x-x_m)^2+(y-y_m)^2\bigr).
\]

Обозначим средние координаты:

\[
\overline{x}=\frac{x_1+\ldots+x_m}{m},
\qquad
\overline{y}=\frac{y_1+\ldots+y_m}{m}.
\]

После раскрытия скобок и группировки слагаемых получается:

\[
T(P)=
m\left((x-\overline{x})^2+(y-\overline{y})^2\right)
+
\sum_{i=1}^{m}
\left((x_i-\overline{x})^2+(y_i-\overline{y})^2\right).
\]

Посмотрим на смысл двух частей.

Первая:

\[
m\left((x-\overline{x})^2+(y-\overline{y})^2\right)
\]

— количество точек, умноженное на квадрат расстояния от кандидата до средней точки.

Вторая часть зависит только от исходных точек. При смене кандидата она **не изменяется**.

Поэтому при сравнении кандидатов достаточно сравнивать первую часть. А множитель \(m\) одинаков для всех.

Получаем:

> Минимизировать сумму квадратов расстояний — значит выбрать допустимую точку, ближайшую к средней точке кластера.

Если разрешена любая точка плоскости, минимум достигается в самой средней точке.

Если разрешены только точки исходного кластера, нужно выбрать ближайшую из них.

Чтобы увидеть источник преобразования, достаточно раскрыть одну часть:

\[
\sum_{i=1}^{m}(x-x_i)^2
=
mx^2-2x\sum_{i=1}^{m}x_i+\sum_{i=1}^{m}x_i^2.
\]

Поскольку:

\[
\sum_{i=1}^{m}x_i=m\overline{x},
\]

получаем квадрат \(m(x-\overline{x})^2\) и остаток, не зависящий от `x`. С координатой `y` происходит то же самое.

Код:

```python
def center_squared(cluster):
    sum_x = 0.0
    sum_y = 0.0

    for x, y in cluster:
        sum_x += x
        sum_y += y

    mean_x = sum_x / len(cluster)
    mean_y = sum_y / len(cluster)

    best_point = cluster[0]
    best_value = float("inf")

    for point in cluster:
        x, y = point

        value = (x - mean_x) ** 2 + (y - mean_y) ** 2

        if value < best_value:
            best_value = value
            best_point = point

    return best_point
```

Мы дважды прошли по точкам, а не сравнивали каждую с каждой.

Это ускорение следует из формулы, поэтому сохраняет правильность. Но оно относится именно к **сумме квадратов евклидовых расстояний**.

---

**Формулу расстояния тоже нужно читать в условии.** Пока мы рассматривали обычное евклидово расстояние. Если задана другая формула, её нужно использовать во всех соответствующих вычислениях.

Например:

\[
d(A,B)=|x_1-x_2|+|y_1-y_2|.
\]

Это **манхэттенское расстояние**. Его можно представить как длину пути, когда разрешено двигаться только по горизонтали и вертикали.

Для точек `(1, 2)` и `(4, 6)`:

\[
|1-4|+|2-6|=3+4=7.
\]

Евклидово расстояние между ними равно 5.

В Python:

```python
def manhattan(a, b):
    return abs(a[0] - b[0]) + abs(a[1] - b[1])
```

`abs` вычисляет модуль числа: его неотрицательную величину.

Перебор кандидатов по сумме расстояний можно оставить прежним, заменив используемую функцию расстояния.

Но доказанное выше ускорение через ближайшую к среднему точку нельзя переносить на новую формулу автоматически.

---

**Разберём, почему поиск центра может занимать много времени.** Пусть в кластере \(m\) точек.

Для каждого кандидата мы проверяем все \(m\) точек:

\[
m\cdot m=m^2.
\]

Примеры:

| Точек в кластере | Вычислений расстояния в прямом двойном цикле |
|---:|---:|
| 100 | 10 000 |
| 1 000 | 1 000 000 |
| 5 000 | 25 000 000 |
| 10 000 | 100 000 000 |

Такой рост называют **квадратичным** и обозначают:

\[
O(m^2).
\]

Эта запись описывает порядок роста работы, а не конкретное количество секунд.

Если точек стало в два раза больше, вычислений в таком алгоритме станет примерно в четыре раза больше.

Если кластеров несколько, объём работы:

\[
m_1^2+m_2^2+\ldots+m_k^2,
\]

где \(m_i\) — размер очередного кластера, а \(k\) — количество кластеров.

То есть после разделения мы не считаем расстояния от кандидата до всех точек файла. Только до точек **его собственного кластера**.

Например, для 10 000 точек, примерно поровну распределённых по трём кластерам, получится около 33 миллионов вычислений расстояния, а не 100 миллионов.

**Автоматическое выделение компонент и поиск центров — две разные по времени операции.** Наивное выделение соседей тоже может потребовать порядка \(N^2\) проверок, где \(N\) — число всех точек файла.

Если кластеры легко разделяются несколькими координатными условиями, это позволяет распределить точки за один проход, без попарного поиска соседей.

Поэтому более «автоматический» способ не всегда является более быстрым.

Не стоит заранее обещать себе, что определённое число миллионов операций выполнится за фиксированное количество секунд. На время влияют компьютер, версия Python и устройство кода. Полезно заранее запускать свои решения на файлах сопоставимого размера.

---

**Первое точное ускорение поиска центра использует симметрию расстояния.**

В исходном алгоритме расстояние между `A` и `B` вычисляется дважды:

- когда кандидатом является `A`;
- когда кандидатом является `B`.

Но:

\[
d(A,B)=d(B,A).
\]

Можно вычислить его один раз и добавить одновременно в обе суммы.

Для этого создаём отдельную сумму для каждой точки:

```python
totals = [0.0] * len(cluster)
```

Если точек четыре, получится:

```python
[0.0, 0.0, 0.0, 0.0]
```

Полная функция:

```python
from math import dist

def center_sum_pairs(cluster):
    n = len(cluster)
    totals = [0.0] * n

    for i in range(n):
        for j in range(i + 1, n):
            d = dist(cluster[i], cluster[j])

            totals[i] += d
            totals[j] += d

    best_index = totals.index(min(totals))

    return cluster[best_index]
```

`range(n)` создаёт последовательность номеров:

```text
0, 1, 2, ..., n - 1
```

Внутренний цикл начинается с `i + 1`, поэтому перебираются только пары, в которых второй номер больше первого.

Для четырёх точек это:

```text
(0, 1), (0, 2), (0, 3),
(1, 2), (1, 3),
(2, 3)
```

Пара `(1, 0)` не нужна: она уже учтена как `(0, 1)`.

Расстояние от точки до самой себя тоже не вычисляется.

Число различных пар:

\[
\frac{m(m-1)}{2}.
\]

Примерно вдвое меньше исходных \(m^2\).

После завершения циклов:

```python
min(totals)
```

находит наименьшую сумму.

```python
totals.index(...)
```

находит номер её первого появления.

По этому номеру возвращаем исходную точку:

```python
cluster[best_index]
```

Порядок роста остаётся квадратичным, но вычислений расстояния становится меньше.

При этом нам не нужна таблица всех попарных расстояний: достаточно списка сумм длины \(m\). Хранить огромную матрицу расстояний ради единственного поиска центра обычно излишне.

---

**Второе точное ускорение — досрочно прекращать проверку заведомо проигравшего кандидата.**

Допустим, для уже проверенной точки сумма равна 500.

Для нового кандидата посчитана только часть расстояний, а сумма уже равна 520.

Оставшиеся расстояния неотрицательны. Следовательно, итоговая сумма не станет меньше 520 и не сможет улучшить результат 500.

Можно остановить внутренний цикл:

```python
def center_sum_early(cluster):
    best_point = cluster[0]
    best_sum = float("inf")

    for candidate in cluster:
        total = 0.0

        for point in cluster:
            total += dist(candidate, point)

            if total >= best_sum:
                break

        if total < best_sum:
            best_sum = total
            best_point = candidate

    return best_point
```

`break` завершает ближайший цикл, внутри которого находится. Здесь — внутренний.

Условие `>=` безопасно, если нас интересует любое улучшение строгого минимума, а равный результат не должен заменять уже найденную точку.

Почему ускорение точное? Потому что мы отбрасываем кандидата только после доказательства, что он уже не может улучшить ответ.

Это отличается от предположения «точка выглядит слишком далёкой, поэтому проверять её не будем».

Такое ускорение не меняет худший квадратичный порядок работы и не обязано давать одинаковый выигрыш на любых данных.

Парный подсчёт и досрочное прекращение — два разных способа организации вычислений. Не нужно пытаться механически вставить один в другой.

---

**Некоторые популярные сокращения поиска не дают гарантии правильного ответа.** Например:

- проверить только несколько ближайших к среднему точек;
- взять случайную часть данных;
- округлить координаты перед поиском центра;
- проверять каждую десятую строку;
- найти приблизительный центр на рисунке и взять ближайшую точку.

Такие способы могут оказаться полезными для предварительного анализа, но как окончательное решение требуют отдельного доказательства.

Если правильный центр не попал в рассмотренную часть точек, программа его уже не найдёт.

Для построения чернового рисунка иногда можно показать часть очень большого набора. Для окончательного поиска центра по условию обычно нужны все соответствующие точки.

Метод `k-means`, который тоже встречается в материалах о кластеризации, работает с другой постановкой и использует средние координаты. Его результат нельзя автоматически считать ответом на задачу о точке кластера с минимальной суммой обычных расстояний.

Тебе важнее научиться переводить определение из условия в вычисление, чем запоминать названия методов.

---

**После нахождения центров начинается отдельная часть задачи: вычисление ответа.** Её легко недооценить.

Даже идеально найденные центры не помогут, если затем усреднить не те координаты или посчитать расстояние между не теми объектами.

Сначала познакомимся с короткой записью перебора, которая часто встречается в решениях:

```python
xs = [point[0] for point in centers]
```

Она означает:

> Для каждой точки из `centers` взять первую координату и собрать результаты в список.

Равносильная длинная запись:

```python
xs = []

for point in centers:
    xs.append(point[0])
```

А выражение:

```python
sum(point[0] for point in centers)
```

последовательно передаёт координаты функции `sum`, которая их складывает.

По такому же принципу:

```python
min(point[0] for point in centers)
max(point[1] for point in centers)
```

находят минимальную координату `x` и максимальную координату `y`.

Теперь разберём основные варианты.

**Если нужно среднее арифметическое координат центров, каждый центр учитывается один раз.**

Пусть центры:

\[
C_1=(x_1,y_1),\ldots,C_k=(x_k,y_k).
\]

Тогда:

\[
P_x=\frac{x_1+\ldots+x_k}{k};
\]

\[
P_y=\frac{y_1+\ldots+y_k}{k}.
\]

Код:

```python
px = sum(center[0] for center in centers) / len(centers)
py = sum(center[1] for center in centers) / len(centers)
```

Если один кластер содержит 100 точек, а другой — 5000, их центры всё равно имеют одинаковый вес, когда условие требует именно среднее **центров**.

Не нужно усреднять все точки файла или дополнительно умножать координаты центра на размер его кластера.

---

**Если нужны минимальные координаты центров, минимумы ищутся независимо.**

```python
px = min(center[0] for center in centers)
py = min(center[1] for center in centers)
```

Например, центры:

\[
(-4,10),\qquad(6,2).
\]

Минимальная абсцисса:

\[
-4.
\]

Минимальная ордината:

\[
2.
\]

Пара результата:

\[
(-4,2).
\]

Она не совпадает ни с одним центром. Это нормально: условие просит две отдельные характеристики.

---

**Если нужно сравнить самый маленький и самый большой кластеры, сначала сохраняем связь между кластером и его центром.**

Удобно упорядочить кластеры по числу точек:

```python
clusters = sorted(clusters, key=len)
```

`sorted` создаёт новый упорядоченный список.

`key=len` означает: сравнивать элементы по их длинам. Поскольку каждый элемент — кластер, его длина равна числу точек.

Обрати внимание: передаётся сама функция `len`, без скобок. Мы сообщаем, каким способом получать величину для сравнения.

Теперь:

```python
clusters[0]   # самый маленький
clusters[-1]  # самый большой
```

Индекс `-1` означает последний элемент.

После этого найдём центры в том же порядке:

```python
centers = []

for cluster in clusters:
    centers.append(center_sum(cluster))
```

Расстояние между центрами крайнего по размеру малого и большого кластеров:

```python
answer = dist(centers[0], centers[-1])
```

Если центры были вычислены до сортировки кластеров, а затем переставили только кластеры, соответствие может нарушиться.

Также нужно проверить, гарантирует ли условие однозначность выбора при одинаковых размерах.

---

**Расстояние от центра до точки своего кластера и расстояние до точки другого кластера — разные вычисления.**

Максимальное расстояние от центра малого кластера до точки большого:

```python
small_center = centers[0]
big_cluster = clusters[-1]

answer = max(
    dist(small_center, point)
    for point in big_cluster
)
```

Максимальное расстояние от любого центра до точки **его собственного** кластера:

```python
answer = 0.0

for i in range(len(clusters)):
    center = centers[i]

    for point in clusters[i]:
        answer = max(answer, dist(center, point))
```

Функция `max(a, b)` возвращает большее из двух чисел.

Центры уже вычислены. Внутри этого цикла их не нужно искать повторно.

Особенно опасна конструкция вида:

```python
# Неудачная организация вычислений:
max(dist(center_sum(cluster), point) for point in cluster)
```

Она снова вызывает поиск центра для каждой точки. То, что можно было сделать один раз, повторяется много раз.

Сначала:

```python
center = center_sum(cluster)
```

И только затем:

```python
radius = max(dist(center, point) for point in cluster)
```

---

**Диаметр кластера — обычно максимальное расстояние между двумя его точками.** Но окончательное определение, как всегда, берём из условия.

\[
D=\max_{A,B\in C}d(A,B).
\]

Здесь запись \(A,B\in C\) означает: обе точки принадлежат кластеру \(C\).

Диаметр не обязан совпадать с расстоянием от выбранного центра до самой далёкой точки.

Если известен центр и его радиус \(R\), то диаметр не больше \(2R\), но равенство выполняется не всегда. Поэтому автоматически писать `diameter = 2 * radius` нельзя.

Для перебора пар одного кластера:

```python
diameter = 0.0

for i in range(len(cluster)):
    for j in range(i + 1, len(cluster)):
        diameter = max(
            diameter,
            dist(cluster[i], cluster[j])
        )
```

Если требуется не только расстояние, но и координаты точек, образующих диаметр, нужно запоминать найденную пару.

---

**Для межкластерного диаметра берут по одной точке из двух разных кластеров.** В № 87445 он определяется как наибольшее расстояние между такими точками, причём дальнейшие вычисления зависят и от самих концов этого отрезка. [inf-ege.sdamgia.ru](https://inf-ege.sdamgia.ru/test?theme=428\&ttest=true\&utm_source=chatgpt.com)

Код:

```python
def farthest_pair(cluster1, cluster2):
    best_distance = -1.0
    best_pair = None

    for point1 in cluster1:
        for point2 in cluster2:
            d = dist(point1, point2)

            if d > best_distance:
                best_distance = d
                best_pair = (point1, point2)

    return best_distance, best_pair
```

`None` — специальное значение, означающее, что результат пока не установлен.

Оба кластера здесь предполагаются непустыми, поэтому пара обязательно будет найдена.

Применение:

```python
diameter, pair = farthest_pair(cluster1, cluster2)
point1, point2 = pair
```

Теперь можно вычислить, например:

```python
x_difference = abs(point1[0] - point2[0])
y_sum = point1[1] + point2[1]
```

Если требуется минимальное расстояние между кластерами, организация похожая, но начальное значение — положительная бесконечность, а сравнение — `<`.

**Расстояние между центрами не заменяет расстояния между крайними или ближайшими точками кластеров.**

И ещё: когда нужно найти минимальное расстояние между **различными** точками одного кластера, нельзя включать пару точки с самой собой. Иначе минимум всегда получится нулевым.

Для различения записей надёжнее использовать разные индексы. Проверка `point1 != point2` исключит также разные записи с одинаковыми координатами.

---

**При подсчёте точек около центра нужно точно определить, какие точки разрешено учитывать.**

Например, число точек на расстоянии не больше `r`:

```python
count = 0

for point in points:
    if dist(center, point) <= r:
        count += 1
```

Фраза «на плоскости» может означать все допустимые точки файла.

Фраза «этого кластера» — только точки соответствующего кластера:

```python
for point in cluster:
    ...
```

Нельзя менять область перебора по привычке.

Слова в условии переводятся так:

| Формулировка | Проверка |
|---|---|
| Меньше `r` | `< r` |
| Не больше `r` | `<= r` |
| Больше `r` | `> r` |
| Не меньше `r` | `>= r` |

Если центр является одной из перебираемых точек, его расстояние до себя равно нулю. При условии `<= r` и неотрицательном `r` он будет посчитан.

Это правильно, если условие включает центр. Если требуется считать только остальные точки, его нужно исключить как конкретную запись.

---

**Дополнительные столбцы не нужно смешивать с координатами.** В некоторых вариантах у объекта кроме положения есть тип, категория или другой признак.

Например:

```text
1.25 3.70 red
2.80 4.10 blue
```

Третий столбец здесь — текстовая характеристика, а не третья пространственная координата.

Её можно сохранить:

```python
parts = line.replace(",", ".").split()

x = float(parts[0])
y = float(parts[1])
kind = parts[2]

record = (x, y, kind)
```

Для расстояния использовать только координаты:

```python
dist(record1[:2], record2[:2])
```

Срез `[:2]` берёт первые два элемента.

А для подсчёта объектов нужной категории:

```python
count = 0

for record in cluster:
    if record[2] == "red":
        count += 1
```

Кластеризацию по расположению, поиск центра и последующий подсчёт объектов определённого типа нужно выполнять в том порядке, который задан условием.

Если кластер выбирается по количеству объектов некоторого вида, это не то же самое, что выбор по общему количеству точек.

---

**Теперь об исключении целых кластеров.** Если условие требует удалить самый маленький кластер, это отдельное действие после правильного разделения.

При гарантии единственности самого маленького:

```python
clusters = sorted(clusters, key=len)
clusters = clusters[1:]
```

Срез `[1:]` берёт все элементы, начиная со второго.

После исключения вычисляем нужные характеристики оставшихся кластеров.

Если требуется удалить самый большой:

```python
clusters = sorted(clusters, key=len)
clusters = clusters[:-1]
```

Срез `[:-1]` берёт все элементы, кроме последнего.

Важно не спутать:

- удалить один кластер с минимальным размером;
- удалить все кластеры минимального размера;
- удалить все кластеры, в которых меньше заданного числа точек.

Это разные правила.

И после удаления нужно делить среднее на **новое** количество кластеров:

```python
average_radius = sum(radii) / len(radii)
```

а не на исходное число групп.

---

**Последний этап — масштабирование и получение целого числа.** Пусть по условию нужно вывести целую часть произведения результата на 10 000.

Для неотрицательного `value`:

```python
answer = int(value * 10000)
```

Например:

\[
value=2.718281.
\]

Тогда:

\[
value\cdot10000=27182.81,
\]

и ответ:

\[
27182.
\]

Здесь нельзя заменять `int` на `round`.

```python
int(2.9)    # 2
round(2.9)  # 3
```

**При отрицательных значениях нужно понимать поведение Python.** `int` отбрасывает дробную часть в направлении нуля:

```python
int(-2.9)  # -2
```

А округление вниз даёт:

```python
from math import floor

floor(-2.9)  # -3
```

Поведение `int` прямо описано в документации Python. Если условие допускает отрицательный итог, нужно внимательно различать отбрасывание дробной части и требование округления вниз. [Python 3.14.8 documentation](https://docs.python.org/3/library/functions.html?utm_source=chatgpt.com)

Если требуется модуль:

```python
answer = int(abs(value) * 10000)
```

Но модуль нужно брать **именно на том шаге, который указан в условии**.

Например, абсциссы центров:

\[
-6,\quad4.
\]

Модуль среднего:

\[
\left|\frac{-6+4}{2}\right|=1.
\]

Среднее модулей:

\[
\frac{|-6|+|4|}{2}=5.
\]

Это разные ответы.

Аналогично:

```python
abs(min(values))
```

и:

```python
min(abs(value) for value in values)
```

неравнозначны.

Для `values = [-8, 3]` первое даёт 8, второе — 3.

Также не нужно округлять каждый центр перед усреднением. Сначала выполняются требуемые вычисления с исходными координатами, затем преобразуется конечный результат.

Множитель тоже нельзя заучивать: в конкретной задаче могут требоваться 100, 1000, 10 000 или разные множители для разных величин.

---

**У дробных вычислений есть ещё одна особенность: `float` хранит многие десятичные числа приближённо.** Например, математически целое произведение иногда может оказаться в памяти чуть меньше или чуть больше целого.

Поэтому полезно помнить:

- не округлять координаты заранее;
- не добавлять произвольное `0.0001` «для надёжности»;
- при подозрительно близком к целому итоговом значении проверить вычисления с большей точностью;
- при почти равных суммах кандидатов отдельно проверить, действительно ли их различие устойчиво.

Функция `math.fsum` может уменьшить ошибку суммирования:

```python
from math import dist, fsum

total = fsum(
    dist(candidate, point)
    for point in cluster
)
```

Но это не превращает все вычисления с `float` в абсолютно точные.

Для обычного первоначального решения достаточно понять алгоритм и использовать исходные значения без лишнего округления. Повышенную точность имеет смысл подключать при конкретном обнаруженном пограничном случае.

**Соберём полноценный небольшой пример от файла до ответа.** Пусть файл `example27.txt` содержит:

```text
X Y
0 0
0 2
1 1
2 0
2 2
10 0
12 0
11 1
```

Условие нашего учебного примера:

- точки образуют два кластера;
- первый расположен левее `x = 5`, второй — правее;
- центр — исходная точка с минимальной суммой расстояний;
- нужно найти средние координаты двух центров;
- вывести целые части этих средних, умноженных на 10 000.

Полная программа:

```python
from math import dist


def read_points(filename):
    points = []

    with open(filename, encoding="utf-8-sig") as f:
        f.readline()  # В нашем файле есть заголовок X Y

        for line in f:
            if not line.strip():
                continue

            sx, sy = line.replace(",", ".").split()

            x = float(sx)
            y = float(sy)

            points.append((x, y))

    return points


def center_sum(cluster):
    best_point = cluster[0]
    best_sum = float("inf")

    for candidate in cluster:
        total = 0.0

        for point in cluster:
            total += dist(candidate, point)

        if total < best_sum:
            best_sum = total
            best_point = candidate

    return best_point


points = read_points("example27.txt")

clusters = [[], []]

for point in points:
    x, y = point

    if x < 5:
        clusters[0].append(point)
    else:
        clusters[1].append(point)

centers = []

for cluster in clusters:
    centers.append(center_sum(cluster))

sum_x = 0.0
sum_y = 0.0

for x, y in centers:
    sum_x += x
    sum_y += y

px = sum_x / len(centers)
py = sum_y / len(centers)

print(int(px * 10000), int(py * 10000))
```

Проверим вручную.

Первый кластер:

```text
(0, 0)
(0, 2)
(1, 1)
(2, 0)
(2, 2)
```

Его центр:

\[
(1,1).
\]

Расстояния от него до четырёх углов одинаковы и равны \(\sqrt2\):

\[
S=4\sqrt2\approx5.657.
\]

Для любого угла сумма:

\[
2+2+2\sqrt2+\sqrt2
=
4+3\sqrt2
\approx8.243.
\]

Значит, `(1, 1)` действительно лучше.

Второй кластер:

```text
(10, 0)
(12, 0)
(11, 1)
```

Для `(11, 1)`:

\[
S=\sqrt2+\sqrt2=2\sqrt2.
\]

Для каждой из двух других точек:

\[
S=2+\sqrt2.
\]

Поскольку:

\[
2\sqrt2<2+\sqrt2,
\]

центр второго кластера:

\[
(11,1).
\]

Средние координаты:

\[
P_x=\frac{1+11}{2}=6;
\]

\[
P_y=\frac{1+1}{2}=1.
\]

Ответ программы:

```text
60000 10000
```

В этом же примере можно вместо границы `x = 5` использовать:

```python
clusters = split_clusters(points, eps=1.5)
```

У каждой группы точки соединяются через расстояния \(\sqrt2<1.5\), а между группами нет близких пар.

Но значения `5` и `1.5` подходят **именно этому примеру**.

Такое описание сразу выявляет места, в которых нельзя использовать старый шаблон без изменений.

| Что выяснить | Какой ответ нужен |

| Как определяется расстояние? | Конкретная формула |
| Что вычисляется после центров? | Среднее, минимум координат, расстояния, количество |

**Файлы А и Б нужно читать как два отдельных набора требований.** В некоторых задачах для них различается не только объём данных, но и сами запрашиваемые величины. Например, в № 81811 для А нужны минимальные координаты центров, а для Б — характеристики расстояний. [inf-ege.sdamgia.ru](https://inf-ege.sdamgia.ru/problem?id=81811\&utm_source=chatgpt.com)

Не переноси формулу ответа для А на Б автоматически.

**Проверять нужно не только напечатанные числа, но и промежуточный смысл результата.**

После чтения:

```python
print("Точек:", len(points))
print(points[:5])
```

После разделения:

```python
print("Кластеров:", len(clusters))

for cluster in clusters:
    print("Размер:", len(cluster))
```

После нахождения центров:

```python
for center in centers:
    print("Центр:", center)
```

Если все точки должны быть распределены и аномалий нет:

```python
assigned = sum(len(cluster) for cluster in clusters)

print("Прочитано:", len(points))
print("Распределено:", assigned)
```

Если есть `noise`:

```python
assigned = sum(len(cluster) for cluster in clusters)

print(assigned + len(noise), len(points))
```

Совпадение количества — необходимая проверка, но само по себе не доказывает правильность: одну точку можно потерять, а другую случайно учесть дважды.

Нужно также проверить сам способ распределения.

Для выбранного центра:

- он должен принадлежать своему кластеру, если это требуется условием;
- его координаты должны соответствовать области кластера;
- он должен вычисляться по правильному критерию.

Удобно нарисовать выделенные кластеры разными цветами, а найденные центры — более крупными маркерами:

```python
import matplotlib.pyplot as plt

for cluster in clusters:
    xs = [point[0] for point in cluster]
    ys = [point[1] for point in cluster]

    plt.scatter(xs, ys, s=3)

cx = [point[0] for point in centers]
cy = [point[1] for point in centers]

plt.scatter(cx, cy, s=100, marker="x", color="black")

plt.axis("equal")
plt.grid()
plt.show()
```

Рисунок помогает заметить ошибку, но не заменяет вычисление критерия. Необычно расположенный центр не обязательно неправильный, особенно у вытянутой или несимметричной группы.

**Частые ошибки можно связать с тем этапом, на котором они возникают.**

| Ошибка | Почему получается неверно |
|---|---|
| Пропустить первую строку без проверки | Можно потерять первую точку |
| Читать дробные координаты как `int` | Формат не подходит или теряется нужная точность при дополнительном преобразовании |
| Не заменить десятичную запятую | `float` не сможет прочитать число |
| Взять границы из чужого решения | Они относятся к другому файлу |
| Включить всё оставшееся в последний кластер | Туда могут попасть аномалии |
| Найти соседей только первой точки | Не будет пройдена вся цепочка |
| Использовать слишком большой порог | Разные группы могут соединиться |
| Принять среднее за центр по сумме расстояний | Это разные задачи |
| Убрать корни в сумме расстояний | Получится сумма квадратов |
| Не обнулять сумму для нового кандидата | Суммы кандидатов смешаются |
| Считать расстояния до всего файла | Вместо своего кластера учитываются чужие точки |
| Переставить кластеры, но не центры | Нарушится соответствие |
| Искать центр внутри цикла по точкам повторно | Время работы резко увеличится |
| Забыть изменить число групп после исключения | Среднее делится на неправильное число |
| Взять модуль до усреднения или до минимума | Изменится математическое выражение |
| Использовать `round` вместо требуемой целой части | Получится другое целое |
| Удалить повторы через `set` | Может измениться смысл исходных наблюдений |

Полезно также проверять имя файла: латинская `A` и кириллическая `А` выглядят почти одинаково, но для компьютера это разные символы.
