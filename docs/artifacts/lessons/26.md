**1. Начинать решение нужно с того, что представляет собой один объект.**

В условии почти всегда описаны какие-то объекты:

- файлы;
- товары;
- участники;
- мероприятия;
- заявки;
- места;
- грузы.

У каждого объекта есть характеристики.

Например:

| Объект | Его характеристики |
|---|---|
| Файл | Размер |
| Товар | Цена, тип |
| Мероприятие | Время начала, время окончания |
| Участник | Идентификатор, баллы, штраф |
| Занятое место | Номер ряда, номер места |

В программе сведения об одном объекте удобно хранить вместе. Такую совокупность сведений будем называть **записью**.

Например:

```python
meeting = (120, 180)
```

Это одна запись о мероприятии:

- началось на 120-й минуте;
- закончилось на 180-й минуте.

Здесь используется **кортеж** — несколько значений, объединённых в одну последовательность. В отличие от списка, отдельные элементы кортежа нельзя заменить присваиванием. Для неизменяемой записи это удобно.

Список мероприятий:

```python
meetings = [
    (120, 180),
    (50, 90),
    (200, 240)
]
```

Важно сохранять связь между характеристиками.

Если отдельно отсортировать начала мероприятий и отдельно окончания, могут получиться пары, которых в исходных данных вообще не было.

**Сортировать нужно целые записи, если их поля относятся к одному объекту.**

Исключение — условие прямо говорит о двух независимых наборах. Например, массы грузов и вместимости контейнеров могут быть двумя отдельными списками, несмотря на то что записаны в одних строках.

**2. Из условия нужно выписать ограничения, цель и порядок приоритетов.**

Эти три вещи определяют алгоритм.

**Ограничение** — правило, которое нельзя нарушать.

Например:

\[
\text{суммарный размер файлов} \le \text{вместимость диска}.
\]

**Цель** — величина, которую нужно сделать как можно больше или как можно меньше.

Например:

\[
\text{количество сохранённых файлов} \longrightarrow \max.
\]

Вариант, удовлетворяющий ограничениям, называется **допустимым**. Лучший допустимый вариант по указанному критерию называется **оптимальным**.

Рассмотрим условие:

> Сохранить максимальное количество файлов. Среди таких вариантов найти максимально возможный размер самого большого сохранённого файла.

Здесь два последовательных требования:

1. Сначала максимизируем количество.
2. Затем, сохраняя это количество, максимизируем размер одного файла.

Пусть существуют варианты:

| Вариант | Количество файлов | Самый большой файл |
|---|---:|---:|
| А | 6 | 30 |
| Б | 6 | 45 |
| В | 5 | 100 |

Лучший вариант — **Б**.

Вариант В проигрывает по первому, более важному критерию.

Такое сравнение называют **лексикографическим**: сначала сравнивают первый показатель, при равенстве — второй, затем третий и так далее.

Термин связан со сравнением слов в словаре: сначала первая буква, при равенстве — следующая.

Для любой задачи полезно заранее заполнить такую таблицу:

| Вопрос | Что нужно выяснить |
|---|---|
| Что является объектом? | Файл, товар, заявка… |
| Какие у него характеристики? | Размер, цена, время… |
| Можно ли менять порядок? | Или порядок задан условием? |
| Что нельзя нарушать? | Вместимость, совместимость, сроки… |
| Что оптимизируем первым? | Количество, стоимость, длину… |
| Что оптимизируем при равенстве? | Размер, номер, остаток… |
| Что именно выводим? | Количество, значение, ID, позицию… |

**Порядок чисел в ответе и порядок критериев — разные вещи.**

В задаче могут сначала требовать максимального общего количества товаров, но в ответ просить количество товаров типа А и остаток денег.

**5. Чтение файла нужно строить по его фактическому формату.**

Допустим, файл содержит:

```text
6
8
12
15
19
22
34
```

Первая строка — количество чисел.

Понятный вариант чтения:

```python
with open("26.txt") as f:
    n = int(f.readline())

    a = []

    for i in range(n):
        x = int(f.readline())
        a.append(x)
```

Разберём действия.

```python
open("26.txt")
```

Открывает файл. Такой путь означает, что файл ищется относительно рабочей папки запуска программы.

```python
with ... as f:
```

Позволяет работать с файлом через имя `f` и автоматически закрывает его после выхода из блока.

```python
f.readline()
```

Читает одну очередную строку.

Из файла поступает текст:

```python
"6\n"
```

`int(...)` преобразует текстовую запись числа в целое число. Завершающий перевод строки этому не мешает.

После чтения первой строки файл уже находится на следующей строке. Повторное чтение продолжает работу с текущего места.

Если первая строка содержит два числа:

```text
60 6
```

И по условию это вместимость и количество объектов:

```python
with open("26.txt") as f:
    s, n = map(int, f.readline().split())
```

Выражение:

```python
f.readline().split()
```

Разбивает строку по пробельным символам:

```python
["60", "6"]
```

`map(int, ...)` применяет преобразование `int` к каждой части.

Присваивание:

```python
s, n = ...
```

Раскладывает два полученных значения по двум переменным.

Если дальше идут пары:

```text
120 180
50 90
200 240
```

Читаем записи целиком:

```python
with open("26.txt") as f:
    n = int(f.readline())

    meetings = []

    for i in range(n):
        start, finish = map(int, f.readline().split())
        meetings.append((start, finish))
```

Если строка содержит число и букву:

```text
120 A
```

Нельзя преобразовывать обе части в `int`.

```python
price_text, kind = f.readline().split()

price = int(price_text)
```

Здесь `kind` останется строкой `"A"`.

Есть и сокращённая запись чтения списка:

```python
a = [int(f.readline()) for i in range(n)]
```

Конструкция `[выражение for ...]` создаёт список результатов выполнения выражения. Она называется **списковым включением**.

Она делает то же самое, что цикл с `append`. Для понимания задачи вполне можно пользоваться обычным циклом.

**Не существует универсального заголовка файла для задания 26.** Где-то записаны `S N`, где-то `N S`, где-то `K` и `N` находятся в разных строках. Сначала читаем описание формата.

**6. Сортировка полезна тем, что создаёт порядок, на который можно опереться в рассуждении.**

Пусть:

```python
a = [19, 8, 22, 12, 15]
```

После:

```python
a.sort()
```

Получим:

```python
[8, 12, 15, 19, 22]
```

Теперь известно:

> Любое следующее число не меньше предыдущего.

Поэтому, например, если очередной файл уже не помещается в оставшееся место, все следующие, ещё более крупные файлы тоже не поместятся.

Для убывания:

```python
a.sort(reverse=True)
```

Различие двух способов:

```python
a.sort()
```

Меняет существующий список.

```python
b = sorted(a)
```

Создаёт новый отсортированный список.

Запись:

```python
a = a.sort()
```

Ошибочна: метод `sort()` возвращает `None`, и переменная `a` потеряет ссылку на список.

Python также позволяет задавать правило сравнения через параметр `key`; при равных ключах исходный взаимный порядок элементов сохраняется. Такое свойство называется устойчивостью сортировки. [Python 3.14.8 documentation](https://docs.python.org/3/howto/sorting.html?utm_source=chatgpt.com)

Для пар обычная сортировка работает по очереди:

```python
records = [(3, 8), (1, 9), (3, 2)]
records.sort()
```

Результат:

```python
[(1, 9), (3, 2), (3, 8)]
```

Сначала сравниваются первые числа. Вторые участвуют только при равенстве первых.

Если нужно сортировать по второму числу, зададим функцию:

```python
def second_value(record):
    return record[1]

records.sort(key=second_value)
```

`def` создаёт функцию — именованный фрагмент программы.

`record` — входное значение функции.

`return` возвращает результат её работы.

Здесь функция говорит:

> Для сравнения этой записи используй её второй элемент.

Короткая равнозначная запись:

```python
records.sort(key=lambda record: record[1])
```

`lambda` создаёт небольшую функцию без отдельного имени:

- перед двоеточием — входное значение;
- после двоеточия — возвращаемое выражение.

В дальнейшем такая запись будет встречаться часто.

Если нужны разные направления сортировки, используем несколько показателей.

Например, запись:

```python
(student_id, score, penalty)
```

Правила:

1. Баллы — по убыванию.
2. Штраф — по возрастанию.
3. ID — по возрастанию.

```python
students.sort(
    key=lambda x: (-x[1], x[2], x[0])
)
```

Почему перед баллами минус?

Потому что:

\[
95>80,\qquad -95<-80.
\]

Обычная сортировка по возрастанию поставит `-95` раньше `-80`. Значит, участник с 95 баллами окажется раньше участника с 80.

**`reverse=True` переворачивает порядок всего ключа.** Если направления полей различаются, удобнее менять знак у конкретных числовых показателей.

**7. До написания алгоритма нужно оценить, сколько работы он выполнит.**

Обозначим количество объектов буквой \(N\).

Один проход по всем объектам выполняет примерно \(N\) действий:

```python
for x in a:
    ...
```

Проход по всем парам:

```python
for i in range(n):
    for j in range(i + 1, n):
        ...
```

Рассматривает:

\[
\frac{N(N-1)}2
\]

пар.

При \(N=100\,000\) это почти пять миллиардов.

Для описания роста объёма работы используют обозначение **\(O(\ldots)\)**:

| Обозначение | Как растёт работа |
|---|---|
| \(O(1)\) | Не зависит от количества объектов |
| \(O(N)\) | Примерно пропорционально количеству объектов |
| \(O(N\log N)\) | Типичный порядок затрат на эффективную сортировку |
| \(O(N^2)\) | Примерно пропорционально квадрату количества объектов |

Логарифм \(\log_2 N\) здесь можно понимать как число последовательных делений размера примерно пополам, необходимых, чтобы дойти до единицы.

Для \(100\,000\) это около 17.

Поэтому масштабы \(N\log N\) и \(N^2\) очень разные:

\[
100\,000\cdot17 \approx 1\,700\,000,
\]

\[
100\,000^2=10\,000\,000\,000.
\]

Это сравнение порядка величин, а не точный прогноз времени работы.

Обращай внимание и на память.

Если координаты не превышают \(100\,000\), это ещё не означает, что нужно создавать таблицу:

\[
100\,000\times100\,000.
\]

В ней десять миллиардов ячеек.

Если во входном файле всего несколько тысяч отмеченных точек, достаточно хранить только эти точки.

**8. Жадный алгоритм делает последовательные выборы, каждый раз используя локальное правило.**

Например:

> Из оставшихся подходящих мероприятий выбираем то, которое раньше закончится.

Такой алгоритм называется **жадным**.

Слово «жадный» не означает «всегда берёт самое большое». Он может выбирать:

- самый маленький размер;
- самое раннее окончание;
- наибольшую допустимую коробку;
- наиболее дешёвый подходящий объект.

Главный вопрос:

> Почему этот выбор не лишит нас лучшего итогового решения?

Одного ощущения «так выгоднее» недостаточно.

Полезны два способа объяснения.

**Первый: выбранный объект оставляет не меньше возможностей.**

Если мероприятие заканчивается раньше, после него доступно не меньше будущих мероприятий.

**Второй: можно заменить чужой выбор нашим и не ухудшить результат.**

Если в некотором оптимальном наборе взят дорогой товар, а более дешёвый равноценный по условиям товар не взят, можно выполнить замену. Количество сохранится, затраты не увеличатся.

Такое рассуждение называют **доказательством обменом**.

Важно учитывать всю формулировку.

Например, при вместимости 10 и размерах:

```text
4 5 6
```

Выбор самых маленьких даёт два объекта `4 + 5`.

Это правильно для максимального количества.

Но максимально возможная сумма равна:

```text
4 + 6 = 10
```

**Максимальное количество, максимальная сумма и максимальный отдельный элемент — разные цели.**

**9. В задачах на максимальное количество объектов при ограниченной сумме нужно начинать с самых маленьких.**

Пусть вместимость:

```text
60
```

Размеры файлов:

```text
8 12 15 19 22 34
```

После сортировки последовательно набираем:

| Файл | Сумма после добавления | Помещается? |
|---:|---:|---|
| 8 | 8 | Да |
| 12 | 20 | Да |
| 15 | 35 | Да |
| 19 | 54 | Да |
| 22 | 76 | Нет |

Получили четыре файла.

Почему пять сохранить невозможно?

Потому что пять самых маленьких файлов имеют сумму:

\[
8+12+15+19+22=76>60.
\]

Любые другие пять файлов будут иметь не меньшую сумму.

Можно записать рассуждение формально.

Пусть отсортированные размеры:

\[
a_1\le a_2\le\ldots\le a_N.
\]

У любого выбранного набора из \(k\) файлов после его собственной сортировки:

\[
b_1\le b_2\le\ldots\le b_k.
\]

Обязательно:

\[
b_1\ge a_1,\quad b_2\ge a_2,\quad \ldots,\quad b_k\ge a_k.
\]

Ведь \(a_i\) — \(i\)-е наименьшее значение среди всех файлов.

Следовательно:

\[
b_1+\ldots+b_k\ge a_1+\ldots+a_k.
\]

То есть **первые \(k\) элементов имеют минимальную возможную сумму среди всех наборов из \(k\) элементов**.

Код:

```python
a.sort()

used = 0
count = 0

for size in a:
    if used + size > capacity:
        break

    used += size
    count += 1
```

Здесь:

- `used` — уже занятый объём;
- `count` — количество выбранных файлов.

Проверяем возможность добавления **до** изменения суммы.

Почему разрешён `break`?

Потому что список отсортирован по возрастанию. Если текущий файл не помещается, следующие ещё крупнее.

Без сортировки такой выход из цикла мог бы пропустить маленький файл в конце списка.

**10. Второе условие про самый большой файл требует отдельного шага.**

Продолжим пример:

```text
Вместимость: 60
Файлы: 8 12 15 19 22 34
```

Максимальное количество равно четырём.

Первоначально выбраны:

```text
8 12 15 19
```

Но наибольший допустимый файл среди оптимальных наборов — **22**:

```text
8 12 15 22
```

Сумма:

\[
8+12+15+22=57.
\]

Как получить это системно?

Зафиксируем три самых маленьких файла:

```text
8 12 15
```

Они занимают:

\[
35.
\]

Для четвёртого остаётся:

\[
60-35=25.
\]

Из имеющихся оставшихся файлов выбираем максимальный размер, не превышающий 25. Это 22.

Почему можно зафиксировать именно \(k-1\) самых маленьких?

Потому что они оставляют максимально возможное место для ещё одного файла.

Если некоторый файл \(x\) нельзя разместить даже вместе с \(k-1\) самыми маленькими файлами, то с любыми другими \(k-1\) файлами он тем более не поместится.

Полный код для формата `S N` в первой строке:

```python
with open("26.txt") as f:
    capacity, n = map(int, f.readline().split())

    a = []

    for i in range(n):
        a.append(int(f.readline()))

a.sort()

used = 0
count = 0

for size in a:
    if used + size > capacity:
        break

    used += size
    count += 1

if count == 0:
    largest = 0
else:
    fixed_sum = used - a[count - 1]
    limit = capacity - fixed_sum

    largest = a[count - 1]

    for size in a[count - 1:]:
        if size > limit:
            break

        largest = size

print(count, largest)
```

Объяснение выражения:

```python
used - a[count - 1]
```

`used` — сумма первых `count` файлов.

`a[count - 1]` — последний из них.

Вычитая его, получаем сумму первых `count - 1` файлов.

Перебор начинается с:

```python
a[count - 1:]
```

Таким образом, зафиксированные первые `count - 1` объектов не используются повторно.

Значение `0` в ветке `count == 0` — условная обработка отсутствия сохранённых файлов. В конкретной задаче нужно учитывать, что сказано о существовании решения и формате ответа для такого случая.

**Этот приём максимизирует один файл. Он не является универсальным способом максимизации общей суммы выбранного набора.**

**11. Если среди покупок есть разные типы, удобно отдельно рассмотреть количество объектов каждого типа.**

В подборке есть задачи с тремя приоритетами: купить максимальное общее количество изделий, затем максимальное количество изделий типа А, затем потратить минимальную сумму. [inf-ege.sdamgia.ru](https://inf-ege.sdamgia.ru/problem?id=38960\&utm_source=chatgpt.com)

Разберём собственный пример:

```text
Бюджет: 36

Тип A: 4 9 14
Тип B: 3 5 6 10
```

Сначала определим максимальное общее количество.

Все цены:

```text
3 4 5 6 9 10 14
```

Пять самых дешёвых стоят:

\[
3+4+5+6+9=27.
\]

Шесть стоят:

\[
27+10=37>36.
\]

Значит, нужно купить ровно пять изделий.

Теперь спрашиваем:

> Сколько из этих пяти может быть изделий А?

Если берём \(x\) изделий А, изделий В должно быть:

\[
5-x.
\]

Для фиксированного \(x\) самая дешёвая покупка состоит из:

- \(x\) самых дешёвых А;
- \(5-x\) самых дешёвых В.

Значит, достаточно быстро находить суммы первых нескольких элементов.

Для этого построим **накопленные суммы**, которые также называют **префиксными суммами**.

Слово «префикс» здесь означает начальный участок последовательности.

Для:

```text
A = 4 9 14
```

Получим:

```text
PA = 0 4 13 27
```

Смысл:

- `PA[0]` — стоимость нуля изделий;
- `PA[1]` — стоимость одного самого дешёвого;
- `PA[2]` — стоимость двух самых дешёвых;
- `PA[3]` — стоимость трёх.

Построение:

```python
prefix_a = [0]

for price in a:
    prefix_a.append(prefix_a[-1] + price)
```

Каждая следующая накопленная сумма равна предыдущей плюс очередная цена.

Для В:

```text
PB = 0 3 8 14 24
```

Проверяем состав покупки:

| Количество А | Количество В | Минимальная стоимость | Подходит? |
|---:|---:|---:|---|
| 1 | 4 | 4 + 24 = 28 | Да |
| 2 | 3 | 13 + 14 = 27 | Да |
| 3 | 2 | 27 + 8 = 35 | Да |

Выбираем три А и два В. Остаток равен 1.

Код основной части:

```python
a.sort()
b.sort()

all_prices = sorted(a + b)

count = 0
spent = 0

for price in all_prices:
    if spent + price > budget:
        break

    spent += price
    count += 1

prefix_a = [0]
for price in a:
    prefix_a.append(prefix_a[-1] + price)

prefix_b = [0]
for price in b:
    prefix_b.append(prefix_b[-1] + price)

best_a = 0
best_cost = 0

for count_a in range(count + 1):
    count_b = count - count_a

    if count_a > len(a) or count_b > len(b):
        continue

    cost = prefix_a[count_a] + prefix_b[count_b]

    if cost <= budget:
        best_a = count_a
        best_cost = cost

print(best_a, budget - best_cost)
```

Почему можно просто перезаписывать ответ?

Потому что `count_a` перебирается по возрастанию. Каждый следующий подходящий вариант содержит больше А.

Почему выполнено третье условие?

Для каждого фиксированного состава мы уже берём самые дешёвые изделия обоих типов.

Здесь нет перебора всех наборов покупок. Мы перебираем только **количество изделий А**, а наилучший набор с таким количеством строится однозначно по ценам.

**12. В задачах на вложенные коробки выбор должен сохранять место для продолжения цепочки.**

Пусть коробку можно вложить в другую, если её размер меньше хотя бы на 6.

Размеры:

```text
12 18 21 27 34 40 45
```

Требуется:

1. Максимальное количество вложенных коробок.
2. Максимальный возможный размер самой маленькой коробки при таком количестве.

Начнём снаружи.

Самая большая коробка — 45.

В неё можно поместить коробку размером не больше:

\[
45-6=39.
\]

Из подходящих выбираем **самую большую** — 34.

Почему не 12?

Потому что после выбора 12 внутри почти не останется возможностей. Коробка 34 оставляет больше места для последующих вложений.

Далее:

```text
45 → 34 → 27 → 21 → 12
```

Получилось пять коробок.

Код:

```python
sizes.sort(reverse=True)

selected = []

for size in sizes:
    if not selected or selected[-1] - size >= gap:
        selected.append(size)

print(len(selected), selected[-1])
```

Здесь предполагается, что исходный список непустой и `gap > 0`.

Почему алгоритм корректен?

На каждой глубине он выбирает максимально возможный размер:

- первая коробка максимально большая;
- вторая — максимально большая среди помещающихся в первую;
- третья — максимально большая среди помещающихся во вторую.

Можно показать по шагам: \(i\)-я коробка жадной цепочки не меньше \(i\)-й коробки любой другой допустимой цепочки.

Следовательно, если другая цепочка может продолжиться, жадная имеет не меньше возможностей продолжиться.

А среди цепочек максимальной длины последняя выбранная коробка получается максимально большой.

Если второй критерий другой:

> Минимизировать размер самой большой коробки,

удобно строить цепочку **изнутри наружу**:

1. Отсортировать размеры по возрастанию.
2. Начать с самой маленькой.
3. Каждый раз брать наименьшую коробку, которая достаточно больше предыдущей.

Для нашего примера:

```text
12 → 18 → 27 → 34 → 40
```

Пять коробок, внешняя имеет размер 40.

**Направление построения связано и с допустимостью, и со вторым критерием.**

Этот разбор предполагает одинаковый минимальный зазор между соседними коробками и отсутствие дополнительных ограничений. Материалы, цвета и зависимость зазора от номера коробки нужно учитывать отдельно.

**13. Рейтинговые задачи требуют буквально перевести правила сравнения в ключ сортировки.**

Пусть записи имеют вид:

```python
(student_id, score, penalty)
```

Данные:

```python
students = [
    (31, 80, 12),
    (7, 95, 20),
    (19, 95, 12),
    (4, 95, 12)
]
```

Правила:

1. Больше баллов — выше.
2. При равенстве меньше штраф — выше.
3. При полном равенстве меньше ID — выше.

```python
students.sort(
    key=lambda x: (-x[1], x[2], x[0])
)
```

Порядок ID:

```text
4 19 7 31
```

Почему 4 раньше 19?

Баллы и штраф совпадают. Решает третий показатель.

Нужно различать:

- **ID участника** — значение из файла;
- **индекс в списке** — позицию, с которой работает Python;
- **место в рейтинге** — обычно индекс плюс один.

```python
students[2][0]
```

Это ID участника на третьем месте.

Если рейтинг строится по вычисляемым показателям, сначала вычисляем их.

Например:

```python
total = 0
positive = 0
answered = 0

for score in scores:
    total += score

    if score > 0:
        positive += score

    if score != 0:
        answered += 1
```

Здесь:

- `total` — сумма всех баллов;
- `positive` — сумма положительных баллов;
- `answered` — количество ненулевых ответов.

После этого сохраняем все показатели вместе с ID.

Особенно внимательно нужно читать правила около проходной границы.

Две разные формулировки:

> Проходят первые 25 участников рейтинга.

и:

> Проходят все, набравшие не меньше баллов, чем участник на 25-м месте.

Во втором случае пройти может больше 25 человек.

Равенство для прохода иногда определяется только баллами, хотя сам рейтинг дополнительно упорядочен по ID. Эти правила нельзя смешивать.

**14. В задачах на скидки сначала нужно выяснить, какие товары могут получить скидку.**

Фраза «каждый третий товар бесплатно» сама по себе ещё не определяет алгоритм.

Возможны разные правила:

| Правило | Что влияет на решение |
|---|---|
| Можно выбрать любые \(k\) товаров со скидкой | Выгодно выбирать наиболее дорогие подходящие |
| В каждой паре скидка на дешёвый товар | Нужно выгодно составить пары |
| В каждой тройке бесплатно самый дешёвый | Нужно выгодно составить тройки |
| Продавец сам переставляет товары | Нужно учитывать цель продавца |
| Скидка действует только выше порога | Сначала выделяются подходящие товары |

Рассмотрим конкретное правило:

> Все товары нужно купить. Их можно разбить на тройки. В каждой полной тройке самый дешёвый товар бесплатный.

Цены:

```text
100 90 80 70 60 50 40
```

Выгодные тройки:

```text
100 90 80
70 60 50
```

Бесплатно получаем 80 и 50.

Товар 40 покупаем отдельно.

Сумма всех цен:

\[
490.
\]

Стоимость покупки:

\[
490-80-50=360.
\]

Код:

```python
prices.sort(reverse=True)

free_sum = 0

for i in range(2, len(prices), 3):
    free_sum += prices[i]

answer = sum(prices) - free_sum
```

Третий параметр `range` — шаг:

```python
range(2, len(prices), 3)
```

Даёт индексы:

```text
2, 5, 8, 11, ...
```

Почему это оптимально?

Чтобы получить один бесплатный товар некоторой цены, к нему нужны ещё два товара не дешевле.

Значит:

- самый дорогой бесплатный товар не может быть дороже третьего по цене;
- второй по дороговизне бесплатный — дороже шестого;
- третий — дороже девятого.

Разбиение отсортированного списка на соседние тройки достигает этих границ.

Отдельный вопрос — округление.

Пусть скидка 25% применяется к товарам с суммарной исходной ценой `discount_base`.

Тогда точная итоговая стоимость:

\[
T-\frac{D}{4}
=
\frac{4T-D}{4},
\]

где \(T\) — сумма всех исходных цен, \(D\) — сумма цен товаров со скидкой.

Если **всю итоговую сумму** нужно округлить вверх:

```python
numerator = 4 * total - discount_base

answer = (numerator + 3) // 4
```

`//` — целочисленное деление с округлением вниз.

Для неотрицательного целого `x`:

```python
(x + d - 1) // d
```

Округляет дробь \(x/d\) вверх.

Нельзя округлять стоимость каждого товара отдельно, если условие требует округлить только общую сумму.

**15. Для работы с рядами и группами полезны множества и словари.**

Допустим, каждая строка содержит:

```text
номер ряда    номер позиции
```

Сначала нужно собрать позиции отдельно для каждого ряда.

Для этого подходит **словарь**.

Словарь хранит соответствие:

```text
ключ → значение
```

В нашем случае:

```text
номер ряда → позиции в этом ряду
```

Пример:

```python
rows = {
    5: {2, 3, 4, 8},
    9: {10, 13, 20}
}
```

Фигурные скобки с элементами:

```python
{2, 3, 4, 8}
```

Создают **множество**.

Множество хранит только различные значения:

```python
set([2, 2, 3, 4])
```

Даёт множество чисел 2, 3, 4.

Оно полезно, если повторные попадания в одну точку не создают новых точек.

Пустой словарь:

```python
rows = {}
```

Пустое множество:

```python
positions = set()
```

Создание групп:

```python
rows = {}

for row, position in data:
    if row not in rows:
        rows[row] = set()

    rows[row].add(position)
```

Разбор:

```python
if row not in rows:
```

Проверяет, встречался ли такой ряд.

```python
rows[row] = set()
```

Создаёт для нового ряда пустое множество позиций.

```python
rows[row].add(position)
```

Добавляет позицию.

**Повторы можно удалять только тогда, когда они не влияют на смысл задачи.**

| Данные | Можно ли удалить одинаковые значения? |
|---|---|
| Несколько попаданий в одну светящуюся точку | Да, если важен только факт свечения |
| Несколько записей об одном занятом месте | Да, если это повторные сведения |
| Два файла одинакового размера | Нет, это два файла |
| Два товара одинаковой цены | Нет, это два товара |
| Несколько заявок на один объект | Зависит от того, нужны ли ID и число заявок |

Если для одинаковой позиции нужно сохранить минимальный номер заявки, одного множества недостаточно. Нужно хранить соответствие:

```text
позиция → минимальный ID заявки
```

**16. Свободные места между занятыми находятся по разности соседних номеров.**

Пусть в одном ряду заняты места:

```text
4 7 12 16
```

Между местами 4 и 7 свободны:

```text
5 6
```

Количество свободных мест между занятыми номерами \(a<b\):

\[
b-a-1.
\]

Почему минус один?

Потому что сами занятые места не входят в промежуток.

Чтобы между двумя **соседними занятыми** местами находились ровно два свободных:

\[
b-a-1=2,
\]

значит:

\[
b-a=3.
\]

Соседними здесь называются соседние элементы **отсортированного списка занятых мест**, а не просто соседние строки файла.

Для условия:

> Выбрать максимальный номер ряда, а внутри него минимальный номер подходящего свободного места

можно сразу задать нужный порядок просмотра:

```python
places = sorted(
    set(data),
    key=lambda x: (-x[0], x[1])
)
```

Здесь `data` должен содержать пары-кортежи:

```python
(row, seat)
```

Далее:

```python
answer = None

for i in range(len(places) - 1):
    row1, seat1 = places[i]
    row2, seat2 = places[i + 1]

    if row1 == row2 and seat2 - seat1 == 3:
        answer = (row1, seat1 + 1)
        break

if answer is not None:
    print(answer[0], answer[1])
```

Почему подходит первое найденное решение?

Потому что:

- ряды идут от больших к меньшим;
- места внутри ряда — от меньших к большим.

Сама сортировка уже учитывает приоритеты ответа.

Почему обязательно:

```python
row1 == row2
```

Потому что соседние записи списка могут относиться к разным рядам.

Почему выводим:

```python
seat1 + 1
```

Потому что `seat1` — занятое место, а нужно первое свободное после него.

Различай условия:

- «ровно два свободных, с обеих сторон занятые» — разность 3;
- «не менее двух свободных между занятыми» — разность не меньше 3;
- «любые два соседних свободных места» — могут подходить и части длинного свободного промежутка.

**17. Последовательности соседних позиций обрабатываются счётчиком текущей серии.**

Пусть в ряду отмечены позиции:

```text
2 3 4 8 9 10 11 20
```

Здесь три непрерывные серии:

```text
2 3 4
8 9 10 11
20
```

Их длины:

```text
3 4 1
```

Чтобы понять, продолжает ли новая позиция текущую серию, достаточно проверить:

\[
\text{новая позиция}=\text{предыдущая}+1.
\]

Код для максимальной длины:

```python
positions = sorted(set(positions))

current = 0
best = 0
previous = None

for position in positions:
    if previous is not None and position == previous + 1:
        current += 1
    else:
        current = 1

    if current > best:
        best = current

    previous = position
```

Почему при разрыве `current = 1`?

Потому что текущая позиция уже начинает новую серию.

Если нужно **количество максимальных непрерывных серий длиной не менее трёх**, логика немного другая:

```python
line_count = 0
current = 0
previous = None

for position in positions:
    if previous is not None and position == previous + 1:
        current += 1
    else:
        if current >= 3:
            line_count += 1

        current = 1

    previous = position

if current >= 3:
    line_count += 1
```

Последняя проверка после цикла обязательна.

Почему?

Потому что серия обычно учитывается при появлении разрыва. После последнего элемента нового значения уже нет, значит, завершающего разрыва программа не увидит.

В подборке есть именно задачи о линиях, ограниченных тёмными точками или краем экрана: там длинная непрерывная серия считается одной линией. [inf-ege.sdamgia.ru](https://inf-ege.sdamgia.ru/problem?id=56526\&utm_source=chatgpt.com)

Например, серия:

```text
10 11 12 13 14
```

Может давать разные ответы в зависимости от вопроса:

| Что считаем | Ответ |
|---|---:|
| Максимальную длину серии | 5 |
| Максимальные непрерывные серии длиной ≥ 3 | 1 |
| Все последовательные тройки внутри неё | 3 |

Тройки:

```text
10 11 12
11 12 13
12 13 14
```

Это три разных задачи.

Для сравнения результатов по рядам:

```python
if (
    line_count > best_count
    or (
        line_count == best_count
        and row > best_row
    )
):
    best_count = line_count
    best_row = row
```

Так явно записываются два приоритета:

1. Больше линий.
2. При равенстве больше номер ряда.

Для **изолированной точки** достаточно проверить ближайшего соседа слева и ближайшего справа.

Если даже ближайшая точка справа дальше \(D\), все остальные справа тем более дальше.

Для позиции с индексом `i`:

```python
left_ok = (
    i == 0
    or positions[i] - positions[i - 1] > distance
)

right_ok = (
    i == len(positions) - 1
    or positions[i + 1] - positions[i] > distance
)
```

Точка изолирована, если:

```python
left_ok and right_ok
```

**18. Максимальное количество непересекающихся мероприятий выбирается по времени окончания.**

У мероприятия есть:

```python
(start, finish)
```

Пусть следующее мероприятие разрешено начать в момент окончания предыдущего.

Тогда совместимость:

\[
start_{\text{следующего}}\ge finish_{\text{предыдущего}}.
\]

Если нужен перерыв \(P\):

\[
start_{\text{следующего}}\ge finish_{\text{предыдущего}}+P.
\]

Как выбирать?

Среди доступных мероприятий берём то, которое **раньше заканчивается**.

Почему?

Оно раньше освобождает зал и оставляет не меньше возможностей для следующих мероприятий.

Сортировка:

```python
meetings.sort(key=lambda x: (x[1], x[0]))
```

Первый показатель ключа — окончание.

Код:

```python
selected = []
last_finish = None

for start, finish in meetings:
    if (
        last_finish is None
        or start >= last_finish + pause
    ):
        selected.append((start, finish))
        last_finish = finish
```

Почему первый выбор обрабатывается через `None`?

Чтобы случайно не потребовать перерыв **до первого мероприятия**. Перерыв по условию обычно нужен между мероприятиями.

Доказательство выбора.

Пусть некоторое оптимальное расписание начинается с мероприятия \(A\).

Наш алгоритм выбирает мероприятие \(G\), заканчивающееся не позже \(A\).

Заменим \(A\) на \(G\).

Все остальные мероприятия расписания останутся допустимыми: зал освободится не позже прежнего.

Количество мероприятий не уменьшилось.

После первого выбора рассуждение повторяется для оставшейся части дня.

Почему не по началу?

Раннее мероприятие может занять весь день:

```text
(0, 20)
(1, 3)
(3, 5)
(5, 7)
```

Если выбрать первое по началу, получим одно мероприятие. Можно провести три.

Почему не по длительности?

Рассмотрим:

```text
(0, 4)
(4, 8)
(3, 5)
```

Короткое мероприятие `(3, 5)` пересекается с обоими длинными.

Выбор его первым даёт одно мероприятие, хотя можно провести два.

Значит, нам важно **освободиться раньше в абсолютном времени**, а не просто выбрать короткое мероприятие.

**19. Максимальный перерыв между последними мероприятиями находится после максимизации их количества.**

Такой дополнительный критерий тоже есть в подборке. [inf-ege.sdamgia.ru](https://inf-ege.sdamgia.ru/problem?id=61372\&utm_source=chatgpt.com)

Учебный пример:

```text
(1, 3)
(3, 5)
(5, 8)
(9, 15)
(12, 16)
```

Жадный алгоритм выберет:

```text
(1, 3), (3, 5), (5, 8), (9, 15)
```

Количество — 4.

Но последнее мероприятие можно заменить на:

```text
(12, 16)
```

Количество останется 4, а перерыв увеличится:

\[
12-8=4.
\]

Порядок решения:

1. Найти максимальное количество \(k\).
2. Взять первые \(k-1\) мероприятий жадного расписания.
3. Узнать время окончания предпоследнего.
4. Среди допустимых последних мероприятий выбрать то, которое позже начинается.

Почему первые \(k-1\) можно оставить жадными?

Потому что жадное построение позволяет закончить \(k-1\) мероприятий максимально рано. Более раннее окончание предпоследнего увеличивает возможный перерыв.

Если гарантировано хотя бы два мероприятия:

```python
count = len(selected)

penultimate_finish = selected[-2][1]

latest_start = None

for start, finish in meetings:
    if start >= penultimate_finish + pause:
        if latest_start is None or start > latest_start:
            latest_start = start

gap = latest_start - penultimate_finish

print(count, gap)
```

`selected[-2]` — предпоследняя выбранная запись.

`selected[-2][1]` — время её окончания.

Обрати внимание:

- максимизируем **начало** последнего мероприятия;
- позднее окончание само по себе не гарантирует большой перерыв;
- если мероприятий меньше двух, такого перерыва нет — этот случай определяется условием.

Если при одинаковом начале нужно выбрать наиболее длительное последнее мероприятие, добавляется ещё один критерий:

\[
finish-start.
\]

**20. Объединение интервалов применяется, когда нужно измерить общее занятое время.**

Это другой вопрос, чем выбор непересекающихся мероприятий.

Пусть система работала в интервалы:

```text
(2, 5)
(4, 8)
(8, 10)
(13, 15)
```

Первые три образуют один непрерывный период:

```text
(2, 10)
```

Получаем:

```text
(2, 10)
(13, 15)
```

Общая длительность работы:

\[
(10-2)+(15-13)=10.
\]

Сначала сортируем интервалы по началу.

Затем храним последний уже объединённый интервал.

```python
intervals.sort()

merged = []

for start, finish in intervals:
    if not merged or start > merged[-1][1]:
        merged.append([start, finish])
    else:
        merged[-1][1] = max(merged[-1][1], finish)
```

Почему объединённые интервалы записаны списками:

```python
[start, finish]
```

Потому что мы изменяем правую границу:

```python
merged[-1][1] = ...
```

Почему используем `max`?

Новый интервал может полностью лежать внутри предыдущего:

```text
(2, 20)
(5, 8)
```

Правая граница должна остаться 20.

Если нужен суммарный простой за период от 0 до `day_end`, считаем промежутки между объединёнными интервалами:

```python
cursor = 0
idle_count = 0
idle_duration = 0

for start, finish in merged:
    if start > cursor:
        idle_count += 1
        idle_duration += start - cursor

    cursor = finish

if cursor < day_end:
    idle_count += 1
    idle_duration += day_end - cursor
```

Здесь предполагается, что все интервалы лежат внутри рассматриваемого периода.

Учтены:

- простой до первой работы;
- простои между работами;
- простой после последней работы.

Важное различие:

\[
b-a
\]

— длительность непрерывного промежутка времени от \(a\) до \(b\).

\[
b-a+1
\]

— количество целых номеров от \(a\) до \(b\) включительно.

Например:

- от 10:00 до 10:05 прошло 5 минут;
- номера 10, 11, 12, 13, 14, 15 — это 6 номеров.

Целочисленные значения времени не делают формулу длительности автоматически равной `finish - start + 1`.

**21. Для количества одновременно работающих объектов удобно рассматривать события.**

Пусть каждый запрос задаётся интервалом работы.

Нужно узнать:

- максимальную одновременную нагрузку;
- сколько времени она держалась;
- число периодов постоянной нагрузки.

В каждый момент времени проверять все запросы дорого.

Но количество активных запросов меняется только при:

- начале запроса;
- окончании запроса.

Такое изменение будем называть **событием**.

Для модели, в которой объект активен при:

\[
start\le t<finish,
\]

записываем:

- в `start` изменение `+1`;
- в `finish` изменение `-1`.

Эта модель называется полуинтервалом \([start, finish)\): начало включено, окончание исключено.

Словарь изменений:

```python
changes = {0: 0, day_end: 0}

for start, finish in intervals:
    changes[start] = changes.get(start, 0) + 1
    changes[finish] = changes.get(finish, 0) - 1
```

Метод:

```python
changes.get(time, 0)
```

Возвращает значение по ключу `time`, а если такого ключа ещё нет — `0`.

Сортируем моменты событий:

```python
times = sorted(changes)
```

Сортировка словаря таким способом даёт отсортированный список его ключей.

Теперь между двумя соседними моментами количество активных объектов постоянно:

```python
current = 0
maximum = 0
total_duration = 0

for i in range(len(times) - 1):
    time = times[i]

    current += changes[time]

    duration = times[i + 1] - time

    if current > maximum:
        maximum = current
        total_duration = duration

    elif current == maximum:
        total_duration += duration

print(maximum, total_duration)
```

Почему сначала меняем `current`, потом учитываем длительность?

Потому что после событий в момент `time` новое количество действует до следующего события.

Пример:

```text
(2, 7)
(4, 10)
(7, 12)
```

В момент 7 один объект заканчивает работу, другой начинает.

Общее изменение:

\[
-1+1=0.
\]

Количество активных объектов не меняется.

Максимум равен 2 и держится с 4 до 10, то есть 6 единиц времени.

**Если нужен максимальный непрерывный период постоянной нагрузки, соседние участки с одинаковым количеством нужно объединять.** Сам факт событий на их границе ещё не означает изменения количества.

При другой трактовке границ алгоритм адаптируют:

- для непрерывных длительностей отдельный момент имеет нулевую длину;
- для подсчёта занятости целых моментов включительный отрезок `[start, finish]` можно представить событиями `+1` в `start` и `-1` в `finish + 1`;
- для максимума именно в момент совпадения начала и окончания нужно учитывать, включены ли обе границы.

Сначала определяется смысл времени, затем порядок обработки событий.

**22. В камере хранения нужно хранить время освобождения каждой ячейки.**

Пусть:

- есть `k` ячеек;
- заявка содержит начало и окончание хранения;
- выбирается свободная ячейка с минимальным номером;
- после освобождения ячейку можно занять сразу;
- если свободных нет, заявку отклоняют.

Состояние:

```python
free_at = [0] * k
```

Эта запись создаёт список из `k` нулей.

`free_at[i]` означает:

> В какой момент ячейка с индексом `i` станет свободной.

При приходе в момент `start` ячейка свободна, если:

```python
free_at[i] <= start
```

Сортируем заявки по приходу:

```python
requests.sort(key=lambda x: x[0])
```

Код:

```python
free_at = [0] * k

accepted = 0
last_cell = None

for start, finish in requests:
    for i in range(k):
        if free_at[i] <= start:
            free_at[i] = finish

            accepted += 1
            last_cell = i + 1

            break

print(accepted, last_cell)
```

Почему `i + 1`?

Индекс начинается с нуля, номер ячейки — с единицы.

Почему нужен `break`?

Одна заявка должна занять ровно одну ячейку. После размещения внутренний цикл завершает работу.

Почему получаем минимальный номер?

Индексы проверяются по возрастанию.

Пример для двух ячеек:

| Заявка | Действие |
|---|---|
| `(1, 5)` | Ячейка 1 |
| `(2, 4)` | Ячейка 2 |
| `(3, 7)` | Отказ |
| `(4, 8)` | Ячейка 2 |
| `(5, 6)` | Ячейка 1 |

Приняты четыре заявки. Последняя принятая размещена в ячейке 1.

Если новая загрузка возможна только **после** указанного момента выдачи, условие будет строгим:

```python
free_at[i] < start
```

Это определяется формулировкой.

Также нужно различать:

- время окончания хранения;
- длительность хранения.

Если дано начало и длительность:

```python
finish = start + duration
```

Ещё одна тонкость: при одинаковом времени прихода должен быть понятен порядок обработки заявок. Нельзя произвольно добавлять сортировку по окончанию, если по условию должен сохраняться порядок поступления.

**23. Очередь отличается от отказа тем, что клиент может начать обслуживание позже своего прихода.**

Для одного окна достаточно хранить время его освобождения.

Пусть:

- клиент пришёл в `arrival`;
- обслуживание длится `duration`;
- окно свободно с `free_at`.

Тогда:

```python
start = max(arrival, free_at)
finish = start + duration
```

Почему максимум?

Обслуживание не может начаться:

- раньше прихода клиента;
- раньше освобождения окна.

Время ожидания:

```python
waiting = start - arrival
```

Если клиент согласен ждать не более `max_wait`:

```python
start = max(arrival, free_at)

if start - arrival <= max_wait:
    free_at = start + duration
    served += 1
else:
    rejected += 1
```

При отказе нельзя менять `free_at`: этот клиент не занял место в расписании.

Для нескольких очередей важно, **что именно минимизирует клиент**:

- количество людей;
- ожидаемое время;
- номер окна;
- стоимость услуги.

Это разные правила.

Например:

- в первой очереди один человек, которому осталось 30 минут;
- во второй два человека, каждому нужна одна минута.

Самая короткая по количеству людей очередь и самое короткое ожидание здесь различаются.

Если нужно знать число людей, ещё находящихся в очереди, удобно хранить времена их окончания обслуживания.

Для очереди «первым пришёл — первым обслужен» подходит `deque` из стандартного модуля `collections`. Он позволяет эффективно добавлять элементы в конец и удалять из начала. [Python 3.14.8 documentation](https://docs.python.org/3/library/collections.html?utm_source=chatgpt.com)

```python
from collections import deque

queue = deque()
```

`from ... import ...` подключает нужный инструмент из стандартной библиотеки Python.

Перед обработкой нового прихода убираем уже обслуженных:

```python
while queue and queue[0] <= arrival:
    queue.popleft()
```

`popleft()` удаляет первый элемент очереди.

После этого, если очередь хранит всех ещё не завершивших обслуживание:

```python
len(queue)
```

даёт их количество.

Новый клиент начнёт:

```python
if queue:
    start = max(arrival, queue[-1])
else:
    start = arrival
```

После принятия:

```python
queue.append(start + duration)
```

Но если условие считает длиной очереди только **ожидающих**, без обслуживаемого клиента, подсчёт нужно изменить.

Для задач об очередях отдельно выписывай:

1. Кто учитывается в очереди?
2. Как выбирается окно?
3. Как разрешается равенство?
4. Когда клиент отказывается?
5. Учитываются начавшие обслуживание до закрытия или закончившие до закрытия?

**24. Если ячеек много, поиск свободной можно ускорить с помощью очереди приоритетов.**

Предыдущий алгоритм в худшем случае проверяет `k` ячеек для каждой из `n` заявок:

\[
O(NK).
\]

Если оба числа большие, это становится дорого.

Нужны две операции:

1. Быстро узнать, какая занятая ячейка освободится раньше.
2. Быстро выбрать минимальный номер среди уже свободных.

Для этого используют **очередь приоритетов** — структуру, из которой удобно извлекать элемент с наименьшим ключом.

В Python её реализует модуль `heapq`.

Основные операции:

```python
heapify(a)
```

Организовать существующий список как такую структуру.

```python
heappush(a, value)
```

Добавить элемент.

```python
heappop(a)
```

Удалить и вернуть минимальный элемент.

```python
a[0]
```

Посмотреть минимальный элемент без удаления.

Остальные элементы при этом не обязаны идти в полностью отсортированном порядке. [Python 3.14.8 documentation](https://docs.python.org/3/library/heapq.html?utm_source=chatgpt.com)

Храним:

- `free_cells` — номера свободных ячеек;
- `busy` — пары `(время освобождения, номер ячейки)`.

```python
from heapq import heapify, heappush, heappop

requests.sort(key=lambda x: x[0])

free_cells = list(range(k))
heapify(free_cells)

busy = []

accepted = 0
last_cell = None

for start, finish in requests:
    while busy and busy[0][0] <= start:
        old_finish, cell = heappop(busy)
        heappush(free_cells, cell)

    if free_cells:
        cell = heappop(free_cells)

        heappush(busy, (finish, cell))

        accepted += 1
        last_cell = cell + 1

print(accepted, last_cell)
```

Здесь `list(range(k))` создаёт список индексов:

```text
0, 1, 2, ..., k - 1
```

Почему нужны две структуры?

В занятой нас интересует **время освобождения**.

В свободной — **номер ячейки**.

Один и тот же порядок не решает обе задачи.

Обработка после сортировки занимает порядка:

\[
O(N\log K).
\]

Если выбирается самая дешёвая свободная ячейка, а при равенстве — минимальный номер, в свободной очереди приоритетов можно хранить:

```python
(price, cell_number)
```

**25. При упаковке грузов важно отличать заданную процедуру от поиска минимального количества контейнеров.**

Рассмотрим правило:

> Заполнять контейнер грузами по убыванию массы. Если очередной груз не помещается, пробовать следующие. Затем повторить для оставшихся грузов.

Это процедура, которую нужно воспроизвести.

```python
remaining = sorted(weights, reverse=True)

loads = []

while remaining:
    next_remaining = []
    load = 0

    for weight in remaining:
        if load + weight <= capacity:
            load += weight
        else:
            next_remaining.append(weight)

    loads.append(load)
    remaining = next_remaining
```

Здесь:

- `remaining` — грузы, ещё не размещённые;
- `load` — загрузка текущего контейнера;
- `next_remaining` — грузы для следующих контейнеров;
- `loads` — загрузки готовых контейнеров.

Предполагается, что каждый отдельный груз не тяжелее контейнера. Иначе такой цикл может никогда не завершиться.

Почему нельзя делать `break`, когда груз не поместился?

Потому что список убывает: следующие грузы легче и могут поместиться.

Это отличается от отбора маленьких файлов в возрастающем списке.

Пример:

```text
Вместимость: 10
Грузы: 7 6 4 3
```

В первый контейнер:

- 7 помещается;
- 6 не помещается;
- 4 не помещается;
- 3 помещается.

Итоговая загрузка — 10.

Важно: эта процедура не всегда даёт минимальное число контейнеров.

Контрпример:

```text
Вместимость: 10
Грузы: 6 5 3 2 2 2
```

Процедура даст:

```text
6 + 3 = 9
5 + 2 + 2 = 9
2
```

Три контейнера.

Но существует размещение в два:

```text
6 + 2 + 2 = 10
5 + 3 + 2 = 10
```

Поэтому нельзя называть результат такого алгоритма оптимальным без доказательства.

Если же он прямо предписан условием, нужно получить именно результат предписанной процедуры.

**26. Два указателя помогают работать с отсортированными списками без перебора всех пар.**

**Указатель** здесь — обычная переменная, хранящая индекс текущего элемента.

Например:

```python
left = 0
right = len(a) - 1
```

Один индекс стоит в начале списка, другой — в конце.

Рассмотрим задачу:

> Каждый рейс перевозит не более двух человек. Суммарная масса не превышает вместимость. Нужно минимизировать количество рейсов.

Предполагается, что любой человек может ехать один.

Сортируем массы:

```python
weights.sort()
```

Берём самого тяжёлого из оставшихся.

Если он не помещается вместе с самым лёгким, ни с кем другим он тоже не поместится.

Значит, должен ехать один.

Если помещается, можно объединить их.

```python
left = 0
right = len(weights) - 1

trips = 0

while left <= right:
    if left < right and weights[left] + weights[right] <= capacity:
        left += 1

    right -= 1
    trips += 1

print(trips)
```

Почему при совместной поездке двигаются оба индекса?

Потому что использованы два человека.

Если вместе не помещаются, используется только тяжёлый — двигается правый индекс.

При `left == right` остался один человек.

Условие `left < right` не позволяет использовать его дважды.

Обоснование совместной поездки строится обменом: самого тяжёлого можно объединить с самым лёгким, не ухудшая необходимое количество пар. Если в другом размещении они ехали с другими людьми, пары можно перестроить; оставшиеся партнёры совместимы, поскольку каждый из них не тяжелее самого тяжёлого.

**Ограничение «не более двух» существенно.** Для произвольного числа объектов в контейнере этот алгоритм уже не является решением общей задачи упаковки.

Другая полезная модель — две разновидности деталей.

Пусть:

- для изделия нужна одна деталь А и одна В;
- размеры различаются не более чем на \(D\);
- прибыль равна сумме размеров;
- все размеры положительные.

Сортируем оба списка по убыванию.

Если самая большая А больше самой большой В более чем на \(D\), эта А не подойдёт ни к одной оставшейся В. Её можно пропустить.

Аналогично для слишком большой В.

Если крупнейшие совместимы — объединяем их.

```python
a.sort(reverse=True)
b.sort(reverse=True)

i = 0
j = 0

count = 0
profit = 0

while i < len(a) and j < len(b):
    if a[i] > b[j] + distance:
        i += 1

    elif b[j] > a[i] + distance:
        j += 1

    else:
        count += 1
        profit += a[i] + b[j]

        i += 1
        j += 1

print(count, profit)
```

Почему можно объединить крупнейшие совместимые детали?

Если в другом решении они соединены с другими партнёрами, эти две пары можно перестроить. Меньшие оставшиеся партнёры сохранят совместимость: их разность ограничивается одной из уже допустимых разностей.

Если одна из крупнейших деталей не использовалась, замена меньшей детали на неё не уменьшает прибыль.

Здесь доказательство использует конкретную совместимость по разности размеров и конкретную формулу прибыли. При других правилах оно может перестать работать.

**27. Подсчёт всех подходящих пар отличается от разбиения объектов на непересекающиеся пары.**

В предыдущем примере каждый объект использовался один раз.

Но условие может требовать:

> Найти количество всех пар, сумма которых не превышает \(S\).

Тогда одно число может участвовать во многих парах.

Пусть список отсортирован по возрастанию.

Если:

```python
a[left] + a[right] <= limit
```

то с `a[left]` подходят все элементы с индексами:

```text
left + 1, ..., right
```

Потому что они не больше `a[right]`.

Таких элементов:

```python
right - left
```

Код:

```python
a.sort()

left = 0
right = len(a) - 1

count = 0

while left < right:
    if a[left] + a[right] <= limit:
        count += right - left
        left += 1
    else:
        right -= 1

print(count)
```

Если сумма слишком велика, уменьшаем правую границу.

Почему можно отбросить текущий правый элемент?

Потому что даже с минимальным доступным левым он не подходит. С более крупными левыми сумма будет ещё больше.

После сортировки оба индекса проходят список только один раз, поэтому сам подсчёт имеет порядок \(O(N)\).

Но этот приём работает благодаря упорядоченному условию на сумму.

Если требуется:

> Среднее арифметическое пары должно встречаться в файле,

одной такой логики движения указателей обычно недостаточно.

Для проверки наличия значения удобно использовать множество:

```python
values = set(a)
```

Операция:

```python
x in values
```

проверяет наличие значения; в обычных условиях поиска по множеству она существенно эффективнее последовательного просмотра списка.

Пары перебираем так:

```python
count = 0
best_average = None

for i in range(len(a)):
    for j in range(i + 1, len(a)):
        total = a[i] + a[j]

        if total % 2 == 0:
            average = total // 2

            if average in values:
                count += 1

                if best_average is None or average > best_average:
                    best_average = average
```

`%` даёт остаток от деления.

```python
total % 2 == 0
```

Проверяет чётность суммы. Это нужно, чтобы среднее было целым.

Почему `j` начинается с `i + 1`?

Чтобы:

- не образовывать пару элемента с самим собой;
- не считать `(a, b)` и `(b, a)` дважды.

Здесь остаётся \(O(N^2)\) пар. Множество ускоряет проверку наличия, но не отменяет сам перебор. Допустимость такого решения зависит от размера входных данных.

**28. Скользящее окно используется, когда подходящий набор можно представить непрерывным участком отсортированного списка.**

Рассмотрим условие:

> Выбрать максимальное количество чисел так, чтобы разность максимального и минимального не превышала \(D\).

После сортировки выбранные числа можно брать подряд.

Почему?

Если минимальное и максимальное допустимы, любое число между ними тоже можно добавить: границы диапазона не изменятся.

Пусть:

```text
1 3 4 10 11 13
```

и:

```text
D = 4
```

Подходят, например:

```text
1 3 4
```

и:

```text
10 11 13
```

Храним две границы участка:

- `left` — левую;
- `right` — правую.

Участок между ними называют **окном**.

Правую границу двигаем вперёд. Если условие нарушено, сдвигаем левую, пока оно снова не выполнится.

```python
a.sort()

left = 0
best = 0

for right in range(len(a)):
    while a[right] - a[left] > distance:
        left += 1

    length = right - left + 1

    if length > best:
        best = length

print(best)
```

Почему длина:

```python
right - left + 1
```

Потому что обе границы входят в участок.

Например, индексы от 2 до 4 включительно — это три элемента.

Почему вложенный `while` не делает алгоритм квадратичным?

Потому что `left` за всю работу только увеличивается и проходит не более \(N\) позиций.

Он не возвращается в начало для каждого `right`.

Здесь принципиальное основание метода:

> При расширении окна нарушение исправляется удалением элементов слева, а пропущенные внутри элементы не нужны.

Для произвольного набора ограничений это свойство нужно доказывать.

**29. Усложнённые цепочки иногда сводятся к нескольким жадным проходам или окну, но это требует нового доказательства.**

Разберём два характерных усложнения.

Первое: коробки двух материалов должны чередоваться, а требуемый зазор зависит от номера вложения.

В подборке есть такие задачи. [inf-ege.sdamgia.ru](https://inf-ege.sdamgia.ru/problem?id=89209\&utm_source=chatgpt.com)

Пусть правило имеет вид:

> Между \(k\)-й и \((k+1)\)-й коробкой нужен зазор хотя бы \(C+k\), материалы должны различаться.

Нумерация идёт изнутри наружу.

Если известно, из какого материала сделана первая коробка, материалы всех следующих определены:

```text
0, 1, 0, 1, ...
```

или:

```text
1, 0, 1, 0, ...
```

Можно выполнить два прохода:

1. Цепочка начинается с материала 0.
2. Цепочка начинается с материала 1.

Внутри каждого прохода берём минимальную подходящую внешнюю коробку.

```python
boxes.sort()

best_count = 0
best_outer = None

for first_type in (0, 1):
    expected_type = first_type

    count = 0
    last_size = None

    for size, material in boxes:
        if material != expected_type:
            continue

        if last_size is None or size - last_size >= base_gap + count:
            count += 1
            last_size = size
            expected_type = 1 - expected_type

    if (
        count > best_count
        or (
            count == best_count
            and last_size is not None
            and (
                best_outer is None
                or last_size < best_outer
            )
        )
    ):
        best_count = count
        best_outer = last_size
```

Здесь `base_gap` соответствует \(C\).

Почему перед добавлением новой коробки используется `count`?

Потому что уже выбрано `count` коробок. Последняя из них имеет номер `count`, значит, следующий зазор должен быть не меньше \(C+count\).

Почему жадность работает при фиксированном первом материале?

На одной и той же позиции цепочки:

- нужный материал одинаков;
- требуемая прибавка к следующей коробке одинакова;
- меньшая текущая коробка оставляет не меньше возможностей продолжения.

Но если бы материал влиял на другую сложную характеристику, например суммарную стоимость или ограниченный запас переходов, одного такого состояния могло бы не хватить.

Второе усложнение: маршрут по убывающим высотам с ограниченным числом специальных переходов.

Предположим:

- обычный переход имеет перепад не более \(D\);
- специальный — не более \(E\);
- специальных переходов не больше \(K\);
- переходить можно только на строго меньшую высоту.

Возникает вопрос:

> Можно ли считать, что оптимальный маршрут проходит по всем высотам подряд в отсортированном списке?

Не всегда.

Но это можно доказать, например, при целых высотах и условии:

\[
E<2(D+1).
\]

Почему появляется \(D+1\)?

Потому что минимальный целый перепад, уже требующий специального перехода, равен \(D+1\).

Два таких перепада вместе дают хотя бы:

\[
2(D+1).
\]

Если это больше \(E\), один допустимый специальный прыжок не может перескочить сразу через два промежутка, каждый из которых требует специального перехода.

Следовательно, добавление пропущенных промежуточных высот внутрь допустимого перехода не увеличивает число специальных переходов:

- обычный переход разбивается на обычные;
- специальный — на обычные и не более одного специального.

Значит, оптимальный маршрут можно искать среди непрерывных участков отсортированных различных высот.

Тогда:

- перепад больше \(E\) разрывает допустимый участок;
- перепад от \(D+1\) до \(E\) расходует один специальный переход;
- при превышении \(K\) сдвигаем левую границу.

```python
heights = sorted(set(heights), reverse=True)

left = 0
special_count = 0

best_length = 0
best_finish = 0

for right in range(len(heights)):
    if right > 0:
        gap = heights[right - 1] - heights[right]

        if gap > special_limit:
            left = right
            special_count = 0

        elif gap > normal_limit:
            special_count += 1

    while special_count > allowed_special:
        old_gap = heights[left] - heights[left + 1]

        if old_gap > normal_limit:
            special_count -= 1

        left += 1

    length = right - left + 1
    finish_height = heights[right]

    if (
        length > best_length
        or (
            length == best_length
            and finish_height > best_finish
        )
    ):
        best_length = length
        best_finish = finish_height
```

Здесь удаление повторных высот допустимо именно потому, что маршрут строго убывает и у лагерей нет других различающих условий: на одной высоте можно посетить не более одного лагеря.

Для учебного примера:

```text
Высоты: 30 28 23 21 17 15 9 8
Обычный перепад: 3
Специальный перепад: 6
Специальных переходов: 1
```

Ответ:

```text
4 21
```

Один из лучших маршрутов:

```text
30 → 28 → 23 → 21
```

Условие на \(D\) и \(E\) нельзя отбросить.

Например, при:

```text
D = 3
E = 12
K = 1
```

и высотах:

```text
53 52 51 50 44 38 37 36 35
```

можно пропустить 44 и пройти:

```text
53 52 51 50 38 37 36 35
```

Использован один специальный переход `50 → 38`.

А прохождение через 44 потребовало бы двух специальных переходов.

Это пример того, почему для усложнённой задачи нужно заново обосновывать возможность свести выбор к соседним элементам.

**30. Задачи о журналах и резервных копиях собираются из уже изученных приёмов.**

Пусть запись содержит:

```text
время    ID клиента    объём
```

Сервер накапливает данные. Если очередной запрос не помещается, сервер:

1. Создаёт резервную копию уже накопленного.
2. Очищает память.
3. Добавляет новый запрос.

Здесь понадобятся:

- преобразование времени;
- сортировка записей;
- накопление объёмов по клиентам;
- моделирование заполнения памяти.

Время вида:

```text
11:59:59
```

можно перевести в секунды:

```python
hours, minutes, seconds = map(int, time_text.split(":"))

time = hours * 3600 + minutes * 60 + seconds
```

`split(":")` разбивает строку по двоеточиям.

Объёмы по клиентам:

```python
client_total[client_id] = (
    client_total.get(client_id, 0) + volume
)
```

Моделирование памяти:

```python
used = 0
backups = []

for time, client_id, volume in records:
    if used + volume > capacity:
        backups.append((time, used))
        used = 0

    used += volume
```

Предполагается, что один запрос помещается в пустую память.

Почему резервную копию записываем **до** прибавления нового объёма?

Потому что она содержит старые накопленные данные. Новый запрос поступает уже после очистки.

Почему условие строгое:

```python
used + volume > capacity
```

Потому что при точном заполнении памяти места пока хватает. Копирование произойдёт при следующем запросе, который не поместится, если именно это предписано условием.

Почему нельзя автоматически добавить резервную копию в конце программы?

Потому что завершение входного файла само по себе не означает, что сервер выполнял копирование.

Если нужны копии до полудня:

```python
if time < 12 * 3600:
    ...
```

Но смысл границы нужно брать из условия.

Также различай:

- две крупнейшие копии среди всех подходящих;
- две соседние по времени копии с максимальной суммой.

Для первого случая достаточно выбрать два максимальных объёма.

Для второго проверяются соседние записи в хронологическом порядке.

**31. Правильность решения удобнее контролировать через смысл переменных.**

Для каждой переменной нужно уметь закончить фразу:

> После обработки очередного объекта эта переменная хранит…

Например:

```python
used
```

Хранит сумму уже выбранных размеров.

```python
last_finish
```

Хранит окончание последнего принятого мероприятия.

```python
free_at[i]
```

Хранит время освобождения конкретной ячейки.

```python
current
```

Хранит длину серии, заканчивающейся в текущей позиции.

Такое утверждение, сохраняющееся по ходу цикла, называют **инвариантом**.

Термин выглядит сложнее самой идеи: это просто точно сформулированный смысл состояния программы.

Если переменная должна хранить число принятых заявок, увеличивать её при отказе нельзя.

Если она должна хранить номер последней занятой ячейки, обновлять её при освобождении ячейки нельзя.

Многие ошибки находятся именно так, без запуска на большом файле.

**32. Есть несколько пограничных случаев, которые особенно полезно проверять.**

Не нужно придумывать огромные тесты. Часто достаточно пяти–восьми чисел.

| Случай | Что проверяет |
|---|---|
| Один объект | Инициализацию, обращение к соседям |
| Все объекты помещаются | Правильность счётчика после завершения цикла |
| Ничего не помещается | Обработку отсутствия решения |
| Сумма точно равна лимиту | Различие `<` и `<=` |
| Два одинаковых значения | Сохранение кратности объектов |
| Полное равенство основных критериев | Дополнительный критерий |
| Лучший результат находится в конце | Обработку последней группы |
| Начало совпадает с окончанием | Правила границ времени |

Особенно частые ошибки:

| Ошибка | Почему опасна |
|---|---|
| Прочитать количество объектов как обычный элемент | В данных появляется лишний объект |
| Отсортировать числа как строки | `"100"` может оказаться раньше `"20"` |
| Сортировать поля записей независимо | Разрушается связь характеристик |
| Удалить одинаковые цены через `set` | Исчезают реальные товары |
| Использовать индекс как количество | Индекс начинается с нуля |
| Забыть последнюю серию | Она не завершится разрывом внутри цикла |
| Выбрать максимальный номер ячейки вместо последней занятой | Это разные величины |
| Поставить `break` без обоснования | Можно пропустить подходящие объекты |
| Искать максимум второго показателя без фиксации первого | Нарушается порядок приоритетов |
| Удалять элементы списка во время прохода по нему | Можно перескочить через элементы |

Ещё одна скрытая проблема — повторная работа внутри цикла.

Например:

```python
for i in range(len(a)):
    total = sum(a[:i])
```

Каждый раз заново создаёт срез и суммирует его.

Если нужна постепенно растущая сумма:

```python
total = 0

for x in a:
    total += x
```

Если нужны суммы разных начальных участков — заранее строятся префиксные суммы.
