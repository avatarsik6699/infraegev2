**Черепаха выполняет команды буквально и хранит своё текущее состояние.**

В информатике *исполнитель* — это объект, который умеет выполнять определённые команды. В нашем случае исполнитель называется Черепахой.

Представь, что по листу бумаги перемещается маленькая стрелка. У неё есть:

- положение на листе;
- направление, в которое она смотрит;
- перо, которое можно опустить или поднять.

Когда перо опущено, перемещение оставляет линию. Когда перо поднято, Черепаха перемещается без линии.

В условиях ЕГЭ вместо слова «перо» обычно используется слово **«хвост»**. Для понимания задачи это одно и то же.

Чтобы описать состояние Черепахи, нужно знать четыре вещи:

| Что нужно знать | Пример |
|---|---|
| Координату по горизонтали | \(x=3\) |
| Координату по вертикали | \(y=5\) |
| Направление головы | Вверх |
| Состояние хвоста | Опущен |

Почему одного положения недостаточно?

Допустим, две Черепахи находятся в одной точке \((3;5)\). Одна смотрит вверх, другая вправо. После команды `Вперёд 2` они окажутся в разных точках.

Почему нужно помнить состояние хвоста?

Две Черепахи могут пройти по одному маршруту, но одна нарисует линию, а другая — нет.

**Алгоритм определяет не только маршрут, но и то, какие части маршрута становятся рисунком.**

**Координаты позволяют точно описывать положение на плоскости.**

В задании используется система из двух числовых осей:

- горизонтальная ось \(Ox\);
- вертикальная ось \(Oy\).

Они пересекаются в точке \((0;0)\), которая называется **началом координат**.

Направления положительных значений:

- по \(Ox\) — вправо;
- по \(Oy\) — вверх.

Отрицательные значения идут в противоположные стороны.

Точка \((3;2)\) находится на 3 единицы правее и на 2 единицы выше начала координат.

Точка \((-4;1)\) находится на 4 единицы левее и на 1 единицу выше начала координат.

Точка \((2;-3)\) находится на 2 единицы правее и на 3 единицы ниже начала координат.

В паре координат **сначала записывается \(x\), затем \(y\)**.

В условиях могут встретиться слова:

| Термин | Значение |
|---|---|
| Ось абсцисс | Ось \(Ox\) |
| Ось ординат | Ось \(Oy\) |
| Положительное направление оси абсцисс | Вправо |
| Положительное направление оси ординат | Вверх |

Например, фраза:

> Голова направлена вдоль положительного направления оси ординат.

означает:

> Черепаха смотрит вверх.

Это нужно прочитать до написания программы. Начальное направление нельзя выбирать по привычке.

**Точка с целочисленными координатами — это точка, у которой обе координаты являются целыми числами.**

Целые числа:

\[
\ldots,-3,-2,-1,0,1,2,3,\ldots
\]

Поэтому подходят точки:

\[
(0;0),\quad (2;5),\quad (-3;4),\quad (7;-1).
\]

Не подходят:

\[
(1{,}5;2),\quad (3;0{,}7),\quad (\sqrt3;4).
\]

Достаточно, чтобы хотя бы одна координата была нецелой, — и точка уже не соответствует условию.

Обрати внимание:

- ноль — целое число;
- отрицательные числа тоже целые;
- точки на осях могут учитываться, если формулировка задачи их допускает.

Иногда спрашивают количество точек **с положительными целочисленными координатами**. Тогда дополнительно требуется:

\[
x>0,\qquad y>0.
\]

При таком условии точки на осях уже не подходят.

Если на плоскости отметить все точки с целыми координатами, получится регулярная сетка точек. Её называют **целочисленной решёткой**.

Именно такую сетку мы будем наносить поверх рисунка Черепахи.

**Движение изменяет положение, а поворот изменяет направление.**

Рассмотрим команды отдельно.

**Команда `Вперёд n` перемещает Черепаху туда, куда смотрит её голова.**

Если Черепаха находится в \((2;3)\) и смотрит вверх, то после `Вперёд 4` она окажется в:

\[
(2;7).
\]

Координата \(x\) не изменилась. Координата \(y\) увеличилась на 4.

Если из той же точки Черепаха смотрит вправо, результат будет:

\[
(6;3).
\]

Если вниз:

\[
(2;-1).
\]

Если влево:

\[
(-2;3).
\]

Слово «вперёд» связано с головой Черепахи. Оно не означает автоматически «вверх».

**Команда `Назад n` перемещает Черепаху в сторону, противоположную направлению головы.**

При этом голова остаётся направленной туда же.

Например:

1. Черепаха смотрит вправо.
2. Выполняет `Назад 3`.
3. Перемещается на 3 единицы влево.
4. Продолжает смотреть вправо.

Это существенно для следующей команды.

Если затем выполнить `Вперёд 5`, Черепаха пойдёт вправо.

**Команда `Направо m` поворачивает голову на \(m\) градусов по часовой стрелке.**

Положение Черепахи при этом не меняется.

Например, если она смотрела вверх:

| Команда | Новое направление |
|---|---|
| Направо 90 | Вправо |
| Направо 180 | Вниз |
| Направо 270 | Влево |
| Направо 360 | Снова вверх |

**Команда `Налево m` поворачивает голову на \(m\) градусов против часовой стрелки.**

Если Черепаха смотрела вверх, после `Налево 90` она будет смотреть влево.

Поворот выполняется **от текущего направления**. Поэтому одна и та же команда может давать разные итоговые направления.

Например:

- смотрела вверх, повернула направо на \(90^\circ\) — смотрит вправо;
- смотрела вправо, повернула направо на \(90^\circ\) — смотрит вниз.

**Команды поднятия и опускания хвоста меняют только режим рисования.**

Они сами по себе:

- не перемещают Черепаху;
- не поворачивают её;
- не стирают уже нарисованное.

**В Python направление удобно описывать углом.**

Во всех примерах дальше используется стандартный режим `turtle`.

В нём направления задаются так:

| Направление | Угол |
|---|---:|
| Вправо | \(0^\circ\) |
| Вверх | \(90^\circ\) |
| Влево | \(180^\circ\) |
| Вниз | \(270^\circ\) |

Положительное изменение этого угла соответствует повороту против часовой стрелки.

Например:

\[
0^\circ+90^\circ=90^\circ,
\]

то есть из направления вправо получаем направление вверх.

При правом повороте угол уменьшается:

\[
90^\circ-90^\circ=0^\circ.
\]

Отрицательные значения можно заменить равнозначными положительными. Например:

\[
-90^\circ=270^\circ
\]

в смысле направления.

Оба угла обозначают направление вниз.

Полный оборот составляет \(360^\circ\), поэтому:

\[
30^\circ,\quad 390^\circ,\quad -330^\circ
\]

задают одно направление.

**По умолчанию новая Черепаха в стандартном режиме Python смотрит вправо.** Если в условии указано направление вверх, его нужно установить в программе. Соответствие направлений и поведение команд описаны в документации Python. [Python 3.15.0 documentation](https://docs.python.org/3/library/turtle.html?utm_source=chatgpt.com)

**Угол поворота Черепахи и внутренний угол фигуры — разные величины.**

Этот момент особенно важен для треугольников и наклонных четырёхугольников.

Внутренний угол фигуры образуют две стороны, если смотреть **внутрь** фигуры.

Черепаха же приходит по одной стороне и поворачивает от направления, в котором продолжала бы двигаться прямо.

Например, у равностороннего треугольника внутренний угол равен:

\[
60^\circ.
\]

Но при обходе такого треугольника Черепаха поворачивает на:

\[
180^\circ-60^\circ=120^\circ.
\]

Поэтому алгоритм:

```text
Повтори 3 [
    Вперёд 8
    Направо 120
]
```

рисует равносторонний треугольник.

Если написать поворот на \(60^\circ\), получится другой рисунок.

Для обычного правильного многоугольника — фигуры с одинаковыми сторонами и одинаковыми углами — полный обход даёт суммарный поворот \(360^\circ\).

Если сторон \(n\), одинаковый поворот на каждом шаге равен:

\[
\frac{360^\circ}{n}.
\]

Например:

| Фигура | Число сторон | Поворот при обходе |
|---|---:|---:|
| Равносторонний треугольник | 3 | \(120^\circ\) |
| Квадрат | 4 | \(90^\circ\) |
| Правильный шестиугольник | 6 | \(60^\circ\) |
| Правильный восьмиугольник | 8 | \(45^\circ\) |

Эта связь применима к последовательному обходу такого многоугольника. В алгоритмах с несколькими перемещениями и разными поворотами внутри одного повторения рисунок нужно исследовать по самим командам.

**Модуль `turtle` — это готовый набор команд для управления Черепахой.**

Модулем в Python называют набор заранее написанных инструментов, которые можно подключить к своей программе.

Подключим `turtle` так:

```python
import turtle as t
```

Разберём запись:

- `import turtle` — подключить модуль `turtle`;
- `as t` — обращаться к нему под коротким именем `t`.

После этого команда движения записывается так:

```python
t.forward(100)
```

Точка между `t` и `forward` показывает, что мы используем команду из подключённого модуля.

Число в скобках сообщает команде, насколько далеко нужно переместиться. Значения, передаваемые команде в скобках, называют **аргументами**.

Для ЕГЭ основные соответствия такие:

| Команда в условии | Команда Python |
|---|---|
| Вперёд \(n\) | `t.forward(n)` |
| Назад \(n\) | `t.backward(n)` |
| Направо \(m\) | `t.right(m)` |
| Налево \(m\) | `t.left(m)` |
| Поднять хвост | `t.penup()` |
| Опустить хвост | `t.pendown()` |

У некоторых команд есть короткие формы:

| Полная запись | Короткая запись |
|---|---|
| `t.forward(n)` | `t.fd(n)` |
| `t.backward(n)` | `t.bk(n)` |
| `t.right(m)` | `t.rt(m)` |
| `t.left(m)` | `t.lt(m)` |
| `t.penup()` | `t.up()` |
| `t.pendown()` | `t.down()` |

Обе формы выполняют одно действие.

На первых этапах полные названия удобнее: по ним легче увидеть смысл программы.

В чужих решениях также встречается:

```python
from turtle import *
```

Тогда команды пишут без `t.`:

```python
forward(100)
right(90)
```

В наших примерах используется первый вариант:

```python
import turtle as t
```

Поэтому команды Черепахи будут иметь начало `t.`.

**Начальное направление лучше устанавливать явно.**

Чтобы направить Черепаху вверх, используем:

```python
t.setheading(90)
```

Название можно понимать как «установить направление».

Эта команда задаёт конкретное направление независимо от того, куда Черепаха смотрела раньше.

Сравни:

```python
t.left(90)
```

и:

```python
t.setheading(90)
```

Первая команда означает:

> Повернуть налево на 90 градусов от текущего направления.

Вторая:

> Установить направление 90 градусов, то есть вверх.

Если Черепаха смотрит вправо, результат совпадёт.

Если она смотрит влево, результат будет различаться:

- после `left(90)` она будет смотреть вниз;
- после `setheading(90)` — вверх.

Для начала программы явная установка помогает избежать ошибки:

```python
t.setheading(90)
```

Но дальше нужно выполнять повороты из условия. Если произвольно устанавливать направление в середине алгоритма, мы изменим его работу.

**Запись «Повтори» переводится в Python с помощью цикла.**

Цикл — это конструкция, которая несколько раз выполняет один и тот же блок команд.

Например:

```text
Повтори 4 [
    Вперёд 5
    Направо 90
]
```

переводится так:

```python
for i in range(4):
    t.forward(5)
    t.right(90)
```

Запись:

```python
range(4)
```

даёт последовательность:

```text
0, 1, 2, 3
```

В ней четыре числа. Для каждого числа выполняются команды с отступом.

Переменная `i` — имя, которому последовательно присваиваются эти значения:

- при первом выполнении блока `i = 0`;
- при втором `i = 1`;
- при третьем `i = 2`;
- при четвёртом `i = 3`.

В этом алгоритме значение `i` не используется. Оно только сопровождает повторения.

Поэтому часто пишут:

```python
for _ in range(4):
    t.forward(5)
    t.right(90)
```

Символ `_` здесь — обычное имя переменной. Его принято использовать, когда само значение не понадобится.

**Один проход по повторяемому блоку называют итерацией.**

В нашем примере одна итерация — это:

```python
t.forward(5)
t.right(90)
```

Сначала выполняются обе команды первого повторения. Потом обе команды второго. И так далее.

Алгоритм не означает «сначала четыре раза двигаться, затем четыре раза поворачиваться».

---

**Отступы в Python определяют, какие команды входят в повторение.**

Правильный перевод:

```python
for _ in range(4):
    t.forward(5)
    t.right(90)
```

Здесь и перемещение, и поворот повторяются четыре раза.

Другая программа:

```python
for _ in range(4):
    t.forward(5)

t.right(90)
```

работает иначе:

1. Черепаха четыре раза идёт вперёд.
2. Один раз поворачивается.

При начальном направлении вверх получится длинный вертикальный отрезок, после которого Черепаха повернёт голову.

Поэтому при переводе команды `Повтори` нужно сохранить:

- число повторений;
- порядок команд;
- состав повторяемого блока.

Удобно использовать четыре пробела для каждого уровня отступа.

**В одном повторении может рисоваться несколько сторон.**

Рассмотрим алгоритм:

```text
Повтори 2 [
    Вперёд 6
    Направо 90
    Вперёд 8
    Направо 90
]
```

Предположим, что Черепаха начинает в \((0;0)\), смотрит вверх, хвост опущен.

Первое повторение:

1. Поднимается на 6 единиц.
2. Поворачивается вправо.
3. Идёт вправо на 8 единиц.
4. Поворачивается вниз.

Второе повторение:

1. Идёт вниз на 6 единиц.
2. Поворачивается влево.
3. Идёт влево на 8 единиц.
4. Поворачивается вверх.

Получается прямоугольник шириной 8 и высотой 6.

Перевод:

```python
for _ in range(2):
    t.forward(6)
    t.right(90)
    t.forward(8)
    t.right(90)
```

В одной итерации рисуются две стороны. Поэтому двух повторений достаточно для четырёх сторон.

**Количество повторений не обязано совпадать с количеством сторон фигуры.**

**Для удобного рисунка нужно ввести масштаб.**

Если выполнить:

```python
t.forward(6)
```

на экране появится очень короткий отрезок.

В стандартных настройках единица движения `turtle` соответствует примерно одному пикселю — маленькому элементу изображения на экране.

Для задачи это неудобно: фигуру нужно рассматривать и считать точки.

Поэтому договоримся, что одна единица из условия занимает, например, 30 экранных единиц.

Запишем:

```python
k = 30
```

Переменная — это имя, которому в программе соответствует некоторое значение. Здесь имени `k` соответствует число 30.

Тогда команда `Вперёд 6` переводится так:

```python
t.forward(6 * k)
```

Черепаха пройдёт:

\[
6\cdot30=180
\]

экранных единиц.

При этом в самой задаче длина стороны по-прежнему равна 6.

Важно различать:

| Величина | Значение |
|---|---:|
| Длина в условии | 6 |
| Масштаб | 30 |
| Длина на экране | 180 |

Масштаб увеличивает изображение, чтобы его было удобно исследовать.

---

**На масштаб умножаются расстояния и координаты.**

Если одна единица задачи занимает 30 экранных единиц, то:

- расстояние 5 нужно изображать как \(5\cdot30\);
- точку \((2;3)\) нужно изображать в экранных координатах \((60;90)\).

Поэтому:

```python
t.forward(5 * k)
```

и:

```python
t.goto(2 * k, 3 * k)
```

используют один масштаб.

Поворот при увеличении рисунка остаётся тем же:

```python
t.right(90)
```

Запись:

```python
t.right(90 * k)
```

изменила бы угол поворота и сам алгоритм.

Размер отметки точки мы тоже обычно оставляем небольшим:

```python
t.dot(3, "red")
```

Здесь число 3 — размер видимого кружочка. Он нужен только для удобства просмотра.

---

**Построим первую полную программу.**

Алгоритм задачи:

```text
Повтори 2 [
    Вперёд 6
    Направо 90
    Вперёд 8
    Направо 90
]
```

Начальное состояние:

- координаты \((0;0)\);
- направление вверх;
- хвост опущен.

Программа:

```python
import turtle as t

k = 30

t.setup(900, 800)
t.tracer(0)
t.pensize(2)

t.setheading(90)
t.pendown()

for _ in range(2):
    t.forward(6 * k)
    t.right(90)
    t.forward(8 * k)
    t.right(90)

t.penup()
t.hideturtle()

for x in range(-2, 13):
    for y in range(-2, 11):
        t.goto(x * k, y * k)
        t.dot(3, "red")

t.update()
t.done()
```

В программе есть три смысловые части:

1. Подготовка окна и Черепахи.
2. Выполнение алгоритма из условия.
3. Нанесение целочисленных точек.

Две последние строки показывают результат и оставляют окно открытым.

---

**Служебные команды управляют отображением рисунка.**

Разберём строки, которые пока не объясняли.

```python
t.setup(900, 800)
```

Задаёт размер окна: ширина 900, высота 800.

```python
t.tracer(0)
```

Отключает постепенную анимацию. Это ускоряет построение, особенно когда нужно нанести много точек.

После такого режима мы явно показываем итог:

```python
t.update()
```

```python
t.pensize(2)
```

Задаёт толщину нарисованной линии.

```python
t.hideturtle()
```

Скрывает значок Черепахи. Сам рисунок остаётся.

Это удобно: стрелка не закрывает точки у границы.

```python
t.done()
```

Запускает ожидание событий окна, чтобы рисунок можно было рассматривать до закрытия.

Эту строку ставят в конце.

Для учебного просмотра движения можно временно убрать `tracer(0)` и задать:

```python
t.speed(3)
```

Тогда Черепаха будет двигаться постепенно.

Значение:

```python
t.speed(0)
```

означает максимальную скорость без анимации перемещения. Ноль здесь не означает остановку.

---

**Целочисленные точки наносятся двумя вложенными циклами.**

Посмотрим на фрагмент:

```python
for x in range(-2, 13):
    for y in range(-2, 11):
        t.goto(x * k, y * k)
        t.dot(3, "red")
```

Сначала разберём `range`.

Запись:

```python
range(a, b)
```

даёт целые числа от `a` до `b - 1`.

Правая граница `b` не включается.

Поэтому:

```python
range(-2, 13)
```

даёт:

```text
-2, -1, 0, 1, ..., 11, 12
```

А:

```python
range(-2, 11)
```

даёт:

```text
-2, -1, 0, 1, ..., 9, 10
```

Теперь посмотрим на два цикла вместе.

Внешний цикл выбирает значение \(x\).

Для каждого выбранного \(x\) внутренний цикл перебирает все значения \(y\).

Например, при \(x=-2\) отмечаются точки:

\[
(-2;-2),\ (-2;-1),\ (-2;0),\ldots,(-2;10).
\]

После этого внешний цикл выбирает \(x=-1\), и отмечаются:

\[
(-1;-2),\ (-1;-1),\ldots,(-1;10).
\]

Получаются все сочетания выбранных целых значений \(x\) и \(y\).

Цикл, находящийся внутри другого цикла, называют **вложенным**.

---

**Переменные `x` и `y` сами по себе не перемещают Черепаху.**

Строка:

```python
for x in range(-2, 13):
```

только присваивает переменной `x` очередное число.

Перемещение выполняет команда:

```python
t.goto(x * k, y * k)
```

`goto` означает «перейти в указанную точку».

Это переход по абсолютным координатам.

Например:

```python
t.goto(100, 50)
```

перемещает Черепаху в точку \((100;50)\), независимо от её прежнего положения и направления.

При этом направление головы не меняется.

Это отличается от:

```python
t.forward(100)
```

Здесь новая точка зависит от текущего положения и направления.

Для нанесения сетки удобнее `goto`: нам известны координаты каждой нужной точки.

---

**Перед нанесением сетки хвост нужно поднять.**

Используем:

```python
t.penup()
```

Если оставить хвост опущенным, переходы между точками сетки будут оставлять линии.

Вместо аккуратных отметок получится множество дополнительных отрезков, которые затруднят чтение фигуры.

При поднятом хвосте:

```python
t.goto(...)
```

перемещает Черепаху без линии.

Но:

```python
t.dot(3, "red")
```

всё равно рисует точку. Эта команда специально ставит отметку независимо от состояния пера.

Следовательно:

```python
t.penup()
t.goto(60, 90)
t.dot(3, "red")
```

означает:

1. Переместиться в \((60;90)\) без линии.
2. Поставить там красную отметку.

---

**Фигура и сетка обязательно должны использовать один масштаб.**

Правильное сочетание:

```python
t.forward(6 * k)
```

и:

```python
t.goto(x * k, y * k)
```

Предположим, \(k=30\).

Сторона длиной 6 занимает на экране 180 единиц. Соседние точки решётки находятся через 30 экранных единиц. Получается ровно шесть единичных промежутков вдоль стороны.

Если фигуру построить с масштабом:

```python
t.forward(6 * k)
```

а сетку нанести без него:

```python
t.goto(x, y)
```

точки окажутся скучены около начала координат. Они будут соответствовать другой системе единиц.

Аналогичная проблема возникнет, если фигура использует один коэффициент, а сетка другой.

**Значение масштаба можно менять, но оно должно согласованно применяться ко всему рисунку и сетке.**

---

**Диапазоны сетки нужно выбирать по расположению фигуры.**

В нашем прямоугольнике:

\[
0\le x\le8,
\qquad
0\le y\le6.
\]

Поэтому достаточно нанести точки в этой области. Мы взяли немного больше:

```python
range(-2, 13)
range(-2, 11)
```

Запас полезен: вокруг фигуры видны внешние точки, и легче различать границу.

У другой задачи рисунок может оказаться:

- левее начала координат;
- ниже начала координат;
- сразу в нескольких частях плоскости.

Тогда диапазоны должны охватывать соответствующие координаты.

Например:

```python
for x in range(-15, 16):
    for y in range(-12, 13):
        t.goto(x * k, y * k)
        t.dot(3, "red")
```

отмечает точки для:

\[
-15\le x\le15,
\qquad
-12\le y\le12.
\]

Здесь числа в `range` — координаты **в единицах задачи**. Умножение на `k` выполняется при переходе к экранным координатам.

---

**При подсчёте нужно различать точки внутри, точки на границе и точки снаружи.**

Граница фигуры — линия, которая отделяет её внутреннюю область от внешней.

У нашего прямоугольника границу составляют четыре стороны.

Например:

- \((3;2)\) — внутри;
- \((0;4)\) — на левой стороне;
- \((8;6)\) — вершина, то есть тоже граница;
- \((9;3)\) — снаружи.

Если спрашивают **строго внутри**, точки на сторонах и вершинах исключаются.

Если спрашивают **внутри и на границе**, они включаются.

Вершины не являются отдельной категорией, которую можно забыть. Они принадлежат границе.

На рисунке линия имеет некоторую толщину, а точка выглядит кружочком. В математической задаче точка не имеет размера, а линия не имеет толщины.

Поэтому проверяется положение **центра отметки**.

Если красный кружочек немного касается чёрной линии, это ещё не означает, что математическая точка лежит на границе.

---

**Точки удобнее считать по горизонтальным рядам или вертикальным столбцам.**

Считать их в случайном порядке неудобно: можно пропустить точку или учесть её дважды.

У нашего прямоугольника строго внутри находятся точки с координатами:

\[
x=1,2,3,4,5,6,7
\]

и:

\[
y=1,2,3,4,5.
\]

Есть 7 допустимых значений \(x\) и 5 допустимых значений \(y\).

Каждому значению \(y\) соответствует горизонтальный ряд из 7 точек.

Всего:

\[
7\cdot5=35.
\]

Это число можно получить и по столбцам: 7 столбцов по 5 точек.

При наклонной границе длина рядов обычно различается. Тогда удобнее записать количество точек в каждом ряду и сложить результаты.

Например:

\[
3+5+7+7+5+3.
\]

Такая запись позволяет проверить каждый ряд отдельно.

---

**Количество точек на отрезке связано с количеством промежутков между ними.**

Рассмотрим отрезок от 0 до 8.

Целые координаты на нём:

\[
0,1,2,3,4,5,6,7,8.
\]

Его длина равна 8, но точек вместе с концами — 9.

Между соседними точками находится один единичный промежуток. У восьми промежутков девять концов.

Если исключить концы отрезка, останутся:

\[
1,2,3,4,5,6,7,
\]

то есть 7 точек.

Для горизонтального или вертикального отрезка с целочисленными концами и длиной \(a\):

- вместе с концами — \(a+1\) целых точек;
- строго между концами — \(a-1\), если \(a\ge1\).

Для наклонного отрезка это правило по его длине не действует. Например, отрезок из \((0;0)\) в \((3;4)\) имеет длину 5, но только две целочисленные точки — его концы. Внутри него целых точек нет: на прямой \(y=4x/3\) при \(x=1\) и \(x=2\) координата \(y\) нецелая.

Именно отсюда берутся добавление и вычитание единицы в формулах для прямоугольника.

---

**Для прямоугольника с целочисленными вершинами и сторонами вдоль осей подсчёт сводится к умножению.**

Пусть ширина прямоугольника равна \(a\), высота — \(b\), причём обе положительны и целочисленны.

Тогда:

\[
N_{\text{внутри}}=(a-1)(b-1).
\]

Почему?

Внутри есть:

- \(a-1\) допустимых целых координат по горизонтали;
- \(b-1\) по вертикали.

Каждая горизонтальная координата может сочетаться с каждой вертикальной.

Вместе с границей:

\[
N_{\text{вместе с границей}}=(a+1)(b+1).
\]

Для нашего примера \(a=8\), \(b=6\):

\[
N_{\text{внутри}}=7\cdot5=35,
\]

\[
N_{\text{вместе с границей}}=9\cdot7=63.
\]

Только на границе:

\[
N_{\text{граница}}=63-35=28.
\]

Для такого прямоугольника можно получить общую формулу:

\[
N_{\text{граница}}=2a+2b.
\]

Её можно вывести непосредственно:

- на двух горизонтальных сторонах по \(a+1\) точке;
- на двух вертикальных по \(b+1\);
- каждая из четырёх вершин посчитана дважды.

Следовательно:

\[
2(a+1)+2(b+1)-4=2a+2b.
\]

Условия применения здесь существенны: стороны должны идти вдоль осей, а координаты вершин должны быть целыми.

Для наклонного прямоугольника такой подсчёт по ширине и высоте автоматически использовать нельзя.

---

**Количество точек, площадь и периметр отвечают на разные вопросы.**

Для прямоугольника \(8\times6\):

| Что требуется найти | Расчёт | Результат |
|---|---|---:|
| Точки строго внутри | \(7\cdot5\) | 35 |
| Точки внутри и на границе | \(9\cdot7\) | 63 |
| Точки только на границе | \(63-35\) | 28 |
| Площадь | \(8\cdot6\) | 48 |
| Периметр | \(2(8+6)\) | 28 |

Площадь показывает, сколько единичных квадратов занимает область.

Периметр показывает длину её контура.

Количество целочисленных точек показывает, сколько узлов координатной решётки попало в указанную область.

В этом примере число граничных точек совпало с числом, выражающим периметр. Такое совпадение объясняется расположением сторон вдоль осей и целыми координатами вершин.

Из него нельзя делать общий вывод для любых фигур.

---

**Повторное прохождение по линии не создаёт новых математических точек.**

Рассмотрим:

```text
Повтори 8 [
    Вперёд 5
    Направо 90
]
```

Первые четыре повторения рисуют квадрат.

Следующие четыре повторения проходят по тому же квадрату ещё раз.

Если спрашивают количество точек внутри области, квадрат учитывается один раз.

Но если бы спрашивали, какое расстояние прошла Черепаха, учитывались бы все восемь перемещений:

\[
8\cdot5=40.
\]

Различай:

- нарисованную геометрическую фигуру;
- весь пройденный путь.

Одна линия может быть пройдена несколько раз.

---

**Повторяющийся рисунок ещё не означает одинаковое конечное состояние Черепахи.**

Это особенно важно, если после одного цикла начинается следующий алгоритм.

Например, треугольник может быть полностью нарисован после трёх повторений. Но если в условии указано семь, нужно выполнить семь.

После лишнего повторения Черепаха может оказаться в другой вершине и смотреть в другую сторону.

Если сократить цикл ради «того же рисунка», следующий участок алгоритма начнётся неправильно.

При анализе повторений полезно проверять:

1. Вернулась ли Черепаха в прежнюю точку?
2. Вернулось ли прежнее направление?
3. Совпадает ли состояние хвоста?

Если полностью совпало состояние и дальше выполняются те же команды, маршрут повторится.

Сам по себе суммарный поворот \(360^\circ\) гарантирует восстановление направления, но не гарантирует возвращение в исходную точку.

Например:

```text
Вперёд 5
Направо 90
Вперёд 7
Направо 270
```

даёт полный суммарный правый поворот \(360^\circ\). Однако при старте вверх Черепаха заканчивает в \((7;5)\), а не в \((0;0)\).

---

**Практический порядок решения можно сделать постоянным.**

Для каждой новой задачи проходи одну последовательность:

1. **Прочитай, что требуется найти.** Точки, площадь, периметр? Внутри какой области? Учитывается ли граница?
2. **Выпиши начальное состояние.** Координаты, направление, состояние хвоста.
3. **Переведи команды в Python.** Сохрани порядок и число повторений.
4. **Умножь все расстояния на один масштаб.**
5. **Построй фигуру.**
6. **Подними перо и нанеси целочисленные точки.**
7. **Проверь, что сетка охватывает весь рисунок.**
8. **Выдели именно ту область, которую спрашивают.**
9. **Посчитай точки по рядам или столбцам.**
10. **Проверь спорные точки и условие о границе.**

Для первых задач полезно перед запуском приблизительно предсказывать рисунок.

Например:

> Сначала вверх, затем вправо, затем вниз, затем влево. Должен получиться прямоугольник.

Если программа показывает другую фигуру, нужно искать ошибку в переводе команд.

---

**При рисовании нескольких фигур положение и направление продолжают сохраняться.**

Разберём более сложный алгоритм:

```text
Повтори 2 [
    Вперёд 6
    Направо 90
    Вперёд 8
    Направо 90
]

Поднять хвост

Вперёд 2
Направо 90
Вперёд 3
Налево 90

Опустить хвост

Повтори 2 [
    Вперёд 5
    Направо 90
    Вперёд 7
    Направо 90
]
```

Начальное направление — вверх.

Первый блок рисует уже знакомый прямоугольник:

\[
0\le x\le8,
\qquad
0\le y\le6.
\]

После двух повторений Черепаха вернулась в \((0;0)\) и смотрит вверх.

Далее хвост поднимается.

Перемещения между фигурами:

| Команда | Положение после команды | Направление |
|---|---|---|
| Вперёд 2 | \((0;2)\) | Вверх |
| Направо 90 | \((0;2)\) | Вправо |
| Вперёд 3 | \((3;2)\) | Вправо |
| Налево 90 | \((3;2)\) | Вверх |

Теперь хвост опускается.

Вторая фигура начинается в \((3;2)\). Её высота 5, ширина 7.

Поэтому она занимает область:

\[
3\le x\le10,
\qquad
2\le y\le7.
\]

Для построения замени в полном шаблоне блок алгоритма таким:

```python
# Первая фигура
for _ in range(2):
    t.forward(6 * k)
    t.right(90)
    t.forward(8 * k)
    t.right(90)

# Переход к началу второй фигуры без рисования
t.penup()

t.forward(2 * k)
t.right(90)
t.forward(3 * k)
t.left(90)

t.pendown()

# Вторая фигура
for _ in range(2):
    t.forward(5 * k)
    t.right(90)
    t.forward(7 * k)
    t.right(90)
```

После этого, как и раньше, поднимаем перо и наносим сетку.

Поднятие хвоста позволяет переместиться к началу второй фигуры, не добавляя соединительную линию.

---

**Пересечение фигур — это их общая часть.**

Точка принадлежит пересечению, если она принадлежит **обеим** фигурам.

В нашем примере первая фигура занимает:

\[
0\le x\le8,\qquad 0\le y\le6.
\]

Вторая:

\[
3\le x\le10,\qquad 2\le y\le7.
\]

Чтобы точка находилась в обеих фигурах, её координата \(x\) должна одновременно удовлетворять двум условиям:

\[
0\le x\le8
\]

и:

\[
3\le x\le10.
\]

Общие значения:

\[
3\le x\le8.
\]

Для координаты \(y\):

\[
2\le y\le6.
\]

Поэтому пересечение — прямоугольник:

\[
3\le x\le8,
\qquad
2\le y\le6.
\]

Его ширина:

\[
8-3=5.
\]

Высота:

\[
6-2=4.
\]

Если граница учитывается, допустимы:

\[
x=3,4,5,6,7,8
\]

и:

\[
y=2,3,4,5,6.
\]

Получаем:

\[
6\cdot5=30
\]

точек.

Если нужны точки строго внутри пересечения:

\[
3<x<8,\qquad 2<y<6.
\]

Допустимы:

\[
x=4,5,6,7
\]

и:

\[
y=3,4,5.
\]

Получаем:

\[
4\cdot3=12.
\]

Площадь пересечения:

\[
5\cdot4=20.
\]

Периметр пересечения:

\[
2(5+4)=18.
\]

Сначала определяется общая область, затем к ней применяется нужный способ подсчёта.

---

**Границы пересечения прямоугольников можно находить через максимумы и минимумы.**

Пусть первый прямоугольник задан границами:

\[
x_1\le x\le x_2,\qquad y_1\le y\le y_2.
\]

Второй:

\[
u_1\le x\le u_2,\qquad v_1\le y\le v_2.
\]

Тогда общая область имеет границы:

\[
x_{\text{лев}}=\max(x_1,u_1),
\]

\[
x_{\text{прав}}=\min(x_2,u_2),
\]

\[
y_{\text{низ}}=\max(y_1,v_1),
\]

\[
y_{\text{верх}}=\min(y_2,v_2).
\]

Почему слева берём максимум?

Чтобы находиться в обоих прямоугольниках, точка должна пройти более строгую из двух левых границ.

Почему справа минимум?

Она не должна выйти за более близкую из двух правых границ.

Например:

\[
x\ge0,\quad x\ge3
\]

вместе означают:

\[
x\ge3.
\]

А:

\[
x\le8,\quad x\le10
\]

вместе означают:

\[
x\le8.
\]

Если получилось:

\[
x_{\text{лев}}>x_{\text{прав}}
\]

или:

\[
y_{\text{низ}}>y_{\text{верх}},
\]

общих точек нет.

---

**Объединение фигур содержит точки, которые находятся хотя бы в одной фигуре.**

Для объединения подходят точки:

- только в первой фигуре;
- только во второй;
- в обеих одновременно.

В нашем примере, с учётом границ:

- в первой фигуре 63 точки;
- во второй:

\[
(7+1)(5+1)=48
\]

точек;
- в пересечении 30 точек.

Если сложить:

\[
63+48,
\]

общие точки будут посчитаны дважды.

Поэтому один их экземпляр нужно убрать:

\[
N_{\text{объединение}}=63+48-30=81.
\]

Общий принцип:

\[
N_{\text{объединение}}
=
N_{\text{первая}}
+
N_{\text{вторая}}
-
N_{\text{пересечение}}.
\]

Он работает для количества различных точек в соответствующих областях.

Аналогично для площади:

\[
S_{\text{объединение}}
=
S_{\text{первая}}
+
S_{\text{вторая}}
-
S_{\text{пересечение}}.
\]

В нашем примере:

\[
48+35-20=63.
\]

Число 63 здесь выражает площадь объединения. Ранее таким же числом выражалось количество точек первого прямоугольника вместе с границей. Это разные величины, которые случайно совпали численно.

---

**Фраза «только в одной фигуре» исключает общую часть.**

Если требуется посчитать точки, принадлежащие ровно одной из двух фигур, подходят:

- точки первой фигуры вне второй;
- точки второй фигуры вне первой.

Точки пересечения исключаются полностью.

При сложении \(N_{\text{первая}}+N_{\text{вторая}}\) они входят дважды. Поэтому нужно вычесть их дважды:

\[
N_{\text{ровно одна}}
=
N_{\text{первая}}
+
N_{\text{вторая}}
-
2N_{\text{пересечение}}.
\]

Для нашего примера с границами:

\[
63+48-2\cdot30=51.
\]

Если требуется только часть первой фигуры, которая не принадлежит второй:

\[
63-30=33.
\]

Смысл формулировок удобно сравнить:

| Формулировка | Какие точки подходят |
|---|---|
| В пересечении | В обеих фигурах |
| В объединении | Хотя бы в одной |
| Ровно в одной | В одной, но не в обеих |
| В первой, вне второй | В первой и одновременно не во второй |

При использовании этих формул условия принадлежности должны совпадать: нельзя одно количество брать вместе с границей, другое строго внутри, а третье по ещё одному правилу.

---

**Наклонные стороны удобно исследовать по той же сетке.**

Модуль `turtle` самостоятельно выполняет движения под любыми указанными углами.

Например:

```text
Повтори 7 [
    Вперёд 8
    Направо 120
]
```

Начальное направление — вверх.

Перевод:

```python
for _ in range(7):
    t.forward(8 * k)
    t.right(120)
```

После трёх повторений получается равносторонний треугольник со стороной 8.

Следующие три повторения проходят по нему ещё раз.

Седьмое повторение проходит по первой стороне в третий раз.

Таким образом, область остаётся одним треугольником.

**Семь повторений здесь не означают семь разных сторон.**

---

**Рассчитаем положение треугольника, чтобы понять его границы.**

Обозначим вершины:

\[
A=(0;0),
\qquad
B=(0;8).
\]

Третья вершина находится справа от вертикальной стороны \(AB\).

Поскольку расстояния от неё до \(A\) и \(B\) одинаковы, она расположена на уровне середины этой стороны:

\[
y=4.
\]

Обозначим её горизонтальное удаление от оси \(Oy\) через \(h\).

Получается прямоугольный треугольник:

- одна сторона равна 4;
- другая равна \(h\);
- наклонная сторона равна 8.

По теореме Пифагора:

\[
h^2+4^2=8^2.
\]

Значит:

\[
h^2=64-16=48,
\]

\[
h=\sqrt{48}=4\sqrt3.
\]

Поэтому третья вершина:

\[
C=(4\sqrt3;4).
\]

Приближённо:

\[
C\approx(6{,}928;4).
\]

Черепаха может оказаться в точке с нецелыми координатами, хотя длины всех движений были целыми.

Причина — наклонное направление.

Целочисленные длины команд не гарантируют целочисленные координаты всех вершин.

---

**Внутри этого треугольника нужно считать точки между двумя наклонными сторонами.**

Нижняя наклонная сторона проходит через:

\[
(0;0)
\]

и:

\[
(4\sqrt3;4).
\]

При увеличении \(x\) на \(4\sqrt3\) координата \(y\) увеличивается на 4.

Поэтому отношение вертикального изменения к горизонтальному равно:

\[
\frac{4}{4\sqrt3}=\frac1{\sqrt3}.
\]

На этой стороне:

\[
y=\frac{x}{\sqrt3}.
\]

Верхняя наклонная сторона начинается в \((0;8)\) и спускается с такой же крутизной:

\[
y=8-\frac{x}{\sqrt3}.
\]

Строго внутри треугольника:

\[
x>0
\]

и:

\[
\frac{x}{\sqrt3}<y<8-\frac{x}{\sqrt3}.
\]

Но для основного способа через `turtle` можно просто построить треугольник и посчитать отметки по столбцам.

Для целых положительных \(x\) получаем:

| \(x\) | Допустимые целые \(y\) внутри | Количество |
|---:|---|---:|
| 1 | 1, 2, 3, 4, 5, 6, 7 | 7 |
| 2 | 2, 3, 4, 5, 6 | 5 |
| 3 | 2, 3, 4, 5, 6 | 5 |
| 4 | 3, 4, 5 | 3 |
| 5 | 3, 4, 5 | 3 |
| 6 | 4 | 1 |

При \(x=7\) мы уже правее третьей вершины, поскольку:

\[
7>4\sqrt3.
\]

Сумма:

\[
7+5+5+3+3+1=24.
\]

**Строго внутри треугольника находятся 24 целочисленные точки.**

Такой подсчёт хорошо проверяется: для каждого столбца отдельно определяются нижняя и верхняя допустимые точки.

---

**Для треугольника граница тоже должна исследоваться отдельно.**

На вертикальной стороне \(x=0\) находятся точки:

\[
(0;0),(0;1),\ldots,(0;8).
\]

Их 9.

На наклонной стороне:

\[
y=\frac{x}{\sqrt3}
\]

при ненулевом целом \(x\) значение \(y\) не будет целым.

На второй наклонной стороне ситуация аналогичная.

Поэтому целочисленные точки на границе этого треугольника — только 9 точек вертикальной стороны.

Вместе с границей:

\[
24+9=33.
\]

Обрати внимание: третья вершина не учитывается как целочисленная точка, потому что её координата \(x=4\sqrt3\) нецелая.

И ещё один важный вывод: **наклонная сторона в других задачах вполне может проходить через целочисленные точки**.

Например, отрезок на прямой:

\[
y=x
\]

может содержать точки:

\[
(1;1),(2;2),(3;3).
\]

Нельзя исключать все точки на наклонных сторонах только из-за наклона.

---

**Седьмое повторение в примере с треугольником влияет на конечное состояние.**

После трёх повторений Черепаха находится в \((0;0)\) и снова смотрит вверх.

После шести — то же самое.

На седьмом повторении:

1. Идёт вверх на 8.
2. Оказывается в \((0;8)\).
3. Поворачивается направо на \(120^\circ\).

Новое направление:

\[
90^\circ-120^\circ=-30^\circ,
\]

то есть:

\[
330^\circ.
\]

Итог после семи повторений:

- положение \((0;8)\);
- направление \(330^\circ\).

Если дальше в условии будут новые команды, они начнут выполняться именно из этого состояния.

Поэтому при переводе в Python оставляем:

```python
range(7)
```

даже если для изображения контура хватило бы трёх повторений.

---

**Наклонный четырёхугольник строится по тем же правилам.**

Рассмотрим:

```text
Повтори 4 [
    Вперёд 6
    Направо 60
    Вперёд 6
    Направо 120
]
```

Начальное направление — вверх.

Перевод:

```python
for _ in range(4):
    t.forward(6 * k)
    t.right(60)
    t.forward(6 * k)
    t.right(120)
```

За первое повторение Черепаха рисует две стороны и суммарно поворачивается на:

\[
60^\circ+120^\circ=180^\circ.
\]

За второе рисует оставшиеся две стороны и возвращается в исходное состояние.

Получается **ромб** — четырёхугольник с четырьмя равными сторонами.

Третье и четвёртое повторения проходят по нему ещё раз.

После построения и нанесения сетки можно посчитать внутренние точки по вертикальным столбцам:

| \(x\) | Целые \(y\) строго внутри | Количество |
|---:|---|---:|
| 1 | 1, 2, 3, 4, 5, 6 | 6 |
| 2 | 2, 3, 4, 5, 6, 7 | 6 |
| 3 | 2, 3, 4, 5, 6, 7 | 6 |
| 4 | 3, 4, 5, 6, 7, 8 | 6 |
| 5 | 3, 4, 5, 6, 7, 8 | 6 |

Всего:

\[
5\cdot6=30.
\]

Здесь у каждого столбца одинаковое количество внутренних точек, хотя верхняя и нижняя точки столбцов смещаются.

Для понимания этой задачи важно увидеть, что два поворота на \(60^\circ\) и \(120^\circ\) не превращают фигуру в прямоугольник. Нужно сохранить реальные команды и исследовать рисунок.

---

**Рисование сетки само по себе не подсчитывает ответ автоматически.**

В программе:

```python
for x in range(...):
    for y in range(...):
        t.goto(x * k, y * k)
        t.dot(3, "red")
```

отмечаются все выбранные точки:

- внутри;
- на границе;
- снаружи.

Команда `dot` не определяет, к какой категории относится точка.

Поэтому основной способ через `turtle` состоит из:

1. построения фигуры;
2. нанесения решётки;
3. визуального подсчёта нужных отметок.

Если точек очень много, можно дополнить рисунок проверкой координат.

Для этого сначала нужно понять, каким условиям удовлетворяют точки нужной области.

---

**Автоматический подсчёт начинается с условия принадлежности точки.**

Например, точка строго внутри нашего прямоугольника удовлетворяет:

\[
0<x<8
\]

и:

\[
0<y<6.
\]

В Python:

```python
0 < x < 8 and 0 < y < 6
```

Слово `and` означает «и». Нужно, чтобы одновременно выполнялись обе части.

Создадим переменную для количества:

```python
count = 0
```

Сначала ни одна точка ещё не посчитана.

Далее перебираем целые координаты:

```python
count = 0

for x in range(-5, 16):
    for y in range(-5, 16):
        if 0 < x < 8 and 0 < y < 6:
            count += 1

print(count)
```

Команда:

```python
if условие:
```

означает:

> Выполнить блок с отступом, если условие верно.

Запись:

```python
count += 1
```

равнозначна:

```python
count = count + 1
```

То есть увеличить счётчик на единицу.

Каждая подходящая точка увеличивает результат ровно один раз.

Программа выведет:

```text
35
```

Для точек вместе с границей изменяем сравнения:

```python
if 0 <= x <= 8 and 0 <= y <= 6:
```

Результат:

```text
63
```

Сам перебор можно взять с запасом. Лишние внешние точки не будут учтены, потому что не пройдут условие.

Но диапазон должен включать все потенциально подходящие точки.

---

**При подсчёте по координатам масштаб уже не нужен.**

Рисование использует:

```python
t.goto(x * k, y * k)
```

потому что нужно показать точку на экране.

Проверка:

```python
0 < x < 8
```

работает с координатами из условия задачи.

Поэтому в неё не нужно добавлять `k`.

Это две разные операции:

| Операция | Какие координаты используются |
|---|---|
| Показать точку в окне | Экранные: \(xk,\ yk\) |
| Проверить её принадлежность области | Координаты задачи: \(x,\ y\) |

Если подставлять масштабированные координаты в условие, границы тоже пришлось бы масштабировать. Проще и понятнее выполнять математическую проверку в исходных единицах.

---

**Для двух прямоугольников можно отдельно проверять принадлежность каждой фигуре.**

Для нашего примера:

```python
in_A = 0 <= x <= 8 and 0 <= y <= 6
in_B = 3 <= x <= 10 and 2 <= y <= 7
```

Каждое выражение даёт одно из двух значений:

- `True` — условие верно;
- `False` — условие неверно.

Такие значения называют **логическими**.

Имена `in_A` и `in_B` хранят ответы на вопросы:

> Принадлежит ли точка первой фигуре?

> Принадлежит ли точка второй фигуре?

Для пересечения:

```python
if in_A and in_B:
    count += 1
```

Для объединения:

```python
if in_A or in_B:
    count += 1
```

`or` означает «или»: достаточно принадлежности хотя бы одной фигуре. Если точка принадлежит обеим, она тоже подходит.

Для первой фигуры вне второй:

```python
if in_A and not in_B:
    count += 1
```

`not` меняет логическое значение на противоположное.

Для принадлежности ровно одной фигуре:

```python
if in_A != in_B:
    count += 1
```

Знак `!=` означает «не равно».

Два логических значения различаются, когда одно равно `True`, а другое `False`. Именно это и соответствует принадлежности ровно одной фигуре.

Каждое из этих условий нужно использовать в отдельном подсчёте, в зависимости от вопроса задачи.

---

**Для треугольника автоматическая проверка опирается на уже найденные наклонные границы.**

Мы получили:

\[
\frac{x}{\sqrt3}<y<8-\frac{x}{\sqrt3}.
\]

В Python квадратный корень удобно вычислять через модуль `math`:

```python
import math
```

Команда:

```python
math.sqrt(3)
```

вычисляет приближённое значение \(\sqrt3\).

Подсчёт:

```python
import math

count = 0

for x in range(1, 7):
    for y in range(1, 8):
        if x / math.sqrt(3) < y < 8 - x / math.sqrt(3):
            count += 1

print(count)
```

Программа выведет:

```text
24
```

Почему выбраны такие диапазоны?

По горизонтали:

\[
0<x<4\sqrt3\approx6{,}928.
\]

Подходящие целые значения:

\[
1,2,3,4,5,6.
\]

Их даёт:

```python
range(1, 7)
```

По вертикали все внутренние точки должны находиться между уровнями 0 и 8. Поэтому проверяем:

```python
range(1, 8)
```

Наклонные стороны затем отсекают лишние точки внутри этого охватывающего прямоугольника.

Этот пример показывает, как рисунок помогает сформулировать точное условие для проверки.

---

**Спорную точку у границы нужно проверять по геометрии, а не по толщине линии.**

На рисунке отметка может выглядеть почти лежащей на наклонной стороне.

В таком случае:

1. Определи координаты точки по сетке.
2. Установи, через какие вершины проходит сторона.
3. Проверь точку по уравнению стороны или другой известной связи.

Для стороны:

\[
y=x
\]

точка \((2;2)\) лежит на линии, потому что:

\[
2=2.
\]

Точка \((2;3)\) выше линии, потому что:

\[
3>2.
\]

Для стороны:

\[
y=\frac{x}{\sqrt3}
\]

точка \((3;2)\) находится выше линии:

\[
2>\frac3{\sqrt3}=\sqrt3\approx1{,}732.
\]

В треугольнике это означает, что точка прошла проверку нижней границы. После этого нужно проверить верхнюю.

Если одновременно:

\[
\frac{x}{\sqrt3}<y
\]

и:

\[
y<8-\frac{x}{\sqrt3},
\]

точка находится между сторонами.

---

**Вычисленные координаты могут содержать небольшую погрешность.**

При наклонном движении Python использует приближённые числовые вычисления.

Поэтому математический ноль иногда может отображаться как очень маленькое число, например:

```text
0.00000000000002
```

Для проверки положения можно вывести:

```python
print(t.xcor() / k, t.ycor() / k)
```

Команды:

- `t.xcor()` возвращает текущую горизонтальную координату;
- `t.ycor()` — вертикальную.

Деление на `k` возвращает координаты из экранных единиц в единицы задачи.

Для удобного отображения:

```python
print(
    round(t.xcor() / k, 6),
    round(t.ycor() / k, 6)
)
```

`round(число, 6)` округляет число до шести знаков после десятичной точки.

Но округление здесь используется для чтения результата. Нельзя автоматически округлять все координаты вершин до целых при математическом подсчёте.

Например:

\[
4\sqrt3\approx6{,}928.
\]

Если заменить эту координату числом 7, мы изменим границу фигуры.

---

**Конечное положение нужно проверять до нанесения сетки.**

Полезный диагностический фрагмент:

```python
print(
    "Координаты:",
    round(t.xcor() / k, 6),
    round(t.ycor() / k, 6)
)

print("Направление:", t.heading())
```

`t.heading()` возвращает текущее направление в градусах.

Эти строки нужно ставить сразу после алгоритма из условия.

Почему?

Сетка тоже рисуется перемещениями:

```python
t.goto(...)
```

Поэтому после нанесения всех точек Черепаха окажется в последней точке сетки.

Если вывести координаты после этого, ты получишь положение после вспомогательных действий, а не после исходного алгоритма.

Для задач с несколькими фигурами можно временно выводить состояние после каждого большого блока. Это помогает проверить, откуда начнётся следующий.

---

**При включении границ пересечение может оказаться отрезком или одной точкой.**

Рассмотрим два прямоугольника:

\[
A:\quad 0\le x\le3,\quad 0\le y\le2,
\]

\[
B:\quad 3\le x\le5,\quad 0\le y\le2.
\]

Они соприкасаются по стороне:

\[
x=3,\qquad 0\le y\le2.
\]

Общая область не имеет положительной площади. Но в ней есть три целочисленные точки:

\[
(3;0),\quad(3;1),\quad(3;2).
\]

Поэтому:

- площадь пересечения — 0;
- количество общих точек с учётом границ — 3;
- количество точек строго внутри пересечения — 0.

Если две фигуры соприкасаются только в одной целочисленной вершине, при включении границ ответ может быть 1.

Поэтому нулевая площадь не означает автоматически отсутствие общих точек.

---

**Граница объединения и границы отдельных фигур требуют внимательного чтения условия.**

Рассмотрим два соседних квадрата:

\[
A:\quad 0\le x\le2,\quad 0\le y\le2,
\]

\[
B:\quad 2\le x\le4,\quad 0\le y\le2.
\]

Вместе они образуют прямоугольник:

\[
0\le x\le4,\qquad 0\le y\le2.
\]

Точка:

\[
(2;1)
\]

лежит на общей стороне двух квадратов.

Относительно каждого отдельного квадрата она находится на границе.

Но относительно их объединения она находится **внутри** большого прямоугольника: общая сторона проходит внутри общей области.

Отсюда различие:

- «строго внутри хотя бы одной из исходных фигур» — точка не подходит;
- «строго внутри объединения» — точка подходит;
- «точки на всех нарисованных линиях не учитывать» — точка не подходит, поскольку общая сторона была нарисована.

Для объединения с включёнными границами обычная проверка `in_A or in_B` подходит.

Если исключается именно внешняя граница объединения, нельзя во всех случаях просто заменить принадлежность каждой фигуре на строгое вхождение. Сначала нужно понять, где проходит внешний контур объединённой области.

Это более тонкий случай. Его полезно знать, чтобы не превращать формулы в механическое правило.

---

**Подсчёт целых координат между нецелыми границами тоже можно сделать точно.**

Для начала вспомним целочисленные границы.

Если:

\[
2\le x\le6,
\]

подходят:

\[
2,3,4,5,6.
\]

Количество:

\[
6-2+1=5.
\]

Если:

\[
2<x<6,
\]

подходят:

\[
3,4,5.
\]

Количество:

\[
6-2-1=3.
\]

Но при нецелых границах правило «длина плюс один» напрямую не работает.

Например:

\[
2{,}3\le x\le6{,}8.
\]

Подходят:

\[
3,4,5,6.
\]

Чтобы описать общий способ, введём две операции.

**Округление вниз** — выбор наибольшего целого числа, которое не больше исходного:

\[
\lfloor6{,}8\rfloor=6.
\]

**Округление вверх** — выбор наименьшего целого числа, которое не меньше исходного:

\[
\lceil2{,}3\rceil=3.
\]

Для условия:

\[
a\le x\le b
\]

первое допустимое целое:

\[
\lceil a\rceil,
\]

последнее:

\[
\lfloor b\rfloor.
\]

Количество:

\[
N=\max\bigl(0,\lfloor b\rfloor-\lceil a\rceil+1\bigr).
\]

`max(0, ...)` означает, что при отсутствии подходящих целых чисел результат принимается равным нулю.

Для строгого условия:

\[
a<x<b
\]

получаем:

\[
N=\max\bigl(0,\lceil b\rceil-\lfloor a\rfloor-1\bigr).
\]

Эти формулы полезны для точного подсчёта в отдельных рядах наклонной фигуры.

На первых задачах удобнее выписывать допустимые числа непосредственно. Формулы становятся понятнее после нескольких таких примеров.

---

**Произвольный поворот фигуры может изменить количество целочисленных точек внутри.**

Площадь и длины сторон при повороте сохраняются. Но расположение фигуры относительно координатной решётки меняется.

Пример: квадрат со стороной 2.

Если его стороны идут вдоль осей и он занимает:

\[
0\le x\le2,\qquad 0\le y\le2,
\]

строго внутри находится одна целочисленная точка:

\[
(1;1).
\]

Если из начала координат построить квадрат той же стороны с начальным направлением \(45^\circ\), затем каждый раз поворачивать направо на \(90^\circ\), внутри окажутся две целочисленные точки:

\[
(1;0),\quad(2;0).
\]

Поэтому произвольно менять начальный угол ради удобства нельзя.

Перенос всей фигуры на целое число единиц по каждой оси сохраняет количество целочисленных точек. Каждая целочисленная точка при таком переносе переходит в целочисленную.

Поворот всей фигуры на \(90^\circ\) вокруг начала координат тоже сохраняет решётку.

Но при полном алгоритме безопаснее точно соблюдать условие: неверное начальное направление может повлиять на все последующие перемещения и взаимное расположение фигур.

---

**Если рисунок не помещается, сначала проверь масштаб и размеры окна.**

Есть несколько разных ситуаций.

**Фигура слишком маленькая.**

Увеличь:

```python
k = 30
```

например до:

```python
k = 40
```

После этого и стороны, и сетка увеличатся одинаково.

**Фигура слишком большая.**

Уменьши масштаб:

```python
k = 15
```

Но при большом количестве точек уменьшение может сделать подсчёт неудобным.

**Фигура уходит за край окна.**

Команда:

```python
t.setup(900, 800)
```

управляет размером видимого окна.

В чужих решениях часто встречается:

```python
t.screensize(2000, 2000)
```

Эта команда меняет размер области для рисования, а не размер самого окна. Скрытые части можно просматривать с помощью полос прокрутки. Разница между `setup` и `screensize` указана в документации Python. [Python 3.15.0 documentation](https://docs.python.org/3/library/turtle.html?utm_source=chatgpt.com)

**Фигура видна, но часть её не покрыта точками.**

Тогда проблема в диапазонах:

```python
range(...)
```

Нужно расширить диапазон \(x\), \(y\) или оба.

Расширение сетки само по себе не уменьшает фигуру и не увеличивает окно.

**Для первых запусков лучше использовать обычный локальный Python с графическим окном.**

Можно работать в редакторе, который запускает установленный Python, например в IDLE.

Практический порядок:

1. Создай файл программы.
2. Вставь полный код.
3. Сохрани файл.
4. Запусти его.
5. Рассмотри открывшееся окно Черепахи.

В IDLE код удобно запускать из окна редактора через `Run → Run Module`, обычно клавишей `F5`.

Некоторые онлайн-среды умеют выполнять Python, но не умеют открывать графическое окно `turtle`.

Если возникает ошибка об отсутствии `_tkinter`, среде не хватает графической части Tk, необходимой для работы `turtle`. [Python 3.15.0 documentation](https://docs.python.org/3/library/turtle.html?utm_source=chatgpt.com)

**Не называй свой файл `turtle.py`.**

Иначе при:

```python
import turtle
```

Python может попытаться подключить твой файл вместо стандартного модуля.

Подходящее имя:

```text
ege6_solution.py
```

---

**Ошибки в решениях обычно связаны с небольшим изменением исходного алгоритма.**

Проверяй их по следующей таблице:

| Ошибка | Что получается | Как проверить |
|---|---|---|
| Не учтено начальное направление | Рисунок повёрнут или расположен иначе | Сверить условие и `setheading` |
| Перепутаны `right` и `left` | Поворот в другую сторону | Проверить каждую команду |
| Угол умножен на масштаб | Изменяется геометрия | На `k` умножать расстояния |
| Масштаб сетки отличается от масштаба фигуры | Точки не соответствуют единицам задачи | Проверить `goto(x * k, y * k)` |
| Перед сеткой не поднято перо | Появляются лишние линии | Добавить `penup()` |
| Часть команд вышла из цикла | Меняется порядок повторений | Проверить отступы |
| Пропущено последнее значение `range` | Не нанесён крайний ряд | Помнить об исключённой правой границе |
| Сетка не охватывает отрицательные координаты | Часть точек отсутствует | Расширить диапазоны |
| Не прочитано условие о границе | Подсчитана другая категория точек | Проверить стороны и вершины |
| Объединение посчитано простым сложением | Общие точки учтены дважды | Вычесть пересечение |
| Цикл сокращён из-за повторения контура | Неверное состояние для следующего блока | Выполнить исходное число повторений |
| Координаты проверены после сетки | Выведено положение в последней точке сетки | Проверять сразу после алгоритма |

Есть ещё геометрическая ловушка: если линия не замкнулась, нельзя самостоятельно дорисовывать соединение между началом и концом и считать появившуюся область.

Например, три стороны квадрата ещё не ограничивают его внутреннюю область.

Команды заливки могут визуально соединять контур, поэтому для первичного исследования алгоритма достаточно обычных линий и сетки.

**Для проверки разберём ответы к практике.**

**1. Конечная точка — \((2;7)\), направление вверх.**

Последовательно:

\[
(0;0)
\rightarrow
(0;5)
\rightarrow
(3;5)
\rightarrow
(2;5)
\rightarrow
(2;7).
\]

Повороты изменяют направление между перемещениями. Команда `Назад 1` перемещает влево, но голова продолжает смотреть вправо.

**2. Получается прямоугольник шириной 7 и высотой 4.**

Два повторения полностью рисуют его. Третье повторно проходит по двум сторонам.

Строго внутри:

\[
(7-1)(4-1)=6\cdot3=18.
\]

Вместе с границей:

\[
(7+1)(4+1)=8\cdot5=40.
\]

После третьего повторения Черепаха находится в:

\[
(7;4)
\]

и смотрит вниз, то есть имеет направление \(270^\circ\).

**3. Получается квадрат со стороной 3 в области \(0\le x\le3,\ 0\le y\le3\).**

Строго внутри:

\[
(3-1)^2=4.
\]

Вместе с границей:

\[
(3+1)^2=16.
\]

**4. Перед сеткой нужно поднять перо и использовать тот же масштаб.**

Исправленный фрагмент:

```python
t.penup()

for x in range(-2, 9):
    for y in range(-2, 9):
        t.goto(x * k, y * k)
        t.dot(3, "red")
```

Первая правка убирает линии между отметками. Вторая согласует сетку с размерами фигуры.

**5. Пересечение задаётся условиями \(1\le x\le5,\ 2\le y\le4\).**

Вместе с границей:

\[
(5-1+1)(4-2+1)=5\cdot3=15.
\]

Строго внутри:

\[
1<x<5,\qquad2<y<4.
\]

Допустимы:

\[
x=2,3,4,\qquad y=3.
\]

Всего:

\[
3\cdot1=3.
\]

**6. В объединении находятся 31 точка.**

В первой фигуре:

\[
5\cdot4=20.
\]

Во второй:

\[
5\cdot4=20.
\]

Пересечение:

\[
2\le x\le4,\qquad1\le y\le3.
\]

В нём:

\[
3\cdot3=9.
\]

Итого:

\[
20+20-9=31.
\]

**7. Общая область — отрезок \(x=3,\ 0\le y\le2\).**

Площадь:

\[
0.
\]

Общих целочисленных точек с границами:

\[
3.
\]

Строго внутри пересечения:

\[
0.
\]

**8. Внутри треугольника находятся 13 точек.**

Повторения рисуют один равносторонний треугольник со стороной 6, затем повторно проходят по части его контура.

По столбцам:

| \(x\) | Допустимые \(y\) | Количество |
|---:|---|---:|
| 1 | 1, 2, 3, 4, 5 | 5 |
| 2 | 2, 3, 4 | 3 |
| 3 | 2, 3, 4 | 3 |
| 4 | 3 | 1 |
| 5 | 3 | 1 |

Сумма:

\[
5+3+3+1+1=13.
\]

**9. Внутри ромба находятся 12 точек.**

Начальное направление нужно установить вправо:

```python
t.setheading(0)
```

Алгоритм:

```python
for _ in range(4):
    t.forward(6 * k)
    t.right(150)
    t.forward(6 * k)
    t.right(30)
```

Для сетки подойдут, например:

```python
for x in range(-7, 9):
    for y in range(-5, 3):
        t.goto(x * k, y * k)
        t.dot(3, "red")
```

Перед этим нужно выполнить `t.penup()`.

Внутренние целочисленные точки находятся в двух горизонтальных рядах:

- при \(y=-1\): \(x=-1,0,1,2,3,4\);
- при \(y=-2\): \(x=-3,-2,-1,0,1,2\).

В каждом ряду по 6 точек:

\[
6+6=12.
\]
