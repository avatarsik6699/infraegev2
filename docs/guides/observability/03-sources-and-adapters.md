# 3. Sources и adapters

Теперь нужен ответ на два разных вопроса: «как вообще читать данные такого вида?» и «откуда именно
их читать в этой установке?».

## Adapter: способ получения и перевода

Adapter — переиспользуемая программа и контракт. Он знает:

- как подключиться к системе определённого типа;
- какие параметры ему нужны;
- как прочитать внешний формат;
- как перевести результат в Metric, Check или Event;
- как описать эти измерения для универсального UI.

Например, `host-metrics-ssh` умеет зайти по SSH и превратить сведения Linux о CPU, RAM и диске в
Metric. При этом в нём не должно быть зашито, что хост обязательно называется `infraegev2`.

## Source: конкретно настроенное подключение

Source — экземпляр adapter для определённой цели. Он связывает универсальный способ сбора с
реальным адресом и Project.

У Source есть:

- стабильный UUID;
- Project;
- имя adapter;
- открытая конфигурация и ссылки на зашифрованные secrets;
- флаг enabled;
- последнее состояние `ok`, `unreachable` или `error`;
- время последнего успешного получения данных.

UUID создаёт core. Он не выводится из IP или порта, поэтому история остаётся привязана к той же
логической Source после изменения адреса цели.

## Project: папка верхнего уровня

Project группирует Source одного наблюдаемого продукта или контура. Для нашей связки это Project
`infraegev2`. Благодаря Project один экземпляр `sre-kit` в будущем сможет наблюдать другие системы,
не смешивая их данные.

```text
Project infraegev2
  ├─ Source uptime-http
  ├─ Source host-metrics-ssh
  ├─ Source fail2ban-ssh
  ├─ Source journal-http
  ├─ Source beszel-api
  ├─ Source umami-http
  └─ Source push
```

## Pull и push

У pull-Source инициатором является `sre-kit`:

```text
sre-kit scheduler → adapter → внешняя система → нормализованные сигналы
```

При старте scheduler запускает pull сразу, затем повторяет его по интервалу Source. В dogfood
конфигурации опрос выполняется примерно раз в минуту.

У push-Source инициатором является producer:

```text
producer infraegev2 → bearer token + Idempotency-Key → sre-kit ingress
```

Это нужно для privacy-safe Nginx traffic publisher: именно `infraegev2` понимает свои журналы и
может удалить лишние поля до пересечения trust boundary.

## Статусы Source

- `ok` — последний цикл сбора и обработки успешен;
- `unreachable` — adapter или внешняя система временно недоступны;
- `error` — adapter запустился, но конфигурация или данные некорректны.

`unreachable` защищён от кратких сетевых сбоев: системный Alert появляется после трёх
последовательных ошибок или примерно пяти минут непрерывного сбоя. `error` требует внимания и
создаёт Alert сразу.

## Secrets

Пароли SSH, Umami, Beszel и Source token не хранятся в обычном config JSON. Core держит secret
отдельно в зашифрованном хранилище, а API не возвращает его обратно. Пример Source в репозитории
содержит только placeholders.

## Контрольный вопрос

Что можно переиспользовать для второго VPS: Source или adapter? Adapter. Для второго VPS создаётся
новый Source с новым UUID и собственной конфигурацией.
