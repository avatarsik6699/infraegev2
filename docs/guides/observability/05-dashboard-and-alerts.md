# 5. Dashboard, Alerts и Notifications

Dashboard — не первичное хранилище и не набор отдельных интерфейсов Umami, Beszel и journald. Это
универсальное операторское представление уже нормализованных данных.

## Три уровня навигации

```text
Project Dashboard
      ↓
Sources
      ↓
Source detail
```

- Dashboard отвечает «что происходит с продуктом в целом?».
- Sources показывают состояние каждого канала сбора.
- Source detail помогает рассмотреть измерения и события одного канала.

Дополнительная страница Notifications управляет правилами и каналами доставки.

## Откуда UI знает, как рисовать данные

Каждый adapter поставляет manifest. В нём есть presentation schema: группы, человекочитаемые
названия, единицы измерения, тип визуализации и доступные dimensions. Поэтому UI умеет построить
таблицу или временной ряд, не зашивая в код понятия Umami или `infraegev2`.

Это позволяет добавить новый adapter без отдельной страницы продукта, если его данные укладываются
в существующий универсальный контракт.

## Alert: внутренняя запись о проблеме

Alert проходит простой lifecycle:

```text
условие стало истинным → firing
условие исчезло       → resolved
```

Alert сохраняется и виден в Dashboard. Для Source connectivity существуют системные Alerts без
пользовательского правила:

- `unreachable` — с debounce;
- `error` — сразу;
- возврат в `ok` — разрешает открытый системный Alert.

Пользовательское правило связывает Source и target measurement с условием, threshold, debounce и
каналом Notification.

## Notification: попытка сообщить наружу

Notification — доставка события об Alert во внешний канал. В v1 реализован Telegram.

```text
сигнал → правило → Alert сохранён → Notification отправлена
```

Если Telegram недоступен или канал выключен, Alert всё равно остаётся в системе. Поэтому фразы
«есть Alert» и «получено сообщение» не равнозначны.

## Текущее состояние dogfood-конфигурации

На снимке последней проверки для Project `infraegev2` не было пользовательских alert rules,
notification channels или активных Alerts. Возможность Telegram реализована в `sre-kit`, но сама
интеграция `infraegev2` ещё не превращена в полноценную систему оповещения.

Следствия:

- Source connectivity Alerts могут появиться в UI автоматически;
- пороги CPU, диска, TLS и другие предметные условия пока не настроены как пользовательские rules;
- Telegram ничего не отправит, пока не создан канал и правило, которое на него ссылается.

## Контрольный вопрос

Если Telegram сломан, исчезнет ли Alert из Dashboard? Нет. Внешняя доставка и внутренний lifecycle
проблемы — разные части.
