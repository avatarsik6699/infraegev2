# 1. infraegev2 как самостоятельная система

Сначала временно забудем про `sre-kit`. Сам по себе `infraegev2` — публичное учебное веб-приложение
на одном VPS.

## Путь обычного запроса

```text
браузер
  ↓ HTTPS
Nginx
  ├─→ Web: страница и интерфейс урока
  └─→ API: проверка ответа и служебные endpoints
          ↓
       PostgreSQL приложения
```

Nginx — публичная входная точка. Он завершает TLS и направляет запрос к Web или API. Web отвечает
за интерфейс и учебный сценарий. API владеет серверной логикой. PostgreSQL приложения отделён от
базы аналитики Umami.

## Что ещё работает рядом

На том же VPS есть независимый operations-контур:

- Umami принимает только разрешённую пользователем браузерную аналитику;
- Beszel Agent измеряет хост и контейнеры, Beszel Hub хранит и отдаёт эти измерения;
- journald хранит системные и прикладные журналы;
- fail2ban защищает публичные сервисы и фиксирует ban/unban;
- Restic и systemd timers обслуживают backup, restore-check и retention;
- WireGuard открывает приватный операторский путь к Umami, Beszel и journal gateway.

Приложение и operations-контур — два независимых Docker Compose project. Обновление Umami не
должно пересоздавать Web/API, а деплой приложения не должен уничтожать данные Beszel.

## Где здесь наблюдаемость

Наблюдаемость — не ещё один обязательный слой обработки пользовательского запроса. Это параллельный
контур, который отвечает на вопросы о работающей системе:

- доступен ли сайт;
- не заканчивается ли TLS-сертификат;
- хватает ли CPU, RAM и диска;
- что происходило в журналах;
- кого блокирует fail2ban;
- какие страницы и учебные действия используются с согласия пользователя;
- сколько запросов фактически дошло до Nginx.

Ключевой принцип отказоустойчивости:

```text
monitoring сломан ≠ продукт должен остановиться
```

`infraegev2` продолжает обслуживать пользователей, даже если локальный `sre-kit` выключен.

## Граница ответственности

`infraegev2` владеет действиями, которые изменяют его целевую систему: Compose, systemd, SSH,
WireGuard, deploy, rollback, backup и restore. Он же владеет смыслом продуктовых событий, browser
consent и безопасной агрегацией Nginx-трафика.

`sre-kit` в эту главу пока не входит. Позже он будет читать результаты работы этих частей, но не
управлять ими.

## Контрольный вопрос

Если `sre-kit` полностью выключить, какие части `infraegev2` продолжат работать? Правильный ответ:
публичное приложение, VPS-сервисы, Umami, Beszel, journald, fail2ban, backups и target-side timers.
