# 8. Зачем источники частично дублируются

Несколько инструментов иногда измеряют похожее. Это не обязательно лишняя сложность: независимые
пути помогают подтвердить проблему и увидеть её с разной стороны.

## Umami и Nginx traffic aggregates

Оба говорят о трафике, но отвечают на разные вопросы.

| Umami | Nginx aggregates |
|---|---|
| Только пользователи с consent | Все запросы, дошедшие до сервера |
| Поведение в интерфейсе | Серверная нагрузка и HTTP-результат |
| Product events, страницы, устройства | Path, status family, грубый traffic class |
| Не видит отказавшихся от analytics | Не знает действий внутри уже загруженной страницы |

Сопоставление позволяет не принимать server request за осознанное действие человека и не считать
consented analytics полным объёмом нагрузки.

## SSH metrics и Beszel

`host-metrics-ssh` — простой прямой канал без отдельного monitoring agent contract со стороны
`sre-kit`. Он даёт базовые CPU, RAM и disk.

Beszel — более богатая система с Agent, Hub, своей историей, load и метриками контейнеров. Adapter
умеет выдавать `container.cpu_percent` и `container.mem_mib` с label контейнера.

Их совместное использование даёт независимую перепроверку host health. На снимке последней
dogfood-проверки в SQLite наблюдались host Metrics Beszel; наличие container support в adapter ещё
не означает, что container series уже практически используются в Dashboard.

## journald и fail2ban

`journal-http` даёт широкий поток технических Events: сервисы, Nginx, приложения и системные
сообщения. `fail2ban-ssh` даёт узкий структурированный поток ban/unban с jail, action и адресом.

Первый удобен для расследования неизвестной причины. Второй — для понятной security-картины без
повторного разбора общего журнала в UI.

## Локальный uptime и GitHub probe

`uptime-http` встроен в общий Source/Check/Alert pipeline и работает во время локальной сессии.
GitHub Actions запускается независимо от workstation каждые 15 минут и проверяет внешний HTTPS и
срок TLS.

GitHub probe не заменяет Dashboard: он не видит CPU, private services, journals или корреляцию.
Но он уменьшает слепую зону, когда локальный core выключен.

## Первичный инструмент и sre-kit storage

Umami, Beszel и journald сохраняют свои специализированные модели. SQLite `sre-kit` хранит
нормализованный операторский срез для корреляции, Alerts и единого UI.

```text
специализированный источник = глубокая первичная модель
sre-kit                    = общий ограниченный обзор
```

Это не попытка навсегда скопировать все данные из каждого инструмента.

## Где перекрытия пока недостаточно

- локальный core не имеет независимого meta-monitoring;
- при выключенной workstation polling и Alerts останавливаются;
- backup/restore status пока не заведён как отдельный Source;
- пользовательские alert rules и Telegram для `infraegev2` не настроены;
- практическое использование container Metrics Beszel требует подтверждения данными.

## Контрольный вопрос

Почему Nginx aggregate нельзя назвать полной заменой Umami? Потому что сервер видит запрос, но не
видит consented действия внутри интерфейса и не может достоверно определить намерение пользователя.
