# Ревизия урока на сайте (Change 197)

> Порядок и правила, выработанные на уроке 1.1 «Программа и её выполнение» курса Python
> (2026-10-19…20). Применяются к каждой следующей подтеме курсов и тем ЕГЭ. Уроки правятся прямо
> на сайте ([порядок](lesson-pipeline.md#сайт--источник-уроков-change-197)); проверки — одним
> прогоном в конце аудита (T1 в `docs/changes/197-content-audit.md`).

## Порядок работы над уроком

1. Архитектор присылает замечания документом в `docs/artifacts/after_review_learning_materials/`.
2. План правок: каждый пункт документа → пункт Backlog; спорное — вопрос архитектору до правок.
3. Правки в коде урока, схемах (`site_media.py`) и банке; проверки не запускаются, только
   генераторы (`site_media.py`, `node scripts/practice-registry.mjs` при смене разделов).
4. Показ на локальном сайте: `make rebuild` при смене реестра, `make practice-bootstrap` при смене
   банка; кадры 1280 и 375 — отдельным headless Chromium (Playwright), а не из Chrome
   пользователя: там масштаб и фоновая вкладка портят снимки.
5. **Чтение глазами ученика** после правок: весь текст страницы, раскрытые «Тонкости», все вопросы
   «Проверьте себя», задачи с решениями. Список находок «мешает понять / неточность / заметка» —
   архитектору, затем правки.

## Текст

- Обращение к ученику — на «ты» везде, включая текст архитектора.
- Никаких ссылок вперёд: термин или конструкция до своего объяснения не встречаются ни в тексте,
  ни в примерах, ни в вопросах («двоеточие», «отступ», переменные, `/` с дробным ответом — только
  после своих уроков). Если без слова не обойтись — одна фраза на месте и «подробнее — ниже».
- Определение даёт ученику способ различить понятия на примере урока (выражение и инструкция —
  на `3 * 40` и `print(3 * 40)`), а не перечень того, чего он ещё не знает.
- Строгие оговорки, нужные знатоку, но не новичку, — в «Тонкости» сразу под тем предложением,
  которое они уточняют.
- Один процесс описывается одной моделью: список шагов и схема называют одни и те же шаги. Шаги пошагового запуска
  говорят словами текста (`// run notes` в манифесте), а не общими словами трассировщика.
- Слово, у которого в курсе уже есть другое значение, разводится при первом появлении: строка-значение
  (`str`) и строка программы.
- Связь с прошлыми уроками — на знакомом: ошибка `NameError` от `pritn`, `print` / `Print`, пояснения
  после `#`; незнакомое (`list`, `for`, «область видимости») в примеры не берётся.
- Инструкция по действиям — конкретная: где открыть, что нажать, какой путь ввести (пример
  `cd C:\Users\Anna\PycharmProjects\kurs`, вкладка «Terminal» в PyCharm).

## Структура страницы урока курса

- Порядок: теория → «Итог» → «Проверьте себя» → «Практика» (SPEC §1.4).
- «Итог» — обзор урока сверху: короткий абзац и сетка «понятие → что запомнить»
  (`LessonSummary` с ключами), без новых фактов.

## Блоки

- **Код** (`CodeBlock`, `CodeRunner`): один вид. Код Python всегда с номерами строк, строки файлов
  и алгоритмы — без; вывод строками, как в терминале; подсветка сдержанная (ключевые слова,
  строки, числа, комментарии); имя файла с иконкой на листе кода, вывод — белая панель.
  Вида редактора (вкладки, яркие схемы) нет: блоки учат, а не изображают IDE.
- **Команда терминала** — `TerminalCommand`, не блок кода; для разных систем — по команде с
  подписью системы.
- **«Тонкости»** — `ProofDisclosure kind="nuance"`: сноска абзаца, стоит сразу под предложением,
  которое уточняет, никогда — после постороннего рисунка.
- **Несколько способов сделать одно** (среды, системы) — `LessonTabs`; основной вариант первым.
- Общие блоки не окрашиваются в цвет курса; цвет курса — только у «текущего места»
  (полосы навигации, надзаголовок, текущая строка, вкладки) и у схем урока.

## Схемы и скриншоты

- Схемы — код (`figures.py`); в курсе — тон курса: `tone="python"` в строке вызова манифеста.
  Схему рендерить в PNG (`svg_png.mjs`) и смотреть глазами: подписи не вылезают за рамки.
- Одна программа — один пошаговый запуск и не больше одной схемы к нему: три изображения одного
  примера не объясняют больше, чем одно.
- Узкая схема рисуется по ширине содержимого (меньше 340 — помещается на телефоне); широкая на
  телефоне прокручивается внутри плашки. Подписи соседних карточек не должны сходиться.
- Скриншоты окон программ (`LessonImage`) — только актуальные и той системы, о которой текст
  (Windows), без посторонних файлов и путей; источник каждого — в
  [lesson-images.md](../artifacts/lesson-images.md). Кадр, который сбивает (другая ОС, старая
  версия, чужие файлы), лучше убрать, чем оставить.
- Факты об установке и версиях — по официальной документации на дату правки (с 2026 г. на
  Windows — Python install manager).

## Практика (банк задач)

- Один вопрос в задаче. Если задача просит написать программу, в поле вводят то, что она
  напечатала, — так и сказано в условии.
- Одно поле ответа; несколько значений — через пробел. Инструкция прямо называет порядок
  значений, без «Например». Ответ не допускает двусмысленного ввода: в значениях нет пробелов,
  если значения разделяются пробелом (меняется задача, а не правило).
- Подсказка своя у каждой задачи — по сути ошибки, а не «опора — урок…».
- Разбор заканчивается отдельным блоком «Ответ: `…`» ровно в том виде, в каком его вводят.
- Название задачи — обычный текст, разметка в нём не работает: код в названии проверяется глазами
  (при переносе из стенда `**` пропадали как жирный шрифт — «2  k» вместо «2 ** k»). Для задачи
  «что напечатает программа» название так и пишут, а программа — блок кода в условии.
- Вопросы «Проверьте себя» решаются знаниями этого и прошлых уроков.
