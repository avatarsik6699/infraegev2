# Волна тем: параллельная подготовка на демо-стенде

> Решение архитектора 2026-10-11 (Change 179): новые темы ЕГЭ идут на стенд волнами по 3–4 темы в
> одном change. Каждую тему ведёт свой агент, общие файлы, проверки и публикацию — оркестратор.
> Этапы и правила темы не меняются: действует [пайплайн](lesson-pipeline.md) целиком.

Общие правила делегирования — [agent-workflow.md](agent-workflow.md) (там конфигурация Codex и
лимит двух дочерних агентов). Для волны тем в Claude Code архитектор разрешил столько пишущих
агентов, сколько тем в волне: у каждого своя папка и свой модуль схем, общих файлов они не правят.
Параллельность экономит время, а не токены: агент на тему стоит примерно как одна тема,
сделанная целиком в одной сессии.

## Роли и файлы

| Кто | Пишет | Не трогает |
|---|---|---|
| Агент темы NN | `content/lesson-design/topic-NN/**`, свой модуль `scripts/lesson_design/<имя>_figures.py`, свои термины в `terms.py` — только под строкой `# --- topic NN ---` | всё остальное: `figures.py`, `build.py`, `verify_code.py`, `index.html`, `docs/**`, чужие темы |
| Оркестратор | исходники и ссылки на них, `figures.py` (регистрация модулей), `index.html`, `build.py` и `verify_code.py` по запросу агента, change, runbook-и, паттерны | — |

Только оркестратор: git, ветки и коммиты; гейт `scripts/gate.py`; браузер (Playwriter — один Chrome
пользователя на всех); `make clean`; публикация артефакта; Backlog change.

Перед запуском оркестратор создаёт модуль схем каждой темы с пустыми словарями
`<ИМЯ>_FIGURES`, `_STEPPERS`, `_WIDGETS`, `_SCRIPTS`, подключает его в конце `figures.py`
и ставит в `terms.py` строки `# --- topic NN ---`.

## Модель и effort

Агенты тем — Opus 5.5, effort high: работа долгая, держится на методике, математике и проверке
ответов вторым способом. Оркестратор — Opus 5.5. Агент запускается заново (не форк сессии
оркестратора) с заданием ниже; нужные выводы прошлых тем передаются в задании явно.

## Порядок

1. **Подготовка (оркестратор).** Этап 1: исходники подтверждены, ссылки на них. Модули схем,
   строки терминов, папки для скачанных подборок вне репозитория.
2. **Фаза А (агенты параллельно).** Этапы 2–3: подборки, `tasks.py`, `frequency.md`, `map.md`,
   `topic.json`. Агент останавливается и возвращает отчёт фазы А.
3. **Контрольная точка (оркестратор, затем архитектор).** Оркестратор проверяет карты: уровни
   по правилу 2.4, границы без ссылок вперёд, что ушло в термины курса, ничего из исходника не
   потеряно. Архитектору — сводка: подтемы, уровни, доля покрытия, спорные решения.
   Замечания передаются тому же агенту.
4. **Фаза Б (те же агенты, продолжение).** Этапы 4–7 без браузера: тексты, схемы, `review.md`,
   задачи, `checks.py`, `verify_code.py`, сборка своей темы. Отчёт фазы Б.
5. **Сборка волны (оркестратор).** Проверка терминов и имён схем на совпадения между темами,
   `index.html`, проход каждой темы глазами ученика с правками, проверки этапа 7 по всем темам,
   регрессия, гейт, браузер на 1280 и 375 px, публикация (этап 8).
6. **Ревью архитектора.** Замечания — новыми пунктами Backlog; правки по темам снова раздаются
   агентам (продолжение того же агента), мелкие — оркестратор.

## Проверки и доказательства

Волна 1 (Change 179): агенты не прогоняли Ruff и Pyright по своим файлам, гейт нашёл 5 замечаний
Ruff и 10 ошибок Pyright — теперь это обязательная проверка агента. Генерация данных, схемы и
ответы прошли без замечаний; проход оркестратора глазами ученика нашёл мелочи (порядок «Что
дальше», подряд идущие жирные утверждения, ссылки на файлы данных в задачах).

Агент приводит в отчёте команды и итоги проверок своей темы. Оркестратор не повторяет их без
изменённых входов, но после своих правок и перед гейтом прогоняет этап 7 по всем темам волны.
Записи гейта (Gate evidence) ведёт только оркестратор.
